# 工程宪法（开工必读 · 违背即任务失败）

> 前 6 条源自架构文档《全局硬约束》（见 [../docs/技术架构-v2/README.md](../docs/技术架构-v2/README.md)），后 5 条是本执行层的流程红线。二者同级，不可妥协。

## 产品铁律（1–6）

1. **本地优先**——所有用户数据本地加密，产品方零接触，核心能力离线可用。
2. **中性视角**——禁止拟人化（人名 / 性格 / 第一人称 / 情感 / 对话体）。
3. **可配置性优先**——对话 + 结构化面板双通道，配置可导出 / 导入 / 版本化。
4. **多视角分歧并列**——不合并分歧、不给统一建议。
5. **可解释**——每条结论可追溯完整推理链（Trace）。
6. **共同演化透明**——任何自动变更显式告知 + 可回滚。

## 工程铁律（7–11）

7. **层间只允许向下依赖**——禁止反向调用与循环依赖；跨层协作一律经 `01-平台共享契约`。
8. **接口变更有序**——先改 [../docs/技术架构-v2/01-平台共享契约.md](../docs/技术架构-v2/01-平台共享契约.md) → 同步各层架构文档 → 最后改代码。
9. **文档一致性**——PRD 需求变更时，受影响的架构文档同批修订；任务状态只改 `tasks/T-*.md`，再跑 `tools/render_ledger.py render` 刷新派生的 [任务账本.md](任务账本.md)（禁手改账本）；全项目相对链接断链校验必须通过。
10. **无留痕不关闭**——任务 `status→done` 之前必须在 [执行日志.md](执行日志.md) 有一条含「验证」行的记录；涉及选型必须登记 [决策日志.md](决策日志.md)；遇未决登记 [阻塞与未决.md](阻塞与未决.md) 并把任务转 `blocked`。
11. **开工先对齐**——动手实现前（[工作流.md](工作流.md) 第 ④ 步），Agent 必须先向人复述「要交付什么 / 验收怎么算过 / 打算怎么做 / 有哪些假设或未决」并获得确认；对齐结论记入执行日志；未对齐不得进入实现。
