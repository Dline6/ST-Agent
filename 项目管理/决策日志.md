## D-001 · ST Agent 采用「Beads 依赖账本 + Spec Kit 精简流程」（B+A 组合）

- **背景**：为单人 + AI Agent 的开发选一套可追踪的软件项目管理方案。
- **选项**：A 纯 Spec Kit 流水线 / B 纯 Beads 任务账本 / C 多 Agent 并行看板编排 / D BMAD 角色流水线。
- **决策**：B+A 组合——以现有 frontmatter 依赖图为账本内核（B），叠加 Spec Kit 的 constitution + plan/tasks 精简流程（A）；暂不引入 C 的并行编排。
- **理由**：项目已是「规范先行」文档体系，B 复用度最高、纯本地无平台锁定（与本地优先价值观自洽）；A 补齐缺失的 tasks/verify 执行段；单人场景下 C 成本过高，留作 M2 后提速选项。
- **影响**：新增 `项目管理/` 执行层，不改动 `docs/` 规格；本目录七文件即其落地。
- **参考**：[AI-Coding项目管理方案.md](AI-Coding项目管理方案.md)（与本日志同目录）

## D-002 · ST Agent 采用「主干开发 + 短生命周期任务分支 + Conventional Commits（中英混排·带任务号）」

- **背景**：`项目管理/` 执行层落地后缺一份入库规范；需在「单人 + AI Agent、严格对齐任务账本工作流、本地优先数据主权」前提下确定 Git 分支模型、提交约定与文档落点。
- **选项**：分支模型 — 主干开发+短分支 / GitHub Flow（常驻 PR 审查）/ 纯单分支直推 / Git Flow；提交约定 — Conventional Commits 中英混排+任务号 / 简化任务号前缀+中文 / 纯英文 Conventional；落点与范围 — 全套并联动任务流 / 仅分支+提交精简 / 全套+顺带建脚手架。
- **决策**：主干开发 + 每任务短生命周期分支（squash 合入即删，命名 `type/T-ID-slug`）；Conventional Commits 中英混排（type 英文枚举 + 中文 subject）+ 每条 commit 强制 `Task:` trailer；规范落 `项目管理/Git协作规范.md`（全套：仓库布局/.gitignore/分支/提交/pre-commit+PR 卡点/里程碑 tag），并与工作流、任务账本 `render`、`verify_docs.py`、三日志联动。本轮只写规范，`git init`/`.gitignore`/`.pre-commit-config.yaml` 脚手架留待正式启动开发时执行。
- **理由**：单人场景下 Git Flow/常驻 develop 过重；主干+短分支保持线性历史且与「一任务一文件」的账本粒度天然对齐。任务号 trailer 实现 `git log --grep` 与 `tasks/*.md` 的双向追溯，呼应「无留痕不关闭」。`.gitignore` 单列数据主权红线，因产品核心承诺是本地优先、用户投资数据/密钥零接触，误入库即安全事故。纯本地 Markdown + git 与 D-001「无 SaaS 锁定」自洽。
- **影响**：新增 `项目管理/Git协作规范.md`，执行层活文档由 7 增至 8；同步在根 [../CLAUDE.md](../CLAUDE.md) 结构表、[AI-Coding项目管理方案.md](AI-Coding项目管理方案.md) 目录树/增量清单、[工作流.md](工作流.md) 入库段、[README.md](README.md) 索引登记该文件。D-001「本目录七文件」为落地时点历史记录，不改写，以本条补充。

## D-003 · 仓库脚手架一次性落地，Agent 入口文件名统一为 `CLAUDE.md`

- **背景**：D-002 只写规范、脚手架待正式启动开发时执行；启动时检查发现规范的仓库布局要求根有面向人类的 `README.md` 与 Agent 入口文件，而实际入口文件名为 `CLAUDE.md`，`Git协作规范` §1、`项目管理/README`、`verify_docs.py` OPS_DOCS 等 6 处仍写 `AGENTS.md`，其中 2 处已被 `verify_docs --strict` 判为断链。
- **选项**：入口命名——A. 新建/改名出 `AGENTS.md`（或双文件并存互为镜像）/ B. 引用侧统一改为既有的 `CLAUDE.md`；脚手架范围——C. 全套（.gitignore + pre-commit + README）/ D. 最小（仅 init + .gitignore）。
- **决策**：B + C。不新增 `AGENTS.md`、不做双文件镜像，全项目 `AGENTS.md` 引用统一改写为 `CLAUDE.md`；同批落地 `.gitignore`（§2 数据主权红线模板原文）、`.pre-commit-config.yaml`（§5.1 verify_docs 卡点）、根 `README.md`（面向人类总览），`git init -b main` 并完成首次提交。
- **理由**：`CLAUDE.md` 是会话工具链实际读取的文件名，改名或双文件并存会引入镜像漂移成本且 verify_docs 只能校验其一；引用侧一次性改写即可让 §1 布局、冷启动六段与断链校验同时收敛。全套脚手架一次到位，避免「规范已写、动作未做」的悬置状态重演。
- **影响**：断链 2 → 0（96 文件 / 803 链接）；§1 布局与根实际文件一致；D-002 的「脚手架留待启动时执行」兑现；后续所有 commit 走 §4 格式 + `Task:` trailer，合入走 §5 卡点。Git 身份暂为 `qianq <qianq@localhost>`（仓库级），建远端前由负责人替换邮箱。
