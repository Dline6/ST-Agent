# 遗留问题登记册

> **本册收「任务收工时的转移 / 待办」**——某任务的「遗留」行指向了别的任务、别的层，或指向一个尚不存在的能力；它既不是当前任务的欠账，也不能靠当前层独力关闭。

## 与 阻塞与未决.md 的分工

| 台账 | 收什么 | 编号 | 处置 |
|---|---|---|---|
| [阻塞与未决](../阻塞与未决.md) | **规格空白**：spec/plan 没定、Agent 会靠臆测填补的问题 | `Q-NNN` | 停手 → 任务转 `blocked` → 等人回填 → 记决策日志 |
| 本册（`遗留问题/`） | **转移 / 待办**：归属已定但归属方尚未开工，或属长跑运营 / 待人决 | `<层>-遗留问题.md` | 不改任务状态；归属任务开工时消费 → 收工时销账（规则 6） |

判据一句话：**「谁来写这段代码」不清楚 → 进未决；清楚但还没轮到 → 进本册。**

## 规则

1. **一层一文件**：`L0-遗留问题.md` / `L1-遗留问题.md` …；新增层时同构加文件，勿把多层混进一册。
2. **每条必含四要素**：遗留内容 / 来源（任务 id + 执行日志锚点）/ 归属（承接任务 id 或「人决」）/ 解封条件（什么 `done` 之后它会被消费）。
3. **只登记未解决项**；已定案关闭的移入文件末尾「已闭（备查）」节，保留一行便于回溯，不删。
4. **关闭留痕**：某条被归属任务兑现后，从本册移除并在 [执行日志](../执行日志.md) 写一条（宪法第 10 条）。
5. **不替代任务文件**：本册是索引不是真相源；范围与验收仍以 `tasks/T-*.md` 为准。
6. **开工消费 · 收工销账**（2026-09-26 机制）：归属任务开工时（[工作流](../工作流.md)「遗留消费」节）把命中项写进任务文件 `## 可关闭的遗留` 并**计入该任务验收**——能闭则闭，闭不了的当场修正本册「归属」或「解封条件」并写明理由，不静默留悬。收工时按规则 3 销账、规则 4 留痕。机器兜底：`verify_docs.py` 检查 8 断言未闭区条目的「归属 / 解封条件」所指任务**未全 `done`**——命中即该销的账没销。
