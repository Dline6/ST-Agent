## Q-005 · open · 出现于 [L1 册 `C1`](遗留问题/L1-遗留问题.md) 收口评估 · 2026-09-26 新登记

**公告全文 / 舆情问答 / 新闻等**文本类**信息，是否单独以文件形式落盘存储（而非仅入库表列）？查阅接口归谁？RAG 索引的事实源与归属如何界定？**

由来：负责人 2026-09-26 提出——文本类信息单独整理为文件存储，便于后续接入 **RAG** 与 **AI 自主查阅文档**。

**已核实的就绪底座（无技术阻塞）**：

- [02 §2.1](../docs/技术架构-v2/02-L0-本地优先基座.md) 的 `data_cache` 分区内容**已明列**为「市场数据快照（**公告**/行情/龙虎榜/股东/**舆情**）」——四域本就在分区设计内，**不需新分区**。
- [`Store`](../src/st_agent/l0/storage/store.py) 已是「分区 + 分区内相对路径 → bytes」的**通用 KV**（`put` / `get` / `list_files` / `delete` / `export_partition` / `wipe_partition`），支持嵌套相对路径、逐文件 `digest` + `size` 清单、落盘加密与分区级校验——**文本文件可直接落 `data_cache`，存储层零改动**。
- [02 §2.3](../docs/技术架构-v2/02-L0-本地优先基座.md) 损坏恢复按分区粒度；[T-L0-006](tasks/T-L0-006-备份恢复完全清空数据留存策略.md) 备份已支持 `data_cache` **可选**纳入归档。

**未定的规格（须人决）**：

① **文件与表的关系**——正文落文件、元数据（title / type / date / code / url / 路径）落表（「文件为主 + 表为索引」），还是两者冗余？事实源只能有**一个**；「表在而文件缺」与「文件在而表缺」两种不一致各走什么状态（`unavailable` 抑或损坏告警）？
② **寻址与证据引用**——`announcement_id`（[01 §1](../docs/技术架构-v2/01-平台共享契约.md) 已登记由 L0 数据缓存产生）与文件路径的双向映射；路径须稳定可复核，而 `EvidenceRef.ref` **≤128 字符**——证据引用继续用 `announcement_id`（路径由其确定性派生），还是直接用路径？
③ **查阅面归属**——L1 沙箱对越界（读文件属三项权限之一）须**声明 + 批准**，故 Skill **不能**直接 `open()`；文档读写接口应作为 L0 的鸭子类型取数面（对齐 `MarketDb.query` 的既有范式，见 [03 §2](../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的官方 Pack 执行面），由 L1 经注入消费。接口形态（列目录 / 读单篇 / 关键词检索 / 范围内全文检索）待定。
④ **RAG 索引的地位**——向量索引是**派生数据**（可由文件重建）而**非事实源**；其落点（L0 / L2 记忆图谱 / 后续独立面）与重建口径须显式，否则会被误当事实源。
⑤ **备份范围**——档案型文本（公告）在源端失效后**不可重取**（参照仓库自述：通达信 K 线 2026-09 失效、网易财经整站下线）；是否应从 `data_cache` 的**可选**备份升为**默认纳入**？（若升，属对已 `done` 的 [T-L0-006](tasks/T-L0-006-备份恢复完全清空数据留存策略.md) 的口径修订。）

- 候选：**A**. 文件为主 + 表为索引（正文落 `data_cache` 文本目录，表存元数据与路径）· **B**. 仅入库表（正文存表列）· **C**. 文件与表冗余双写
- 影响任务：待立项的「多源信息面采集与管理机制」（[L1 册 `C1`](遗留问题/L1-遗留问题.md) 的承接方）；若 ⑤ 取默认纳入，另需复核 [T-L0-006](tasks/T-L0-006-备份恢复完全清空数据留存策略.md)
- 决议：待补

## Q-004 · open · 出现于 [L1 册 `C1`](遗留问题/L1-遗留问题.md) 收口评估 · 2026-09-26 新登记

**四域带回的标的中，[`security`](../docs/数据库设计-BaoStock数据层/schema.sql) 主档未收录的代码（北交所 `920xxx` / `8xxxx` 等）如何处理？**

- 影响任务：待立项的「多源信息面采集与管理机制」；若取 A，牵动 [T-L0-005](tasks/T-L0-005-数据源缓存BaoStock首个源落地.md) 的主档同步面
- 决议：待补

## Q-002 · decided (D-029) · 出现于 T-L1-004.3（C1 收口评估）· 2026-09-26 裁定

**信息面（公告 / 龙虎榜 / 股东变化 / 舆情）的采集通道归谁：L0 数据源网关直抓、story-08 的官方 MCP Server、还是两者分工（谁主谁备）？**

核查证据（2026-09-26）：

- [00-架构总览 §5 端到端数据流](../docs/技术架构-v2/00-架构总览.md) 步骤 1：「**数据入湖**：L0 数据源网关抓取公告 → 写入本地数据缓存（带快照 ID），登记 NetworkEvent」——公告**走 L0 网关**。
- [02 §5 数据源缓存](../docs/技术架构-v2/02-L0-本地优先基座.md) 只定义了「首个数据源为 BaoStock」；多源扩展的**库表**侧规约在 [数据库设计 §多源扩展规约](../docs/数据库设计-BaoStock数据层/00-设计总览.md)（登记 `data_source`、按域前缀建表组、复用 `sync_state`、在 05 登记同步与新鲜度契约），但**未说采集通道由谁实现**。
- [story-08](../docs/PRD-v2-Agent/story-08-mcp-hub.md)：「**官方 MCP Server**：产品自带一批（交易所公告、行情、龙虎榜、股东数据、舆情）」；同文边缘情况写「MCP Server 崩溃 → **降级到官方数据源**」——把 L0 数据源当**兜底**。与上一条「公告走 L0 网关」并列，两处对同一批信息源的**通道归属与主备关系均未定义**。
- [01 §1](../docs/技术架构-v2/01-平台共享契约.md) 把 `announcement_id` 的产生方登记为「L0 数据缓存」（未提 MCP）。
- [story-05](../docs/PRD-v2-Agent/story-05-local-first.md) 要求「数据源逐个可开关（如禁用舆情抓取）」——开关是配置注册表（01 §7）职责，通道选型不影响该要求，但影响**每个源在 `data_source` 里登记几条**。

外部信源佐证（2026-09-26 经 `gh api` 核实，仅作候选 A 的可行性佐证，**不构成决议**）：

- 开源项目 [`simonlin1212/a-stock-data`](https://github.com/simonlin1212/a-stock-data)（Apache-2.0 · 10,349 star / 1,888 fork · 创建 2026-05-11 · 最后推送 2026-09-25）以单文件 `SKILL.md`（425 KB / 7,509 行，15 层 · 87 端点 · 34 源）**覆盖本条暂定的互补部分（四域）**：公告（巨潮 §7.1，备胎深交所官方 / 东财）、龙虎榜（东财 §3.5·§3.9，备胎沪深交易所官方含营业部席位）、股东变化（东财 §4.3）、舆情（互动易 §10.1 / 上证e互动 §10.3 / 热榜 §10.2 / 新闻 §5.x）。四域所需端点**全为纯 `requests` / `urllib`**，重依赖只在行情 / 研报等本机制不需要的层。
- **对候选 A（L0 网关直抓）**：该仓库是一份**现成的直抓实现**——把「四域能否直抓、字段有哪些、怎么防封（`em_get()` 串行 + 最小间隔 1 s + 抖动 + 复用 Session）」从**待调研**变为**已核实**，大幅降低选 A 的实现风险。
- **对候选 B / C**：该仓库**不提供** MCP Server 形态的封装——根目录**无 `pyproject.toml` / `setup.py`**（非可 `pip` 安装的库），`.github/` 下仅 `FUNDING.yml`（无 CI）——故对「官方 MCP Server」通道**无直接佐证**。
- **它不回答本条**：只证明「直抓可实现」，不回答「通道该归谁」；且**不含**四域的表结构、`sync_state` 任务与新鲜度契约（[数据库设计 §多源扩展规约](../docs/数据库设计-BaoStock数据层/00-设计总览.md) 的建模层仍须自研）。三层分解（信源知识 / 数据建模 / 机制）与移植口径的完整核实见 [L1 册 `C1` 补充](遗留问题/L1-遗留问题.md)。

**范围口径（2026-09-26 修正）**：本机制的信息面取「**与 BaoStock 互补的部分**」，**暂定四域**（公告 / 龙虎榜 / 股东变化 / 舆情）——后续可能再引入其他域，故**不写死为「四域」**。收录判据为**两条并列**：① **供给侧不重复**（BaoStock 无此域；与既有域重叠之处已核出六处，见 [L1 册 `C1` 补充](遗留问题/L1-遗留问题.md)）；② **需求侧有明确消费方**（不预设）。仅满足 ① **不足以**收录——「BaoStock 的补集」按仓库端点计约 60 个，须由 ② 收敛，否则会把补集误当路线图。

**「互补」对通道的推动**：互补的意义在于上层（L4 情绪视角需**同时**读行情与舆情热度）能在**一个口径**下取数；若一部分走 L0、一部分走 MCP，上层须合并两条管子，正是单一事实源欲防之事。叠加 [02 §6 的本地 stdio MCP 子进程出网不在审计范围](../docs/技术架构-v2/02-L0-本地优先基座.md)（D-023 已登记的已知边界），**本条候选 A 由此获实质强化**。但**主备口径**与**未收录代码主键**两个衍生点不在本条内，另立 `Q-003` / `Q-004`；文本类信息的存储形态另立 `Q-005`。

影响：L1 官方 Skill 的「关键词」类条件（`stock-watch`，[L1 册](遗留问题/L1-遗留问题.md) `C1`）与 L4 情绪视角（舆情热度 / 龙虎榜资金，[story-04](../docs/PRD-v2-Agent/story-04-multi-lens.md)）、M3 的端到端触发流（[00 §5](../docs/技术架构-v2/00-架构总览.md) 以公告为样例）都依赖这批信息面；通道未定则表结构落点、同步任务归属与新鲜度契约无从下笔，实现方只能猜。

- 候选：**A**. 全部走 **L0 网关直抓**（与 00 §5 步骤 1 / 01 §1 产生方一致；story-08 的「官方 MCP Server」在实现上退化为「官方内置数据源」的对外说法）· **B**. 全部走**官方 MCP Server**（须改 00 §5 步骤 1 与 01 §1 的产生方登记）· **C**. **分工**：结构化信息面（龙虎榜 / 股东）走 L0 直抓，非结构化（公告 / 舆情）走 MCP Server，并在 02 §5 与 story-08 双向写明主备与降级关系
- 影响任务：待立项的「多源信息面采集与管理机制」（[L1 册](遗留问题/L1-遗留问题.md) `C1` 的承接方）；[T-L1-004](tasks/T-L1-004-官方SkillPack公共认知主动服务Bundl.md)（`stock-watch` 的关键词条件）
- 决议：**A** —— 全部走 **L0 网关直抓**；官方 MCP Server 若保留则降为「**L0 缓存的只读暴露面**」（不出网、不采集、不写库），交付**可延后**。候选 C 失效、保留备查。**衍生点另立**：主备口径 `Q-003` · 未收录代码主键 `Q-004` · 文本类存储形态 `Q-005`。见 [决策日志 D-029](决策日志.md)
