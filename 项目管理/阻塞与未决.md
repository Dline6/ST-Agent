## Q-016 · decided (D-060) · 出现于 负责人形态复核（桌面 vs 浏览器）· 2026-09-28 登记 · 2026-09-28 裁定

  - [02 §2.2](../docs/技术架构-v2/02-L0-本地优先基座.md)：全部分区落盘加密，密钥由**用户主密码派生**——浏览器存储给不出「按分区独立加密 + 独立导出 / 独立清空」；

  - [02 §8.1](../docs/技术架构-v2/02-L0-本地优先基座.md)：一键备份产出**单个加密归档文件**；

- 决议：**逐项定**（编号对应上文）
  - **① 壳选型**：**延后，不列终选**——只立两条约束：**(a) 兼容底线**＝表现层 UI 以「系统 WebView 三引擎」（WebView2 / WKWebView / WebKitGTK）为兼容目标，从而同时兼容 Electron 与浏览器，壳选型因此可推到打包期；若可视化复杂度证明三引擎成本不可接受，再改以 Electron 单引擎为底线。**(b) 壳的定位**＝只承载原生窗口 / 托盘 / 自启 / 原生通知接线，**不含任何业务逻辑**。**C（暂不套壳）改判为「阶段」而非终态**——[00 §1](../docs/技术架构-v2/00-架构总览.md) 的桌面客户端是终态要求，C 是其前置阶段
  - **② 进程边界**：**取「后端常驻为主体、UI 为可分离客户端」**（修正本条登记时的「壳为主、后端为 sidecar」默认）——定时调度（[T-L1-005](tasks/done/M0/T-L1-005-定时调度.md)）、每周反思（[T-L6-001](tasks/T-L6-001-反馈采集FeedbackEvent每周反思报告.md)）、触达升级链首环的桌面通知都要求**没有窗口时仍在运行**，故 Python 后端必须活得比任何 UI 窗口久；UI（浏览器或壳）只是客户端，可随时开关。**E 否决**：Tauri 无 Python 内嵌、Electron 需 WASM 桥而 Pyodide **无法 spawn 子进程**，与 [02 §1](../docs/技术架构-v2/02-L0-本地优先基座.md) 的 stdio MCP 子进程正面冲突
  - **③ 本地服务安全口径**：**取 F**——绑 `127.0.0.1` + 每次启动随机端口 + 启动令牌握手，并**加 Origin 校验 / 自定义头**防 DNS rebinding。**G 否决**（本机任意进程可读明文，与数据主权相悖）。**H 保留为发布版可选收窄**（关端口改命名管道 / stdio，代价是浏览器直开不可用）——**H 与 ④I 互斥**，故不作当前口径
  - **④ 开发 / 验收期可达性**：**取 I**——允许浏览器直开同一 Web UI，由**显式 dev 开关**控制且**发布包必须剔除**。理由：[T-INT-002](tasks/T-INT-002-M1集成关卡首次可对话.md) 的可观测验收面与 Agent 驱动开发闭环都依赖它
  - **⑤ 交付归属**：**新立跨层 `T-UI-*` 任务组**（`T-UI-001` 骨架 / `T-UI-002` 壳与打包）。架构未给表现层单列一层，故它是**跨层工程任务**（同 `T-SC-*` 先例，`parent: null`、不进层号预排），**不是**第七层；[`render_ledger.LAYERS`](tools/render_ledger.py) 新增 `UI` 条目并置于 **L3 之后、L4 之前**。**L 否决**——并入库 [`T-L3-004`](tasks/T-L3-004-GenerativeUI推理链可视化.md) 会使其溢出 [05 §6–§7](../docs/技术架构-v2/05-L3-对话主入口.md) 已界定的「Generative UI + 推理链」范围，并与 Studio 画布（L1）/ 设置面板（01 §7）的渲染归属叠床架屋。**渲染器的组件类型注册表归 T-UI-001**（[05 §6](../docs/技术架构-v2/05-L3-对话主入口.md) 原文「渲染器维护组件类型注册表」），故 `T-L3-004 depends_on T-UI-001`，两任务只此一条边
  - **IA 缺口归属**：PRD 预留的 [`11-sitemap.md`](../docs/PRD-v2-Agent/README.md) 由 [`T-UI-001.1`](tasks/T-UI-001.1-IA骨架与页面Flow.md) 承接产出——不留「待生成」的空指针（合「欠账要有机制接住」）

- [数据库设计 §设计原则 1](../docs/数据库设计-BaoStock数据层/00-设计总览.md) 原文为「**每张表**只有一个写入来源（一个同步任务），全库口径唯一」——粒度为**表**；这是禁止「一张表按源分行」的**唯一**条款。
- [§3「同域替代源 → 独立源表 + 聚合视图」](../docs/数据库设计-BaoStock数据层/00-设计总览.md) 的触发条件是「新源与 **BaoStock 提供同域同语义数据**」——四域（公告 / 龙虎榜 / 股东 / 舆情）**不在** BaoStock 的五个域（行情 / 财务 / 公司报告 / 板块 / 宏观）内，故 §3 **从未被触发**；四域全落 §2「异构数据域 → 新建表组」，而 §2 对**域内多源**完全沉默。**拦路的是原则 1 的粒度，不是 §3。**
- 四域的真实拓扑**没有一个是「同域同语义的平行替代源」**：公告 = **覆盖分片**（巨潮全市 / 深交所仅深市 / 东财仅沪市）；龙虎榜 = **实体粒度不同**（上榜记录 vs 席位明细）；股东户数 = **单源**；舆情 = **双市并行互补**（同语义、按市场分片）+ 热榜（易腐、另一实体）。§3 的模型套不上。
- 技术面：`sync_state.table_name` **无唯一约束**（一表可挂多任务，逐源水位本就可行）；但 `indicator_dictionary.indicator_key` 为主键、`source_api` / `api_field` 单值——**同一列来自多源时无法表达**（实测 DDL，见 [schema.sql](../docs/数据库设计-BaoStock数据层/schema.sql)）。

影响：[数据库设计 §设计原则 1 / §2](../docs/数据库设计-BaoStock数据层/00-设计总览.md) · [05 的 `as_of` 与水位口径](../docs/数据库设计-BaoStock数据层/05-同步策略与新鲜度契约.md) · [`indicator_dictionary` 的多源承载](../docs/数据库设计-BaoStock数据层/schema.sql) · **四域表组的切分方式**（归属机制立项）。

- 候选：**A**. 维持表级（域内多源一律按源分表 + 聚合视图）· **B**. 粒度改**业务键级**（同实体表内按 `source_id` 分行；表边界按**实体语义**定）· **C**. 维持表级但为四域开例外
- 决议：**B** —— 原则 1 改为**每条记录只有一个写入来源**（粒度＝业务键），§2 补五条多源子条款（表组按实体切分 / 行级 `source_id` / 覆盖差异显式化 / 跨源重复归一化且 ID 由 L0 生成 / 与 §3 的边界）；`as_of` 随之为「一域多源取各源水位的**保守下界**（`min`）」；`indicator_source_map(indicator_key, source_id, source_api, api_field)` 承载多源字段映射（**纯增量**：不动主键、不改既有种子口径，DDL 随机制立项）。**§3 保留不动**——与既有域同域同语义的平行替代源仍按其走独立源表 + 聚合视图。见 [决策日志 D-030](决策日志.md)

## Q-005 · decided (D-031) · 出现于 [L1 册 `C1`](遗留问题/L1-遗留问题.md) 收口评估 · 2026-09-27 裁定

**公告全文 / 舆情问答 / 新闻等**文本类**信息，是否单独以文件形式落盘存储（而非仅入库表列）？查阅接口归谁？RAG 索引的事实源与归属如何界定？**

由来：负责人 2026-09-26 提出——文本类信息单独整理为文件存储，便于后续接入 **RAG** 与 **AI 自主查阅文档**。

**已核实的就绪底座（无技术阻塞）**：

- [02 §2.1](../docs/技术架构-v2/02-L0-本地优先基座.md) 的 `data_cache` 分区内容**已明列**为「市场数据快照（**公告**/行情/龙虎榜/股东/**舆情**）」——四域本就在分区设计内，**不需新分区**。

- [02 §2.3](../docs/技术架构-v2/02-L0-本地优先基座.md) 损坏恢复按分区粒度；[T-L0-006](tasks/done/M0/T-L0-006-备份恢复完全清空数据留存策略.md) 备份已支持 `data_cache` **可选**纳入归档。

**未定的规格（须人决）**：

① **文件与表的关系**——正文落文件、元数据（title / type / date / code / url / 路径）落表（「文件为主 + 表为索引」），还是两者冗余？事实源只能有**一个**；「表在而文件缺」与「文件在而表缺」两种不一致各走什么状态（`unavailable` 抑或损坏告警）？
② **寻址与证据引用**——`announcement_id`（[01 §1](../docs/技术架构-v2/01-平台共享契约.md) 已登记由 L0 数据缓存产生）与文件路径的双向映射；路径须稳定可复核，而 `EvidenceRef.ref` **≤128 字符**——证据引用继续用 `announcement_id`（路径由其确定性派生），还是直接用路径？
③ **查阅面归属**——L1 沙箱对越界（读文件属三项权限之一）须**声明 + 批准**，故 Skill **不能**直接 `open()`；文档读写接口应作为 L0 的鸭子类型取数面（对齐 `MarketDb.query` 的既有范式，见 [03 §2](../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的官方 Pack 执行面），由 L1 经注入消费。接口形态（列目录 / 读单篇 / 关键词检索 / 范围内全文检索）待定。
④ **RAG 索引的地位**——向量索引是**派生数据**（可由文件重建）而**非事实源**；其落点（L0 / L2 记忆图谱 / 后续独立面）与重建口径须显式，否则会被误当事实源。
⑤ **备份范围**——档案型文本（公告）在源端失效后**不可重取**（参照仓库自述：通达信 K 线 2026-09 失效、网易财经整站下线）；是否应从 `data_cache` 的**可选**备份升为**默认纳入**？（若升，属对已 `done` 的 [T-L0-006](tasks/done/M0/T-L0-006-备份恢复完全清空数据留存策略.md) 的口径修订。）

- 候选：**A**. 文件为主 + 表为索引（正文落 `data_cache` 文本目录，表存元数据与路径）· **B**. 仅入库表（正文存表列）· **C**. 文件与表冗余双写
- 影响任务：待立项的「多源信息面采集与管理机制」（[L1 册 `C1`](遗留问题/L1-遗留问题.md) 的承接方）；[T-L0-006](tasks/done/M0/T-L0-006-备份恢复完全清空数据留存策略.md)（备份范围，本决议**不改**其口径）
- 决议：**逐项定**（编号对应上文「未定的规格」①②③④⑤）——
  - **① 承载形态**：**A** ＝「**表行（元数据 / 可查询索引）＋文件（正文）**」两段构成**一条记录**，两段**同源同现**。**不**取 B（大文本进 SQLite 列，查询与备份双输）、**不**取 C（正文无冗余必要）。一致性判据：**表在而文件缺 → 损坏**（走分区恢复）；**文件在而表缺 → 孤儿**（可回收）——不静默当作有数据
  - **② 寻址与证据引用**：证据引用持 **L0 生成的 `announcement_id`**，**文件路径由其确定性派生**（`<域>/<代码>/<日期>/<id>.txt`）→ `EvidenceRef.ref` 恒有界，**无需**为路径另设规则。`announcement_id` 形态＝**业务键（代码 + 标题 + 披露日期）的确定性摘要**：跨源的同一公告得**同一 ID**（天然去重，合 [D-030](决策日志.md) 的「ID 由 L0 生成、不沿用源方 ID」），已写入 [01 §1](../docs/技术架构-v2/01-平台共享契约.md)
  - **③ 查阅面归属**：**L0 提供鸭子类型「文档取数面」**（`list_docs` / `read_doc` / `search_docs`，与 `MarketDb.query` **同构**），L1 经**注入**消费；**Skill 不直读文件**，故**不涉** `local_read:<path-scope>`（该权限针对**缓存外**文件）。理由：与官方 Pack 的既有范式一致（`GWT-5` 以 AST 断言执行器不 import `st_agent.l0.*`），且「文件缺失 → `unavailable`」的判定**只在 L0 一处**，不让每个 Skill 各判一套
  - **④ RAG 索引**：**是派生数据、不是事实源**（可由文件重建）→ **不参与** `as_of` / 快照口径，**不得**作证据引用目标。**落点延后**——是 `data_cache` 子目录还是新分区，留待真正做 RAG 时定（避免为一个尚未建的能力先动 [02 §2.1](../docs/技术架构-v2/02-L0-本地优先基座.md) 的分区表）
  - **⑤ 备份范围**：**维持按分区、`data_cache` 整体可选**的既有一口径，**不**引入子路径粒度（那会改动已 `done` 的 [T-L0-006](tasks/done/M0/T-L0-006-备份恢复完全清空数据留存策略.md)）；改为**强制风险提示**——「`data_cache` 未纳入备份时，档案型文本在源端失效后**不可恢复**」。**触发复核**：机制立项定下同步范围后，若文本体量可接受则改默认纳入
  见 [决策日志 D-031](决策日志.md)

## Q-004 · decided (D-032) · 出现于 [L1 册 `C1`](遗留问题/L1-遗留问题.md) 收口评估 · 2026-09-27 裁定

**四域带回的标的中，[`security`](../docs/数据库设计-BaoStock数据层/schema.sql) 主档未收录的代码（北交所 `920xxx` / `8xxxx` 等）如何处理？**

核查证据（2026-09-26）：

- [数据库设计 §多源扩展规约 §1](../docs/数据库设计-BaoStock数据层/00-设计总览.md)：「新源的证券代码一律映射进 `security` 主档（`sh./sz.` 格式），**不另建证券表**」。
- [`security` DDL](../docs/数据库设计-BaoStock数据层/schema.sql) 主键 `code` 注释为「`sh.600000` / `sz.000001` / 指数代码」，由 BaoStock `query_all_stock` 落数，**未登记 `bj.` 前缀**。
- 开源仓库 [`a-stock-data`](https://github.com/simonlin1212/a-stock-data) 专门处理了此类代码（其 #46 修复：`get_prefix()` 覆盖 `51x` 沪 ETF / `900x` 沪 B / `920x` 北交所，并指出硬编码前缀会把它们判错）；**龙虎榜、舆情热榜会带回北交所标的**。
- **BaoStock 实测不出北交所**（2026-09-27 核）：[BaoStock API 手册](../docs/BaoStock-API手册/README.md) **全目录无**「北交所 / 北京证券 / `bj.`」字样，其 `code` 说明一律为「`sh` 或 `sz` + 6 位数字」→ 候选 A 的「须 BaoStock 支持」这一支**不成立**，只能另源补主档。
- **外键是硬的**（[schema.sql](../docs/数据库设计-BaoStock数据层/schema.sql)）：域表 `code TEXT NOT NULL REFERENCES security(code)`，且同文件首行 `PRAGMA foreign_keys = ON` → 未收录代码**插不进去**，**一条记录即可让整批同步失败**（故必须**预过滤**，不能靠 DB 报错兜底）。

影响：不解决则产生**悬空 code**（违反规约 §1）或**静默丢数据**；决定 `security` 的覆盖面及其同步任务是否扩展。

- 候选：**A**. 扩展 `security` 覆盖 `bj.`（须 BaoStock 支持或另源补主档）· **B**. 过滤未收录代码并在载荷显式标注 · **C**. 四域表允许多前缀、放宽 `security` 外键
- 影响任务：待立项的「多源信息面采集与管理机制」；若取 A，牵动 [T-L0-005](tasks/done/M0/T-L0-005-数据源缓存BaoStock首个源落地.md) 的主档同步面
- 决议：**B** —— **过滤未收录代码 + 显式计数与标注**；**不为单个源补建主档行、不放宽外键、不静默丢**。要点：
  ① **必须预过滤**（按 `security` 成员判定），**不得**靠 FK 报错兜底——`PRAGMA foreign_keys=ON` 下一条北交所记录即可炸掉整批同步
  ② **过滤可见**：载荷携 `filtered_unmapped` 计数与样例代码；同步任务按 `sync_state.last_status='partial'`（「任务完成但校验未全部通过」）登记
  ③ **已知空集 ≠ 数据缺失**：未覆盖交易所的标的在四域表中恒为空，消费面须能区分二者
  ④ **等价于**：产品数据面**暂定为沪深两市**（与 `security` 既有覆盖面一致），北交所不覆盖。这是**产品范围**判断；若要求覆盖，走候选 A——为 `security` 引入**第二个主档来源**并补主档融合规则（属契约级变更，见 [01-核心实体层](../docs/数据库设计-BaoStock数据层/01-核心实体层.md)）
  拒 **A**：主档权威来源须唯一；为四域补录会让 `security` 变成多源融合体，而融合规则（权威优先级 / 字段补全 / 退市同步）尚无口径——为一个「副产品」付 §3 级的工作量不划算。拒 **C**：§1 是刚在 [D-030](决策日志.md) 里被强化的原则，开豁免口子会让域表 `code` 变成「有时有主档、有时没有」，成本分摊到**所有**消费方。
  见 [决策日志 D-032](决策日志.md)

## Q-002 · decided (D-029) · 出现于 T-L1-004.3（C1 收口评估）· 2026-09-26 裁定

**信息面（公告 / 龙虎榜 / 股东变化 / 舆情）的采集通道归谁：L0 数据源网关直抓、story-08 的官方 MCP Server、还是两者分工（谁主谁备）？**
