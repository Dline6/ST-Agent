## Q-001 · decided (D-005) · 出现于 T-L1-001.5

**运行时组合根未定义：谁装配 `EndpointRegistry` / `CredentialVault` / `LlmClient` 并注入 `SkillRunner`？`provider → host` 映射（`llm_transport` 的入参）归哪一层持有？**

核查证据（2026-09-26）：
- `tasks/` 与 `docs/` 全量检索，`LlmClient` / `EndpointRegistry` / `CredentialVault` 仅出现在 T-L0-002/003/004、T-L1-001.2 等**已 done** 任务的实现描述中；**无任何未完成任务**承载它们。
- 最接近的调用方 [T-L3-002](tasks/T-L3-002-意图理解与澄清协议任务派发总线.md)（派发总线）与 `T-L1-005`（定时调度）均为 bootstrap 空壳，未提端点注册表/凭据库/组合根。
- `src/st_agent/` 只有 `contracts/` `l0/` `l1/`，无 app/装配层；docs 无「装配 / 组合根 / 启动顺序」定义。

影响：T-L1-001.5 的 LLM 出网路径（`SandboxedGateway.llm_transport` + `provider_hosts`）无法自定归属；同理 T-L1-005（调度触发执行）、T-L4-002（视角编排调度）、T-L3-002（派发总线）都会撞上「谁来建 `LlmClient`」。

- 候选：A. `provider_hosts` 暂归 L1 沙箱（按 01 §7 `ConfigEntry` 形态持久化于 `config/`），组合根另立新任务 · B. `provider_hosts` 归 L0 端点配置（扩展 02 §4 `LlmEndpoint` 或平行 `ConfigEntry`），随 T-L0-003 面返工 · C. 在 T-L1-001.5 内建最小组合根（越出 .5 声明范围）· D. 组合根单立任务、并入 L3 之前（`depends_on` 指向 L0-002/003 + T-L1-001）
- 影响任务：T-L1-001.5（当前 blocked）, T-L3-002, T-L1-005, T-L4-002
- 决议：**A** —— `provider → host` 映射暂归 L1 沙箱（01 §7 条目形态，`config/llm-provider-host/`）；运行时组合根新立 `T-L1-006` 承载装配并复核迁移。见 [决策日志 D-005](决策日志.md)
