# T-L1-001.5 · 沙箱接线 SkillRunner 注入

## 目标
兑现 T-L1-001.3 遗留①②：把执行沙箱真正接进 `SkillRunner` 的一次执行——禁用 Skill 直接拦截、执行器拿到的 `ctx.gateway` 为受限出口、经 `ctx` 暴露会话供文件/命令出口核对，并补齐 LLM 出网路径（`SandboxedGateway.llm_transport` + `provider → host` 映射落配置）。

## 验收标准（Given-When-Then）
- GWT-W1（禁用生效）：Given 某 Skill 已被 `sandbox.disable`，When 经 runner 执行，Then 直接 `validation_failed` 拦截且执行器不被调用。
- GWT-W2（网络出口受限）：Given runner 已接沙箱，When 执行器用 `ctx.gateway` 向声明外主机出网，Then 拦截 + `BehaviorViolation` 留痕 + 底层 sender 未被触碰。
- GWT-W3（文件/命令出口受限）：Given runner 已接沙箱，When 执行器经 `ctx` 会话读取声明外路径或执行未批准命令，Then 拦截 + 不执行原操作。
- GWT-W4（LLM 路径受限）：Given 端点 provider 的目标主机不在声明 `net_access` 内，When 执行器经受限 transport 发起 LLM 调用，Then 拦截 + 不触碰底层 sender；`provider → host` 映射可按 01 §7 条目形态持久化并读回。
- 回归：不接沙箱时 `SkillRunner` 行为与现状一致（ctx 句柄原样透传）。

## 假设与前提
- A1 沙箱经 `SkillRunner` 可选参数注入（`sandbox=None` 时行为与现状完全一致、`ctx` 句柄原样透传）/ 若错：接线形态返工 / 验证：回归用例（不接沙箱时 ctx 句柄同一性断言）
- A2 禁用拦截在 runner 内、执行器调用前生效，走 `validation_failed` / 若错：拦截点返工 / 验证：GWT-W1
- A3 LLM 路径取**行为性代理**（`session.guard_llm(...)`，在 `invoke` 边界核对）——因 .2 约定注入的 `LlmClient` 其 transport 在构造时已绑定真网关，runner 无法重建 / 若错：需改 .2 的 `SkillContext` 契约 / 验证：GWT-W4
- A4 `SandboxedGateway.llm_transport(provider_hosts)` 作为结构性 API 一并交付，供未来由组合根构建 `LlmClient` 的调用方使用；本任务 runner 路径不依赖它 / 若错：API 面返工 / 验证：单测 + 与真网关行为对齐
- A5 `SkillContext` 增 `sandbox` 字段承载受限会话（L1 内部模型，不动 01 契约）/ 若错：执行器接口返工 / 验证：GWT-W3
- A6 `provider → host` 映射按 [Q-001](../阻塞与未决.md) 决议（[D-005](../决策日志.md)）由 L1 沙箱持有，按 01 §7 `ConfigEntry` 七字段形态持久化于 `config/llm-provider-host/<provider>.json`；最终归属由 `T-L1-006` 复核，本任务不臆测迁移 / 若错：映射归属迁移（新增 D-NNN supersede D-005）/ 验证：GWT-W4 读回断言
