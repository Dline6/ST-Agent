# T-L3-007 · 意图目标解析与可派发性守门

## 目标

修掉「**确认卡可以在派发必然失败的状态下被确认**」这一类问题：需要目标 Skill 的去向（`query` / `configure`）在自然语言输入下从来没有目标解析，确认口也不校验，于是用户点了「确认并执行」才收到 `validation_failed`（现象见执行日志 `[T-L3-007]` 的现场：输入「帮我同步ST股票名单」→ 卡上目标「未指定」→ 派发报「query 去向缺少目标 Skill 标识」）。

## 验收标准（Given-When-Then）

- **GWT-1 · 目标补位**：Given 理解端口对一段自然语言给出 `intent` ∈ {`query`, `configure`} 且 `target` 为空，When 收敛，Then 用注入的 `matcher` 对用户原话做**确定性匹配**（`SkillRunner.match` 的 bigram 口径，重叠 ≥ 2），命中即补为该 Skill 标识、确认卡上以来源「匹配」标注；确认后派发**真跑到该 Skill**，信封原样透出。
- **GWT-2 · 补不上就不出卡**：Given 匹配未达阈值 / 未注入 `matcher` / 目标标识不存在，When 收敛，Then **不产确认卡**（`needs_confirmation=False`），返回带原因的澄清轮或空态；**不伪造目标**、不把失败推迟到派发。
- **GWT-3 · 目标未声明的参数不进 values**：Given 目标已确定而其描述体未声明理解端口抽出的某个参数（如 `action=同步`），When 出卡，Then 该键**不进** `values`，卡上以来源「未采用」显式呈现（不静默丢弃）。
- **GWT-4 · 派发口不炸**：Given 目标标识形态非法或未注册（如缺版本后缀），When 派发，Then 返回 `validation_failed` 信封，**异常不穿透**调用方。
- **GWT-5 · 既有路径逐字不变**：Given 快捷指令短路、未注入 `matcher` 的组合根、以及不需要目标的去向（`analyze` / `train` / `investigate` / `explain` / `memory_op`），When 收敛与派发，Then 行为与改动前一致（既有用例全绿）。

## 假设与前提

- **A1 · 补位属「确定性推导」而非「代替用户选择」**：匹配结果在确认卡上明示、用户确认后才执行，故不违背 [05 §3.1](../../docs/技术架构-v2/05-L3-对话主入口.md) 的「理解提示词不含能力清单」（该口径约束的是**提示词**，不是理解之后的本层处理）；快捷指令路径已在同一层用同一个 `_match` 先例（[protocol.py](../../src/st_agent/l3/intent/protocol.py) 的 `_from_command`）。若错（改判禁止补位）：返工面＝GWT-1 整条删除，只留守门，自然语言查询仍不可用。
- **A2 · 重叠阈值 ≥ 2 足以避免误配**：实测输入「帮我同步ST股票名单」→ `sk_st_list_sync` 重叠 **3**、其余技能全 **0**。若错（误配率上升）：返工面＝阈值常量与 GWT-2 用例。
- **A3 · 未注入 `matcher` 的调用方行为不变**：绝大多数既有单测与历史组合根不注入 `matcher`，补位分支须在缺省时**静默跳过**（不报错）。若错（单测批量红）：返工面＝补位分支的缺省路径。
- **A4 · 本次不改 01 平台共享契约、不触 LLM 出网面**：改动在 L3 内部与 [05](../../docs/技术架构-v2/05-L3-对话主入口.md) 口径，未动 `l0/llm/**` / `l0/net/gateway.py` / `l1/runtime.py` 的 LLM 装配段，故**不触发** `pytest -m live` 轴。若错（被判定为契约变更）：补 01 变更并改跑全量。
