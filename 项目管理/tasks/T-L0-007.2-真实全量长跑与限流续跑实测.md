# T-L0-007.2 · 真实全量长跑与限流续跑实测

## 目标
用 [T-L0-007.1](T-L0-007.1-脚本化全量同步与续跑语义.md) 交付的长跑脚本，在**真实网络**上跑一次全市场首次全量同步（`run_all`，1990 年起），观测限流与中断续跑，产出**真实数据基线**（各域水位、行长、耗时、体量）替代一次性手工操作。

## 验收标准（Given-When-Then）
- GWT-0 真实链路冒烟（小样本，先行）：Given 真网络 + 真实加密库，When 依次跑 `setup` → 日历 → 证券主档 → 全量快照 → 3 只真实 A 股日线全历史，Then 各步 `ok`、数据面非空、抓取全部经网关留审计、盘上无明文——证明整条管道可用。
- GWT-1 全量首次同步：Given 全新 `data_cache` + 真实网络，When 跑 `run_all`（元数据、K 线、财务、板块、宏观各域），Then 逐表水位推进至当前交易日，`freshness_verdict` 各域非 `stale`，抓取全部经 L0 网关留审计。
- GWT-2 限流与续跑：Given 源端限流或中途中断，When 重跑同一任务，Then 增量续跑不重复写、水位单调不回退、失败留有可查原因（不静默失败、不用旧数据冒充新数据）。
- GWT-3 基线记录：Given 长跑完成，When 查脚本摘要，Then 长跑耗时与各域数据量基线记录在案（可与他机复跑对比）。

## 假设与前提
- A1 源端在当前速率下不触发硬限流 / 若错：需分批 + 退避驱动（当前引擎无退避、且码分片会因全局水位跳历史），全量长跑须先补该能力 / 验证：冒烟实测 3 码 × 全历史未见限流（日志 [T-L0-007.2]）；全量运行时复核
- A2 真实数据只落本地加密库与 pytest 临时目录，不进 Git / 若错：违反数据主权红线，按 [Git协作规范 §7.4](../Git协作规范.md) 安全事件处理 / 验证：冒烟后全盘明文扫描 0 命中、`git status` 无真实库
- A3 小样本冒烟可代表全市场链路可用性（同一管道，仅码数与时长不同）/ 若错：须全量重跑才能证实 / 验证：冒烟覆盖 `setup` / 日历 / 主档 / 全量快照 / 日线五类调用与网关审计
- A4 `run_task` 直调须先 `setup()`（`run_all` 内部会调，直调则须显式）/ 若错：调用方漏 setup → 得到显式 `unavailable`（失败显式化已覆盖，不会静默）/ 验证：冒烟首跑即踩到该点并据报错修正，第二跑通过
