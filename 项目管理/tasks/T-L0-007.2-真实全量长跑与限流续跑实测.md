# T-L0-007.2 · 真实全量长跑与限流续跑实测

## 目标
用 [T-L0-007.1](T-L0-007.1-脚本化全量同步与续跑语义.md) 的长跑脚本 + [T-L0-017](T-L0-017-BaoStock长跑能力分批写入断点续跑与重试退避.md) 的分批 / 续跑 / 退避能力，在**真实网络**上跑一次**全市场首次全量同步**，观测限流与中断续跑，产出**真实数据基线**（各域水位、行长、耗时、体量）替代一次性手工操作。

**窗口口径（2026-10-04 人定，取代原「1990 起全历史」）**：K 线类任务的取数起点降级为**近一年**（滚动窗口，起点由脚本 `--start` 显式给出，收工记录实际取值）。理由：① 全历史实测单码 15–22s、全市场 ≈85h 且逐码整库加解密使其再翻数倍，而近一年单码仅 0.8–1.7s（726 行）；② 近一年下每码行数 < 页大小（2000），**不触发翻页**，静默截断风险随之归零；③ M1 的数据面需求不依赖 1990 年起的历史深度。**全历史回填另立**，登记于 [L0 册](../遗留问题/L0-遗留问题.md) C 段（归属＝人决），不留在本任务的隐性缺口里。

## 验收标准（Given-When-Then）
- GWT-0 真实链路冒烟（小样本，先行）：Given 真网络 + 真实加密库，When 依次跑 `setup` → 日历 → 证券主档 → 全量快照 → 3 只真实 A 股日线全历史，Then 各步 `ok`、数据面非空、抓取全部经网关留审计、盘上无明文——证明整条管道可用。**（2026-09-26 已通过，见执行日志 `[T-L0-007.2]`）**
- GWT-1 全量首次同步（近一年窗口）：Given 全新 `data_cache` + 真实网络，When 跑 `run_all`（元数据、K 线、财务、板块、宏观各域，K 线类起点＝近一年），Then 逐表水位推进至当前交易日，`freshness_verdict` 各域非 `stale`，抓取全部经 L0 网关留审计。
- GWT-2 限流与续跑：Given 源端限流 / 断连或中途中断，When 重跑同一任务，Then 增量续跑不重复写、水位单调不回退、失败留有可查原因（不静默失败、不用旧数据冒充新数据、不入库半截结果集）。
- GWT-3 基线记录：Given 长跑完成，When 查脚本摘要，Then 长跑耗时与各域数据量基线记录在案（可与他机复跑对比），并记录实际使用的窗口起点与分片参数。

- A1 近一年窗口下每码行数 < 页大小（2000）⇒ 不翻页、不触发静默截断路径 / 若错：少数码行数超页时走 [T-L0-017.2](T-L0-017.2-抓取韧性与截断检测.md) 的截断复核分支，不影响正确性 / 验证：真跑统计每码行数分布（摘要含行数与水位）
- A2 真实数据只落本地加密库与 pytest 临时目录，不进 Git / 若错：违反数据主权红线，按 [Git协作规范 §7.4](../Git协作规范.md) 安全事件处理 / 验证：真跑后全盘明文扫描 0 命中、`git status` 无真实库
- A3 小样本冒烟可代表全市场链路可用性（同一管道，仅码数与时长不同）/ 若错：须全量重跑才能证实 / 验证：冒烟覆盖 `setup` / 日历 / 主档 / 全量快照 / 日线五类调用与网关审计（**已成立**）
- A4 `run_task` 直调须先 `setup()`（`run_all` 内部会调，直调则须显式）/ 若错：调用方漏 setup → 得到显式 `unavailable`（失败显式化已覆盖，不会静默）/ 验证：冒烟首跑即踩到该点并据报错修正，第二跑通过（**已成立**）
