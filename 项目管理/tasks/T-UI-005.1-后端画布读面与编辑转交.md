# T-UI-005.1 · 后端画布读面与编辑转交

## 目标

在组合根与回环服务上交付 Studio 画布页的**后端面**，令前端只取描述、不碰层类型：

1. **契约先行**（[铁律 8](../工程宪法.md)）：[01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 新增 `studio_canvas` 型 + `contracts/ui_description.py` 的 `ComponentType` / `IMPLEMENTED_COMPONENT_TYPES` + `ui/registry.py` 的 `REQUIRED_SLOTS`（必填槽：`canvas` + `labels`）。
2. **组合根适配面**（`src/st_agent/app.py` 的 `ReflectionFacade` 只增）：`studio_sessions()`（已交会话一览）· `studio_canvas(proposal_id)`（画布描述就绪结构）· `studio_edit(proposal_id, op, args)`（六个编辑操作转交）· `studio_skills()`（可选 Skill 清单，供加节点下拉）。
3. **回环端点**（`ui/server.py` 路由表 + `ui/app.py` 的 `api_*` 只增）：`GET /api/studio/sessions` · `GET /api/studio/canvas?proposal_id=` · `GET /api/studio/skills` · `POST /api/studio/edit`；接受 / 否决**复用**既有两条路由（`/api/reflection/proposals/studio/decide`），本叶不另造。
4. **端到端**：`tests/integration/test_studio_canvas.py` 以**真组合根**钉住「提案 → 交 Studio → 画布读 → 编辑 → 接受落编辑后 DAG」。

**本叶的边界**（不越界）：**不出任何前端页面与渲染件**（归 [`.2`](T-UI-005.2-前端画布页与渲染件.md)）；**不动** `DraftIntake` / `CanvasEditor` / `EditResult` 的判定件（只调用，不复制）；**不动**周报 / 训练 / 待批准 / 提案卡的既有端点（逐字节不变）。

## 验收标准（Given-When-Then）

- **GWT-1 · 画布读面**：Given 一条已交 Studio 的提案，When `GET /api/studio/canvas?proposal_id=<id>`，Then 信封 `data` 为 `studio_canvas` 描述——`canvas.session`（proposal_id / base / 暂定 flow_id / 节点数 / 状态）与 `StudioDraftView` 一致，`canvas.nodes` / `edges` / `groups` 与该会话 `dag` 逐字段一致，`canvas.violations` 与首轮语义违规清单一致；**表现层不 import** 任何 L1 / L6 类型（`ui/**` 只经鸭子端口）。未交 Studio → `validation_failed` + 点名；子面未接线（`L6Stack.studio is None`）→ `unavailable` + 点名。
- **GWT-2 · 编辑转交**：Given 一条已交 Studio 的提案，When `POST /api/studio/edit`（`{proposal_id, op, args}`，`op` ∈ `add_node` / `remove_node` / `connect` / `disconnect` / `group` / `ungroup`），Then 经 `tune` 取**同一个** `CanvasEditor` 执行对应操作，回 `EditResult` 视图（`applied` / `message` / `blocked_by` / 新画布 + 全图校验结论）；用户级冲突一律 `applied=false` 表达（画布不变），**不抛异常、不转 `failed`**；未知 `op` / 缺键 → `validation_failed`；会话不存在 → `validation_failed` + 点名。
- **GWT-3 · 编辑后接受落编辑后 DAG**：Given 一条已交 Studio 且经 GWT-2 编辑过的提案，When 走既有 `studio_decide(action=accept)`，Then 落 v1.0 的 `flow_id` 对应 DAG **含本次编辑**（如新增节点在盘上可查），并产生 `change_id`；`reject` → 不落盘、值逐字节不变（复用 `T-L6-004.2` 口径，本叶只以用例钉住「编辑后」这一增量）。
- **GWT-4 · 未接线与输入类失败**：Given `reflection` 面未注入或 `StudioHandoff.available` 为假，When 访问本叶任一端点，Then `unavailable` + 点名（不 500、不伪造画布）；请求体缺 `proposal_id` / 非法 `op` → `validation_failed`（沿用 `T-UI-003` 的「回信封、不断连」口径）。
- **GWT-5 · 既有面回归**：Given 周报 / 训练 / 待批准 / 提案卡与既有两条 studio 路由，When 回归，Then 行为与返回**逐字节不变**（既有用例零改动仍绿）。

## 假设与前提

- **A1 · 编辑只转交、不重包**——前提：`CanvasEditor` 六操作已是公开 API 且口径齐备（[03 §4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)），除一致性（同一 `proposal_id` 同一会话，经 `tune` 取）外本叶不复制判定；`EditResult` 全函数（冲突即 `applied=false`）故转交层不抛异常。若错：返工面＝`studio_edit` 返回类型与 L1 三态对齐。**验证方式**：GWT-2 断被拦操作回 `applied=false` + 原因，信封仍为 `ok`（操作结论在载荷里，不在信封态里）。
- **A2 · 接受 / 否决不另造端点**——前提：`T-L6-004.2` 的 `/api/reflection/proposals/studio/decide` 已是「接受落 v1.0 / 否决不落盘」的通道，画布页的接受 / 否决是**同一动作换个入口**，故复用。若错（要求画布页独立通道）：返工面＝路由表与前端动作常量。**验证方式**：GWT-3 走既有 `studio_decide` 不断编辑后 DAG 落盘。
- **A3 · `params`（节点参数绑定）本批不开放编辑**——前提：B2 解封条件是「节点 / 连线 / 分组 / 校验违规 + 三态动作」，参数绑定是 Skill 级表单面（story-06 的参数面板），且 `ParamBinding` 的 `literal` / `ref` 形态经 POST 体易错。若错（要求本批可改参数）：返工面＝`studio_edit` 新增 `set_params` 操作 + 前端参数表单，应另立项。**验证方式**：GWT-2 的 `op` 枚举恰为六个结构操作，无参数操作；`grep` 断言本叶不碰 `params`。
- **A4 · 会话由组合根持有、跨请求经 `proposal_id` 寻址**——前提：[`T-L6-004.1 A2`](T-L6-004.1-L6侧翻译与Studio交接受体.md)（`StudioHandoff` 内存持会话）；表现层无状态（每请求重新按 `proposal_id` 找会话）。若错（要求会话跨重启存活）：返工面＝引入会话落盘，与「编辑期不落盘」正面冲突。**验证方式**：GWT-2 断同一 `proposal_id` 的 canvas → edit 两请求间会话延续。
