# T-L0-001 · 存储分区 · 落盘加密 · 损坏恢复

## 目标
实现 [02 §2](../../docs/技术架构-v2/02-L0-本地优先基座.md) 存储子系统：七个逻辑分区的分区注册与目录布局、全分区落盘加密（密钥由用户主密码派生）、分区级完整性校验与损坏恢复（最近备份恢复 / 无备份进入冷启动）。这是 L0 一切持久化（T-L0-002 secrets、T-L0-005 data_cache 等）的物理底座。

## 验收标准（Given-When-Then）
- GWT-1（分区独立性）：Given 已初始化的存储根，When 查看分区布局，Then 七个分区（memory / config / chat_history / execution_log / reflection / data_cache / secrets）各自独立成目录、可独立导出、可独立清空，互不混落数据。
- GWT-2（落盘加密与密码校验）：Given 用户主密码，When 初始化存储，Then 主密码经标准口令派生（PBKDF2）派生主密钥，全部分区内容以 AES-256-GCM 加密落盘，盘上无明文用户数据；`secrets` 分区在此基础上单独隔离（独立派生密钥），密钥材料不出现在其他分区；When 用错误主密码打开，Then 校验失败、拒绝打开、数据不被破坏，不设任何由产品方持有的恢复通道（密码丢失 = 数据不可恢复）。
- GWT-4（读写闭环）：Given 已解锁的存储，When 向任一分区写入再读回，Then 数据往返一致（加密对上层透明）；分区级校验和通过。
- GWT-5（损坏检测与恢复）：Given 任一分区数据被篡改/损坏，When 打开存储并校验，Then 该分区被标记损坏并明确报告损坏范围（分区名+原因），其余分区不受影响；配合最近备份可恢复该分区（备份恢复流程在 T-L0-006 按本任务的分区级校验和口径兑现）；无备份时明确告知丢失范围、进入冷启动流程（该分区重建为空、其余分区可用）。
- GWT-6（零接触）：Given 任意操作，When 检查存储根与日志，Then 无任何数据发送到产品方服务器，无产品方持有的密钥或后门（本地优先铁律）。

## 接口面
> 追补于 2026-09-26：本任务完成早于接口面机制落地，据已合入代码与执行日志回溯填写（非 ④ 对齐时填写）。
- 输入（消费的前置接口）：T-SC-001.1 契约包；外部依赖 cryptography（AES-256-GCM / PBKDF2-HMAC-SHA256）
- 输出（本任务交付的公共 API / 落盘位置）：
  - `st_agent.l0.storage`：`Store.create` / `.open` / `.put` / `.get` / `.delete` / `.list_files` / `.sealed_mtime` / `.export_partition` / `.wipe_partition` / `.reset_partition` / `.partition_state` / `.storage_report`
  - `PARTITIONS`：`memory` / `config` / `chat_history` / `execution_log` / `reflection` / `data_cache` / `secrets`（`secrets` 独立密钥派生）七分区
  - 错误类型：`StorageError` / `CryptoError` / `StorageOpenError` / `StorageCorruptionError`
  - 落盘：`<root>/<partition>/` 七分区目录 + 每分区加密清单 `manifest.bin`（分区级 SHA-256）
  - 消费方：全部 L0 子系统与 L1 运行时（构造注入 `Store`，层内不直连文件系统）

## 假设与前提

- A1 口令派生取 PBKDF2-HMAC-SHA256 / 600_000 迭代（OWASP 2023；02 §2.2 不锁定算法，安全评审可调） / 若错：换算法或迭代数即主密钥不兼容，需全部分区重建并返工 T-L0-002 会话密钥口径 / 验证：本任务 GWT-2 加密落盘 + 错密码拒绝测试已证实成立
- A2 `secrets` 分区用独立 salt 重走一遍 PBKDF2（隔离强度等同主密钥重设），而非 HKDF 子密钥 / 若错：隔离口径变化，需返工 `crypto.py` 派生路径 + T-L0-002 凭据落点 / 验证：本任务 GWT-2 secrets 隔离测试已证实成立
- A3 物理组织取每分区一个目录、每文件独立加密 / 若错：改容器布局，T-L0-005（data_cache blob）与 T-L0-006（备份归档）落点随之返工 / 验证：本任务 GWT-1 分区独立 + SQLite blob 往返已证实成立
- A4 损坏检测口径为每分区加密清单（SHA-256）+ GCM 认证，损坏定位到分区级 / 若错：换校验口径需返工 `manifest.py` + T-L0-006 备份校验入口 / 验证：本任务 GWT-5 篡改/缺失/清单损坏三类测试已证实成立
- A5 备份恢复流程不在本任务（T-L0-006 按分区级校验和口径兑现）；无备份时损坏分区冷启动重建为空 / 若错：本任务补备份归档，验收口径随之变化 / 验证：本任务 GWT-5 冷启动重建测试已证实成立；备份口径待 T-L0-006 定义时复核
- A6 KDF 迭代数是性能敏感参数（600k 本机约 0.3s/次），登录态会话密钥缓存复用同一口径 / 若错：T-L0-002 登录态设计返工 / 验证：待 T-L0-002 定义会话密钥缓存时复核（当前成立：单次派生成本可接受）
