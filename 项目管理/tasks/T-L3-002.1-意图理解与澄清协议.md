# T-L3-002.1 · 意图理解与澄清协议（§3）

## 目标

兑现 [05 §3](../../docs/技术架构-v2/05-L3-对话主入口.md)：把一段用户输入收敛为 **§3.1 六类意图之一 + 派发目标**，模糊处按 **§3.2 澄清协议**追问（预算 ≤3、每题可跳过），收敛后产出**意图确认卡**（「我理解到 N 件事」）。本叶交付**协议与结构**（确定性、可测），理解本身的实现口径见 `## 假设与前提` A1。

## 验收标准（Given-When-Then）

- **GWT-1 · 意图分类到 §3.1 六类**：Given 一段用户输入与一个理解产物，When 收敛，Then 落 [§3.1](../../docs/技术架构-v2/05-L3-对话主入口.md) 六类意图之一并给出该类的**派发目标**；无法确定时**不硬猜**（走 GWT-4）。意图词汇复用 [`INTENT_KINDS`](../../src/st_agent/l3/commands/registry.py)，**不新造第二套**。
- **GWT-2 · 快捷指令短路**：Given 以 `/` 开头且命中注册表的输入，When 处理，Then 直接取该指令的意图模板与参数预填（[§8](../../docs/技术架构-v2/05-L3-对话主入口.md)），**已预填的参数不再追问**；未命中仍走普通理解路径（不静默当普通消息，[`resolve`](../../src/st_agent/l3/commands/registry.py) 的 `empty` 原样透出）。
- **GWT-3 · 澄清预算 ≤3 且可跳过**：Given 目标有若干未澄清的关键参数，When 生成追问，Then 问题数 **≤3**；每个问题**可跳过**，跳过即以默认值继续；超出预算的未澄清项以默认值填充并在确认卡上**显式标注「默认值」**（不静默替用户决定）。
- **GWT-4 · 无法收敛给 3 个方向**：Given 意图过于模糊（理解端口不解 / 候选不足），When 无法收敛，Then 给出 **≤3 个可能方向**而非强行猜测；理解端口**不可用**时走 `unavailable` + 原因（不静默失败）。
- **GWT-5 · 意图确认卡（确认前不派发）**：Given 澄清完成（含全部跳过），When 收敛，Then 产**意图确认卡**——结构化的「我理解到 N 件事」条目（`N ≥ 1`）+ 默认值来源标注；状态为**未确认**，[`T-L3-002.2`](T-L3-002.2-任务派发总线.md) 只接受已确认的卡。卡面文案（含追问、方向候选）过 [01 §6](../../docs/技术架构-v2/01-平台共享契约.md) 执行点 2 `check_output`，**命中即阻断**。

## 假设与前提

- **A1 · 理解（文本 → 意图）经注入端口，本叶另交付一个 LLM 实现**：[05 §3](../../docs/技术架构-v2/05-L3-对话主入口.md) 未规定理解实现。本叶把理解做成注入的 `IntentUnderstander` 端口（缺省 fail-closed），**并交付一个经注入 [`LlmClient`](../../src/st_agent/l0/llm/client.py) 的 LLM 实现**（结构化提示词 → `IntentDraft` JSON），使 M1 关卡有可跑的默认路径；离线单测用 Fake 端口与 Fake transport。若错（须改由调用方自备理解实现 / 或须纯规则实现）：返工面＝本叶 `protocol.py` 的理解实现部分 + M1 关卡的装配。
- **A2 · 澄清问题取自目标 Skill 的声明参数**：[05 §3.2](../../docs/技术架构-v2/05-L3-对话主入口.md) 只说「关键参数缺失→追问」。本叶把「关键参数」落为**目标 `SkillDescriptor.parameters` 中未给出值的项**（一问一参、跳过取 `ParameterSpec.default`），使「跳过用默认值继续」有确定的来源（[01 §2](../../docs/技术架构-v2/01-平台共享契约.md) 参数本就带默认值）。若错（须由理解方自由产问题）：返工面＝`ClarificationQuestion` 的构造面。
- **A3 · 「3 个可能的方向」来自理解产物的 `directions`**：[05 §3.2](../../docs/技术架构-v2/05-L3-对话主入口.md) 未说方向候选从哪来。本叶取理解端口产物自带的 `directions`（本层只裁剪到 ≤3 条 + 中性改述）；不为此扩 L1 `match` 的 API（那会让本叶依赖一个不存在的返 top-N 口）。理解端口 `unavailable` 时**不给**方向（无从给出），走 `unavailable` + 原因——**不降级为「拿官方指令充数」**。若错：返工面＝方向候选的取源。
- **A4 · 确认卡与 §5 `understanding_summary` 同源**：[05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 的 `ConfigDraft.understanding_summary` 说明其是「『我理解到 N 件事』的内容源」。本叶产出的确认卡条目列表即该字段的内容源，`T-L3-003` 直接消费，**不另造第二份摘要**。若错：返工面＝`IntentConfirmation` 的条目结构与 §5 草稿的对接。
