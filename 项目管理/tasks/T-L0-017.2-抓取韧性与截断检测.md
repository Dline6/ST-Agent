# T-L0-017.2 · 抓取韧性与截断检测

## 目标
让引擎能分辨「源端网络/会话故障」与「调用方缺陷」：对前者**退避重试**（含会话重建），对后者如实失败；并杜绝「结果集被静默截断却记 `ok`」。2026-10-04 真网实测：源端会在数次查询后强断连接（`WinError 10054`），客户端 `next()` 遇到翻页收发失败时**返回 `False` 而 `error_code` 仍为 `0`**（[`resultset.py`](https://pypi.org/project/baostock/) 的 `BAOSTOCK_PER_PAGE_COUNT = 2000`），同一只 `sz.000001` 因此首次只返 **4000** 行（恰 2 页）、重测两次均 **8664** 行——而引擎当下会把半截数据当成功入库。

## 验收标准（Given-When-Then）
- GWT-1 `error_code` 保留：Given 源端返回非 0 `error_code`，When 抓取失败，Then 异常对象与失败原因里**带上 `error_code` 原文**（可机器识别），不再只剩 `error_msg`。
- GWT-2 错误分类：Given 网络 / 会话类（`10002xxx`、`10001005` 登录数上限）与参数类（`10004006`–`10004008`）错误，Then 前者判**可重试**、后者**立即失败不重试**（不用重试掩盖调用方缺陷）。
- GWT-3 退避重试：Given 可重试错误连续发生，When 重试，Then 按**指数退避 + 次数上限**；用尽仍失败 → 任务 `failed` 且原因可查；**每次重试各经一次网关审计**（`data_fetch` 条数如实增长，不合并、不隐藏）。
- GWT-4 连接重建：Given 源端强制关闭连接，When 后续抓取，Then 会话自动重建并成功，**不因一次断连毁掉整批 / 整任务**。
- GWT-5 截断检测：Given 结果集行数恰为页大小（2000）整数倍——正常收尾与「下一页静默收发失败」在该形态下不可区分，When 判定，Then 复核一次；两次行数 / 末行不一致 → 判失败（**不静默入库半截数据**，对齐 GWT-2「不用旧数据冒充新数据」的 007.2 口径）。

- 输入（消费的前置接口）：

  - T-L0-005 [`sync.py`](../../src/st_agent/l0/market/sync.py)：`_via_gateway`（抓取唯一出口；重试须逐次经此）
  - T-L0-004 [`gateway.py`](../../src/st_agent/l0/net/gateway.py)：`EgressGateway.execute(kind="data_fetch", …)`（重试＝多次 execute，审计条数如实增长）
- 输出（本任务交付的公共 API / 落盘位置）：
  - `FetchError.error_code`（只读属性，缺省 `None`；消息形态保持可读）、`FetchError.retryable`（或等价的分类函数）与错误码分类表（网络 / 会话类 vs 参数类）

## 假设与前提
- A1 `error_code` 的语义分类（`10002xxx` 网络、`10001005` 登录数上限、`1000400x` 参数）取自 baostock 客户端常量表（[`common/contants.py`](https://pypi.org/project/baostock/)），**不是**本品自定 / 若错：分类表按实测修正，分类函数是唯一落点 / 验证：用例逐码钉住分类；真跑时记录实际遇到的错误码分布
- A2 「行数为页大小整数倍」是静默截断的**可判定形态**（正常收尾的末页必然不足一页，除非总数恰为整数倍——此时复核一次的成本＝一次重复抓取）/ 若错：假阳性只增加一次抓取，不影响正确性 / 验证：用例构造「恰 2000 / 恰 4000 行」与「2001 行」三态
- A3 重试仍走网关唯一出口：每次重试是一次独立 `execute`，审计条数如实增长——**不**为「看起来干净」而合并审计 / 若错：违 [02 §6](../../docs/技术架构-v2/02-L0-本地优先基座.md) 唯一出口与如实留痕 / 验证：用例钉住「审计条数 = 抓取次数（含重试）」
- A4 会话重建只影响抓取器实现，不改 `Fetcher` 协议的调用形态（测试注入的 Fake 不受影响）/ 若错：协议面变更须同步 `T-L0-005.1` 接口面与全部 Fake / 验证：既有 `tests/l0/` 全绿
