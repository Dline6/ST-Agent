# T-L3-004.1 · 推理链时间线渲染件

> **本叶是 M1 关卡的点名项**：[`T-INT-002`](T-INT-002-M1集成关卡首次可对话.md) 的验收明列「推理链可视化可展开到证据」（原文「点击『推理链』→ 展开完整推理过程，每一环可点开细看」）。

## 目标
交付 **`trace_timeline`** 组件的**描述件 + 渲染件**：把一个 [`Trace`](../../src/st_agent/contracts/trace.py) 转成符合 [01 §12 UI 描述](../../docs/技术架构-v2/01-平台共享契约.md) 的描述（经 `ok` 信封包裹），并注册进 [`T-UI-001.3`](T-UI-001.3-契约登记与组件注册表宿主.md) 的注册表。该渲染件**跨层复用**——L4 视角追问与 L6 反思报告取同一件。

## 验收标准（Given-When-Then）
- Given 一条 `Trace`，When 经描述件产出，Then `component_type = "trace_timeline"` 且包裹在 [`ResultEnvelope.ok`](../../src/st_agent/contracts/result_envelope.py) 内
- Given 描述中的任一步，When 展开细看，Then 可见 `step_type` / `ref` / `input_digest` / `output_digest` / `duration_ms` / `timestamp` / `degraded` / `note`（[05 §7](../../docs/技术架构-v2/05-L3-对话主入口.md) 的「输入快照、输出、耗时、依赖」）
- Given [06 §5](../../docs/技术架构-v2/06-L4-多视角推理.md) 的视角追问与 [08 §2](../../docs/技术架构-v2/08-L6-反思演进.md) 的反思报告，When 需要渲染推理链，Then **直接取用同一渲染件**，无需 L3 专属改动
- Given `Trace` 缺失或不可用，When 渲染，Then 显式降级（`unavailable` + 原因），**不静默留空**

## 接口面
- **输入**：
  - [`contracts/trace.py`](../../src/st_agent/contracts/trace.py)——`Trace`（`trace_id` / `steps` / `conclusion_ref` / `closed`）· `TraceStep`（`step_type` / `ref` / `input_digest` / `output_digest` / `duration_ms` / `timestamp` / `degraded` / `note`）· `STEP_TYPES` · `ConclusionRef`
  - [`l3/dispatch/bus.py`](../../src/st_agent/l3/dispatch/bus.py)——`DispatchOutcome.trace`（`explain` 去向的载荷）
  - [`T-UI-001.3`](T-UI-001.3-契约登记与组件注册表宿主.md) 的 `ui_description` 契约与注册表宿主
  - [05 §7](../../docs/技术架构-v2/05-L3-对话主入口.md)（推理链展开的语义）
- **输出**：
  - `src/st_agent/l3/render/describe.py`——`describe_trace(trace) -> ResultEnvelope`（`data` 为 `UiDescription`）
  - `src/st_agent/ui/web/js/plugins/l3/trace_timeline.js`——渲染件（并注册进注册表）
  - `tests/l3/test_render_describe.py`——描述件契约测试

## 假设与前提
- **A1 · 本叶只交付 [`T-INT-002`](T-INT-002-M1集成关卡首次可对话.md) 点名的渲染面**——前提：M1 关卡验收只点名「推理链可展开到证据」+ 三态渲染；[05 §6](../../docs/技术架构-v2/05-L3-对话主入口.md) 的 Generative UI 看板全量（钉住 / 刷新 / 下钻）与 Studio 首页卡片推后到 M2+（[D-063](../决策日志.md)）。若错（M1 需全量）：返工面＝范围扩张、M1 收口延后。验证方式：逐条对位 `T-INT-002` 验收段，范围外条目显式登记去向。
- **A2 · 该渲染件按跨层可复用实现，不做 L3 私有件**——前提：[05 §7](../../docs/技术架构-v2/05-L3-对话主入口.md)「Trace 视图与 [06-L4](../../docs/技术架构-v2/06-L4-多视角推理.md) 视角追问、[08-L6](../../docs/技术架构-v2/08-L6-反思演进.md) 反思报告**复用同一渲染组件**」（与 [`T-UI-001.3`](T-UI-001.3-契约登记与组件注册表宿主.md) 的同一处口径）。若错（L3 私有）：L4 / L6 渲染面后期重写。验证方式：注册表中 `trace_timeline` 可被 L4 / L6 的渲染面直接取用。
- **A3 · 渲染范围不越界到 Studio 画布与设置面板**——前提：[D-060](../决策日志.md) ⑤ 的归属划分（画布归 L1、设置面板归 [01 §7](../../docs/技术架构-v2/01-平台共享契约.md)）。若错（越界实现）：与既有归属叠床架屋。验证方式：交付的组件类型清单不含画布 / 设置面板。
- **A4 · L3 只产描述、不直连 HTTP；描述件为纯函数**——前提：前端只经回环服务取数（[00 §1.1](../../docs/技术架构-v2/00-架构总览.md)），L3 与 `ui` 之间不引入反向依赖（[铁律 7](../工程宪法.md)）。若错（L3 内起服务或 import `ui`）：破坏分层与单一写者。验证方式：描述件可在 `tests/l3` 内直接断言（无需起服务）；`tests/test_layering.py` 的 `test_ui_is_client_only()` 断言无层 import `ui`。
