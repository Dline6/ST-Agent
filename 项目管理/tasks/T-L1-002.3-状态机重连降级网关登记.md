# T-L1-002.3 · MCP Server 状态机 + 崩溃重连 + 降级 + 网关登记

## 目标
给 MCP Server 一个显式的生命周期：五态状态机 + 转移留痕；崩溃时明确提示并按可配次数自动重连；重连耗尽后**并列暴露**官方数据源 Skill 兜底候选（不自动切换、不给统一建议）；禁用 Server 时中止进行中调用；Server 的全部远程出网经 L0 网关登记且可查——兑现 [L0 遗留册 A1](../遗留问题/L0-遗留问题.md) 的「远程 MCP」半。

## 验收标准（Given-When-Then）
- GWT-1 五态状态机 + 留痕：Given 一个已注册 Server，When 经历 `connected` / `disconnected` / `reconnecting` / `permission_pending` / `disabled` 之间的合法转移，Then 每次转移被记录（含前后状态、时间、关联 `trace_id`），非法转移被显式拒绝；`permission_pending` 由 `.1` 的未批准权限触发。
- GWT-2 崩溃 → 提示 + 自动重连（次数可配）：Given 一个 `connected` 的 Server，When 连接断开，Then 产生显式提示事件并进入 `reconnecting`，按配置的重连次数自动重试；重试次数与间隔经 01 §7 `ConfigEntry` 形态注册（`config` 分区），可改且改动留 `change_id`。
- GWT-3 重连耗尽 → 降级候选并列暴露：Given 重连次数耗尽，When 查询降级候选，Then 得到该 Server 所遮蔽的官方数据源 Skill 候选**列表**（并列陈列，附各自可用性），**不自动切换、不合并、不给统一建议**（宪法铁律 4）；状态转 `disconnected` 并留痕。
- GWT-4 禁用 → 进行中调用中止：Given 该 Server 有进行中的调用，When 用户禁用该 Server，Then 状态转 `disabled`，进行中调用经取消信号中止且结果走显式失败分支（不留「成功」假象）。
- GWT-5 出网全登记可查：Given 该远程 Server 发生过若干次调用，When `gateway.query(kind="remote_mcp", initiator=<server_id>)`，Then 每条出网都有审计记录（含目的说明与字节数，无明文）；`remove_server` 后历史审计记录**保留**（审计不可被注销）。
- 回归：既有 591 用例全绿；`verify_docs.py --strict` PASS。

## 假设与前提
- **A1 · 崩溃提示取 L1 本地结构化提示，不扩 01 §11**：提示载体为新增的 `McpHubNotice`（中性措辞 + 落 `execution_log`），**不改 01 §11**——§11 是跨层上行事件清单（`PlatformEvent.event` 为闭合 `Literal`，10 个固定事件名），M0 无 L3 消费方；扩事件须走工作流第 ⑦ 步（改 01 → 03 → 代码），成本大于收益。若错（须是 §11 事件）：返工面＝`PlatformEvent.event` Literal + `CORE_EVENTS` + 01 §11 表 + 03 §5.3，且触发第 ⑦ 步。验证：GWT-2 用例断言提示可落盘可查，且 `git diff` 显示 `docs/` 与 `time_events.py` 零改动。
- **A2 · 降级候选＝平台内置 Skill 全量并列**：候选 = `SkillRegistry.list_all()` 中 `source != "mcp-mapped"` 者（每条带 `source` 与自身可用性），按 `skill_id` 确定性排序，**不排序、不建议、不自动切换**（宪法铁律 4）。理由：03 §5.3 只说「**可**降级到官方数据源 Skill 兜底」，spec 未定义 tool ↔ 内置 Skill 的对位关系；若引入 `check_link` 对位（D-009 判定件可用于「连不连得上」），候选会被读成「推荐」，与铁律 4 相悖。若错（须只列官方 Pack，或须按契约对位筛选）：返工面＝`degrade_candidates` 筛选口径 + GWT-3 断言。验证：GWT-3 用例断言返回值为候选项列表、每项含可用性、且调用前后**不改变任何执行路径与状态**。
- **A3 · 禁用即中止，不留半成品结果**：进行中调用经 `cancel` 信号中止，结果走显式失败分支（网关按 `cancelled` 落审计；调用包装在返回后若已置信号则转显式失败）。若错（要求等本次调用跑完）：返工面＝`cancel_inflight` 语义与 GWT-4 断言。验证：GWT-4 用例断言信封为失败分支且审计含 `cancelled`。
- **A4 · 审计记录随 Server 删除而保留**：出网审计属 L0 分层留痕，`remove_server` 只删注册表与映射，不动 `execution_log`。若错（要求连带清理）：返工面＝`remove_server` + 可能触碰 L0 审计不可删的红线。验证：GWT-5 用例断言删除后 `query` 仍可查得历史记录。
- **A5 · 当前状态与转移留痕分置两分区**：当前态落 `config/mcp-lifecycle/<server_id>.json`（单条可覆盖的**当前事实**），转移留痕与提示落 `execution_log/mcp-lifecycle/**`（append-only 的**历史**）。后者沿用 L1 既有留痕口径（如 `sandbox-violation/`），不新开分区类型。若错：返工面＝留痕分区与查询入口。验证：`list_files` 两分区各见对应文件、格式自洽。
- **A6 · 重连策略拆为两条标量 `ConfigEntry`（次数 / 间隔各一条）**：01 §7 一条目只有**一个** `panel_form_spec`（单字段 `PanelField`），「次数 + 间隔」双字段对象无法在面板通道正确渲染。故 `config/mcp-hub/reconnect-max-retries.json` 与 `.../reconnect-interval-ms.json` 各为独立条目（`scope="global"`、`record_history=True`）。若错（产品要一个复合条目）：返工面＝条目拆分与面板规格 + GWT-2 断言。验证：两条目读回均为七字段 `ConfigEntry`，改动产生 `change_id` 且落变更留痕。
- **A7 · 「中止」在检查点生效，不承诺抢占式中断**：`EgressGateway.execute` 只在**发起前**查 `cancel`（[gateway.py:156](../../src/st_agent/l0/net/gateway.py)），进行中的阻塞 POST 无法被抢占（02 §6 现口径）。故本任务的「中止」＝置信号 + 传输层在发包前后各查一次信号（已置即按 `EgressCancelledError` 上报，网关照常落 `cancelled` 审计）+ 调用包装在返回后复核信号并转显式失败。若错（要求真抢占）：返工面＝L0 传输层（超出本任务范围，须新立任务）。验证：GWT-4 用例中阻塞的替身 sender 在信号置位后中断，审计 `status == "cancelled"`、信封非 `ok`。
