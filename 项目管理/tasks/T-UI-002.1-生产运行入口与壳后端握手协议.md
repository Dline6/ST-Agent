# T-UI-002.1 · 生产运行入口与壳后端握手协议

## 目标
交付**生产运行入口** `python -m st_agent`：解析平台默认存储根 → [`build_m2_runtime`](../../src/st_agent/app.py) 装配 L0–L4 → [`serve(chat=…)`](../../src/st_agent/ui/server.py) 起本机回环面，并在就绪后向 stdout 输出**单行机器可读握手**（`host` / `port` / `token` / `pid` / `root` / `version`）——它是壳（[`T-UI-002.2`](T-UI-002.2-桌面壳本体窗口托盘自启与通知接线.md)）消费的唯一接口。同时交付后端侧的**生命周期语义**：父进程死亡看门狗、信号驱动的优雅收尾、加密根无口令时显式 fail-closed。

## 验收标准（Given-When-Then）
- Given 首次运行（根目录不存在），When `python -m st_agent --root <tmp> --handshake json`，Then stdout **首行**是合法 JSON 握手且字段齐备，`GET /api/health` 返 `ok`，`POST /api/chat` **不再是 `unavailable`**（走真组合根）
- Given 壳传入 `--parent-pid <pid>`，When 父进程退出，Then 后端在数秒内自行优雅退出（不留孤儿进程）
- Given 运行中的后端，When 收到 SIGINT / SIGTERM，或壳经 stdin 投递停止指令 / 关闭管道（EOF），Then 优雅收尾（存储关闭 / 审计冲刷）后以 0 退出
- Given 一个**已开启加密**的存储根且未提供口令，When 启动，Then **显式失败**（非零退出 + 中性原因），不静默降级为明文、不阻塞在交互输入上
- Given 同一根二次启动（端口由 OS 重分配），When 请求带旧端口的 `Host` / 错误 `Origin`，Then 守卫按**新端口**严格校验、一律拒（复跑不放宽）

  - `tests/integration/test_runtime_entry.py`——跨层装配用例（entry ≈ `app` + `ui`，故归 `tests/integration`，随跨层套件恒跑）

## 假设与前提
- **A1 · 握手走 stdout 单行 JSON，不落盘**——前提：壳以后端为子进程、管道即通道，故不引入运行时描述文件的第二个真相源（也免去文件权限 / 残留问题）。若错（壳无法读管道，如 future 的「后端独立常驻」形态）：需补发现机制，返工面＝握手面与其用例。验证方式：用例以子进程管道读首行并解析；**不产生**任何端口 / 令牌落盘文件。
- **A2 · 默认根按平台惯例自定**——同父任务 `A2`（[02 §2.1](../../docs/技术架构-v2/02-L0-本地优先基座.md) 明说物理组织由实现决定）。验证方式：逐平台断言解析结果 + `ST_AGENT_ROOT` 覆盖生效。
- **A3 · 加密根的口令交互不在本叶**——同父任务 `A3`。无口令时**显式失败**（非零退出 + 中性原因），不做交互式 `input()`（[02 §2.2](../../docs/技术架构-v2/02-L0-本地优先基座.md)：格式自辨、调用方不指定格式）。验证方式：加密根用例断言退出码非零且原因中性、未创建明文根。
- **A4 · 父进程死亡看门狗是跨平台兜底**——前提：Windows 无进程组随父退出语义，`TerminateProcess` 亦非优雅。故「父死子退」不能只靠壳侧 `terminate()`。若错（看门狗误杀 / 不触发）：返工面＝看门狗实现与其用例。验证方式：用例终结父进程后轮询子进程退出（含优雅收尾痕迹）。
- **A5 · 壳的优雅停走 stdin 控制通道，而非控制台信号**——前提：桌面壳（GUI 进程）**没有控制台**，Windows 的 `CTRL_BREAK_EVENT` / POSIX 的 `SIGTERM` 都送不到无控制台的子进程；管道关闭带来的 EOF 则一定能。若错（须另辟收尾通道，如 token 保护的 `POST /api/shutdown`）：返工面＝收尾面与其用例，且会给回环 API 面新增一个「可被页面调用」的端点。验证方式：用例以管道投递 `stop` 与直接关管道两条路径都断言退出码 0 + 末行 `event=stopped`。
