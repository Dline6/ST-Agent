# T-UI-030 · 同步面板折叠态与点选不重绘

## 目标

同步目录的标的 / 其他分组首次打开全部折叠；点选数据集、指标组或时间不再整块重建目录，从而不跳动、不复位已折叠分组、不丢焦点；批次结束后不再整页重绘。

## 验收标准（Given-When-Then）

- GWT-1 默认折叠：Given 首次打开 `/settings?view=data`，When 目录渲染完成，Then 全部标的与其他分组均为收起态，没有任何分组因写死的默认值展开。
- GWT-2 点选不跳动：Given 用户已展开若干分组并滚动到某数据集，When 勾选或取消该数据集的复选框，Then 勾选立即生效、预检刷新，分组展开态与滚动位置保持不变，被点行不移动。
- GWT-3 指标与时间不重建：Given 用户点选指标组 chip 或切换时间模式，When 配置变化，Then 只有该数据集行内的控件更新，其余分组的展开态与滚动位置不变。
- GWT-4 结构变化保留现场：Given 用户切换「显示高级项与强制重拉」，When 目录因列表结构变化而重建，Then 已展开分组与滚动位置恢复，焦点仍在该开关上。
- GWT-5 批次结束不整页重绘：Given 同步批次结束，When 刷新进度与结果，Then 只更新进度 / 结果区，同步目录的展开态与滚动位置不变。

## 接口面

- 输入（消费的前置接口）：
  - 既有 `GET /api/settings/data`（`ui/app.py` 的 `api_settings_data`）：提供 `targets` / `datasets` / `groups` / `job`。
  - 既有 `POST /api/settings/data/preflight` 与 `GET /api/settings/data/job`。
  - 既有 `settings.js` 的 `renderDataWorkspaceV2`（`renderTarget` / `renderDatasetRow` / `renderTimeControl` / `renderCatalog`）。
- 输出（本任务交付的公共 API / 落盘位置）：
  - `src/st_agent/ui/web/js/pages/settings.js`：新增模块级 `openTargets`（展开态集合）；`renderCatalog` 重建时按它恢复；勾选、chip、时间模式改为原地更新，不再触发整块重建。
  - 无新增 HTTP 端点、无新增落盘。

## 可关闭的遗留

无（已扫 `L0/L1/L2/L3/L5/L6` 各遗留册未闭区，无归属本任务的条目）。

## 假设与前提

- A1 分组展开态只需**会话内**记忆：切到别的页面再回来由 `T-UI-032` 的客户端路由保活；浏览器刷新后回到默认全折叠。若错：需要把展开态存 `localStorage`，会改变「第一次打开默认折叠」的口径。
- A2 点选不再重建目录不影响预检：勾选后仍按 250ms 合并调用 `/api/settings/data/preflight`。若错：预检可能显示旧选择，需在勾选处理器内显式刷新。
- A3 「显示高级项」仍需要重建目录（可见数据集集合变化）；本任务只保证重建后恢复展开态与滚动，不保证焦点停留在具体数据行。验证：浏览器走查 GWT-4。
