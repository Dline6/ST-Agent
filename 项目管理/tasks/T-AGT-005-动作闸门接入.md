# T-AGT-005 · 动作闸门接入（分组节点）

> **本节点不直接交付**——按[拆分触发](../工作流.md)拆为两叶（本次 ④ 对齐，[D-097](../决策日志.md)），交付由 [`.1`](T-AGT-005.1-运行期授权档位与共享清单.md) / [`.2`](T-AGT-005.2-逐步闸门与终止交还.md) 承接。父状态与父 `depends_on` 由 `render` 按 children 派生。

## 目标

| 叶 | 能力 | 依赖 |
| --- | --- | --- |
| [`.1`](T-AGT-005.1-运行期授权档位与共享清单.md) | **L6 侧**：清单键空间含动作标识 + 运行期档位条目 `agent.authorization` + 「清单 × 档位 → 三态结论」的判据面 | — |
| [`.2`](T-AGT-005.2-逐步闸门与终止交还.md) | **L3 侧**：逐步闸门（接 [`.2`](T-AGT-004.2-循环驱动、协议端口与上界.md) 的授权端口）+ 终止交还 | [`.1`](T-AGT-005.1-运行期授权档位与共享清单.md) · [`T-AGT-004.2`](T-AGT-004.2-循环驱动、协议端口与上界.md) |

**拆分依据**：命中[拆分触发](../工作流.md)两条——验收 GWT 8 > 5 · 跨 L6 / L3 **两个架构层**（[08 §5](../../docs/技术架构-v2/08-L6-反思演进.md) + [05 §10](../../docs/技术架构-v2/05-L3-对话主入口.md) / [01 §7](../../docs/技术架构-v2/01-平台共享契约.md)）。同因拆叶的先例＝[`T-L6-003`](done/M4/T-L6-003-演进授权与变更流回滚与出厂重置.md) → 三叶（[D-087](../决策日志.md) ①）。两叶的**失败面互不重叠**：`.1` 是配置面（清单与档位的判定口径），`.2` 是运行期面（闸门接线与交还产出）。

## 验收标准（Given-When-Then）

分组节点不单独验收——验收由两叶的 GWT 合成（GWT-1–5 归 [`.1`](T-AGT-005.1-运行期授权档位与共享清单.md)、GWT-6–8 归 [`.2`](T-AGT-005.2-逐步闸门与终止交还.md)）：

- **GWT-1 · 单一清单**：Given 运行期授权与演进授权两个读取方，When 各自取风险清单，Then 得**同一张**（同一个 `config_id` 与同一份取值）——**不存在第二张清单**。
- **GWT-2 · 红线单点**：Given `memory.*` 一类红线，When 从两处判风险类，Then 均得 `never-autonomous`（红线**只登记一处**即对两处生效）。
- **GWT-3 · 动作标识可判**：Given 一个动作标识（如 `skill.sk_stock_watch`），When 判其风险类，Then 按清单**首个命中前缀**得结论；**未命中即保守**（`collaborative-required`）。
- **GWT-4 · 档位彼此独立**：Given 演进档为 `autonomous`、运行期档为 `collaborative`，When 判一次工具调用，Then **不放行**（运行期档说了算）——两档互不顶替。
- **GWT-5 · 缺省与损坏都放行不了**：Given 运行期档条目**未落值**或**形态损坏**，When 判，Then `collaborative` / 显式不放行（fail-closed），**不臆测为自主**。
- **GWT-6 · 遇需协作即终止交还**：Given 循环首步就是 `collaborative-required` 的动作，When 驱动，Then **一步不执行**、循环终止，且产出**显式**说明「下一步需确认」+ 已收集证据。
- **GWT-7 · 交还不伪装完成**：Given GWT-6 的情形，When 取产出，Then 状态**非 `ok`**，**不得**把半程结果呈现为已完成。
- **GWT-8 · 不淹变更历史**：Given 一次 N 步自主循环跑完，When 读变更历史（`reflection/changes/`），Then **无新增 `ChangeRecord`**。

## 假设与前提

- **A1 · 运行期档位是**新的一条**条目，不并入 `evolution.authorization`**——前提：[D-090](../决策日志.md) ① 判「演进是每周低频配置面、运行期是每轮高频动作面，两种节律」；并入会让「我想让演进更自主」连带放开工具调用。
  **若错的影响**：若两档合一，用户调档的**语义**变成「同时调两件事」，且 L6 的边界模糊；返工面 = 条目分拆 + 设置页改位。
  **验证方式**：[`.1`](T-AGT-005.1-运行期授权档位与共享清单.md) 的 GWT-4 以「两档互不顶替」钉死。
- **A2 · 清单共享须防「两处各标一遍」**——前提：[08 §7 红线](../../docs/技术架构-v2/08-L6-反思演进.md) 要求 Memory 内容与策略恒不可自主；若运行期侧另起一张清单，该红线会被标两处、日后增删必漂移。
  **若错的影响**：红线静默失守（一处改了另一处没改），而**没有任何用例会红**。
  **验证方式**：[`.1`](T-AGT-005.1-运行期授权档位与共享清单.md) 的 GWT-1 / GWT-2 以「同一张清单」「两处同判」钉死——这是本任务最不可放宽的两条。
- **A3 · 闸门落在 L3 侧、清单落在 L6 侧**——前提：清单是配置面（L6 的演进授权面既有的 owner），闸门是运行期判断（循环内）；L3 **向下**依赖 L6 是被 [铁律 7](../../项目管理/工程宪法.md) **禁止**的（`LAYER_ORDER` 为 `l3` < `l6`）。
  **若错的影响**：**这是本任务最关键的一条**——L3 取 L6 的判据必须经**鸭子端口注入**（同 [`DispatchBus`](../../src/st_agent/l3/dispatch/bus.py) 的 `deliberations` / `trainings` 先例），由组合根把 L6 的授权面注入循环；若写成 `l3` import `l6`，`tests/test_layering.py` 当场判失败。
  **验证方式**：[`.2`](T-AGT-005.2-逐步闸门与终止交还.md) 的 GWT-6 经注入面成立；`tests/test_layering.py` 全绿且 `l3/runtime/**` 无 `st_agent.l6` import（AST 断言）。
