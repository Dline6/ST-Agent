# T-L1-003.5 · 模板库与空状态

## 目标

落地 03 §4 的**模板库**与**空状态**：官方预置一批工作流模板（每日 ST 简报 / 退市风险扫描 / 策略回测流水线等），用户可 fork 后修改；用户尚无自建工作流时返回空状态（模板库 + 「用一句话描述你想要的工作流」入口）。

④ 对齐定案：模板库的**机制与官方预置模板内容**均归本任务（[`T-L1-004`](T-L1-004-官方SkillPack公共认知主动服务Bundl.md) 保持纯 Skill Pack 面）。

## 验收标准（Given-When-Then）

- GWT-1 模板库浏览：Given 首次使用，When 打开模板库，Then 列出官方预置模板（至少含「每日 ST 简报」「退市风险扫描」「策略回测流水线」），每条含名称、说明、节点数与该模板引用的 Skill 清单。
- GWT-2 fork：Given 一个模板，When fork，Then 生成**用户自有**工作流副本（新 `flow_id`，可编辑 / 可试跑 / 可保存为复合 Skill），模板本身**逐字段不变**。
- GWT-3 加载即走依赖提示：Given 模板引用的某 Skill 未注册，When 浏览 / fork / 加载该模板，Then 走依赖提示流程（逐条列出缺失 `skill_id`），**不静默通过**。
- GWT-4 空状态：Given 用户未创建任何工作流（`WorkflowStore.list_all()` 为空），When 查询 Studio 空状态，Then 返回「模板库 + 一句话入口」的结构化空状态（不外抛异常、不返回空对象）。

## 接口面

- 输入（消费的前置接口）：
  - `T-L1-003.1` 的 `st_agent.l1.workflow` 包：`WorkflowDAG` / `validate` / `WorkflowStore.list_all` / `flow_id_for`
  - `T-L1-003.2` 的 `st_agent.l1.workflow.composite`：`missing_dependencies`（依赖提示的同一口径 —— 模板引用缺失与复合 Skill 依赖缺失是同一个问题面）
  - T-L1-001.1 [`registry.py`](../../src/st_agent/l1/skills/registry.py)：`SkillRegistry.get` / `get_latest`（模板引用的 Skill 是否存在）
- 输出（本任务交付的公共 API / 落盘位置）：
  - `st_agent.l1.studio.templates`：`TemplateLibrary`（`list` / `load(template_id)` / `fork(template_id) -> WorkflowDAG`）、`OFFICIAL_TEMPLATES` 种子（形态与 [`skills/pack.py::OFFICIAL_PACK`](../../src/st_agent/l1/skills/pack.py) 同构：`register` kwargs 式纯数据、可增不可缺）
  - `st_agent.l1.studio.empty_state`：`studio_empty_state(store) -> StudioHome`（模板库清单 + 一句话入口）
  - 落盘：模板为**内置种子**（随包发布，不落用户存储）；fork 出的工作流走 `T-L1-003.1` 的 `config` 分区 `workflow/` 布局
  - 消费方：`T-L1-003.4`（fork 后进入编辑面）、`T-L3-004`（渲染模板库与空状态）

## 假设与前提

- A1 官方模板以**纯数据种子**随包内置（形态同 `skills/pack.py::OFFICIAL_PACK`），不落用户存储、不依赖网络——本地优先（宪法铁律 1）/ 若错（模板需可更新分发）：须走官方 Pack 更新通道（01 §9）/ 验证：GWT-1 离线可用。
- A2 模板内容（节点与连线）只引用官方 Skill 的 `skill_id`；官方 Skill 描述体由 `T-L1-001.1` 已交付的 `ensure_official_pack` 播种，故模板的引用**可解析**；其**执行器**归 `T-L1-004` 尚未交付——即模板可浏览 / fork / 保存，但 fork 结果**试跑需 `T-L1-004`**（`T-L1-003.3` 的试跑会得到「未注册执行器」的 `failed` 信封，属显式失败而非静默）/ 若错（模板须能立即试跑）：本任务对 `T-L1-004` 的依赖需升为硬依赖并改 `depends_on` / 验证：GWT-2 fork 后调 `.1` 的 `validate` 通过（引用存在）。
- A3 fork 产生的 `flow_id` 由模板名派生并**去重**（同 base 已存在即加序号或走版本），不覆盖用户既有工作流 / 若错（用户期望 fork 必得同名）：须改为「重名即拒 + 提示改名」/ 验证：GWT-2 连 fork 两次不冲掉第一次。
- A4 空状态判据取 `WorkflowStore.list_all()` 为空（**未创建任何工作流**），不是「未打开过 Studio」——与 story-06「新用户未创建任何工作流」字面一致 / 若错（口径应为「无最近编辑」）：须改判据 / 验证：GWT-4。
- A5 模板的**中性化命名**同样过 01 §6（模板名会进入 fork 出的工作流 `name`）/ 若错（模板名有豁免）：须在 01 §6 扩口径 / 验证：GWT-1 种子在装载时过校验（测试断言全部模板校验通过）。
