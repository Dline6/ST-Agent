# T-L1-003.5 · 模板库与空状态

## 目标

落地 03 §4 的**模板库**与**空状态**：官方预置一批工作流模板（每日 ST 简报 / 退市风险扫描 / 策略回测流水线等），用户可 fork 后修改；用户尚无自建工作流时返回空状态（模板库 + 「用一句话描述你想要的工作流」入口）。

④ 对齐定案：模板库的**机制与官方预置模板内容**均归本任务（[`T-L1-004`](T-L1-004-官方SkillPack公共认知主动服务Bundl.md) 保持纯 Skill Pack 面）。

## 验收标准（Given-When-Then）

- GWT-1 模板库浏览：Given 首次使用，When 打开模板库，Then 列出官方预置模板（至少含「每日 ST 简报」「退市风险扫描」「策略回测流水线」），每条含名称、说明、节点数与该模板引用的 Skill 清单。
- GWT-2 fork：Given 一个模板，When fork，Then 生成**用户自有**工作流副本（新 `flow_id`，可编辑 / 可试跑 / 可保存为复合 Skill），模板本身**逐字段不变**。
- GWT-3 加载即走依赖提示：Given 模板引用的某 Skill 未注册，When 浏览 / fork / 加载该模板，Then 走依赖提示流程（逐条列出缺失 `skill_id`），**不静默通过**。
- GWT-4 空状态：Given 用户未创建任何工作流（`WorkflowStore.list_all()` 为空），When 查询 Studio 空状态，Then 返回「模板库 + 一句话入口」的结构化空状态（不外抛异常、不返回空对象）。

## 接口面

- 输入（消费的前置接口）：
  - `T-L1-003.1` 的 `st_agent.l1.workflow` 包：`WorkflowDAG` / `checked_dag` / `validate_dag` / `flow_id_for` / `base_of` / `WorkflowStore.list_all`
  - `T-L1-003.2` 的 `st_agent.l1.workflow.composite`：`missing_dependencies(dag, registry) -> tuple[DependencyGap, ...]` 与 `CompositeDependencyError`（依赖提示的同一口径 —— 模板引用缺失与复合 Skill 依赖缺失是同一个问题面）
  - `T-L1-003.4` 的 `st_agent.l1.studio.ids`：`slugify` / `SLUG_PATTERN`（注册名派生口径不另造）
  - `T-L1-001.1` [`registry.py`](../../src/st_agent/l1/skills/registry.py)：`SkillRegistry.get` / `get_latest`（模板引用的 Skill 是否存在）· [`pack.py::ensure_official_pack`](../../src/st_agent/l1/skills/pack.py)（官方 Skill 描述体的播种方，A2 的前提）
  - `T-L0-001` 的 `Store`（`WorkflowStore(store, registry)` 与 `TemplateLibrary(store, registry)` 的构造入参；fork 去重需读 `config` 分区既有工作流）
- 输出（本任务交付的公共 API / 落盘位置）：
  - `st_agent.l1.studio.templates`：`OFFICIAL_TEMPLATES` 种子（形态与 [`skills/pack.py::OFFICIAL_PACK`](../../src/st_agent/l1/skills/pack.py) 同构：`register` kwargs 式纯数据、可增不可缺、不含身份字段）、`TemplateLibrary(store, registry)`（`list() -> tuple[TemplateSummary, ...]` / `get(template_id) -> TemplateSummary` / `load(template_id) -> WorkflowDAG` / `fork(template_id) -> WorkflowDAG`）、`TemplateSummary`
    - `list` / `get`：逐条给 名称 / 说明 / 节点数 / 引用的 Skill 清单 / **缺失 Skill 清单**（GWT-3 的「浏览」面；`get` 是单条详情面，与 `WorkflowStore.get` / `SkillRegistry.get` 同形）
    - `load`：模板**只读预览**——身份取临时位 `wf_<注册名>_v0.0`（表未发布），供画布看结构
    - `fork`：用户自有副本——base 由种子 ASCII `flow_name` 派生，与既有 base 冲突即**加序号**（`_2` / `_3` …），身份 `wf_<注册名>[_n]_v1.0`；**本步不落盘**（落盘由「接受」承担，见下）
  - `st_agent.l1.studio.empty_state`：`StudioHome` + `studio_empty_state(store, registry) -> StudioHome`（`templates` + `one_line_entry` + `is_empty`）
  - `st_agent.l1.studio.errors`：新增 `TemplateError`（模板标识不存在 / 种子非法）——与 `Draft*` 三型并列，不混用
  - 落盘：模板为**内置种子**（随包发布，不落用户存储）；`fork` **不落盘**，其结果交 `T-L1-003.4` 的 `CanvasEditor` 编辑、「接受」落 `config` 分区 `workflow/<flow_id>.json`（+ `execution_log` 变更留痕）
  - 消费方：`T-L1-003.4`（fork 后进入编辑面）、`T-L3-004`（渲染模板库与空状态）

## 假设与前提

- A1 官方模板以**纯数据种子**随包内置（形态同 `skills/pack.py::OFFICIAL_PACK`），不落用户存储、不依赖网络——本地优先（宪法铁律 1）/ 若错（模板需可更新分发）：须走官方 Pack 更新通道（01 §9）/ 验证：GWT-1 离线可用（用例在无网络依赖下装载全部种子）。
- A2 模板内容（节点与连线）只引用官方 Skill 的 `skill_id`；官方 Skill 描述体由 `T-L1-001.1` 已交付的 `ensure_official_pack` 播种，故模板的引用**可解析**；其**执行器**归 `T-L1-004` 尚未交付——即模板可浏览 / fork / 保存，但 fork 结果**试跑需 `T-L1-004`**（`T-L1-003.3` 的试跑会得到「未注册执行器」的 `failed` 信封，属显式失败而非静默）/ 若错（模板须能立即试跑）：本任务对 `T-L1-004` 的依赖需升为硬依赖并改 `depends_on` / 验证：GWT-2 fork 后调 `.1` 的 `validate_dag` 通过（引用存在）。
- A3 fork 产生的 `flow_id` 由模板的 ASCII `flow_name` 派生并**去重**（同 base 已存在即加序号 `_2` / `_3` …），不覆盖用户既有工作流。**④ 定案取「加序号」而非「重名即拒」**——模板名是系统派生的、用户对 base 无选择权，拒绝会让「fork」按钮莫名失败（与 `.4` 草稿「接受」的 G 口径差异属**有意的**：那条的 base 由用户/LLM 给出，这条不是）/ 若错（用户期望 fork 必得同名）：须改为「重名即拒 + 提示改名」/ 验证：GWT-2 连 fork 两次不冲掉第一次。
- A4 空状态判据取 `WorkflowStore.list_all()` 为空（**未创建任何工作流**），不是「未打开过 Studio」——与 story-06「新用户未创建任何工作流」字面一致；`StudioHome.is_empty` 承载该判据，模板清单**恒返回**（非空时亦然，供「新建」入口复用）/ 若错（口径应为「无最近编辑」）：须改判据 / 验证：GWT-4 双向（空 → `is_empty=True`；有工作流 → `False`）。
- A5 模板的**中性化命名**同样过 01 §6（模板名会进入 fork 出的工作流 `name`）/ 若错（模板名有豁免）：须在 01 §6 扩口径 / 验证：GWT-1 种子在装载时过 `validate_dag`（用例断言全部种子校验通过）。
- A6 `template_id` **不登记**进 01 §1 契约 ID 表——模板是随包内置的纯数据常量，只在 L1 进程内寻址（不持久化、不分享、不跨会话），不满足 01 §1 对 ID 的「可本地持久化」要求；跨层只用 fork 产物的 `flow_id`（已在 01 §1 登记）。**④ 定案**，与 `trial_id`（D-020）/ `flow_id`（D-018）「两者都已落盘才登记」的既有口径一致 / 若错（L3 需按 template_id 持久化引用某模板）：须补登记 01 §1 并同步各层 / 验证：`list` / `load` / `fork` 三面均以 `template_id` 作进程内入参，无任何落盘路径携带它。
- A7 种子装载期经 `checked_dag` + `validate_dag` 构造校验（含 01 §6 命名），种子有错**装载期即失败**而非运行期静默；`fork` 深拷贝种子内容，模板本身**逐字段不变**（GWT-2）/ 若错（模板可变）：GWT-2 的「模板逐字段不变」断言失效 / 验证：GWT-2 断言 fork 前后 `OFFICIAL_TEMPLATES` 构造出的模板身份与内容不变。
