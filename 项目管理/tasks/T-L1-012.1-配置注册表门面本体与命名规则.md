# T-L1-012.1 · 配置注册表门面本体与命名规则

## 目标

建 `01 §7` 配置注册表的**门面本体**（落 [01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 的消费面语义）：`config_id` 点分命名与路径确定性派生、族（family）扩展协议、门面三语义（按 `config_id` / `(target, param)` 读、按 `scope` 列举、一次落值 + 产生 `change_id`），并交付 **skill / workflow 参数族**——按描述体 `ParameterSpec` **物化**规范 `ConfigEntry`（读时合成、不落盘），只把**被显式改过、偏离默认**的值落盘为 override。本叶只交付库与用例，不装配组合根（归 `.2`）。

## 验收标准（Given-When-Then）

- **GWT-1 · 命名与派生**：Given `config_id="skill.sk_risk_alert.window"`，Then 落盘路径为 `skill/sk_risk_alert/window.json`（点分语义 → 路径确定性派生，`. → /` + `.json`；与 L0 已写的 `retention.chat_history_days` 同族口径）；非法 `config_id`（空段 / 含空白 / 含 `..` / 超 128 字符 / 族与作用域段无法反解）**即拒**，不静默取最近值。
- **GWT-2 · 物化（不落盘）**：Given 描述体声明的某参数且**无** override，When `entry_for(skill_id, param)`，Then 返回一条 `ConfigEntry`——`config_id` 为点分形式、`display_name` / `description_for_chat` 取声明 `ParameterSpec.description`、`panel_form_spec` 由 `type` 映射（与 [`panel_field_for`](../../src/st_agent/l3/config/registry.py) 同一份口径，不各造一套）、`default` = 声明默认、`scope="skill"`；且 `config` 分区**无新增文件**。
- **GWT-3 · override 往返**：Given `apply(skill_id, {"window": 60})`，Then 值落 `config` 分区（该参数一条 `ConfigEntry`）、`execution_log` 分区落一条 `ChangeRecord`（含 `change_id` / `old_value` / `new_value` / `applied_at`）；再 `entry_for` 读到的 `default == 60`。
- **GWT-4 · 值未变不留痕**：Given 已落值 60，When 再 `apply(skill_id, {"window": 60})`，Then **不落盘、不留痕**（该参数不返回 `ChangeRecord`）——与既有各族 `set` 的同一取向。
- **GWT-5 · 列举与 fail-closed**：`list(scope="skill")` 列举全部已落 override；`list()` 列举门面已注册族的全部条目；**未注入**描述体取数口时，对未知目标 `entry_for` 返回 `None`（回落声明面），**不臆测**、不抛裸异常。

## 假设与前提

- **A1 · 配置键取 skill 的 `base`、不取带版本的 `skill_id`**：`config_id = skill.<base>.<param>`，故同 base 的版本升级**沿用**同一份配置（对齐 [D-042](../决策日志.md) 批准账本「键为 base」的口径；`skill_id` 版本号形如 `_v1.0`，进 key 会让每次发版丢配置）。
  - 若错的影响：返工面＝`skill_config_id` 的键形态与已落 override 的迁移；`entry_for` 的入参需从 `skill_id` 改为 base。
  - 验证方式：GWT-3 用 `sk_x_v1.0` 落值、再用 `sk_x_v1.1` 读同一条 override（同 base 共用）断言成立。
- **A2 · 命名段分隔符固定为 `.`，故 base / 参数名不得含 `.`**：base 形态 `sk_[a-z0-9][a-z0-9_.\-]{0,60}` 与 `ParameterSpec.name`（≤64，**未限字符集**）在契约上**允许**含 `.`，点分会歧义。门面**反解失败即拒**（不静默误解析），并在 `naming.py` 文档写明「注册表的寻址段不含 `.`」。
  - 若错的影响：若后续确有含 `.` 的 base / 参数名，需换分隔符（如 `:`）或转义——返工面＝`config_id` 拼接与反解一处。
  - 验证方式：GWT-1 的负例（含歧义段的 `config_id` 被拒）＋ 官方 Pack 12 条播种后 `list(scope="skill")` 的键全部可反解。
- **A3 · 「物化」不落盘、`origin` 因此恒为 `registry`**：`entry_for` 对**任何已声明参数**都返回条目（读时由 `ParameterSpec` 合成），L3 [`dual_channel_view`](../../src/st_agent/l3/config/registry.py) 的 `origin` 随之恒为 `registry`、「声明面回落」只在门面未注入或目标未知时出现——这正是 [L1 册 `E1`](../遗留问题/L1-遗留问题.md)「升为真登记项」的字面兑现。
  - 若错的影响：若认为「未改过的参数不算登记项」，则 `entry_for` 应只在有 override 时返回；返工面＝`SkillParamFamily.entry` 一处与 [`tests/l3/test_config_draft.py`](../../tests/l3/test_config_draft.py) 的期望。
  - 验证方式：GWT-2（无 override 也返回条目、且盘上无文件）与 `.2` 的集成用例（`origin == "registry"`）。
- **A4 · 留痕前缀 `skill-config-change/` 为本族自有、不与既有 `*-change/` 冲突**：既有四族的留痕前缀（`scheduler-change/` / `mcp-hub-change/` / `memory-policy-change/`）各归其族；skill 参数族的留痕前缀新增且唯一。
  - 若错的影响：若与既有前缀撞名，`list_files("execution_log")` 的按前缀扫描会串族；返工面＝前缀常量一处。
  - 验证方式：GWT-3 落一条后，`execution_log` 下仅 `skill-config-change/` 前缀的文件数 +1（既有前缀计数不变）。
