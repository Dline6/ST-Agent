# T-L1-004.1 · 官方 Pack 装载接线与数据访问基件

## 目标

交付官方 Skill Pack 的**装载入口**与 12 个执行器共用的**取数基件**：一条 `install_official_pack(...)` 把「描述体播种 + 执行器注册」一次做完，装载后 12 个 Skill 全部**可执行**（不再出现「未注册执行器」的 `failed`）；取数一律经 L0 `MarketDb.query` **单一入口**，其非 `ok` 信封原样上抛——数据不可用与空结果由 L0 判定，执行器不编造、不吞掉。

## 验收标准（Given-When-Then）

- GWT-1 装载即用：Given 全新 Store + 口令 + 一个已接数据面的取数源，When 调 `install_official_pack(registry, runner, market_query=…)`，Then 12 个官方 Skill 描述体全部落盘，且 12 个 `skill_id` 全部注册了执行器（逐条 `runner.run` 均不返回「未注册执行器」的 `failed`）。执行器工厂表以参数注入（`executors=`）；默认表由两 Bundle 模块提供（延迟导入，见下）。
- GWT-2 幂等装载：Given 已装载过一次的运行时，When 再次装载，Then 描述体不重复注册（`SkillExistsError` 被吞掉而非上抛）、执行器不被「清空重注册」改变行为，且返回本次新增的 `skill_id` 清单为空。
- GWT-3 数据不可用不编造：Given 本地市场库尚未建立（取数源对查询返回 `unavailable`），When 官方 Skill 的执行器经基件取数，Then 执行结果信封为 `unavailable` 且携带「最后更新时间 T」（经 `MarketDb.query` 的既有判定原样透出，执行器不自行造时间、不自行编载荷）。
- GWT-4 空结果是合法结果：Given 库可用但查询条件无匹配行（取数源返回 `empty`），When 取数，Then 信封 `empty` 且带原因说明（结构化空结果，**不是** `ok` 包空数组，也不是 `failed`）。
- GWT-5 取数只有一条通道：Given 官方 Pack 执行面的全部源码，When 解析其 import，Then 不含 `sqlite3` 与 `st_agent.l0.*` 数据面实现依赖（取数一律经基件的单一入口进入 `MarketDb.query`；违反即用例失败）。

## 接口面

- 输入（消费的前置接口）：
  - `T-L1-001.1` [`skills/pack.py`](../../src/st_agent/l1/skills/pack.py)：`OFFICIAL_PACK` 种子（12 项，每项含 `base` / `version` / `parameters` 等 `register` kwargs）与 `ensure_official_pack(registry) -> tuple[str, ...]`（幂等播种，返回本次新增 `skill_id`）
  - `T-L1-001.1` [`skills/registry.py`](../../src/st_agent/l1/skills/registry.py)：`SkillRegistry.get` / `get_latest`；`T-L1-001.1` [`skills/ids.py`](../../src/st_agent/l1/skills/ids.py)：`skill_id_for(base, version)`（base → `skill_id` 的拼接口径，装载侧必须复用而非自造）
  - `T-L1-001.2` [`runner/runner.py`](../../src/st_agent/l1/runner/runner.py)：`SkillRunner.register_executor(skill_id, fn)` 与 `SkillExecutor` 签名 `(SkillContext, dict) -> ResultEnvelope`；`SkillContext.upstream`（依赖输出）、`SkillContext.llm` / `gateway` / `freshness` / `sandbox`
  - `T-L1-001.6` [`contracts/schema_check.py`](../../src/st_agent/contracts/schema_check.py)：`check_payload`（输出契约核验在 runner 内已接，执行器只需产出合契约载荷）
  - `T-L0-005` [`l0/market/db.py`](../../src/st_agent/l0/market/db.py)：`MarketDb.query(sql, params=()) -> ResultEnvelope`（含 `ok` / `empty` / `unavailable` 分支与 `last_updated_at`）、`MarketDb.exists()`、`MarketDb.last_updated_at()`、`MarketDb.snapshot_id()`、`MarketDb.as_of(domain)`；`T-L0-001` 的 `Store`（`MarketDb(store)` 的构造入参）
- 输出（本任务交付的公共 API / 落盘位置）：
  - 新子包 `st_agent.l1.skills.official`：
    - `official.common`：`MarketQuerySource`（鸭子类型协议，只要求 `query(sql, params=()) -> ResultEnvelope`，与 [`reuse/freshness.py`](../../src/st_agent/l1/reuse/freshness.py) 的适配口径同构，**不在 L1 硬绑 L0 具体类型**）、`query_rows(source, sql, params=()) -> RowsResult | ResultEnvelope`（`ok` 时摊平 `data["rows"]` 为 `RowsResult(rows, as_of)`；非 `ok` **原样返回同一信封**）、`ok_envelope(payload, *, as_of=None, evidence_refs=())` / `empty_envelope(reason, *, as_of=None, evidence_refs=())`、`snapshot_ref(source) -> EvidenceRef | None`（`dataset_snapshot_id` 证据引用，见 A6）
    - `official.install`：`install_official_pack(registry, runner, *, market_query, executors=None) -> tuple[str, ...]`（播种 + 逐 `skill_id` 注册执行器；返回本次新增 `skill_id`）、`executor_table()`（合并两 Bundle 模块的 `EXECUTORS` 表）、`uncovered_bases(executors=None) -> tuple[str, ...]`（尚无执行器的 base，装载完整性口径）、`BUNDLE_MODULES` / `ExecutorFactory`
    - `official.errors`：`OfficialPackError`（基类，承 `SkillError`）+ `OfficialPackLoadError`（装载期缺陷：取数源不合口径 / Bundle 未提供 `EXECUTORS` / 工厂非 callable / `ok` 载荷缺 `rows`）
  - 落盘：沿用既有布局，**不新增分区**——描述体 → `config/skill-registry/<skill_id>.json`；SkillRun → `execution_log/skill-run/<skill_run_id>.json`
  - 消费方：`T-L1-004.2` / `.3`（各自的执行器经基件取数与构信封）、`T-L1-006`（组合根在启动序列里调装载入口）、`T-INT-001`（GWT-2 装配即用）

## 假设与前提

- A1 运行期输入口径取「**声明参数 + `ctx.upstream`**」两条既有通道，**不新增第三通道**（不改 `SkillRunner.run` / `SkillContext` 签名）/ 若错（须支持独立于参数的输入载荷，如 `stock_id` / 组合对象）：须先改 [03 §1.2](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 与 01 §2 契约，再返工全部 12 个执行器与本基件 / 验证：GWT-1 逐条 `runner.run(skill_id, {…参数})` 即可得到非「未注册执行器」的结果；`SkillContext` 字段表零变化。
- A2 描述体种子（`pack.py`）的 `input_schema` / `output_schema` **维持原样**——前者是工作流连线契约（T-L1-003 已按 `required` 判定），后者是执行期核验契约；本任务不为「让输入可传」而增删既有参数（[T-L1-003.5](T-L1-003.5-模板库与空状态.md) 的模板已按名绑定 `threshold` / `format` / `window_days` / `margin` / `lookahead_days` / `shock` / `lookback_years` / `fiscal_years` / `top_n` / `max_results` / `exchange` / `frequency_minutes`，改名即断链）/ 若错（须改种子）：返工面＝种子 + 本父任务全部执行器 + `T-L1-003.5` 模板绑定复核 / 验证：装载后 `SkillRegistry.list_all()` 的 12 项与装载前逐字段一致（装载只播种不改造）。
- A3 取数源以**鸭子类型**接入（`MarketQuerySource` 只要求 `query`），不在 L1 内 import L0 具体类——与 [`freshness.py`](../../src/st_agent/l1/reuse/freshness.py) 的 `MarketFreshnessOracle` 同一取向，使测试可注入离线 Fake 而不污染 L0 / 若错（须硬绑 `MarketDb`）：`test_layering` 仍通过（向下依赖合法），但 Fake 注入口收窄、`T-INT-001` 的离线装配变难 / 验证：本任务用例以一个内存 Fake 取数源跑通 GWT-1/3/4；`test_layering.py` 通过。
- A4 「数据不可用」与「空结果」的判定**全部由 L0 侧给出**（`MarketDb.query` 已把库缺失判为 `unavailable` 并带 `last_updated_at`、无行判为 `empty`），本基件只做**透传**不做二次判定 / 若错（须在 L1 侧另判新鲜度）：返工面＝基件 + `.2` / `.3` 全部分支用例 / 验证：GWT-3 用「库缺失」的 Fake（`query` 返回 `unavailable`）断言信封原样透出，`reason` 与 `last_updated_at` 逐字段相等。
- A5 装载**只增量、不清理**：已注册的 `skill_id` 不重复注册、已注册的执行器不被覆盖为空；本任务不提供「卸载官方 Pack」路径（Story-02 的 Out of Scope 明列无自动更新，更新走 01 §9 版本通道）/ 若错（须支持卸载/换版）：须另立任务并接 [T-L1-007](T-L1-007-stdio审计边界与MCP派生Skill回收.md) 的回收面 / 验证：GWT-2 二次装载返回空清单且执行器行为不变。
- A6 数据快照证据引用取**有界稳定摘要**：L0 的水位组合串（`MarketDb.snapshot_id()`）在满任务表（20 个同步任务）下约 350 字符、且不是 `snap_<20 位>` 形态，超出 `EvidenceRef.ref` 的 128 上限；故 `snapshot_ref` 取 `snap_ + sha256(组合串)[:20]`（确定性：同水位同名、换水位换名）。**该越界是 L0 侧既有口径问题**，已按册规登记 [L0 册](../遗留问题/L0-遗留问题.md) E 段（实现期新发现），本任务只做有界化不追改 L0 / 若错（须原样携带组合串，或 L0 直接产出 `snap_` 形态 ID）：返工面＝本基件 `snapshot_ref` + `T-L1-004.2` 的 `delisting-risk-scan` 证据引用（并随 L0 侧改造联动）/ 验证：`test_snapshot_ref_is_bounded_and_deterministic`（同名 / 换名 / 长度 ≤128 / `kind` 与 `snap_` 形态）。
