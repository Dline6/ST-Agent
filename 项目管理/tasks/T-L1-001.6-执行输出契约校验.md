# T-L1-001.6 · 执行输出契约校验

## 目标
让 01 §2 声明的 `input_schema` / `output_schema` 从**装饰性字段**变成执行期真校验：SkillRunner 执行成功后按描述体的 `output_schema` 核对结果载荷，不合契约则走显式失败分支并留痕，**不得**把不合契约的载荷按 `ok` 登记进输出复用；同一校验器交付为可复用件，供 T-L1-003 连线校验（上游输出 → 下游输入匹配）复用，避免各层各造一套匹配口径。

## 验收标准（Given-When-Then）
- GWT-C1 不合契约即显式失败：Given 描述体声明了 `output_schema`（含必填属性与类型），When 执行器返回的载荷缺必填属性或类型不符，Then 信封为 `failed`（含 `log_ref` 可查日志入口与违规点说明），且本次输出不登记为可复用结果。
- GWT-C2 合规输出放行：Given 载荷符合 `output_schema`，When 执行成功，Then 信封 `ok` 且照常登记为可复用结果（行为与现状一致）。
- GWT-C3 未声明不误伤：Given `output_schema` 为空（历史 Skill / 宽松态），When 执行，Then 不做校验、行为与现状完全一致（`status=empty` 的合法空结果同样不校验）。
- GWT-C4 校验器可复用：Given 同一校验器，When 上层（连线校验 / 官方 Pack 装载）调用它判定「上游输出 → 下游输入」是否匹配，Then 得到确定性结论与人类可读的不匹配说明（指出缺哪个字段、类型差在哪）。
- 回归：既有全量用例全绿（591，含官方 Pack 全部 Skill 的 schema 与执行器输出一致）。

  - T-L1-001.2：`SkillRunner._execute`（`src/st_agent/l1/runner/runner.py`）执行器返回点（`runner.py:338`–`352`）与 `finish()` 输出登记点（`runner.py:231`）；登记口径 `REUSABLE_STATUSES`（`src/st_agent/l1/reuse/models.py`）

## 假设与前提
- **A1 · 方言口径＝最小 JSON Schema 子集**：取 `type` / `properties` / `required` / `items` 四个关键字，`type` 取值 `object`/`string`/`number`/`integer`/`boolean`/`array`。若错（下游或导入方需要更宽方言）：返工面＝校验器 + T-L1-003 连线校验 + T-L1-004 Pack 装载 + 生态导入校验。验证：官方 Pack 现有 12 个描述体全部落在子集内（已核对 `pack.py`），本批用例覆盖每个关键字。
- **A2 · 校验触发条件＝`status=ok` 且 `output_schema` 非空**：`empty` 无载荷不校验、未声明不校验（GWT-C3）。若错：历史宽松 Skill 被误伤，或合法空结论被误判失败。验证：`tests/l1` 既有流水线用例（`output_schema` 为默认空 dict）+ 本批 GWT-C2/C3 用例。
- **A3 · 违规分支取 `failed`**：§5 中 `validation_failed` 语义限「输入/参数校验失败」，输出契约违例属执行面失败；GWT-C1 要求「可查日志入口」，`failed` 恰需 `log_ref`。若错：状态语义与 UI 渲染口径需回调。验证：GWT-C1 用例断言 `status == "failed"` 且 `log_ref` 指向本次 `skill-run/<id>.json`。
- **A4 · 校验器落在 `contracts/`**：与 §6 的 `NeutralityGuard`（`src/st_agent/contracts/neutrality.py`）同构——层间中立、各层可复用。若错：T-L1-004 装载期复用须跨层 import L1 内部，违反宪法第 7 条。验证：T-L1-003/T-L1-004 只经 `st_agent.contracts` 引用。
- **A5 · 类型判定用严格口径**：`bool` 不算 `number`/`integer`（沿用 `registry._check_single` 既有口径，避免 Python `bool` 是 `int` 子类的陷阱）。若错：`True` 被当作合规数值放行。验证：本批单测含 `bool` 对 `number` 的反例。
