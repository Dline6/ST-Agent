# T-L1-001.6 · 执行输出契约校验

## 目标
让 01 §2 声明的 `input_schema` / `output_schema` 从**装饰性字段**变成执行期真校验：SkillRunner 执行成功后按描述体的 `output_schema` 核对结果载荷，不合契约则走显式失败分支并留痕，**不得**把不合契约的载荷按 `ok` 登记进输出复用；同一校验器交付为可复用件，供 T-L1-003 连线校验（上游输出 → 下游输入匹配）复用，避免各层各造一套匹配口径。

## 验收标准（Given-When-Then）
- GWT-C1 不合契约即显式失败：Given 描述体声明了 `output_schema`（含必填属性与类型），When 执行器返回的载荷缺必填属性或类型不符，Then 信封非 `ok`（含可查日志入口与违规点说明），且本次输出不登记为可复用结果。
- GWT-C2 合规输出放行：Given 载荷符合 `output_schema`，When 执行成功，Then 信封 `ok` 且照常登记为可复用结果（行为与现状一致）。
- GWT-C3 未声明不误伤：Given `output_schema` 为空（历史 Skill / 宽松态），When 执行，Then 不做校验、行为与现状完全一致。
- GWT-C4 校验器可复用：Given 同一校验器，When 上层（连线校验 / 官方 Pack 装载）调用它判定「上游输出 → 下游输入」是否匹配，Then 得到确定性结论与人类可读的不匹配说明（指出缺哪个字段、类型差在哪）。
- 回归：既有 397 用例全绿（官方 Pack 全部 Skill 的 schema 与执行器输出一致）。
