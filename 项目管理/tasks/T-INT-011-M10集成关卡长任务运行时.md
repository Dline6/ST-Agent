## 目标
端到端验证：一个需要多轮、多工具、大结果的任务能跑完且不崩上下文。

## 验收标准（Given-When-Then）
- GWT-1：Given 一个需要十余步与多个工具的任务，When 循环执行，Then 不超窗、不丢结果。
- GWT-2：Given 大结果，Then 可回读而不必重查。
- GWT-3：Given 并行调用，Then 权限与留痕口径不因并发而放宽。
- GWT-4：Given 子 Agent，When 派生，Then 其上下文不进主窗，仅回传结论与引用。

## 假设与前提
- **A1**（「十余步」按 ≥12 个动作步计）——前提：缺省步数上界 8 不足以覆盖；关卡内经 `investigate.max_steps` 提到 16（≤32 上限），并以 `investigate.context_budget=32000`（登记上限）验证「不超窗」。若错的影响：GWT-1 无法按字面覆盖十余步。验证方式：断言 12 步全为真实执行步、最终 prompt 含全部 12 步且每轮 prompt 字符数 ≤ 预算。
- **A2**（组合根已声明并发安全）——前提：`composition/agent.py` 的 `investigate` / `resume` 均注入 `parallel_safe=True`（T-AGT-018.1）。若错的影响：并行批退回串行，GWT-3 的「并发下口径不放宽」落不了地。验证方式：断言 `AgentRunRecord.parallel_used is True` 且 `parallel_note` 标明并行执行。
- **A3**（子 Agent 隔离判据）——前提：子步载荷不进主上下文，主上下文只含结论与 `skill_run_id` 引用。若错的影响：隔离目标被破坏。验证方式：断言子步骤结果中的独有标记不出现在父循环 prompt，同时子结论与引用出现。
- **A4**（stdio stub 可入关卡）——前提：`_mcp_stub_server.py` 是本机子进程，不经 L0 出网网关、不联网。若错的影响：关卡需另造注入式替身。验证方式：装配后 `add_server` 连接测试成功，资源读取走真 stdio 往返。
- **A5**（模型选步质量不在关卡范围）——前提：脚本端点代表模型选步，沿用 M5–M9 关卡先例。若错的影响：关卡只能证明装配与跨层数据流，不能证明模型质量。验证方式：执行日志显式写明该边界。
- **A6**（脚本端点扩展属测试夹具）——前提：新增的多调用 / 动态参数能力只用于 `tests/integration/rig_m10.py`，不改产品 API 与既有 rig。若错的影响：测试夹具与产品行为混同。验证方式：产品代码零改动，既有集成套件仍全绿。
