# T-L3-003.1 · 草稿契约与生成（§5）+ configure 去向接线

## 目标

兑现 [05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 的**契约与生成**面：把一张**已确认**的 `configure` 意图确认卡收敛为 `ConfigDraft`（四字段），并把派发总线里 `wired=False` 的 `configure` 去向接活（现登记 `owner="T-L3-003"`）。草稿的**处置**（接受/微调/拒绝）归 [`.2`](T-L3-003.2-双通道登记面与处置三态.md)，工作流分支归 [`.3`](T-L3-003.3-工作流草稿交接与Studio落画布.md)。

## 验收标准（Given-When-Then）

- **GWT-1 · 草稿四字段生成**：Given 一张已确认的 `configure` 意图确认卡（[§3.2](../../docs/技术架构-v2/05-L3-对话主入口.md)）与目标声明体，When 生成草稿，Then 产出 `ConfigDraft` 四字段齐备——`target`（目标 Skill / 工作流）、`parameter_draft`（对齐 `SkillDescriptor.parameters` 的取值）、`understanding_summary`（**与确认卡条目同源**，不另造第二份摘要）、`open_questions`（未澄清参数）；目标缺失或参数未在声明体内 → `validation_failed` + 理由，**不静默补默认**。
- **GWT-2 · 未澄清项与默认值来源标注**：Given 目标声明的参数中有**未经用户给出值**者，When 生成草稿，Then 已取到默认值的项进 `parameter_draft` 并在 `open_questions` 中**显式标注其来源为默认值**、无默认值的项标为待追问——两类**不混同**、**不静默替用户决定**。
- **GWT-3 · `configure` 去向接线**：Given 一张已确认的 `configure` 卡，When 经 [`DispatchBus.dispatch`](../../src/st_agent/l3/dispatch/bus.py) 派发，Then 不再走「去向尚未接入」的 `unavailable`，而是产出草稿；**未注入**草稿生成面时仍 fail-closed（`unavailable` + 点名），**不伪造**。同一改动不得影响其余五类去向的既有行为。

## 接口面

- **输入（消费的前置接口）**
  - `T-L3-002.1`（done）确认卡：[`IntentConfirmation`](../../src/st_agent/l3/intent/protocol.py) 的 `items`（`ConfirmationItem.text` / `.value` / `.source` / `.line()`）、`values`、`target`、`intent`、`mark_confirmed`——`parameter_draft` 与 `understanding_summary` 的**唯一来源**（[05 §3.2](../../docs/技术架构-v2/05-L3-对话主入口.md) 定案：卡的条目列表即 §5 `understanding_summary` 的同一份内容源）
  - `T-L3-002.2`（done）总线：[`DispatchBus`](../../src/st_agent/l3/dispatch/bus.py) / `DispatchOutcome` / [`ROUTE_SPECS`](../../src/st_agent/l3/dispatch/bus.py) 中 `configure` 一行的 `wired=False, owner="T-L3-003"`
  - `T-L1-001`（done）描述体：[`ParameterSpec`](../../src/st_agent/contracts/capability_types.py)（`name` / `type` / `default` / `choices`）——`open_questions` 的候选源与默认值来源；经**注入的鸭子类型取数口**（`get(skill_id) -> SkillDescriptor`，同 [`IntentProtocol`](../../src/st_agent/l3/intent/protocol.py) 的 `descriptors` 参数），缺省不注入即不产 `open_questions`（不臆测）
  - `T-SC-001.1`：[`ResultEnvelope`](../../src/st_agent/contracts/result_envelope.py)（01 §5）
- **输出（本任务交付的公共 API / 落盘位置）**
  - 新增 `src/st_agent/l3/config/` 包（本叶建 `draft.py` 与 `__init__.py`）：
    - `ConfigDraft`——[05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 四字段的机器可读形态；`open_questions` 的元素为结构化条目（`param` / `prompt` / `default` / `source`），以承载「供追问**或**标注默认值来源」两种用途
    - `generate(confirmation, *, descriptors=None) -> ResultEnvelope`（载荷为 `ConfigDraft`；未确认的卡 → `validation_failed`）
  - `DispatchBus` 增**可选**注入面与 `configure` 去向实现：`DispatchOutcome` 增草稿载荷字段；`ROUTE_SPECS` 的 `configure` 一行 `wired=True`（缺省未注入 → `unavailable` + 点名，同 `query` 去向「未注入 Skill 执行面」的写法）
  - 落盘：**本叶不落盘**（草稿是内存对象；「接受」的落盘归 [`.2`](T-L3-003.2-双通道登记面与处置三态.md)）
  - 同批改 [05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md)：补「四字段各自的**生成来源**」与「工作流分支的判定来源」两条实填口径

## 假设与前提

- **A1 · 草稿的 `parameter_draft` 取确认卡已收敛的 `values`，不再回到会话原文**：[05 §3.2](../../docs/技术架构-v2/05-L3-对话主入口.md) 已定案「确认卡是收敛的唯一落点」，且 [`T-L3-002.1`](T-L3-002.1-意图理解与澄清协议.md) 假设 A4 已把 `understanding_summary` 的同源口径钉死。若错（草稿须能表达卡上没有的信息）：返工面＝`generate` 的入参面与 §5 的口径。
- **A2 · 未澄清项的默认值来源以 `ParameterSpec.default` 判定**：[05 §3.2](../../docs/技术架构-v2/05-L3-对话主入口.md)「跳过用默认值继续」的默认值只存在于声明参数里。若错（默认值另有来源，如 01 §7 登记项的 `default`）：返工面＝`open_questions` 的来源与 [`.2`](T-L3-003.2-双通道登记面与处置三态.md) 的登记面口径。
- **A3 · `understanding_summary` 是**派生**字符串，不重复过中性校验**：[05 §2](../../docs/技术架构-v2/05-L3-对话主入口.md) 与 [D-053](../决策日志.md) 把「生成描述」与「数据本体」分栏——确认卡条目的 `text` 已在构造期过 [01 §6](../../docs/技术架构-v2/01-平台共享契约.md) 执行点 2，`value` 属数据展示原样承载；摘要由二者拼装而成，故不再整串复检（复检会把用户数据误判为违规）。若错（摘要须整体过校验）：返工面＝`generate` 的校验点。
- **A4 · `configure` 去向往 `DispatchOutcome` 增字段而非复用 `run`**：`run` 现语义为 `query` 的 `RunOutcome`。若错（须统一成一类载荷）：返工面＝`DispatchOutcome` 的形状与 [`.2`](T-L3-002.2-任务派发总线.md) 的既有用例。
