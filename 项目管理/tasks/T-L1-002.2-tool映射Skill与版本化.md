# T-L1-002.2 · MCP tool → Skill 自动映射与版本化

## 目标
把 MCP Server 的每个 tool 自动注册为平台 Skill（`source: mcp-mapped`），元数据从 MCP schema 派生（经 §6 中性化校验、schema 落 01 §2 方言）；映射关系版本化并按 tool 契约指纹判断「是否需要重新映射」，使挂载的外部能力与官方 Skill 在同一注册表、同一执行流水线里被调度。

## 验收标准（Given-When-Then）
- GWT-1 tool 自动注册为 Skill：Given 一个已注册且权限已批准的 MCP Server 提供了 N 个 tool，When 执行映射装载，Then N 个 Skill 经 `SkillRegistry.register` 落盘，`source == "mcp-mapped"`，`input_schema` 从 tool 的 MCP schema 派生并落在 01 §2 最小子集内，`name` 过 §6 中性化校验，可在 `SkillRegistry.list_all()` 中查到。
- GWT-2 幂等与增量：Given 同一 Server 已装载过，When 重复装载（tool 集合未变），Then 不产生重复注册、不报错（幂等）；When Server 新增了一个 tool，Then 只注册新增的那个，既有映射不受影响。
- GWT-3 契约变化标「待重新映射」：Given 某 tool 的 MCP schema 指纹与既有映射记录不一致，When 装载，Then 该映射被标记为「待重新映射」并给出显式提示（含 tool 名与变化说明），**不静默覆盖**已注册的 Skill 描述体。
- GWT-4 映射记录可复查：Given 一次装载完成，When 读取映射记录，Then 可得到 `tool 名 → skill_id + schema 指纹 + 映射版本` 的对应关系（按 01 §9 版本语义），供后续增量判断与生态追溯。
- GWT-5 Server 禁用联动：Given 某 Server 已被禁用（`.1`/`.3` 的禁用标记），When 查询可用 Skill 列表，Then 该 Server 派生的全部 Skill 立即不在可用列表中（映射记录保留，以便重新启用）。
- 回归：既有 591 用例全绿；`verify_docs.py --strict` PASS。

## 假设与前提
- **A1 · `skill_id` 由 server + tool 派生**：按 T-L1-001.1 口径拼 `sk_mcp_<server_id>_<tool>_v<主>.<次>`，两段都归一为小写 kebab/下划线并限长（`check_skill_id` 上限 128，注册名段 ≤60），冲突/超长即显式拒。若错（既有命名规则装不下）：返工面＝派生规则 + 映射记录 + 下游引用。验证：合法与超长两类用例。
- **A2 · 映射关系复用 T-L1-001.1 的待检查标记形态**：tool 契约变化以平行记录 `McpToolMapping.status` 表达（`active` / `pending-remap`），**不**复用 `UpdateInfo`（后者是版本升级语义，两者混用会让更新面板语义失真）。若错（产品要求统一面板）：返工面＝映射状态模型 + 面板数据源。验证：GWT-3 用例断言不产生 `skill-update/<base>.json`。
- **A3 · `output_schema` 由 MCP tool 的 output schema 派生，缺失时留空**：空 schema 在 T-L1-001.6 口径下不校验（宽松态），故不会误伤。若错：返工面＝映射派生 + 可能触发 `.3` 的调用结果校验。验证：无 output schema 的 tool 用例断言执行不因校验失败。
- **A4 · 装载不自动批准权限**：映射只对**已批准**权限的 Server 执行（GWT-1 前置），权限闸门仍归 `.1`。若错（要求装载时连带申请）：返工面＝装载入口 + `.1` 的批准面。验证：未批准 Server 用例断言装载被拒。
