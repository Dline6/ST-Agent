# T-L1-005 · 定时调度

## 目标

交付 L1 定时调度器（[03 §6](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)）：把「已注册的工作流」按其 `schedule` 与「声明了频率参数的 Skill」按其频率**到点触发**，触发产生的执行走 [03 §1.2](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 完整流水线（[01 §1](../../docs/技术架构-v2/01-平台共享契约.md) 的 `trace_id` 由调度器创建，留痕 SkillRun / Trace / ResultEnvelope），并处置**断网期间到期**的调度。

## 验收标准（Given-When-Then，从 Story 抄）

Story 02 的验收段**不含**定时调度，故 GWT 逐条锚定 [03 §6](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 三条原文与 [01 §1](../../docs/技术架构-v2/01-平台共享契约.md)，按叶子分散承载——见各叶子文件的 GWT 节（`T-L1-005.1` 四条 + `T-L1-005.2` 五条 + `T-L1-005.3` 五条）。

## 拆分记录（③ 已执行）

命中拆分触发（GWT 合计 14 条 ≫ 5、跨 [03 §6](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) / [03 §1.2](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) / [02 §7](../../docs/技术架构-v2/02-L0-本地优先基座.md) / [01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 四个契约小节、预计 Agent 会话轮次 > 20），已拆为三个叶子：

- `T-L1-005.1` 调度触发判定与运行状态：目标枚举（工作流 schedule + Skill 频率参数）+ 到期判定（`manual`/`interval`/`cron`/`event`）+ cron 求值件 + 运行状态落盘 + 手动触发（03 §6）
- `T-L1-005.2` 调度执行接线：到期项经 `SkillRunner` 走 §1.2 完整流水线；调度器创建 `trace_id`；工作流经复合 Skill（未物化即记依赖缺口、不执行）；权限经注入的鸭子类型来源（03 §1.2 / §3.2）
- `T-L1-005.3` 离线到期处置：按 `offline_level` 分级照跑并标注 / 记「待补」，网络恢复后按用户配置补跑或跳过（03 §6 第三句 + 02 §7）

④ 对齐定案：**触发目标范围取「工作流 `schedule` ＋ Skill 频率参数」**（03 §6 两个源头都落；不并入 L0 同步任务的触发节奏——那条归属在 docs 中无主，另议）；**调度执行的权限批准取「注入鸭子类型权限来源」**，本任务不建持久化批准面，Skill 侧批准记录落点的缺失已登记 [L1 册](../遗留问题/L1-遗留问题.md) `D1`（归属待立项）。cron 取自研最小 5 段子集（零第三方依赖）；`mode=event` 本轮只交付形态与显式 API 触发。

父任务 `T-L1-005` 的 `status` 由 children 派生，不再手填。
