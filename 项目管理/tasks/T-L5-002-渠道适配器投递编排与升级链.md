# T-L5-002 · 渠道适配器 + 投递编排与升级链

## 目标
交付 L5 的**触达执行面**（[07 §3–§4](../../docs/技术架构-v2/07-L5-主动触达.md)）：四类渠道适配器（桌面通知 / TTS / 邮件 SMTP / IM Webhook）、渠道偏好可配、渠道失效的显式降级，以及投递编排与升级链（每级 `delivery_id` 留痕、未读超时升级、`routine` 汇总进日报、文案个性化）。头两段（信号模型与采纳、注意力预算与情境模式）已由 [T-L5-001](T-L5-001-信号模型注意力预算.md) 交付。

**上游与本批的边界**（2026-10-06 读码核实）：

- [`EgressGateway`](../../src/st_agent/l0/net/gateway.py) 的白名单**已含 `channel_delivery`**（`tests/l0/test_net.py` 已有该 kind 的用例），云端渠道无需新增出网类目；`CredentialVault.use()`（[T-L0-002](done/M0/T-L0-002-密钥与凭据子系统掩码显示使用记录.md)）与 `ConfigRegistryFacade`（[T-L1-012](done/M2/T-L1-012-统一配置注册表门面.md)）均已就位。
- **原生通知的入口已存在但不可直接 import**——[`ui/shell/notify.py`](../../src/st_agent/ui/shell/notify.py) 给出平台命令与 `send_notification`，但 [`tests/test_layering.py`](../../tests/test_layering.py) 的 `test_ui_is_client_only` **机器禁止任何层 import `st_agent.ui`** ⇒ L5 只能经**注入的鸭子端口**取用；**本仓无 TTS 面** ⇒ 该渠道接线前走显式不可用。
- **事件投递面缺位**——[01 §11](../../docs/技术架构-v2/01-平台共享契约.md) 只登记事件形态与产生方 / 订阅方，「订阅面」无承载（[L3 册 `A2`](../遗留问题/L3-遗留问题.md)）；本批按 [铁律 8](../工程宪法.md) **先补契约再实现**。
- **`DeliveryId` 现为随机生成**（`dlv_` ＋ uuid 前 20 位）——本批把形态收窄为**确定性摘要**（[01 §1](../../docs/技术架构-v2/01-平台共享契约.md) 同批写实），使升级链重放 / 补发得同一 ID。

**拆分**（命中[拆分触发](../工作流.md)两条：验收 GWT>5 · 跨 [01 §1](../../docs/技术架构-v2/01-平台共享契约.md) / [§7](../../docs/技术架构-v2/01-平台共享契约.md) / [§11](../../docs/技术架构-v2/01-平台共享契约.md) 三个契约小节）——父转为分组节点，交付由三叶承接：

- [`T-L5-002.1`](T-L5-002.1-渠道适配器与渠道偏好.md)——**渠道适配器与渠道偏好**（07 §3）：四类渠道适配器 · 渠道偏好（级别 → 有序渠道链）与 01 §7 登记 · 渠道失效的显式提示与降级 · 离线标注与待发清单的标记
- [`T-L5-002.2`](T-L5-002.2-投递编排与升级链.md)——**投递编排与升级链**（07 §4）：升级链状态机与 `delivery_id` 留痕 · 未读超时升级与 `DeliverySettled` · `routine` 汇总进日报的路由 · 文案个性化（过 01 §6）· 离线补发的执行面（销 [L0 册 `A5`](../遗留问题/L0-遗留问题.md)）
- [`T-L5-002.3`](T-L5-002.3-平台事件投递机制与L5装配缝.md)——**平台事件投递机制与 L5 装配缝**（01 §11 + [L3 册 `A2`](../遗留问题/L3-遗留问题.md)）：事件投递口径契约 · 进程内 pub/sub 总线 · 接通 L2→L3 的 `MemoryConflictDetected` 与 L1/L4→L5 的 `SignalEmitted` · `build_l5` 薄装配缝（含 `AttentionBudgetFamily` 注入）

不拆成「一段一任务」之外的更细粒度，也不合并成一叶：三叶各有独立的失败面与验收（渠道面 / 编排面 / 事件面），合在一起会让范围套件与留痕混在一起（拆法同 [D-079](../决策日志.md) / [D-080](../决策日志.md) / [D-081](../决策日志.md)）。

## 验收标准（Given-When-Then）

取自 [story-07](../../docs/PRD-v2-Agent/story-07-ambient-delivery.md) 与本任务范围内的架构段，逐条落到三叶（父级只汇总，不重复）：

- Given 副驾产生一条紧急信号，When 触达策略判断，Then 按用户配置的升级链依次发送（桌面通知 → 5 分钟未读 → 邮件 → 15 分钟未读 → IM），每级产生一枚 `delivery_id` 留痕 → [`.2`](T-L5-002.2-投递编排与升级链.md) GWT-1
- Given 副驾产生一条日常信号，When 触达策略判断，Then 汇总进日报、**不单独推送**（除非用户显式配置）——记 `route="daily_report"` 的待汇总项，不丢弃 → [`.2`](T-L5-002.2-投递编排与升级链.md) GWT-3
- Given 断网状态，When 有紧急信号，Then 本地通知正常发送 + 云端渠道明确标注「离线，暂无法发送」+ 网络恢复后按用户开关自动补发 → [`.1`](T-L5-002.1-渠道适配器与渠道偏好.md) GWT-4 / [`.2`](T-L5-002.2-投递编排与升级链.md) GWT-5
- 边缘：某渠道配置错误（如 IM Webhook 失效）→ 明确提示 + 自动降级到下一渠道 → [`.1`](T-L5-002.1-渠道适配器与渠道偏好.md) GWT-3
- Given 每种信号级别，When 配置对应渠道，Then 偏好经 01 §7 的对话 / 面板两通道读到同一份值 → [`.1`](T-L5-002.1-渠道适配器与渠道偏好.md) GWT-2 / GWT-5
- Given 同一条信号对不同用户，When 生成推送文案，Then 措辞随记忆图谱的风格偏好切片而变，且**一律过 01 §6 中性化**（个性化 ≠ 拟人化） → [`.2`](T-L5-002.2-投递编排与升级链.md) GWT-4
- Given 一条 `SignalEmitted` 与一条 `MemoryConflictDetected`，When 经总线发布，Then 订阅方按登记顺序收到（派发决定论），订阅者抛错**不吞**且其余订阅者照常收到 → [`.3`](T-L5-002.3-平台事件投递机制与L5装配缝.md) GWT-2 / GWT-3

> 每日报告本体、去重频控与推送疲劳监控**不在本任务**（[T-L5-003](T-L5-003-每日报告去重频控推送疲劳监控.md)）；端到端装配与真实 SMTP / Webhook 复核归关卡 [T-INT-004](T-INT-004-M3集成关卡主动触达投递闭环.md)。

## 假设与前提
- **A1 · 三叶按阶段拆**（2026-10-06 ④ 对齐拍定，[D-082](../决策日志.md)）——前提：渠道面 / 编排面 / 事件面各有独立失败面与验收，且跨 [01 §1](../../docs/技术架构-v2/01-平台共享契约.md) / [§7](../../docs/技术架构-v2/01-平台共享契约.md) / [§11](../../docs/技术架构-v2/01-平台共享契约.md) 三节。若错（要求更细 / 更粗的粒度）：返工面＝父子任务文件与关卡的 `depends_on` 指向。验证方式：三叶各自的范围套件与 `verify_docs --strict` 检查 7。
- **A2 · 原生能力经注入端口、L5 不 import 表现层**（2026-10-06 ④ 对齐拍定）——前提：[`test_ui_is_client_only`](../../tests/test_layering.py) 机器禁止任何层 import `st_agent.ui`；原生通知的平台命令已有单一份实现（[`ui/shell/notify.py`](../../src/st_agent/ui/shell/notify.py)）。若错（要求 L5 自持平台命令）：返工面＝[`.1`](T-L5-002.1-渠道适配器与渠道偏好.md) 的桌面渠道适配器。验证方式：`.1` 以注入替身断言命令、并断言 `src/st_agent/l5/**` 无 `st_agent.ui` import。
- **A3 · 事件总线住 L1 且以鸭子端口接入**（2026-10-06 ④ 对齐拍定）——前提：[01 §11](../../docs/技术架构-v2/01-平台共享契约.md) 的发布方 / 订阅方跨 L1–L5，住 L1 时全部接入方向合法（L0 不发布事件）；与 [D-067](../决策日志.md) 的 01 §7 门面归属同一裁法。若错（要求总线下沉到 L0 或上浮到 L5）：返工面＝[`.3`](T-L5-002.3-平台事件投递机制与L5装配缝.md) 的总线落点与各层接入。验证方式：`.3` 的派发用例 + [`tests/test_layering.py`](../../tests/test_layering.py)。
- **A4 · 补发依据取本层留痕而非 L0 审计**（2026-10-06 ④ 对齐拍定，[L0 册 `A5`](../遗留问题/L0-遗留问题.md) 的收口口径）——前提：02 §6 的出网审计**可选、默认关**（[D-073](../决策日志.md)），默认关时 `pending_reconnect()` 按设计走显式 `unavailable`，故补发清单不能建在审计上。若错（要求以审计为准）：返工面＝[`.2`](T-L5-002.2-投递编排与升级链.md) 的待发清单来源。验证方式：审计**关闭**时补发链照常工作（用例钉住）。
- **A5 · `routine` 的日报路由只记待汇总项**——前提：[07 §5–§6](../../docs/技术架构-v2/07-L5-主动触达.md) 的日报本体与去重频控归 [T-L5-003](T-L5-003-每日报告去重频控推送疲劳监控.md)，本批只有「记下这条该进日报」的判定与留痕。若错（要求本批产日报）：返工面＝[`.2`](T-L5-002.2-投递编排与升级链.md) 的范围。验证方式：判定用例断言 `route="daily_report"` 且**未调**任何渠道投递。
