# T-SC-001.5 · 时间锚点 dataset_snapshot_id / as_of 与事件信封

## 目标
实现 [01-平台共享契约](../../docs/技术架构-v2/01-平台共享契约.md) §8 的时间锚点类型（dataset_snapshot_id + as_of，用户本地时区语义、内部传输带时区）与 §11 事件清单的统一事件信封（核心事件名 + 强制携带关联 trace_id / change_id）。新鲜度水位与陈旧判据本身由 L0（T-L0-005）按数据库设计 sync_state 落地，此处只定类型口径。

## 验收标准（Given-When-Then）
- GWT-5：Given 快照/新鲜度需求，When 标注数据时间，Then 统一用 `dataset_snapshot_id` + `as_of`（§8），不另立第二套口径。
- GWT-SC11：Given 一个跨层上行事件，When 构造事件，Then 事件名属于 §11 核心事件清单且携带关联 trace_id / change_id（如适用）。

## 涉及契约
- [01-平台共享契约](../../docs/技术架构-v2/01-平台共享契约.md) §8 数据快照与时间口径 / §11 事件清单（上行通知）
- 时间水位真相源：[05-同步策略与新鲜度契约](../../docs/数据库设计-BaoStock数据层/05-同步策略与新鲜度契约.md)（由 T-L0-005 消费）
