# T-UI-003 · 对话端点请求体失败显式化

## 目标
回环对话端点 `POST /api/chat` 对**非法请求体**（畸形 JSON / 空体 / 缺 `text` 键名写错）当前**不显式失败**：
门面在构造 `ChatMessage` 时抛 `pydantic ValidationError`，异常从 `UiRequestHandler.do_POST` 逸出
→ 线程打印 traceback、连接被关闭，客户端拿到 `RemoteDisconnected` 而**不是任何信封**。
本条把它收敛为**显式**：非法请求体 → 合法 `ResultEnvelope`（`validation_failed`，中性原因）；
门面的其他未预期异常 → `failed`（附 `log_ref`）**且**服务端日志含 traceback（不吞真错）。
产出归 `00 §6「失败显式化」`。

> **本任务由实测暴露（2026-10-05）**：起后端 `python -m st_agent --root <临时根> --handshake json --control-stdin`
> 后 `POST /api/chat` 带 `{"message": "你好"}`（键名写错，`DialogFacade` 期望 `{"action": "post"|"dispatch", "text": …}`）
> → 客户端恒 `RemoteDisconnected`；三种非法体均复现（复现脚本与 traceback 见执行日志）。

## 验收标准（Given-When-Then）
- **GWT-1** Given 畸形请求体（非 JSON 字节 / 非法 UTF-8），When `POST /api/chat`（带令牌），
  Then HTTP 200 且 body 为**合法信封**载荷（含 `status` ∈ 六态、`render.presentation`、非 ok 带 `reason`），
  **不**出现连接被服务端关闭（客户端不获 `RemoteDisconnected`）。
- **GWT-2** Given 空体（`Content-Length: 0` 或 body 为 `{}`），When 同上，Then 同 GWT-1。
- **GWT-3** Given 缺 `text` 的体（`{"action": "post"}`）与**错键**体（`{"message": "你好"}`，
  门面期望 `text`），When 经**真实** `DialogFacade` 走 HTTP，Then 同 GWT-1（`status="validation_failed"`）。
- **GWT-4** Given 门面抛**非输入类**异常（编程 / 内部错误），When `POST /api/chat`，
  Then HTTP 200 且信封 `status="failed"`、`log_ref` **非空**，且服务端日志记录了该异常的 **traceback**（未静默）。
- **GWT-5** Given 合法请求（`{"action": "post", "text": "查 sh.600000 退市风险"}`），When 同端点，
  Then 行为**不变**：`status="ok"`、`needs_confirmation=true`（捕获不得改变正常路径语义）。

- **输入**：

    的 `UiRequestHandler.do_POST` / `_read_json_body`（畸形 / 空体已归一为 `{}`）与 `src/st_agent/ui/app.py`
    的 `UiApp.api_chat(body) -> dict`（本任务改点）。
  - [`T-UI-002.1`](T-UI-002.1-生产运行入口与壳后端握手协议.md) 的生产入口——把组合根的 `chat` 门面
    经 `serve(chat=…)` 注入（本任务复现路径）。
  - 门面契约：`st_agent.app.DialogFacade.turn(body: Mapping) -> dict`（[`T-INT-002`](done/M1/T-INT-002-M1集成关卡首次可对话.md)），
    返回 `{"reply": ResultEnvelope, "session_id", "needs_confirmation", "description"}`；
    非法输入时其在构造 L3 契约对象处抛异常（非返回信封），故**失败显式化的责任在 ui 边界**。
  - 契约口径：[00 §6 失败显式化](../../docs/技术架构-v2/00-架构总览.md) ·
    [01 §5 ResultEnvelope](../../docs/技术架构-v2/01-平台共享契约.md) ·

- **输出**：`UiApp.api_chat` 的**前端契约不变**（仍回可 JSON 化的 dict 载荷，字段同 `envelope_payload`），
  但**新增不变量**：它**不向上抛**门面异常，任何输入都回一个合法信封载荷。
  `log_ref` 形态 `ui/chat-<12hex>`，与服务端 `st_agent.ui.server` 日志行内同一串（可 grep 定位）。

## 假设与前提
- **A1**：「请求体非法 → 门面拒绝」在本仓的全部形态是 **`ValueError` 族**——
  pydantic 包装的 `ValidationError`（`ChatMessage` 空白文本）与 L3 的 `SessionValidationError` /
  `IntentValidationError` / `ConfigValidationError` / `ConflictValidationError` 均继承 `ValueError`；
  另有 `session_id` 寻址失败＝`SessionNotFoundError`（`KeyError` 子类）。
  **若错的影响**：漏转一类非法输入 → 该输入仍断连（GWT 覆盖不到）。**验证方式**：GWT-1–3 以真实门面各取一族
  （空白文本→ValidationError；未知 `session_id`→KeyError）证实转入信封。
- **A2**：门面**正常路径不靠异常做控制流**（合法输入恒返 dict、不抛）。**若错的影响**：捕获过宽会改变正常语义。
  **验证方式**：GWT-5 回归 + 既有 `tests/ui` / `tests/integration` 原有用例保持全绿。
- **A3**：该端点的**失败以「HTTP 200 + 信封 body」表达**（与既有成功路径及「未注入门面→unavailable」
  一致），**不**改为 4xx。**若错的影响**：前端按 `status` 选渲染会与传输层语义打架（成功/失败混在状态码与 body 两处）。
  **验证方式**：GWT-1–4 断言 HTTP 200。
