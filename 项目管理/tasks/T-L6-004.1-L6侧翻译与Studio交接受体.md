# T-L6-004.1 · L6 侧：`SkillDraft`→`WorkflowDraft` 翻译与 Studio 交接受体

## 目标
在 L6 侧交付**主动提案落 Studio** 的两个纯库面构件（[08 §4](../../docs/技术架构-v2/08-L6-反思演进.md)）：

1. **翻译（唯一实现）**：把 [`SkillDraft`](../../src/st_agent/l6/proposal.py)（`name` / `description` / `nodes` / `edges` / `groups` / `schedule` / `flow_name`）翻成 [03 §4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的 [`WorkflowDraft`](../../src/st_agent/l1/studio/draft.py)（四字段 + `workflow_draft` 子对象；**身份字段 `flow_id` / `version` 不入**）。
2. **交接受体**：`StudioHandoff`——按 `proposal_id` 取提案、翻译、交 [`DraftIntake.receive`](../../src/st_agent/l1/studio/draft.py) 落画布、**持会话**（`proposal_id → DraftSession`），三态（接受 / 微调 / 拒绝）**转交** L1，**不复制**其判定。

**为什么住 L6**：L6 > L1，可向下 import L1（[铁律 7](../工程宪法.md)）；先例 [`AgentFamily`](../../src/st_agent/l6/registry_adapter.py)（上层 owner 经组合根注入 L1 门面）。`SkillDraft` 本体（[`proposal.py`](../../src/st_agent/l6/proposal.py)）**保持不 import L1**——依赖只落在本适配器模块。

## 验收标准（Given-When-Then）
- **GWT-1 · 翻译形态对齐**：Given 一条含 `SkillDraft` 的 `SkillProposal`，When 翻译，Then 得 `WorkflowDraft`——`target` / `understanding_summary` 非空、`parameter_draft={}` / `open_questions=()`、`workflow_draft` 恰含 `name` / `description` / `nodes`（`edges` / `groups` / `schedule` / `flow_name` 空者不携），且**不含** `flow_id` / `version`——携身份字段即由下游 `DraftIntake` 拒（不静默丢）。
- **GWT-2 · 落画布交接**：Given 一条已检出提案，When `handoff(proposal_id)`，Then 经 [`DraftIntake.receive`](../../src/st_agent/l1/studio/draft.py) 产出 `DraftSession` 并**持住**；返回的画布视图含暂定 `flow_id`（`_PROVISIONAL_VERSION` = `0.0`）、`base`、节点数、语义违规清单（`DraftSession.validation`）。**形状**非法（草稿无法构造 `WorkflowDAG`）→ `DraftShapeError` **显式上升**、会话**不登记**（画布不开）。
- **GWT-3 · 三态委托 L1**：Given 一个已开画布的会话，When 接受 / 微调 / 拒绝，Then 分别落 v1.0 并产生 `change_id`（`AcceptResult.change_id`）/ 返回**同一个** `CanvasEditor` 句柄 / 丢弃不落盘——**委托** L1，本叶**不另造**第二套落盘或变更留痕；接受后该 `proposal_id` 的会话标 `accepted`，重复处置**显式拒**（`DraftSessionError`）。
- **GWT-4 · 未注入即 fail-closed**：Given 未注入 `DraftIntake` 或 `ProposalEngine`，When 交 Studio，Then **显式失败并点名**（`StudioHandoffError` / 未接面），**不伪造**「已交 Studio」；`proposal_id` 不存在 → 同样显式点名（不臆造一条提案）。
- **GWT-5 · 文案中性**（[铁律 2](../工程宪法.md) / [01 §6](../../docs/技术架构-v2/01-平台共享契约.md)）：翻译**不新造**生成性文案——`understanding_summary` 取提案 `reason`（缺省回落草稿 `description`），两者均已在提案检出时过 [01 §6](../../docs/技术架构-v2/01-平台共享契约.md) 执行点 1/2 校验，故本叶不引入新的中性化面。

## 假设与前提
- **A1 · 翻译的 `target` / `understanding_summary` 取自提案既有字段，不新造文案**——前提：`WorkflowDraft` 两字段均 `min_length=1`，而 `SkillDraft.name` 非空（`min_length=1`）、提案 `reason` 可空。故 `target=draft.name`；`understanding_summary = proposal.reason or draft.description`（两者均已在提案检出时过 [01 §6](../../docs/技术架构-v2/01-平台共享契约.md)）。
  **若错的影响**：若要求另写一段「我理解到 …」的生成文案，返工面＝本叶引入 `NeutralityGuard.check_output` 与对应用例（新增一个中性化面）。
  **验证方式**：GWT-5 断言 `understanding_summary` 与 `reason` / `description` 同源；`grep` 断言本叶不调 `check_output`。
- **A2 · 会话按 `proposal_id` 持在适配器内存**——前提：草稿态**不落盘**（[03 §4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 编辑期不落盘，「接受」是唯一落盘点），故会话无需持久化；重启丢会话＝丢草稿，可重新交 Studio（幂等）。
  **若错的影响**：若要求会话跨重启存活，返工面＝引入会话落盘（新分区/新形态），与「编辑期不落盘」正面冲突，应另立项。
  **验证方式**：GWT-2 断会话在 `handoff` 后可经 `session(proposal_id)` 取回；用例断言未接受时盘上无新文件。
- **A3 · 重复交 Studio 幂等**——前提：同 `proposal_id` 已有未闭会话时 `handoff` 返回**同一**会话视图（不新开、不重置）；已 `accepted` / `rejected` 的会话 → `handoff` 重新开会话（接受过则重申会因 base 已存在而由 L1 显式拒）。
  **若错的影响**：若要求「一律新开会话」，返工面＝`handoff` 的幂等分支与用例。
  **验证方式**：GWT-2 / GWT-3 的重复调用用例。
- **A4 · 三态不重包**——前提：`DraftIntake.accept` / `.tune` / `.reject` 已是公开 API 且口径齐备（[03 §4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)），除一致性（同一 `proposal_id` 同一会话）外本叶不复制判定。若错：返工面＝`StudioHandoff` 返回类型与 L1 三态对齐。
  **验证方式**：GWT-3 断接受经 `DraftIntake.accept`、`change_id` 由 L1 铸造。
