# T-UI-010.2 · 页面集与导航模型

> [T-UI-010](T-UI-010-契约先行组件型补齐与页面集口径.md) 的页面集叶（[D-108](../决策日志.md)）。IA 是「有哪些屏」（[`T-UI-006`](T-UI-006-IA补章受控自主分区与页面Flow.md) 已补章）；本叶定「**屏落到哪个路径**、导航怎么组织」，并与 [`PAGE_PATHS`](../../src/st_agent/ui/app.py) / [`pages.js`](../../src/st_agent/ui/web/js/pages.js) 同源。

## 目标

两件交付，都在**口径 + 文档 + 机器守卫**面（本叶**不建页面、不注册新页面**——登记归 [`T-UI-011`](T-UI-011-底座与骨架多面端口注入与全IA页面登记.md)）：

1. **屏 → 页面路径对位**——把 [`.1`](T-UI-010.1-组件型补齐屏形态对位与四型落地.md) 判为**页面**的屏逐条归并到**页面路径**（判为壳面 / 对话流内面的屏**不落路径**，其在 `/` 主入口内承载——该结论取自 `.1` 的对位表）；路径命名沿用既有段式（分区前缀 + `kebab`，如 `/memory` · `/reflection/changes` · `/eco/import`）。
2. **导航模型口径**——[11-sitemap §1](../../docs/PRD-v2-Agent/11-sitemap.md) 声明「**无传统菜单式入口层级**」，而现壳有常驻 `nav` 列表；把两者调和的口径落文档：`nav` ＝**辅助区的扁平入口**（非多级菜单），主入口恒为 Chat `/`，非对话类页面从上下文卡片 / 结果组件 / 全局入口进入（§1 原声明）——`nav` 只是把「全局入口」可视化的**同一件事**，不构成层级。

**本批的边界**（不越界）：

- **不建页面、不注入端口**——`PAGE_PATHS` / `pages.js` 的**新增登记**归 [`T-UI-011`](T-UI-011-底座与骨架多面端口注入与全IA页面登记.md)；本叶只出**权威口径**并加一条**防漂移守卫**（既有的页面路径不得超出对位表声明集）。
- **不重排既有 13 条路由**——已落地的路径（`/memory` · `/reflection/**` · `/settings/evolution` · `/eco/**` · `/studio`）逐字不动；对位表以它们为既定事实、不更名。
- **不改壳的路由机制**——`PAGE_PATHS` 是**精确匹配**集合、SPA 回退与令牌分档（[D-063](../决策日志.md)）不动；本叶不为动态段（如节点详情）改机制，改用**查询串 / 页内视图**表达（见 §2.2 口径）。

## 验收标准（Given-When-Then）

- GWT-1：Given [11-sitemap §2](../../docs/PRD-v2-Agent/11-sitemap.md) 的屏与 [`.1`](T-UI-010.1-组件型补齐屏形态对位与四型落地.md) 的形态对位表，When 逐条归路径，Then **每个「页面」类屏落到某路径**、**每个声明路径有出处**（点名承载的屏），壳面 / 对话内面显式标注「落 `/` 主入口，不单列路径」
- GWT-2：Given 声明路径集与 [`PAGE_PATHS`](../../src/st_agent/ui/app.py) / [`pages.js`](../../src/st_agent/ui/web/js/pages.js)，When 对位，Then 既有注册的每条路径都在声明集内（**新守卫**：`tests/ui` 里的漂移用例解析 11-sitemap §2.2 的声明集，断言 `PAGE_PATHS ⊆ 声明集`），且 `PAGE_PATHS` ↔ `pages.js` 仍相等（既有漂移断言不红）
- GWT-3：Given 导航模型口径，When 查文档，Then 口径已落 [11-sitemap](../../docs/PRD-v2-Agent/11-sitemap.md) 且与 §1「无传统菜单式入口层级」**不冲突**（显式说明 `nav` ＝扁平全局入口，非层级）
- GWT-4：Given 未注册的声明路径（缺口），When 查账，Then 有**显式的欠账去向**（点名 [`T-UI-011`](T-UI-011-底座与骨架多面端口注入与全IA页面登记.md) 承接，非静默留悬）
- GWT-5：Given 全项目相对链接，When 在 `项目管理/` 下跑 `python tools/verify_docs.py --strict`，Then 检查 1–9 全过、0 断链

## 假设与前提

- **A1**：页面路径可用**页内视图切换**表达「同一路径下的多视图」（记忆区三视图 → `/memory`；设置四页 → `/settings` 分支），无需为每视图各立一条路由。**若错的影响**：声明路径数膨胀，且需为壳引入动态段 / 子路径匹配（现为精确匹配集合），波及 [`T-UI-011`](T-UI-011-底座与骨架多面端口注入与全IA页面登记.md) 与壳机制。**验证方式**：查 [`pages.js`](../../src/st_agent/ui/web/js/pages.js) 的既有登记已按分区聚合（`/eco` 一条 + 其子面三条），非「一屏一路径」。
- **A2**：节点详情等**带标识**的面用**查询串**（`/memory?node=<id>`）而非路径段。**若错的影响**：`PAGE_PATHS` 需支持前缀匹配，GSWT-2 的漂移守卫要改口径。**验证方式**：`PAGE_PATHS` 现状为精确匹配 + `pageFor(pathname)` 精确查表；查询串不进 pathname，天然兼容。
- **A3**：**不更名既有路径**（即便与新分区命名不完全一致）——更名会让既有页面、用例与文档链接同批返工。**若错的影响**：`PAGE_PATHS` / `pages.js` / 用例 / 文档链接一批改写。**验证方式**：对位表以既有 13 条为既定事实；§2.2 逐条标注「既有」与「待登记」两态。
- **A4**：新增的漂移守卫用**解析 Markdown 表格**取声明路径（同 [`.1`](T-UI-010.1-组件型补齐屏形态对位与四型落地.md) 与既有 `pages.js` 的静态解析取向，无 JS 运行时）。**若错的影响**：守卫脆弱、易误报，需改为在 Python 侧维护一份声明集副本（那会引入第二真相源）。**验证方式**：声明集用**反引号包裹的路径字面量**书写、正则只取 `` `/…` `` 形态，与既有 `_frontend_page_paths()` 同法。
