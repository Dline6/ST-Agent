## 验收标准（Given-When-Then）
取自 [story-09](../../docs/PRD-v2-Agent/story-09-reflection-loop.md) 与本任务范围内的架构段（[08 §1–§2](../../docs/技术架构-v2/08-L6-反思演进.md)），逐条落到三叶（父级只汇总，不重复）：

- Given 用户对某条推送 / 结论 / 建议给出反馈（采纳 / 忽略 / 否定 / 追问 / 点赞），When 采集，Then 该反馈**落进本地反思数据池**（`reflection` 分区）、可读回、**不外发**；否定类必携 `reason` → [`.1`](T-L6-001.1-反思数据池.md) GWT-1 / GWT-2
- Given 每周用户配置时刻（如周日晚 8 点），When 到点，Then 本地生成四段式「本周反思报告」（① 本周为你做了什么 ② 偏好漂移 ③ 错误与理解 ④ 建议调整），**生成走完整 Trace** → [`.2`](T-L6-001.2-每周反思报告本体.md) GWT-1 / GWT-4
- Given 一份反思报告，When 分发，Then 经 [07-L5](../../docs/技术架构-v2/07-L5-主动触达.md) 的**既有渠道面**投出、可订阅到任一渠道；渠道全不可用 ⇒ **不假装送达** → [`.3`](T-L6-001.3-L6装配缝与报告投出.md) GWT-1
- Given 反馈数据不足（新用户），When 生成报告，Then 明确写「数据还不够，下周见」，**不硬凑** → [`.2`](T-L6-001.2-每周反思报告本体.md) GWT-3
- Given 某周无任何推送，When 生成报告，Then 只写「本周无触达，无反馈可分析」 → [`.2`](T-L6-001.2-每周反思报告本体.md) GWT-3
- Given 同一 `(周, 留痕状态)`，When 重复生成，Then 结论恒同、写同一路径、**不产生重复报告** → [`.2`](T-L6-001.2-每周反思报告本体.md) GWT-5 / [`.3`](T-L6-001.3-L6装配缝与报告投出.md) GWT-2

> 端到端装配（跨层组合根 `build_m4_runtime`）与「反馈 → 报告 → 建议 → 变更流」全链路复核归关卡 [T-INT-005](T-INT-005-M4集成关卡反思演进与生态闭环.md)。

- **A6 · 「本周」窗口 = ISO 周**（2026-10-06 ④ 对齐拍定）——前提：报告以「周」为粒度，需一个确定性的窗口定义才能幂等落盘（[`date.isocalendar()`](https://docs.python.org/3/library/datetime.html#datetime.date.isocalendar)）。取 ISO 周（周一 00:00 → 生成时刻，落盘键 `<ISO 年>-W<ISO 周>`）。若错（要求滚动 7 日窗 / 自然周从周日起）：返工面＝[`.2`](T-L6-001.2-每周反思报告本体.md) 的窗口与落盘键。验证方式：跨月 / 跨年边界的窗口用例。
- **A7 · 数据不足阈值默认 3、走可配条目**（2026-10-06 ④ 对齐拍定）——前提：story-09 边缘情况要求「反馈数据不足 → 写『数据还不够，下周见』」，但「不足」的判据未定（触达数为 0 与有触达无反馈是两种情形，后者见 GWT-3 后半）。“有触达但本周反馈事件 < N”判为不足，N 缺省 3、登记为 01 §7 条目（`weekly-report.min-feedback`）。若错（要求固定值 / 另一判据）：返工面＝[`.2`](T-L6-001.2-每周反思报告本体.md) 的不足判定与条目表。验证方式：N=3 阈值两侧的成对用例。
