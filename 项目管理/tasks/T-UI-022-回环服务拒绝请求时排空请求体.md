# T-UI-022 · 回环服务拒绝请求时排空请求体

## 目标

让 [`UiRequestHandler`](../../src/st_agent/ui/server.py) 在**未读请求体**即回拒绝（401 / 403 / 404）时先把体读掉（有界），使客户端拿到的是那支 `ResultEnvelope` 错误 JSON，而不是一个**网络层异常**。

## 背景（本项由 T-UI-021 的 ⑥ 验证期发现）

[`do_POST`](../../src/st_agent/ui/server.py) 的拒绝分支一律**在 `_read_json_body()` 之前** return：令牌无效 / `Host` 不符 / 路径不在 `_POST_ROUTES` 时，请求体**从未被读走**。响应写完后 `daemon_threads` 的 handler 线程结束、连接关闭，而 socket 里躺着未读数据——**Windows 在此时发 RST**，客户端读到的是 `ConnectionAbortedError: [WinError 10053]`。

**实测复现**（2026-10-11，本机 Windows，脚本见「复现」节）：4 MiB 体打 401 路径 3/3 中招、打 404 路径 2/3 中招；小体（`{}`）不中招——故它表现为**负载 / 体量相关**的间歇失败。这正是 `T-UI-021` 范围套件里 `tests/ui/test_ui_face_ports.py::test_new_paths_are_get_only[/api/graph/status]` 偶发 FAILED（`ConnectionAbortedError`，单跑 5/5 全绿）的成因；未读体这一行为**与 T-UI-021 的守卫改动无关**（守卫判定对该请求前后一致）。

**为什么要修**：拒绝路径的语义是「**显式告知失败**」（[00 §6 失败显式化](../../docs/技术架构-v2/00-架构总览.md)）。连接被复位时前端拿到的是 `fetch` 层的网络错误，六态信封**根本没机会显示**——本该 point at「令牌失效」的 401 退化成一句无信息量的「Failed to fetch」。

## 复现

最小脚本（`PYTHONPATH=src` 后运行）——起真服务，向 401 路径 POST 一个大于套接字缓冲的体：

```python
import http.client
from st_agent.ui.server import serve

with serve(dev=False) as running:
    body = b"x" * (4 * 1024 * 1024)
    conn = http.client.HTTPConnection("127.0.0.1", running.port, timeout=5)
    conn.request(
        "POST", "/api/health", body=body,
        headers={"Host": f"127.0.0.1:{running.port}", "Content-Length": str(len(body))},
    )
    print(conn.getresponse().status)  # 多数轮次在此抛 ConnectionAbortedError
```

症状对照：体小（`b"{}"`）时稳定拿到 `401`。

## 备注

**未在本批修**——`T-UI-021` 的对齐范围只含守卫的允许集口径；混入一处 socket 语义改动会把两条口径揉进同一条决策。本条独立立项、待其自身 ④ 对齐。候选取向（留待 ④ 判）：拒绝前**有界排空**请求体 vs. 回拒绝后置 `close_connection` 并排空 vs. 交由 `Connection: close` + 读空的组合。
