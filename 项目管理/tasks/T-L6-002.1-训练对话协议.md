# T-L6-002.1 · 训练对话协议

## 目标
交付 [08 §3](../../docs/技术架构-v2/08-L6-反思演进.md) 的**训练对话协议**：用户明确修正（「这条不对，因为…」）或发起「我想训练你」时，经**注入的理解端口**做**概念性理解**（结构化复述用户的修正逻辑、请用户确认）→ **确认后**才落三件：① 经记忆写入面**新增** `pattern` 节点（`source: user_stated`）② 产出**一条 Skill 参数调整的提案候选** ③ 落**回访留痕**（供「下次对话主动提及」取材）。同批把 [05 §4](../../docs/技术架构-v2/05-L3-对话主入口.md) 的 `train` 去向接上（该去向的 `owner` 早已点名本任务）。

**与上游的边界**（2026-10-06 读码核实）：

- **理解不在本层硬做**：全仓无「概念性理解」实现；[05 §3.2](../../docs/技术架构-v2/05-L3-对话主入口.md) 已立下「理解经注入端口、缺省 fail-closed」的口径（L3 的 [`LlmIntentUnderstander`](../../src/st_agent/l3/intent/protocol.py) 是意图理解的同型先例）。本叶**只交端口与协议**，真实 LLM 适配器与组合根注入归关卡 [T-INT-005](T-INT-005-M4集成关卡反思演进与生态闭环.md)。
- **记忆写入只增不改**：[04 §3.2](../../docs/技术架构-v2/04-L2-记忆图谱.md) 红线（副驾不得自主修改既有节点内容）+ [`MemoryWriter`](../../src/st_agent/l2/memory/writer.py) 的 API 形状（`edit_node` 只接受 `confirmed_by="user"`，本叶**不用**它）。`pattern` 节点的 `triggered_by` 各项须为 `mn_*` 形态 ⇒ 用户自陈类可留空。
- **提案候选不生效**：载体复用 [`ProposalCandidate`](../../src/st_agent/l6/weekly.py)（[T-L6-001.2](T-L6-001.2-每周反思报告本体.md) 交付，**无 `change_id`**）；生效 / 回滚属 [08 §5](../../docs/技术架构-v2/08-L6-反思演进.md)，归 [T-L6-003](T-L6-003-演进授权与变更流回滚与出厂重置.md)。
- **「下次对话提及」的渲染不在此处**：L6 只交留痕 + 读面，跨层装配归 [T-INT-005](T-INT-005-M4集成关卡反思演进与生态闭环.md)（[工作流](../工作流.md)「跨层装配与端到端验证不按此拆分」）。

## 验收标准（Given-When-Then）
- **GWT-1**：Given 一条带 `reason` 的否定反馈（或用户直接发起「我想训练你」），When 派发 `train` 去向，Then 经**注入的理解端口**产出**结构化复述**（复述文案是生成性文案、过 [01 §6](../../docs/技术架构-v2/01-平台共享契约.md)）+ 待确认标记；Given **未注入理解端口**，Then 该次派发**fail-closed**（`unavailable` + 点名），**不硬猜、不伪造复述**
- **GWT-2**：Given 一份**未经用户确认**的理解草案，When 尝试落账，Then **拒**（`validation_failed` + 说明）——未经确认**不写记忆、不产提案、不留回访**
- **GWT-3**：Given 一份**已确认**的理解，When 落账，Then ① 经注入的记忆写入面**新增**一个 `pattern` 节点（`source=user_stated`、不带 `provenance`、`triggered_by` 允许为空）② 产出**一条** `ProposalCandidate`（`config_id` + 现值 + 建议值 + 理由 + `trace_ref`）③ 两者可分别缺席但**必须显式说明**——**不产 `change_id`**、不落变更历史
- **GWT-4**：Given 未注入记忆写入面 / 理解草案未给出建议值，When 落账，Then 各面**显式降级**（「未写入记忆」/「本次无建议」逐条写明 + 点名归属），**没有一处静默降级**
- **GWT-5**：Given 一次已确认的训练，When 落账，Then 落 `reflection/training/<training_id>.json`，且**读面**可取回**待回访项**（含中性回访文案与来源锚点）；**换一个构造器续读仍在**（重启安全，同 [D-060](../决策日志.md) ② 的常驻 / 可分离口径）；Given 从未训练过，Then 读面给**空集**而非报错
- **GWT-6**：Given `train` 去向的接线，When 派发，Then `DispatchOutcome.wired` 为真、载荷含训练会话（沿用 `analyze` 去向的鸭子面口径：本层只认 `envelope`，**L3 不 import L6**）；Given 注入的端口返回非法结构，Then `dependency_failed` 并写明类型，**不静默吞**

## 可关闭的遗留
- [L6 册](../遗留问题/L6-遗留问题.md) **`A2`**「周报第三段的『理解』与『下次对话主动提及』未落地」——**本批关闭**（归属按[册规](../遗留问题/README.md) 2 细化为本叶）：概念性理解与其回访留痕在本叶落地；**「让周报第 3 段也承载『理解』」这一支未取**——[08 §2](../../docs/技术架构-v2/08-L6-反思演进.md) 第 3 段的语义是「哪些推送被否定 + 用户给出的 reason 原文」（中性呈现用户数据），概念性理解是**对话产物**、其回访在**对话**里发生；把它塞进周报会（a）把「用户原话」与「系统复述」混成一段，违 [D-053](../决策日志.md) 的生成性 / 数据分栏，（b）逼周报在生成时刻做一次 LLM 复述（[08 §2](../../docs/技术架构-v2/08-L6-反思演进.md) 的报告生成面**不依赖理解端口**）。故**不改** [08 §2](../../docs/技术架构-v2/08-L6-反思演进.md) 与 [T-L6-001.2](T-L6-001.2-每周反思报告本体.md)；周报第 3 段的「理解」由**回访**在对话侧兑现。

## 假设与前提
- **A1 · 概念性理解经注入端口、真实适配器归关卡**（2026-10-06 ④ 对齐拍定）——前提：[05 §3.2](../../docs/技术架构-v2/05-L3-对话主入口.md) 的「理解经注入、缺省 fail-closed」口径 + 本批不产生新 LLM 出网面。若错（要求本层自带真实理解）：返工面＝本叶范围与范围套件（须加跑 `pytest -m live tests/live/test_llm_live.py`）。验证方式：`grep` 断言 `src/st_agent/l6/**` 不 import `l0.llm` / `l0.net`。
- **A2 · 记忆写入只增不改、`user_stated` 直写**（2026-10-06 ④ 对齐拍定）——前提：[04 §3.2](../../docs/技术架构-v2/04-L2-记忆图谱.md) 红线 + [04 §4](../../docs/技术架构-v2/04-L2-记忆图谱.md)「白名单只约束 `inferred` 写入，`user_stated` 直接写入」；用户**确认过**的复述即用户自陈。若错（要求改既有节点）：返工面＝本叶写入面（须改走 [`ConflictQueue`](../../src/st_agent/l2/memory/conflict.py) 的新增 + `evolves_from` 裁决路径），并触 [04 §4](../../docs/技术架构-v2/04-L2-记忆图谱.md)。验证方式：断言写入恒为 `add_node`（`grep` 不出现 `edit_node`）；节点校验用例（`user_stated` 带 provenance 即拒）。
- **A3 · 训练对话的提案出自「用户明说的修正」而非规则表**（2026-10-06 ④ 对齐拍定）——前提：[08 §3](../../docs/技术架构-v2/08-L6-反思演进.md) 第 2 步的提案是「**对应** Skill 参数调整」（由这次修正直接推出），而 [08 §4](../../docs/技术架构-v2/08-L6-反思演进.md) 的规则表是**从观察推断**（周报第四段 / 模式识别）——两者来源不同，故候选的生成规则归 [`.2`](T-L6-002.2-主动提案与周报候选生成.md)，本叶只承载「理解草案给出的建议 → 提案候选」这一跳。若错（要求本叶也套规则表）：返工面＝本叶提案面（改为消费 `.2` 的规则引擎）。验证方式：本叶提案用例直接由理解草案驱动、不注入规则表即可跑绿。
- **A4 · `training_id` 走确定性摘要**（2026-10-06 ④ 对齐拍定）——前提：[01 §1](../../docs/技术架构-v2/01-平台共享契约.md) 的 15 类 ID 无「训练会话」一类，新增一类要改契约；[`weekly.py`](../../src/st_agent/l6/weekly.py) 已有「本层内部锚点走 `digest_id` 本地前缀」的先例（`wk`）。**同一反馈的重复训练 = 同一次会话**（幂等覆盖），与池子的 `feedback_id` 幂等口径同构。若错（要求登记为本层 ID 类）：返工面＝[01 §1](../../docs/技术架构-v2/01-平台共享契约.md) + [`identifiers.py`](../../src/st_agent/contracts/identifiers.py)（**须走 [铁律 8](../工程宪法.md) 契约先行**）。验证方式：同一输入两次得同一 `training_id` 的用例。
- **A5 · `train` 去向本批接线、端口注入归关卡**（2026-10-06 ④ 对齐拍定）——前提：`wired` 的语义是「**总线实现了该去向的分派**」（先例＝`analyze`：`wired=True` 而端口缺省仍 fail-closed），而端口的组合根注入归里程碑关卡（`analyze` 于 [T-INT-003](done/M2/T-INT-003-M2集成关卡多视角决策闭环.md) 注入）。若错（要求连注入一起做）：返工面＝本叶范围（须动 `build_m3_runtime` / 造 M4 组合根——后者是 [T-INT-005](T-INT-005-M4集成关卡反思演进与生态闭环.md) 的交付，会与其范围重叠）。验证方式：未注入端口时 `_dispatch_train` 走 `unavailable` + 点名（`requested` 不伪造）的用例。
