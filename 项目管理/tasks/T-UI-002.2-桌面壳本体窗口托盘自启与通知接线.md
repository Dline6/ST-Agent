# T-UI-002.2 · 桌面壳本体（窗口 / 托盘 / 自启 / 通知接线）

## 目标
交付桌面壳 `src/st_agent/ui/shell/**`：拉起后端二进制 → 读[握手](T-UI-002.1-生产运行入口与壳后端握手协议.md) → 用**系统 WebView**（pywebview，三引擎：WebView2 / WKWebView / WebKitGTK）打开 `http://127.0.0.1:<port>/#t=<token>` → 托盘（显示 / 隐藏 / 自启开关 / 测试通知 / 退出）。**壳不含任何业务逻辑、不提供壳专有通道**——它只做原生能力接线（[D-060](../决策日志.md) ①）。

## 验收标准（Given-When-Then）
- Given 后端握手就绪，When 壳启动，Then 原生窗口加载握手给出的回环地址（令牌经 URL fragment 传入），**壳内渲染与浏览器直开一致**（Windows 实测）
- Given 窗口已打开，When 关闭窗口，Then 窗口**隐藏到托盘**、后端进程**仍在运行**，托盘可再次唤起
- Given 托盘「退出」，When 选择，Then 后端被**优雅回收**（收工留痕可见、无孤儿进程）
- Given 自启开关，When 打开 / 关闭，Then 平台的登录项注册写入 / 移除并能读回（Windows 实测注册表项出现 / 消失）
- Given 托盘「发送测试通知」，When 触发，Then 系统通知在桌面可达且**不发任何出网请求**（本地子进程，非网络）

## 接口面
- **输入**：
  - [`T-UI-002.1`](T-UI-002.1-生产运行入口与壳后端握手协议.md) 的握手 JSON（`event=ready` / `host` / `port` / `token` / `pid`）与 `event=error` 失败行
  - [`T-UI-001.2`](done/M1/T-UI-001.2-骨架通信面与组件注册表宿主.md) 的令牌经 URL fragment `#t=` 约定（[`api.js`](../../src/st_agent/ui/web/js/api.js) 只从 fragment 读、不落浏览器存储）
  - [00 §1.1](../../docs/技术架构-v2/00-架构总览.md)（壳只承载原生窗口 / 托盘 / 自启 / 原生通知接线）· [11-sitemap §1/§5](../../docs/PRD-v2-Agent/11-sitemap.md)（原生呈现面划出页面集）
- **输出**：
  - `src/st_agent/ui/shell/__init__.py` / `errors.py`（`ShellSurfaceUnavailable` 显式失败）· `backend.py`（拉起 + 握手 + 回收，鸭子端口注入）· `autostart.py`（三平台登录项读写）· `notify.py`（三平台通知 argv 构造 + 执行）· `window.py` / `tray.py`（pywebview / pystray 薄边，**惰性导入**）· `app.py`（壳装配）· `__main__.py`（壳入口）
  - `pyproject.toml` 新增可选 extra `shell = ["pywebview", "pystray"]`——CI 不装，故壳边模块**惰性导入 + 显式失败**
  - 自启注册口径：Windows `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` · macOS `~/Library/LaunchAgents/com.stagent.shell.plist` · Linux `~/.config/autostart/st-agent.desktop`
  - `tests/ui/test_shell_*.py`（纯逻辑：URL 构造 / 握手解析 / 回收序列 / 自启内容与读回 / 通知 argv 逐平台；GUI 边不测、靠 Windows 走查）

## 假设与前提
- **A1 · pywebview 的窗口必须在主线程、后端是独立进程**——前提：macOS 的 WKWebView 要求主线程；后端既有独立进程（[`T-UI-002.1`](T-UI-002.1-生产运行入口与壳后端握手协议.md) 起子进程），故不受影响，壳进程可全身心跑窗口与托盘循环。若错（须在同进程起服务）：返工面＝进程边界，与 [D-060](../决策日志.md) ② 冲突。验证方式：Windows 走查中窗口与后端 pid 不同；壳代码不 import 任何 `st_agent.l*` 业务模块（`test_shell_is_native_only`）。
- **A2 · 托盘用 pystray、通知用本地子进程**——前提：需求只要「接线」，系统级通知在 D-060 ① 已列为可用手段（macOS `osascript` / Linux `notify-send` / Windows PowerShell WinRT toast）。若错（须引 WebView JS 桥或服务端通道）：破坏「无壳专有通道」。验证方式：`notify.py` 的 argv 逐平台用例；不出现向 WebView 注册 JS 桥的调用。
- **A3 · 关窗＝隐藏、退出＝回收，是「常驻」的正确读法**——前提：[00 §1.1](../../docs/技术架构-v2/00-架构总览.md) 要求「后端比任何窗口活得久」，而桌面应用语义下「退出应用」应当真的结束。若错（须「退出后后端仍在跑」）：需补发现机制（端口 / 令牌文件复用），返工面＝生命周期面。验证方式：关窗用例断言后端存活、退出用例断言后端回收。
- **A4 · 自启不注册为 [01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 条目**——同父任务 `A5`（真相源＝OS 登录项本身）。验证方式：自启开关对读 OS 注册项；注册表条目集合不因本叶新增。
- **A5 · 三平台中本机只实测 Windows**——同父任务 `A4`；macOS / Linux 的窗口、托盘、自启、通知均**未经实测**（在遗留里显式登记，不写成「已支持」）。
