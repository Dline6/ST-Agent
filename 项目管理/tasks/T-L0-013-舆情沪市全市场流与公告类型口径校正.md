# T-L0-013 · 舆情沪市全市场流与公告类型口径校正

## 目标

闭掉 [L0 遗留册 `F1` 的**沪市部分**](../遗留问题/L0-遗留问题.md) 与 `F4`（连带新登记的 `F5`）：① 沪市舆情当前被登记为「**按公司**接口、须先在分页公司列表里二分定位 `uid`」（[`_fetch_info_sentiment_qa_sse`](../../src/st_agent/l0/info/fetch.py) 直接抛能力缺口），实测上证e互动**有全市场流**，该前提对沪市**不成立**；② 公告域 `ann_type` 列在巨潮源恒为 `NULL`，而深挖发现**三源语义根本不统一**——不是「一个源缺列」，是**这个列本身没有统一语义**（见 `F5`）。

**已实测的关键事实（2026-09-27 真实请求与源码核对）**：

- **上证e互动全市场流**：`https://sns.sseinfo.com/ajax/feeds.do?type=11|10&pageSize=<n>&lastid=-1&show=1&page=<p>`（Referer `https://sns.sseinfo.com/`）；`type=11` 最新已回复、`type=10` 最新提问。实测各返回 10 条**沪市代码**（如 `600585` / `601238` / `601800` / `603392`）→ **无需逐公司定位 uid**。（对照：[`akshare` `stock_sns_sseinfo.py`](https://github.com/akfamily/akshare/blob/main/akshare/stock_feature/stock_sns_sseinfo.py) 与 `a-stock-data` skill **都只做按公司**——「有全市场流」超出两者。）
- **`ann_type` 三源语义（实测）**：
  - **巨潮** `hisAnnouncement/query`：`announcementTypeName` **恒为 `None`**（两组参数各 30 行 + 4 个类目各 30 行，共 180 行**非空 0**）。响应另有 `announcementType`＝**数字码串**（如 `'01010503||010113||011705||012317||012399'`）。
  - **东财** `security/ann`：`codes[].ann_type` 实测为 `'A,BJA'` / `'A,CYB'`——是**证券类别/板块码**（沪深A股 / 北交所A / 创业板），**不是公告内容类型**。当前 [`parse_announcement_em`](../../src/st_agent/l0/info/fetch.py) 把它填进 `ann_type`，属**语义错位**（`F5` 的本体）。
  - **深交所** `annList`：有 `bigCategoryId` / `smallCategoryId` 字段，但实测该窗口 20 行**全为 null**。
- **内容类型若需要则有确定路径**：巨潮的 **`category` 请求参数**实测有效（[`akshare` `stock_disclosure_cninfo.py`](https://github.com/akfamily/akshare/blob/main/akshare/stock_feature/stock_disclosure_cninfo.py) 载有完整 26 类字典，`category_ndbg_szsh` 等）；实测按类目拉取总量显著收敛（年报 4316 / 业绩预告 47 / 股东大会 3373 / 风险提示 300，全量 82248）。**反查路线已实测排除**——响应数字码是**重叠多标签**（`01010503` 出现在全部 4 个类目），无法由响应反推类目。

## 验收标准（Given-When-Then）

- **GWT-1 沪市有全市场流**：Given 上证e互动，When 跑 `info_sentiment_qa_sse`，Then 走 `feeds.do` 的 `type=11|10` 分页、`sentiment_qa.market='sh'`，**不再抛「按公司 / 须先定位 uid」的能力缺口**。
- **GWT-2 登记校正**：When 收工，Then [05 登记表](../../docs/数据库设计-BaoStock数据层/05-同步策略与新鲜度契约.md) 中 `info_sentiment_qa_sse` 的「**待定**——须先定位公司 `uid`」改为**窗口式节奏**；并据 2026-09-27 实测显式标注该平台**可见窗口的性质**——**是「条数上限」而非日期下界**：`type=11`（已回复）约 **5675 条**、按**回复时间**倒序覆盖近约 1 个月；`type=10`（提问）约 **4381 条**、按**提问时间**倒序覆盖约 3 周。更早条目不可回溯；且 `type=11` 内**提问时间**可远早于该下界（实测回溯至 2025-07）——故**不得**由日期下界反推「某天无舆情」。
- **GWT-3 `ann_type` 语义显式**：Given 三源公告，When 落库，Then `ann_type` 的**逐源语义被显式声明**（东财＝证券类别码 / 巨潮＝`NULL` / 深交所＝大类字段可空），**且不得再被当作「公告内容类型」消费**——代码注释与文档两处同步。
- **GWT-4 内容类型有确定路径**：Given 消费方需要公告**内容类型**，When 走巨潮，Then 用**请求侧 `category` 参数**（26 类字典），**不**依赖响应侧字段；这条路径在文档中写明（含 26× 请求与跨类去重的代价）。

## 假设与前提

- **A1** `feeds.do` 的 `page` / `pageSize` 分页可达平台开放窗口，且「按时间序翻页至窗口起点即停」**不会漏拉** / 若错（静默截断）：窗口内会丢数据 / 验证：2026-09-27 实测已证分页有效（`pageSize` 被尊重；`type=11` 末页 189、`type=10` 末页 146，均按每页 30 计）且两流的排序键**单调**（`type=11` 按回复时间、`type=10` 按提问时间）——故实现取「翻页至本页最早时间 < 窗口起点」为停止判据，另设**页数上限**兜底（两重保险）。
- **A2** `ann_type` 取「**按源可空 + 显式声明语义**」，而非「按 26 类逐类拉」 / 若错（消费方确需内容类型）：须改走 GWT-4 的 `category` 路径——代价是 26× 请求 + 跨类去重 / 验证：本轮实测（逐类拉总量收敛、响应码重叠不可反查）已排除反查路线；采用与否由消费方需求决定。
- **A3** 沪市全市场流与既有 `parse`／落盘链路（`market` 分片、`qa_id` 确定性摘要）兼容，无需改表 / 若错（须加列或改分片键）：`sentiment_qa` 的 DDL 与 `T-L0-010.5` 的交付面须返工 / 验证：GWT-1 用例 + `T-L0-010.5` 既有离线用例全绿。
