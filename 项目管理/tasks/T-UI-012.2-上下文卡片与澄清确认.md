# T-UI-012.2 · 上下文卡片与澄清确认

> [T-UI-012](T-UI-012-Chat主界面对话流与生成式UI宿主.md) 的**上下文卡片与澄清确认叶**（[D-110](../决策日志.md) ①）。把 [05 §2](../../docs/技术架构-v2/05-L3-对话主入口.md) 的**六段上下文卡片**做成首页常驻面，并把 [§3.2](../../docs/技术架构-v2/05-L3-对话主入口.md) 的**澄清追问**与**意图确认卡**接进对话流——三者都是「对话流内面」，**不落组件注册表**，由页面按信封内含的契约对象内联呈现。

## 目标

三件交付，都挂在 [`.1`](T-UI-012.1-对话骨架与快捷指令.md) 立起的页面宿主上：

1. **六段上下文卡片（常驻首页）**——经 `.1` 交付的 `GET /api/chat/context` 取 `context_card` 描述，交**既有** [`context_card` 渲染件](../../src/st_agent/ui/web/js/plugins/l3/context_card.js) 渲染。六段段序 / 段名固定（偏好画像 / 持仓摘要 / 关注池 / 当前观点 / 未读告警 / 近期热点）；**非 `ok` 段必带原因 + 生产方**（`--delayed` 呈现，**不静默留空、不用其他数据顶替**）；无记忆（`is_empty`）时出 Onboarding 空态引导（`empty_hint` + onboarding 目标）。
2. **澄清追问对话框**——[05 §3.2](../../docs/技术架构-v2/05-L3-对话主入口.md)：澄清预算 **≤ 3 问**，每问**可跳过**（跳过即取该参数 `default`）。问句文本来自后端 `ClarificationQuestion.prompt`（已过中性门），前端**不杜撰**；超过预算的未澄清项以默认值填充（后端已在确认卡标注来源）。
3. **意图确认卡**——收敛后（`needs_confirmation`）列 `IntentConfirmation.items` 理解条目（同 [§5](../../docs/技术架构-v2/05-L3-对话主入口.md) `ConfigDraft.understanding_summary` 的**同一内容源**，前端不另造摘要）+ 确认入口；确认即 `POST /api/chat {action:"dispatch", session_id, answers}` 派发。

**本批的边界**（不越界）：

- **不新建渲染路径**——卡片走既有 `context_card` 渲染件；本叶只做取数与装配（同 [`memory.js`](../../src/st_agent/ui/web/js/pages/memory.js) 的取向）。
- **不触生成式 UI**——`dispatch` 返程的 `description` 渲染归 [`.3`](T-UI-012.3-生成式UI宿主.md)；本叶只负责把确认卡与澄清面呈现、把确认动作发出去。
- **不动后端对话语义**——澄清问项与确认条目**由后端产出**（[`IntentProtocol`](../../src/st_agent/l3/intent/protocol.py)，`done`）；本叶不加后端业务逻辑，`/api/chat/context`（`.1` 交付）照旧消费。
- **不引构建链**（[D-063](../决策日志.md)）；**不越层取数**（[铁律 7](../工程宪法.md)）。

## 验收标准（Given-When-Then）

- **GWT-1** Given 首页 `/`，When 打开，Then 常驻一张六段上下文卡片（段序段名固定、六段齐），经 `GET /api/chat/context` 取描述交既有 `context_card` 渲染件；**未注入 `chat` 门面**时该面 `unavailable` + 点名、以非 `ok` 态如实呈现。
- **GWT-2** Given 卡片任一段非 `ok`，When 渲染，Then 该段以 `--delayed`（`unavailable`）/ 空态样式呈现 + **中性原因** + 生产方（[05 §2](../../docs/技术架构-v2/05-L3-对话主入口.md)：不静默留空）；`ok` 段**不得**带原因。
- **GWT-3** Given 记忆为空（`is_empty`），When 渲染卡片，Then 出 Onboarding 空态引导（`empty_hint`）与 onboarding 目标入口，**不**摆假数据、**不**用其他数据顶替（`ok` 段与空态互斥，由卡片契约保证）。
- **GWT-4** Given 一句含糊意图（关键参数缺失），When 提交，Then 出澄清追问**不超过 3 问**、每问可跳过（跳过取默认值）；收敛后出意图确认卡列出理解条目，确认即 `POST /api/chat {action:"dispatch"}` 派发；Given 意图仍无法收敛，Then 呈现方向候选（≤3）或 `unavailable` + 原因，**不**强行猜测。
- **GWT-5** Given 本叶界面文案（澄清面标题 / 跳过按钮 / 确认卡标题与按钮 / 空状态引导），When 逐条核对，Then 按[契约 9 中性表达](../../docs/PRD-v2-Agent/10-platform-capabilities.md)撰写、**无拟人化**；问句与理解条目**取自后端**、前端不杜撰；Given 本叶改动，When 跑范围套件 + `verify_docs.py --strict`，Then 全绿、检查 1–9 全过 0 断链。

## 接口面

- **输入**（消费的前置接口）：
  - `GET /api/chat/context`（**本批**，由 [`.1`](T-UI-012.1-对话骨架与快捷指令.md) 交付）——回 `context_card` 描述信封（`slots.sections` / `labels` / `greeting` / `empty_hint` / `is_empty` / `targets`）。
  - `POST /api/chat` 的返回键 `needs_confirmation` / `session_id`（`done`，`DialogFacade.turn`）——驱动澄清面与确认卡的出现与派发。
  - 澄清 / 确认契约对象（`done`）：[`ClarificationRound`](../../src/st_agent/l3/intent/protocol.py)（`questions[].{name,prompt,default}`，≤ `CLARIFICATION_BUDGET`）· [`IntentConfirmation`](../../src/st_agent/l3/intent/protocol.py)（`items[].line`）——随 `reply` 信封的 `data` 下发，**无 `component_type`**（[11-sitemap §2.1](../../docs/PRD-v2-Agent/11-sitemap.md) 判为「对话流内面」）。
  - 卡片渲染件：[`context_card.js`](../../src/st_agent/ui/web/js/plugins/l3/context_card.js)（`done`，[`T-L3-001.2`](done/M1/T-L3-001.2-上下文卡片与空状态.md) 交付）——本叶**复用**，不另造段渲染。
  - 页面宿主与挂载点：[`pages/chat.js`](../../src/st_agent/ui/web/js/pages/chat.js)（`.1` 交付）。
- **输出**（本任务交付的公共 API / 落盘位置）：
  - `src/st_agent/ui/web/js/pages/chat.js`——填上卡片挂载点（取 `/api/chat/context` 交 `renderEnvelope`）、澄清面与确认卡的内联呈现、确认派发动作。
  - `src/st_agent/ui/web/css/app.css`——卡片容器 / 澄清面 / 确认卡的中性样式。
  - 前端守卫（`tests/ui/**`）——卡片六段呈现、非 `ok` 必带原因、澄清 ≤3 / 可跳过、确认卡列条目、文案中性。
  - **不交付**：生成式 UI 宿主（[`.3`](T-UI-012.3-生成式UI宿主.md)）· 新后端端点（`.1` 交付）· 契约文档变更。

## 假设与前提

- **A1**：澄清追问对话框与意图确认卡是「**对话流内面**」（[11-sitemap §2.1](../../docs/PRD-v2-Agent/11-sitemap.md)：持 `ResultEnvelope` 而无 `component_type`）——故前端按 `reply.data` 内含的 `ClarificationRound` / `IntentConfirmation` **内联**呈现，**不走**组件注册表。**若错的影响**：若它们应有 `component_type`，则本叶实现方式与 [01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 登记面冲突，需补登记 + 渲染件。**验证方式**：GWT-4 走查确认卡 / 澄清面由 `reply.data` 驱动；`tests/ui/test_ui_registry.py` 的登记集**不改即绿**。
- **A2**：澄清问句文本由后端 `ClarificationQuestion.prompt` 提供（已过中性门），前端**不杜撰**问句；「跳过」＝前端把该问项以 `default` 填入 `answers` 后随确认派发。**若错的影响**：若前端需自行取 `ParameterSpec`，会把后端已有的问项来源（[05 §3.2](../../docs/技术架构-v2/05-L3-对话主入口.md)）在两端各造一份。**验证方式**：GWT-4 断言问句文本来自 `reply.data.questions[].prompt`；GWT-5 文案核对。
- **A3**：确认卡条目＝`IntentConfirmation.items`（同 [05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) `ConfigDraft.understanding_summary` 的**同一内容源**），前端**不**另造理解摘要。**若错的影响**：双份摘要会分叉（[05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 明禁）。**验证方式**：GWT-4 断言条目来自 `reply.data.items`。
- **A4**：上下文卡片经 `GET /api/chat/context`（由 `.1` 交付）取，**六段渲染全交既有 `context_card` 渲染件**，页面**不**自己拼段（否则与渲染件分叉、且绕过中性门）。**若错的影响**：页面自拼段会复制段渲染逻辑，`state` / `reason` 规则在两处各写一遍。**验证方式**：GWT-1 / GWT-2 走查渲染由渲染件产出；[`tests/ui/test_ui_memory.py`](../../tests/ui/test_ui_memory.py) 式取数装配守卫不改即绿。
