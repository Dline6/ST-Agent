# T-UI-016.3 · 推理区：推理链面板与决策记录

> [`T-UI-016`](T-UI-016-推理区触发进度分歧图与视角详情.md) 三叶之一（[D-112](../决策日志.md) ①）——把**推理链展开面板**做成[§3.3](../../docs/PRD-v2-Agent/11-sitemap.md) 声明的**跨页复用件**（本 Flow / 视角追问 / 反思报告三处同一渲染件），并接通 [Chat 结论卡](../../src/st_agent/ui/web/js/pages/chat.js) 的「推理链」入口；同时落地**决策记录页**（写 + 读）。

## 目标

- **推理链展开面板**（[11-sitemap §3.3](../../docs/PRD-v2-Agent/11-sitemap.md)：「结论卡 → 推理链入口 → 展开面板 → 调用序列 / 记忆片段 / 视角汇总 / 耗时 → 任一环点开细看」）——复用既有 [`trace_timeline`](../../src/st_agent/ui/web/js/plugins/l3/trace_timeline.js)，**不新建第二套**；跨页复用点是**同一渲染件 + 同一描述件**（`describe_trace`）。
- **Chat 结论卡的「推理链」入口接通**——[`chat.js`](../../src/st_agent/ui/web/js/pages/chat.js) 现只出按钮并报「尚未接入：该动作归 T-UI-016 落地」；本叶把 `analyze` 去向的**各视角链**随 [`POST /api/chat`](../../src/st_agent/app.py) 响应内联（增 `traces` 键，同 [D-110](../决策日志.md) ⑤ 往同一响应加 `clarification` 键的先例），点击即展开面板。
- **决策记录页**（`/deliberation?view=decisions`）——[11-sitemap §2.1](../../docs/PRD-v2-Agent/11-sitemap.md)：复用 `report_card`，呈现「决策 + 理由 + 采纳视角 + 忽略视角」，**并列不合并**；写入经 L4 `Deliberation.record_decision`（[06 §2.4](../../docs/技术架构-v2/06-L4-多视角推理.md) → L2 `history` 节点）。

**本批的边界**（不越界）：

- **不重造 `trace_timeline`**——`describe_trace` 与 `trace_timeline.js` 均已实现且已在反思报告等处复用，本叶只做**宿主与取数**。
- **决策的语义归 L2**——L4 `record_decision` 已声明「L4 不自校验决策内容」；本叶只转发与呈现，**不新增**决策语义。
- **不做「建议」字段**（[06 §6](../../docs/技术架构-v2/06-L4-多视角推理.md)）——决策记录页只列出用户自陈的决策与理由，**不产生任何系统建议**。
- **不引入会话态**——[D-112](../决策日志.md) ② 已定：链随响应内联，页面不存「最近一次分析」。

## 验收标准（Given-When-Then）

- GWT-1：Given Chat 里一次多视角结论卡，When 点「推理链」，Then 展开面板出**调用序列 / 记忆片段 / 视角汇总 / 耗时**（`trace_timeline` 的逐步 `steps`），**任一环可点开细看**（输入快照 / 输出 / 耗时 / 降级说明）；本次响应里没有链 ⇒ 显式告知 + 点名原因，**不伪造**一条链
- GWT-2：Given 同一个渲染件，When 从 `/deliberation` 的视角详情进入，Then 出**同一件**（跨页复用，不复制第二套词表 / 结构）
- GWT-3：Given 决策（决策文本 + 理由 + 采纳视角 + 忽略视角），When 提交，Then 经 `record_decision` 写 L2 `history` 节点并回 `ok {memory_node_id}`；**未采纳的参与视角默认计入「忽略」**（每条参与视角都在「采纳 / 忽略」之一，**不静默丢弃**）；缺决策文本 ⇒ `validation_failed`；未注入写入面 ⇒ `unavailable` + 点名归属
- GWT-4：Given 既有决策留痕，When 打开决策记录页，Then 逐条**并列**呈现（决策内容 / 时刻 / 来源 / 置信度），**不合并、不给统一建议**；无留痕 ⇒ `empty` + 原因，**不静默留空**
- GWT-5：Given 面板 / 记录的文案，When 核对，Then 按[契约 9](../../docs/PRD-v2-Agent/10-platform-capabilities.md) 中性撰写，**无拟人化**（视角无「性格」称谓、无第一人称）
- GWT-6：Given 真组合根 + 真回环服务，When 在 Edge 走查「结论卡 → 推理链」与「触发 → 决策记录」，Then 全程可用、控制台无新增报错

## 接口面

- 输入（消费的前置接口）：
  - [`.2`](T-UI-016.2-分歧图与视角详情.md) 交付的 `POST /api/deliberation/analyze` 响应 `lenses` 键（`[{lens_id, trace_id, opinion, trace}]`）与 `divergence` 键；[`.1`](T-UI-016.1-触发进度与视角阵容.md) 的页骨架与 `?view=` 分派
  - L3 描述件：`describe_trace(trace, *, now=...)` → `trace_timeline`（槽 `steps` / `conclusion_ref` / `closed`）；L4 层的既有翻译面 `DialogFacade.lens_trace_of(analysis, trace_id)`（[`app.py`](../../src/st_agent/app.py)，按锚点取链、取不到回 `empty`）
  - L4 写入面：`Deliberation.record_decision(*, decision, reasoning, adopted_lens_ids, ignored_lens_ids)` → `ResultEnvelope`（[`l4/deliberation.py`](../../src/st_agent/l4/deliberation.py)）
  - L2 读面：`MemoryReader.query(SliceQuery(task_type="decision"))`——`TASK_TYPE_AFFINITY["decision"]` 含 `history`（[`l2/memory/reader.py`](../../src/st_agent/l2/memory/reader.py)），故决策留痕可按该口径取回
  - UI 槽词汇（[`ui/registry.py`](../../src/st_agent/ui/registry.py)）：`trace_timeline`(`steps`) · `report_card`(`sections`)
- 输出（本任务交付的公共 API / 落盘位置）：
  - `POST /api/chat` 响应**增 `traces` 键**（仅 `analyze` 去向非空；其余去向为 `[]`）——纯增量，既有读取方按具名键取，不回归
  - `POST /api/deliberation/decision`（体 `{decision, reasoning, adopted_lens_ids, ignored_lens_ids}`）→ `ok {memory_node_id}` / `validation_failed` / `unavailable`
  - `GET /api/deliberation/decisions` → 决策留痕 `report_card`（逐条并列）；无留痕 ⇒ `empty` + 原因
  - [`chat.js`](../../src/st_agent/ui/web/js/pages/chat.js) 的推理链面板（「推理链」按钮由「尚未接入」改接真数据；`TRACE_OWNER` 常量随之下线）
  - [`web/js/pages/deliberation.js`](../../src/st_agent/ui/web/js/pages/deliberation.js) 增 `?view=decisions` 段（**留痕清单**）+ **触发与进度页底部的决策提交表单**（参与视角逐条「采纳 / 忽略」，默认未采纳者入「忽略」）——[D-112](../决策日志.md) ② 无会话态，故冷开 `?view=decisions` 不凭猜参与视角，只出留痕与一行指引
  - 测试：[`tests/ui/test_ui_deliberation.py`](../../tests/ui/test_ui_deliberation.py) 与 [`tests/integration/test_ui_deliberation_wiring.py`](../../tests/integration/test_ui_deliberation_wiring.py) 各补本叶用例（真组合根上：真 `record_decision` 落 `history` 节点、真 L2 读回、真链内联）；`tests/ui/test_ui_chat_page.py` 补 Chat 侧 `traces` 透传用例；写面白名单（[`tests/ui/test_ui_face_ports.py`](../../tests/ui/test_ui_face_ports.py)）+1

## 假设与前提

- **A1**：`Deliberation.record_decision` 写入的 `history` 节点（`event` ＝ `决策｜理由：…｜采纳视角：[…]｜忽略视角：[…]`，单字符串）不要求读面**再解析**回结构化字段——决策记录页按 `event` **原文如实并列**呈现，结构化四要素由**写入前的表单**承载。**若错的影响**：若产品要求读面逐字段拆开展示，则须改 `record_decision` 的载荷形态（属 L4 面变更，越出本任务），或在前端解析该分隔符（**猜格式**，[D-110](../决策日志.md) ⑤ 同类）。**验证方式**：Edge 走查断言读面把 `event` 原文逐条列出且不丢字；用例断言写入后 `event` 同时含决策 / 理由 / 采纳 / 忽略四段。
- **A2**：`TASK_TYPE_AFFINITY["decision"]` 含 `history`，故决策留痕**无需新增查询面**即可取回。**若错的影响**：该表自陈为「初版、§3.1 未定口径」，若日后改写剔除 `history`，决策记录页会退回 `empty`（显式、不静默），但 GWT-4 的「既有留痕可见」不成立——届时应改走 `task_type="chat"`（含全类型）或新立查询口径。**验证方式**：集成套件在**真组合根**上先 `record_decision` 再经 `GET /api/deliberation/decisions` 读回，断言该节点在返回集内。
- **A3**：GWT-3 的「未采纳的参与视角不静默丢弃」由**表单侧口径**兑现（参与视角逐条二选一，默认入「忽略」），而非 `record_decision` 的契约强制（它接受空的两个列表）。**若错的影响**：若只让用户标注「采纳」、其余不传，则未采纳视角**不在留痕里**——正是 GWT-3 要防的。**验证方式**：用例提交只标部分采纳的表单，断言请求体的 `ignored_lens_ids` 补齐了剩余参与视角；走查断言留痕的「忽略视角」列非空且覆盖未采纳者。
- **A4**：`POST /api/chat` 增 `traces` 键是**纯增量**——既有读取方（`test_m1_chat` / `test_ui_chat_boundary` 及 `chat.js` 的 `reply` / `description` / `clarification` 分支）按具名键取数，不受新键影响。**若错的影响**：若有读取方按「键集合相等」断言响应形状，会回归——须同批更新该断言（同 [D-110](../决策日志.md) ⑤ 的处置）。**验证方式**：跑 `tests/integration` ∪ `tests/ui` 的范围套件 + 全量；抽查响应键集合断言（若有）并同批更新。
