# T-SC-001 · 平台共享契约核心类型落地

## 目标
把 [01-平台共享契约](../../docs/技术架构-v2/01-平台共享契约.md) 定义的跨层复用类型实现为代码里的单一真相源（各层只能 import 它，不得各自另立），作为 L0–L6 一切实现的前置底座。队首任务，无前置依赖，就绪即可开工。

## 验收标准（Given-When-Then）
- GWT-1：Given 任一上层模块，When 引用 `stock_id`/`trace_id`/`skill_id` 等标识，Then 均来自本契约定义、全局唯一、生成后不可变（§1）。
- GWT-2：Given 一次 Skill 执行，When 产出结果，Then 必须包成 `ResultEnvelope` 且失败语义走 §5 分支，不得裸返回。
- GWT-3：Given 一条结论，When 需要溯源，Then 可沿 `Trace`（§4）还原完整推理链。
- GWT-4：Given 任一对外可见文本（Skill 名、视角输出），When 过中性化校验（§6），Then 拟人化表达被判失败。
- GWT-5：Given 快照/新鲜度需求，When 标注数据时间，Then 统一用 `dataset_snapshot_id` + `as_of`（§8），不另立第二套口径。

## 涉及契约
- [01-平台共享契约](../../docs/技术架构-v2/01-平台共享契约.md) §1 标识体系 / §2 SkillDescriptor / §3 LensOpinion / §4 Trace / §5 ResultEnvelope 与错误 / §6 中性化校验 / §7 配置元模型与降级 / §8 时间锚点
- 平台通用能力（What）见 [10-platform-capabilities](../../docs/PRD-v2-Agent/10-platform-capabilities.md)

## ⚠ 拆分预判（③ 阶段执行）
命中拆分触发（涉及 ≥ 2 个契约小节、跨 §1–§8 多类类型）：开工时在 ③ 将其拆为叶子子任务，建议按契约块切：
- `T-SC-001.1` 标识体系 + ResultEnvelope + 错误分支（§1/§5）
- `T-SC-001.2` Trace 结构 + 可追溯串联（§4）
- `T-SC-001.3` 中性化校验器（§6）
- `T-SC-001.4` 配置元模型 + 离线降级枚举（§7）
- `T-SC-001.5` 时间锚点 dataset_snapshot_id / as_of（§8，依赖 [数据库设计 sync_state](../../docs/数据库设计-BaoStock数据层/05-同步策略与新鲜度契约.md)）

父任务 `T-SC-001` 的 `status` 拆分后改由 children 派生，不再手填。

序列化格式 / schema 方言 / 目录结构由实现阶段决定（契约文档明确不锁定），故 ④ 对齐时须先与人确认技术栈选型再动手。
