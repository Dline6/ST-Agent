# T-L0-018.2 · 出网审计可选（默认关）与落盘形态批量化

## 目标
把出网审计由**强制逐次留痕**改为**可选、默认关**；并在审计开启时把落盘形态由「一请求一文件 + 每次重写整分区清单」（实测 ≈16 ms/次、n=3.7 万，O(n²) 形态）改为批量/追加形态，使落盘写入次数与请求数**解耦**。

## 验收标准（Given-When-Then）
- GWT-1 审计默认可关：Given 缺省构造的网关，When 发一次请求，Then 请求照常执行与返回（发包、计时、结果映射不变），但**不产生**逐次审计记录；Given 显式开启，Then 逐次留痕与现状同形。
- GWT-2 开关可配：Given [01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 的配置注册表条目，When 打开 / 关闭审计，Then 后续请求按新口径留痕（不重启进程），且该条目可导出 / 导入 / 版本化（铁律 3）。
- GWT-3 关闭时的连带口径（**显式化，不静默**）：Given 审计关闭，When 请求被离线拦截 / 查询 `pending_reconnect`，Then —— 离线拦截仍生效（那是**功能**不是留痕）；补发清单查询走**显式**的 `unavailable`（写明「审计未开启，无补发清单可查」），**不得**静默返回空集被读成「没有待补发」。
- GWT-4 落盘批量化（参考形态＝**分段日志**）：Given 审计开启，When 连发 N 次请求，Then ① 落盘的 `put` 次数与 N **解耦**（一段装 N 条，次数降到 ⌈N/段大小⌉ 量级，而非现状的 O(N) 且每次重写整分区清单）；② `query(since=…)` 借段的时间有序性**跳段**——查最近时段**不读全量历史**（现状 `pending_reconnect` 与日预算计量每次都要扫全分区）；③ `query` / `export_report` 的**读接口形态与时戳升序口径不变**（消费方零改动）。
- GWT-5 契约先行（铁律 8）：Given 本批变更，When 检查，Then [01](../../docs/技术架构-v2/01-平台共享契约.md) `net_access` 权限行的「所有实际请求纳入 L0 网络审计」与 [02 §6](../../docs/技术架构-v2/02-L0-本地优先基座.md) 的「必须经统一网关执行并登记」均**已改实**（改码之前），且断网可查历史的既有要求按新模式写明。

## 可关闭的遗留
- L0 / L1 / L2 / L3 四册未闭区逐册扫过：**无命中**（L0 册 `A5`「离线补发执行」归属 L5 升级链、解封条件「L5 升级链 `done`」在本批**不变**，仅其查询口的可用性口径随本任务写明）

## 假设与前提
- B1 关闭审计**不影响**网关的其他职责（发起前校验 / 计时 / 结果映射 / 离线拦截 / 能力分级）——被去掉的只是**落盘留痕**这一条 / 若错：会把「可关」误扩成「网关退化」，伤及铁律 1 之外的既有约束 / 验证：GWT-1 与既有 `tests/l0/test_gateway*.py` 全绿
- B2 审计开关的**唯一真相源**是配置注册表（[01 §7](../../docs/技术架构-v2/01-平台共享契约.md)），构造函数参数只是覆盖入口——避免「构造参数与配置各说各话」 / 若错：两处状态漂移，面板与行为不一致 / 验证：GWT-2 的热切换用例
- B3 批量形态**不改变**审计记录的内容与语义（仍只记计数与时戳、内容零明文），只改变**落盘组织**；故 §6 的「零明文」纪律不受影响 / 若错：批量封装的载荷边界会把内容带进留痕 / 验证：既有零泄漏用例 + 新增批量形态下的明文扫描用例
- B4 关闭审计后 `query` / `export_report` 对**历史**记录仍可读（旧记录不因关开关而消失或不可读）——关的是「以后记不记」，不是「已经记的删不删」 / 若错：用户会以为关闭=清除，与「可解释」相悖 / 验证：GWT-3 的历史可读用例

## 备注
**落盘形态的参考解法（分段日志，2026-10-04 ④ 对齐时定）**：现状是「一请求一文件」+ `Store.put` **每次重写整分区清单**，实测 ≈16 ms/次（n=37,700、清单 5.2 MB、约 139 字节/条），外推 12 万次请求累计 20–45 分钟；且 `gateway.query` 每次读全分区、`Store.open` 的 `_verify_all` 要逐文件解密。改为「**一段装 N 条**（如 1000 条或按小时切段）」后：`put` 次数由 12 万降到百量级、清单恒为百量级、文件数同步下降、`query(since)` 可**跳段**。**记录内容与读接口都不变**（仍只记计数与时戳、仍时戳升序），故 §6 的零明文纪律与消费方零改动。

更通用的替代是改 `Store` 的**清单为增量 / 分片**（`manifest.py` 的核心不变式，收益覆盖所有大分区，但风险高于分段日志）——**另案**，不在本任务内。
