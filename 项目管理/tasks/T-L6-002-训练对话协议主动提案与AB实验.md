## 验收标准（Given-When-Then）
取自 [story-09](../../docs/PRD-v2-Agent/story-09-reflection-loop.md) 与本任务范围内的架构段（[08 §3–§4](../../docs/技术架构-v2/08-L6-反思演进.md)），逐条落到三叶（父级只汇总，不重复）：

- Given 用户对某条推送点击「否定 + 说明原因」，When 记录，Then 反馈进入反思数据池（[`.1`](T-L6-002.1-训练对话协议.md) 上游）+ 概念性理解与「下次对话主动提及」落地 → [`.1`](T-L6-002.1-训练对话协议.md) GWT-1 / GWT-5
- Given 用户发起「训练对话」，When 明确修正，Then 做**概念性理解**（不是简单加权）+ 更新 Memory「你的模式」节点 + 生成对应 Skill 参数调整建议 → [`.1`](T-L6-002.1-训练对话协议.md) GWT-3
- Given 观察到「用户反复问某类问题超过 5 次」，When 触发，Then 主动提议「要不要创建一个专门 Skill？」+ 给出草稿 → [`.2`](T-L6-002.2-主动提案与周报候选生成.md) GWT-1
- Given 周报第四段「建议调整」，When 逐条查看，Then 每条含 `config_id` / 现值 / 建议值 / 理由且可追溯；**未经 §5 变更流不生效** → [`.2`](T-L6-002.2-主动提案与周报候选生成.md) GWT-4
- Given 一份低风险参数的实验，When 启用，Then 受授权面约束、全程留痕可查、效果判断保守（用户反馈优先）→ [`.3`](T-L6-002.3-AB实验.md) GWT-1 / GWT-3 / GWT-4

> 端到端装配（`build_m4_runtime`、「下次对话主动提及」的渲染、授权档位本体）与「反馈 → 训练 → 提案 → 变更流」全链路复核归关卡 [T-INT-005](T-INT-005-M4集成关卡反思演进与生态闭环.md)。
