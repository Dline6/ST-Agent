# T-L0-024 · 存量存储根对新增分区的兼容迁移

## 目标

修掉升级回归：新增第 8 个存储分区 `workspace`（提交 `35386c0`，T-AGT-014 批）后，早于该改动的存量存储根在 `Store.open` 时把「分区目录不存在」判成损坏、后端起不来。让「注册表新增分区」对存量根可自动消化，同时保留「已初始化分区被删」的损坏判定。

## 验收标准（Given-When-Then）

- GWT-1：Given 一个在 `workspace` 引入前创建的**明文**存储根（其余分区与清单齐全、无 `workspace` 目录），When `Store.open`，Then 不抛 `StorageCorruptionError`，`workspace` 以空分区就位，其余分区数据逐字节可读。
- GWT-2：Given 同类的**加密**存储根，When `Store.open(主密码)`，Then 同上；`workspace` 的空清单按该分区密钥落盘。
- GWT-3：Given 一个已把某分区登记为「已初始化」的根，When 其分区目录（连同清单）被删除后打开，Then 仍按 02 §2.3 报损坏，不静默重建为空。
- GWT-4：Given 一个不带分区表标记的旧根，When 首次以新版本打开，Then 只补建注册表中缺失且从未初始化的分区，并把该根的分区表刷新为当前注册表（此后删除可被 GWT-3 检出）。
- GWT-5：其余既有损坏语义（文件缺失 / 校验和不符 / 清单损坏 / 单分区失败不影响其余）When 打开，Then 行为不变。

## 接口面

- 输入（消费的前置接口）：
  - `PARTITIONS` / `PARTITION_NAMES`：`src/st_agent/l0/storage/partition.py`，由 `T-AGT-014` 批（提交 `35386c0`）交付，现为 8 个分区。
  - 格式标记：`src/st_agent/l0/storage/format.py` 的 `store.json` 读面与 `write_marker`（`T-L0-018.1` 交付）。
  - 打开与校验路径：`Store.open` → `_verify_all` / `_verify_partition`（`T-L0-002` / `T-L0-018.1` 既有实现）。
- 输出（本任务交付的公共 API / 落盘位置）：
  - `Store.open`：打开时先迁移「注册表有、本根从未初始化」的分区，再走既有校验；公共签名不变。
  - `format.read_partition_set(root) -> tuple[str, ...] | None`；`format.write_marker(root, mode, partitions=None)` 增加可选分区表参数。
  - `store.json` 新增 `partitions` 字段（本根已初始化的分区名集合，明文、不含密钥材料）；`Store.create` 写入全量注册表。
  - 回归夹具：`tests/l0/test_store_partition_migration.py`。

## 假设与前提

- **A1**：旧根（分区表字段缺失或标记缺失）首开时无法区分「本次新增的分区」与「升级前已被删的分区」；处置为首开补建并把分区表刷新为当前注册表，此后删除可检出。若错的影响：旧根上早已被删的分区会被静默恢复为空分区（无数据可丢——数据随目录已丢失）；验证方式：`test_legacy_root_without_marker_also_migrates` 与 `test_deleted_registered_partition_is_not_recreated` 分别钉住两端口径。
- **A2**：只有「目录不存在」或「目录为空且无清单」才算从未初始化；目录在而清单缺失仍判损坏（可能残留数据）。若错的影响：把残留数据的半截分区误当空分区、静默丢数据；验证方式：`test_missing_manifest_with_data_stays_corrupt`。
- **A3**：整个根没有任何有效分区清单时不补建（不把误删的根复活成空存储）。若错的影响：用户误删全部数据后启动得到一个空存储而非明确的损坏告知；验证方式：`test_wiped_root_is_not_resurrected`。
- **A4**：未解锁的 `secrets` 无密钥、不参与迁移；其「已初始化」登记随分区表落盘，解锁后的缺失仍按既有语义处理。若错的影响：迁移不触碰凭据面，无额外风险；验证方式：明文/加密存量根两条 GWT 用例均含 `secrets` 未解锁形态。
