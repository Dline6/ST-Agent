# T-UI-016.1 · 推理区：触发、进度与视角阵容

> [`T-UI-016`](T-UI-016-推理区触发进度分歧图与视角详情.md) 三叶之一（[D-112](../决策日志.md) ①）——把 `/deliberation` 立起来：页面骨架与 `?view=` 分派、编排触发、**逐视角进度面**，以及视角**阵容**（列表 / 新建自定义视角 / 启停 / 删除）。分歧图两视图与视角详情归 [`.2`](T-UI-016.2-分歧图与视角详情.md)，推理链面板与决策记录归 [`.3`](T-UI-016.3-推理链面板与决策记录.md)。

## 目标

- **`/deliberation` 页骨架**——`pages.js` 挂 `render`（本叶起首屏不再走可用性探针），页内按 `?view=` 分派：缺省＝触发与进度，`?view=lenses`＝自定义视角创建页（[11-sitemap §2.2](../../docs/PRD-v2-Agent/11-sitemap.md)：一屏一路径、子面按页内视图 / 查询串聚合）。
- **编排触发**——主题（自由文本）+ 模式（快速 / 深度）；`POST /api/deliberation/analyze` 一次跑完，响应按 [`/api/chat`](../../src/st_agent/ui/web/js/pages/chat.js) 的先例**分多段**回（本叶消费 `reply` 信封 + `progress` 进度描述）。
- **多视角并行执行进度页**（[11-sitemap §2.1](../../docs/PRD-v2-Agent/11-sitemap.md)：复用 `report_card`）——**逐视角状态并列**，非 `ok` 视角显式原因，**不合并、不给统一建议**（[铁律 4](../工程宪法.md)）。
- **视角阵容**（[06 §1](../../docs/技术架构-v2/06-L4-多视角推理.md) 常设阵容·用户可增删）——阵容读面（复用 `setting_panel`，新增 `deliberation-lens` 面键）+ 自定义视角创建（页内表单：名称 / 描述 / `skill_bundle` / 评判准则 / 信心度策略）+ 启停 / 删除。
- **空态**（[06 §6](../../docs/技术架构-v2/06-L4-多视角推理.md)）——阵容非空时正常呈现 7 官方视角；**创建入口常驻**，不靠「有无自定义」反推（「不由计数 0 反推」）。

**本批的边界**（不越界）：

- **触发确认对话框与追问对话框是[对话流内面](../../docs/PRD-v2-Agent/11-sitemap.md)，住 `/`（Chat）**——`analyze` 的 `mode`（快速 / 深度）已由[意图级参数声明](../../src/st_agent/l3/intent/protocol.py)承载，本叶**不重复造**一套；页面上的模式选择器是**页内触发**的入口，不是 §3.2 澄清协议的复制。
- **编排本体归 L4**——本叶只触发与呈现，不改 `Deliberation` / `LensRoster` 的既有语义。
- **不重造 `divergence_map`**——分歧图归 [`.2`](T-UI-016.2-分歧图与视角详情.md)。
- **中性化校验不前置到前端**——命名 / 描述的唯一真相源是 `LensRoster.add_custom`（→ `NeutralityGuard.check_name`），前端只转发原文、由后端拒。

## 验收标准（Given-When-Then）

- GWT-1：Given 空主题 / 未知模式，When 提交触发，Then 回 `validation_failed` + 原因，**未跑编排**（校验在编排之前）
- GWT-2：Given 触发（快速 / 深度），When 执行，Then 参与视角由**后端**定（快速 ＝ `FAST_COMBO` 三条、深度 ＝ 全部启用），前端不硬编码视角名单；进度面**逐视角并列**呈现立场 / 信心度 / 理由，`insufficient-data` 视角**照常成行**并显式原因
- GWT-3：Given 阵容为空 / 未注入 Skill 执行面，When 触发，Then 分别回 `empty` + 原因 / `unavailable` + 点名归属（装配归组合根），**不静默留空、不伪造**
- GWT-4：Given 自定义视角创建，When 命名或描述含拟人化（人名 / 性格 / 第一人称），Then 经 `LensRoster.add_custom` 的中性化校验**拒**（`validation_failed` + 原因），**不落盘**；命名合法时落盘并在阵容里可见
- GWT-5：Given 内置视角，When 尝试删除，Then 显式拒（内置只能停用不可删），阵容与磁盘均不变；停用后再触发时该视角**不参与**（由后端 `list_enabled` 定）
- GWT-6：Given 真组合根 + 真回环服务，When 在 Edge 走查「触发 → 进度」与阵容增删启停，Then 全程可用、控制台无新增报错

## 假设与前提

- **A1**：`/deliberation` 的**触发**入口与 [11-sitemap §2.1](../../docs/PRD-v2-Agent/11-sitemap.md) 判为「对话流内面」的**触发确认对话框**是两回事——后者（3 / 7 视角的问项）住 `/`，已由 [`T-INT-003`](done/M2/T-INT-003-M2集成关卡多视角决策闭环.md) / [`T-UI-012.2`](T-UI-012.2-上下文卡片与澄清确认.md) 交付；本叶的页内模式选择器只是**页内触发**的入口，不是 §3.2 澄清协议的复制。**若错的影响**：会造出第二套问项真相源（与 [D-110](../决策日志.md) ⑤ 的「猜协议」同类），并把 GWT-1 的「触发确认」误判为本叶未交付。**验证方式**：读 [`INTENT_PARAM_SPECS`](../../src/st_agent/l3/intent/protocol.py) 确认 `analyze.mode` 在册、并在 Edge 走查 Chat 侧触发确实出模式问项；本叶不新增任何 mode 词表。
- **A2**：`POST /api/deliberation/analyze` 的**多段响应**可用——`envelope_payload` 之外允许一个响应 dict 携带若干**各自独立渲染**的段（`reply` 信封 + `progress` 描述），先例是 [`POST /api/chat`](../../src/st_agent/ui/app.py) 的 `{reply, session_id, needs_confirmation, description, clarification}`。**若错的影响**：若既有约定要求端点**恒回单个信封**，则进度 / 分歧图 / 链三段要么塞进同一描述（造出 `01 §12` 无对应型的复合型，[铁律 8](../工程宪法.md) 触发），要么退回「会话态 + 独立读端点」——[D-112](../决策日志.md) ② 已否决后者。**验证方式**：读 [`server.py`](../../src/st_agent/ui/server.py) 的 `_dispatch_guarded` 与 [`chat.js`](../../src/st_agent/ui/web/js/pages/chat.js) 确认多段形状是既有做法；集成套件断言 `analyze` 响应同时含 `reply.status` 与 `progress.component_type`。
- **A3**：`DeliberationResult.opinions` 足以支撑**进度面**（逐视角状态 = `stance` / `confidence` / `key_reasons`），无需 L4 新增「运行中」中间态。**若错的影响**：若 PRD 的「进度」被理解为**运行中的实时进度**（流式），则本叶的**事后**逐视角并列与之不符——那需要流式通道（SSE / 轮询 + 会话态），远超本任务范围。**验证方式**：读 [11-sitemap §2.1](../../docs/PRD-v2-Agent/11-sitemap.md) 的「多视角并行执行进度页 → 复用 `report_card`（逐视角状态并列，非 ok 段显式原因）」——`report_card` 是**终态**描述件，与事后并列一致；Edge 走查确认进度面出逐视角状态且非 `ok` 视角带原因。
- **A4**：`skill_bundle` 的存在性校验（经 `SkillRegistry.get`）在组合根已注入 `skills` 时生效；**若错的影响**：本叶创建自定义视角时若引用了不存在的 `skill_id`，在已注入时被拒（`validation_failed`）、未注入时只过形态校验（延迟到运行期降级为 `insufficient-data`）——两种行为都**显式**，无静默。**验证方式**：读 [`LensRoster.__init__`](../../src/st_agent/l4/roster.py) 的 `skills` 分支与组合根 [`build_m2_runtime`](../../src/st_agent/app.py) 的 `LensRoster(store, skills=runtime.skills)`；用例分别覆盖注入 / 未注入两态。
