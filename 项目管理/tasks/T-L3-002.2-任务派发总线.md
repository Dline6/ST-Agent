# T-L3-002.2 · 任务派发总线（§4）

## 目标

兑现 [05 §4](../../docs/技术架构-v2/05-L3-对话主入口.md)：意图确认后**派发执行**——每次派发产生 `trace_id`（[01 §4](../../docs/技术架构-v2/01-平台共享契约.md)），按 [§3.1](../../docs/技术架构-v2/05-L3-对话主入口.md) 的六类去向路由，结果以 [01 §5](../../docs/技术架构-v2/01-平台共享契约.md) 的 `ResultEnvelope` 语义渲染；LLM 端点不可用**显式降级告知**，不静默失败。本叶交付**总线路由面与渲染语义**；尚未接入的去向**显式标 unavailable**，不假装执行。

## 验收标准（Given-When-Then）

- **GWT-1 · 派发产生 `trace_id` 且可展开**：Given 一张**已确认**的意图确认卡，When 派发，Then 本次派发携带唯一 `trace_id`（[01 §4](../../docs/技术架构-v2/01-平台共享契约.md)）——`query` 去向的链含 `skill_run` 步骤、可沿 `replay()` 回放；未接入去向为**空链** + 显式原因（**不伪造步骤**，[01 §4](../../docs/技术架构-v2/01-平台共享契约.md) 的五类 `step_type` 无「派发」一类）。未确认的卡**拒绝派发**（`validation_failed` + 理由）。
- **GWT-2 · `query` 去向接 L1 Skill**：Given `query` 意图 + 目标 `skill_id`，When 派发，Then 经**注入的** [`SkillRunner.run`](../../src/st_agent/l1/runner/runner.py) 执行，产出 `RunOutcome`（信封 + 链），且信封**原样透出**——总线不重包、不改 `status`、不吞 `reason`。
- **GWT-3 · 未接入去向显式不可用**：Given 去向属 [§3.1](../../docs/技术架构-v2/05-L3-对话主入口.md) 中**尚未接入**的类（`configure` → [`T-L3-003`](T-L3-003-对话即配置ConfigDraft双通道.md) · `analyze` → [`T-L4-002`](done/M2/T-L4-002-多视角执行编排.md) · `memory_op` → [`T-L3-005`](T-L3-005-冲突裁决与反馈采集点.md) · `train` → [`T-L6-002`](T-L6-002-训练对话协议主动提案与AB实验.md)），When 派发，Then 返 `unavailable` + 原因 + **归属任务 id**（同 [`card.py`](../../src/st_agent/l3/home/card.py) 的「未接入即 `unavailable` + 生产方」先例）；不静默丢弃、不伪造结果。
- **GWT-4 · 六态渲染语义齐备**：Given 任一 `ResultEnvelope`，When 取渲染语义，Then 按 [§4](../../docs/技术架构-v2/05-L3-对话主入口.md) 逐态给出 UI 语义——`ok`→正常 UI · `empty`→空状态文案 + 原因 · `unavailable`→数据延迟提示 + **最后更新时间** · `dependency_failed`/`failed`→错误态 + **日志入口** · `validation_failed`→参数/输入校验失败 + 理由；映射表**穷尽六态**（缺态即构造期拒绝）。
- **GWT-5 · LLM 端点不可用显式降级**：Given 派发路径需要 LLM 而端点不可用，When 派发，Then 产出 `unavailable` 信封并携**中性改述**的降级告知（Story 原文「云端 LLM 暂不可用，切换到本地推理模式（能力受限）」按铁律 2 中性化），可用的离线路径**不被一并掐断**；文案过 [01 §6](../../docs/技术架构-v2/01-平台共享契约.md) 执行点 2 `check_output`。

## 假设与前提

- **A1 · 六类去向中本叶只接 `query`（+ `explain` 的 Trace 访问面），其余四类标 `unavailable` 并点名归属任务**：[§3.1](../../docs/技术架构-v2/05-L3-对话主入口.md) 的六类去向对应的下游任务（`T-L3-003` / `T-L3-004` / `T-L3-005` / `T-L4-002` / `T-L6-002`）**全为 `todo`**。总线若等它们则整批阻塞，若伪造则违「失败显式化」。故本叶交付**路由表 + 接入态**，未接入者按 GWT-3 显式不可用（同 [`card.py`](../../src/st_agent/l3/home/card.py) 六段先例）。若错（须在做总线前先做下游）：返工面＝`DispatchRoute` 的接入态与四个下游任务的排序。
- **A2 · `trace_id` 由 L1 `SkillRunner` 产生并回传，总线不另生成**：[01 §1](../../docs/技术架构-v2/01-平台共享契约.md) 登记 `trace_id` 产生方为「L1 调度器」。`SkillRunner.run(trace=None)` 内部新建 `Trace`，故 `query` 去向的 `trace_id` **由 L1 产**、总线经 `RunOutcome.trace.trace_id` 取用；未接入去向无 Skill 执行，其 `trace_id` 由总线新建一条**仅含派发步骤**的链以保全「一切可追溯」。若错（须总线统一生成）：返工面＝`DispatchOutcome` 的取链逻辑。
- **A3 · 「未接入」的 `unavailable` 用 `last_updated_at` 承接 `ResultEnvelope` 的构造约束**：[01 §5](../../docs/技术架构-v2/01-平台共享契约.md) 要求 `unavailable` 必带「最后更新时间」。下游未接入时**没有任何数据落地**，无真实更新时间；本叶沿用 [`card.py`](../../src/st_agent/l3/home/card.py) 的处置——把**归属任务 id 与生产方说明**写进 `reason`，`last_updated_at` 取派发时刻并在 `reason` 中**明说该时间不代表数据时间**（不冒充「数据截止时刻」）。若错（须为此新增信封字段）：返工面＝01 §5 契约 + 信封构造面。
- **A4 · LLM 降级的落点是「渲染语义」而非「总线阻断」**：[05 §4](../../docs/技术架构-v2/05-L3-对话主入口.md) 只写「LLM 端点不可用时显式降级告知」。本批唯一真正调 LLM 的在 `.1` 的理解端口，总线自身无 LLM 调用；故 `.2` 交付**中性降级告知常量**并把 `llm_degraded` 作为渲染语义的显式入参——`unavailable` 信封若源于 LLM 路径则附降级告知，否则只是普通数据延迟；**不依赖 LLM 的去向（`query`）不受影响**（不静默失败、可用路径不被掐断）。若错（须由总线自己判 LLM 可用性并阻断）：返工面＝`DispatchBus` 的构造面与 `RENDER_SEMANTICS` 的入参。
