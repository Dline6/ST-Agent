# T-UI-039 · 运行失败恢复与授权记忆

## 目标

补齐运行面板/对话面的失败恢复与授权体验：`llm_failed` 显示“从已有证据继续”而不是重发原文；用户批准过的工具在同一运行内不再反复询问；失败原因以可读形态呈现。预算/步骤显示与上限预警已迁至 [`T-AGT-033.4`](done/M11/T-AGT-033.4-长任务步骤压缩与预算联动.md)，子 Agent 的步骤口径说明归 [`T-AGT-032.2`](T-AGT-032.2-子Agent事件流与独立超时.md)。

## 验收标准（Given-When-Then）

- GWT-1：Given 运行因超时或提供方错误失败，Then 对话面提供“从已有证据继续”，走 `resume`（`kind=retry`）而不是重新 `send` 原文；继续后旧步骤不重跑。
- GWT-2：Given 用户在协作档批准某工具一次，Then 同一运行内再次调用该工具不再要求确认；会话级“本会话允许”与全局档位的关系在界面上明确可见。
- GWT-3：Given 失败原因，Then 界面显示可读原因（超时值、端点、重试次数），不只显示 `failed`。

## 接口面

待 ④ 对齐实填。预计落点：

- 输入：`agent_continuation`（[`facades/chat.py`](../../src/st_agent/composition/facades/chat.py)）· 续跑入口（[`continuation.py`](../../src/st_agent/l3/runtime/continuation.py)）· 运行期授权（[`runtime_authorization.py`](../../src/st_agent/l6/runtime_authorization.py)）· 运行事件（[`run_events.js`](../../src/st_agent/ui/web/js/run_events.js)）· 对话页（[`chat.js`](../../src/st_agent/ui/web/js/pages/chat.js)）。
- 输出：失败续跑按钮与载荷 · 运行/会话级允许集 · 可读失败原因。

## 可关闭的遗留

无（新建任务；④ 对齐时逐册复核）。

## 假设与前提

- **A1**：失败续跑复用 `T-AGT-031.3` 的 `llm_failed` 可续跑路径；若错，本任务只能做“重发 + 提示”，不能承诺不重跑。
- **A2**：运行级允许集是进程内瞬态，不落全局配置；若错，需要在 L6 增加持久化与变更留痕。
