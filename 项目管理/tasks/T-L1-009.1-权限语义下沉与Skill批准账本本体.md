# T-L1-009.1 · 权限语义下沉与 Skill 批准账本本体

## 目标

给 Skill 侧批准态造落点：`SkillPermissionBook`（`config/skill-permissions/<base>.json`，**base 粒度**），并把批准语义的**共用件**下沉到层间中立处——`PermissionApproval` / `PERMISSION_KINDS` / `describe_permission` 一个口径只住一份，两个账本共用同一套簿记基类，各自只提供「键校验 + 落盘前缀」。MCP 侧改为继承基类，但**公共 API 与落盘布局逐字节不变**。

## 验收标准（Given-When-Then）

- **GWT-1 共用语义只有一份**：Given 全仓检索 `PermissionApproval` / `PERMISSION_KINDS` / `describe_permission`，When 完成本叶，Then 定义体只在 `contracts/permissions.py` 与 `l1/permission_book.py` 各一处出现；`l1.mcp.permissions` / `l1.mcp.models` 的既有导入路径与 `__all__` **保持可用**（re-export）。
- **GWT-2 MCP 侧零变化**：Given 既有 `tests/l1/test_mcp_registry.py` / `test_mcp_mapping.py` / `test_mcp_lifecycle.py` / `test_runtime_mcp.py`，When 完成本叶，Then 全绿且未改断言；`McpPermissionBook(store)` 签名不变、落盘仍 `config/mcp-permission/<server_id>.json`。
- **GWT-3 账本语义对齐**：Given `SkillPermissionBook`，Then `declare` / `approve` / `reject` / `approvals` / `approved_permissions` / `pending_permissions` / `describe` / `forget` 与 `McpPermissionBook` 同语义——`declare` 保留**仍在清单内**的既有决定；对未声明的权限 `approve` / `reject` → `SkillPermissionError`；`pending` 不得带 `decided_at`、已决必须带。
- **GWT-4 批准随 base 跨版本存活**：Given 对 base `sk_x` 批准某权限，When 取同 base 另一版本（`sk_x_v1.1`）的批准集，Then 同一条记录生效（账本按键为 base，非 `skill_id`）。
- **GWT-5 落盘分区**：Given 两个账本各写一次，Then Skill 侧落 `config/skill-permissions/<base>.json`、MCP 侧落 `config/mcp-permission/<server_id>.json`，互不串扫。

## 假设与前提

- **A1 · `PermissionApproval` 下沉后异常语义不变**：现模型的 `_shape` 抛 `McpValidationError`，下沉到 `contracts` 后只能抛 `ContractViolation`（contracts **不得** import 具体层）。已核 [contracts/errors.py](../../src/st_agent/contracts/errors.py) 的既有口径「pydantic 会包装为 `ValidationError`，异常链中保留本类型」——`McpPermissionBook._parse` 正是 catch `(TypeError, ValidationError)` 再抛 `McpValidationError`，故**对外异常类型逐字节不变**。若错：返工面＝`_parse` 的 catch 面与 MCP 用例断言。
- **A2 · 「共用簿记基类」值得引入**：两个账本的 declare/decide/approve/reject/approvals/describe/forget 逻辑同形，基类消掉重复（[D-004](../决策日志.md) / [D-009](../决策日志.md) / [D-033](../决策日志.md) 的「口径只有一份」取向）。代价＝一层继承 + 错误类型经构造参数注入。若错（判定为过度抽象）：返工面＝退回「两份近似实现」，行为不变。
- **A3 · base 粒度不与既有语义冲突**：`SkillRegistry` 的待检查标记按 base 归集（[registry.py:345](../../src/st_agent/l1/skills/registry.py)）已有先例；批准按键为 base 后，「同一能力的批准跨版本存活」成立，而**残留的多余记录无害**——`SkillRunner` 的硬门比对的是**当前描述体**的 `permissions`，多余的已批准项不会被取用。验证：GWT-4 + GWT-3。
