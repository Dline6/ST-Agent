# T-L3-006 · 能力安装 / 导入审批面（双通道）

> **本任务是 [L1 册 `D2`](../遗留问题/L1-遗留问题.md) 的点名承接方**（2026-09-29 由 [`T-L3-004.1`](T-L3-004.1-推理链时间线渲染件.md) / [`.2`](T-L3-004.2-上下文草稿裁决卡渲染件.md) 批次 ④ 对齐时就地修正归属：原归属列的 `T-L3-004` 只覆盖 [05 §6–§7](../../docs/技术架构-v2/05-L3-对话主入口.md) 的四型渲染件，**不含**安装 / 导入审批面，见 [D-064](../决策日志.md)）。任务本身尚未 ④ 对齐——`## 接口面` 与 `## 假设与前提` 是**开工时的实填入点**，下方内容为待确认的草案。

## 目标
给 [01 §10](../../docs/技术架构-v2/01-平台共享契约.md) 权限模型的**逐项批准**这一环补上 L3 侧的**双通道**（对话 + 结构化面板）表现面：能力的权限申请在此**展示 + 逐项批准 / 拒绝**，并调用 L1 的 `SkillPermissionBook.declare` / `approve` / `reject` 落账。落点口径见 [03 §5.1](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)（MCP Server 添加时「连接测试 + 权限申请展示 + 逐项批准」）与 [09 §3](../../docs/技术架构-v2/09-生态与分享.md)（导入流水线的「权限审核 → 用户批准 → 安装」）。

## 验收标准（Given-When-Then）
> 草案，待人 ④ 对齐时逐条定案（并核对是否命中[拆分触发](../工作流.md)）。

- Given 一个声明了权限的能力（挂载的 MCP Server 或待导入的分享物），When 打开审批面，Then 逐项列出其声明权限（经 `describe_permission` 的中性措辞），**不合并成一句话**
- Given 用户在审批面逐项批准，When 提交，Then 经 [`SkillPermissionBook.approve`](../../src/st_agent/l1/skills/permissions.py) 落账（挂载时先 `declare`），**未经批准的能力仍 `fail-closed`**
- Given 用户拒绝某项，When 提交，Then 落 `reject` 且原因随返回值透传（反馈池归 [L6](../../docs/技术架构-v2/08-L6-反思演进.md)）
- Given 未注入批准账本，When 打开审批面，Then `unavailable` + 点名（**不假装已批准**）

## 接口面
- **输入**：
  - [`l1/skills/permissions.py`](../../src/st_agent/l1/skills/permissions.py)——`SkillPermissionBook.declare` / `approve` / `reject`（写入入口**当前无调用方**，正是 [`D2`](../遗留问题/L1-遗留问题.md) 所指）
  - [`contracts/permissions.py`](../../src/st_agent/contracts/permissions.py)——`PermissionApproval` / `PERMISSION_KINDS` / `describe_permission`
  - [`T-UI-001.3`](T-UI-001.3-契约登记与组件注册表宿主.md) 的 [`ui_description`](../../src/st_agent/contracts/ui_description.py) 契约与组件注册表宿主
- **输出**：`src/st_agent/l3/`（审批面视图数据）· `src/st_agent/ui/web/js/plugins/`（对应渲染件）· 落盘：**无新分区**——批准态落 L1 的 `config/skill-permissions/<base>.json`，本任务只接线

## 可关闭的遗留
- **L1 册 `D2`**（Skill 侧批准账本的写入入口无落点）——**本任务即其归属修正后的点名承接方**；立项时按[册规](../遗留问题/README.md) 2 复核归属，交付后销账。
