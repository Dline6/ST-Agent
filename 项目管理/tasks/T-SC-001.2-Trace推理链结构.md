# T-SC-001.2 · Trace 推理链结构与可追溯串联

## 目标
实现 [01-平台共享契约](../../docs/技术架构-v2/01-平台共享契约.md) §4 的 Trace 推理链结构：步骤列表（step_type 五枚举、ref、输入输出摘要、耗时、时间戳）+ conclusion_ref，支持追加、禁止改写既有步骤；断网/降级路径同样可记入。

## 验收标准（Given-When-Then）
- GWT-3：Given 一条面向用户的结论，When 沿 `Trace.steps` 逐段回放（step_type → ref → 摘要），Then 可还原完整推理链并落到 `conclusion_ref`（§4）。
- GWT-3a：Given 一个已存在步骤的 Trace，When 尝试修改既有步骤内容，Then 被拒绝；When 追加新步骤，Then 成功且顺序保留（Trace 不可事后修改、追加可以）。

## 接口面
> 追补于 2026-09-26：本任务完成早于接口面机制落地，据已合入代码与执行日志回溯填写（非 ④ 对齐时填写）。
- 输入（消费的前置接口）：T-SC-001.1 的 `ContractViolation` 与 `trace_id` 类型
- 输出（本任务交付的公共 API / 落盘位置）：
  - `st_agent.contracts.trace`：`Trace.append_step` / `.append_degraded` / `.conclude` / `.replay`、`TraceStep`、`ConclusionRef`、`digest_of`、`TraceError`
  - 无本任务落盘（Trace 由调用方随结论持久化）
  - 消费方：T-L1-001.2（SkillRun 追加 `skill_run` 步骤）、L3 推理链可视化与 L4 视角观点锚点（均未开工）
