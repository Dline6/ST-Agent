# T-UI-012.1 · 对话骨架与快捷指令

> [T-UI-012](T-UI-012-Chat主界面对话流与生成式UI宿主.md) 的**对话骨架叶**（[D-110](../决策日志.md) ①）。把 IA 的**唯一主入口**接通——首页 `/` 挂上 `render`，对话流 + 输入面 + 首开引导语落地，输入框提交走既有 `POST /api/chat`（[D-103](../决策日志.md) ① 的缺口：后端早已通、前端无一文件消费它），并立起 `/` 触发的快捷指令菜单。

## 目标

四件交付：

1. **首页挂 `render`**——[`pages.js`](../../src/st_agent/ui/web/js/pages.js) 给 `/` 登记项加 `render: renderChatPage`（静态 import 新模块 [`web/js/pages/chat.js`](../../src/st_agent/ui/web/js/pages/chat.js)）。这是本批三叶共用的**页面宿主**：本叶立起骨架，[`.2`](T-UI-012.2-上下文卡片与澄清确认.md) / [`.3`](T-UI-012.3-生成式UI宿主.md) 往其中填卡片与生成式 UI 面。
2. **对话流 + 输入面 + 首开引导语**——消息列表（user / assistant 气泡，**非**对话体措辞，只承载文本与信封）、输入框、首开引导语（取自上下文卡片描述的 `greeting` 槽，单一来源＝L3 `HOME_GREETING`）。提交走 `POST /api/chat {action:"post", text}`，回复信封经**既有** `renderEnvelope`（六态 chrome + 注册表）进流；`session_id` 在**进程内**保持，后续轮带同一 id（`append` 入会话树，§1）。
3. **快捷指令菜单**（[05 §8](../../docs/技术架构-v2/05-L3-对话主入口.md)）——输入框键入 `/` 触发补全清单，条目取自真 `CommandRegistry.list()`（官方 / 用户分组，名称 + 说明）；点选即把 `/名称` 填入输入框。**不前端硬编码**指令表（避免第二真相源）。
4. **两枚新读端点**（本批后端骨架，`.2` / `.3` 消费）——`GET /api/chat/context`（上下文卡片描述，走既有 `chat.context_card()`）与 `GET /api/chat/commands`（指令清单）；`UiApp` 新增 `commands` 鸭子端口，组合根 `M5Runtime` 透出 `m1.commands`、[`__main__.py`](../../src/st_agent/__main__.py) 注入。**未接线即 fail-closed**（`unavailable` + 点名，不 500、不装空表）。

**本批的边界**（不越界）：

- **两枚端点均为只读**——写面白名单（`_POST_ROUTES`）逐条不变，`/api/chat` 仍是本组**唯一写端点**。
- **不填卡片 / 生成式 UI 内容**——六段卡片归 [`.2`](T-UI-012.2-上下文卡片与澄清确认.md)，描述渲染归 [`.3`](T-UI-012.3-生成式UI宿主.md)；本叶只留挂载点与回复流。
- **不动壳的路由机制**（[D-063](../决策日志.md)）——`PAGE_PATHS` 精确匹配 + SPA 回退 + 令牌分档不变；`PAGE_PATHS` 本身**不增条目**（`/` 已在）。新端点属 `/api/*`，**要令牌**。
- **不引构建链**（[D-063](../决策日志.md)）。
- **不越层取数**——表现层只经鸭子端口，组合根是唯一装配点（[铁律 7](../工程宪法.md)）。

## 验收标准（Given-When-Then）

- **GWT-1** Given 首页 `/`（首导航），When 打开，Then 出对话流 + 输入框 + 首开引导语（**无**传统菜单式入口层级），输入框提交走 `POST /api/chat` 并落一条 user 气泡、回复信封以六态 chrome 进流；同会话后续轮带同一 `session_id`（[D-103](../决策日志.md) ① 缺口关闭）。
- **GWT-2** Given `chat` 门面未注入，When 提交，Then 回复信封 `unavailable` + 点名装配归属，页面**如实**呈现该态（不静默丢弃、不伪造成功）；Given `chat` 已注入，When 提交，Then 正常往返。
- **GWT-3** Given 输入框键入 `/`，When 触发补全，Then 列出来自 `GET /api/chat/commands` 的指令（名称 + 说明，按来源分组），点选即填入输入框；Given `commands` 端口未注入，When 打开菜单，Then 显式不可用 + 点名（不摆假清单）。
- **GWT-4** Given 本叶生成的界面文案（首开引导语挂点 / 输入占位符 / 按钮 / 未知路径提示），When 逐条核对，Then 按[契约 9 中性表达](../../docs/PRD-v2-Agent/10-platform-capabilities.md)撰写、**无拟人化**（人名 / 性格 / 第一人称 / 情感 / 对话体）；引导语取后端 `greeting` 槽、不在前端另造。
- **GWT-5** Given 本叶改动，When 跑 `pytest tests/contracts tests/test_layering.py tests/test_tools.py tests/integration tests/ui` + `python tools/verify_docs.py --strict`（在 `项目管理/` 下），Then 范围套件全绿、检查 1–9 全过 0 断链；且 [`tests/test_layering.py`](../../tests/test_layering.py) 的 `test_ui_is_client_only` / `test_app_is_composition_root_only` **不改即绿**。

## 接口面

- **输入**（消费的前置接口）：
  - `POST /api/chat` → [`UiApp.api_chat`](../../src/st_agent/ui/app.py) → [`DialogFacade.turn`](../../src/st_agent/app.py)（`done`，M1 关卡 [`T-INT-002`](done/M1/T-INT-002-M1集成关卡首次可对话.md) 交付）——返 `{reply(ResultEnvelope+render), session_id, needs_confirmation, description(UiDescription|null)}`；本叶按 `session_id` 续轮、按 `needs_confirmation` 交由 [`.2`](T-UI-012.2-上下文卡片与澄清确认.md) 呈现确认卡。
  - 既有六态渲染 chrome 与组件调度：[`web/js/render.js`](../../src/st_agent/ui/web/js/render.js) 的 `renderEnvelope`（`done`，[`T-UI-001`](done/M1/T-UI-001-表现层骨架与本地服务通信面.md) 交付）——本叶**复用**，不复制语义表。
  - 上下文卡片数据：`DialogFacade.context_card()`（`done`，`app.py:322`）——本叶把它接成 `GET /api/chat/context`，取 `greeting` 槽。
  - 快捷指令注册表：L3 [`CommandRegistry.list()`](../../src/st_agent/l3/commands/registry.py)（`done`，[`T-L3-001.3`](done/M1/T-L3-001.3-快捷指令注册表.md) 交付）——经 `M5Runtime.m1.commands` 取。
  - 端口注入范式：`T-UI-004.1` / [`T-UI-011.1`](T-UI-011.1-多面端口注入与各面门面装配.md)（`done`）的 `UiApp` 字段 + `build_ui` / `serve` 同名关键字 + `__main__.py` 的 `getattr(runtime, …, None)`。
- **输出**（本任务交付的公共 API / 落盘位置）：
  - `src/st_agent/ui/web/js/pages/chat.js`（新）——导出 `renderChatPage(page, mount)`：对话流宿主 + 输入面 + 首开引导语 + `/` 补全菜单；导出供 `.2` / `.3` 复用的挂载点（会话流容器 / `session_id` 句柄）。
  - `src/st_agent/ui/web/js/pages.js`——`/` 登记项加 `render: renderChatPage`。
  - `src/st_agent/ui/app.py`——`UiApp` 新增 `commands` 鸭子端口字段；新增 `api_chat_context()` / `api_chat_commands()`（均出信封、未接线即 `unavailable` + 点名）。
  - `src/st_agent/ui/server.py`——`_GET_ROUTES` 新增 `/api/chat/context` · `/api/chat/commands`（**只读**）；`serve(...)` 加 `commands` 可选关键字。
  - `src/st_agent/app.py`——`M5Runtime` 透出 `commands`（＝`m1.commands` 句柄）。
  - `src/st_agent/__main__.py`——`run_backend` 注入 `commands=getattr(runtime, "commands", None)`。
  - `src/st_agent/ui/web/css/app.css`——对话流 / 输入面 / 补全菜单的中性样式。
  - **供 [`.2`](T-UI-012.2-上下文卡片与澄清确认.md) / [`.3`](T-UI-012.3-生成式UI宿主.md) 消费**：`GET /api/chat/context` · `GET /api/chat/commands` · `pages/chat.js` 的挂载点。
  - **不交付**：卡片六段渲染 / 澄清确认交互 / 描述渲染 / 契约文档变更。

## 假设与前提

- **A1**：首页**保留**既有 `nav`——[11-sitemap §2.2](../../docs/PRD-v2-Agent/11-sitemap.md) 的导航模型口径明调：`nav` 是「全局入口」的**一层平铺可视化**，而 §1 的「无传统菜单式入口层级」指**无多级展开菜单**，二者不冲突。故首页沿用壳的 `nav`，**不**在页内另造第二套菜单。**若错的影响**：首页需隐藏 / 改造 `nav`，会波及 [`main.js`](../../src/st_agent/ui/web/js/main.js) 与 [`.2`](T-UI-012.2-上下文卡片与澄清确认.md)–[`T-UI-018`](T-UI-018-设置区与全局要素.md) 全部页面。**验证方式**：GWT-1 走查首页**无页内菜单区**；[`tests/ui/test_ui_shell_routing.py`](../../tests/ui/test_ui_shell_routing.py) 的 `nav` 收敛守卫**不改即绿**。
- **A2**：快捷指令数据源＝真 `CommandRegistry`，经新 `commands` 端口 + `GET /api/chat/commands` 下发（**不**前端硬编码指令表，避免 [05 §8](../../docs/技术架构-v2/05-L3-对话主入口.md) 警告的第二份枚举）。**若错的影响**：若前端自持指令表，会与官方 Pack 的 `command` kind 更新分叉。**验证方式**：GWT-3 断言条目来自端点；`commands` 缺席时菜单 fail-closed。
- **A3**：首开引导语取 `context_card` 描述的 `greeting` 槽（单一来源＝L3 [`HOME_GREETING`](../../src/st_agent/l3/home/card.py)），前端**不**另造引导语常量。**若错的影响**：若前端自持引导语，中性改述会两处分叉。**验证方式**：GWT-4 逐条核对文案来源；GWT-1 走查引导语随卡片空/非空态一致。
- **A4**：`/api/chat` 回复信封已附 `render` 六态语义（[`envelope_payload`](../../src/st_agent/ui/envelope.py)），前端**复用** `renderEnvelope` 呈现、不复制语义表（缺 `must_show` 字段按服务端契约违规明说）。**若错的影响**：需前端自带语义映射，与唯一真相源分叉。**验证方式**：GWT-1 / GWT-2 的回复态走查；`tests/ui/test_ui_six_states.py` 不改即绿。
