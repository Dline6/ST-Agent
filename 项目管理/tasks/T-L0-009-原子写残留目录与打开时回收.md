# T-L0-009 · 原子写残留目录与打开时回收

## 目标

闭掉 [L0 遗留问题册 E2](../遗留问题/L0-遗留问题.md)：`Store._atomic_write` 的中间产物写在**分区目录内**（`.<名>.tmp-<hex>`），进程被强杀时留下的残留不会被任何路径清理，且大小可达当时待写文件本身（`data_cache` 的 `market.db` opaque blob 可至数十 MB）。本任务把中间产物移到存储根下的**专属临时目录** `root/.st-agent-tmp/`，并在 `Store.open` 时**整体回收**——回收对象是专属目录，无需文件名模式匹配，不可能误删用户数据；分区目录随此保持「只有清单 + 数据文件」。

## 验收标准（Given-When-Then）

- GWT-1 崩溃残留被回收：Given 既有存储的临时目录内留有中间产物（模拟进程被强杀），When `Store.open`，Then 临时目录被清空，分区数据逐字节完整、`partition_state` 为 `ok`。
- GWT-2 中间产物不落分区目录：Given 一次正常写入，When 检视分区目录与临时目录，Then 分区目录内只有清单与数据文件、临时目录写完后为空。
- GWT-3 回收不碰数据面：Given 残留文件含任意字节（半截密文），When 回收后重开，Then 七分区校验 `clean`、`list_files` 口径与既有文件内容均不变。
- GWT-4 旧存储兼容（无临时目录）：Given 临时目录缺失的既有存储（T-L0-008 形态创建，或目录被手工删除），When `Store.open`，Then 自动补建并正常可用，不因缺目录而失败。
- GWT-5 完全清空覆盖临时目录：Given 存储含残留，When `wipe_all`，Then 存储根整目录连同临时目录一并移除（既有 `shutil.rmtree(root)` 路径，不新增代码）。

## 接口面

- 输入（消费的前置接口）：
  - T-L0-008 [`store.py`](../../src/st_agent/l0/storage/store.py)：`_atomic_write`（中间产物当前落在**分区目录内**）、`Store.create` / `Store.open` / `_unlock`
  - T-L0-006 [`backup.py`](../../src/st_agent/l0/backup/backup.py)：`wipe_all`（`shutil.rmtree(root)`，须覆盖临时目录）
  - [02 §2.4](../../docs/技术架构-v2/02-L0-本地优先基座.md) 落盘原子性条款（本任务为其补「残留须回收」）
  - 既有消费方（`EgressGateway` / `McpHubStateMachine` / `SkillRegistry` / `CredentialVault` / `MarketDb`）**调用面不改**
- 输出（本任务交付的公共 API / 落盘位置）：
  - `Store` 全部公共方法**签名不变**；私有 `_atomic_write` 由静态方法改为实例方法（寻址到实例的临时目录）
  - 模块级新增 `TMP_DIR_NAME = ".st-agent-tmp"`（临时目录名，供落盘与测试引用）
  - 物理布局新增 `root/.st-agent-tmp/`；`Store.open` 负责补建 + 整体回收
  - [`tests/l0/test_store_concurrency.py`](../../tests/l0/test_store_concurrency.py) 追加 GWT-1..5 用例（该文件即 02 §2.4 的契约测试，docstring 同步声明范围）

## 假设与前提

- A1 崩溃残留只可能落在**临时目录**内（`_atomic_write` 是唯一写临时文件的路径），故整目录回收不会触及数据面 / 若错（另有路径往该目录写非临时内容）：须改为按模式回收并同步挑明 / 验证：全仓 `TMP_DIR_NAME` 引用仅 `_atomic_write` / `create` / `open` 三处；GWT-3 回收后逐字节一致。
- A2 临时文件只含**密文**（`seal_bytes` 先于 `_atomic_write`），故残留回收不涉明文数据主权 / 若错（明文落临时目录）：违反铁律 1 / 验证：GWT-3 用例 + 收工前「盘上明文 0 命中」复核（沿用既有口径）。
- A3 回收时机取 `Store.open`——E2 描述的正是「跨进程重启才会产生的残留」，与 open 时机对位；`create` 面向全新目录无需回收 / 若错（长驻进程长期不重开、残留持续占盘）：须加运行期或定时回收 / 验证：GWT-1 / GWT-2 / GWT-4。
- A4 临时目录置于**存储根下**而非系统临时目录——`os.replace` 须同卷才原子 / 若错（跨卷）：原子性失效、退化为复制 + 删除 / 验证：GWT-2 + 既有 8 条并发/原子用例全绿。
- A5 存储根多出一个目录不影响既有消费方：全仓无任何按目录遍历 root 的代码（`iterdir`/`os.walk`/`listdir`/`rglob` 均 0 命中，已核），备份按分区名经 `Store` 取数、`wipe_all` 走 `shutil.rmtree(root)` 一并覆盖 / 若错：备份 / 清空 / 校验面需适配 / 验证：GWT-5 + 全量用例（含 `test_backup.py`）绿。
- A6 公共 API 签名零变更、02 §2.4 只补一句「残留须在下次打开时回收」→ 不触发工作流 ⑦ 的跨层契约链 / 若错（实为跨层契约变更）：须按契约优先序回改 01 与各层 / 验证：`git diff --name-only` 无其他层代码改动。
