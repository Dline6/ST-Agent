# T-UI-009.2 · 记忆区持仓行情读面

> [`T-UI-009`](T-UI-009-记忆区持仓行情读面.md) 的**第二叶**，也是那两条视觉基线的**真实消费方**：`--up` / `--down` / `--flat` 与 `--font-num` 到这里第一次被生产面上的读面用上。

## 目标

在记忆区落一条持仓 / 关注行情读面：**持仓与关注取自 L2 记忆**（`attention` 节点的 `holdings` / `watchlist`），**行情取自 L0 最新日线**（`v_k_line_latest`），以 [`T-UI-009.1`](T-UI-009.1-表格槽词汇与数字涨跌渲染原语.md) 定下的表格词汇呈现——涨跌列走三路冗余编码，数字列右对齐等宽。

三件交付：

1. **第四个鸭子端口 `memory`**——沿用 `chat` / `reflection` / `eco` 的同形（[`build_ui`](../../src/st_agent/ui/app.py) 注入，缺省 `None` ⇒ 该面 fail-closed）；`ui` 仍**不 import** `l2` / `l3` / `app`。
2. **读面端点** `GET /api/memory/holdings`——出 `table` 描述，走**同一条**出站路径（必填槽 + 中性化门）。
3. **`/memory` 页面**——记忆区的**首个读面**（IA 补章与本批的其余记忆区读面归 M6 后续叶）。

## 验收标准（Given-When-Then）

- GWT-1：Given 记忆里有持仓 / 关注、L0 缓存有对应最新日线，When 取该端点，Then 出一份 `table` 描述（代码 / 名称 / 收盘 / 涨跌幅 / 换手率），涨跌幅列 `kind: "direction"`、换手率与收盘列 `kind: "number"`，且数值与 L0 视图**逐行一致**
- GWT-2：Given 上述，When 浏览器打开 `/memory`，Then 持仓与关注两张表**非空渲染**（表头与单元格都有内容），涨跌幅列出 ▲▼ + 带符号数值 + 方向色，导航含该项
- GWT-3：Given **无记忆** / **行情源未注入** / **持仓在缓存中无日线**，When 取该端点，Then 依次为 `empty`（带原因）/ `unavailable`（带原因并点名装配归属）/ 该行显「无数据」——**三种互不冒充**，且**不**把「无行情」说成「无持仓」
- GWT-4：Given 未注入 `memory` 端口，When 取该端点，Then 回 `unavailable` 并点名（**不**回一张空表冒充「你没有持仓」）
- GWT-5：Given `ui` 侧既有的「只经鸭子端口消费、不 import 各层」约束，When 加上第四个端口，Then `test_ui_is_client_only` 与 `tests/test_layering.py` **不改即绿**

## 接口面

- **输入**（消费的前置接口）：
  - L2 记忆读者 `MemoryReader`（[`l2/memory/reader.py`](../../src/st_agent/l2/memory/reader.py)；`SliceQuery(view="list")` → `AttentionNode.holdings` / `.watchlist`）——上游 [`T-L2-001.1`](done/M1/T-L2-001.1-记忆图谱本体节点边模型与落盘.md) 已交付。
  - L0 行情：鸭子类型 `market_query`（`MarketDb.query`，[`l0/market/db.py`](../../src/st_agent/l0/market/db.py)）查 `v_k_line_latest`（`code` / `trade_date` / `close` / `pct_chg` / `turn`）+ `security`（`code_name`）——上游 L0 线已交付；**注入为可选**（`build_m5_runtime(market_query=None)` 时不注入）。
  - [`T-UI-009.1`](T-UI-009.1-表格槽词汇与数字涨跌渲染原语.md) 的表格槽形状（列 `{key,label,kind}` / 行键控对象）与 `ui/tables.py` 漏斗——上游未交付时本叶不可开工（`depends_on` 已锁）。
  - [`ui/registry.py`](../../src/st_agent/ui/registry.py) 的 `REQUIRED_SLOTS["table"]`——本叶不改。
- **输出**（本任务交付的公共 API / 落盘位置）：
  - `src/st_agent/app.py`（组合根）——装配 memory 面（读 L2 持仓 / 关注 + 依 `market_query` 取最新日线），与既有 `reflection` / `eco` 面同形。
  - [`ui/app.py`](../../src/st_agent/ui/app.py)——`UiApp.memory` 端口 + `api_memory_holdings()`；`PAGE_PATHS` 增 `/memory`。
  - [`ui/server.py`](../../src/st_agent/ui/server.py)——`_GET_ROUTES` 增 `/api/memory/holdings`；`serve(..., memory=…)`。
  - [`__main__.py`](../../src/st_agent/__main__.py)——生产入口注入该端口。
  - `src/st_agent/ui/web/js/pages/memory.js`（新）+ [`pages.js`](../../src/st_agent/ui/web/js/pages.js) 登记一条。
  - 测试：`tests/ui/test_ui_memory.py`（新，端点与六态）+ `tests/integration/` 一条跨层装配（真记忆 + 真行情视图 → 真描述）。
- **降级路径**：`market_query` 未注入 ⇒ 该面走 `unavailable` 并点名「行情源未注入」，**不**退化成「只有代码没有行情」的半表（那是另一件事，会让人以为行情就是空）；某标的在缓存里无日线 ⇒ 该行行情列显中性「无数据」，**不**静默留白、**不**当 0。

## 假设与前提

- **A1 · 行情取数由组合根经既有鸭子类型读 L0，不新增 L1 Skill**（2026-10-09 ④ 对齐前选定，[D-105](../决策日志.md) ③）：前提是「取数只有一条通道」那条约束的对象是 **L1 执行器**（[`common.py`](../../src/st_agent/l1/skills/official/common.py) 的「执行器要行情 / 财务 / 板块数据时一律经 `query_rows`」），组合根装配面本就直持 `market_query`（`MarketDimensionCatalog` 即此先例）。若错（组合根也不得直读行情）→ 返工面＝补一个 L1 行情快照 Skill 并改装配，读面与页面不返工。**验证方式**：`tests/test_layering.py` 绿 + `tests/integration` 的真装配用例。
- **A2 · 端口取名 `memory`**：前提是与既有三端口（`chat` / `reflection` / `eco`）同粒度——一端口一「面」。若错（M6 底座 / 骨架叶的端口划分另有取法，如按 IA 分区拆）→ 返工面＝端口改名与注入点调整（读面与页面不返工）。**验证方式**：M6 底座叶开工时复核；本叶在备注留痕点名。
- **A3 · `/memory` 作为记忆区首个读面不改 IA**：前提是 [11-sitemap §2](../../docs/PRD-v2-Agent/11-sitemap.md) 记忆区本就含「图谱视图 / 列表视图 / 时间线视图」三种组织——本叶落的是**列表视图**下的第一块内容。若错（补章后记忆区的页集不含本读面）→ 返工面＝页面归属调整。**验证方式**：`T-UI-006` 收工后复核（同批次假设 `A1`）。
- **A4 · 行情列取「收盘 / 涨跌幅 / 换手率」**：前提是这三项在 `v_k_line_latest` 里齐备且是持仓 / 关注面上最直接关心的三项（[`ambient.py`](../../src/st_agent/l1/skills/official/ambient.py) 的盯盘口径同样锚在 `pct_chg` 与 `turn` 上）。若错（列集不合用）→ 返工面＝只改列清单（漏斗与渲染件不返工）。**验证方式**：GWT-1 的逐行一致断言。
- **A5 · 名称取自 `security.code_name`**：前提是该表在本地缓存里有行；缺行时**只**退「名称」一列为「无数据」，不影响其余列与涨跌编码。**验证方式**：GWT-1 与 GWT-3 的两条分支用例。
