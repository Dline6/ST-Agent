# T-L1-003.4 · 编辑面（画布 mutation + 草稿落画布）

## 目标

落地 03 §4 的双通道之一与画布编辑面：**可视化画布编辑**的增量操作 API（增删节点、连线、分组）与**连线时的即时契约提示**；以及**对话式生成**的接收面——把 [05-L3 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 的工作流草稿对象落到画布，供用户**接受 / 微调 / 拒绝**（01 §7 配置注册表口径，接受即产生 `change_id`）。

> 本阶段交付**后端编辑面 API**；画布渲染与交互 UI 归 L3 Generative UI 或后续前端任务（仓库无前端）。

## 验收标准（Given-When-Then）

- GWT-1 画布 mutation：Given 一份工作流草稿，When 增/删节点、连线/断线、分组/解组，Then 每次操作的结果可由 `WorkflowDAG` 读回，且操作后**自动跑一次校验**（成环 / 连线契约 / 命名），校验结论随操作一并返回。
- GWT-2 连线即时契约提示：Given 节点 A 的输出与节点 B 的输入声明不匹配，When 建立 A→B 连线，Then 返回「这里需要一个 XX 类型的输入」式提示且**该连线不生效**（画布状态不变）；匹配时连线生效。
- GWT-3 草稿落画布：Given L3 传入工作流草稿对象（对话式生成），When Studio 接收，Then 产出可编辑的 `WorkflowDAG` 草稿（节点 / 连线 / 参数齐备）并**先过一遍校验**（不合规的草稿同样可落，但须带回违规清单供用户看）。
- GWT-4 接受 / 微调 / 拒绝：Given 一份草稿，When **接受**，Then 落盘为 v1.0 并产生 `change_id`；When **微调**，Then 返回可继续编辑的编辑面句柄；When **拒绝**，Then 丢弃且可选记录原因。
- GWT-5 成环即时阻止：Given 一条会导致成环的连线，When 建立该连线，Then 拒绝并指出环路径（编辑期即拦，不必等到保存）。

## 接口面

- 输入（消费的前置接口）：
  - `T-L1-003.1` 的 `st_agent.l1.workflow` 包：`WorkflowDAG` / `validate` / `WorkflowStore.save`、[`schema_check.check_link`](../../src/st_agent/contracts/schema_check.py)
  - T-SC-001.4 [`registry_types.py`](../../src/st_agent/contracts/registry_types.py)：`ConfigEntry`（`scope=workflow`）/ `ChangePolicy` / `ChangeRecord`（接受的落痕形态）
  - [05-L3 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 工作流草稿对象 —— L3 尚未交付（`T-L3-003`），**本任务定义接收契约**（`target` / `parameter_draft` / `understanding_summary` / `open_questions` 四字段在「target=工作流」下的落画布映射）
- 输出（本任务交付的公共 API / 落盘位置）：
  - `st_agent.l1.studio.canvas`：`CanvasEditor`（`add_node` / `remove_node` / `connect` / `disconnect` / `group` / `ungroup` / `validate_current`）——每次写操作返回 `EditResult`（新 DAG 视图 + 校验结论 + 人类可读提示）
  - `st_agent.l1.studio.draft`：`WorkflowDraft`（接收契约，字段对齐 05-L3 §5）+ `DraftIntake.accept` / `.tune` / `.reject`（接受 → `WorkflowStore.save` + `ChangeRecord`）
  - 落盘：草稿态不落盘（内存编辑会话）；**接受**时落 `config` 分区 `workflow/<flow_id>.json`；`change_id` 随落痕（`ChangeRecord` 形态）登记
  - 消费方：`T-L1-003.5`（模板 fork 后进入编辑面）、`T-L3-003`（产出草稿对象）、`T-L3-004`（渲染编辑面与提示）

## 假设与前提

- A1 编辑面是**内存会话 + 增量操作**（`CanvasEditor` 持有草稿态，写操作返回新视图），草稿态不落盘——「保存」才落盘（与 story-06「编辑中 / 保存成功」状态划分一致）/ 若错（需草稿自动持久化以防丢失）：须加草稿分区与恢复语义 / 验证：GWT-1 / GWT-4。
- A2 连线即时校验**复用同一判定件** `check_link`（[01 §2](../../docs/技术架构-v2/01-平台共享契约.md) 明令唯一口径），编辑期（连线时）与保存期（整图校验）是**同一判定件的两次调用**，不是两套逻辑 / 若错（编辑期需更宽松的暂存语义，如允许「先连后补 schema」）：须引入显式的「待补」占位态 / 验证：GWT-2 / GWT-5 与 `.1` 的保存期用例共用断言。
- A3 草稿对象由**本任务定义接收契约**，因 L3（`T-L3-003`）尚未交付；字段名对齐 05-L3 §5 表述，L3 开工时若需调整须回改本任务（属**向上依赖**的接口先行定义，不是反向调用）/ 若错（L3 设计的草稿形态与之不兼容）：需改本任务的 `WorkflowDraft` 并对齐 05 §5 / 验证：本任务用例 + L3 开工时核对。
- A4 「接受」产生 `change_id` 并登记 `ChangeRecord`（01 §7），复用配置注册表的变更留痕机制，不新造 / 若错（工作流不接受配置注册表口径）：须另立变更机制并回改 01 §7 / 验证：GWT-4 断言 `change_id` 与变更记录。
- A5 「拒绝」的原因记录为**可选**（story-06 空状态与反馈池归 L6；本任务只透传，不建反馈存储）/ 若错（须在 L1 落反馈）：须改由 `T-L6-001` 承载 / 验证：GWT-4 拒绝分支不落盘。
