# T-UI-037.2 · 自主查证预算上界建议化

## 目标

把 `investigate.max_steps` / `investigate.max_llm_calls` / `investigate.context_budget` 的防跑飞上限
从**硬拒绝**改为**建议值**：只校验整数 ≥ 1，超过建议上限仍可保存并生效。

## 验收标准（Given-When-Then）

- **GWT-1 · 超出建议值可保存**：Given 当前值为 8，When 设置 `max_steps = 100`，Then 落值成功、读回 100、下次循环生效。
- **GWT-2 · 下界仍拒绝**：Given 输入 `0` / 非整数，When 落值，Then `validation_failed`，原值不变。
- **GWT-3 · 既有超限值可读**：Given 盘上已有超过建议上限的值，When 读面 / 循环读取，Then 不抛错、原样使用。
- **GWT-4 · 页面标为建议范围**：Given 打开运行期授权页，Then 预算条目提示为「建议 1–N，可超出」，不再显示为硬性取值范围。

## 接口面

**输入**

- `LoopBounds` 与三条目（[`l3/runtime/bounds.py`](../../../../src/st_agent/l3/runtime/bounds.py)）。
- 预算面板条目的 `note` 装配（[`ui/surfaces/settings/shared.py`](../../../../src/st_agent/ui/surfaces/settings/shared.py) `_budget_entries`）。

**输出**

- `_check` 只校验整数 ≥ 1；`value_schema` 去掉 `maximum`；建议上限保留为文案常量。
- [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 与 [05 §10](../../../../docs/技术架构-v2/05-L3-对话主入口.md) 的「带防跑飞上限」措辞改为「建议上限」。

## 可关闭的遗留

无。

## 假设与前提

- **A1 · 上限只作建议、不保留任何硬上限**（2026-11-02 负责人要求）：输入极大值由用户自担模型窗口 / 费用的后果。
  **若错的影响**：若仍要求安全护栏，需恢复一个显式可配的硬上限条目。
  **验证方式**：GWT-1 的 100 / 1000 用例。
- **A2 · 不建议值不改前端渲染形态**：仍用自由文本输入，仅改提示与校验。
  **验证方式**：GWT-4 的 `note` 断言。
