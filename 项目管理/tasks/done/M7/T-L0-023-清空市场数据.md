# T-L0-023 · 清空市场数据（一级清库）

## 目标

在现有「完全清空」之外增加一级「清空市场数据」：只删市场/信息数据与水位，保留用户记忆、配置、聊天等分区，使重新同步成本低且不误伤个人数据。

## 验收标准（Given-When-Then）

- GWT-1 删除范围：Given 本地已有市场库与公告/问答正文，When 执行一级清库，Then `data_cache/market.db` 与 `data_cache/info/**` 全部删除，`sync_state` 随库消失；其他分区与其他 `data_cache` 文件不动。
- GWT-2 保留范围：Given 记忆、配置、聊天、执行日志、反思、凭据分区有数据，When 一级清库，Then 这些分区逐字节不变；备份归档（存储根之外）不被触碰。
- GWT-3 单飞：Given 同步批次运行中，When 请求一级清库，Then 显式拒绝并提示先停止/等待，不产生半删状态。
- GWT-4 可重建：Given 一级清库完成，When 再次同步，Then `setup()` 能重新建库并写入种子行，总览从「未建库」进入正常态。
- GWT-5 结果留痕：Given 清库完成，When 读返回，Then 列出删除的文件数与保留的分区名；正文缓存不可恢复一事由 UI 明示。

## 接口面

- 输入：
  - `Store.delete(partition, name)` / `Store.list_files(partition)`；`MarketDb.exists()`。
  - `DataSyncRunner` 的单飞状态与 `job()`。
- 输出：
  - `DataSyncRunner.clear_market()`（或等价公开方法）：删除 `market.db` 与 `data_cache/info/` 前缀文件，重置内存批次，返回删除/保留清单。
  - `ui/app.py` + `server.py` 的 `POST /api/settings/data/clear` 由 `T-UI-029.2` 接线。
  - `tests/l0/test_sync_clear.py`（或并入 runner 用例）。

## 可关闭的遗留

- 无归属本任务的既有条目。完全清空（二级）继续沿用备份面既有口径，不在本任务改写。

## 假设与前提

- A1 一级清库使用 `Store.delete` 逐个删除 `market.db` 与 `info/` 文件，不用 `wipe_partition("data_cache")`——后者会连带删除未来可能存在的非市场 Skill 缓存。若错：可能多删未来缓存。验证：保留其他 `data_cache` 文件的用例。
- A2 公告/问答正文属于市场/信息数据，一级清库一并删除；不可恢复。若错：用户若只想清行情，需另做更细粒度选项（本期不做）。验证：对话框影响清单。
- A3 清库不触碰 `secrets` 分区；因此重新同步时凭据仍在。若错：用户需重新录入凭据，属体验回归。
- A4 清库后本进程无需重启；`MarketDb.exists()` 为清单口径，下一次 `setup()` 自动建库。若错：需加重启闸门。验证：清库后同步用例。
