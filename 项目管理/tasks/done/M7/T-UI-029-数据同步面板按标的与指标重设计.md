# T-UI-029 · 数据同步面板按标的与指标重设计

## 目标

把设置-数据同步页从「数据集优先 + 全局范围/日期」改为「标的折叠分组 → 数据集 → 指标组 + 时间」，并接入细粒度进度与两级清库。

## 验收标准（Given-When-Then）

- GWT-1 标的组织：Given 打开数据同步页，When 浏览，Then 全部 A 股 / ST / 沪深300 / 上证50 / 中证500 / 关注池 / 自定义代码 / 其他各自成组，显示数量与来源时间；不可用标的显式说明原因。
- GWT-2 单独可选：Given 展开任一标的，When 勾选数据集，Then 只提交该组合；同一数据集可在多个标的下分别配置指标组与时间。
- GWT-3 显式忽略：Given 选了不适用标的/指标/时间的任务，When 预检，Then 在预检与结果中逐项点名，不静默套用。
- GWT-4 进度与清库：Given 运行中，When 查看进度卡，Then 显示组/码/请求/行/ETA；Given 触发清库，Then 一级需输入确认词、二级需三令牌。
- GWT-5 可访问性：Given 纯键盘操作，When 展开分组、勾选数据集、切换指标、提交，Then 全部可达；破坏性对话框有焦点陷阱与确认词。

## 接口面

- 输入：
  - `T-L0-019`～`T-L0-023` 的标的/数据集/覆盖/进度/清库 API。
  - 现有 `settings.js` 的 `field` / `openDialog` / `collapsible` / `renderPart` 与 `.settings-*` CSS。
- 输出：
  - `src/st_agent/ui/data_catalog.py` 的 `targets[]` / `datasets[]` / `groups[]` 载荷与 `validate_catalog`。
  - `GET /api/settings/data`、`POST /preflight`、`POST /sync`、`GET /job`、`POST /clear` 的前端消费与路由白名单。
  - 叶子任务：`.1` 目录/面板，`.2` 进度/清库。

## 可关闭的遗留

- 无归属本任务的既有条目。D-130 的「按数据项目录 + 全局范围」UI 由本任务改写，已记 D-132。

## 假设与前提

- A1 面板状态（展开组、勾选、指标、时间）只需会话内保存，不跨重启持久化。若错：需要新增偏好存储。
- A2 自定义代码文件导入在浏览器端读文本后随请求发送，不新增二进制上传端点。若错：大文件/编码问题需另做上传面。
- A3 目录载荷是唯一展示词表，前端不另抄任务键/中文名。若错：新增任务要改两处。验证：`validate_catalog` 与前端纯函数用例。
- A4 一级清库只清市场数据，不影响本进程其他面；成功后刷新当前页即可，不需重启。若错：需加重启闸门。
