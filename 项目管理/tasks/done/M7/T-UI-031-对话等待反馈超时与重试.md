# T-UI-031 · 对话等待反馈、请求超时与重试

## 目标

对话提交后立即给出中性等待态，请求具备超时、失败显式化与重试入口，并防止等待期间重复提交产生第二个会话。

## 验收标准（Given-When-Then）

- GWT-1 立即反馈：Given 用户在右栏提交一条消息，When 请求尚未返回，Then 对话流出现中性等待轮（忙碌标记，`aria-live` 可播报），发送键与输入框置为不可用，用户消息仍保留。
- GWT-2 失败与重试：Given 请求超时或网络失败，When 等待结束，Then 等待轮替换为显式失败态并附「重试」；点击重试重发同一文本，沿用同一会话。
- GWT-3 正常返回：Given 请求返回回复，When 渲染完成，Then 等待轮移除，回复按既有渲染路径入流，发送键与输入框恢复可用。
- GWT-4 防重复：Given 等待轮仍在，When 用户再次提交或被触发提交，Then 不产生第二条请求，也不新建第二个会话。
- GWT-5 确认卡忙碌：Given 用户点击「确认并执行」，When 派发请求进行中，Then 按钮置忙并显示中性执行中文案，期间不可重复点击；失败时恢复按钮并显式报错。

## 接口面

- 输入（消费的前置接口）：
  - 既有 `POST /api/chat`（`ui/app.py` 的 `api_chat`）：`action=post` / `action=dispatch`。
  - 既有 `chat.js` 的 `chatRequest` / `appendReply` / `confirmationNode`。
  - 既有 `busy.js` 的忙碌分级口径（14 册 §8.4）。
- 输出（本任务交付的公共 API / 落盘位置）：
  - `src/st_agent/ui/web/js/api.js`：`postJson` 增加可选超时（`AbortController`），默认不改变既有调用。
  - `src/st_agent/ui/web/js/pages/chat.js`：等待轮、提交锁、超时与重试、确认卡忙碌态；等待轮与失败态的 CSS 落 `app.css`。
  - 无新增后端端点、无新增落盘。

## 可关闭的遗留

无（已扫各遗留册未闭区，无归属本任务的条目）。

## 假设与前提

- A1 前端超时取 120 秒（大于 LLM 端点缺省 60 秒）；只有整体请求超过该值才判超时。若错：长回答被误判为失败，可调大但不得小于端点缺省。
- A2 超时只中止客户端等待，服务端可能已完成；重试会重发同一文本，极端情况下同一提问在会话内出现两条用户消息。鉴于服务端 LLM 调用有 60 秒上界，此情形概率极低；本任务不做幂等键（需改后端契约）。验证：读代码 + 超时走查。
- A3 等待轮文案为中性「正在处理…」，不含第一人称或拟人化措辞（铁律 2）。验证：走查 + 既有中性化用例。
