# T-UI-028.5 · 数据同步目录与页面重构（P0）

## 目标

- 把「直接展示任务键 / 裸表名」改成**中文数据项目录**：9 个中文大类 → 数据项（中文名 + 一句话说明 + 目标表 + 底层任务）。
- 主源默认显示，备源与默认关闭项收进「高级」；「全选」只选可见主源。
- 每项显示目标表、行数、最近同步、水位/数据截止、状态；失败项直接显示 `last_error`。
- 页面重排为「总览 → 同步控制 → 可选目录 → 本机数据明细（折叠）」，去掉重复标题与原始「状态：ok」。

## 验收标准（Given-When-Then）

- GWT-1：Given 打开 `/settings?view=data`，Then 31 个同步任务全部落在中文大类下，主标签为中文名与一句话说明，不再以 `bs_*` / `info_*` 作为主标签。
- GWT-2：Given 任一数据项，Then 可见目标表、行数、最近同步、状态；`sync_state.last_error` 非空时直接显示原因。
- GWT-3：Given「高级」开关关闭，Then 备源与默认关闭项不出现；打开后出现。「全选 / 同步全部」永不选中隐藏项、备源与默认关闭项。
- GWT-4：Given 一次批次结束并重绘，Then 先前的勾选保留；页面不再出现重复的「手动同步」标题或原始「状态：ok」行，「最后成功」为本地时间格式。
- GWT-5：Given 页面滚动，Then 同步控制位于总览之后、明细表之前；明细表折叠在「本机数据明细」内。

## 接口面

- 输入：
  - [`T-UI-028.4`](T-UI-028.4-手动同步与后台任务.md) 的 `DataSyncRunner.overview()`：`tasks` 行已含 `task_key` / `domain` / `tables` / `mode` / `schedule` / `coverage` / `role` / `needs` / `default_disabled` / `status` / `watermark` / `last_success_at` / `last_error` / `table_rows`。
  - L0 任务注册表：`st_agent.l0.market.tasks.SYNC_TASKS`、`st_agent.l0.info.sources.INFO_TASKS`。
  - `MarketDb.sync_state_rows()` / `MarketDb.table_counts()`。
- 输出：
  - 新增 `src/st_agent/ui/data_catalog.py`：中文大类顺序、逐任务中文名 / 说明 / 高级标记、逐表中文名 / 说明；**唯一**展示词表（服务端表格与前端目录共用，前端经 `tasks` / `tables` 的 `values` 消费，不另抄一份）。
  - `UiApp._data_parts` 的 `tasks` values 增加 `item_id` / `item_display_name` / `category` / `category_order` / `display_name` / `description` / `advanced` / `per_code` / `supports_range` / `window_desc` / `source_id` / `role` / `coverage` / `schedule` / `mode` / `default_disabled`；`tables` 行增加 `display_name` / `description`。
  - `src/st_agent/ui/web/js/pages/settings.js` 的目录装配与选择保持；`src/st_agent/ui/web/css/app.css` 的目录样式。
  - `GET /api/settings/data` 路径与四段形态不变。

## 可关闭的遗留

无（逐册查未闭区：L0/L1/L2/L3/L5/L6 均无归属本任务的条目；L0 未闭仅 `C3` / `C5` 为人决，`D1`–`D3` 为人决）。

## 假设与前提

- A1：展示目录归 UI 层（`ui/data_catalog.py`），L0 只给任务键与能力位。若错：中文标签需下沉 L0，破坏「层间只向下依赖」与展示/事实分层。验证方式＝layering 测试 + 目录完整性测试。
- A2：一张表可由多条任务写入（公告 3 主备、`security` 2 任务、`index_constituent` 3 任务），目录项按「主源任务集」聚合，备源单独成项并默认隐藏。若错：同一数据项重复出现或漏表。验证方式＝目录完整性测试断言每个 `task_key` 恰属一个目录项（可见项或高级项）。
- A3：`overview()` 的 `tasks` 行已含 `last_error`，无需改 L0 取数面。若错：需补 L0 字段并同步接口面。验证方式＝UI 契约测试断言 `last_error` 随 `tasks` values 下发并可渲染。
- A4：高级项默认隐藏只影响默认勾选集，不削减同步能力。若错：用户找不到备源。验证方式＝高级开关用例与「全选」集合断言。
