# T-L0-019 · 同步标的注册表与 ST 名单任务（方案 B）

## 目标

把同步的证券范围从三个全局 scope 改为可扩展的标的注册表，并用 `query_stock_basic(code_name="ST")`（方案 B）建立 ST 同步标的池；分析区 `v_st_universe` 保持日线 `is_st` 口径不变。

## 验收标准（Given-When-Then）

- GWT-1 标的解析：Given 选择全部 A 股 / ST / 沪深300 / 上证50 / 中证500 / 关注池 / 自定义代码，When 预检，Then 各自解析出代码集、数量、来源时间与可用原因；空池与不可用分开呈现，不合并。
- GWT-2 ST 名单：Given 源端返回 314 条含退市/`*ST` 的记录，When 执行 `bs_st_list`，Then 只保留 `type=1 & status=1` 且名称前缀为 `ST`/`*ST`/`SST`/`S*ST` 的行，原子替换 `st_membership`，并把保留码 UPSERT 进 `security`。
- GWT-3 两套口径：Given 同时查分析池与同步池，When 日线 `is_st` 与名称名单不一致，Then `v_st_universe` 与 `v_st_sync_pool` 各自返回自己的结果，互不覆盖；UI 载荷分别带 `as_of` / `captured_at`。
- GWT-4 自定义代码：Given 粘贴/文件导入混合格式（`sh.600000`、`000001`、重复、非法行），When 解析，Then 返回 `codes / invalid / duplicates`，非法行显式列出，不静默丢弃。
- GWT-5 旧库升级：Given 缺 `st_membership` / `v_st_sync_pool` 的旧库，When `ensure_schema()`，Then 新对象补齐、业务行不变；ST 名单为空时按「未刷新」而非「无 ST」呈现。

## 接口面

- 输入（消费的前置接口）：
  - `src/st_agent/l0/market/fetch.py` 的 `Fetcher` 协议与 `map_security_basic`；`live.py` 的 `BaoStockFetcher`。
  - `src/st_agent/l0/market/db.py` 的 `MarketDb` 只读/事务入口；`schema.sql`。
  - 关注池注入：`DataSyncRunner` 既有 `watchlist` callable。
- 输出（本任务交付的公共 API / 落盘位置）：
  - 新增 `src/st_agent/l0/market/targets.py`：`TargetSpec`、`resolve_target(target_id, ...)`、七类标的解析。
  - 新增 `src/st_agent/l0/market/codes.py`：`parse_custom_codes(text)`。
  - `tasks.py` 新增 `bs_st_list`（第 21 个任务）；`sync.py` 新增 `_load_st_list`；`live.py` 新增 `st_basic()`。
  - `schema.sql` 新增 `st_membership` / `v_st_sync_pool`；`db.py` 新增 `ensure_schema()` / `st_sync_pool()`。

## 可关闭的遗留

- 逐册扫未闭区：无归属本任务的既有条目。L0 `C5`（全市场码表首次全量未跑）不因本任务关闭，仍待人决。

## 假设与前提

- A1 `query_stock_basic(code_name="ST")` 的模糊匹配覆盖 `*ST` / `SST` / `S*ST`（2026-10-26 真网实测 314 条含 `*ST`）。若错：回退为按四个前缀分别查询并去重，请求数由 1 增至 4。
- A2 ST 名单是**抓取时点快照**，不承载日线级 ST 历史。若错：需要另建逐日成员表，超出本期。验证：`v_st_universe` 的 §9 历史查询保持不变。
- A3 指数标的依赖本地 `index_constituent` 最新一期；同步时不实时拉成员。若错：成员变更要等下一次成分快照。验证：预检显示 `as_of` 并在过旧时警告。
- A4 自定义代码允许本地主档未登记的合法格式代码，抓取时由源端返回空或错误。若错：预检需改为强制本地存在；本期先给警告。
