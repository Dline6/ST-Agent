# T-UI-029.2 · 细粒度进度与两级清库对话框

## 目标

在同步面板接入逐组/逐码进度与 ETA，并交付一级「清空市场数据」与二级「完全清空」的破坏性确认流程。

## 验收标准（Given-When-Then）

- GWT-1 进度卡：Given 批次运行中，When 轮询 job，Then 显示总体/逐组进度、当前数据集与码、X/Y、请求数、行数、ETA；完成后保留结果表；被跳过码不计为失败。
- GWT-2 一级清库：Given 打开清库对话框，When 输入“清除市场数据”，Then 调用 `/api/settings/data/clear` 一级，删除市场数据并刷新页面；影响清单列明删除/保留项与正文不可恢复。
- GWT-3 二级清库：Given 触发完全清空，When 依次集齐三枚令牌，Then 沿用现有重启闸门；运行中批次时两级清库都被拒绝并提示先停止。
- GWT-4 路由与失败：Given 端点不可用/未授权/批次运行中，When 操作，Then 显式错误，不静默成功；路由白名单与 fail-closed 用例通过。
- GWT-5 可访问性：Given 纯键盘，When 打开/关闭清库对话框，Then 焦点被困、Esc 关闭、焦点归还；进度用 `aria-live` 播报关键变化。

## 接口面

- 输入：
  - `T-L0-022` 的 job `progress`；`T-L0-023` 的 `clear_market()`。
  - 现有 `openDialog`（`scope` / `requirePhrase` / `destructive`）与 `settings.js` 的 `renderJob` / `pollJob`。
- 输出：
  - `ui/app.py` + `server.py` 的 `POST /api/settings/data/clear` 与路由白名单。
  - `settings.js` 的 `renderProgress` / `clearMarketDialog` / `renderDangerZone`；`app.css` 的进度条与危险区样式。
  - `tests/ui` / `tests/integration` 的端点、对话框与运行中拒绝用例。

## 可关闭的遗留

- 无归属本任务的既有条目。现有「完全清空」三令牌流程保留，仅接上运行中拒绝。

## 假设与前提

- A1 一级清库成功后不需要重启；页面刷新即可重新读总览。若错：需加重启闸门并提示。
- A2 进度轮询继续走轻量 job 端点，不读表行数。若错：轮询会重新引入整库解密。
- A3 进度 ETA 只是估算，UI 在样本不足时显示“估算中”，不承诺精确。若错：用户误读为 SLA。
- A4 清库对话框的确认词由服务端校验，前端只做体验提示。若错：可绕过确认词。验证：端点用例。
