# T-UI-033 · 对话历史页与多会话切换

## 目标

新增 `/chat` 页面：列出全部会话、回放选定会话并可继续对话；右栏提供「新对话 / 历史」入口，窄窗（右栏收起）时仍可完整对话。

## 验收标准（Given-When-Then）

- GWT-1 历史列表：Given 打开 `/chat`，When 数据就绪，Then 列出全部会话（标题、更新时刻、消息数、末条摘要），按更新时间倒序；无会话时显示显式空态与引导。
- GWT-2 回放与继续：Given 点选一个会话，When 右侧回放，Then 用户与助手轮次按原顺序呈现；助手载荷存在时用与右栏**同一条** `renderEnvelope` 回放生成式卡片，旧会话无载荷时只显示文本并标注；输入框可继续该会话。
- GWT-3 两处同流：Given `/chat` 与右栏同时可见，When 在任一处发送消息，Then 两处显示同一条流，活动会话一致。
- GWT-4 多会话切换：Given 右栏头部，When 点击「新对话」，Then 清空当前活动会话，下一条消息创建新会话；点击「历史」进入 `/chat`；选定历史会话后右栏切到该会话。
- GWT-5 窄窗可达：Given 窗口宽度小于 1240（右栏自动收起），When 点击命令栏「对话」入口，Then 进入 `/chat` 并可完整输入与查看历史。

## 接口面

- 输入（消费的前置接口）：
  - `T-L3-008` 的 `GET /api/chat/sessions`、`GET /api/chat/session?id=`，以及助手消息的载荷字段。
  - `T-UI-031` 的提交等待态、超时与重试。
  - `T-UI-032` 的 `navigate()` 与 `pageFor()`。
  - 既有 `renderEnvelope`（`render.js`）与对话流内面渲染（`chat.js`）。
- 输出（本任务交付的公共 API / 落盘位置）：
  - `docs/PRD-v2-Agent/11-sitemap.md` §2 / §2.1 / §2.2：新增「对话历史页」与 `/chat` 路径（Chat 分区的二级项，不改变分区根）。
  - `src/st_agent/ui/app.py` 的 `PAGE_PATHS`：新增 `/chat`。
  - `src/st_agent/ui/web/js/pages.js`：新增 `/chat` 登记（`partition: 'Chat 主界面'`、挂 `render`、`statusPath` 指向既有路由）。
  - 新增 `src/st_agent/ui/web/js/pages/chat_history.js`；`chat.js` 抽出可复用的会话 store 与回放渲染，右栏与历史页共用。
  - `app.css`：历史页双栏与等待轮 / 会话列表样式。
  - `tests/ui/test_ui_shell_routing.py` 等守卫用例同步（路径集 19 → 20）。

## 可关闭的遗留

无（已扫各遗留册未闭区，无归属本任务的条目）。

## 假设与前提

- A1 `/chat` 作为 Chat 分区的**二级项**（左栏 `nav` 二级），不新增一级项；`_declared_partition_roots` 仍取 Chat 分区首行 `/`。若错：左栏一级项集合变化，需同步 nav 守卫与 11 册口径。
- A2 右栏与 `/chat` 共用同一个活动会话与消息流（同一模块级 store），避免两处各自维护状态。若错：两处可能显示不同会话。
- A3 历史回放只在存档载荷存在时渲染卡片；旧会话（无载荷）只回放文本并显式标注「该轮次为历史文本，未保存展示内容」。若错：用户误以为历史缺数据。
- A4 本批不提供重命名 / 删除会话；会话标题由首条用户消息派生，只读展示。
