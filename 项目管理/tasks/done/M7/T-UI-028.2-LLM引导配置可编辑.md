# T-UI-028.2 · LLM 引导配置可编辑（P0）

## 目标

- 设置-LLM 提供方页新增「引导配置」：显示 `base_url` / `model` / `api_key`（掩码），可修改。
- 保存时：写回启动 `.env`（保留注释与其他键）→ 轮换加密凭据 → 更新 `provider → host` → 重建 transport → 立即可用。
- 凭据分区未解锁时，表单内提供凭据口令解锁（新装用户首次配置 Key 不再需要另起进程）。

## 验收标准（Given-When-Then）

- GWT-1：Given 设置-LLM 页，When 打开，Then 三段（引导配置 / 端点 / 凭据）并列，Key 只显示掩码。
- GWT-2：Given 修改三键并保存，When 保存完成，Then `.env` 中三键更新且其他行未改，凭据库版本 +1，transport 已指向新端点。
- GWT-3：Given 凭据分区未解锁，When 表单带凭据口令提交，Then 分区解锁并完成保存；无口令时显式 `unavailable`，不静默失败。
- GWT-4：Given 保存了非法 `base_url`，Then `validation_failed`，`.env` 与凭据均不被改动。

## 接口面

- 输入：
  - [`T-L1-011`](../M1/T-L1-011-LLM端点与会话装配接线.md) 的 `LlmBootstrap` / `_bootstrap_llm_transport` / `_seed_llm_records` / `LLM_ENDPOINT_ID` / `LLM_CREDENTIAL_ID`
  - `EndpointRegistry.replace/register` · `CredentialVault.rotate/add` · `ProviderHostRegistry.update/register` · `Store.unlock_secrets`
- 输出：
  - `st_agent/l0/bootstrap/dotenv.py`：`read_dotenv()` / `write_dotenv()`（原子写、保留非目标行）
  - `LlmClient.set_transport()` 与 `L1Runtime.apply_llm_bootstrap(config)`
  - `SettingsFacade.llm_runtime` / `dotenv_path`；`UiApp.api_settings_llm_bootstrap`；`POST /api/settings/llm/bootstrap`
  - `src/st_agent/ui/web/js/pages/settings.js` 的 LLM 页 chrome

## 可关闭的遗留

无。

## 假设与前提

- A1：`.env` 是**开发 / 自用**引导通道（[`T-L1-011`](../M1/T-L1-011-LLM端点与会话装配接线.md) A1），设置页写它属于同口径；产品的凭据本体仍只落加密凭据库，页面明示「.env 为明文文件」。若错：需改为仅凭据库并调整启动优先级。
- A2：`_seed_llm_records` 的「端点已存在即整组跳过」不改；换 Key 由本次 `vault.rotate` 承担，故重启后也不会回退旧 Key。若错：重启后 Key 回退。验证方式＝保存后重启，断言调用仍用新 Key。
- A3：`base_url` / `model` 只存在于启动装配的 `OpenAiRoute`，端点记录不承载它们——热更新必须重建 transport 并替换 `LlmClient` 的传输件。若错：保存后仍走旧端点。验证方式＝以替身 transport 断言替换前的调用走旧、替换后走新。
