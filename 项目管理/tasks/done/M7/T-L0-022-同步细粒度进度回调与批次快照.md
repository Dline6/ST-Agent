# T-L0-022 · 同步细粒度进度回调与批次快照

## 目标

让长任务内部可见：按码/按季/按请求回传进度，聚合到轻量 job 快照，供 UI 显示 X/Y 码、请求数、行数与 ETA。

## 验收标准（Given-When-Then）

- GWT-1 逐任务进度：Given 日线同步 314 只码，When 执行，Then 进度按码单调递增，含 `unit_done / unit_total / requests / rows / phase / label`，只含计数与标签，不含任何行内容。
- GWT-2 批次聚合：Given 一个批次含多个数据集组，When 轮询 job，Then 返回总体与逐组进度、当前组/码、已发请求、已入库行、ETA（完成 ≥10 单元后显示）。
- GWT-3 节流：Given 高频逐码回调，When Runner 聚合，Then 写入 job 的频率不超过约 500ms 一次，不因进度更新阻塞抓取。
- GWT-4 取消：Given 运行中取消，When 当前请求结束，Then 终态 `cancelled`，已完成结果与进度保留；未执行组标记未执行。
- GWT-5 覆盖计划：Given 覆盖账本跳过若干码，When 显示进度，Then 单独显示跳过码数/节省请求数，不把跳过算成失败。

## 接口面

- 输入：
  - `T-L0-021` 的覆盖计划与请求单元。
  - 现有 `_BatchWriter`、`_via_gateway`、`fetch_attempts`、`_run_market` 的 job 结构。
- 输出：
  - `sync.py` 的 `run_task(..., progress=None)` 与各 `_load_*` 回调。
  - `sync_runner.py` 的 job `progress` 字段与逐组进度；`GET /api/settings/data/job` 载荷扩展。
  - `tests/l0/test_sync_progress.py`（或并入既有同步用例）。

## 可关闭的遗留

- 无归属本任务的既有条目。D-130 的「逐任务进度」由本任务细化为逐码/逐组，已记 D-133。

## 假设与前提

- A1 进度单元按「请求单元」计（码×窗口、码×季度），不按行计；行数单独累计。若错：ETA 在空结果码上失真。验证：空结果码计入完成但不增加行。
- A2 节流在 Runner 侧做，L0 回调同步调用；回调抛异常不打断抓取。若错：进度故障会影响长跑。验证：回调异常用例。
- A3 ETA 只在样本足够时显示，使用最近完成速率而非全程平均。若错：开头 ETA 抖动大。
- A4 进度不进入审计、不落盘；进程退出后不保留。若错：无影响，符合现有批次语义。
