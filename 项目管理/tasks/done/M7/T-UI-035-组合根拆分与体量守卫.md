# T-UI-035 · 组合根拆分与体量守卫

## 目标

把 `src/st_agent/app.py`（3,792 行）按「门面 / 里程碑运行时 / 适配器」拆进 `st_agent.composition` 包；`app.py` 收薄为**再导出门面**（公开导入面不变）。同时新增体量守卫，把拆分后的尺寸钉成上限，防止下一次功能把代码堆回门面。

## 验收标准（Given-When-Then）

- GWT-1 导入面不变：Given 既有 `from st_agent.app import build_m5_runtime, M4Runtime, MemoryPositionsFacade, ReflectionFacade, TurnResult, LlmPatternObserver …`，When 拆分后导入，Then 全部仍可取（生产入口 `__main__.py` 与集成 fixture 不改）。
- GWT-2 依赖方向不变：Given 拆分后的 `composition/**`，When 跑 `tests/test_layering.py`，Then 部件只向下 import 各层与同包，层不得 import `composition` / `app`。
- GWT-3 门面收薄：Given 拆分完成，When 跑 `tests/test_module_size.py`，Then `app.py` ≤ 300 行、`composition/**` 单文件 ≤ 800 行。
- GWT-4 无行为变更：Given 拆分后的组合根，When 跑 `tests/integration` 的 M1–M6 装配用例，Then 结果与拆分前一致。

## 接口面

- 输入（消费的前置接口）：
  - 既有 L0–L6 / `eco` 各层的公共 API（门面与运行时只做装配，不新增层内逻辑）。
  - 既有 `st_agent.app` 的公开名：`TurnResult` / `M1Runtime`–`M5Runtime` / `build_m1_runtime`–`build_m5_runtime` / `MemoryPositionsFacade` / `ReflectionFacade` / `EcoFacade` / `GraphFacade` / `DeliberationFacade` / `DeliveryFacade` / `SettingsFacade` / `SkillsFacade` / `McpFacade` / `StudioFacade` / `TrialSessions` / `LlmTrainingUnderstander` / `LlmPatternObserver` / `InvestigationOutcome`。
- 输出（本任务交付的公共 API / 落盘位置）：
  - 新增 `src/st_agent/composition/`：`common.py`、`facades/`（chat / reflection / eco / memory / reasoning / delivery / settings / capability）、`runtime/`（m1–m5）、`adapters.py`、`agent.py`。
  - `src/st_agent/app.py` 只做再导出与 `__all__`。
  - 新增 `tests/test_module_size.py`（体量守卫）。
  - 无新增 HTTP 端点，无新增落盘格式。

## 可关闭的遗留

无（纯结构搬迁；已扫各层遗留册未闭区，无归属本任务的条目）。

## 假设与前提

- A1 拆出的部件是**单向 DAG**：`common ← chat ← rt_m1 ← rt_m2 ← rt_m3 ← rt_m4 ← rt_m5`，门面与适配器为叶子。开工前已用 AST 扫过跨组引用。若错：出现环时把共用项下沉到 `composition/common.py`。
- A2 再导出覆盖全部消费点：开工前 grep 过 `from st_agent.app import` 的每个名字（生产入口 1 处、集成 fixture 5 处、UI 集成 6 处、live 3 处）。若错：导入期报错即可定位，补一条再导出。
- A3 拆分不改 CI 范围判定：`src/st_agent/app.py` 与 `composition/**` 不落在按层映射的路径里，PR 仍会跑跨层套件（`tests/integration` 等）；本任务不修改 CI 配置。若后续要求「改组合根也跑 `tests/ui`」，另立任务补 `.github/workflows/ci.yml` 与工作流映射。
