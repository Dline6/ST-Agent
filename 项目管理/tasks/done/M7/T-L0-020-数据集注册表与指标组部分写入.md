# T-L0-020 · 数据集注册表、指标组与部分写入

## 目标

把现有 21 个任务归位到「数据集」能力模型，并交付指标组选择、部分 UPSERT 与按数据性质的时间口径。

## 验收标准（Given-When-Then）

- GWT-1 数据集注册：Given 现有任务清单，When 构建数据集目录，Then 每个任务恰属一个数据集；逐码/全局、指标组、时间类型、覆盖单元、默认时间、高级/默认关闭等能力位齐全，中文名与说明不缺失。
- GWT-2 指标组：Given K 线只选「估值」、财务只选「盈利」，When 同步，Then K 线只更新估值列并保留既有价格/成交列；财务只调用盈利接口，其余五组不发起请求；`code` 与主键始终写入。
- GWT-3 时间口径：Given 日线选日期区间、财务选最近 N 季或 `YYYYQn` 区间、分红选年份区间、快照无时间，When 执行，Then 各 loader 收到正确窗口；不支持的维度在预检与结果中显式回报忽略。
- GWT-4 不可拆分数据集：Given 复权因子/分红/快报/预告，When 选择，Then 整取；复权因子三列 NOT NULL 不被部分写入破坏；分红无操作日期的去重口径不变。
- GWT-5 完整性：Given 未选 `trade_status` 或 `is_st`，When 跑完整性校验，Then 依赖该列的检查跳过并在结果里说明，不静默通过。

## 接口面

- 输入：
  - `T-L0-019` 的标的解析与 `st_membership` / `v_st_sync_pool`。
  - `fetch.py` 现有 `map_*` 与固定字段常量；`sync.py` 现有 `_load_*` / `_write_*` / `_BatchWriter`。
- 输出：
  - 新增 `src/st_agent/l0/market/datasets.py`：`DatasetSpec`、指标组定义、时间类型、默认时间、刷新视界、覆盖单元。
  - `fetch.py` 新增字段→列→组映射与 `ST_NAME_PREFIXES` 邻近的组常量；`sync.py` 的 `run_task` / `_fetch_and_load` / 各 `_write_*` 接受 `groups` / `time_spec`，按选中列构造 UPSERT。
  - 财务 loader 只调用选中组；`pub_date` 保持已查接口最大值。

## 可关闭的遗留

- 无归属本任务的既有条目。D-130 的「整表取数」口径由本任务改写，已在新决策 D-132 记录。

## 假设与前提

- A1 K 线抓取侧仍取全集，只做写入投影——避免半列结果与抓取协议大改。若错：若源端按字段计费/限流，需再做 API 字段裁剪。验证：抓取调用参数不变、写入列按组变化。
- A2 财务的六个接口可独立跳过；`pub_date` 在跨组增量时取已有值与新值的最大。若错：财报披露日会回退。验证：先选盈利、再选成长，`pub_date` 不回退。
- A3 未选列在冲突时保留原值，首次插入为 NULL。若错：会把既有数据清空，属严重回归。验证：部分写入用例。
- A4 时间类型是数据集能力位，不在 UI 里按任务键硬编码。若错：新增任务要改前端。验证：目录载荷驱动控件。
