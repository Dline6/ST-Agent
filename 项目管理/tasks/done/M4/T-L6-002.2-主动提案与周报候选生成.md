# T-L6-002.2 · 主动提案与周报候选生成

## 目标
交付 [08 §4](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的**主动提案**（前半）：模式识别（同类问题重复出现 > N）→ 产出**含 Skill 草稿的提案**、受**频率上限**约束（防骚扰，超限**排队不丢**）；同批交出 [08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 第四段「建议调整」的**候选生成规则**并接到 `WeeklyReportBuilder(advisor=...)` 的注入面——两处**同源**（同一提案面），这正是 [L6 册 `A1`](../../../遗留问题/L6-遗留问题.md) 所指的缺口。

**与上游的边界**（2026-10-06 读码核实）：

- **承载与呈现已交付**：[`ProposalCandidate`](../../../../src/st_agent/l6/weekly.py)（`config_id` + 现值 + 建议值 + 理由 + `trace_ref`，**无 `change_id`**）与 `advisor` 注入面归 [T-L6-001.2](T-L6-001.2-每周反思报告本体.md)；本叶**不重造载体**，只补「候选从哪来」。
- **观察不由本层扫描**：全仓无「同类判定」实现，且 L3 的对话史不是 L6 的读面（[铁律 7](../../../工程宪法.md) 只约束向下依赖，但**对话史无既成交出的读面**）⇒ 观察经**注入的模式观察面**取得，缺省**不产提案**（fail-closed），不以「计数为 0」反推「没有问题模式」。
- **Skill 草稿的形态**：[03 §4](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的 Studio 草稿是**工作流草稿**（[`WorkflowDraft`](../../../../src/st_agent/l1/studio/draft.py)，含 `workflow_draft` 子对象），本叶承载的正是该**子对象**的形态（`name` / `description` / `nodes` / `edges` / `groups` / `schedule`）——不 import L1、不在本层物化 Skill（物化归 Studio 的「接受」）。
- **提案不生效**：本叶产出的一切都是**候选 / 提案**，**不产 `change_id`、不落变更历史**；生效 / 回滚属 [08 §5](../../../../docs/技术架构-v2/08-L6-反思演进.md)，归 [T-L6-003](T-L6-003-演进授权与变更流回滚与出厂重置.md)。

## 验收标准（Given-When-Then）
- **GWT-1**：Given 注入的模式观察面给出「同类问题重复出现 > N（缺省 5）」的观察，When 判定，Then 产出一条 **`SkillProposal`**——含同类键、计数、样本来源锚点、**Skill 草稿**（`workflow_draft` 形态：名称 / 说明 / 节点 / 连线 / 分组 / 调度）与中性理由，并落 `reflection/proposals/<proposal_id>.json`；Given **未注入观察面**，Then **不产任何提案**并显式说明（`unavailable` 语义），**不由计数 0 反推**
- **GWT-2**：Given 阈值条目 `proposal.repeat-threshold` 被改（如 5 → 2），When 重新判定同一批观察，Then 提案随阈值变化——阈值走 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 条目，**不硬编进代码**
- **GWT-3**：Given 本 ISO 周的提案配额（`proposal.rate-limit`，缺省 1）已用尽，When 又有一条命中，Then 该条以**排队态**落痕、**不丢弃**；Given 进入下一窗口，When `release`，Then 排队的提案按配额放行——读面始终可查排队态
- **GWT-4**：Given `ProposalEngine` 接上 `WeeklyReportBuilder(advisor=...)`，When 组装周报，Then 第四段由**规则表**产出候选（每条含 `config_id` + 现值 + 建议值 + 理由 + 依据锚点），**零 `change_id`**、**零变更历史**；Given 某条规则的**现值读不到**（未接条目读面 / 条目缺），Then **跳过该条并记因**（读面可查），**不臆造现值**
- **GWT-5**：Given `proposal.*` 族注入 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 门面，When 逐条目读 / 写，Then 读面全接；两条标量条目经统一落值面**可写**并产 `change_id` 留痕（`execution_log/proposal-change/`）；取值未变**不落盘不留痕**（同 [`WeeklyReportStore.set`](../../../../src/st_agent/l6/weekly_store.py) 的口径）

## 假设与前提
- **A1 · 观察经注入端口、缺省不产提案**（2026-10-06 ④ 对齐拍定）——前提：「同类问题」的判定需要 L3 的对话史，而 L6 无该读面（读码核实：无既成交出的对话史取数面），按 [D-062](../../../决策日志.md)「判定类能力经注入端口、缺省不判定」的先例落地。若错（要求本层自行扫描对话史）：返工面＝本叶观察面 + 一条新的 L3→L6 读面（须触 [05 §1](../../../../docs/技术架构-v2/05-L3-对话主入口.md) 的会话模型契约）。验证方式：未注入观察面时 `detect` 返回空 + 说明、且**不落任何提案文件**的用例。
- **A2 · 频率上限按 ISO 周窗口**（2026-10-06 ④ 对齐拍定）——前提：频率上限需要一个**确定性**窗口才能离线复算与幂等（同 [08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的 ISO 周口径），且该窗口已在 [`week_key`](../../../../src/st_agent/l6/weekly.py) 落地——**复用而不另造**第二套时间口径。若错（要求滚动窗口 / 自然周）：返工面＝本叶窗口判定与条目语义。验证方式：跨 ISO 周边界（含跨年周）的成对用例。
- **A3 · 周报第四段的规则＝本叶的规则表（两处同源）**（2026-10-06 ④ 对齐拍定）——前提：[08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 第四段与 [§4](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的提案是同一件事的两处呈现（§2 原文「每条 = §5 的 Change Proposal」、§4 原文「提案 = Change Proposal 的一种」）。若错（要求两处各持一套）：返工面＝本叶规则面 + [08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的取材面行文。验证方式：周报第四段的候选与 `proposals` 直调**逐条相同**的用例。
- **A4 · 缺省规则表取「忽略占优 → 疲劳阈值」「触达偏密 → 去重窗口」两条**（2026-10-06 ④ 对齐拍定）——前提：规则要可判、可溯、且目标条目都是**既有标量条目**（[`fatigue.ignore-threshold`](../../../../src/st_agent/l5/fatigue_store.py)、[`frequency.dedup-window-minutes`](../../../../src/st_agent/l5/frequency_store.py)，读码核实两者皆存在）；判据只用周报注入面已给的 `evidence`（`ignored` / `rejected` / `week_deliveries`），**不扩 `evidence` 结构**（那会改 [T-L6-001.2](T-L6-001.2-每周反思报告本体.md) 的交付面）。若错（要求另换规则或另加判据）：返工面＝`DEFAULT_RULES` 表与相应用例（规则表是**声明式数据**，换规则不动引擎）。验证方式：两条规则各自的命中 / 未命中成对用例 + 目标条目的现值经门面读取。
- **A5 · Skill 草稿只承载形态、不物化**（2026-10-06 ④ 对齐拍定）——前提：[03 §4](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的「接受」才是唯一落盘点，物化走 [`SkillRegistry.register(source="user-built")`](../../../../src/st_agent/l1/skills/registry.py) / [`save_as_composite_skill`](../../../../src/st_agent/l1/workflow/composite.py)，且该路径归 Studio + L3 派发。若错（要求本叶物化）：返工面＝本叶范围（并会绕过 Studio 的草稿边界与变更留痕）。验证方式：`grep` 断言 `src/st_agent/l6/**` 不 import `l1.skills` / `l1.studio`。
