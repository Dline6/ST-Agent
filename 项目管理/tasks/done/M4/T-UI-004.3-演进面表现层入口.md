# T-UI-004.3 · 演进面表现层入口

> 由 [`T-UI-004`](T-UI-004-反思中心与生态面的表现层入口.md) 按[拆分触发](../../../工作流.md)拆出（D-089 ①）；底座见 [`T-UI-004.1`](T-UI-004.1-回环端点骨架、鸭子端口注入与前端页面壳.md)。

## 目标
交付 [story-09「设计触点」](../../../../docs/PRD-v2-Agent/story-09-reflection-loop.md) 演进面的表现层入口（L6 的 **变更历史读面 + 演进写面**）：

- **变更历史时间线**（`change_timeline`）——逐条变更（来源 / 授权档 / 理由 / trace 依据 / 回滚状态），含已回滚标注。
- **一键回滚**——任一 `change_id` 回滚，回滚**本身也是一次变更**。
- **演进授权设置页**——三档（手动 / 协作 / 自主）切换 + 风险分级清单读面，切换**留痕**。
- **出厂重置**——**三次确认**后清空演进状态（保留 Memory 原始数据、历史归档可查）。

与 [`T-UI-004.2`](T-UI-004.2-反思中心表现层入口.md) 的分工：**本叶拥有变更流的「读历史 / 回退 / 授权 / 重置」，提案的「生成与处置」归 `.2`**——两叶各占变更流的一半，不重叠。

## 验收标准（Given-When-Then）
- **GWT-1** Given 已发生若干演进变更与回滚，When GET `/api/evolution/changes`，Then 时间线按 `(seq, applied_at, change_id)` **确定定序**、逐条含来源 / 授权档 / 理由 / trace 依据，且**已回滚的记录保留并标注**（不抹除）、回滚本身另有记录。
- **GWT-2** Given 任一 `change_id`，When POST `/api/evolution/changes/rollback`，Then 经 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 门面落值、产生**新** `change_id`，条目回到该变更的 `old_value`；**首改条目**（`old_value` 为空）取该条目的声明面默认；连默认也读不出时 `unavailable` 并**如实说明**（不写假值冒充恢复）。
- **GWT-3** Given 授权设置页，When GET `/api/evolution/authorization`，Then 给出当前档位、风险分级清单与逐 range 判据（可自主 / 必须协作 / 永不可自主）；When POST 切换档位，Then 经统一标量落值面生效并**产生 `ChangeRecord` 留痕**；非法取值 → `validation_failed`。
- **GWT-4** Given 出厂重置入口，When POST 确认次数 < 3，Then **拒**——不留痕、不执行任何动作、不留「做了一半」的状态；When 确认次数 = 3，Then 逆序回放演进变更 + 在跑实验转已停止 + 档位复位，且**`memory` 分区清单与逐文件内容逐字节不变**。
- **GWT-5** Given 档位条目损坏或读不到，When GET 任一演进端点，Then **fail-closed**——`unavailable` / 明确不放行，**不臆测为 `autonomous`**；重置时无历史可回放 → 照常成功并如实说明。
- **GWT-6** Given L6 端口未注入，When 访问上述任一端点，Then `unavailable` + 点名（不伪造档位、不假装重置过）。

## 假设与前提
- **A1 · 回滚与重置都走变更流，表现层不得直改落盘**——前提：[08 §6](../../../../docs/技术架构-v2/08-L6-反思演进.md) 明写回放**经门面落值**、回滚本身也是变更（产生新 `change_id`），[§7](../../../../docs/技术架构-v2/08-L6-反思演进.md) 红线禁静默路径。
  **若错的影响**：端点直改落盘即造出绕过审批门的第二条路径，且 `old_value` 链断裂、重置的逆序回放失去依据。
  **验证方式**：GWT-2 的「产生新 `change_id` + 原记录保留并标注」；`grep` 断言新端点无直写 `config` 分区、无第二条 `change_id` 铸造点。
- **A2 · 三次确认是硬门，且「拒绝」必须无副作用**——前提：[08 §6](../../../../docs/技术架构-v2/08-L6-反思演进.md) 明写「不足三次**即拒**——不留痕、不执行任何动作、不留『做了一半』的状态」。
  **若错的影响**：确认不足却先回放了一半，用户数据处于不一致状态且不可恢复（Memory 保留承诺也可能被破）。
  **验证方式**：GWT-4 同时断言「重置留痕为空 + 条目值与档位一字未动 + `memory` 分区逐字节不变」。
- **A3 · 授权档读不到即不放行**——前提：[08 §5](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的判据「档位读不到即 fail-closed（不臆测为 `autonomous`）」。
  **若错的影响**：条目损坏被当作「自主档」= 静默放开自主变更，正面违 [§7](../../../../docs/技术架构-v2/08-L6-反思演进.md) 红线。
  **验证方式**：GWT-5 以损坏条目构造，断言不放行且给出原因。

## 备注
授权设置页的**呈现**走 `config_draft_card` 的面板视图分支（[05 §5](../../../../docs/技术架构-v2/05-L3-对话主入口.md) 双通道同源），但**改值**另用带动作的 `setting_panel`——`config_draft_card` 按既有口径是**只读**视图（渲染件只呈现、不落值），把它改成可写会动一条既已 `done` 的交付面语义；两者**不合并**的理由与契约登记见 [01 §12](../../../../docs/技术架构-v2/01-平台共享契约.md)（「只渲染」与「会写」是两条不同的安全边界）。

出厂重置的**三次确认**是**页面级 chrome**（计数 + 提交），不是描述承载的动作；服务端才是判据（不足即拒、一步不做，[08 §6](../../../../docs/技术架构-v2/08-L6-反思演进.md)），页面的 `NEEDED = 3` 只把同一口径渲染出来。

**本批范围**：风险分级清单（对象类条目）**只呈现**、不提供页内编辑器（其替换经自有 API，[01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md)；端点亦接受该写面，但页面不给控件）。
