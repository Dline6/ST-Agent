# T-L6-003 · 演进授权与变更流 + 回滚与出厂重置

## 目标
交付 L6 的第三批（[08 §5–§7](../../../../docs/技术架构-v2/08-L6-反思演进.md)）：**演进授权档位 + 变更流**（[§5](../../../../docs/技术架构-v2/08-L6-反思演进.md)：三档授权 · 风险分级清单 · 提案 → 审批门 → 生效 → 告知 → 可回滚）+ **回滚与出厂重置**（[§6](../../../../docs/技术架构-v2/08-L6-反思演进.md)：任一 `change_id` 一键回滚 · 三次确认的出厂重置）+ 把 [§7](../../../../docs/技术架构-v2/08-L6-反思演进.md) 三条红线以机器断言钉住（不存在绕过变更流的静默调参 · 不自主改 Memory · 无跨用户学习）。

**承接前两批刻意留下的缺口**（2026-10-07 读码核实）：

- **全仓无任何 `rollback` 实现**（`grep` 零命中），且 [01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md) 登记的 `ChangeApplied` / `ChangeRolledBack` **无发布点**——T-L6-002 批次明确把「每次变更经 L5 显式告知」与「A/B 实验停止」划给本任务。
- **授权档位本体未落地**——[`ExperimentConsole`](../../../../src/st_agent/l6/experiment.py) 的启用门只消费**注入的授权面**（鸭子面 `permits(scope) -> bool`），档位本体（`manual` / `collaborative` / `autonomous` 三档、切换留痕、风险分级清单）正是本任务的交付。
- **提案只到候选为止**——[T-L6-001.2](T-L6-001.2-每周反思报告本体.md) 的 `ProposalCandidate`、[T-L6-002.1](T-L6-002.1-训练对话协议.md) 的 `SuggestionDraft`、[T-L6-002.2](T-L6-002.2-主动提案与周报候选生成.md) 的提案引擎都**只产候选、不产 `change_id`、不生效**（[§7](../../../../docs/技术架构-v2/08-L6-反思演进.md) 红线）；本任务把候选接进变更流。
- **`config` 条目的 `default` 槽存的是当前取值**（读码核实：[`weekly_store.py`](../../../../src/st_agent/l6/weekly_store.py) 的 `set` 把新值写进 `entry.default`）——故「恢复默认」**无法**由 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 门面泛化给出；§6 的「Skill 参数恢复默认」以**演进变更历史逆序回放**兑现（见 `## 假设与前提` A3）。

**上游已就位**（读码核实）：[`ConfigRegistryFacade`](../../../../src/st_agent/l1/registry/facade.py) 的 `apply` / `set` 已产 `ChangeRecord`（`change_id` 即回滚单位，[T-L1-012](../M2/T-L1-012-统一配置注册表门面.md)）；各族把变更留痕落在 `execution_log/<族前缀>-change/`；[`ChangeRecord` / `ChangePolicy`](../../../../src/st_agent/contracts/registry_types.py) 与 [`PlatformEvent`](../../../../src/st_agent/contracts/time_events.py) 的 Change 类形态齐备；[`EventBus`](../../../../src/st_agent/l1/events.py) 与 [`ChannelDispatcher`](../../../../src/st_agent/l5/channels.py) 均可用。

**本任务的边界**（不越界）：

- **跨层组合根 `build_m4_runtime`、常驻驱动、把授权档位对象注入 `build_l6` 的 `authorizer` 口、以及 L5 告知通道对 `ChangeApplied` 的订阅** → 关卡 [T-INT-005](T-INT-005-M4集成关卡反思演进与生态闭环.md)（先例＝`build_m3_runtime` 归 [T-INT-004](../M3/T-INT-004-M3集成关卡主动触达投递闭环.md)）。
- **表现层渲染**（变更历史时间线页 / 演进授权设置页 / 回滚按钮）不在本任务——本任务只交**留痕与读面**（同 [T-L6-002.1](T-L6-002.1-训练对话协议.md) 对「下次对话主动提及」的口径）。
- **Skill 草稿提案的「接受」**（[08 §4](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的 `SkillProposal`）不属变更流——其物化归 L1 Studio 的既有落盘点；变更流只承载**配置变更候选**（`config_id` + 现值 + 建议值）。
- **不产生新的 LLM 出网面**——本批全是本地判定与落值，[工作流](../../../工作流.md)「测试分层」的联网面强制项因此**不适用**。

**拆分**（命中[拆分触发](../../../工作流.md)两条：验收 GWT>5 · 跨 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) / [§11](../../../../docs/技术架构-v2/01-平台共享契约.md) / [§6](../../../../docs/技术架构-v2/01-平台共享契约.md) 与 [08 §5](../../../../docs/技术架构-v2/08-L6-反思演进.md) / [§6](../../../../docs/技术架构-v2/08-L6-反思演进.md) / [§7](../../../../docs/技术架构-v2/08-L6-反思演进.md) 多个契约小节）——父转分组节点，交付由三叶承接：

- [`T-L6-003.1`](T-L6-003.1-演进授权档位与风险分级清单.md)——**演进授权档位与风险分级清单**（[08 §5](../../../../docs/技术架构-v2/08-L6-反思演进.md) 前半）：三档授权 · 切换留痕 · 哪些参数可自主 · 实验授权面的实体
- [`T-L6-003.2`](T-L6-003.2-变更流与变更历史回滚.md)——**变更流与变更历史回滚**（[08 §5](../../../../docs/技术架构-v2/08-L6-反思演进.md) 后半 + [§6](../../../../docs/技术架构-v2/08-L6-反思演进.md) 前半）：提案 → 审批门 → 生效 → 告知 · 变更历史时间线 · 任一 `change_id` 一键回滚

## 验收标准（Given-When-Then）
取自 [story-09](../../../../docs/PRD-v2-Agent/story-09-reflection-loop.md) 与本任务范围内的架构段（[08 §5–§7](../../../../docs/技术架构-v2/08-L6-反思演进.md)），逐条落到三叶（父级只汇总，不重复）：

- Given 用户查看反思报告的「建议调整」，When 逐条处理，Then 每条建议可一键**接受 / 否决 / 延后**，接受后**立即生效并记入变更历史** → [`.2`](T-L6-003.2-变更流与变更历史回滚.md) GWT-1 / GWT-4
- Given 用户切换演进授权级别到「自主」，When 副驾做小步优化，Then 每次变更都**通过 Ambient 显式告知** + 用户可在**变更历史中一键回滚** → [`.1`](T-L6-003.1-演进授权档位与风险分级清单.md) GWT-1 / [`.2`](T-L6-003.2-变更流与变更历史回滚.md) GWT-3 / GWT-5
- Given 用户点击「回滚到出厂设置」，When **三次确认**，Then 所有演进状态清空（Skill 参数恢复默认 · A/B 实验停止 · 授权档复位）+ **Memory 原始数据保留** + 变更历史归档但可查 → [`.3`](T-L6-003.3-出厂重置.md) GWT-1 / GWT-2 / GWT-3
- Given 任一时刻，When 检查演进路径，Then **不存在**绕过变更流的「静默调参」路径；Given 任一演进变更，Then **不得**修改 Memory 节点内容 → 三叶的红线断言（[`.1`](T-L6-003.1-演进授权档位与风险分级清单.md) GWT-4 · [`.2`](T-L6-003.2-变更流与变更历史回滚.md) GWT-6 · [`.3`](T-L6-003.3-出厂重置.md) GWT-3）
- Given 一个 A/B 实验请求，When 在「自主」档下启用低风险范围，Then **放行**；When 在「手动 / 协作」档下，Then **不放行**（走协作路径） → [`.1`](T-L6-003.1-演进授权档位与风险分级清单.md) GWT-3

> 端到端装配（`build_m4_runtime`、授权面注入、L5 告知通道订阅、表现层渲染）与「反馈 → 训练 → 提案 → 变更流 → 告知 → 回滚」全链路复核归关卡 [T-INT-005](T-INT-005-M4集成关卡反思演进与生态闭环.md)。

- **A3 · 回滚与「恢复默认」以演进变更历史为据**（2026-10-07 ④ 对齐拍定）——前提：读码核实条目的 `default` 槽存的是**当前取值**（[`weekly_store.py`](../../../../src/st_agent/l6/weekly_store.py) 的 `set`），故门面无法泛化给出「出厂默认」；而 `ChangeRecord` 本就记着 `old_value`。故**单项回滚**＝按该 `change_id` 回放 `old_value`（经门面落值、产生**新** `change_id`，不静默改值）；**出厂重置**＝逆序回放全部演进变更 + 停实验 + 档位复位 + 历史归档。**重置范围＝演进变更历史所记录的条目**（不波及 `retention.*` / `mcp-hub/` 等与演进无关的条目）——该口径同批写进 [08 §6](../../../../docs/技术架构-v2/08-L6-反思演进.md)。若错（要求「全量条目恢复出厂默认」）：返工面＝[`.3`](T-L6-003.3-出厂重置.md) 的范围（须逐族补默认值来源）。验证方式：回滚后条目值等于该变更的 `old_value`；重置后条目值等于该条目最早一条演进变更的 `old_value`。
- **A4 · 变更历史时间线经 L1 门面的只增读面取数**（2026-10-07 ④ 对齐拍定）——前提：[01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 已定「读取与落值的公共面只此一处」且「存储布局不构成契约」；L6 若自扫 `execution_log` 会把各族路径前缀（`weekly-report-change/` 等）上升为**事实契约**，与 [D-067](../../../决策日志.md) 相悖。若错（要求不动 L1）：返工面＝[`.2`](T-L6-003.2-变更流与变更历史回滚.md) 的读面。验证方式：门面 `changes()` 在既有族上返回其变更记录、既有 `entry` / `apply` 行为逐字节不变（既有用例不改）。
- **A5 · 授权档位与风险分级清单都是 01 §7 条目**（2026-10-07 ④ 对齐拍定）——前提：[08 §5](../../../../docs/技术架构-v2/08-L6-反思演进.md) 原文「三档授权（**配置注册表项**，切换留痕）」且「以**风险分级清单**形式注册」；[01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 的「新增条目同此」口径要求新增条目随实现一并接入门面。档位是标量枚举 ⇒ 走统一标量落值面；风险分级清单取值是对象 ⇒ 写面归自有 API（先例＝`weekly-report.template`）。若错（要求档位住代码常量）：返工面＝[`.1`](T-L6-003.1-演进授权档位与风险分级清单.md) 的条目面与其「切换留痕」验收。验证方式：档位条目可经门面 `set` 落值并产生 `ChangeRecord`；缺省值 `collaborative`。
