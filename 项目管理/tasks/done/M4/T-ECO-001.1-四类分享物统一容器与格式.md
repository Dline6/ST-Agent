# T-ECO-001.1 · 四类分享物统一容器与格式

## 目标
交付 [09 §1](../../../../docs/技术架构-v2/09-生态与分享.md) 的**统一容器**（四类同构的三段结构）与它的**读取面**：

| 段 | 内容 |
| --- | --- |
| `header` | 格式标识（四类 kind 之一）+ 格式版本（[01 §9](../../../../docs/技术架构-v2/01-平台共享契约.md) 语义） |
| `payload` | 分享物本体（四类各一种形状） |
| `manifest` | 作者声明 · 创建时间 · 依赖声明（`skill_id` 清单）· 来源追溯（分享者标识 + 原始出处链）· 校验和 |

容器**明文可检视**（UTF-8 JSON），与 [02 §8.1](../../../../docs/技术架构-v2/02-L0-本地优先基座.md) 的备份归档容器**同族但互不通用**——两者格式相近（都是「容器 + 本体 + 元数据」），但备份是加密容器含私有敏感数据，分享文件是明文且经强制隐私过滤；把一类喂给另一类的读取面必须明确拒绝，不得静默当空。

**不做**：不取材、不导出、不落盘（归 [`T-ECO-001.2`](T-ECO-001.2-四类导出流程与分享卡片.md)）；不改四类本体的模型；不新增契约 ID 类。

## 验收标准（Given-When-Then）
- **GWT-1**：Given 四类分享物本体各一（`SkillDescriptor` / `WorkflowDAG` / `Lens` / `FragmentPayload`），When 打包成容器，Then `header` / `payload` / `manifest` 三段齐备、格式标识与扩展名一一对应（`.stskill` / `.stflow` / `.stlens` / `.stmem`），且产出是**可检视的明文**（UTF-8 可解、无加密层）
- **GWT-2**：Given 一个容器，When 读回本体，Then 得到**逐字段一致**的对象（四类各自往返；`.stmem` 的节点子类专属字段不得因判别联合而丢失）
- **GWT-3**：Given `header` 的格式版本，When 与读取面支持的版本比对，Then：**主版本不同** ⇒ 明确拒读（不静默降级、不猜结构）；**次版本更高** ⇒ 可读并如实标注——与 [01 §9](../../../../docs/技术架构-v2/01-平台共享契约.md) 的「主＝不兼容 / 次＝兼容」同义
- **GWT-4**：Given 一个容器，When 重算校验和，Then 与 `manifest` 所载一致；**改动载荷任一处** ⇒ 校验和不符并明确报错（不静默接受）
- **GWT-5**：Given 损坏 / 截断 / 非 JSON / 缺段 / 非本族（[02 §8.1](../../../../docs/技术架构-v2/02-L0-本地优先基座.md) 备份归档的字节），When 交给读取面，Then 逐类**明确报错**（点名是格式标识不符 / 段缺失 / 结构非法 / 校验和不符），**不**产出空容器或半截对象

## 假设与前提
- **A1 · 四类本体皆可 JSON 往返，且 `.stmem` 不丢子类字段**——前提（父 `A1` 的证伪点）：`FragmentPayload.nodes` 已是 §1 的判别联合 `AnyNode`（[`sharing.py`](../../../../src/st_agent/l2/memory/sharing.py) 已就 pydantic v2 按声明类型序列化的问题做过处理）。若错（某类本体含 JSON 不可表达的字段、或子类字段在容器往返中被吞）：返工面＝该类的 `payload` 适配件（容器形态不变）。验证方式：四类各自的打包 → 读回逐字段比对用例。
- **A2 · 校验和＝容器规范化字节的 sha256（hex 64）**——前提：L2 的 `ImportOrigin.checksum` 文档口径写明是「分享**文件**校验和（sha256 十六进制 64 位，09 §1 manifest）」，故导入侧要核的那个数（[T-ECO-002](T-ECO-002-导入校验流水线官方Skill索引生态边界.md)）就是本叶产出的这个数；两侧不能各造一套算法。若错（口径分叉）：返工面＝导入侧的校验步骤。验证方式：同字节重算一致、单字节改动即失败的用例 + 形态断言（64 位十六进制）。
- **A3 · 单个明文 JSON 文档足以承载三段，不需归档形态**——前提：四类 payload 全为 JSON 可表达结构（schema / DAG / Lens 定义 / 节点与边），当前无一需要随包携带的二进制或多文件实现体。若错（将来某类需附实现体，如可执行代码或附件）：返工面＝容器形态改为归档（zip / 目录），**四类同改**（同构是 [D-043](../../../决策日志.md) 的立点）。验证方式：四类打包产物的可检视断言（UTF-8 解码后能读到三段键）+ 与备份归档互不通用的用例。
- **A4 · 版本判据取「同一主版本可读」**——前提：[01 §9](../../../../docs/技术架构-v2/01-平台共享契约.md) 的语义是主版本＝契约不兼容、次版本＝兼容增强，故读取面对**更高主版本**拒读、对**更高次版本**可读并标注；本层持一个当前容器版本常量。若错（产品要求向后兼容读旧主版本）：返工面＝读取面的分派。验证方式：GWT-3 的三例（同版本 / 更高次版本 / 更高主版本）。
- **A5 · 与备份归档的区分靠格式标识**——前提：两类容器都有格式标识段，故「非本族」可在读 `header` 时判定，无需先试解 JSON。若错（备份归档的标识落在本层看不见的位置）：返工面＝判定顺序（先结构后标识）。验证方式：把 [T-L0-006](../M0/T-L0-006-备份恢复完全清空数据留存策略.md) 产出的归档字节喂给本层读取面 ⇒ 明确拒。
