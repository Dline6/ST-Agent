# T-L6-001.2 · 每周反思报告本体（四段式 + 完整 Trace + 空态）

## 目标
交付 [08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的**每周反思报告本体**：到用户配置的每周时刻本地生成四段式报告——**① 本周为你做了什么 · ② 偏好漂移 · ③ 错误与理解 · ④ 建议调整**；**生成走完整 Trace**、留档 `reflection` 分区；两处空态（**数据不足** / **无触达**）显式、**不硬凑**；时段与结构模板登记进 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md)。

**上游与本叶的边界**（2026-10-06 读码核实）：

- **取材面全是既有读面**：① 的触达统计取 [`DeliveryOrchestrator.ledger / settlements`](../../../../src/st_agent/l5/delivery.py)、② 取 [`MemoryReader.query`](../../../../src/st_agent/l2/memory/reader.py) 的 `reflection` 切片（[04 §3.1](../../../../docs/技术架构-v2/04-L2-记忆图谱.md)）、③ 取本批 [`.1`](T-L6-001.1-反思数据池.md) 的池内 `rejected` 条目、噪音过滤取 [`FrequencyController.counts`](../../../../src/st_agent/l5/frequency.py) 与 [`FatigueMonitor.counts`](../../../../src/st_agent/l5/fatigue.py)。**不新增上游数据源**。
- **第四段只产候选**（本批最关键的一处边界，见 `## 假设与前提` A3）：[08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 原文「建议调整的配置（每条 = Change Proposal，见 §5）」，而 [§5](../../../../docs/技术架构-v2/08-L6-反思演进.md)（变更流 / 授权门 / 生效 / 回滚）归 [T-L6-003](T-L6-003-演进授权与变更流回滚与出厂重置.md)。本叶交**结构化候选**（`config_id` + 现值 + 建议值 + 理由 + trace 依据），**不产 `change_id`、不落变更历史、不生效**——[08 §7](../../../../docs/技术架构-v2/08-L6-反思演进.md) 红线「任何演进变更不得绕过变更流（不存在静默调参路径）」。
- **投出不在此叶**：本叶交 `due(now)` 的纯函数判定与 `build(week, now)`，**实际投出**（经 [07 §3](../../../../docs/技术架构-v2/07-L5-主动触达.md) 渠道面）与「一周一次」去重归 [`.3`](T-L6-001.3-L6装配缝与报告投出.md)（同 [T-L5-003.1](../M3/T-L5-003.1-每日报告本体与模板配置.md) 交本体、[T-INT-004](../M3/T-INT-004-M3集成关卡主动触达投递闭环.md) 接到点驱动的分工）。

## 验收标准（Given-When-Then）
- **GWT-1**：Given 一个 ISO 周（[`## 假设与前提` A4](T-L6-001-反馈采集FeedbackEvent每周反思报告.md)）与该周已积累的留痕 / 池内反馈 / Memory 切片，When `build(week, now)`，Then 产出四段齐备的 `WeeklyReport`：**① 本周为你做了什么**（触达 / 采纳 / 过滤噪音的**中性统计陈述**）· **② 偏好漂移**（经注入的记忆读取面的 `evolution` 节点取材）· **③ 错误与理解**（被否定的推送与用户给出的原因，**原样中性呈现**）· **④ 建议调整**（**结构化候选**：`config_id` + 现值 + 建议值 + 理由 + trace 依据）；第四段**不含 `change_id`、不落变更历史**（只在 [§5](../../../../docs/技术架构-v2/08-L6-反思演进.md) 落地后由其接管）
- **GWT-2**：Given 报告时段与结构模板（周几 / 时刻 / 四段开关 / 订阅渠道链 / 数据不足阈值），When 经对话与面板两通道配置，Then 两通道读到**同一份值**（取值是标量的条目按 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 走统一落值面、对象类条目归本叶自有 API，同 [T-L5-003.1](../M3/T-L5-003.1-每日报告本体与模板配置.md) 的裁定）；Given 未配置，Then 走内置缺省（周日 20:00 / 四段全开 / 订阅 `desktop` / 阈值 3），**不臆造用户偏好**
- **GWT-3**：Given 该周**无任何触达**，When 生成，Then 正文只写「**本周无触达，无反馈可分析**」；Given 有触达但本周反馈数低于阈值（[`A7`](T-L6-001-反馈采集FeedbackEvent每周反思报告.md)），Then 明确写「**数据还不够，下周见**」；两式皆**不硬凑**内容、不产空壳报告
- **GWT-4**：Given 一次生成，When 观察产出，Then 报告携**完整 Trace** 锚点（参与的 `delivery_id` / `feedback_id` / `memory_node_id` / `signal_id` / `trace_id` 逐条可回溯，[01 §4](../../../../docs/技术架构-v2/01-平台共享契约.md)），且**整段文案过 [01 §6](../../../../docs/技术架构-v2/01-平台共享契约.md) 执行点 2**（命中即显式抛错、不静默吞）——[story-09](../../../../docs/PRD-v2-Agent/story-09-reflection-loop.md) 的行文是第一人称叙事的**产品描述**，**不是**输出模板（见 `## 假设与前提` A2）
- **GWT-5**：Given 同一 `(周, 留痕状态)`，When 重复 `build`，Then 结论恒同且（落盘时）**写同一路径** `reflection/weekly/<ISO 年>-W<ISO 周>.json`——生成可安全重入、到点重跑**不产生重复报告**

## 假设与前提
- **A1 · 四段取材面全用既有读面**——前提：[08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 只给四段的**段名与语义**（不给字段结构），故以本层已有的数据面组装（池内反馈 + L5 留痕 + 记忆切片），同 [T-L5-003.1](../M3/T-L5-003.1-每日报告本体与模板配置.md) A3 的日报取材口径。若错（要求新上游数据源）：返工面＝本叶四段取材面与 [08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 行文。验证方式：段级取材用例（含各段空态）。
- **A2 · 报告文案中性化、story-09 的第一人称行文不是模板**——前提：[08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) / [story-09](../../../../docs/PRD-v2-Agent/story-09-reflection-loop.md) 用「本周为你做了什么」「**我**观察到的偏好漂移」「**我**犯的错误」这类第一人称叙述，属**产品描述**；[铁律 2](../../../工程宪法.md) 禁拟人化（人名 / 性格 / **第一人称** / 情感 / 对话体），[01 §6](../../../../docs/技术架构-v2/01-平台共享契约.md) 执行点 2 强制校验。故报告输出取**中性陈述**（如「本周触达 N 次」而非「我为你做了 N 次」），「理解了什么」不臆造（[§3](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的概念性理解归 [T-L6-002](T-L6-002-训练对话协议主动提案与AB实验.md)，本叶只中性呈现用户给出的 `reason` 原文，见 [L6 册 `A2`](../../../遗留问题/L6-遗留问题.md)）。若错（要求照抄故事行文）：返工面＝本叶全部文案 + 与 [D-053](../../../决策日志.md) 的适用面冲突（**须走 [铁律 8](../../../工程宪法.md) 契约先行**）。验证方式：GWT-4 的中性化断言用例；`grep` 断言 `weekly.py` 的模板常量不含第一人称词元。**实现期细化**（同批拍定）：§6 的适用面以 [`ReportLine.generated`](../../../../src/st_agent/l6/weekly.py) **逐行显式区分**——生成性文案（统计陈述 / 段标签 / 空态说明 / 候选理由）过 §6，**用户数据**（③ 中用户给出的 `reason` 原文）**不过**（[D-053](../../../决策日志.md)：用户数据属数据展示）。若不区分：用户写「我觉得…」这类极常见的话时，报告会因**用户自己的话**而拒生成。验证方式：`tests/l6/test_weekly.py::test_user_reason_is_displayed_even_with_a_first_person_pronoun`（含第一人称的 `reason` 照常呈现）+ 同文件的守卫替身用例（生成性文案命中即抛）。
- **A3 · 第四段只产候选、不接通变更流**——前提：[08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 第四段「每条 = Change Proposal，见 §5」而 [§5](../../../../docs/技术架构-v2/08-L6-反思演进.md) 归 [T-L6-003](T-L6-003-演进授权与变更流回滚与出厂重置.md)；本批若自行生效即造出绕过授权门的静默调参路径（[08 §7](../../../../docs/技术架构-v2/08-L6-反思演进.md) 红线）。若错（要求本批接通）：返工面＝本叶第四段 + [T-L6-003](T-L6-003-演进授权与变更流回滚与出厂重置.md) 范围。验证方式：`grep` 断言 `weekly.py` 不产 `ChangeRecord` / `change_id`；候选形态用例。
- **A4 · 时段＝「周几 + HH:MM」两项标量条目**——前提：story-09 写「每周日晚 8 点（用户配置时间）」，周几与时刻都需可配才能表达「用户配置时间」；两项皆标量 ⇒ 各走 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 统一落值面（同 [T-L5-003.1](../M3/T-L5-003.1-每日报告本体与模板配置.md) 的日报时刻条目）。`due(now)` 判据 = 「已到该周的该时刻」，**不含**「本周发过没发过」（去重归 [`.3`](T-L6-001.3-L6装配缝与报告投出.md)，同日报口径）。若错（要求单个 cron 串 / 周几固定）：返工面＝条目形态与 `due` 判定。验证方式：改周几 / 时刻后 `due` 随之改变的用例。
- **A5 · ② 的取材面是 `evolution` **节点**、经 `reflection` 切片读**——前提：[08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 写「来自 Memory `evolution` 边分析」，而 [04 §3](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) 的 `evolution` 是**节点类型**（六类节点之一）、`evolves_from` 才是边类型；[`MemoryReader`](../../../../src/st_agent/l2/memory/reader.py) 的 `task_type` 映射按**节点类型**收（`"reflection" → history / pattern / evolution`），边的读面不在该映射内。故取 `evolution` 节点。若错（要求按 `evolves_from` 边遍历）：返工面＝② 的取材实现；**并按 [铁律 8](../../../工程宪法.md) 提请订正 [08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的「边」字（本批不改该文档）。验证方式：注入含 `evolution` 节点的记忆面即可组出 ② 的用例。
- **A6 · ④ 的候选从**注入的建议面**取，本叶不自造生成规则**（实现期补记）——前提：[08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 只说第四段「每条 = Change Proposal，见 §5」，**未给候选的生成规则**；而「从哪些观察推出哪条配置建议」正是 [08 §4](../../../../docs/技术架构-v2/08-L6-反思演进.md)「主动提案」的内容，归 [T-L6-002](T-L6-002-训练对话协议主动提案与AB实验.md)。故本叶交**承载 + 呈现 + 注入面**（`advisor` 鸭子端口 `proposals(evidence)`），缺省 `None` ⇒ 该段显式写「未接入建议面」。若错（要求本叶内置一套规则）：返工面＝本叶 `_proposals` 与 [T-L6-002](T-L6-002-训练对话协议主动提案与AB实验.md) 的范围；且内置规则会在 [§5](../../../../docs/技术架构-v2/08-L6-反思演进.md) 未落地时**看起来像能生效的建议**。验证方式：未注入 → 空态说明含「未接入建议面」；注入确定性替身 → 候选逐条呈现。**该缺口已登记**：[L6 册 `A1`](../../../遗留问题/L6-遗留问题.md)。
