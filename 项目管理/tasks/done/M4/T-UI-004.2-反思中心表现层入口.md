# T-UI-004.2 · 反思中心表现层入口

> 由 [`T-UI-004`](T-UI-004-反思中心与生态面的表现层入口.md) 按[拆分触发](../../../工作流.md)拆出（D-089 ①）；底座见 [`T-UI-004.1`](T-UI-004.1-回环端点骨架、鸭子端口注入与前端页面壳.md)。

## 目标
交付 [story-09「设计触点」](../../../../docs/PRD-v2-Agent/story-09-reflection-loop.md) 反思面的表现层入口（L6 的 **读面 + 反馈采集**）：

- **每周反思报告页**——`report_card` 四段式 + `trace_timeline` 完整 Trace；**双空态分开判定、皆不硬凑**（无任何触达 → 「本周无触达，无反馈可分析」；有触达但反馈数低于数据不足阈值 → 「数据还不够，下周见」）。
- **反馈采集组件**（`feedback_capture`）——采纳 / 忽略 / 否定+原因 / 追问 / 点赞五类入口；`rejected` 的 `reason` **必填**。
- **主动提案卡**（`proposal_card`）——含 Skill 草稿；逐条**接受 / 否决 / 延后**。
- **A/B 实验日志页**——假设 / 范围 / 样本 / 结果 / 决策五字段全程可查。
- **训练对话面**——训练会话与待回访项读面。

## 验收标准（Given-When-Then）
- **GWT-1** Given 某周已有周报，When GET `/api/reflection/reports`，Then 信封 `data` 为 `report_card` 描述（四段式：本周做了什么 / 偏好漂移 / 错误与理解 / 建议调整），并附 `trace_timeline` 完整 Trace（触达 / 采纳 / 噪音统计可追溯）；**两种空态各自成立**——无触达与数据不足**分开判定**、各自的 `reason` 不混用。
- **GWT-2** Given 一条推送/结论/建议，When POST `/api/reflection/feedback`（五类动作之一），Then 反馈**经交互层采集面**产生（`feedback_id` 由该面铸造）并进入反思数据池；`action="rejected"` 缺 `reason` → `validation_failed`；其余四类 `reason` 可选。
- **GWT-3** Given 周报第四段的建议或 §4 的提案，When 渲染提案卡，Then 卡上给出 `config_id` / 现值 / 建议值 / 理由 / trace 依据（+ Skill 草稿，若有）；**接受** → 经变更流落值生效并产生 `change_id`；**否决** → 留痕而配置取值**逐字节不变**；**延后** → **排队可再处置**，不是丢弃。
- **GWT-4** Given 已归档的若干实验，When GET `/api/reflection/experiments`，Then 逐条列出五字段 + 状态与决策；判定为**保守**（低于样本下限即 `inconclusive`，**不产 p 值 / 置信区间**）。
- **GWT-5** Given 训练会话与待回访项，When GET `/api/reflection/training`，Then 可读且标注「已确认 / 未确认」；未接概念性理解端口时**显式标注**（不硬猜复述）。
- **GWT-6** Given L6 端口未注入或某读面不可用，When 访问上述任一端点，Then `unavailable` + 点名（不伪造报告 / 不把「未接入」当「本周无数据」）；生成文案过 [01 §6](../../../../docs/技术架构-v2/01-平台共享契约.md) 执行点 2，`data` 槽（用户 `reason` 原话 / 记忆本体）原样呈现。

## 假设与前提
- **A1 · 提案处置的唯一通道是变更流，端点不得直写配置**——前提：[08 §5](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的「生成与生效分离」与 [§7](../../../../docs/技术架构-v2/08-L6-反思演进.md) 红线（不存在静默调参路径），且 `change_id` 只由 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 门面铸造。
  **若错的影响**：绕开门面即产生第二条写值路径，红线失守、回滚依据（`old_value`）失真。
  **验证方式**：GWT-3 的「接受产生 `change_id`」与「否决后取值逐字节不变」成对；`grep` 断言新端点无直写 `config` 分区。
- **A2 · 反馈的产生方是交互层（L3），表现层只提交**——前提：[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 的 `feedback_id` 产生方＝交互层、[05 §9](../../../../docs/技术架构-v2/05-L3-对话主入口.md) 的「L3 只产事件、不建反馈存储」。
  **若错的影响**：端点直写 L6 池会造出第二条产生路径，`feedback_id` 的来源不可追（幂等去重的前提被破坏）。
  **验证方式**：GWT-2 以「经采集面产生」钉住；反馈落 `reflection/feedback/<feedback_id>.json` 且 `feedback_id` 与采集面返回一致。
- **A3 · 双空态的分野由 L6 的数据字段给出，表现层不自行推断**——前提：[08 §2](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的 `empty` / `insufficient` 两态已由 `WeeklyReport` 承载、阈值是可配条目。
  **若错的影响**：表现层按「反馈数为 0」自行推「无触达」，会把「有触达但反馈不足」误报成「无触达」（与 [08 §4](../../../../docs/技术架构-v2/08-L6-反思演进.md) 「不由计数 0 反推」同型错误）。
  **验证方式**：GWT-1 两种空态各自成立、`reason` 不混用；GWT-6 的「未接入」与「无数据」分别报不同态。

## 备注
「训练对话」的**发起**仍走对话通道的 `train` 意图（[`T-L6-002.1`](T-L6-002.1-训练对话协议.md) 已接），本叶只交付其**读面**（会话与待回访项），不另造第二条发起路径。

同批把前端通用取值助手 `slots.js` 由 `plugins/l3/` 上移到 `components/`（反思件与 L3 件共用），并新增一条**静态守卫**（相对 import 必须可解析）——浏览器实测撞出该类错的**整页加载失败**，而服务端用例看不见它。
