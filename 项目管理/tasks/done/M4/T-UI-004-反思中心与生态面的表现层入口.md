# T-UI-004 · 反思中心与生态面的表现层入口

> **本任务已转分组节点**（2026-10-07，命中[拆分触发](../../../工作流.md)「验收 GWT>5」「涉及 2 个及以上契约小节」「单次预计会话轮次 > 20」，选型见 [D-089](../../../决策日志.md) ①）。交付由四叶承接，本节与下列各节只记**批次口径**，逐叶验收见各叶文件。

## 目标
把 [M4 关卡 `T-INT-005`](T-INT-005-M4集成关卡反思演进与生态闭环.md) 装配好的 L6 / ECO 面接到**表现层**：
在回环服务（`ui`）上新增只读 / 受限写端点，并在前端工程提供反思中心、变更历史时间线、导入导出面板、
演进授权设置页四处的入口与渲染。`T-INT-005` 只接线（`M4Runtime.l6` / `.eco` / `training_callbacks()` 与
`DialogFacade.turn` 的 `callbacks` 键），**表现层入口不在其范围内**（[D-088](../../../决策日志.md) ③）。

- 逐叶 GWT 见各叶任务文件；批次层面只钉两条不变量：**新增端点一律经回环面既有守卫**（令牌 + `Origin`）且**文案过 [01 §6](../../../../docs/技术架构-v2/01-平台共享契约.md) 执行点 2**；**各处空态不硬凑**（未导入任何第三方 Skill / 本周无触达 / 数据不足各自成立）。

## 接口面
- **输入**：`T-INT-005` 的 `M4Runtime`（`l6` 八面 / `eco` 三面 / `training_callbacks()`）· `DialogFacade` 的反馈采集面与 `callbacks` 键 · `ui` 既有回环守卫（`RequestGuard`）与中性化门（`NeutralityGate`）· [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 配置门面。
- **输出**：`ui` 的 `/api/reflection/**` · `/api/evolution/**` · `/api/eco/**` 端点（均回七键信封载荷）· `ui/web/**` 页面入口与新渲染件 · [01 §12](../../../../docs/技术架构-v2/01-平台共享契约.md) 新增五型（`feedback_capture` / `proposal_card` / `change_timeline` / `setting_panel` / `violation_alert`）· `__main__.py` 的端口注入（两个**适配面**：`M4Runtime.reflection` / `.ecosystem`——组合根所有，表现层不 import 各层类型）。
- 逐叶细目见各叶的 `## 接口面` 节。

## 假设与前提
批次假设逐叶编号登记（见各叶 `## 假设与前提`）；批次层面只有一条：

- **A0 · 四处入口共用一层底座，故底座先立**——前提：四处的路由 / 注入 / 导航同型，分头建会出现三套口径（D-089 ①）。
  **若错的影响**：若某叶的页面形态特殊到无法复用底座，该叶需自建一套路由，底座的价值随之下降。
  **验证方式**：后三叶的 `depends_on` 均为 [`.1`](T-UI-004.1-回环端点骨架、鸭子端口注入与前端页面壳.md)；`.1` 交付的端口名与路由登记点被三叶直接消费，无需各自新增注入点。
