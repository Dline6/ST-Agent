# T-L6-001.1 · 反思数据池（FeedbackEvent 落盘与读面）

## 目标
交付 [08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的**反思数据池**：交互层（L3）采集的 `FeedbackEvent` 经 `FeedbackRecorded` 事件（[01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md)）落进 `reflection` 分区（[02 §2.1](../../../../docs/技术架构-v2/02-L0-本地优先基座.md)），**本机生成、不外发**，并给出供周报取材的读面与统计面。

**上游与本叶的边界**（2026-10-06 读码核实）：

- [T-L3-005.2](../M1/T-L3-005.2-反馈采集点.md) 的 [`FeedbackCollector`](../../../../src/st_agent/l3/feedback/collector.py) **只采集不落盘**——其模块 docstring 明写「L3 不建反馈存储：反馈全部进 L6 的本地反思数据池（`reflection` 分区），故本模块不接 `Store`、零落盘」，未注入事件面时如实标注「未送达」并点名归属任务。**池子是本叶的交付**，不是上游欠账。
- [L5 疲劳面](../../../../src/st_agent/l5/fatigue.py) 已订阅同一 `FeedbackRecorded`（[T-L5-003.3](../M3/T-L5-003.3-推送疲劳监控与答复回流.md)）——[`EventBus`](../../../../src/st_agent/l1/events.py) **一事件多订阅者**、逐订阅者记因，两方并列消费、互不干扰；疲劳面只认 `context.fatigue_choice` 的答复，**不落反馈池**，故无重复落盘。
- **反馈事件不是反馈池的唯一形态**：[08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的采集点是「交互层的所有推送 / 结论 / 建议反馈入口 + [07-L5 疲劳监控](../../../../docs/技术架构-v2/07-L5-主动触达.md)」；两处最终都经 [01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md) 的 `FeedbackRecorded` 汇到本池（疲劳侧由 L5 产生询问、交互层采集答复），故本叶**只认事件**、不另开采集口。

## 验收标准（Given-When-Then）
- **GWT-1**：Given 一条 `FeedbackRecorded`（五类动作之一，`target.kind` ∈ delivery / trace / change），When `consume(event)`，Then 该反馈的 [08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md) 六字段（`feedback_id` / `target` / `action` / `reason` / `timestamp` / `context`）完整落 `reflection/feedback/<feedback_id>.json` 并可按 `feedback_id` 读回；**同一 `feedback_id` 重复到达不产生第二条**（幂等，不重复计数）
- **GWT-2**：Given 若干已达反馈，When 统计，Then 可按**动作 / 目标类型 / 时间窗**聚合计数（周报 [`.2`](T-L6-001.2-每周反思报告本体.md) 的取材面）；Given 负载不合 [08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md) 契约（缺字段 / `target.ref` 不合 [01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 形态 / `rejected` 缺 `reason`），Then **拒收 + 显式记因**（`validation_failed` 语义），**不落盘、不静默丢**、不污染池子
- **GWT-3**：Given 池子句柄与一个时间窗，When 读，Then 只返窗口内的条目、按 `timestamp` 升序；窗口内无条目 ⇒ **空集**（合法空结果，不臆造）；Given 事件名不是 `FeedbackRecorded` 或负载非映射，Then 返回 `None`（**不属本面**，同 [L5 `consume` 口径](../../../../src/st_agent/l5/fatigue.py)）
- **GWT-4**：Given 未注入 `Store`，When 采集与读，Then 走**纯内存态**（池子照常可读、**不落盘**且不谎称已持久化）；Given 落盘文件存在但损坏，When 读，Then **显式抛错**（[00 §6](../../../../docs/技术架构-v2/00-架构总览.md)）——**不把损坏读成「没有反馈」**（空池会被周报读成「本周无反馈」，正是静默失败）
- **GWT-5**：Given 本层全部代码，When 断言，Then **不铸 `feedback_id`**（`feedback_id` 恒来自事件负载，[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 产生方＝交互层）、**不对外发送任何反馈数据**（本机优先，[08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md)「不外发」）

## 假设与前提
- **A1 · 复用 L3 的 `FeedbackEvent` 模型、不另造平行模型**——前提：[08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md) 六字段已由 [T-L3-005.2](../M1/T-L3-005.2-反馈采集点.md) 落成 `FeedbackEvent`（含 `target.ref` 的 [01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 形态校验与 `rejected` 必填 `reason`），池内不需要第二份字段定义（两份必然漂移）。先例＝[`l5/daily_report.py`](../../../../src/st_agent/l5/daily_report.py) 向下复用 [`l2.SliceQuery`](../../../../src/st_agent/l2/memory/reader.py)。若错（要求 L6 自持一份池侧模型）：返工面＝本叶模型与 `pool_store` 的序列化面。验证方式：`grep` 断言 `pool.py` 的六字段来自 import 而非本地重定义；池内往返用例。
- **A2 · 池内以 `feedback_id` 为落盘键、幂等覆盖**——前提：[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 的 `feedback_id` 是**一条用户反馈**的标识、全局唯一（L3 铸造），故同一 ID 即同一条反馈；重复到达应是同一事实的重放而非新增。若错（要求每次到达追加一条流水）：返工面＝落盘键与 `counts()` 的口径。验证方式：同一 ID 连投两次、池内计数仍为 1 的用例。
- **A3 · 本叶只提供消费入口、不自订阅总线**——前提：总线的装配是**组合根**的事（[`EventBus`](../../../../src/st_agent/l1/events.py) 由 [T-INT-004](../M3/T-INT-004-M3集成关卡主动触达投递闭环.md) 系的组合根创建），单层自订阅会让本层在测试里也要一条总线。故本叶交 `consume(event)`，接线归 [`.3`](T-L6-001.3-L6装配缝与报告投出.md) 的 `build_l6`。若错（要求本层自订阅）：返工面＝本叶构造面与用例夹具。验证方式：本叶用例全部不建 `EventBus` 即可跑通。
