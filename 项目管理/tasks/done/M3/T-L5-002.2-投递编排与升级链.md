# T-L5-002.2 · 投递编排与升级链

## 目标
交付 [07 §4](../../../../docs/技术架构-v2/07-L5-主动触达.md) 的**编排面**：升级链状态机（按信号级别与用户配置逐级推进、每级产生一枚 `delivery_id` 留痕）、未读超时升级与 `DeliverySettled`、`routine` 汇总进日报的路由、文案个性化（过 01 §6），以及**离线补发的执行面**（销 [L0 册 `A5`](../../../遗留问题/L0-遗留问题.md)）。

## 验收标准（Given-When-Then）
- **GWT-1**：Given 一条 `emergency` 信号与缺省偏好（链 `[desktop, email, im_webhook]` + 等待 `[5, 15]` 分钟），When `dispatch(signal, now)`，Then 按链**首级投递**并落一条 `delivery_id` 留痕（链首、`status` 待确认）；Given 未读且 `now+5min`，When `advance(now+5min)`，Then **升级到第二级**并产生**新的** `delivery_id`；再 `+15min` 升级到第三级——每级各一枚留痕，级次可查
- **GWT-2**：Given 一条待确认投递，When 交互面报「已读」（反馈对象取该 `delivery_id`，[05 §9](../../../../docs/技术架构-v2/05-L3-对话主入口.md)），Then 该链**即刻结算**为已读、**不再升级**；Given 链尽仍未读，When 最后一跳等待届满，Then 结算为「未确认」并**转入日报汇总**（记为待汇总项），**不丢弃、不静默**
- **GWT-3**：Given 一条 `routine` 信号且 [`.2`](T-L5-001.2-注意力预算与情境模式.md) 的 `BudgetVerdict.dispatch="daily_report"`，When `dispatch`，Then 只记一条 `route="daily_report"` 的**待汇总项**、**不调任何渠道**；Given 用户把该级别显式配进该格位（判定改判 `separate`），When 再 `dispatch`，Then 走正常升级链
- **GWT-4**：Given 同一条信号与置信度不同的记忆切片（**档位的驱动量**——[04 §3.1](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) 的 `MemorySlice.confidence` 原文即「消费方按它调整表述强度」），When 生成推送文案，Then 措辞档**随之不同**（`detailed` / `standard` / `concise` 三档，差别只在信息密度）且三者**均过 01 §6 中性化**（无第一人称 / 无情绪词 / 无对话体）、**均并列保留全部逐视角摘要**（铁律 4）；Given 记忆面未注入 / 查询抛错 / 无切片，Then 回落**中性缺省**（不阻断投递、不臆造用户偏好），并在 `WordingProfile.note` 里写明理由
- **GWT-5**：Given 断网时一条云端渠道的投递，When 记录，Then 留痕为 `pending_reconnect` 态并计入**本层自持的待发清单**；Given 网络恢复且用户**开着**补发开关，When `resend(now)`，Then 重发得**同一 `delivery_id`**（确定性摘要，不产生重复记录）；Given 用户**关着**补发开关，Then 不重发且显式标注「补发已关闭」——**全程不依赖 L0 出网审计**（审计默认关，见 [02 §6](../../../../docs/技术架构-v2/02-L0-本地优先基座.md)）
- **GWT-6**：Given 同一 `(signal, 渠道, 级次)`，When 重放 `dispatch` / `advance` / `resend`，Then `delivery_id` **恒同**且留痕**不重复**（升级链可安全重入）；Given 同一 `(状态, now)` 序列，When 重复推进，Then 结论恒同（纯函数口径，时钟由调用方按次传入）
- **GWT-7**：Given 投递结算，When 观察事件面，Then 产生 `DeliverySettled`（含**未读超时**语义，[01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md)）并携关联 `trace_id`；事件面未注入时**不假装送达**（记 `delivered=False` + 点名归属）

## 可关闭的遗留
- [L0 册 `A5`](../../../遗留问题/L0-遗留问题.md)（离线补发执行，L0 仅提供 `pending_reconnect` 查询口）——**本批关闭**。**收口口径据实修正并写明理由**：`A5` 原设想的补发清单来源是 L0 的 `pending_reconnect()`，但 02 §6 的出网审计**可选、默认关**（[D-073](../../../决策日志.md)），默认关时该查询按设计走显式 `unavailable`（不返回空集被读成「没有待补发」）⇒ 补发**不能**建在审计上。改由本叶的 `delivery_id` 留痕承载 `pending_reconnect` 态 + 本层自持待发清单；[07 §3](../../../../docs/技术架构-v2/07-L5-主动触达.md) 同批写实该口径。用例钉住：**审计关闭**时补发链照常工作。

## 假设与前提
- **A1 · 升级链的判定与推进是「显式时刻的纯函数」**（2026-10-06 ④ 对齐拍定）——前提：时钟由调用方按次传入（先例＝[L1 调度器](../../../../src/st_agent/l1/scheduler/scheduler.py) 的 `due(now)` / `catch_up`），故同一 `(状态, now)` 恒得同一结论、可离线重复验证。若错（要求本层自读系统时钟）：返工面＝`dispatch` / `advance` 的签名与全部用例。验证方式：GWT-6 的重入与重复推进用例。
- **A2 · `delivery_id` 取确定性摘要（本批同批收窄 01 §1）**——前提：升级链要能**安全重入**（重放 / 补发不产生重复记录），故 ID 须由 `(signal_id, 渠道, 级次)` 确定性推出（同 [T-L5-001.1](T-L5-001.1-信号模型与采纳.md) 对 `signal_id` 的裁法）。若错（要求随机 ID）：返工面＝`delivery_store` 的去重口径与 01 §1 行文。验证方式：GWT-5 / GWT-6 的同 ID 用例。
- **A3 · 日报路由只记待汇总项，本体归 T-L5-003**——前提：[07 §5–§6](../../../../docs/技术架构-v2/07-L5-主动触达.md) 的日报本体、去重合并与频控归 [T-L5-003](T-L5-003-每日报告去重频控推送疲劳监控.md)；本叶只交「这条该进日报」的判定与可读队列。若错（要求本批产日报）：返工面＝本叶范围与 `.3` 的装配。验证方式：GWT-3 断言 `route="daily_report"` 且**未调**任何渠道。
- **A4 · 文案个性化取「措辞档」而非「人格」**——前提：[07 §4](../../../../docs/技术架构-v2/07-L5-主动触达.md) 明写「个性化 ≠ 拟人化」（[铁律 2](../../../工程宪法.md)），且生成的文案要过 [01 §6](../../../../docs/技术架构-v2/01-平台共享契约.md)；用户自己的偏好原文属**数据展示**、不整串复检（[D-053](../../../决策日志.md) 的切分）。若错（要求更自由的个性化）：返工面＝`personalize.py` 的档位面与 07 §4 行文。验证方式：GWT-4 的两用户对照 + 中性化命中即阻断的用例。
