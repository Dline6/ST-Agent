# T-UI-002.4 · 启动期凭据口令交互与凭据可用性

## 目标
补上桌面启动路径上**唯一缺失的一环**——凭据口令的**索取与传递**：口令以何形态向用户索取、缺失时
应用以何状态呈现、以及它如何经**不落 argv / 不落环境变量 / 不落日志**的通道送到后端。

> **本任务由实测暴露（2026-10-05，[`T-UI-002.2`](T-UI-002.2-桌面壳本体窗口托盘自启与通知接线.md) 的
> Windows 走查顺手实测）**：把仓库 `.env`（LLM 三键）配好、存储为**明文根**（加密默认关，
> [D-073](../../../决策日志.md)）时，后端在装配 L1 时以 `StorageSecretsLockedError` 失败
> ——`.env` 引导装载要把 Key 写进**凭据库**，而凭据**恒加密**（[02 §2.2](../../../../docs/技术架构-v2/02-L0-本地优先基座.md)），
> 明文根的 `secrets` 分区在给出凭据口令前**保持锁定**（惰性解锁，[D-074](../../../决策日志.md) ②）。
> 壳的行为是对的（显式报错、不开空窗口，[`T-UI-002.1`](T-UI-002.1-生产运行入口与壳后端握手协议.md) 假设 `A3`），
> 但**用户拿不到任何输入口令的地方** ⇒ 桌面应用在「已配 LLM」的常见配置下起不来。
> [D-074](../../../决策日志.md) 已定**存储侧**口径（凭据恒加密 / 惰性解锁 / 明文根的凭据口令由首次解锁 TOFU 设定）；
> 缺的是**交互面**，本条即它。

**本任务不改存储侧口径**（[D-074](../../../决策日志.md) 已定），只补交互面与启动路径。

**拆分**（命中[拆分触发](../../../工作流.md)两条：验收 GWT>5 · 跨多个契约小节与层）——父转为分组节点，
交付由两叶承接：

- [`T-UI-002.4.1`](T-UI-002.4.1-入口侧口令协商与显式失败分类.md)——**后端 / 入口侧**：就绪握手**之前**的
  口令协商（`passphrase_required` 事件 + 管道回传 + 有界重试）与「需口令」的显式失败分类（L0 异常面）
- [`T-UI-002.4.2`](T-UI-002.4.2-壳侧口令框与OS凭据库记忆.md)——**壳侧**：原生口令索取框、操作系统凭据库
  记忆（免重复输入）、取消 / 失败的中性呈现

## 验收标准（Given-When-Then）
- Given 一个**明文根且凭据已建立**（先前设过口令）或**加密根**，When 经桌面路径启动，Then 应用能在
  **装配之前**向用户索取口令，给对后正常就绪（真组合根、`/api/chat` 走真 LLM 端点），**无「起不来」**
- Given 明文根且凭据分区**从未建立**而 `.env` 三键齐备，When 首次启动，Then 索取并**设定**凭据口令
  （TOFU），此后同根须以同一口令通过——**不**在无需口令的根上凭空造出一个口令
- Given 口令给错或用户取消，When 处理，Then **显式**中性说明（不静默降级为明文、不当作空凭据继续、
  不开空窗口），错误可重试、取消即退出
- Given 任一口令输入，When 传递与使用，Then 口令**不出现在 argv / 环境变量 / 日志 / 存储明文**中，
  只经壳与后端**两个进程之间的管道**传递
- Given 既有路径，When 复核，Then **不回归**：`--passphrase-env` 的无交互路径仍可用；免口令明文根的
  启动路径逐字节不变；壳仍不 import 任何业务层、不提供壳专有通道

## 假设与前提
- **A1 · 口令是外壳的一条自由文本**——前提：本批只索取**一个**口令，它同时充当「加密根的主密码」与
  「明文根的凭据口令」（`Store.open` 的既有语义即如此：给出的口令满足凭据校验锚则一并解锁）。
  若错（[D-074](../../../决策日志.md) ② 的**转换产物**可令主密码 ≠ 凭据口令，此时单次输入不足）：
  返工面＝协商协议与壳侧框数（须两次索取），影响 [`T-UI-002.4.1`](T-UI-002.4.1-入口侧口令协商与显式失败分类.md) /
  [`T-UI-002.4.2`](T-UI-002.4.2-壳侧口令框与OS凭据库记忆.md) 两叶。验证方式：以 `Store.convert` 产出
  「主密码 ≠ 凭据口令」的加密根实跑一次桌面启动，记录其行为（本批作为已知边界显式登记，若确不足另立任务）。
- **A2 · 询问的触发有两处，缺一不可**（**开工后被实测订正**，2026-10-05）——原假设为「只靠装配期显式异常，不必引入只读探测」；写码前读装配面即证伪：`_seed_llm_records` 的播种是**幂等**的（「端点已存在即整组跳过」，[`runtime.py`](../../../../src/st_agent/l1/runtime.py)），故「凭据已建立」的明文根**装配能过、不进交互**，口令始终没到位，失败被推到**第一次读凭据**时（如首次 LLM 调用）——正是本任务名里「凭据可用性」所指。现口径＝**开局只读探测（`Store.passphrase_requirement`：加密根 / 凭据已建立）+ 装配期异常（凭据**尚未建立**时的首次设定，以及给错口令的重试）**两者并用。若错（探测判据与真实需求分叉）：返工面＝入口时序，落 [`T-UI-002.4.1`](T-UI-002.4.1-入口侧口令协商与显式失败分类.md) 的 `A1`/`A6`。验证方式：该叶的两条探测用例（已建立 ⇒ 先索取且**不**试跑一次；从未建立 ⇒ 不索取）+ 端到端的 TOFU 用例。
- **A3 · 原生口令框取 stdlib，且在窗口循环之前调用**——前提：`tkinter.simpledialog` 无新依赖；
  壳侧调用点在 pywebview 窗口主循环**之前**（[`T-UI-002.2`](T-UI-002.2-桌面壳本体窗口托盘自启与通知接线.md) `A1`
  的「窗口占主线程」不与之冲突）。若错（冻结产物未打 Tk / 宿主无 Tk）：返工面＝框的实现
  （候选：平台原生 ctypes / 独立小窗口），落 [`T-UI-002.4.2`](T-UI-002.4.2-壳侧口令框与OS凭据库记忆.md)。
  验证方式：该叶的**惰性导入 + 显式失败**用例（CI 无 GUI）+ Windows 走查。
- **A4 · 口令的免重复输入交操作系统凭据库，不引第二份本地凭据落点**——前提：[02 §3](../../../../docs/技术架构-v2/02-L0-本地优先基座.md)
  新增的口令托管条款；凭据库缺失 / 不可用即**降级为每次索取**并显式告知，不静默。若错
  （宿主无凭据库后端，如无 Secret Service 的 Linux）：返工面＝降级路径的表现。验证方式：该叶的
  注入式 vault 用例 + 缺依赖时显式降级的用例。
- **A5 · 口令每次启动索取或经凭据库取，绝不落本地文件**——前提：[02 §3](../../../../docs/技术架构-v2/02-L0-本地优先基座.md)
  「凭据绝不出现在 Trace、日志明文、导出物中」与「无产品方恢复通道」。验证方式：该叶用例断言
  口令不出现在 argv / 子进程环境 / 日志 / 存储根内的任何文件。
