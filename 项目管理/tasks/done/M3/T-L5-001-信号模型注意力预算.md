# T-L5-001 · 信号模型 + 注意力预算

## 目标
交付 L5 层的头两段（[07 §1–§2](../../../../docs/技术架构-v2/07-L5-主动触达.md)）：**信号模型**（上游经 `SignalEmitted` 投递、L5 采纳）与**注意力预算**（情境 × 时段 × 内容类型三维矩阵 + 情境模式）。

**上游与本批的边界**（2026-10-06 读码核实）：

- `src/st_agent/l5/` **尚不存在**——本批是新层落地的第一刀；`tests/test_layering.py` 的 `LAYER_ORDER` 已预留 `l5`、`render_ledger.LAYERS` 已有 L5 条目，两层无需改。
- `SignalId` 已在 [01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 登记（**产生方＝L5**）、`SignalEmitted` 已在 [01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md) 事件清单（发布方 L1/L4、订阅方 L5）；但**上游尚无任何产生点**——本批即该负载结构的定义方。
- 统一配置注册表门面已由 [T-L1-012](../M2/T-L1-012-统一配置注册表门面.md) 交付（01 §7）；L2 的 [`MemoryPolicyFamily`](../../../../src/st_agent/l2/memory/registry_adapter.py) 给出了「适配器住本层、组合根注入」的先例，且 `PanelField.widget` 已含 `matrix`。

缺的只有信号模型与预算两面本身。

**拆分**（命中[拆分触发](../../../工作流.md)两条：验收 GWT>5 · 跨 [01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) / [§7](../../../../docs/技术架构-v2/01-平台共享契约.md) / [§11](../../../../docs/技术架构-v2/01-平台共享契约.md) 三个契约小节）——父转为分组节点，交付由两叶承接：

- [`T-L5-001.1`](T-L5-001.1-信号模型与采纳.md)——**信号模型与采纳**（07 §1）：`SignalEmitted` 负载的解释与校验 · `signal_id` 的确定性铸造 · 内容载体（结论 + 逐视角摘要，非单视角结论）· 显式拒绝面
- [`T-L5-001.2`](T-L5-001.2-注意力预算与情境模式.md)——**注意力预算与情境模式**（07 §2）：情境 × 时段 × 内容类型矩阵 · 情境模式与手动切换 · 格位判定与「汇总进日报」路由 · 注册进 01 §7（只读族）+ 「注意力预算地图」的可读投影

不拆成「一个任务里两段」的理由同 [D-079](../../../决策日志.md) / [D-080](../../../决策日志.md)：两段各有独立的失败面与验收，合在一起会让范围套件与留痕混在一起。

## 验收标准（Given-When-Then）

取自 [story-07](../../../../docs/PRD-v2-Agent/story-07-ambient-delivery.md) 与本任务范围内的架构段，逐条落到两叶（父级只汇总，不重复）：

- Given 用户首次配置注意力预算，When 完成配置，Then 得到「你的注意力预算地图」（情境 × 时段 × 内容类型的可读矩阵）+ 两条配置通道（对话 / 面板）读到同一份值 → [`.2`](T-L5-001.2-注意力预算与情境模式.md) GWT-1 / GWT-5
- Given 副驾产生一条日常（routine）信号，When 预算判定，Then 汇总进每日报告、**不单独触达**（除非用户显式把该级别配进该格位）→ [`.2`](T-L5-001.2-注意力预算与情境模式.md) GWT-3
- Given 用户切换情境模式（如从工作日切到休假），When 切换，Then 下一次判定即按新情境的预算 → [`.2`](T-L5-001.2-注意力预算与情境模式.md) GWT-4
- Given 上游投递一条 `SignalEmitted`，When L5 采纳，Then 得到一条六字段齐备的信号；缺字段 / 非法 `level` / 空结论 / 空逐视角摘要一律**显式拒绝**、不臆补 → [`.1`](T-L5-001.1-信号模型与采纳.md) GWT-1 / GWT-4
- 边缘：预算配置越界（未知级别 / 未知内容类型 / 时钟区间非法 / 空允许集）→ 显式拒绝，不静默落一个永不命中的格位 → [`.2`](T-L5-001.2-注意力预算与情境模式.md) GWT-6

> 渠道投递、升级链、每日报告本体、去重频控与推送疲劳监控**不在本任务**（[T-L5-002](T-L5-002-渠道适配器投递编排与升级链.md) / [T-L5-003](T-L5-003-每日报告去重频控推送疲劳监控.md)）。

## 假设与前提
- **A1 · 负载结构可由 L5 单方定义**（2026-10-06 ④ 对齐拍定）——前提：上游 L1/L4 尚无 `SignalEmitted` 产生点（`grep` 只命中契约与文档），而订阅方是 L5，故本批把负载结构登记进 [01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md)（[铁律 8](../../../工程宪法.md)，改码之前）。若错（上游另有既定结构）：返工面＝`.1` 的采纳面与 01 §11 登记项。验证方式：`.1` GWT-1 按契约结构构造事件即被采纳、偏离即被拒。
- **A2 · `signal_id` 由 L5 铸造且**不改契约产生方**——前提：[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 已登记「产生方＝L5」；本批只把它的**形态**从随机 uuid 收窄为**投递内容的确定性摘要**（§1 行文与 `contracts/identifiers.py` 的 `_generated_by` 同批写实）。若错（要求上游铸造）：返工面＝01 §1 行文 + `SignalId` 的构造路径。验证方式：同一事件重复采纳得同一 `signal_id`、`SignalId.generate()` 被拒的用例。
- **A3 · 预算矩阵的格位取值是「对象」，故落在 owner 写面而非统一标量落值面**——前提：[01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 的裁定「取值为对象 / 列表的条目不在统一落值面内，写面归各自 owner 的 API」，先例为 L2 `memory-policy`。若错（要求逐格位标量落值）：返工面＝`.2` 的族与条目切分（矩阵要拆成一格一条）。验证方式：族的 `apply` 对 `attention-budget/*` fail-closed 并点名 owner 的用例。
- **A4 · 手动模式切换即可，日历自动不在本批**——前提：[07 §2](../../../../docs/技术架构-v2/07-L5-主动触达.md) 的「手动切换或按日历自动」中，**用户日历面本仓尚不存在**（只有 L0 的市场交易日历）。若错（要求本批接日历）：返工面＝`.2` 的模式判定入口。验证方式：口径同批写进 07 §2；`.2` 只交付手动切换的用例。
