# T-L5-002.1 · 渠道适配器与渠道偏好

## 目标
交付 [07 §3](../../../../docs/技术架构-v2/07-L5-主动触达.md) 的**渠道面**：四类渠道适配器（桌面通知 / TTS / 邮件 SMTP / IM Webhook）的统一协议、渠道偏好（级别 → 有序渠道链 + 每级未读等待）与其 01 §7 登记，以及「渠道失效 → 显式提示 + 自动降级到下一渠道」与「离线标注 + 待发标记」。

**两处现成、本叶不重造**（2026-10-06 读码核实）：

- **出网类目**：`channel_delivery` 已在 [`EgressGateway`](../../../../src/st_agent/l0/net/gateway.py) 白名单（`tests/l0/test_net.py` 已有该 kind 用例），云端渠道只需**消费**它，不改网关。
- **原生通知入口**：[`ui/shell/notify.py`](../../../../src/st_agent/ui/shell/notify.py) 给出平台命令与 `send_notification`——但 [`test_ui_is_client_only`](../../../../tests/test_layering.py) **机器禁止任何层 import `st_agent.ui`**，故本叶只收一个**注入的鸭子端口**，真实实现由组合根／生产入口提供。

**边界**：本叶只到「把一条已备好的载荷投到某个渠道」为止——**升级链的时间维度（未读超时 → 下一级）、`delivery_id` 留痕、日报路由与文案个性化归 [`.2`](T-L5-002.2-投递编排与升级链.md)**；本叶的「降级到下一渠道」是**同一次投递内的即时失败转移**（渠道坏了换下一个），与时序升级不是一回事。

## 验收标准（Given-When-Then）
- **GWT-1**：Given 全新装置（无任何落盘偏好），When 取渠道偏好，Then 得三级（`emergency` / `important` / `routine`）齐备的**有序渠道链 + 每级未读等待**，逐级带**来源标注** `configured` / `default`；缺省取向是「少而准」——`emergency` 走完整链（桌面 → 邮件 → IM），`routine` 只占最轻的一级且**不带等待**（不升级）
- **GWT-2**：Given 渠道偏好，When `set_policy` 传入非法值（未知级别 / 未知渠道 / 空链 / 链内重复 / 等待时长 ≤0 或非整数 / 等待条数与链长不匹配），Then **逐类显式拒绝并点名违规点**，不落盘、不留痕；给定值与当前取值**相同**同样不落盘、不留痕（01 §7）
- **GWT-3**：Given 一条链 `[desktop, email, im_webhook]` 且 `email` 不可达，When 投递，Then 桌面渠道**照常投递成功即止**；Given `desktop` 失败，When 投递，Then 记下该步的**显式失败原因**并**自动降级**到 `email`——链尽仍失败则整次投递显式失败（**不静默丢弃**）
- **GWT-4**：Given 断网（`gateway.set_online(False)`），When 投递，Then **本地渠道照常成功**，**云端渠道**返回 `unavailable` 且 `pending_reconnect=True`、文案为「离线，暂无法发送」（02 §7 的 `full` / `none` 分级）
- **GWT-5**：Given 渠道偏好，When 经 01 §7 门面读，Then 与经本层自有面读到**同一份值**（两通道同源）；对象条目（每级的链 + 等待）的 `apply` **fail-closed 并点名 owner**（`ChannelPolicies` 的写面）
- **GWT-6**：Given 一条云端渠道，When 投递，Then 请求经网关 `kind="channel_delivery"` 发出、凭据**只经 `CredentialVault.use()`** 取明文（明文不进网关、不进审计）；Given 渠道未接线（TTS 无合成端口 / 云端无传输端口 / 桌面通知端口未注入），Then 该渠道 `health()` 与 `deliver()` 走**显式不可用并点名缺口**，**不假装能投递**

## 假设与前提
- **A1 · 原生能力与云端传输都取注入端口，本层不自持实现**（2026-10-06 ④ 对齐拍定）——前提：层表禁止 L5 import `st_agent.ui`（`test_ui_is_client_only`），且 02 §6 的「按次 sender 承载载荷」已是既有纪律。若错（要求 L5 自持平台命令 / SMTP 实现）：返工面＝`DesktopChannel` / `EmailChannel` 的构造面。验证方式：用例注入替身断言命令与载荷；并断言 `src/st_agent/l5/**` 无 `st_agent.ui` import。
- **A2 · 「即时失败转移」归本叶、「时序升级」归 `.2`**——前提：07 §3 的「渠道失效 → 自动降级到下一渠道」是**同一次投递内**的转移，07 §4 的升级链是**未读超时驱动**的时序推进；两者混淆会让 `delivery_id` 的级次语义失真。若错（要求本叶一并做时序升级）：返工面＝本叶与 `.2` 的分工线。验证方式：本叶用例断言「一次 `deliver` 调用内按链序走到底」，且不含任何时钟参数。
- **A3 · 渠道偏好的取值是「列表 + 等待」对象 ⇒ 族只读、写面归 owner**——前提：[01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 的「取值为对象 / 列表的条目不在统一标量落值面内」，先例＝L2 `memory-policy` / L5 `attention-budget` 的格位。若错（要求逐项标量落值）：返工面＝族与条目的切分。验证方式：GWT-5 的 fail-closed 用例。
- **A4 · 缺省链的取值取自 Story 的例，可被用户逐级覆盖**——前提：[story-07](../../../../docs/PRD-v2-Agent/story-07-ambient-delivery.md) 只给了 `emergency` 的完整链例（桌面通知 → 邮件 → IM）与总策略「少而准」，故其余级别按同类推。若错（产品要另一套缺省）：返工面＝`default_policies()`。验证方式：GWT-1 的偏好快照用例（逐级标注来源）。
- **A5 · TTS 与云端传输本仓均无实现 ⇒ 走显式不可用**——前提：读码核实 `grep` 无任何本地 TTS 合成面，且无 SMTP / Webhook 传输实现（真实链路归关卡 [T-INT-004](T-INT-004-M3集成关卡主动触达投递闭环.md) 的 `live` 面）。若错（要求本批真实合成）：返工面＝`TtsChannel`。验证方式：GWT-6 的未接线用例（`health().available is False` + 点名缺口）。
