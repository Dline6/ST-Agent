# T-L5-001.1 · 信号模型与采纳

## 目标
交付 [07 §1](../../../../docs/技术架构-v2/07-L5-主动触达.md) 的**信号模型与采纳面**：把上游经 `SignalEmitted` 投递的负载变成一条 `Signal`，并让「这一条是本层第一次见到、还是同一条的又一次投递」在**不做任何记账**的前提下可判。

**两处已现成、本叶不改**（2026-10-06 读码核实）：

- [`PlatformEvent`](../../../../src/st_agent/contracts/time_events.py) 已把 `SignalEmitted` 列入核心事件并强制它携带 `trace_id`（01 §11）——本叶只**消费**该信封。
- [`SignalId`](../../../../src/st_agent/contracts/identifiers.py) 已在 01 §1 登记（产生方＝L5）；本叶把它从「随机 uuid」收窄为「**投递内容的确定性摘要**」——形态仍合 `sig_<20 位十六进制>`，故**不改 `_pattern`，只走 `_generated_by`**（`generate()` 被拒、构造一律经 [`digest_id`](../../../../src/st_agent/contracts/identifiers.py)）。

**负载结构登记在 [01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md)**（本批改码之前）；本叶是它的**唯一解释方**。

## 验收标准（Given-When-Then）
- **GWT-1**：Given 一条 `SignalEmitted`（负载五字段齐备 + `trace_id`），When 采纳，Then 得 `Signal`——**六字段齐备**（`signal_id` / `level` / `content_ref` / `evidence_refs` / `dedup_key` / `source_trace_id`），且 `signal_id` 为 `sig_` + 20 位十六进制（01 §1 形态）
- **GWT-2**：Given 上游重试同一事件，When 采纳两次，Then 两次得**同一个 `signal_id`**；Given 内容 / 级别 / 溯源任一不同，When 采纳，Then 得**不同的 `signal_id`**（幂等锚点，且证据引用**顺序不同不算不同信号**）
- **GWT-3**：Given 内容载体（结论 + 逐视角摘要），When 采纳，Then `content_ref` 逐视角**并列保留**（每项 `lens_id` / `stance` / `summary`）——**不得为空、不合并为单一结论**（三视角分歧时三项各自保留其 `stance`）
- **GWT-4**：Given 负载缺字段 / 非法 `level` / 空 `conclusion` / 空逐视角摘要 / 非法 `source_trace_id` / `evidence_refs` 含非 §1 四类的引用 / 事件名不是 `SignalEmitted` / 事件缺 `trace_id`，When 采纳，Then 逐类**显式报错并点名字段**，**不臆补、不产出半截信号**
- **GWT-5**：Given 结论或任一条逐视角摘要含第一人称 / 情感表达 / 对话体（[01 §6](../../../../docs/技术架构-v2/01-平台共享契约.md) 执行点 2），When 采纳，Then **拒收**并点名命中的原文（中性化是平台硬约束，不在 L5 边界上开口子）

- **降级路径**：无上游产生点期间，采纳面照常可被注入采纳（本叶的验收方式即注入构造的事件）；负载不合契约时**显式失败**，不回落任何默认值

## 假设与前提
- **A1 · 负载只承载 01 §11 登记的五个字段，`signal_id` 不在其中**（2026-10-06 ④ 对齐拍定）——前提：负载结构由 L5 单方定义并登记进 01 §11（[铁律 8](../../../工程宪法.md)，本批改码之前已完成），`signal_id` 由采纳时铸造。若错（上游已在负载里放了 `signal_id`）：返工面＝采纳面（应改为「校验上游给的 id」而非铸造）+ 01 §1 的产生方。验证方式：GWT-1 / GWT-4 用例（含 `signal_id` 的负载不被当合法输入静默接受）。
- **A2 · 证据引用沿用 01 §3 的字符串形态（四类 §1 ID），不引入 `EvidenceRef` 的 `kind` 标注**——前提：[`LensOpinion.evidence_refs`](../../../../src/st_agent/contracts/capability_types.py) 即该形态，信号与观点共用同一口径才不会造出第二种证据引用表示。若错（要求带 `kind`）：返工面＝`SignalContent` / `Signal` 的字段与 01 §11 登记表。验证方式：GWT-4 的四类引用判据 + 非四类引用被拒的用例。
- **A3 · 逐视角摘要的 `lens_id` 只校验 §1 形态，不解析 L4 阵容**——前提：**L5 不向上读 L4 的阵容**（阵容是 L4 的取数面）；本层只验形态，看不清的视角不臆断。若错（要求核对视角确实在阵容内）：返工面＝采纳面需注入 L4 `LensRoster`（多一条跨层注入）。验证方式：未注册的 §1 形态 `lens_id` 被采纳、非法形态被拒的用例。
- **A4 · 中性化校验复用 01 §6 的同一份规则库**——前提：`NeutralityGuard.check_output` 是 01 §6 执行点 2 的唯一实现，本层不自造词表。若错（本层另有规则库）：返工面＝规则库归属（与 [D-053](../../../决策日志.md) 的记忆数据展示豁免口径同族）。验证方式：GWT-5 用例（用会命中的原文反证规则库确实生效）。
