# T-L5-003 · 每日报告 + 去重频控 + 推送疲劳监控

## 目标
交付 L5 的最后三段（[07 §5–§7](../../../../docs/技术架构-v2/07-L5-主动触达.md)）：**每日报告本体**（「给你的信」四段 + 模板注册为配置 + 空态）+ **去重与频控**（同 `dedup_key` 合并 + 格位节奏计数与排队）+ **推送疲劳监控**（连续忽略计数 + 询问信号 + 答复回流）。上游两批（信号模型与预算 [T-L5-001](T-L5-001-信号模型注意力预算.md)、渠道与投递编排 [T-L5-002](T-L5-002-渠道适配器投递编排与升级链.md)）已 done。

**上游与本批的边界**（2026-10-06 读码核实）：

- [`DeliveryOrchestrator.daily_report_queue()`](../../../../src/st_agent/l5/delivery.py) **已交付**——`route="daily_report"` 且 `status="queued"` 的待汇总项，每条**连推送文案（`title` / `body`，已过 01 §6）一起落盘**（[`delivery_store.py`](../../../../src/st_agent/l5/delivery_store.py) 的「留痕自足」口径），故日报面**只凭留痕即可组装**，不需要上游重发信号。
- [`DeliveryOrchestrator.ledger()` / `pending()` / `settlements()`](../../../../src/st_agent/l5/delivery.py) 给出**逐级留痕与结算**——「链尽未读 ⇒ `unacknowledged`」「未读超时 ⇒ `DeliverySettled(unread_timeout=True)`」即 §7 的**忽略**信号面；`mark_read` 已交付「已读」。
- [`AttentionBudget.resolve`](../../../../src/st_agent/l5/budget.py) 给的 `max_per_slot` 是**节奏上限**（[T-L5-001.2](T-L5-001.2-注意力预算与情境模式.md) 明写「本层只给上限、不做计数」）——**计数状态、合并与排队正是本任务的 §6**。
- [`ChannelPolicies`](../../../../src/st_agent/l5/channel_policy.py) 的 `set_policy` / `set_resend_on_reconnect` 与 [`AttentionBudget.switch_mode` / `set_cell`](../../../../src/st_agent/l5/budget.py) 是 §7「用户可减少/关闭/保持」的**落值面**（01 §7：对象类条目写面归各 owner 自有 API）。
- [`MemoryReader.query`](../../../../src/st_agent/l2/memory/reader.py) 是「Memory 更新摘要」的**唯一取数面**（04 §3.1；`task_type` 未登记即取全类型）。
- **`DeliveryRecord` 不含 `dedup_key`**——§6 的合并键与 §7 的「类」都需要它，本批按**只增**口径给留痕补上该字段（缺省空串 ⇒ 既有用例逐字节不变）。
- **01 §1 与 07 §7 的口径张力**（见 `## 假设与前提` A4）：`feedback_id` 的**产生方**已登记为**交互层（L3）**（[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md)，2026-09-28 由 [T-L3-005.2](../M1/T-L3-005.2-反馈采集点.md) 订正；[05 §9](../../../../docs/技术架构-v2/05-L3-对话主入口.md) 落地口径同），而 [07 §7](../../../../docs/技术架构-v2/07-L5-主动触达.md) 写「计数与用户答复作为 FeedbackEvent 交 L6」。本批按 01 §1 的**既有登记**落地（L5 不自铸 `feedback_id`），不改契约。

**拆分**（命中[拆分触发](../../../工作流.md)两条：验收 GWT>5 · 跨 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) / [§11](../../../../docs/技术架构-v2/01-平台共享契约.md) / [§6](../../../../docs/技术架构-v2/01-平台共享契约.md) / [08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md) 多个契约小节）——父转为分组节点，交付由三叶承接：

- [`T-L5-003.1`](T-L5-003.1-每日报告本体与模板配置.md)——**每日报告本体与模板配置**（07 §5）：四段「给你的信」· 生成时刻配置 · 模板注册进 01 §7（可订阅到任一渠道）· 空态 · 生成走完整 Trace
- [`T-L5-003.2`](T-L5-003.2-去重合并与频控计数.md)——**去重合并与频控计数**（07 §6）：同 `dedup_key` 短时合并（附触发次数）· 格位节奏计数 · 超限排队进下一次日报（不丢弃）
- [`T-L5-003.3`](T-L5-003.3-推送疲劳监控与答复回流.md)——**推送疲劳监控与答复回流**（07 §7）：连续忽略计数与阈值 · 询问信号 · 答复（减少/关闭/保持）落到渠道偏好 / 预算 · 计数与答复供 [T-L6-001](../M4/T-L6-001-反馈采集FeedbackEvent每周反思报告.md) 消费

不合并成一叶：三叶各有独立失败面（「报告组不出」「把该推的压没了」「反复骚扰同一条」），且拆法同 [D-079](../../../决策日志.md) / [D-080](../../../决策日志.md) / [D-081](../../../决策日志.md) / [D-082](../../../决策日志.md)。

## 验收标准（Given-When-Then）
取自 [story-07](../../../../docs/PRD-v2-Agent/story-07-ambient-delivery.md) 与本任务范围内的架构段，逐条落到三叶（父级只汇总，不重复）：

- Given 到用户配置的日报时刻，When 生成，Then 产出「给你的信」含**昨日回顾 + 今日关注 + 多视角摘要 + Memory 更新摘要**四段、生成过程**走完整 Trace** → [`.1`](T-L5-003.1-每日报告本体与模板配置.md) GWT-1 / GWT-4
- Given 某日无值得推送的信号，When 生成日报，Then 明确写「今天没有需要打扰你的事」、**不硬凑内容** → [`.1`](T-L5-003.1-每日报告本体与模板配置.md) GWT-3
- Given 日报结构模板，When 配置，Then 经 01 §7 的对话 / 面板两通道读到同一份值、**可订阅到任一渠道** → [`.1`](T-L5-003.1-每日报告本体与模板配置.md) GWT-2
- Given 同一 `dedup_key` 短时间多次触发，When 处理，Then **合并为一条**并附**触发次数**（呼应 anti-metric「不追求推送量」） → [`.2`](T-L5-003.2-去重合并与频控计数.md) GWT-1
- Given 某格位节奏上限 `max_per_slot` 已用尽，When 又一条该格位信号，Then **排队进下一次日报**，**不丢弃** → [`.2`](T-L5-003.2-去重合并与频控计数.md) GWT-2
- Given 用户连续忽略某类推送达阈值（可配，默认 5），When 检测到，Then 产生**询问信号**「这类推送对你有用吗？要不要减少？」 → [`.3`](T-L5-003.3-推送疲劳监控与答复回流.md) GWT-1
- Given 用户答复「减少 / 关闭 / 保持」，When 落值，Then 经既有配置写面生效（渠道偏好 / 预算）且**可回溯**；计数与答复**可被 L6 消费** → [`.3`](T-L5-003.3-推送疲劳监控与答复回流.md) GWT-2 / GWT-3

> 端到端装配（跨层组合根 `build_m3_runtime`、真实 SMTP / Webhook 的 `live` 复核）归关卡 [T-INT-004](T-INT-004-M3集成关卡主动触达投递闭环.md)。

## 假设与前提
- **A1 · 按阶段拆三叶**（2026-10-06 ④ 对齐拍定）——前提：日报面 / 频控面 / 疲劳面各有独立失败面与验收，且跨 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) / [§11](../../../../docs/技术架构-v2/01-平台共享契约.md) / [§6](../../../../docs/技术架构-v2/01-平台共享契约.md) / [08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md) 多个契约小节。若错（要求更细 / 更粗的粒度）：返工面＝父子任务文件与关卡 [T-INT-004](T-INT-004-M3集成关卡主动触达投递闭环.md) 的 `depends_on` 指向。验证方式：三叶各自的范围套件与 `verify_docs --strict` 检查 7。
- **A2 · 日报与计数只凭本层留痕组装**（2026-10-06 ④ 对齐拍定）——前提：[T-L5-002.2](T-L5-002.2-投递编排与升级链.md) 的留痕已连文案一起落盘（[`delivery_store.py`](../../../../src/st_agent/l5/delivery_store.py) 的「留痕自足」），故日报面与疲劳面**不依赖进程内信号上下文**、可跨进程重建。若错（要求上游重发信号或另存一份上下文）：返工面＝[`.1`](T-L5-003.1-每日报告本体与模板配置.md) / [`.3`](T-L5-003.3-推送疲劳监控与答复回流.md) 的取材面。验证方式：新开一个构造器续读既有留痕即可组出日报 / 计出忽略数（用例钉住）。
- **A3 · 去重与疲劳的「类」取 `dedup_key`**（2026-10-06 ④ 对齐拍定）——前提：[07 §1](../../../../docs/技术架构-v2/07-L5-主动触达.md) 的 `dedup_key` 即「同一标的同一事件类型」的合并键，是信号面上**唯一现成**的「类」标识（`Signal` 无别的分类字段）。若错（要求按 `level` 或另一套分类）：返工面＝[`.2`](T-L5-003.2-去重合并与频控计数.md) / [`.3`](T-L5-003.3-推送疲劳监控与答复回流.md) 的计数键与 07 §6–§7 行文。验证方式：同 `dedup_key` 合并 / 跨 `dedup_key` 不合并的成对用例。
- **A4 · L5 不自铸 `feedback_id`，答复回流经交互层（L3）**（2026-10-06 ④ 对齐拍定）——前提：[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 已把 `feedback_id` 的产生方登记为**交互层（L3）**（[05 §9](../../../../docs/技术架构-v2/05-L3-对话主入口.md) 落地口径同），而 [07 §7](../../../../docs/技术架构-v2/07-L5-主动触达.md) 的「作为 FeedbackEvent 交 L6」与它字面有张力。本批按**既有登记**落地：L5 只产**询问信号**与**计数**，答复由交互层采集并铸 `FeedbackEvent`（`feedback_id` 仍归 L3），L5 经 `FeedbackRecorded` 的**订阅面**消费答复。**不改契约**（既不新增产生方、也不改 01 §1）。若错（要求 L5 自铸）：返工面＝[`.3`](T-L5-003.3-推送疲劳监控与答复回流.md) 的答复承接面 + [01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 的产生方行文（**须走 [铁律 8](../../../工程宪法.md) 的契约先行**）。验证方式：`grep` 断言 `src/st_agent/l5/**` 不产 `feedback_id`；答复用例经注入的订阅面往返。
