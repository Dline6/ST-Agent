# T-L5-002.3 · 平台事件投递机制与 L5 装配缝

## 目标
补上 [01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md) 一直缺的**投递（发布 / 订阅）面**——「下层向上层只通过事件通信」此前只有**形态与产生方 / 订阅方**的登记，没有承载机制（[L3 册 `A2`](../../../遗留问题/L3-遗留问题.md)）；并交付 L5 的**薄装配缝** `build_l5`，把 [T-L5-001.2](T-L5-001.2-注意力预算与情境模式.md) 点名的 `AttentionBudgetFamily` 注入点与本批的渠道 / 编排面接起来。

**契约先行**（[铁律 8](../../../工程宪法.md)，**改码之前**已落）：[01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md) 新增「事件投递口径」表（总线归属 L1 / 鸭子端口接入 / 同步按序派发 / 失败显式化 / 未接通不假装 / 不落盘六条）；**不新增事件名与负载结构**（仍归各小节）。

**边界**：本叶只做**进程内**投递（后端单进程内的跨层通知）。「后端 → 可分离 UI 客户端」的**跨进程**推送是表现层消费面的事（[00 §1.1](../../../../docs/技术架构-v2/00-架构总览.md)），**不在本叶**；M3 的跨层组合根 `build_m3_runtime` 归关卡 [T-INT-004](T-INT-004-M3集成关卡主动触达投递闭环.md)（先例＝`build_m1_runtime` / `build_m2_runtime` 由 T-INT-002 / T-INT-003 交付）。

## 验收标准（Given-When-Then）
- **GWT-1**：Given 一条 `MemoryConflictDetected`（L2 产生），When 经总线发布，Then L3 的冲突裁决面**收到并消费**——**不再靠调用方手递**（[L3 册 `A2`](../../../遗留问题/L3-遗留问题.md) 解封条件要求的那一条链路接通）；Given 未注入总线，When 发布，Then 记 `delivered=False` + **点名归属**，不假装送达、不静默丢弃
- **GWT-2**：Given 两个订阅者按序登记，When 发布一条事件，Then **按登记顺序**同步派发，各自收到一次；同一事件序列重复发布得**同一派发序列**（决定论，可离线重复验证）
- **GWT-3**：Given 某订阅者抛错，When 发布，Then 该次的返回**逐订阅者**记结果（受理 / 异常 + 原因），异常**不被吞成「已送达」**，且**其余订阅者照常收到**（不阻断）
- **GWT-4**：Given 一条 `SignalEmitted`（[01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md) 的五字段负载 + `trace_id`），When 经总线发布，Then L5 的采纳面收到并产出 `Signal`（复用 [T-L5-001.1](T-L5-001.1-信号模型与采纳.md) 的 `adopt_signal`，**不重写校验**）；缺字段 / 非法负载仍走既有的**显式拒绝**
- **GWT-5**：Given 一个 `Store` 与已交付的 L1 运行时，When `build_l5(...)`，Then 得一个装配好的 L5 面（`AttentionBudget` + 其族**已注入** 01 §7 门面 + 渠道适配器 + `DeliveryOrchestrator` + 事件端口），且**不 import 表现层、不反向依赖上层**（[铁律 7](../../../工程宪法.md) 机器断言）
- **GWT-6**：Given 订阅句柄，When 注销后再发布，Then 该订阅者**不再收到**（注销生效，无残留）；Given 重复注销同一句柄，Then 幂等无害

## 可关闭的遗留
- [L3 册 `A2`](../../../遗留问题/L3-遗留问题.md)（平台事件的投递机制未立）——**本批关闭**。解封条件要求的「`T-L5-002` 交付投递机制、且 L2→L3 的 `MemoryConflictDetected` 经该通道接通（不再靠调用方手递）」由本叶兑现；机制形态＝**进程内 pub/sub 总线**（2026-10-06 ④ 对齐拍定，[D-082](../../../决策日志.md)），[01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md) 的投递口径**改码之前**已补

## 假设与前提
- **A1 · 总线住 L1（`st_agent.l1.events`）**（2026-10-06 ④ 对齐拍定）——前提：[01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md) 的发布方 / 订阅方跨 L1–L6，住 L1 时全部接入方向合法（L2 / L3 / L5 皆向下依赖 L1；**L0 不发布事件**——`NetworkRequestLogged` 由查询侧按需组装，见 [02 §6](../../../../docs/技术架构-v2/02-L0-本地优先基座.md)，故总线住 L1 不引 L0 反向依赖）；与 [D-067](../../../决策日志.md) 把 01 §7 门面放 L1 是**同一裁法**。若错（要求总线下沉 L0 或上浮 L5）：返工面＝总线落点与各层接入。验证方式：GWT-5 的装配用例 + [`tests/test_layering.py`](../../../../tests/test_layering.py)。
- **A2 · 接入形态取鸭子端口、层间不互相 import**——前提：既有先例一致（L3 `DispatchBus` 的 `analyze` 去向、L3 `FeedbackCollector` 的 `sink`），且 `publish(event) -> bool` 与 `subscribe(...)` 两条签名足够表达「受理 / 未接通」。若错（要求各层直接 import 总线）：返工面＝各接入点的构造面。验证方式：GWT-1 / GWT-3 的注入替身用例。
- **A3 · 同步按序派发**——前提：决定论优先（与 [L1 调度器](../../../../src/st_agent/l1/scheduler/scheduler.py) / 网关的同步口径一致），可离线重复验证；代价是发布方会被订阅者的耗时阻塞，本仓事件都短（无网络、无长计算）。若错（要求异步）：返工面＝`EventBus.publish` 的签名与 `DispatchResult`（异步下无法在发布这一跳得知逐订阅者结果）。验证方式：GWT-2 / GWT-3。
- **A4 · 跨进程推送不在本叶**——前提：[00 §1.1](../../../../docs/技术架构-v2/00-架构总览.md) 的「后端常驻为主体、UI 为可分离客户端」下，跨进程推送是表现层消费面的事；本叶只做进程内。若错（要求本叶一并交付回环推送）：返工面＝本叶范围（须引入 SSE / 回环面）。验证方式：01 §11 的投递口径表已明写该边界。
- **A5 · `build_m3_runtime` 归关卡 T-INT-004**——前提：[工作流](../../../工作流.md)「跨层装配与端到端验证不按此拆分——归里程碑集成关卡」，且先例＝`build_m1_runtime` / `build_m2_runtime` 由 T-INT-002 / T-INT-003 交付。本叶只交付 **L5 自持的薄缝**（`build_l5`），由关卡调用。若错（要求本批一并造 M3 组合根）：返工面＝本叶范围与 `app.py` 的 `APP_ALLOWED_IMPORTS`。验证方式：GWT-5 的 `build_l5` 装配用例。
