# T-L5-003.3 · 推送疲劳监控与答复回流

## 目标
交付 [07 §7](../../../../docs/技术架构-v2/07-L5-主动触达.md) 的**推送疲劳监控**：每类信号维护「连续忽略计数」，超阈值（可配，默认 5）→ 产生**询问信号**「这类推送对你有用吗？要不要减少？」；用户答复（**减少 / 关闭 / 保持**）经既有配置写面生效；**计数与答复供 [T-L6-001](../../T-L6-001-反馈采集FeedbackEvent每周反思报告.md)（L6）消费**。按 [01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 的既有登记，L5 **不自铸 `feedback_id`**——答复由交互层采集（见 `## 假设与前提` A1）。

## 验收标准（Given-When-Then）
- **GWT-1**：Given 某一 `dedup_key` 的推送被**连续忽略**达阈值（可配，默认 5；「忽略」＝链尽 `unacknowledged` / 未读超时结算，[T-L5-002.2](T-L5-002.2-投递编排与升级链.md)），When 监控推进，Then 产生一条**询问信号**并经既有渠道投出（得一枚可寻址的 `delivery_id`）；Given 中间有一次**已读**，Then 该类的**连续**计数**归零**（不是累计计数）；Given 同类已发问而用户**尚未答复**，Then **不重复发**；Given 用户已答复过，Then 须**再攒满一轮阈值**（连续计数 ≥ 上次发问时的计数 + 阈值）才复问——否则「保持」之后计数不变、下一轮会立刻再问；Given 未达阈值，Then 不发问（默认「少而准」）
- **GWT-2**：Given 用户对询问答复**减少 / 关闭 / 保持**，When 落值，Then 三种落点各自生效且**可回溯**——**「减少」**经 [`.1`](T-L5-002.1-渠道适配器与渠道偏好.md) 的**既有写面**收窄该级别的渠道链（01 §7 留痕、可回滚）；**「关闭」**记入 L5 自持的**静音清单**（逐 `dedup_key`；粒度小于渠道偏好与预算任一既有面，故本层承载），[`.2`](T-L5-003.2-去重合并与频控计数.md) 的频控面读它把该类**改判为汇总进日报**（关闭单独触达 ≠ 丢弃）；**「保持」**不改配置、只把该类连续计数**归零**并记下「已询问」；答复对象（询问的 `delivery_id`）与改动**一一对应可解释**
- **GWT-3**：Given 疲劳计数与答复，When 被 L6 读取，Then 逐类的**连续忽略计数 / 阈值 / 最近答复**在**本层可读面**上齐备且带时间锚（`as_of`）——满足 [07 §7](../../../../docs/技术架构-v2/07-L5-主动触达.md)「交 [08-L6](../../../../docs/技术架构-v2/08-L6-反思演进.md) 消费」的实质；**答复作为 `FeedbackEvent` 的送达**仍走交互层的采集（`feedback_id` 归 L3，[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md)），本叶经 `FeedbackRecorded` 的**订阅面**消费答复
- **GWT-4**：Given 询问文案，When 产出，Then **过 [01 §6](../../../../docs/技术架构-v2/01-平台共享契约.md) 执行点 2**（中性问句：无第一人称、无情绪词、无对话体，[铁律 2](../../../工程宪法.md)），命中即显式抛错；Given 计数条目损坏，Then 显式暴露（不把「读不出」静默当成「没疲劳」）
- **GWT-5**：Given 同一 `(留痕状态, now)`，When 重复推进监控，Then 结论恒同、**不重复发问**（显式时刻的纯函数推进；询问的去重键由 `(类, 计数轮次)` 确定性派生）

## 假设与前提
- **A1 · L5 不自铸 `feedback_id`，答复回流经交互层（与父 `A4` 同源）**——前提：[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 已登记 `feedback_id` 产生方＝**交互层（L3）**（[05 §9](../../../../docs/技术架构-v2/05-L3-对话主入口.md) 落地口径同），而 [07 §7](../../../../docs/技术架构-v2/07-L5-主动触达.md)「计数与用户答复作为 FeedbackEvent 交 L6」与之字面有张力。本批按**既有登记**落地：答复由交互层采集并铸 `FeedbackEvent`（`target` 取询问推送的 `delivery_id`，[08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的三类之一），本叶经 `FeedbackRecorded` 的**订阅面**消费；`answer(...)` 是同一落点的**第二条通道**（无 UI 时的直接承接，两通道同源、留痕一致）。**不改契约**。若错（要求 L5 自铸）：返工面＝本叶答复承接面 + [01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 产生方行文（须走 [铁律 8](../../../工程宪法.md) 契约先行）。验证方式：`grep` 断言 `src/st_agent/l5/**` 不产 `feedback_id`；答复经两条通道往返得同一留痕。
- **A2 · 询问复用 `Signal` 承载**——前提：[07 §7](../../../../docs/技术架构-v2/07-L5-主动触达.md) 原文即「产生**询问信号**」，且 [`signal.py`](../../../../src/st_agent/l5/signal.py) 对 `lens_id` **只校验形态、不解析 L4 阵容**，故 L5 的疲劳观察可作为一条逐视角摘要落进 `content_ref`，从而**零改动** [T-L5-002.2](T-L5-002.2-投递编排与升级链.md) 的 `delivery.py` 就得到可寻址的 `delivery_id`（[08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的反馈对象三类之一）。若错（要求询问不入信号模型、另造一条非信号推送面）：返工面＝本叶询问承载 + [`delivery.py`](../../../../src/st_agent/l5/delivery.py) 的公开面（**只增**）。验证方式：询问投出落一条 `DeliveryRecord`（含 `delivery_id`）、其 `content_ref` 形态合法且过 01 §6 的用例。
- **A3 · 「类」＝ `dedup_key`**（与父 `A3` / [`.2`](T-L5-003.2-去重合并与频控计数.md) `A2` 同源）——前提：[07 §1](../../../../docs/技术架构-v2/07-L5-主动触达.md) 的 `dedup_key` 是信号面上唯一现成的「同一标的同一事件类型」标识。若错（要求按 `level` 或另一套分类）：返工面＝计数键与 [07 §7](../../../../docs/技术架构-v2/07-L5-主动触达.md) 行文。验证方式：同类连续忽略合并计数、跨类不串的成对用例。
- **A4 · 计数的「连续」以**已读**打断**——前提：[07 §7](../../../../docs/技术架构-v2/07-L5-主动触达.md) 原文「**连续**忽略计数」；[T-L5-002.2](T-L5-002.2-投递编排与升级链.md) 的 `mark_read` 会**按信号**把同信号在途级一并结算为 `read`，故打断判据取留痕状态即可。若错（要求累计而非连续）：返工面＝计数推进与 GWT-1。验证方式：GWT-1 的「中间已读 ⇒ 归零」用例。
