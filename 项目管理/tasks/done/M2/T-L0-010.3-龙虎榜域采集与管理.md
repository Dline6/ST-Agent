# T-L0-010.3 · 龙虎榜域采集与管理

## 目标

交付**龙虎榜域**的完整链路，服务 [L4 情绪视角](../../../../docs/PRD-v2-Agent/story-04-multi-lens.md) 的「龙虎榜资金」维度。

- **表组按实体分两表**（**关键**：两源的差异是**实体粒度不同**，不是主备——[D-030](../../../决策日志.md) / `Q-003` 决议）：
  - `dragon_tiger`——**上榜记录**（`code` / `trade_date` / 上榜原因 / 买卖净额 / 换手率 / `source_id`）
  - `dragon_tiger_seat`——**席位明细**（`code` / `trade_date` / 席位 / 买入额 / 卖出额 / 排名 / `source_id`）
- **主备**：上榜记录以东财为主、**深交所官方**兜底（`coverage=sz`，**仅深市**）；**席位明细暂无已验证源**
- **新鲜度**：盘后 T+0 晚（当日盘后可得），逐日增量
- **范围**：全市场端点会带回 `security` 未收录代码（如北交所）→ 经 `.1` 的**预过滤 + `filtered_unmapped` 计数**处置（[D-032](../../../决策日志.md)），**不得**让批次失败

### 实测校正（2026-09-27 真实探测，**推翻原设计两处**）

| 原设计 | 实测 | 处置 |
|---|---|---|
| 「交易所官方」覆盖沪深 | `ShowReport/data` 的 `CATALOGID=1842_xxpl` 是**深交所专用** | 任务改名 `info_dragon_tiger_exchange` → **`info_dragon_tiger_szse`**、`coverage` 由 `all` → **`sz`** |
| 官方为**席位明细主源**（一手营业部明细、排名可推导） | 该端点只给**上榜记录**（`dqrq/zqdm/plyjc/cjje/plyy`），**不含席位** | 任务目标表由 `dragon_tiger_seat` → **`dragon_tiger`**、角色由 `primary` → **`backup`**；**席位明细无可信源**，登记 [L0 册 `F2`](../../../遗留问题/L0-遗留问题.md) |

另：东财市场级端点的 `filter` 含 `<` / `>`，**必须 `urlencode`**（直接拼串实测 400）——已修正并加回归用例（`tests/l0/test_info_parsers.py::TestUrlEncodingRegression`）。

## 验收标准（Given-When-Then，从 Story 抄）

（④ 对齐定稿；实现与机器可查证据见 `tests/l0/`）
  - GWT-1 两实体可分：Given 一次龙虎榜同步，When 查上榜记录与席位明细，Then 两表各自可查、粒度不同的事实**不混在一张表里**
  - GWT-2 席位的两个源可辨：Given 明细来自官方、排名来自东财，When 查询，Then 每条行带 `source_id`，**不冒充**单一来源
  - GWT-3 预过滤不炸批：Given 全市场批次含未收录代码，When 同步，Then 批次成功、计数如实登记
  - GWT-4 逐日增量：Given 已同步 T-1，When 同步 T，Then 仅追加 T 的记录，历史不动

## 假设与前提

- A1 上榜记录的**业务键**取 `(code, trade_date)`——每标的每交易日**一行**，多原因合并入 `reasons` / 若错（须按原因分行）：跨源去重将依赖原因串措辞（两源措辞不一 → 重复行）/ 验证：GWT-1「多原因合并为一行」+ GWT-3 跨源一行。
- A2 席位明细以**交易所官方**为主源（一手营业部明细、排名可推导），东财 TOP5 为补充 / 若错（以东财为主）：`rank` 仅覆盖前 5、明细不全 / 验证：GWT-2 两源各带 `source_id` 可辨。
- A3 席位业务键含 `rank`（`(code, trade_date, side, rank)`）——同一席位在两个源下若排名不同会被视为两行 / 若错（须按席位名去重）：需引入席位名归一化 / 验证：GWT-1「rank 是业务键的一部分」。
- A4 全市场端点会带回主档外代码，故**预过滤必须在同步侧**（否则硬外键炸整批）/ 若错：`failed` 而非过滤 / 验证：GWT-3。
