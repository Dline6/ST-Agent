# T-L0-015.2 · 深市互动易真实抓取器与解析（两步流程 + 翻页）

> 2026-09-28 由 `T-L0-015` ④ 对齐拆分（叶 `.2` 依赖 [`.1`](T-L0-015.1-关注面注入通道与coverage合约.md) 的注入通道）。

## 目标

把 [`HttpInfoFetcher._fetch_info_sentiment_qa_irm`](../../../../src/st_agent/l0/info/fetch.py) 从「每轮抛能力缺口」换成**真实采集**：按注入的关注面**逐公司**走两步流程（先定位 `orgId`、再取问答），并翻页至 `totalPage`（页数上限兜底）。落表与落文件复用既有 [`InfoSync._load_sentiment_qa`](../../../../src/st_agent/l0/info/sync.py)。

## 验收标准（Given-When-Then）

- **GWT-1 两步流程**：对关注面内每只**深市**标的：① `POST https://irm.cninfo.com.cn/newircs/index/queryKeyboardInfo`，body `{"keyWord": 六位代码}` → `data[0].secid` ＝ `orgId`；② `POST https://irm.cninfo.com.cn/newircs/company/question`，参数**在 query string**（`stockcode` / `orgId` / `pageSize` / `pageNum` / `keyWord=""` / `startDay=""` / `endDay=""`）。
- **GWT-2 翻页**：按载荷 `totalPage` 翻页、`pageNum` 递增；页数上限兜底（循 [`_SSE_FEED_MAX_PAGES`](../../../../src/st_agent/l0/info/fetch.py) / `_SZSE_MAX_PAGES` 范式），上限内已翻到 `totalPage` 即停。
- **GWT-3 覆盖域＝关注面 ∩ 深市**：只对 `sz.` 前缀标的发请求；**非深市标的不发请求**（源只覆盖深市，实测沪市公司返 0 条）——这是**源知识**，不是静默丢弃；行为与理由写进抓取器 docstring 与 [05](../../../../docs/数据库设计-BaoStock数据层/05-同步策略与新鲜度契约.md)。
- **GWT-4 未回复是合法态**：`attachedContent=None` → `answer=None` **不丢行**（否则系统性漏掉「公司尚未回应」这一风险信号）。
- **GWT-5 解析稳健 / fail-fast**：`parse_sentiment_qa_irm` 按真实载荷取键（`stockCode` / `mainContent` / `attachedContent` / `attachedAuthor` / `pubDate`，ms 时间戳经 `_stamp`）；**「无问答」与「结构变更」必须可区分**——定位 `orgId` 的第一步行载荷无 `data`、第二步载荷无 `rows`（且非合法空）时抛 `InfoValidationError`，不返回空冒充。
- **GWT-6 真实端点可复跑**：[`tests/live`](../../../../tests/live) 补一条 `@pytest.mark.live` 用例（单只深市标的、串行、只读、不写库），把「两步端点可达 + 解析出行」从一次性手工探测变成可复跑事实（假设 A1 的验证口）。

## 接口面

- **输入**
  - [`.1`](T-L0-015.1-关注面注入通道与coverage合约.md) 交付的 [`InfoFetcher.fetch_task(task_key, window, *, codes=…)`](../../../../src/st_agent/l0/info/fetch.py)（`codes` ＝ 注入的关注面 stock_id 元组；已 `done` 后可用）。
  - 端点知识（**取知识不取依赖**）：[`akshare` `stock_irm_cninfo.py`](https://github.com/akfamily/akshare/blob/main/akshare/stock_feature/stock_irm_cninfo.py) 与 [`simonlin1212/a-stock-data`](https://github.com/simonlin1212/a-stock-data) §10.1 —— 两者一致给出上述两步契约与「第二步参数放 query string（否则 400）」。
- **输出**
  - [`HttpInfoFetcher._fetch_info_sentiment_qa_irm`](../../../../src/st_agent/l0/info/fetch.py)（真实实现，替换现能力缺口分支）

  - 落盘：经 [`InfoSync._load_sentiment_qa`](../../../../src/st_agent/l0/info/sync.py) 写 `sentiment_qa`（`market='sz'`、`source_id='cninfo_irm'`）+ 问答正文落 `data_cache` 文本目录（[D-031](../../../决策日志.md)）
- **不交付**：`InfoSync` 通道与契约变更（属 `.1`）；`InfoFilter`/预过滤改动（复用既有）

## 假设与前提

- **A1** 两步端点/参数契约（URL、`keyWord` 入 body、第二步参数入 query string、`secid` ＝ `orgId`、`pubDate` 为 ms 时间戳）以两个独立第三方**一致**为准 ｜ 若错则抓取器按实测校正、离线夹具同步 ｜ 验证：本叶 GWT-6 的 `tests/live` 用例（真实请求）。
- **A2** 关注面规模下「每标的 2+ 次请求」可接受（[D-037](../../../决策日志.md) 已据此否决**全市场**迭代 A，保留关注面）｜ 若错（关注面本身很大）则须加限流/分批，属运营口径 ｜ 验证：`tests/live` 单标的计时 + 05 的触发节奏登记。
- **A3** 互动易**无全市场流**、只有按公司口（[L0 册 `F1`](../../../遗留问题/L0-遗留问题.md) 实测；`akshare` / `a-stock-data` 均只做按公司）｜ 若错（存在未发现的全市场口）则任务形状可简化 ｜ 验证：D-037 的既有实测结论（本叶不重探）。
