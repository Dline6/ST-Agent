# T-L0-012 · 龙虎榜席位明细补齐与沪市官方源接入

## 目标

闭掉 [L0 遗留册 `F2` / `F3`](../../../遗留问题/L0-遗留问题.md)：`dragon_tiger_seat` 表在真实源下**恒为空**（[`parse_dragon_tiger_szse`](../../../../src/st_agent/l0/info/fetch.py) 硬返回空元组、东财**市场级**端点不返席位），且沪市上榜记录**只有东财一个源**（官方端点是深交所专用，`coverage` 仅 `sz`，无官方兜底）。本任务接上深交所官方**席位明细**端点——调用契约从 `1842_xxpl` 响应自带的 `bz` 链接解出，非猜测——并新增**上海证券交易所**官方源与 `coverage=sh` 任务。

**已实测的端点契约（2026-09-27 真实请求，非源码推断）**：

- **深交所席位明细**：`1842_xxpl` 每行的 `bz` 字段内嵌完整钻取链接 `…CATALOGID=1842_detal&TABKEY=tab1,tab2&DQRQ=<日>&ZQDM=<代码>&ZBDM=<原因类别>…`；`TABKEY=tab1,tab2` 时第二个块返 10 行，字段 `mmlb`（买1/卖1）/ `zsmc`（营业部名）/ `mrje`（买入金额）/ `mcje`（卖出金额）。`ZBDM` **随上榜原因变**（实测见 `0901` / `0902` / `0921` / `1001`），故**不得硬编码**。实测样本：2026-07-10 / `000004` / `ZBDM=0921` → `{"mmlb":"买1","zsmc":"中信证券股份有限公司深圳分公司","mrje":"802,800","mcje":"0"}`。
- **上交所每日交易信息**：`https://query.sse.com.cn/infodisplay/showTradePublicFile.do?jsonCallBack=cb&isPagination=false&dateTx=<日>`（Referer `https://www.sse.com.cn/disclosure/diclosure/public/`）；实测 2026-07-10 → `fileContents` **510 行 / 35633 字符**，含「买入营业部名称」180 处、买入/卖出营业部各 25 处——**上榜记录与营业部席位同在**，形态为**定宽文本**（`(N) 名称  金额`）。

## 验收标准（Given-When-Then）

- **GWT-1 席位明细非空且可回溯**：Given 一个真实交易日（有上榜记录），When 跑 `info_dragon_tiger_szse`，Then `dragon_tiger_seat` 得非空行，字段 `(code, trade_date, side, rank, seat_name, buy_amount, sell_amount)` 齐备，且每行可回溯到其 `(code, trade_date, 上榜原因)`。
- **GWT-2 契约取自响应而非硬编码**：Given `1842_xxpl` 的真实响应，When 解析，Then 逐行从 `bz` 解出 `DQRQ` / `ZQDM` / `ZBDM` 并据此钻取；`ZBDM` 的取值集**不由本任务写死**（新原因类别出现时不需要改代码）。
- **GWT-3 沪市官方源落地**：Given 新源 `sse` 与任务 `info_dragon_tiger_sse`（`coverage=sh`、`role=backup`），When 抓一个真实交易日，Then 得上榜记录 + 营业部买卖席位；文件内的**非股票标的**（实测含债券，如代码 `0664`）经主档预过滤，并按 `filtered_unmapped` 计数（[D-032](../../../决策日志.md)）。
- **GWT-4 结构变更 fail-fast**：Given 官方端点结构变化（`1842_xxpl` 缺 `bz` / 上交所缺 `fileContents` / 定宽文本解析不出），When 抓取，Then **抛错而非返空**——「该日无数据」与「抓取或解析失败」必须可区分（对齐既有 `_sse_parse_feed` 的 fail-fast 范式）。
- **GWT-5 登记一致**：When 收工，Then [`data_source`](../../../../docs/数据库设计-BaoStock数据层/schema.sql) 增 `sse` 行、[05 登记表](../../../../docs/数据库设计-BaoStock数据层/05-同步策略与新鲜度契约.md) 增 `coverage=sh` 的官方任务行，且该文档「真实端点核验」段的措辞校正（现写「官方只给**上榜记录**、且**仅覆盖深市**；**席位明细暂无已验证源**」——两句均已被实测推翻）。

## 假设与前提

- **A1** 上交所 `fileContents` 在非交易日（`isTradeDate=false`）为**空**，属「该日无数据」而非抓取失败 / 若错（非交易日也应有内容、或交易日为空是正常）：GWT-4 的两态判据须重定 / 验证：交易日与非交易日各抓一次对账。
- **A2** 深交所「逐 `(code, trade_date, 上榜原因)` 钻取明细」的请求量在限流约束下可接受（单交易日上榜量级为数十行、每行一次请求） / 若错（须批量化或分级抓取）：同步时长与限流预算须重估 / 验证：真实交易日全量跑一次并计时、核对 `NetworkEvent` 条数。
- **A3** 东财侧可另加 `RPT_ORGANIZATION_SEATNEW`（机构席位统计）/ `RPT_OPERATEDEPT_ACTIVE`（活跃营业部）等报表作补充源 / 若错（报表名或字段有变）：仅少一层冗余，**不影响 F2 关闭** / 验证：**akshare 源码佐证，本任务不依赖**（若采信须逐条实测）。
- **A4** 上交所每日交易信息文件对沪市**全部证券**（含债券/基金）生效，主档预过滤足以收敛到股票 / 若错（同一 `code` 在债券与股票间歧义）：须补交易所/证券类别判据 / 验证：GWT-3 的 `filtered_unmapped` 计数 + 抽查若干非股票行的过滤结果。
