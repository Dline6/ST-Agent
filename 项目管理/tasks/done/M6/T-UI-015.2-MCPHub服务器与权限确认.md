# T-UI-015.2 · 能力区：MCP Hub 服务器、tool 映射与权限确认

> [`T-UI-015`](T-UI-015-能力区Skill库MCPHub与Studio附加面.md) 三叶之一（[D-117](../../../决策日志.md) ①）——把 `/mcp` 立起来：Hub 主页 / Server 列表 / Server 详情 / **权限确认对话框** / tool schema 浏览器，另含**添加 Server 表单**（含远程 Server 的数据外发确认）。Skill 库与详情归 [`.1`](T-UI-015.1-Skill库浏览详情参数与执行日志.md)，Studio 附加面归 [`.3`](T-UI-015.3-Studio附加面与工作流调试.md)。

## 目标

把 [11-sitemap §2 能力](../../../../docs/PRD-v2-Agent/11-sitemap.md) 里 story-08 的五条屏做成可用界面——`/mcp` 现**登记在册但无 `render`**，`McpFacade` 已装配真 `servers` / `permissions` / `mapper` / `machine` 四支句柄却**零读面**：

- **MCP Hub 主页 / Server 列表**（[§2.1](../../../../docs/PRD-v2-Agent/11-sitemap.md)：复用 `table`，逐条并列）——逐 Server 出名称 / 标识 / 传输 / 启用 / 生命周期状态
- **Server 详情页**（复用 `report_card`，多段式陈述）——注册记录 + 当前状态 + 状态转移 / 通知摘要 + 降级候选 + 已批准 / 待批准权限
- **权限确认对话框**（复用 `permission_approval_card`；[03 §5.1](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)）——逐条**批准 / 拒绝**，附「这个 Server 想做什么」的逐条措辞（`McpPermissionBook.describe`）
- **tool schema 浏览器**（复用 `table`，逐字段并列）——逐 tool 的映射状态（`active` / `vanished` / 待重映射）+ 从 MCP schema 派生的参数面；**tool 映射为 Skill 可见**（[§3.7](../../../../docs/PRD-v2-Agent/11-sitemap.md)）
- **添加 Server 表单**（story-08 GWT-1 的屏清单之外但缺它则 Hub 无可产生数据的入口）——命令 / URL + 环境变量引用 + 权限申请；远程传输在页内出「数据会离开本机」警示并要求**显式确认**（[03 §5.1](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) / story-08 GWT-5），保存即**自动连接测试**

**本批的边界**（不越界）：

- **不重造渲染件**——`table` / `report_card` / `permission_approval_card` 均已实现，本叶只做**宿主页与取数**。
- **不新造型**——权限确认面复用既有 `permission_approval_card`，确有新形态归 [`T-UI-010`](T-UI-010-契约先行组件型补齐与页面集口径.md)。
- **MCP 本体归 L1**——传输 / 生命周期状态机 / 映射 / 回收语义一律不动，本叶只呈现与转交动作。
- **删除即回收**走 [`L1Runtime.remove_mcp_server`](../../../../src/st_agent/l1/runtime.py)（组合根已接回收回调），**不**直接调 `servers.remove_server`——否则派生 Skill 与映射记录成孤儿。
- **远程 Server 的网络请求**在**网络活动面板**可见（[02 §6](../../../../docs/技术架构-v2/02-L0-本地优先基座.md)）；面板本体归 [`T-UI-018.3`](T-UI-018.3-网络活动与离线横幅.md)，本叶只提供通往 `/settings?view=network` 的入口，不重造。

## 验收标准（Given-When-Then）

- GWT-1：Given [11-sitemap §2 能力](../../../../docs/PRD-v2-Agent/11-sitemap.md) 的 story-08 五条屏，When 逐条走查，Then Hub 主页 / 列表 / 详情 / 权限确认 / tool schema 各有可见载体，`/mcp` 退出六态探针页
- GWT-2：Given 权限确认，When 逐条批准 / 拒绝，Then 经 `McpPermissionBook` 真落账（刷新后仍为决定态），**逐项、不合并**（[01 §10](../../../../docs/技术架构-v2/01-平台共享契约.md)）；未批准的 Server 首次调用仍被拒（fail-closed）
- GWT-3：Given 添加远程（`remote`）Server，When 未显式确认数据外发，Then `validation_failed` + 原因且**不落盘**；显式确认后连接测试失败 ⇒ 同样**不落盘**并如实回失败原因（[03 §5.1](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)）
- GWT-4：Given 一个 Server 的 tool 映射，When 查看 tool schema 浏览器，Then 逐 tool 出映射状态与参数面；tool 已 `vanished` ⇒ 如实标注并从**可用列表滤除**（**不删记录**，可自愈）；禁用 Server ⇒ 其 Skill 立即从可用列表移除
- GWT-5：Given 数据面非 `ok`，When 呈现，Then 按 [01 §5](../../../../docs/技术架构-v2/01-平台共享契约.md) 六态如实——未挂载任何 Server ⇒ `empty` + 原因、面未接线 ⇒ `unavailable` + 点名、标识不认识 / 不存在互不冒充
- GWT-6：Given 文案与呈现，When 核对，Then 按[契约 9 中性表达](../../../../docs/PRD-v2-Agent/10-platform-capabilities.md)撰写（无拟人化）；Server 自述（`display_name`）作 `data` 槽原样呈现
- GWT-7：Given 真组合根 + 真回环服务，When 在 Edge 走查「列表 → 详情 → 加 Server → 权限批准 → tool 浏览器」，Then 全程可用、控制台无新增报错

## 假设与前提

- **A1**：`/mcp` 的**添加 Server 表单**属本叶范围，尽管它不在 [11-sitemap §2 能力](../../../../docs/PRD-v2-Agent/11-sitemap.md) 的屏清单里——story-08 GWT-1（「添加 → 配置表单 → 自动连接测试」）与 GWT-5（远程警示）都指它，且缺它则 Hub 页**无可产生数据的入口**（列表恒空）。**若错的影响**：若坚持不建表单，则 Hub 只能展示既有 Server，story-08 GWT-1 / GWT-5 无载体，本叶交付「看得见但用不起来」。**验证方式**：读 story-08 的验收标准前两条与 [03 §5.1](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的「添加时连接测试 + 权限申请展示 + 逐项批准」；集成用例覆盖远程未确认 ⇒ 拒、stdio 正常 ⇒ 落盘。
- **A2**：`remove_server` **必须**经 [`L1Runtime.remove_mcp_server`](../../../../src/st_agent/l1/runtime.py)（内部先 `disable` 再 `remove_server`，触发回收回调）；表现层只发 `action: "remove"`，**不**自行拼两步。**若错的影响**：直接调 `servers.remove_server` 会跳过回收 → 派生 Skill 与映射记录成孤儿（[03 §5.2 回收落地口径](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)）。**验证方式**：读 [`registry.py`](../../../../src/st_agent/l1/mcp/registry.py) 的 `on_server_removed` 回调接线与 `L1Runtime.remove_mcp_server` 的实现顺序；集成用例断言移除后该 Server 的派生 Skill **不在**可用列表。
- **A3**：**权限确认对话框**的宿主是 `/mcp`（Server 详情内嵌一段），story-08 GWT-3 字面的「首次调用时弹出」是**对话流内**的触发面，归 L3 审批面（`T-L3-006` 已交付）；本叶做的是同一簿记（`McpPermissionBook`）在**独立页**的**逐项批准面**，**不重造**对话流内那套。**若错的影响**：若把两者当同一件事，会造出第二份权限真相源或误判 GWT-3 未交付。**验证方式**：读 [03 §1.5](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的「声明 → 逐项批准」落点（`config` 分区 `mcp-permission/<server_id>.json`，与 Skill 侧共用同一簿记实现）确认两侧同簿；走查确认批准后刷新仍为决定态。
- **A4**：tool → Skill 映射的**可见性**由 `McpSkillMapper.available_skills()` 定（已滤除 `vanished` 与禁用 Server 的派生 Skill），表现层**不自行过滤**。**若错的影响**：前端再滤一遍会与后端判据漂移（如禁用 Server 时前端漏滤，用户看到「可用」但调用被拒）。**验证方式**：读 [`mapping.py`](../../../../src/st_agent/l1/mcp/mapping.py) 的 `available_skills` / `_unavailable_skill_ids`；集成用例断言禁用 Server 后其 Skill 从该面消失。
- **A5**：`env_refs` 只存**环境变量名**（取值经 `CredentialVault`，不落注册表），故添加表单的「环境变量」一栏收的是**变量名清单**、**不收明文**。**若错的影响**：若表单收明文并落盘，会违反数据主权（凭据分区恒加密、其余分区不存明文凭据）。**验证方式**：读 [`models.py`](../../../../src/st_agent/l1/mcp/models.py) 的 `env_refs` 注释与 `_resolve_env`；用例断言请求体不含明文值、落盘记录里只有变量名。
