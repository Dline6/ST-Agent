# T-UI-017.3 · 触达区：疲劳反馈与调整询问

> [`T-UI-017`](T-UI-017-触达区日报历史与预算渠道配置.md) 三叶之一（[D-118](../../../决策日志.md) ①）——触达区的**反馈面**：五动作推送反馈对话框（[11-sitemap §2.1](../../../../docs/PRD-v2-Agent/11-sitemap.md) 复用 `feedback_capture`）与推送疲劳**调整询问**的答复（[07 §7](../../../../docs/技术架构-v2/07-L5-主动触达.md) 的减少 / 关闭 / 保持）。日报与历史归 [`.1`](T-UI-017.1-日报与推送历史.md)，预算 / 渠道 / 情境配置归 [`.2`](T-UI-017.2-预算渠道与情境模式.md)。

## 目标

- **推送疲劳反馈对话框**（[11-sitemap §2.1](../../../../docs/PRD-v2-Agent/11-sitemap.md)：复用 `feedback_capture`）——对**一条推送留痕**采集反馈：五动作（采纳 `adopted` / 忽略 `ignored` / 否定 `rejected`+原因 / 追问 `queried` / 点赞 `liked`，[08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md)）齐备、**否定类的 `reason` 入口独立**（必填）；目标取自推送历史（[`.1`](T-UI-017.1-日报与推送历史.md)）的 `delivery_id`（`target = {kind: "delivery", ref}`）。写面＝**既有** `POST /api/reflection/feedback`（[01 §12](../../../../docs/技术架构-v2/01-平台共享契约.md) 的三个固定回环路由族之一），**本叶不另造写通道**。
- **推送疲劳调整询问**——逐类（`dedup_key`）的**连续忽略计数 / 阈值 / 静音态 / 最近答复 + 时间锚**读面；**未答复的询问**（`asked_delivery_id` 非空）连同其**中性问句**（取自该询问推送的 `DeliveryRecord` 文案）与计数如实呈现。
- **答复落值（减少 / 关闭 / 保持）**——经 **L3 采集面铸 `FeedbackEvent`**（`feedback_id` 归交互层，[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md)）并发布 `FeedbackRecorded`，由 L5 `FatigueMonitor.consume` 以 `context.fatigue_choice` 落值——与 [`test_m3_delivery.py::test_gwt8_answer_reaches_l5_through_the_feedback_bus`](../../../../tests/integration/test_m3_delivery.py) 已在案的路径一致；**L6 同经总线收到该反馈**。三落点：**减少**收窄该级别渠道链 / **关闭**入静音清单（该类改判汇总进日报，不丢弃）/ **保持**不改配置、计数归零。
- **阈值可读改**——`fatigue.ignore-threshold`（[01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 标量条目，默认 5）经 [`setting_panel`](../../../../src/st_agent/ui/web/js/plugins/reflection/setting_panel.js)（面键 `delivery-config`，与预算 / 渠道 **同键同路由**）读改。

**本批的边界**（不越界）：

- **疲劳判定 / 静音清单 / 频控归 L5**——本叶只取数与转发答复，不改 `FatigueMonitor` / `FrequencyController` 的既有语义。
- **不铸 `feedback_id`**——产生方是交互层（[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md)），本叶经采集面转发、**不自行铸造**。
- **询问的「发问」不在本叶**——由 L5 `sweep` 在组合根 `tick` 内产出（[T-INT-004](../M3/T-INT-004-M3集成关卡主动触达投递闭环.md) 已接）；本叶只呈现**已发出**的询问。

## 验收标准（Given-When-Then）

- GWT-1：Given 一条推送留痕，When 打开反馈对话框，Then 五动作齐备、**否定类的 `reason` 入口独立且必填**；提交后经 L3 采集面产生 `FeedbackEvent`（[08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md) 六字段）并经总线送达（`delivered=True`）；否定类缺 `reason` ⇒ `validation_failed`
- GWT-2：Given 某类连续忽略计数已达阈值（L5 已发询问），When 打开调整询问，Then 中性问句与计数如实呈现（带 `as_of` 时间锚）；答复 **减少 / 关闭 / 保持** ⇒ L5 三落点各自生效且**可回溯**
- GWT-3：Given 答复「关闭」，When 落值，Then 该类入静音清单、频控把该类**改判为汇总进日报**（关闭单独触达 ≠ 丢弃）；答复「减少」收窄该级别渠道链（链只剩一级 / 未接渠道面时**显式标注无可收窄**，不静默）；答复「保持」不改配置、连续计数归零
- GWT-4：Given 未注入疲劳面，或 `FeedbackRecorded` 总线未接通，When 访问 / 答复，Then 回 `unavailable` + **点名归属**（**不假装收到答复**；答复如实标注未送达）
- GWT-5：Given 真组合根 + 真回环服务，When 在 Edge 走查「推送历史选一条 → 五动作反馈 → 调整询问 → 答复」闭环，Then 全程可用、控制台无新增报错

  - **L5 疲劳面** [`FatigueMonitor`](../../../../src/st_agent/l5/fatigue.py)：`counts() -> tuple[FatigueState,...]`（`dedup_key` / `ignored_streak` / `threshold` / `muted` / `last_answer` / `answered_at` / `asked_delivery_id` / `as_of`）· `sweep(now)` → `Inquiry(dedup_key, signal_id, delivery_id, level, ignored_streak, question, asked_at)` · `answer(delivery_id, choice, *, now=None) -> AnswerResult`（**第二通道**，无 UI 时的直接承接）· `consume(event)` 接 `FeedbackRecorded` · `is_muted(dedup_key)` · `threshold()` / `set_threshold(value)`；`Answer ∈ {reduce, disable, keep}` · `AnswerResult(dedup_key, delivery_id, choice, applied)`
  - **L3 反馈采集面** [`DialogFacade.record_feedback`](../../../../src/st_agent/app.py)（委托 [`FeedbackCollector.record`](../../../../src/st_agent/l3/feedback/collector.py)；`feedback_id` 由它铸造、`rejected` 缺 `reason` 即拒、`target.ref` 按 [01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 形态校验）——答复回流与五动作反馈的**同一产生方**

- 输出（本任务交付的公共 API / 落盘位置）：
  - **组合根**：[`DeliveryFacade`](../../../../src/st_agent/app.py) 增 `fatigue`（L5 `FatigueMonitor`，现未透出）与 `feedback`（L3 采集面的 `record` 绑定，经 [`M5Runtime.delivery`](../../../../src/st_agent/app.py) 装配）
  - **端点**：`GET /api/delivery/feedback?delivery=<delivery_id>` → `feedback_capture` 描述（目标＝该推送；五动作 + 否定类原因入口）· `GET /api/delivery/fatigue` → `report_card` 描述（阈值 / 逐类计数 / 静音 / 最近答复 / `as_of` + 可答复口径）· `GET /api/delivery/inquiries` → `table` 描述（**待答复询问逐条给 `delivery_id`**——页面据此就地造答复按钮，**不解析卡片文本**；本端点是**只读**，**不调 `sweep`**——发问有副作用）· `POST /api/delivery/fatigue/answer`（体 `{delivery_id, choice}`）→ 经 L3 采集面铸 `FeedbackEvent`（`target={kind:"delivery", ref}`、`context={"fatigue_choice": choice}`）并发布 → `ok {choice, delivered, applied}` / `validation_failed`

## 假设与前提

- **A1**：**答复走 `FeedbackEvent`、不自铸 `feedback_id`**——[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 登记 `feedback_id` 产生方＝交互层（L3），而 [07 §7](../../../../docs/技术架构-v2/07-L5-主动触达.md) 明写「答复由交互层采集成 `FeedbackEvent`，L5 经 `FeedbackRecorded` 订阅面消费」；`FatigueMonitor.answer()` 是同一落点的**第二通道**（[T-L5-003.3 `A1`](../M3/T-L5-003.3-推送疲劳监控与答复回流.md)）。本叶经 L3 采集面铸事件，**L5 与 L6 各经同一总线收到**。**若错的影响**：若要求 L5 自铸 `feedback_id`，返工面＝本端点 + [01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 产生方行文（须走 [铁律 8](../../../工程宪法.md) 契约先行）。**验证方式**：集成套件重放 [`test_gwt8_answer_reaches_l5_through_the_feedback_bus`](../../../../tests/integration/test_m3_delivery.py) 的路径（L3 入口 → 总线 → L5 落值），并断言 `result.data.delivery.delivered is True`。
- **A2**：**`FeedbackEvent.action` 只承载合法枚举内的固定值，答复语义载在 `context.fatigue_choice`**——[08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md) 的 `action` 只有五值（采纳 / 忽略 / 否定 / 追问 / 点赞），**无「减少 / 关闭 / 保持」的对应值**；L5 `consume` **只读** `context.fatigue_choice`，不读 `action`。既有集成用例即以 `action="ignored"` + `context={"fatigue_choice": "disable"}` 走通，本叶沿用该形态（**不改契约**）。**若错的影响**：若要求 `action` 表达三答复，`FeedbackEvent.action` 须扩值域并从 [08 §1](../../../../docs/技术架构-v2/08-L6-反思演进.md) 起走 [铁律 8](../../../工程宪法.md)（且 `rejected` 的 `reason` 必填会把「关闭」变成必须填理由，与 07 §7 的按钮答复不符）。**验证方式**：集成用例断言答复后 `is_muted` / 渠道链收窄 / 计数归零三态各自生效。
- **A3**：**推送历史是可寻址的反馈目标源**——反馈对话框的 `target.ref` 须是 `delivery_id` 形态（[`FeedbackTarget`](../../../../src/st_agent/l3/feedback/collector.py) 按 [01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 校验，**不合形态即拒**），推送历史（[`.1`](T-UI-017.1-日报与推送历史.md)）提供这批 id。**若错的影响**：无历史面则反馈对话框无目标可挂（页面只能给 `empty`）。**验证方式**：集成用例从**真**留痕取一枚 `delivery_id` 提交反馈并断言 `status=ok`。
- **A4**：**阈值经统一标量落值面、与矩阵 / 渠道链分属两面**——`fatigue.ignore-threshold` 取值是整数（在 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 统一落值面内），而 [`.2`](T-UI-017.2-预算渠道与情境模式.md) 的格位 / 渠道链是对象 / 列表（owner 写面）。故本叶的阈值条目走**注册表 `set`**，[`.2`](T-UI-017.2-预算渠道与情境模式.md) 的条目走 L5 自有 API——同页两面各有对策。**若错的影响**：把阈值塞进 L5 自有写面会造出第二条落值路径。**验证方式**：集成用例经门面 `set` 改阈值并读回 `FatigueMonitor.threshold()`。
- **A5**：**「未答复的询问」的判据是 L5 落盘态，不由前端计数反推**——`FatigueState.asked_delivery_id` 非空即「已发问未答复」（L5 的复问基线由它释放，[07 §7](../../../../docs/技术架构-v2/07-L5-主动触达.md)），问句文案取自该询问推送的 `DeliveryRecord`。**若错的影响**：前端自算「是否已问」会与 L5 的复问基线漂移（可能重复发问或漏发）。**验证方式**：集成用例断言发问后 `counts()` 里该类 `asked_delivery_id` 非空、答复后为空。
