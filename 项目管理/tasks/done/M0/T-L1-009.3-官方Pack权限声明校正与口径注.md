# T-L1-009.3 · 官方 Pack 权限声明校正与口径注

## 目标

校正官方 Pack 的 12 条**声明错位**：`permissions` 一律清空（字段保留）。判据三条——① [D-031](../../../决策日志.md) ③ 已裁定「读 `data_cache` 内的缓存数据**不是** `local_read` 的范围」（它走 L0 鸭子类型文档面）；② 官方执行器**从不调用沙箱三类出口**（取数与出网全经注入的 `market_query` / 网关）；③ [01 §10](../../../../docs/技术架构-v2/01-平台共享契约.md) 的 enforcement 是**行为式**（运行时行为超出声明即拦截），一个只经注入句柄取数的 Skill 自身并无越界行为可言。故这 12 条声明既拦不住任何东西，又照样触发 [`SkillRunner` 的硬门](../../../../src/st_agent/l1/runner/runner.py)，使调度与试跑对官方 Skill 恒失败。

同批把该判据写进契约与架构文档，避免后来者照着这 12 条再补一遍。

## 验收标准（Given-When-Then）

- **GWT-1 官方 Pack 无需批准即可执行**：Given 组合根装配的运行时（无任何批准记录），When 执行任一官方 Skill，Then 不再因「缺少已批准权限」而 `validation_failed`；`skill_st_list_sync` / `sk_stock_watch` 的 `net_access` 声明同批清除。
- **GWT-2 声明字段与校验仍在**：Given 清空后的种子，Then `SkillDescriptor.permissions` 字段保留（空元组）、`validate_permissions` 仍被调用；一个**自建**的声明权限的 Skill 仍走完整批准流程（未被本叶削弱）。
- **GWT-3 口径可查**：Given [01 §10](../../../../docs/技术架构-v2/01-平台共享契约.md) 与 [03 §1.1](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) / [§2](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)，Then 写明「权限声明只覆盖**该能力自身发起**的文件/网络/命令行为；经注入取数面消费数据不属声明范围（[D-031](../../../决策日志.md) ③）」；`verify_docs.py --strict` 通过。

## 假设与前提

- **A1 · 清空声明不削弱沙箱**：声明是「允许范围」的上界，空声明意味着该 Skill 走沙箱出口一律被拦（[sandbox.py](../../../../src/st_agent/l1/sandbox/sandbox.py) 的 `_check` 对未声明即 `deny`）——这是**更严**而非更松；官方执行器本就不走沙箱出口，故无回归。若错（有执行器实际调用沙箱出口）：返工面＝该 Skill 的声明按真实行为补回。
- **A2 · 既有用例不依赖这 12 条声明**：现用例经 `_pack_permissions(registry)` 动态取描述体的 `permissions` 喂批准（[test_official_pack_install.py](../../../../tests/l1/test_official_pack_install.py) 等），空集下 `missing` 为空、仍通过。验证：GWT-2 + 既有官方 Pack 用例全绿（含红-绿：先改种子跑一次，失败面应为零）。
- **A3 · [03 §2](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的官方 Pack 表未列权限列**：已核该节表不含权限字段，故清声明不动其表；若错（有列）：返工面＝同步该表。
