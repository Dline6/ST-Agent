# T-L1-005.2 · 调度执行接线（走 §1.2 完整流水线）

## 目标

把 `T-L1-005.1` 判定的到期目标接到执行面：调度触发产生的执行走 [03 §1.2](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 完整流水线（留痕、Trace、ResultEnvelope），[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 的 `trace_id` 由调度器创建，结果回写运行状态。

## 验收标准（Given-When-Then）

- GWT-1 触发即走完整流水线（到期触发与手动触发同一路径）：Given 一个到期目标**或**一次手动触发（工作流，其复合 Skill 已物化），When 触发，Then [03 §1.2](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 流水线执行一次、SkillRun 落盘可回放（输入快照 / 输出 / 耗时）、Trace 含本次步骤且 `trace_id` **由调度器创建**、返回 ResultEnvelope，且该次执行的 `initiator` 标明来源＝定时调度。
- GWT-2 传参取描述体当前默认值：Given 用户经双通道（`SkillRegistry.set_parameters`）改过某 Skill 的参数默认值，When 调度执行，Then 本次执行用的是**改后**的值，不是改前。
- GWT-3 依赖缺口显式不执行：Given 工作流对应的复合 Skill **未物化**（依赖缺失），When 该工作流到期，Then 本次**不执行**、记一条显式缺口（不静默、不落半成品，[03 §3.2](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)），状态可查。
- GWT-4 已禁用与失败不静默：Given 目标内含被 `SkillSandbox.disable` 的 Skill，When 到期，Then 不执行并留痕；Given 执行返回失败信封，When 查运行状态，Then 该次为失败且原因可查，**上次成功时间不推进**。
- GWT-5 权限来源注入：Given 注入了一个鸭子类型权限来源，When 调度执行，Then 会话收到的 `approved_permissions` 逐条来自该来源（不是描述体声明值、也不是无条件放行）；Given 来源给出空集，Then 需要声明的执行被沙箱拦下并经信封显式化。

## 假设与前提

- A1 调度**经复合 Skill** 执行工作流（先物化、后调度），不另造逐节点驱动路径 / 若错：需复用 [`workflow/trial.py`](../../../../src/st_agent/l1/workflow/trial.py) 的编排逻辑另立执行面，GWT-1 / GWT-3 返工 / 验证：GWT-1 的「复合 Skill 已物化」与 GWT-3 的「未物化即不执行」两侧用例。
- A2 调度执行的入参取描述体**当前参数默认值**（用户在双通道改参即生效），不另建调度专用参数落点 / 若错：需新立参数面并同步 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) / 验证：GWT-2 的改参后生效用例。
- A3 权限经**注入的鸭子类型来源**取得，本任务**不**建持久化批准面（Skill 侧批准记录的落点缺失，已登记 [L1 册](../../../遗留问题/L1-遗留问题.md) `D1`，归属待立项）/ 若错：待该面立项后改由它供给，本任务 GWT-5 的注入面不变 / 验证：GWT-5 的两侧用例（有来源 / 空集）。
- A4 不需要新事件名——[`CORE_EVENTS`](../../../../src/st_agent/contracts/time_events.py) 的 10 个不动，留痕靠既有 SkillRun / Trace / 信封 / 运行状态 / 若错：须改 [01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md) 契约（走工作流第 ⑦ 步）/ 验证：`tests/contracts` 的事件清单用例不受影响。
- A5 一条到期的调度 = 一次 `SkillRunner.run`（不并发、不重入）；重入保护在本任务内以目标级互斥实现 / 若错：长任务与下个到期点重叠的处理须改口径 / 验证：GWT-4 与 `T-L1-005.1` 的幂等用例。
