# T-L1-006.4 · 调度面装配与在线翻转补跑

## 目标

把 [`T-L1-005`](T-L1-005-定时调度.md) 的调度器接进运行时：注入 `Store` / 工作流库 / Skill 注册表 / 沙箱 / `SkillRunner` / 出网网关 / 权限来源，并在**在线态翻回在线**时触发一次 `catch_up`（[D-039](../../../决策日志.md) 的「影响」项）。

## 验收标准（Given-When-Then）

- GWT-1 调度装配可用：Given 已装配运行时，When 读取，Then `Scheduler` 就绪且已注入 `Store` / 工作流库 / Skill 注册表 / 沙箱 / `SkillRunner` / 出网网关 / 权限来源；`targets()` 枚举与既有口径一致（工作流按 `schedule`、Skill 按频率参数）。
- GWT-2 在线翻转触发补跑：Given 离线期间累计了待补到期点且策略为补跑，When 在线态翻回在线，Then **自动**触发一次 `catch_up` 并按策略处置（补跑一次 / 记已跳过）；重复翻转与重复调用幂等（待补集不被重复补偿、也不被吞掉）。
- GWT-3 权限来源不臆测：Given 未提供权限来源，When 定时触发一个声明了权限的 Skill，Then 由流水线 / 沙箱拦为 `validation_failed`（**不**自动放行，[01 §10](../../../../docs/技术架构-v2/01-平台共享契约.md)）；Skill 侧持久化批准面的缺失仍归 [L1 册 `D1`](../../../遗留问题/L1-遗留问题.md)。

## 接口面

- 输入（消费的前置接口）：
  - `T-L1-006.2`（本批姊妹）· 装配出的 `SkillRunner` / `SkillSandbox` / `WorkflowStore` / `SkillRegistry`；`T-L1-006.1` · 装配出的 `EgressGateway`（在线态唯一源头）
  - `T-L1-005.1`（done）· [`scheduler/scheduler.py`](../../../../src/st_agent/l1/scheduler/scheduler.py) 的 `Scheduler(store=None, *, workflows, skills, sandbox, runner, permissions, gateway, policy, frequency_param)` 与 `targets()` / `state()`
  - `T-L1-005.2`（done）· 同上 `Scheduler.tick(now)` / `trigger(target_id, now=…)`；权限来源鸭子类型 `PermissionSource`（`approved_for(target) -> tuple[str, ...]`）
  - `T-L1-005.3`（done）· 同上 `Scheduler.catch_up(now)`；[`scheduler/policy.py`](../../../../src/st_agent/l1/scheduler/policy.py) 的 `SchedulerPolicy(store)`（缺省 `catch-up`）
  - `T-L0-004`（done）· [`net/gateway.py`](../../../../src/st_agent/l0/net/gateway.py) 的 `EgressGateway.set_online(online)` / `.online`
- 输出（本任务交付的公共 API / 落盘位置）：
  - `src/st_agent/l1/runtime.py` 的 `L1Runtime`（新增 `scheduler` 字段）与 `set_online(online)`（翻转网关在线态；翻回在线时触发一次 `catch_up`）
  - 落盘位置按调度器既有口径（`config/scheduler/<target>.json`、`config/scheduler-policy/offline-catch-up.json`），**不新增分区**
  - 消费方：[`T-INT-001`](T-INT-001-M0集成关卡骨架打通冒烟.md)

## 可关闭的遗留

无（已逐条核 [L0 册](../../../遗留问题/L0-遗留问题.md) 与 [L1 册](../../../遗留问题/L1-遗留问题.md) 未闭区；L1 册 `D1` 的归属是「待人定（**待立项**）」，不属本任务，本叶只按其现状口径消费）。

## 假设与前提

- A1 权限来源经注入且**缺省为空集**——组合根不造「已批准」这一事实（[D-039](../../../决策日志.md) 已否决「取描述体声明即视为已批准」）/ 若错：无人值守执行被静默放行，违 [01 §10](../../../../docs/技术架构-v2/01-平台共享契约.md) / 验证：GWT-3。
- A2 在线翻转的接线点取 `set_online(bool)` **单一入口**（内部调 `EgressGateway.set_online` 后按需 `catch_up`），**不改** `Scheduler` 与 `EgressGateway` 的既有 API / 若错：在线态出现两个源头 / 验证：GWT-2 双侧（离线累计 → 翻回 → 处置一次；仍未离线态不触发）。
- A3 `catch_up` 的幂等由调度器既有口径承担（`T-L1-005.3` 已验），组合根只在「翻回在线」这一跳调用一次，不额外重复调 / 若错：重复补跑 / 验证：GWT-2 的幂等断言。
