# T-L1-006.2 · L1 能力面装配（注册表 / 官方 Pack 播种 / 沙箱 / 执行器 / 复用 / 工作流）

## 目标

在 `.1` 装好的 L0 面之上，装配 L1 能力面：`SkillRegistry`（含官方 Pack 播种与执行器注册）、`SkillSandbox`（携端点注册表与 `provider → host` 映射）、`SkillRunner`、输出复用注册表与新鲜度判定件、工作流库——使「装上就能跑」在**空 `Store` 首启**时即成立。

## 验收标准（Given-When-Then）

- GWT-1 装配完整：Given 已装配 L0 面（`.1`）与注入的取数源，When 装配 L1 能力面，Then `SkillRegistry` / `SkillSandbox` / `SkillRunner` / 输出复用注册表 / 工作流库全部就绪，且沙箱**已携**端点注册表与 `provider → host` 映射（LLM 出网可核对，不因装配缺参恒 fail-closed）。
- GWT-2 官方 Pack 自动可用（[Story 02](../../../../docs/PRD-v2-Agent/story-02-skills-runtime.md) 验收①）：Given 全新空 `Store` 且未配置任何云端点 / 凭据，When 首次装配，Then 官方 Pack 全部 Skill **自动可列出**、无需下载，且 `uncovered_bases()` 为空（每个 base 都有执行器）。
- GWT-3 端到端一次执行可追溯：Given 已装配运行时 + 一个官方 Skill（取数源为离线 Fake），When 经 `SkillRunner` 执行一次，Then 信封合法（`ok` / `empty`）、SkillRun 落盘可回放、Trace 可追溯（装配面把 `trace_id` 与 `skill_run_id` 的落盘位置串起来）。
- GWT-4 重复装配幂等：Given 已装配过的 `Store`（已有 Skill 版本、工作流与执行留痕），When 再次装配，Then 无 `SkillExistsError`、既有版本与参数保留、已登记工作流原样可读。

## 假设与前提

- A1 官方 Pack 的取数源经**注入**（`MarketQuerySource` 鸭子类型，形态 `query(sql, params=()) -> ResultEnvelope`），组合根**不**硬编码 `MarketDb` / 若错：装配面被 L0 具体类绑死、用例无法注入 Fake / 验证：装配签名接受 `market_query`；GWT-3 传离线 Fake 源。
- A2 官方 Pack 首启自动可用**不以**任何云端点 / 凭据已配为前提——官方执行器工厂只取 `MarketQuerySource`（`ExecutorFactory = Callable[[MarketQuerySource], SkillExecutor]`）/ 若错：首启要求用户先配密钥，违 [Story 02](../../../../docs/PRD-v2-Agent/story-02-skills-runtime.md) 验收① / 验证：GWT-2 在「空 `Store` + 未配端点」下断言 Pack 可列出。
- A3 沙箱必须**同时**拿到端点注册表与 `provider → host` 映射，否则 LLM 出网恒 fail-closed（[`T-L1-001.5`](T-L1-001.5-沙箱接线runner注入.md) 假设 A3 口径）/ 若错：LLM 路径静默不可用 / 验证：GWT-1 的「沙箱已携端点与映射」断言。
- A4 幂等取「已存在即跳过」（各子系统既有的 `ensure_official_pack` / `register` 语义），不引入装配版本 / 若错：二次装配失败或覆盖 / 验证：GWT-4。
