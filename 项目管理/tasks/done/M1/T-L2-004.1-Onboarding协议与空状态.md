# T-L2-004.1 · Onboarding 协议与空状态（§7）

## 目标

兑现 [04 §7 Onboarding 协议](../../../../docs/技术架构-v2/04-L2-记忆图谱.md)：新用户首启的**对话式快速画像构建**——问题清单不超过 10 问、由 [01 §7](../../../../docs/技术架构-v2/01-平台共享契约.md) 配置注册表管理（可随官方 Pack 更新）、支持跳过；答完产出至少 3 个维度的初始节点；某维度无记忆时**可查到**「这个维度你还没告诉我任何信息」，且不阻断其他功能。

## 验收标准（Given-When-Then）

- **GWT-1 · 问题清单是 01 §7 条目**：Given 本叶交付，When 取条目，Then 得到七字段齐备的 `ConfigEntry`（`config_id` / `display_name` / `value_schema` / `default` / `description_for_chat` / `panel_form_spec` / `scope` / `change_policy`），落 `config` 分区 `memory-policy/onboarding-questions.json`。
- **GWT-2 · 清单 ≤10 问且覆盖 3 个必需维度**：Given 缺省清单，When 校验，Then 条数 ≤ 10，且其字段覆盖 [§7](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) 点名的风险偏好 / 投资年限 / 当前关注板块三处；When 写入 11 条，Then 显式拒绝（不静默截断）。
- **GWT-3 · 答完建立初始画像**：Given 三个必需维度都有答案，When 构建，Then 图谱落 `identity` + `attention` 两类节点（`source=user_stated`、直接写入，§3.2），字段逐一对应答案；答案里的空白值按**跳过**处理，不产空字段。
- **GWT-4 · 跳过维度进空状态且不阻断**：Given 跳过一个维度，When 构建，Then 该维度不产节点、其余照产；`empty_dimensions()` 能查到被跳过的维度；同图上的其他操作（如 `MemoryReader` 切片）不受影响。
- **GWT-5 · 改清单即生效且留痕**：Given 当前清单，When 改一版，Then 落盘更新 + 一条 `ChangeRecord`（`change_id` 作回滚单位）写入 `execution_log` 的 `memory-policy-change/`；**值未变不留痕**；未知节点类型 / 未知字段 / 超 10 条的清单显式拒。

## 假设与前提

- **A1 · 「3 类初始节点」＝ 3 个维度，不是 3 类节点 type**（④ 对齐确认）：[04 §7](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) 点名的三项按 [§1](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) 字段表落在 **两类** 节点上——风险偏好 / 投资年限 → `identity`（`risk_preference` / `investing_years`），当前关注板块 → `attention`（`sector_preferences`）。故「至少 3 类」按**维度**判（缺省清单覆盖 3 个维度）。若错（须 3 类 type）：返工面 = `DEFAULT_ONBOARDING_QUESTIONS` 增加第三类 type 的问题 + GWT-2 / GWT-3 的口径。
- **A2 · 初始节点的 `confidence` 取 §5 基线的初版值（0.9）**：§7 未规定初始画像的置信度。[§5](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) 的基线是**读面上限**（消费方读到的有效值不超过该来源基线），故这里写 `DEFAULT_STATED_CONFIDENCE = 0.9` 与 §5 缺省基线同值；调用方可传参覆盖。若错（须与 `ConfidenceModel` 实时同源）：返工面 = `build_initial_nodes` 增注入参数，落盘不变。
- **A3 · 集合型字段的答案由调用方拆好，本模块不猜分隔符**：`sector_preferences` / `theme_interests` / `holdings` 等字段是 `tuple[str, ...]`，而 §7 未规定对话里「银行、券商」怎么变成多项。`build_initial_nodes` 的答案取值因此收 `str`（标量字段）或 `str` 序列（集合字段）；集合字段收到单个 `str` 时按**单元素**处理。理由：分隔符约定属对话理解（L3/DM）面，在 L2 里猜会让同一句答案在不同入口得到不同切分。若错（须在 L2 里定分隔符）：返工面 = `_answer_value` 的归一规则 + 一条分隔符约定进 04 §7。
