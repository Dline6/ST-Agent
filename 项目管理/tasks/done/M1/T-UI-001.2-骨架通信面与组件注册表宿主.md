# T-UI-001.2 · 骨架、本机通信面与六态渲染

> **本任务已拆分（2026-09-29，命中[拆分触发](../../../工作流.md)「涉及 2 个及以上契约小节」与「单次预计会话轮次 > 20」）**——原 `T-UI-001.2` 的范围含「UI 描述契约登记 + 组件注册表宿主 + 渲染前中性化门」，与骨架/通信面不属同一面，已移交 [`T-UI-001.3`](T-UI-001.3-契约登记与组件注册表宿主.md)。选型见 [D-063](../../../决策日志.md)。

## 目标
交付**前端工程骨架**与**本机回环通信面**：无构建静态前端（原生 ES modules，无 npm / 无打包器）、`UiServer`（loopback + 随机端口 + 启动令牌握手 + 请求守卫）、`ResultEnvelope` 六态渲染（语义由服务端下发，前端不复制），以及 **dev 开关下的浏览器直开**（构建期开关，发布构建**物理剔除**）。

## 验收标准（Given-When-Then）
- Given dev 开关开启，When 浏览器直开，Then 骨架页可加载并取到一条真实信封
- Given 发布构建配置，When 检查打包发现，Then dev 面已被物理剔除（`packages.find` 的 `exclude` 生效，机器可查）
- Given 无令牌 / 错 `Origin` / `Host` 为攻击域名，When 请求，Then 一律拒（401 / 403 + 中性原因），**不回任何数据**
- Given 六个 `status`，When 序列化信封，Then 各态附确定的 `render` 元数据，且与 [`RENDER_SEMANTICS`](../../../../src/st_agent/l3/dispatch/bus.py) **逐项一致**

  - [00 §1.1](../../../../docs/技术架构-v2/00-架构总览.md)（后端常驻 / UI 可分离 / UI 只经 IPC、不直开存储）· [02 §2.4](../../../../docs/技术架构-v2/02-L0-本地优先基座.md)

## 假设与前提
- **A1 · 前端技术栈＝零构建原生 ES 模块，且不依赖任何 Node 运行时特性**——前提：三引擎 WebView（WebView2 / WKWebView / WebKitGTK）内**无 Node 运行时**（[D-060](../../../决策日志.md) ① 的兼容底线），故不使用 import maps、top-level await 之外的现代特性，不写打包器配置。若错（须引构建链）：返工面＝`ui/web/**` 的组织方式与 `pyproject.toml` 的资产打包；且壳选型会被提前锁进 M1。验证方式：`ui/web/**` 加载时不出现任何 Node-only 语法；dev 直开在普通浏览器可跑。
- **A2 · dev 面的「发布剔除」＝setuptools 包剔除**——前提：当前 ship 形态以 Python 包为准。若错（最终 ship 形态非 wheel，或打包移交 [`T-UI-002`](../M3/T-UI-002-桌面壳与打包.md)）：剔除机制随之改，本任务只保证「dev 面收在独立子包、可被整体剔除」这一结构。验证方式：`tests/ui/` 解析 `pyproject.toml` 断言 `exclude` 含 `st_agent.ui.dev`；且 `dev=False` 时 dev 路由未挂载。
- **A3 · 启动令牌经 URL fragment 传递**——前提：fragment 不发送到服务端、不进 `Referer`；前端只存内存不落 localStorage。若错（令牌泄漏面）：握手校验形同虚设。验证方式：握手失败用例（缺令牌 / 错令牌 / 错 `Origin` / 攻击域名 `Host`）逐条拒。
- **A4 · 前端零 `import st_agent`，只经 HTTP 取 JSON**——前提：[00 §1.1](../../../../docs/技术架构-v2/00-架构总览.md) 的「UI 只经 IPC 取数、不直开存储」与单一写者＝后端进程。若错（前端直连存储或 import 后端）：破坏数据主权与单一写者。验证方式：`tests/ui/test_frontend_pure.py` 扫描 `ui/web/**` 断言无 `st_agent` 引用、无 `eval(` / `new Function`。

- **A5 · 本叶只证明「管道通、六态对、鉴权硬」，不接真实数据**——前提：M1 骨架叶若被迫先接 `MemoryReader` / `L1Runtime` 的真实装配，就会在 `T-INT-002`（组合根装配）之前**提前定死装配形态**，与 [D-063](../../../决策日志.md) 的 M1 最小面口径相抵。故本叶的 API 面只有 `/api/health`（恒 `ok`）与**仅 dev 挂载**的 `/api/dev/sample?status=<六态之一>`（用 [`ResultEnvelope`](../../../../src/st_agent/contracts/result_envelope.py) 的工厂造合法信封），真实数据接线留给需要它的叶与 `T-INT-002`。若错（骨架叶即须接真数据）：返工面＝`build_ui` 的装配签名与 `T-INT-002` 的装配归属重叠。验证方式：`/api/health` 与 dev 示例端点各自出合法信封；发布构建（`dev=False`）下 dev 路由不存在。
