# T-L3-005.1 · 冲突裁决

## 目标

兑现 [05 §9](../../../../docs/技术架构-v2/05-L3-对话主入口.md) 第一条：L3 承接 L2 的 `MemoryConflictDetected` 事件（[01 §11](../../../../docs/技术架构-v2/01-平台共享契约.md)），在对话中发起裁决（[04 §4](../../../../docs/技术架构-v2/04-L2-记忆图谱.md)），把用户的裁决结果交回 L2；并把派发总线里 `wired=False` 的 `memory_op` 去向往接活（现登记 `owner="T-L3-005"`）。反馈采集点归 [`.2`](T-L3-005.2-反馈采集点.md)。

## 验收标准（Given-When-Then）

- **GWT-1 · 承接事件并产出裁决卡**：Given 一条 `MemoryConflictDetected` 平台事件（L2 [`ConflictQueue.event_for`](../../../../src/st_agent/l2/memory/conflict.py) 产出）或一条待裁决提案，When L3 承接，Then 产出一张**裁决卡**——含冲突两方内容（既有节点 / 新提案）、中性问句、可选方向候选、`accept` / `reject` 两个动作；**记忆本体文本原样承载、不过 [01 §6](../../../../docs/技术架构-v2/01-平台共享契约.md)**，而**本层自有的生成话术（问句 / 抬头 / 动作标签）逐条过 §6 执行点 2，命中即阻断**（[D-053](../../../决策日志.md) 的分栏口径）。**前置未就绪**（未注入 L2 裁决面、提案不存在）→ `unavailable` / `empty` + 点名，**不伪造裁决、不静默丢弃**。
- **GWT-2 · 裁决交回 L2，只新增不改写**：Given 一张裁决卡与用户选择，When 提交，Then 经 L2 `ConflictQueue.resolve(conflict_id, decision, confirmed_by="user", reason)` 落裁决——`accept` → 新节点 + `evolves_from` 边、`reject` → 丢弃并记录；**L3 不自行改写 L2 图谱、不绕过 `resolve`**。
- **GWT-3 · 重复裁决与非法确认方一律拒绝**：Given 一条状态非 `pending` 的提案、或 `confirmed_by` 不是 `"user"`，When 提交裁决，Then `validation_failed` + 理由——**不吞 L2 的拒绝、不静默当成功**（04 §3.2 红线）。
- **GWT-4 · 方向判定归 L3 的注入端口（L2 册 `B1` 的解封条件）**：Given 结构化检测判不出「thesis 方向相反」（§1 的 `thesis` 只有自由文本 `view`，无方向字段），When L3 组织裁决，Then 方向候选经**注入的判定端口**得出；**缺省不注入即不判定**——卡上不给方向候选并**标注「方向未判定」**；**L2 节点模型不增字段**、`ThesisNode` 零返工。
- **GWT-5 · `memory_op` 去向接线**：Given 一张已确认的 `memory_op` 意图确认卡，When 经 [`DispatchBus.dispatch`](../../../../src/st_agent/l3/dispatch/bus.py) 派发，Then 不再走「去向尚未接入」的 `unavailable` 而是产出裁决卡；**未注入裁决面时仍 fail-closed（`unavailable` + 点名）**；同一改动**不得影响其余五类去向的既有行为**。

## 假设与前提

- **A1 · 裁决对话用专用卡，不并入 §3.2 的意图确认卡**：§3.2 的确认卡服务于**派发**（其条目即 §5 `understanding_summary` 的同一份内容源），而裁决没有派发目标 Skill、动作只有两个且与 L2 `resolve` 的 `decision` 一一对应。若错（须并入确认卡）：返工面＝本叶卡模型 + `memory_op` 去向的载荷形态。
- **A2 · 方向判定经注入端口，缺省不判定**：04 §4 原文把询问对话归 L3，且 `thesis` 无方向字段、L2 无 LLM 出口。若错（须由 L2 结构化判定）：返工面＝[04 §1](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) 节点模型 + `ThesisNode`（即册内 `B1` 已列的返工面）。
- **A3 · 裁决卡载荷往 `DispatchOutcome` 增字段而非复用 `draft`**：`draft` 现语义为 `configure` 去向的 `ConfigDraft` / `WorkflowDraft`（[`T-L3-003.1`](T-L3-003.1-草稿契约与生成与configure去向接线.md) 假设 A4）。若错（须统一成一类载荷）：返工面＝`DispatchOutcome` 的形状与 `T-L3-002.2` / `T-L3-003.1` 的既有用例。
- **A4 · 裁决卡的「两方内容」取自提案载荷与图上目标节点**：`MemoryConflictProposal.proposed` 是完整节点载荷（仅去 ID / 时间戳），既有方按 `target_node_id` 从 [`MemoryGraph`](../../../../src/st_agent/l2/memory/graph.py) 取。若错（提案载荷不足以呈现）：返工面＝L2 提案载荷（[04 §4](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) 面）。
