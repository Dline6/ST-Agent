# T-L2-002.1 · 自主写入白名单与写入策略（01 §7 配置条目）

## 目标

兑现 [04 §4](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) 第一句：**「自主写入白名单：按节点维度配置（注册进 01 §7 配置注册表）——哪些维度副驾可自主写入、哪些必须询问」**。交付 L2 侧的配置条目落盘与变更留痕共用件，以及在其之上的 `WritePolicy` 判定面：一条**推断类**新信息进来时，判它「可直写」还是「须进冲突队列」。

## 验收标准（Given-When-Then）

- **GWT-1 · 白名单是 01 §7 条目**：Given 本叶交付，When 取条目，Then 得到一条七字段齐备的 `ConfigEntry`（`config_id` / `display_name` / `value_schema` / `default` / `description_for_chat` / `panel_form_spec` / `scope` / `change_policy`），落 `config` 分区的 `memory-policy/write-whitelist.json`，取值域＝[04 §1](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) 的六类节点。
- **GWT-2 · 白名单内直写 / 白名单外须询问**：Given 一条 `source=inferred` 的新信息，When 其节点类型在白名单内，Then 判定为 `direct`（直写）；When 不在白名单内，Then 判定为 `propose`（须询问，进冲突队列）。
- **GWT-3 · 判定不看 source 之外的写入路径**：Given 一条 `source=user_stated` 的新信息，When 判定，Then 不适用白名单门（§3.2 用户显式写入直接写入）——白名单只约束副驾推断面。
- **GWT-4 · 改配置即生效且留痕**：Given 当前白名单，When 用户改一版，Then 落盘更新 + 产出一条 `ChangeRecord`（`change_id` 作回滚单位）写入 `execution_log` 的 `memory-policy-change/`；**值未变则不留痕**（不产空变更）。
- **GWT-5 · 越界取值显式失败**：Given 一个非六类节点的类型名，When 写入白名单，Then 显式拒绝（不静默丢弃、不静默取最近值）；条目缺失或损坏时读面回落缺省值而非停摆。

## 假设与前提

- **A1 · 白名单的「维度」粒度＝节点类型（六类）**：[04 §4](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) 写「按节点维度配置」而未定粒度（节点类型 vs 字段级）。取**节点类型**——与 §7「某维度无记忆」的维度口径一致，且配置面可读可改。若错（须字段级）：返工面 = `WritePolicy` 的取值域与条目 `value_schema`，落盘位置与判定入口不变。
- **A2 · 缺省白名单＝观察/历史/演化三类，画像/关注/观点三类须询问**：`pattern` / `evolution` / `history` 是「副驾观察到的事实」，自主写符合 §1 对 `pattern` 的定义；`identity` / `attention` / `thesis` 是用户自述面，取「必须问我」（宪法铁律 6 共同演化透明 + §3.2 红线取向）。**用户可改**。若错：改 `DEFAULT_WRITE_WHITELIST` 一处即可，无返工面。
- **A3 · 白名单只约束 `source=inferred`**：[04 §3.2](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) 已定「用户显式…直接写入」，§4 的白名单只管副驾推断面。若错（须对用户显式也设门）：返工面 = `decide` 的入口条件。
- **A4 · 白名单不覆盖「写入期不需要 LLM」这一前提**：本叶的判定是**结构化**的（类型 ∈ 白名单），不含语义比较——语义冲突检测归 [`.2`](T-L2-002.2-冲突检测提案队列与裁决落盘.md)。若错（须在同一门里做语义判定）：返工面 = 判定入口拆为两段。
