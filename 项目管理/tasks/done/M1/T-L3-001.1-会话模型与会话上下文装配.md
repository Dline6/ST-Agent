# T-L3-001.1 · 会话模型（树状会话 + 落盘 + 搜索 + 导出 + 上下文装配）（§1）

## 目标

兑现 [05 §1](../../../../docs/技术架构-v2/05-L3-对话主入口.md) 的会话模型：多轮、有状态、可回溯、**可分支**的树状会话；对话历史落 L0 `chat_history` 分区（完全离线可查、可搜索、可导出 Markdown）；会话上下文 = 当前会话消息 + [04 §3.1](../../../../docs/技术架构-v2/04-L2-记忆图谱.md) `MemoryReader` 切片（受 Token 预算约束）。本叶**只交付模型与数据面**，不含任何界面渲染。

## 验收标准（Given-When-Then）

- **GWT-1 · 树状会话与分支**：Given 一个已有若干消息的会话，When 任取一条消息发起分支并追加新消息，Then 新分支挂在被选消息之下，原链路的后续消息**不受影响**（可回溯到两条并存的分支）。
- **GWT-2 · 落盘与重启可读**：Given 一次会话写入，When 重新 `Store.open`（模拟断网重启），Then 全部消息按树结构完整读回（顺序、父子关系、角色、文本逐项一致）。
- **GWT-3 · 可搜索**：Given 多个会话的消息，When 按关键词搜索，Then 返回全部命中的消息与其所属会话（不编造、不遗漏；无命中返回 `empty` 并带原因）。
- **GWT-4 · 导出 Markdown**：Given 一个会话（含分支），When 导出 Markdown，Then 产出稳定可复核的文本——消息按时间序成节、角色与时刻可见、分支关系可辨，且**同一会话重复导出得同一文本**。
- **GWT-5 · 上下文装配受预算约束**：Given（会话 + 对话主题 + Token 预算），When 装配上下文，Then 结果 = 当前活跃链路的会话消息 + `MemoryReader` 切片，总字符数**不超预算**，且切片携 `as_of` 与置信度（消费方可区分「用户说的 / 推断的」）。

## 假设与前提

- **A1 · 落盘粒度＝「一会话一文件」**：[05 §1](../../../../docs/技术架构-v2/05-L3-对话主入口.md) 未定粒度。取一会话一份 JSON（根含会话元数据 + 完整消息树），使「分支」「导出」「读回」都在单次 `get` 内完成；`chat_history` 分区按会话名索引（`session/<id>.json`）。若错（须一消息一文件）：返工面 = `SessionStore` 的读写实现与 `list_files` 用法，公共 API 签名不变。
- **A2 · 搜索是**扫描式**而非倒排索引**：[05 §1](../../../../docs/技术架构-v2/05-L3-对话主入口.md) 只要求「可搜索」。本叶按分区内文件遍历 + 子串命中实现（`Store.list_files` + `get`），不建派生索引——建索引会引入「索引与真相源不一致」的第二个事实源，与单一事实源约束相抵。若错（须索引）：返工面 = `search` 实现，检索面接口不变。
- **A3 · 消息 ID 用本地前缀、**不新增契约 ID 类**：[01 §1](../../../../docs/技术架构-v2/01-平台共享契约.md) 的 14 类 ID 无 `session_id` / `message_id`；新增即契约变更（铁律 8）。沿用 [`T-SC-002`](../M0/T-SC-002-确定性摘要ID封堵随机产出面.md) 取向，取 `digest_id("msg", …)` 形态的本地标识。若错（须登记契约 ID）：返工面 = 01 §1 增两条 ID + 各层 `ID_ALIASES`。
- **A4 · 上下文装配的预算口径与 L2 一致（字符数近似）**：[§1](../../../../docs/技术架构-v2/05-L3-对话主入口.md) 说「受 Token 预算约束」而未定单位。本叶沿用 [`T-L2-001.3`](T-L2-001.3-MemoryReader上下文切片查询.md) 假设 A1 的字符数近似，并把预算在「会话消息 + 记忆切片」之间**显式分配**（消息优先保近、切片取剩余）。若错（须真实 tokenizer）：返工面 = `assemble_context` 的度量函数。
