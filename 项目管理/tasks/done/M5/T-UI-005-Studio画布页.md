# T-UI-005 · Studio画布页（真可编辑）

> 关闭 [L6 册 `B2`](../../../遗留问题/L6-遗留问题.md)（待人立项）——负责人 2026-10-09 拍定立项，按**真可编辑画布**做。

## 目标

把 `T-L6-004` 落到画布会话里的东西**真正渲染出来并可编辑**——[story-06](../../../../docs/PRD-v2-Agent/story-06-skill-studio.md) / [11-sitemap](../../../../docs/PRD-v2-Agent/11-sitemap.md) 的「Studio 主画布」表现层：已交 Studio 会话的画布（节点 / 连线 / 分组 / 校验违规）+ 可视化微调（增删节点 / 连线断线 / 建分组解散，经 `CanvasEditor` 同一判定件）+ 接受 / 否决，与「交 Studio」返回的句柄接上（`T-L6-004.2` 已交其会话与视图）。

**本批交付**（三处，见「拆分」）：

1. **后端**（组合根适配面 + 回环端点）：画布读面（`studio_canvas` 描述）+ 编辑转交（六个 `CanvasEditor` 操作）+ 可选 Skill 清单；表现层**不 import 各层类型**（口径同 `T-UI-004.2` 的 `ReflectionFacade`）。
2. **前端**（页面 + 渲染件 + 接线）：`/studio` 页 + `studio_canvas` 渲染件 + 编辑控件 + 与提案卡的互跳；只用 `textContent` / `replaceChildren` 构造 DOM，不解析任意代码。
3. **端到端**：集成套件以**真组合根**钉住一次「提案 → 交 Studio → 画布编辑 → 接受落编辑后 DAG」。

**本批的边界**（不越界）：

- **只做「已交 Studio 会话」的画布**——模板库 / 调试控制台 / 版本历史 / 导入导出仍留后续（story-06 其余屏不在本批）。
- 其余三处建议（周报第四段候选 / 训练建议 / 待批准队列）与提案卡既有行为**逐字节不变**。
- **后端接收面沿用不改**（[03 §4](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的 `DraftIntake` / `CanvasEditor` / `EditResult` 判定件不复制、不旁路）。

**拆分**（命中[拆分触发](../../../工作流.md)：涉及 [01 §12](../../../../docs/技术架构-v2/01-平台共享契约.md) / [05 §6](../../../../docs/技术架构-v2/05-L3-对话主入口.md) / [08 §4](../../../../docs/技术架构-v2/08-L6-反思演进.md) / [03 §4](../../../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 多个契约小节与 UI / L6 / L1 三层；单次预计 Agent 会话轮次 > 20）——父转分组节点，交付由两叶承接：

- [`T-UI-005.1`](T-UI-005.1-后端画布读面与编辑转交.md)——**后端**：契约登记 + 组合根画布读面与编辑转交 + 回环端点
- [`T-UI-005.2`](T-UI-005.2-前端画布页与渲染件.md)——**前端**：`/studio` 页面 + `studio_canvas` 渲染件 + 编辑控件与接线

不合并成一叶：两叶失败面不同（「读面错 / 转交错 / 信封错」vs「页面错 / 渲染错 / 路由错」），且 `.1` 是纯后端面（可被 Python 用例直接覆盖），`.2` 是前端工程。

## 验收标准（Given-When-Then）

取自 [story-06](../../../../docs/PRD-v2-Agent/story-06-skill-studio.md) 的「Studio 主画布」与 [11-sitemap](../../../../docs/PRD-v2-Agent/11-sitemap.md) 的「能力」区，逐条落到两叶（父级只汇总，不重复）：

- Given 一条已交 Studio 的提案，When 打开 Studio 页，Then 看到该会话画布（节点 / 连线 / 分组 / 首轮语义违规）与 `StudioDraftView` 一致 → [`.1`](T-UI-005.1-后端画布读面与编辑转交.md) GWT-1 / [`.2`](T-UI-005.2-前端画布页与渲染件.md) GWT-1
- Given 画布页，When 增删节点 / 连线断线 / 建分组解散，Then 经 `CanvasEditor` 同一判定件生效并即时重校验，被拦即显式原因、画布不变 → [`.1`](T-UI-005.1-后端画布读面与编辑转交.md) GWT-2 / [`.2`](T-UI-005.2-前端画布页与渲染件.md) GWT-2
- Given 编辑后的画布，When 接受 / 否决，Then 接受落 v1.0 并产生 `change_id`（落的是**编辑后** DAG）、否决不落盘 → [`.1`](T-UI-005.1-后端画布读面与编辑转交.md) GWT-3 / [`.2`](T-UI-005.2-前端画布页与渲染件.md) GWT-3
- Given 未交 Studio / 会话不存在 / 子面未接线，When 访问画布面，Then `unavailable` 或 `validation_failed` 并点名，不伪造画布 → [`.1`](T-UI-005.1-后端画布读面与编辑转交.md) GWT-4 / [`.2`](T-UI-005.2-前端画布页与渲染件.md) GWT-4
- Given 既有三处建议与提案卡，When 回归，Then 逐字节不变 → [`.1`](T-UI-005.1-后端画布读面与编辑转交.md) GWT-5 / [`.2`](T-UI-005.2-前端画布页与渲染件.md) GWT-5

## 假设与前提

- **A1 · 按交付面拆两叶**（2026-10-09 ④ 对齐拍定）——前提：读面与编辑转交是**纯后端面**（组合根 + 回环端点），页面与渲染件是**前端工程**，各有独立失败面。若错（要求更细 / 更粗的粒度）：返工面＝父子任务文件与 [T-INT-006](T-INT-006-M5集成关卡受控自主闭环.md) 的 `depends_on` 指向。**验证方式**：两叶各自范围套件 + `verify_docs --strict` 检查 7。
- **A2 · 真可编辑（2026-10-09 ④ 对齐拍定）**——前提：B2 解封条件字面即「可视化微调」，只读画布 + 接受 / 否决不算关闭 B2（那仍是 `T-L6-004` 的状态）。故六个 `CanvasEditor` 操作（增删节点 / 连线断线 / 建分组解散）经新端点暴露，被拦即显式原因。若错（要求只读）：返工面＝[`.1`](T-UI-005.1-后端画布读面与编辑转交.md) 的编辑端点与 [`.2`](T-UI-005.2-前端画布页与渲染件.md) 的编辑控件整段删除。**验证方式**：GWT-2 断每次编辑走 `CanvasEditor` 同一判定件。
- **A3 · 组件键取 `studio_canvas`**（2026-10-09 ④ 对齐拍定）——前提：[01 §12](../../../../docs/技术架构-v2/01-平台共享契约.md) 的键是小写下划线枚举（`proposal_card` / `change_timeline` 同型）。若错：返工面＝契约登记行 + 两侧注册表 + 渲染件名。**验证方式**：`tests/ui/test_ui_registry.py` 不改即绿。
- **A4 · 里程碑取 M5（零工具改动）**（2026-10-09 ④ 对齐拍定）——前提：`MILESTONES` 固定 M0–M5，而 [verify_docs 检查 7](../../../tools/verify_docs.py) 要求**有活跃任务的里程碑必有活跃 `T-INT-*` 关卡覆盖**；M4 的关卡 [T-INT-005](../M4/T-INT-005-M4集成关卡反思演进与生态闭环.md) 已归档，故归 M4 会破检查 7（除非改工具）。机械后果：`.1` / `.2` 须补进 [T-INT-006](T-INT-006-M5集成关卡受控自主闭环.md) 的 `depends_on`。**验证方式**：`verify_docs --strict` 检查 7 过。
- **A5 · 只做已交会话的画布，不碰模板库 / 调试 / 版本历史**（2026-10-09 ④ 对齐拍定）——前提：story-06 其余屏是独立后续工作，本批范围是 B2 解封条件（渲染草稿会话的画布 + 三态动作）。若错（要求本批出模板库等）：返工面＝本批范围扩张，应另立项。**验证方式**：`grep` 断言不新增模板 / 试跑 / 版本端点。
