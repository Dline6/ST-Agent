# T-UI-005.2 · 前端画布页与渲染件

## 目标

把 [`.1`](T-UI-005.1-后端画布读面与编辑转交.md) 的后端面**画出来并可点**：

1. **`/studio` 页面**（`ui/web/js/pages/studio.js`）：已交会话一览 + 单会话画布（节点表 / 连线表 / 分组 / 违规清单 / 会话信息）+ 编辑控件（增删节点 / 连线断线 / 建分组解散）+ 接受 / 否决；`PAGES` 登记 + `PAGE_PATHS` 登记。
2. **`studio_canvas` 渲染件**（`ui/web/js/plugins/studio/studio_canvas.js`）：按 `canvas` / `labels` 两槽渲染；`registry.js` 登记。
3. **接线**：提案卡 skill 项成功交 Studio 后给「去画布看看」链接（拼回 fragment 保令牌）；画布页的接受 / 否决走既有 decide 路由；每次编辑调 `/api/studio/edit` 并重渲染。

**本叶的边界**（不越界）：**不动任何 Python 后端判定**（只调 [`.1`](T-UI-005.1-后端画布读面与编辑转交.md) 的端点）；**不动**既有页（reflection / evolution / eco）与提案卡既有行为（只增一条互跳链接）；**不引入** `eval(` / `new Function` / 动态 `import()`（既有纯性断言不破）。

## 验收标准（Given-When-Then）

- **GWT-1 · Studio 页与渲染件**：Given 一条已交 Studio 的提案，When 打开 `/studio?proposal_id=<id>`（或从一览点入），Then 看到该会话画布——节点表（node_id / skill_id）/ 连线表（edge_id / from → to）/ 分组（group_id / name / 成员）/ 违规清单 / 会话信息（base / 暂定 flow_id / 节点数 / 状态），与 `GET /api/studio/canvas` 的载荷一致；未知 `component_type` 仍走显式降级占位（不猜测）。
- **GWT-2 · 真可编辑**：Given 画布页，When 增节点（填 node_id + 选 skill_id）/ 删节点（连带提示）/ 连线 / 断线 / 建分组 / 解散分组，Then 每次调 `POST /api/studio/edit` 并按回载重渲染画布 + 校验结论 + `message`；被拦（成环 / 契约不匹配 / 标识重复）→ 显式原因、画布保持操作前状态（`applied=false` 即不刷新为新 DAG）。
- **GWT-3 · 接受 / 否决与互跳**：Given 画布页，When 点接受 / 否决，Then 走既有 `/api/reflection/proposals/studio/decide`，接受显 `flow_id` + `change_id`、否决显已否决；Given 提案卡 skill 项交 Studio 成功，When 看卡，Then 有「去画布看看」链接跳 `/studio?proposal_id=<id>`（`href` 拼回当前 fragment，跳页不丢令牌）。
- **GWT-4 · 空态与失败**：Given 无已交会话（`opened()` 空），When 打开 `/studio`，Then 空态文案（不硬凑假会话）；Given 非法 `proposal_id` / 未接线，When 访问，Then 显式错误态（信封 `validation_failed` / `unavailable` 的 `reason` 原样呈现，不伪造画布）。
- **GWT-5 · 既有页回归**：Given reflection / evolution / eco 各页与提案卡，When 回归，Then 行为逐字节不变；`tests/ui/test_ui_registry.py` 全绿（两侧注册表不漂移）；`grep` 断言 `ui/web/**` 无 `eval(` / `new Function` / 动态 `import()`。

## 假设与前提

- **A1 · 画布用表格呈现，不做 SVG 连线图**——前提：B2 解封条件是「渲染节点 / 连线 / 分组 / 校验违规 + 三态动作」，story-06 的「节点 + 连线 + 分组框」可视化语义由**表格 + 违规清单**完整承载；SVG 拖拽画布是交互升级，不在 B2 字面内。若错（要求拖拽画布）：返工面＝渲染件重写为 SVG 交互，应另立项。**验证方式**：GWT-1 断四块信息齐全且与载荷一致。
- **A2 · 加节点只填 node_id + 选 skill_id，不填 params**——前提：[[`.1 A3`](T-UI-005.1-后端画布读面与编辑转交.md)]（参数绑定本批不开放编辑），故新增节点一律空 `params`（Skill 默认值在执行期生效）。若错：返工面＝加节点表单增参数分支。**验证方式**：GWT-2 加节点只断 node_id + skill_id。
- **A3 · 互跳链接只增不改**——前提：提案卡既有「交 Studio → 接受 / 否决」流程不变，互跳只是成功后多一条去画布的路；画布页的接受 / 否决与卡上同动作语义一致（同一条 decide 路由）。若错（要求卡上流程改走画布页）：返工面＝`proposal_card.js` 动作行重写。**验证方式**：GWT-3 + GWT-5 成对（新增链接 + 既有流程不变）。
- **A4 · 单会话寻址经 query 串 `proposal_id`**——前提：页面路由走路径（`pages.js` 按 `pathname` 选页），会话标识放 query 串（`location.search`），令牌仍在 fragment——三者不打架。若错：返工面＝页面寻址改路径段。**验证方式**：GWT-1 直开带参 URL 成立；跳页保令牌不断言失败。
