# T-UI-028.4 · 手动同步与后台任务（P0）

## 目标

- 数据同步视图提供按域分组的任务勾选，支持「同步所选」「同步全部」。
- 同步在后台线程顺序执行（单任务并发＝1），页面返回任务 ID 并轮询进度；可离开本面。
- 自动补结构前置（行情 / 财务任务的 `needs`）；建库 / 主档未就绪时给显式建议。
- 逐任务回报状态与原因；结束后刷新总览。

## 验收标准（Given-When-Then）

- GWT-1：Given 勾选若干任务，When 点「同步所选」，Then 返回 `job_id`，任务按依赖顺序后台执行，页面可离开。
- GWT-2：Given 一个同步任务正在跑，When 再次触发同步，Then 明确拒绝（`validation_failed` + 原因），不并发写库。
- GWT-3：Given 勾选 `bs_k_daily`，Then 自动补入 `bs_calendar` / `bs_all_stock` 两个前置，并在结果中标注「自动补入」。
- GWT-4：Given 某个任务失败，Then 其余任务继续执行，失败任务在结果中如实呈现状态与原因，不把整批报成成功。
- GWT-5：Given 同步结束，Then 数据总览的行数 / 状态 / 最近成功随之更新。

## 接口面

- 输入：
  - [`T-UI-028.3`](T-UI-028.3-数据总览读面.md) 的 `DataSyncRunner.overview()`
  - `BaoStockSync` / `InfoSync` 的 `setup` / `run_task`（[`T-L0-005`](done/M0/T-L0-005-数据源缓存BaoStock首个源落地.md) / [`T-L0-010`](done/M2/T-L0-010-多源信息面采集与管理机制.md)）
  - `BaoStockFetcher`（`l0/market/live.py`）· `HttpInfoFetcher`（`l0/info/fetch.py`）
  - 关注池：`MemoryPositionsFacade.codes("holdings") + codes("watchlist")`
  - 信息面开关：`enabled_task_map(store)`
- 输出：
  - `DataSyncRunner.start(task_keys)` / `.job()`（后台线程 + 单飞锁 + 逐任务结果）
  - `UiApp.api_settings_data_sync`；`POST /api/settings/data/sync`
  - `src/st_agent/ui/web/js/pages/settings.js` 的勾选、发起、轮询与结果回报

## 可关闭的遗留

无。

## 假设与前提

- A1：同步任务可在**后台守护线程**执行；`Store` 分区锁与 `MarketDb` 事务保证与 UI 只读查询不互相撕裂。若错：并发读写导致清单损坏。验证方式＝用例在同步进行时并发调用 `overview()`。
- A2：批次串行执行，不并发多任务——`MarketDb.transact()` 是「整库取 blob → 写回」，并发任务会互相覆盖。若错：丢写入。验证方式＝用例断言第二次启动被拒。
- A3：真实抓取器可能缺席（`baostock` 未装）或不可达；此时任务结果为 `unavailable` 并写明原因，不把整批报成内部错误。验证方式＝注入缺依赖 / 抛 `FetchUnavailableError` 的替身。
- A4：首次全量可能耗时很长（全市场日线）；页面只呈现进度、不阻塞 HTTP，也不假装能预估完成时间。验证方式＝替身跑多任务并断言进度推进。
