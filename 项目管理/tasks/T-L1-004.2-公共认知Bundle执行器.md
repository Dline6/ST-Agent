# T-L1-004.2 · 公共认知 Bundle 执行器

## 目标

为 03 §2.1 公共认知 Bundle 的 6 个 Skill 交付**可执行实现**：`st-list-sync` / `delisting-risk-scan` / `unhat-eligibility-check` / `sector-heatmap` / `sentiment-flow-analysis` / `fundamental-screening`——各自履行 §2.1 表列的职责与关键输出，取数经 `.1` 的基件进入 L0 数据源缓存，输出过各自 `output_schema`，且**去拟人化**（承接 v1 的「散户模拟 / 机构模拟」命名被替换为 `sentiment-flow-analysis` / `fundamental-screening` 的同一去人格化动作）。

## 验收标准（Given-When-Then）

- GWT-1 六个执行器逐个产出：Given 已装载的运行时 + 离线数据面（Fake 取数源注入固定行情 / 财务 / 板块行），When 逐个 `runner.run(skill_id, {})`，Then 六条信封均为 `ok`，且载荷通过各自描述体的 `output_schema` 核验（runner 侧核验点不得把任一官方 Skill 打成 `failed`）。
- GWT-2 `st-list-sync` 的 diff 语义：Given 两个交易日的 ST 标记不同，When 执行，Then 输出名单变更 `diff` 同时含**新增**与**移除**两个方向，且逐条给出 `code`（无变更时 `empty` + 原因，不返回 `ok` 包空 diff）。
- GWT-3 `delisting-risk-scan` 可解释：Given 命中退市高危信号的样本，When 执行，Then 每条信号携带**触发原因**与人可读说明，并用 `evidence_refs` 指明证据来源（`dataset_snapshot_id`，01 §1 合法 ID 类型）。
- GWT-4 去拟人化：Given 六个 Skill 的全部输出，When 过 `NeutralityGuard.check_output`，Then 无拟人化命中（不含第一人称 / 情感 / 人名 / 对话体；01 §6）。
- GWT-5 数据面缺失不编造：Given 取数源对任一查询返回 `unavailable` / `empty`，When 执行对应 Skill，Then 信封状态与原因**原样透出**（`unavailable` 带最后更新时间），不出现 `ok` 包造出的替代数据。

## 接口面

- 输入（消费的前置接口）：
  - `T-L1-004.1` `st_agent.l1.skills.official.common`：`MarketQuerySource` 协议、`query_rows(source, sql, params=())`、`ok_envelope(payload, source)` / `empty_envelope(reason, source)`（取数与挂 `as_of` 的唯一入口）
  - `T-L1-004.1` `st_agent.l1.skills.official.install`：`OFFICIAL_EXECUTORS` 登记表（本任务按其约定回填 6 个 `base` 的执行器工厂）
  - `T-L0-005` [数据库设计族](../../docs/数据库设计-BaoStock数据层/README.md) 的表与视图：`security`（`code` / `code_name` / `type` / `status`）、`k_line_daily`（`close` / `preclose` / `pct_chg` / `turn` / `amount` / `pe_ttm` / `pb_mrq` / `is_st` / `trade_status`）、`v_st_universe`（当前 ST 池）、`stock_industry`（行业快照）、`financial_quarter`（`roe_avg` / `np_margin` / `net_profit` / `yoy_ni` / `liability_to_asset`）、`performance_express`（`net_asset`）、`profit_forecast`（`forecast_type` / `chg_pct_up` / `chg_pct_dwn`）
  - `T-L1-001.2` [`runner/runner.py`](../../src/st_agent/l1/runner/runner.py)：`SkillContext`（`skill_id` / `skill_run_id` / `trace_id` / `upstream`）
  - `T-L1-001.1` 参数面：各 Skill 已声明参数的**默认值即合理口径**（`exchange` / `threshold` / `fiscal_years` / `top_n` / `window_days` / `margin`）
- 输出（本任务交付的公共 API / 落盘位置）：
  - `st_agent.l1.skills.official.cognition`：6 个执行器工厂（各为 `market_query -> SkillExecutor`），经 `OFFICIAL_EXECUTORS` 按 `base` 登记，由 `install_official_pack` 装载
  - 载荷形态（关键输出，须与 03 §2.1 表一致；`output_schema` 只约束已声明属性，附加字段允许）：
    - `st-list-sync` → `{"diff": {"added": [...], "removed": [...], "counts": {...}, "as_of_date": str}}`
    - `delisting-risk-scan` → `{"risk_level": str, "triggers": [{"code", "reason", "detail"}], "evidence_refs": [...]}`
    - `unhat-eligibility-check` → `{"conditions": [{"name", "satisfied", "detail"}], "score": float}`
    - `sector-heatmap` → `{"heatmap": {"industries": [...]}, "rating": str}`
    - `sentiment-flow-analysis` → `{"warnings": [{"code", "kind", "detail"}]}`
    - `fundamental-screening` → `{"pool": [{"code", "score", "reasons"}]}`
  - 落盘：沿用既有布局，**不新增分区**（SkillRun 由 runner 落 `execution_log/skill-run/`，执行器本身无状态、不落盘）
  - 消费方：`T-L1-004.3`（`risk-alert` / `opportunity-mine` 依上游输出）、`T-L1-003.5` 的官方模板（「每日 ST 简报」「退市风险扫描」的节点即这 6 个 Skill）、`T-INT-001`

## 假设与前提

- A1 各 Skill 的**默认口径**取「本地缓存全量」（ST 池 / 全市场 / 全部行业），参数用于收窄（阈值 / 窗口 / 条数）；不依赖任何未声明的输入通道（父任务 A1 的子口径）/ 若错（须按标的逐个调用）：返工面＝`.1` 的输入通道口径 + 本任务 6 个执行器 / 验证：GWT-1 以空参 `{}` 执行六条全部 `ok`。
- A2 `st-list-sync` 的「新增 / 移除」以**本地相邻两个交易日的 ST 标记**为对照（无交易所侧名单接口时唯一可离线复现的口径；Story 的 Out of Scope 未含交易所名单接口，故本地口径即当前承诺面）/ 若错（须以交易所公告为准）：返工面＝该执行器 + 生态侧公告源任务 / 验证：GWT-2 双向 diff 用例 + 无变更时的 `empty` 用例。
- A3 指标阈值取**可解释的规则常量**（如面值退市 `close < 1`、换手率与涨跌幅分位、`roe_avg` 与安全边际），不引入黑箱打分；常数集中定义于模块内便于复核 / 若错（口径须由产品给定）：返工面＝该常量表 + 相应用例 / 验证：GWT-3 断言触发原因逐条可读且与常数一致。
- A4 输出**去拟人化**由本任务在实现期自证（GWT-4），不把校验责任推给渲染层——`sentiment-flow-analysis` / `fundamental-screening` 承自 v1 的「散户 / 机构模拟」，措辞须为陈述式 / 若错（渲染层才校验）：`NeutralityGuard.check_output` 的消费点须前移，须改 [03 §1.2](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) / 验证：GWT-4 过 `NeutralityGuard.check_output`。
- A5 「数据不可用 / 空结果」的分支**不在本任务重判**，只断言透传正确（沿用 `.1` 的 A4）/ 若错：返工面＝`.1` 基件 / 验证：GWT-5 对六条逐个断言信封状态与原因与取数源产出逐字段相等。
