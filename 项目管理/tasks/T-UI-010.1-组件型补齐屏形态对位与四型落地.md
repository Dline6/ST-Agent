# T-UI-010.1 · 组件型补齐：屏→形态对位与四型落地

> [T-UI-010](T-UI-010-契约先行组件型补齐与页面集口径.md) 的组件型叶（[D-108](../决策日志.md)）。把 [11-sitemap §2](../../docs/PRD-v2-Agent/11-sitemap.md) 的每条屏对位到**呈现形态**，对 [01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 的枚举面逐条表态；缺口处**先改契约、再改代码**（[铁律 8](../工程宪法.md)）。

## 目标

两件交付，都在**契约 + 镜像**面（本叶**不建任何页面**）：

1. **屏 → 形态对位表**——[11-sitemap §2](../../docs/PRD-v2-Agent/11-sitemap.md) 的全部屏逐条落一条**归属**，四类之一：① **复用**某既有已实现型；② **新登记并实现**（枚举面原无此型）；③ **预留型升实现**（枚举面已登记其名，补实现属「实现」非「改契约」）；④ **非组件型面**——页面（页面登记归 [`T-UI-011`](T-UI-011-底座与骨架多面端口注入与全IA页面登记.md)）/ 壳面（对话流宿主、输入面、全局 chrome）/ 对话流内面（L3 协议模型直出，如 `ClarificationRound` / `IntentConfirmation`，不经组件注册表）。**无未表态者**。
2. **四型落地**——对位表判定确需的型，两侧一次做齐：契约行（若为新登记）+ [`ui_description.py`](../../src/st_agent/contracts/ui_description.py) 的 `ComponentType` / `IMPLEMENTED_COMPONENT_TYPES` + [`ui/registry.py`](../../src/st_agent/ui/registry.py) 的 `REQUIRED_SLOTS` + 前端 [`registry.js`](../../src/st_agent/ui/web/js/registry.js) 的渲染件 + [13-visual-design §5](../../docs/PRD-v2-Agent/13-visual-design.md) 视觉基线行 + 两侧类型集合一致性断言。

**本批的边界**（不越界）：

- **不改既有型的槽语义**——只增不改；某既有型的槽词汇确需变更时按[铁律 8](../工程宪法.md) 另立条目、不在本叶夹带。
- **不建页面、不注入端口**——页面登记与端口注入归 [`T-UI-011`](T-UI-011-底座与骨架多面端口注入与全IA页面登记.md)。
- **不重排 IA 既有分区**——11-sitemap 的分区编排归 [`T-UI-006`](T-UI-006-IA补章受控自主分区与页面Flow.md)，本叶只在其上表形态。
- **不引构建链**——[D-063](../决策日志.md) 的零构建原生 ES 模块口径不动。
- **不重复定视觉**——只补 §5 的基线行，配色 / 令牌由 [`T-UI-007`](T-UI-007-视觉设计规范研判页方向与token层.md) 已定的规范承接。

## 假设与前提

- **A1**：§2 的「屏」与 01 §12 的「组件型」是**两个粒度**——屏可以是页面 / 壳面 / 对话流内面，不必各对应一个组件型。**若错的影响**：要求「每屏一型」则对位表口径整体返工，且会为对话宿主、快捷指令菜单等造出无渲染意义的型。**验证方式**：对位表里非组件型面逐条给出直出模型（如 `ClarificationRound` / `IntentConfirmation` 持 `ResultEnvelope` 而无 `component_type`，见 [`l3/intent/protocol.py`](../../src/st_agent/l3/intent/protocol.py)）作为证据。
- **A2**：记忆区「图谱视图」的节点-边图**不复用** `divergence_map`——后者 `REQUIRED_SLOTS` 为 `("matrix", "network")` 两者同必填，且其槽语义对位「分歧」（[铁律 4](../工程宪法.md)）；复用会迫使记忆面的描述同时携带一张空分歧矩阵并混淆语义。**若错的影响**：省一次新登记（01 §12 少一行、渲染件少一个）。**验证方式**：查 `divergence_map` 的 `REQUIRED_SLOTS` 与 [06 §5](../../docs/技术架构-v2/06-L4-多视角推理.md) 的两视图均实现要求。
- **A3**：四型判定＝`graph_view` / `timeline_view`（新登记并实现）+ `heatmap` / `trend_chart`（预留升实现）；后两型有 story 级需求出处（[story-01](../../docs/PRD-v2-Agent/story-01-chat-as-os.md) 的看板含热力图、看板 / 图表），`timeline_view` 跨记忆 / 触达两区同形（记忆时间线 · 修正历史 · 推送历史）。`pinned_board` / `risk_badge` **保留预留**——前者对位「工作区」承载页（钉住物按**自身型**渲染，§5 允许 `data` 为**描述序列**，看板即该序列），后者对位偏好画像卡内**单元级装饰**（[05 §2](../../docs/技术架构-v2/05-L3-对话主入口.md) 的 ≤5 标签由 `report_card` 段承载；徽章同 §5.1 涨跌三路编码由渲染件一次产出的先例）。判据另核 [05 §6](../../docs/技术架构-v2/05-L3-对话主入口.md) 的注册表表述明列「趋势图、热力图、风险徽章」而未列看板。**若错的影响**：少实现 1–2 型或需追加，波及 [`.2`](T-UI-010.2-页面集与导航模型.md) 的路径表与后续七叶。**验证方式**：对位表逐条给判据；`heatmap` / `trend_chart` 各有 story 级需求出处（[story-01](../../docs/PRD-v2-Agent/story-01-chat-as-os.md) 的看板含热力图、看板/图表）。
- **A4**：**槽词汇不属契约面**（[D-064](../决策日志.md) / [D-102](../决策日志.md) 已定）——01 §12 只登记**型**与通用槽形状，槽名由两侧共同约定、机器可读副本在 `REQUIRED_SLOTS`。**若错的影响**：新型的槽名要写进 01 §12，契约面扩大。**验证方式**：01 §12 的字段表本就不列槽名（只有「命名槽 → 已解析 JSON 值」的形状条款）。
- **A5**：`RESERVED` 由 4 型缩到 2 型（`risk_badge` / `pinned_board`）后，既有的「预留型不被判缺槽」用例需换样例——本批把 `tests/ui/test_ui_registry.py::test_reserved_type_is_not_judged_here` 的样例由 `heatmap` 改为 `pinned_board`（**行为断言不变**）。**若错的影响**：该用例红。**验证方式**：跑 `tests/ui/test_ui_registry.py`。
