# T-L4-004 · 分歧图可视化 + 边界与特殊情形

## 目标

兑现 [06 §5 分歧图可视化](../../docs/技术架构-v2/06-L4-多视角推理.md)（矩阵视图为主 + 证据网络图为辅 + 追问接口）与 [§6 边界与特殊情形](../../docs/技术架构-v2/06-L4-多视角推理.md)（全部视角一致 → 群体思维提示），把 [`T-L4-003`](T-L4-003-交叉对照MiniDebate冲突质询.md) 的 `DisagreementMap` 变成**可渲染的分歧图**。

**父任务本身不产出代码**——按 ④ 对齐拆两叶：`.1` L4 侧的**视图数据面**（矩阵要全部参与视角的立场/信心度，`DisagreementMap` 只带冲突对各两方 → 必须由 [`T-L4-002`] 的 `DeliberationResult` 派生）与 §6 一致性语义；`.2` L3 侧的 **`divergence_map` 描述件**（[01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 的产出方＝L3）+ 组件升真 + 前端渲染件。

**落层依据**（决策 [D-071](../决策日志.md)）：[01 §12](../../docs/技术架构-v2/01-平台共享契约.md)／[05 §6](../../docs/技术架构-v2/05-L3-对话主入口.md) 规定 UI 描述由 **L3 产出**（分歧图列在 L3 特有组件内），而 [`test_layering.py`](../../tests/test_layering.py) 的 `LAYER_ORDER` 是 `l3 < l4`（**L3 不得 import L4**）——两条同时成立只能靠**鸭子端口/鸭子取值**：`.2` 的描述件按属性取值收 `.1` 的 `DivergenceView`，不 import `st_agent.l4`。

## 验收标准（Given-When-Then，从 Story 4 + 06 §5–§6 抄，限本任务范围）

- **GWT-1**（两视图）Given 一次 Deliberation 的 `DisagreementMap` 与各视角观点，When 生成分歧图，Then 产出**矩阵视图**（视角 × 结论：每行一个参与视角的立场与信心度）与**证据网络图**（节点 + 引用边）两视图，**均实现**（06 §5「两视图均实现」）。
- **GWT-2**（追问接口）Given 矩阵中的某一行视角，When 用户追问，Then 可定位该视角的完整 Trace（每行携 `trace_id`），复用 [05 §7](../../docs/技术架构-v2/05-L3-对话主入口.md) 的 `trace_timeline` 渲染（不另造一套推理链渲染）。
- **GWT-3**（一致性提示）Given 全部参与视角均有结论且立场唯一，When 判断，Then 给出中性提示「罕见的高度一致，请警惕群体思维」且**仍完整展示证据**（不因一致而裁掉证据面）；Given 存在 `insufficient-data` 视角或立场不唯一，Then 不给该提示（不臆断「高度一致」）。
- **GWT-4**（组件升真与两端不漂移）Given `divergence_map` 原为「已登记未实现」，When 本任务落地，Then 它升为**本期实现**型且前端注册表同步（两侧类型集合相等、必填槽齐）——属**实现**而非改契约（[01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 提前登记的用途）。
- **GWT-5**（无合并结论）Given 分歧图的视图数据面与描述件，When 检视字段，Then **均无** `verdict` / `recommendation` / `summary` 等合并结论字段（[铁律 4](../../项目管理/工程宪法.md) 的机器化，沿用 `T-L4-003` 的 `hasattr` + `model_dump` 双向钉法）。

## 假设与前提

- **A1**：一致性判据取「**全部参与视角均有结论**（无 `insufficient-data`）且立场唯一」。**若错**（要求放宽为「多数同向即提示」）：只需改 `.1` 的一个谓词。**验证**：GWT-3 两用例（全一致 → 提示 / 含数据不足视角 → 不提示）。
- **A2**：`divergence_map` 由 RESERVED 移入 IMPLEMENTED 属**实现**（[01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 「提前登记使后续补这些形态属于实现而非改契约」的明文用途），`§12` 的字段表与槽形状不动（槽词汇表归 D-064 口径）。**若错**（判定为契约变更）：按 [铁律 8](../../项目管理/工程宪法.md) 先改 01 → 再改 05 / 06 → 最后改代码。**验证**：GWT-4 两端注册表一致。
- **A3**：描述件**鸭子取值**收 `.1` 的 `DivergenceView`（不 import `st_agent.l4`）——同 [`l4/deliberation.py`](../../src/st_agent/l4/deliberation.py) 收 `roster` / `runner` 的注入范式，也是 [01 §12](../../docs/技术架构-v2/01-平台共享契约.md)「产出方＝L3」与 `LAYER_ORDER` `l3 < l4` 同时成立的唯一解。**若错**（要求 L3 直接 import L4 类型）：须改 `LAYER_ORDER` 或放开 `test_only_downward_dependencies`，属架构级返工。**验证**：`test_layering.py` 全绿 + `l3/render/describe.py` 无 `st_agent.l4` import。
- **A4**：06 §6 的另三条不属本批——**空状态入口**（数据面 `has_custom()` 已交付，入口属渲染面）、**无建议字段**（`DisagreementMap` 已由 `T-L4-003` 钉住；本批对新模型同型自钉，视为新模型自身正确性）、**触达联动**（M3/L5）。**若错**（要求本批一并落空状态入口）：须改前端骨架与 L4 阵容的交互面，另立任务。**验证**：GWT-5 钉「无合并结论」；空状态 / 触达在任务「接口面」的「不交付」段显式点名归属。
