# T-L0-005.1 · BaoStock 真实抓取器接入与首次真实入库

## 对齐（④ · 2026-09-25 人指示「帮我真实入库」后立项、「请开始」「继续」后开工）
- 交付：`Fetcher` 协议的联网实现 `BaoStockFetcher` + 首次真实入库验证（元数据 + 单证券行情样本）
- 验收：见下 3 条 GWT（真实登录拉取 / 行情样本入库 / 失败可解释）
- 路径：`live.py` 封装 `login → 批量 query → logout`；复用 T-L0-005 的 `BaoStockSync` + 网关按次 sender 注入；不引入 `pandas`（逐行 `get_row_data`）；真实库只落 `tmp/` 不入库
- 假设与前提：
  - A1 本机可联网直达 BaoStock 服务（登录/查询走公网；断网则走 GWT-3 `unavailable` 分支，不做离线重试）
  - A2 `baostock` 包版本 ≥0.9.4（`pip install baostock`；缺失构造即 `FetchUnavailableError`，不做包内兜底）
  - A3 源端字段语义与 06-API映射契约一致（`adjustflag=3` 只取不复权；准备金 `yearType=0` 公告日口径；`mortgate` 拼写沿用映射层修正）
  - A4 首次入库为样本验证（元数据全量 + 1 只证券），非全市场全量——全量 `run_all` 体量大，另行排期（见执行日志遗留②）
  - A5 真实数据仅落本地加密库与 `tmp/` 验证库，不进 Git（`.gitignore` 已覆盖 `*.db`）；验证通过后 `tmp/` 即清
- 未决：无（open 未决 0；源端限流阈值未触发，如全量时遇限流另立任务处理）

## 目标
兑现 T-L0-005 遗留③——按 `Fetcher` 协议封装真实 `baostock` 抓取器（`login → 批量 query → logout`），跑通首次真实入库（元数据 + 一小批行情），抓取经网关审计。

## 验收标准（Given-When-Then）
- GWT-1 真实登录拉取：Given 本机联网且装好 `baostock` 包，When 执行 `bs_calendar`（小窗口）+ `bs_security_basic`，Then 真实行入库（`trade_calendar` / `security` 有行），网关记 `data_fetch`/`baostock` 审计。
- GWT-2 行情样本入库：Given 元数据已就绪，When 对 1–2 只证券跑 `bs_k_daily`（近 5 个交易日，`adjustflag=3`），Then `k_line_daily` 有行且水位回写，全程无 Fake 注入。
- GWT-3 失败可解释：Given 源不可达或包缺失，When 执行同步，Then 走 `unavailable`/`failed` 显式分支（不抛裸异常、不写脏水位）。
