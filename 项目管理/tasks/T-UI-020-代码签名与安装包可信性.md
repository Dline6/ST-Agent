# T-UI-020 · 代码签名与安装包可信性

> **M7 打包发布叶之一**（[D-103](../决策日志.md)：签名）。未签名的 exe / 安装包在 Windows 上触发 SmartScreen 与「未知发布者」警示——「本地优先 / 数据主权」的产品不该让用户绕过系统安全警告来装它。

## 目标

给 [`T-UI-019`](T-UI-019-Windows安装器与安装体验.md) 的安装包与其中的可执行文件加**代码签名链**：

- **签名对象**：安装包本体 + `st-agent-server.exe` / `st-agent-shell.exe`（含内嵌的 PyInstaller 冻结运行时）逐个签名
- **时间戳**：签名带可信时间戳（离开签名有效期后仍可验）
- **构建集成**：签名步骤接进 `packaging/build.py`（或安装器构建脚本），密钥 / 凭据**不入仓**（经环境 / 凭据库存取）
- **验签口径**：签名后 `signtool verify` 通过；SmartScreen 行为**如实记录**（EV / OV 证书差别的实测结论写进留痕）

**本批的边界**（不越界）：

- **不采购证书**——证书的获取 / 预算 / 类型（OV / EV / 是否走托管）属**人决**，④ 对齐时登记未决或决策；本叶交付**签名机制与集成**，证书到位即可签。
- **不改安装包内容**——安装器构建归 [`T-UI-019`](T-UI-019-Windows安装器与安装体验.md)，本叶只叠加签名。
- **不做 macOS / Linux 签名**（[D-103](../决策日志.md) ③）。

## 验收标准（Given-When-Then）

- GWT-1：Given 有可用证书的环境，When 跑构建，Then 安装包与两份 exe **逐个**签名成功、带时间戳
- GWT-2：Given 已签名安装包，When `signtool verify`，Then 通过；安装包属性页「数字签名」显示发布者（**非**「未知发布者」）
- GWT-3：Given 无证书的构建环境，When 跑构建，Then **显式跳过**签名并**大声标注**产物未签名（**不**静默产出一个看起来正常的包）
- GWT-4：Given 构建脚本，When 查源码，Then 密钥 / 密码 / 证书**不在仓内**（经环境变量或 OS 凭据库存取），且不落进日志
- GWT-5：Given 签名后的包，When 在一台干净机安装，Then SmartScreen 实测行为如实记录（含证书类型说明）
