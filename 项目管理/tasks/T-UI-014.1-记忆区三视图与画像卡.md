# T-UI-014.1 · 记忆区三视图与画像卡

> [`T-UI-014`](T-UI-014-记忆区三视图画像卡与节点详情.md) 三叶之一（[D-111](../决策日志.md) ①）。三视图是 [11-sitemap §2 记忆](../../docs/PRD-v2-Agent/11-sitemap.md) 的五条屏里**共用同一查询层**的那三条——[`MemoryReader.query`](../../src/st_agent/l2/memory/reader.py) 的 `view` 槽早已支持 `graph` / `list` / `timeline`，但**无宿主页、无 HTTP 端点**；`graph_view` / `timeline_view` 两型的**渲染件已就位**（[`T-UI-010.1`](T-UI-010.1-组件型补齐屏形态对位与四型落地.md) 登记并实现）而 **Python 侧无 `describe_*`**——这是 M6 里「渲染件在、取数面缺」的第一处真实缺口。

## 目标

- **三视图共享同一查询层**：三条视图走**同一条** `MemoryReader.query(SliceQuery(view=…))`，只换排序不换候选集（[04 §3.1](../../docs/技术架构-v2/04-L2-记忆图谱.md)）；图谱视图取材 `graph_view`、列表视图取材 `table`、时间线视图取材 `timeline_view`
- **偏好画像卡**：`identity` / `evolution` 节点摘要，**不超过 5 条**关键标签
- **页内视图切换**：`/memory` 一条路径承载三视图（[11-sitemap §2.2](../../docs/PRD-v2-Agent/11-sitemap.md)），不新增路由

**本批的边界**（不越界）：

- **不新登记组件型**——三视图复用既有 `graph_view` / `table` / `timeline_view`，画像卡复用既有 `report_card`（[01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 的枚举面无需改动）
- **不重造持仓 / 关注行情读面**（[`T-UI-009`](T-UI-009-记忆区持仓行情读面.md) 已交付）——本叶在其所在页上加三视图与画像卡
- **节点详情 / 修正历史归 [`.2`](T-UI-014.2-节点详情与修正历史.md)、导入导出与 Onboarding 归 [`.3`](T-UI-014.3-导入导出面板与Onboarding.md)**

## 验收标准（Given-When-Then）

- GWT-1：Given 记忆图谱，When 切三视图，Then 三条视图走**同一查询层**——候选集相同、仅组织不同；图谱视图出节点-边、列表视图出逐条、时间线视图按时刻组织
- GWT-2：Given `identity` / `evolution` 节点，When 看画像卡，Then 出「当前画像」摘要且**标签数 ≤ 5**，超出即显式收窄（不静默丢弃）
- GWT-3：Given 记忆内容（`data` 槽）混合生成文案，When 渲染，Then 记忆本体**原样呈现**（[D-053](../决策日志.md)）、系统文案（节点类型名 / 关系名 / 隐私分级名）经生成文案槽下发，**无拟人化**（[契约 9](../../docs/PRD-v2-Agent/10-platform-capabilities.md)）
- GWT-4：Given 空记忆，When 呈现，Then `empty` + 引导（**不静默留空**）；Given 面未接线，When 呈现，Then `unavailable` + 点名（[01 §5](../../docs/技术架构-v2/01-平台共享契约.md)）
- GWT-5：Given 真组合根 + 真回环服务，When 在 Edge 走查三视图与画像卡，Then 全程可用、控制台无新增报错

## 接口面

- 输入（消费的前置接口）：
  - `graph` 鸭子端口（[`T-UI-011.1`](T-UI-011.1-多面端口注入与各面门面装配.md) 已注入）——经 [`GraphFacade`](../../src/st_agent/app.py) 取 `reader`（三视图查询层）与 `graph`（画像取材）
  - [`MemoryReader.query`](../../src/st_agent/l2/memory/reader.py) → `MemorySliceResult`（`envelope` + `slices` + `as_of`）
  - [`MemorySlice`](../../src/st_agent/l2/memory/reader.py) 的 `node` / `as_of` / `confidence` / `base_confidence` / `source` / `edges`
- 输出（本任务交付的公共 API / 落盘位置）：
  - `GET /api/memory/browse?view=graph|list|timeline&topic=…` —— 只读；出一条 `UiDescription`（`view=graph` → `graph_view`、`list` → `table`、`timeline` → `timeline_view`）；面缺席 ⇒ `unavailable` + 点名，无切片 ⇒ `empty` + 原因
  - `GET /api/memory/profile` —— 只读；出画像卡 `report_card`（≤5 标签；无 `identity` / `evolution` 节点 ⇒ `empty`）
  - [`src/st_agent/ui/web/js/pages/memory.js`](../../src/st_agent/ui/web/js/pages/memory.js) —— 页内三视图切换器 + 画像卡常驻段（复用既有持仓 / 关注两表）

## 假设与前提

- **A1**：三视图「共享同一查询层」的判据是**同候选集、只换排序**——`SliceQuery.view` 的既有语义（[04 §3.1](../../docs/技术架构-v2/04-L2-记忆图谱.md)）。若错的影响：三视图会退化为三条独立查询；验证方式：集成套件断言同 `topic` / `task_type` 下三视图的 `memory_node_id` 集合相同
- **A2**：图谱视图的节点-边取自切片的 `node` + `edges`，边按 `(source, target, relation)` 去重。若错的影响：边会重复渲染；验证方式：真组合根上注入两条共享边的节点，断言去重后边数
- **A3**：画像卡取 `identity` / `evolution` 两类节点，≤5 条标签按 `updated_at` 降序截取。若错的影响：画像摘要与「当前画像」不符；验证方式：造 7 个 `identity` 节点，断言出 5 条 + 收窄提示
- **A4**：置信度在 `graph_view` 的 `confidence` 槽给**浮点原值**（渲染件出「置信度：0.82」），不私自分档——分档口径若要有，归契约层（`confidence.ConfidenceModel`）而非表现层。若错的影响：表现层自造第二套置信度语义；验证方式：describe 输出断言为浮点
