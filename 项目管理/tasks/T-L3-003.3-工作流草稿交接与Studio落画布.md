# T-L3-003.3 · 工作流草稿交接（Studio 落画布）

## 目标

兑现 [05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 末段：`target` 为工作流时，草稿在四字段之外**另携** `workflow_draft` 子对象（`name` / `description` / `nodes` / `edges` / `groups` / `schedule`，可含 ASCII `flow_name`）承载结构与暂定名，**身份字段 `flow_id` / `version` 不在草稿中**；草稿交 [03 §4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的 Skill Studio 落画布可视化微调。本叶只做**产出 + 交接**：草稿对象的载体复用 L1 已交付的模型，三态由 L1 的草稿会话承载。

## 验收标准（Given-When-Then）

- **GWT-1 · 工作流草稿的产出**：Given `target` 为工作流的一份已确认 `configure` 卡 + 工作流结构载荷（节点 / 连线 / 分组 / 调度），When 生成草稿，Then 四字段齐备并**另携** `workflow_draft` 子对象（`name` / `description` / `nodes` / `edges` / `groups` / `schedule`，可含 `flow_name`），且**不含**身份字段 `flow_id` / `version`——携带即拒（由载体模型的形状校验兜住，不静默丢弃）。
- **GWT-2 · 落画布交接**：Given 一份工作流草稿，When 交 Studio 接收面，Then 经 [`DraftIntake.receive`](../../src/st_agent/l1/studio/draft.py) 产出可编辑的画布会话；**形状**非法（无法构造 `WorkflowDAG`）→ 画布**不开**且错误显式上升；**语义**不合规（成环 / 契约不匹配 / 命名未中性化）→ **照开画布**，违规清单随会话带回（[03 §4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的两段口径，本叶不改判）。
- **GWT-3 · 三态委托 L1 草稿会话**：Given 一个已开画布的工作流草稿会话，When **接受** / **微调** / **拒绝**，Then 分别落 v1.0 并产生 `change_id`（`AcceptResult.change_id`）/ 返回同一个编辑面句柄 / 丢弃不落盘——**委托 L1 的 [`DraftIntake`](../../src/st_agent/l1/studio/draft.py)**，本叶**不另造**第二套工作流落盘或变更留痕。
- **GWT-4 · 非工作流分支不受牵连**：Given 一份**不含** `workflow_draft` 的草稿，When 处置，Then 仍走 [`.2`](T-L3-003.2-双通道登记面与处置三态.md) 的登记表口径，不进工作流通道；两分支的判定**只有一处**，不各判各的。

## 接口面

- **输入（消费的前置接口）**
  - `T-L3-003.1`（本批同出）`generate` 与确认卡的 `items` / `values` / `target`
  - `T-L1-003.4`（done）[03 §4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 接收面：[`WorkflowDraft`](../../src/st_agent/l1/studio/draft.py)（四字段 + `workflow_draft` 子对象，**形状已对齐** [05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md)）· [`DraftIntake.receive` / `.tune` / `.accept` / `.reject`](../../src/st_agent/l1/studio/draft.py) · `DraftSession` · `AcceptResult.change_id` · `RejectResult` · [`DraftShapeError`](../../src/st_agent/l1/studio/errors.py)
  - `T-L1-003.1`（done）[`WorkflowDAG`](../../src/st_agent/l1/workflow/models.py)（结构载体；`flow_id` / `version` 为身份字段，由「接受」派生）
  - `T-L1-001`（done）[`SkillRegistry`](../../src/st_agent/l1/skills/registry.py)——`DraftIntake` 构造所需（经组合根 / 调用方注入，本叶不自行装配）
- **输出（本任务交付的公共 API / 落盘位置）**
  - `src/st_agent/l3/config/workflow.py`：
    - `is_workflow_draft(confirmation, *, workflow=None) -> bool`——**唯一**的「是否工作流分支」判据（GWT-4）
    - `build_workflow_draft(confirmation, workflow) -> WorkflowDraft`——把确认卡面与结构载荷合成 [05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 的草稿载体（**复用** L1 模型，不另造平行模型）
    - `handoff(intake, draft) -> DraftSession`——交 Studio 接收面；三态经 `DraftSession` 的 `DraftIntake` 入口走（**不包装成第二套 API**）
  - 落盘：**本叶不落盘**——工作流的落盘点是「接受」（`config` 分区 `workflow/<flow_id>.json` + `execution_log` 分区 `workflow-change/<change_id>.json`），已由 [`WorkflowStore`](../../src/st_agent/l1/workflow/store.py) 承载
  - 同批改 [05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md)：与 [`.1`](T-L3-003.1-草稿契约与生成与configure去向接线.md) 合批补「工作流分支的判定来源与交接点」

## 假设与前提

- **A1 · 工作流草稿的载体复用 L1 的 `WorkflowDraft`，不另造平行模型**：[`T-L1-003.4`](done/M0/T-L1-003.4-编辑面与草稿落画布.md) 的 `WorkflowDraft` 已含 [05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 四字段 + `workflow_draft`，其假设 A3 明说「L3 开工时若需调整须回改本任务」。单一真相源避免两处形状漂移。若错（须 L3 自定义）：返工面＝本叶模型 + 回改 `T-L1-003.4` 的 `WorkflowDraft` 与 [03 §4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的接收契约。
- **A2 · 「是否工作流分支」由**结构载荷**判定，不从 `target` 字符串猜**:[05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 只说「`target` 为工作流时」，未说谁判。新工作流的草稿还没有 `flow_id`（身份字段不在草稿中），无从按 id 形态识别；故判据取「调用方随派发提供了工作流结构载荷」，且**只有一处**判据（GWT-4）。若错（须按 `target` 形态识别）：返工面＝`is_workflow_draft` 的判据与 §5 口径。
- **A3 · 工作流结构本身由上游理解产物承载，本叶只取用 + 校验 + 交接**:[05 §3.1](../../docs/技术架构-v2/05-L3-对话主入口.md) 的 `IntentDraft.understood` 是自由结构，工作流节点 / 连线的**生成**（从自然语言到 DAG）不属本叶——它是理解面的产物。本叶只把结构载荷落成草稿载体并交 Studio。若错（须本叶从文本产结构）：返工面＝本叶范围扩张到理解面，应另立任务。
- **A4 · 三态不在本叶重包**：`DraftIntake` 的 `accept` / `tune` / `reject` 已是公开 API 且口径齐备（[03 §4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 编辑面落地口径表），本叶只做转交，不复制其判定。若错（L3 侧需与参数分支统一的返回形状）：返工面＝`handoff` 的返回类型与 [`.2`](T-L3-003.2-双通道登记面与处置三态.md) 的三态形状对齐。
