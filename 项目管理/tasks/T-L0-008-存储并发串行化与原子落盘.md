# T-L0-008 · 存储写并发串行化与原子落盘

## 目标

闭掉 [L0 遗留问题册 E1](../遗留问题/L0-遗留问题.md)：`Store` 的 `put` / `delete` 是「读内存清单缓存 → 重建 → 写回」三步且**全程无锁**，同分区并发写者互相覆盖，条目静默丢失（`T-L1-002.3` GWT-4 全链路用例实证，该用例为此退让为「并发窗口内单一写者」）。本任务给分区读写路径加**分区级互斥**、把清单与数据文件落盘改为**原子替换**，使公共 API 签名不变而语义增强为「同一进程内、同一分区的并发调用安全」。

## 验收标准（Given-When-Then）

- GWT-1 同分区并发写不丢条目（核心回归）：Given 一个 `Store`，When 8 个线程并发向同一分区 `put` 各自不同的文件，Then `list_files` 与重开后的清单都含全部 8 个文件，且逐个 `get` 回原值。
- GWT-2 并发删改混合不丢不残留：Given 分区内已有 N 个文件，When 一半线程 `delete` 既有文件、另一半 `put` 新文件并发执行，Then 被删者全部消失、新写者全部在册，清单口径与磁盘事实一致（无「在册取不到」与「取得到不在册」）。
- GWT-3 同键并发读写零假损坏：Given 同一分区的同一文件名被一个线程反复覆写、另一线程反复 `get`，When 并发跑满轮次，Then 读方每次得到某个**完整**版本，**从不**抛 `StorageCorruptionError`（消除「清单-文件配对不一致」造成的假损坏）。
- GWT-4 落盘原子：Given 在临时文件写完、`os.replace` 之前注入失败，When 该次 `put` 中断，Then 目标要么保留完整旧内容、要么为完整新内容（无半截密文 / 半截清单），且重开 `Store` 后该分区 `partition_state == "ok"`。
- GWT-5 删除窗口不制造损坏：Given `delete` 在「清单已更新」之后被中断（数据文件尚未删），When 重开 `Store`，Then 七分区校验 `clean`——孤儿文件不进入清单口径，不产生损坏报告。

## 假设与前提

- A1 进程内多线程同写同一分区是**真实且需覆盖**的场景（依据：L1 `StdioTransport` 常驻 pump 线程 + `T-L1-002.3` GWT-4 实证）/ 若错（实际恒为单写者）：本修复为防御性冗余，不产生返工，可降级为 `wontfix` / 验证：GWT-1 用例先在**修复前实现**上跑一次，确认能复现丢条目。
- A2 用**分区级**互斥而非单把全局锁：把 `data_cache`（可含数十 MB 的 `market.db` opaque blob）的写与其余分区的读写解耦 / 若错（有调用方以跨分区原子性为前提）：需另立任务提供跨分区事务 / 验证：既有全量用例绿 + 无调用方做跨分区组合写。
- A3 **读路径也进同一把分区锁**（而非读无锁）：`get` 的「读清单 + 读文件」两步会在写者更新清单与更新文件之间读到不一致配对，产生假损坏 / 若错（读锁导致不可接受的阻塞）：退回读无锁 + 读侧识别后重试，GWT-3 随之改写 / 验证：GWT-3 用例（同键并发读写零 `StorageCorruptionError`）；锁内仅一次 AES 与一次文件 I/O，无长持有。
- A4 原子落盘用**同目录**临时文件 + `os.replace`（同卷原子），零新依赖；临时残留不被清单口径读取（`list_files` 与逐分区校验均由清单驱动）/ 若错（残留文件污染目录）：需在 `open` 时清理残留 / 验证：GWT-4 崩溃注入后重开 `clean`。
- A5 `Store` 并发口径属 L0 内部语义，不涉 [01 平台共享契约](../../docs/技术架构-v2/01-平台共享契约.md)（该契约不定义 `Store`）→ 不触发工作流 ⑦ 的跨层契约链，只在 02 §2 补说明 / 若错（实为跨层契约变更）：需按契约优先序回改 01 与各层 / 验证：`git diff --name-only` 中 `src/st_agent/l1/` 仅测试注释一处、其余层零改动。
