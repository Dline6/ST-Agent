# T-UI-002.4.2 · 壳侧口令框与 OS 凭据库记忆

## 目标
在桌面壳侧交付**口令的索取与记忆**：读到后端的 `passphrase_required` 事件后，优先取**操作系统凭据库**
里记着的口令（免重复输入），取不到才弹**原生口令框**；口令经**两个进程之间的管道**回传。口令错误
（凭据库里的已失效）时**改为弹框**并就地更新；用户**取消**即以中性说明退出，**不开空窗口**。托盘给出
**清除已记住的口令**的出口（可回滚）。

**不做**：不含任何解锁或存储逻辑（解锁只发生在后端进程内，[00 §1.1](../../docs/技术架构-v2/00-架构总览.md)）；
不读存储、不解析根目录布局；不新增壳专有通道（回传走既有的 stdin 管道）。

## 验收标准（Given-When-Then）
- **GWT-1**：Given 后端回 `passphrase_required`，When 壳处理，Then 调用**口令索取端口**（注入替身断言）
  取到口令、写入后端子进程的 stdin，随后读到 `ready` 并开窗（窗口地址仍是握手给的 `#t=<token>`）
- **GWT-2**：Given 凭据库中已记有该根的口令，When 壳启动，Then **不**调用口令框（替身断言零次），
  直接把凭据库的值回传，一次成功就绪
- **GWT-3**：Given 凭据库里的口令已失效（后端再次回 `passphrase_required`，`attempt` 递增），
  When 处理，Then **改为弹框**索取；成功后把新口令**写回**凭据库条目（替身断言 `set` 被调用一次）
- **GWT-4**：Given 用户在口令框上**取消**，When 处理，Then 后端子进程被**回收**（无孤儿）、应用以
  中性说明退出（提示端口被调用一次）、**不**打开空窗口、**不**降级为明文
- **GWT-5**：Given 托盘「清除已记住的凭据口令」，When 触发，Then 凭据库条目被删（替身断言 `delete`
  一次）；此后启动改走弹框路径（GWT-1 的行为）
- **GWT-6**：Given 宿主**没有**可用凭据库后端（缺 `keyring` 依赖或平台无 Secret Service），
  When 壳启动，Then **降级为每次索取**并**显式告知**一次（不静默、不发生错误崩溃）；
  且壳产物不 import 任何业务层（既有 `test_shell_is_native_only` 保持绿）

## 假设与前提
- **A1 · 原生口令框用 stdlib `tkinter`，在窗口循环之前调用**——同父 `A3`。前提：`simpledialog` 无新
  依赖，且调用点在 pywebview 窗口主循环**之前**（[`T-UI-002.2`](T-UI-002.2-桌面壳本体窗口托盘自启与通知接线.md)
  `A1` 的「窗口占主线程」不受影响，因为此刻窗口尚未起循环）。
  若错（冻结产物未打 Tk / 宿主无 Tk）：返工面＝框的实现（平台原生 ctypes / 独立小窗口）并须在
  `packaging/*.spec` 补 hiddenimports。验证方式：本叶「缺 Tk ⇒ 显式失败」用例 + Windows 走查。
- **A2 · 凭据库条目按「存储根」为账号键**——前提：同一台机器可有多根（开发 / 自用 / 测试），
  以**规范化后的根路径**为 account、以固定 service 名（如 `st-agent` 的后端口令）区分，避免跨根串用。
  若错（路径大小写 / 短名 / 符号链接导致同根异键）：返工面＝键规范化。验证方式：注入式用例断言
  键取自事件携带的 `root`；另在 Windows 上对同一根跑「写入 → 重启读回」一次。
- **A3 · 凭据库不可用时降级为每次索取**——同父 `A4`。前提：[02 §3](../../docs/技术架构-v2/02-L0-本地优先基座.md)
  「降级为每次索取并显式告知」。若错（静默失败或崩溃）：返工面＝降级分支。验证方式：GWT-6 的
  缺依赖用例（CI 天然不装 `keyring`）。
- **A4 · 「取消」与「启动失败」是两种收场**——前提：取消是**用户的决定**（中性说明 + 退出，退出码 0），
  启动失败是**错误**（中性原因 + 退出码非 0）；两者都不留孤儿后端。若错（语义混同导致脚本难判）：
  返工面＝退出码与提示面。验证方式：GWT-4 与既有壳失败用例（`test_shell_*`）各自断言退出码与
  提示端口调用。
- **A5 · 三平台中本机只实测 Windows**——同 [`T-UI-002.2`](T-UI-002.2-桌面壳本体窗口托盘自启与通知接线.md) `A5`；
  macOS / Linux 的**原生框与凭据库后端**均未实测（在遗留里显式登记，不写成「已支持」）。
  验证方式：Windows 走查（真框弹出一次 + 真凭据库往返一次，或如实登记未走查）。
