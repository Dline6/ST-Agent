# T-L6-003.2 · 变更流与变更历史回滚

## 目标
交付 [08 §5](../../docs/技术架构-v2/08-L6-反思演进.md) 的**变更流**（所有演进动作的**唯一通道**）与 [08 §6](../../docs/技术架构-v2/08-L6-反思演进.md) 前半的**回滚**：

```
Change Proposal（含理由、影响范围、trace 依据）
  → 审批门（按授权档位决定：用户批准 / 自动放行）
  → 生效（产生 change_id，记入变更历史）
  → 告知（发布 ChangeApplied）
  → 可回滚（任一 change_id，一键恢复前一版本）
```

把前两批**只到候选为止**的提案（[T-L6-001.2](T-L6-001.2-每周反思报告本体.md) 的 `ProposalCandidate` · [T-L6-002.1](T-L6-002.1-训练对话协议.md) 的 `SuggestionDraft` · [T-L6-002.2](T-L6-002.2-主动提案与周报候选生成.md) 的提案引擎）真正接进生效路径，并把 [08 §7](../../docs/技术架构-v2/08-L6-反思演进.md) 的「不存在静默调参路径」以**机器断言**钉住。

**与上下游的边界**（2026-10-07 读码核实）：
- **全仓无任何 `rollback` 实现**（`grep` 零命中）；[01 §11](../../docs/技术架构-v2/01-平台共享契约.md) 登记的 `ChangeApplied` / `ChangeRolledBack` **无发布点**——本叶落发布端。
- 档位与风险分级判据由 [`.1`](T-L6-003.1-演进授权档位与风险分级清单.md) 交出；本叶**不自己判档位**，只调用其判据。
- 出厂重置（三次确认 · 演进状态清空）归 [`.3`](T-L6-003.3-出厂重置.md)——本叶交出它要调用的**回滚 / 立案 / 历史读面**。
- **Skill 草稿提案**（[08 §4](../../docs/技术架构-v2/08-L6-反思演进.md) 的 `SkillProposal`）不进变更流——其「接受」是 L1 Studio 的既有物化落盘点；本叶只承载**配置变更候选**（`config_id` + 现值 + 建议值）。

## 验收标准（Given-When-Then）
- **GWT-1**：Given 一条配置变更提案，When 过审批门，Then **按 [`.1`](T-L6-003.1-演进授权档位与风险分级清单.md) 的档位与风险类**给结论——`manual` ⇒ **不立案**（提案止步于建议面，不进待批准队列）；`collaborative` ⇒ **立案待批准**；`autonomous` 且风险类为「可自主」⇒ **自动放行**；`autonomous` 但风险类为「必须协作」⇒ 仍立案待批准；「永不可自主」类 ⇒ **恒不自动**。逐条的结论与原因**可查**
- **GWT-2**：Given 一条待批准提案，When 接受，Then 经 [01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 门面**落值生效** → 产生 `change_id` 并**记入变更历史**（含 `config_id` / 旧值 / 新值 / 时刻 / 理由 / trace 依据 / 授权档 / 提案来源），可读回、**重启安全**；Given 目标条目不在任何已接入族，Then **拒生效**并点名（不假装落值）
- **GWT-3**：Given 一次生效 / 一次回滚，When 完成，Then 在 [01 §11](../../docs/技术架构-v2/01-平台共享契约.md) 的总线上发布 `ChangeApplied` / `ChangeRolledBack`（**必带 `change_id`**）；Given **未接总线**，Then 发布端**如实标注未受理并点名归属**（不假装送达）；Given 订阅者抛错，Then 逐订阅者记因、不吞不阻断
- **GWT-4**：Given 反思报告第四段的一条建议，When 逐条处理，Then **一键接受 / 否决 / 延后**三种处置都有落痕——接受 ⇒ 生效（同 GWT-2）；否决 ⇒ **留痕但不生效**（条目值逐字节不变）；延后 ⇒ **排队而非丢弃**（可后续再处置，状态与次数可查）
- **GWT-5**：Given 变更历史时间线（跨族、按时刻排序），When 对任一 `change_id` 一键回滚，Then **回放该变更的 `old_value`**（经门面落值、产生**新** `change_id`）、原记录**保留**并标注已回滚；Given 回滚一条已被后续变更覆盖的早期变更，Then 同样以 `old_value` 为准（**不猜**），且历史里新旧两条都在
- **GWT-6**：Given 本层任一条目录值，When 检查路径，Then **只经 [01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 门面**、且 `change_id` 的产生只此一处——`grep` 断言 `src/st_agent/l6/**` 无第二条静默调参路径（[08 §7](../../docs/技术架构-v2/08-L6-反思演进.md) 红线）

## 假设与前提
- **A1 · 变更事件由本叶的变更流发布**（2026-10-07 ④ 对齐拍定）——前提：[01 §11](../../docs/技术架构-v2/01-平台共享契约.md) 登记「发布方＝配置注册表」，而 [01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 门面**今日无 events 端口**、全仓无发布点；[08 §5](../../docs/技术架构-v2/08-L6-反思演进.md) 明写变更流属 L6，给 L1 门面加 events 端口会把 L5 / L2 的一切配置落值也一并广播。故取本叶发布 + 同批写实 [01 §11](../../docs/技术架构-v2/01-平台共享契约.md) 的发布方一栏（**改码之前**）。若错（要求由 L1 门面发布）：返工面＝本叶发布端 + [01 §11](../../docs/技术架构-v2/01-平台共享契约.md) + 触 [T-L1-012](done/M2/T-L1-012-统一配置注册表门面.md) 的交付面。验证方式：生效 / 回滚后总线上可查得带 `change_id` 的对应事件；未接总线时发布端如实标注未受理。
- **A2 · 回滚以 `ChangeRecord.old_value` 为据、产生新 `change_id`**（2026-10-07 ④ 对齐拍定）——前提：读码核实条目的 `default` 槽存的是**当前取值**（[`weekly_store.py`](../../src/st_agent/l6/weekly_store.py) 的 `set`），门面无法泛化给出「出厂默认」；而 `ChangeRecord` 本就记着 `old_value`。回滚＝经门面落值回放 `old_value` ⇒ **本身也是一次变更**（新 `change_id`、新留痕），故不绕开 [01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 的「落值即留痕」。若错（要求回滚不出新 `change_id` / 直改落盘）：返工面＝本叶回滚面与其用例（且会与 [08 §7](../../docs/技术架构-v2/08-L6-反思演进.md) 红线冲突）。验证方式：回滚后条目值等于该变更的 `old_value`，且新增一条指向该条目的 `ChangeRecord`。
- **A3 · `manual` 档的机制差异是「不立案」**（2026-10-07 ④ 对齐拍定）——前提：[08 §5](../../docs/技术架构-v2/08-L6-反思演进.md) 三档语义中，`collaborative` 是「提案 → 用户批准 → 生效」，而 `manual` 是「副驾**只能建议**，任何配置永不自动变」——「只能建议」＝不推进变更流（不进待批准队列）；否则两档在机制上无差别、验收也分不出。若错（要求 manual 也立案）：返工面＝本叶 `gate` 的一处分支与相应用例（判据是 [`.1`](T-L6-003.1-演进授权档位与风险分级清单.md) 给的三档，改分支不动引擎）。验证方式：`manual` 档下 `submit` 不产待批准项、`collaborative` 档下产。
- **A4 · 跨族变更读面加在 L1 门面上**（2026-10-07 ④ 对齐拍定）——前提：[01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 已定「读取与落值的公共面只此一处」与「存储布局不构成契约」；L6 若自扫 `execution_log` 会把各族路径前缀上升为**事实契约**，与 [D-067](../决策日志.md) 相悖。故**只增**门面的 `changes()`。若错（要求不动 L1）：返工面＝本叶读面 + 相应范围套件（须补跑 `tests/l1`）。验证方式：`changes()` 在既有族上返回其变更记录、既有 `entry` / `apply` / `set` 用例**不改**即全绿。
- **A5 · 延后是排队而非丢弃**（2026-10-07 ④ 对齐拍定）——前提：[08 §4](../../docs/技术架构-v2/08-L6-反思演进.md) 的频率上限已确立「被上限压下的提案**排队而非丢弃**」为本项目口径（[T-L6-002.2](T-L6-002.2-主动提案与周报候选生成.md)），报告的建议处置同此；story-09 GWT-3 亦写「延后」。故 `defer` 落 `deferred` 态、可再处置，**不静默消失**。若错（要求延后即弃）：返工面＝本叶待批准面与其用例。验证方式：`defer` 后仍在待批准读面、且可再次 `accept` 的用例。
