# T-UI-016.2 · 推理区：分歧图两视图与视角详情

> [`T-UI-016`](T-UI-016-推理区触发进度分歧图与视角详情.md) 三叶之一（[D-112](../决策日志.md) ①）——把 [`divergence_map`](../../src/st_agent/ui/web/js/plugins/l3/divergence_map.js) 这件**已实现却无宿主**的渲染件接上 `/deliberation`（矩阵视图 + 证据网络图**两视图均实现**），并补**视角详情页**与[06 §5](../../docs/技术架构-v2/06-L4-多视角推理.md) 的**追问接口**。

## 目标

- **分歧图宿主**（[11-sitemap §2.1](../../docs/PRD-v2-Agent/11-sitemap.md)：复用 `divergence_map`）——一次编排结果出**矩阵视图（视角 × 结论，主视图）**与**证据网络图（证据节点 + 引用边，辅视图）**，一致 / 分歧 / 盲点三段 + Mini Debate 冲突段**并列**。
- **视角详情页**（`/deliberation?lens=<lens_id>`）——该视角的**定义**（名 / 描述 / `kind` / `skill_bundle` / 评判准则 / 信心度策略，复用 `report_card`）+ **本次观点卡**（立场 / 信心度 / 理由 / 触发的 Skill / 证据引用）+ **该视角完整推理链**（复用 `trace_timeline`，[11-sitemap §2.1](../../docs/PRD-v2-Agent/11-sitemap.md) 的「`report_card` + `trace_timeline`」）。
- **追问接口**（[06 §5](../../docs/技术架构-v2/06-L4-多视角推理.md)：「点击某视角 → 展开该视角完整 Trace」）——从矩阵行点入即展开该视角链，**不新开一轮对话**（[D-112](../决策日志.md) ② 已定：本次结果随响应内联，无会话态）。
- **取数面扩展**——`POST /api/deliberation/analyze` 响应增 `divergence` 与 `traces` 两键（[`.1`](T-UI-016.1-触发进度与视角阵容.md) 立端点、本叶加键）；新增 `GET /api/deliberation/lens?id=<lens_id>`（视角定义读面）。

**本批的边界**（不越界）：

- **不重造 `divergence_map` / `trace_timeline`**——两者是已实现型，本叶只做**宿主与取数**；渲染件的槽语义一字不改。
- **不合并分歧、不给统一建议**——[06 架构级红线](../../docs/技术架构-v2/06-L4-多视角推理.md) 与 [铁律 4](../工程宪法.md)：描述里没有、本叶也不造「汇总结论」字段。
- **对照是算法性比对**（[06 §3](../../docs/技术架构-v2/06-L4-多视角推理.md)）——本叶**不引入**任何额外 LLM 裁判。
- **理由 / 提示等生成文案仍走生成槽**（[D-064](../决策日志.md)）——矩阵立场词表由服务端下发（`stance_labels`），前端**不自带词表**。
- **推理链展开面板的跨页复用接线归 [`.3`](T-UI-016.3-推理链面板与决策记录.md)**——本叶只把 `/deliberation` 侧的链路接通。

## 验收标准（Given-When-Then）

- GWT-1：Given 一次编排结果，When 呈现分歧图，Then **矩阵视图与证据网络图两视图均在**（[06 §5](../../docs/技术架构-v2/06-L4-多视角推理.md) 明列「两视图均实现」），一致 / 分歧 / 盲点三段与 Mini Debate 冲突段**并列**，描述里**无**汇总结论 / 建议字段（[铁律 4](../工程宪法.md)）
- GWT-2：Given `insufficient-data` 视角，When 呈现矩阵，Then 该视角**照常成行**（[06 §2.3](../../docs/技术架构-v2/06-L4-多视角推理.md) 的失败隔离不是「从图里消失」）、立场与原因如实，不被抹掉也不被算作共识
- GWT-3：Given 无参与视角 / 视图缺失，When 取分歧图，Then 分别回 `empty` + 原因 / `unavailable` + 原因，**不返回残缺卡**（视图为 `None` 与「空图」是两回事）
- GWT-4：Given 点击矩阵某行（视角），When 展开，Then 出该视角**完整推理链**（调用序列 / 记忆片段 / 耗时，复用 `trace_timeline`）；链不在本次结果里 ⇒ `empty` + 原因，**不臆造**一条链
- GWT-5：Given 视角详情页，When 打开，Then 出该视角**定义**（服务端读面）+ 本次观点卡 + 该视角链；未参与本次编排 ⇒ 定义照出、观点与链段显式标注「本次未参与」（**不假装有观点**）
- GWT-6：Given 文案，When 核对，Then 立场词表与视角名均由服务端下发（视角名取阵容，寻址失败退回 `lens_id`，**不臆造名字**），**无拟人化**（[契约 9](../../docs/PRD-v2-Agent/10-platform-capabilities.md)）
- GWT-7：Given 真组合根 + 真回环服务，When 在 Edge 走查「分歧图 → 视角详情 → 追问」，Then 全程可用、控制台无新增报错

## 接口面

- 输入（消费的前置接口）：
  - [`.1`](T-UI-016.1-触发进度与视角阵容.md) 交付的 `POST /api/deliberation/analyze`（回 `{reply, progress}`）、`DeliberationFacade.analyze`（持 `AnalyzeService`）、`/deliberation` 页骨架与 `?view=` 分派、`GET /api/deliberation/lenses`
  - L4 视图投影：`AnalyzeService.analyze(...)` → `AnalyzeOutcome`（`view` ＝ `DivergenceView`、`map` ＝ `DisagreementMap`、`traces` ＝ 各视角 `Trace`、`trace_for(trace_id)`）
  - L3 描述件：`describe_divergence_map(view, *, now=...)`（[`describe.py`](../../src/st_agent/l3/render/describe.py)）→ `divergence_map` 描述（槽 `topic` / `map_id` / `matrix` / `agreements` / `disagreements` / `blind_spots` / `network` / `conflicts` / `conflict_texts` / `notes` / `unanimous` / `uniform_stance` / `unanimity_notice` / `stance_labels`）；`describe_trace(trace, *, now=...)` → `trace_timeline`
  - L4 阵容面：`LensRoster.get(lens_id)` / `list_all()`（视角定义读面）
  - UI 槽词汇（[`ui/registry.py`](../../src/st_agent/ui/registry.py)）：`divergence_map`(`matrix` / `network`) · `trace_timeline`(`steps`) · `report_card`(`sections`)
- 输出（本任务交付的公共 API / 落盘位置）：
  - `POST /api/deliberation/analyze` 响应**增两键**——`divergence`（`divergence_map` 描述或 `None`）与 `lenses`（`[{lens_id, trace_id, opinion, trace}]`：逐视角的**观点卡 `report_card`** 与**完整链 `trace_timeline`** 描述，按锚点与矩阵行对位；链取不到时该项为 `None`）
  - `GET /api/deliberation/lens?id=<lens_id>` → 视角定义 `report_card`；缺 `id` ⇒ `validation_failed`；不存在 ⇒ `unavailable` + 点名；未过校验的非法 id ⇒ `validation_failed`（三种缺口**互不冒充**）
  - [`web/js/pages/deliberation.js`](../../src/st_agent/ui/web/js/pages/deliberation.js) 增：分歧图段 + `?lens=` 页模式分派 + 矩阵行 / 视角入口的**呈现内展开**
  - [`web/css/app.css`](../../src/st_agent/ui/web/css/app.css) 增分歧图 / 视角详情的中性样式
  - 测试：[`tests/ui/test_ui_deliberation.py`](../../tests/ui/test_ui_deliberation.py) 与 [`tests/integration/test_ui_deliberation_wiring.py`](../../tests/integration/test_ui_deliberation_wiring.py) 各补本叶用例（真组合根上：真 `DivergenceView` 出 `matrix` / `network` / `stance_labels`，真链按 `trace_id` 展开）

## 假设与前提

- **A1**：`DivergenceView` 的**矩阵行**已含追问所需的一切（`lens_id` / `name` / `stance` / `confidence` / `trace_id`），故「点击某视角 → 展开链」可在**同一响应**内完成，无需按 `lens_id` 回查 L4。**若错的影响**：若矩阵行的 `trace_id` 与 `AnalyzeOutcome.traces` 对不上（如链缺失），追问只能出 `empty` + 原因——GWT-4 的「不臆造」成立，但「展开可用」不成立。**验证方式**：集成套件在**真组合根**上断言「`matrix[*].trace_id` 的集合 ⊆ `traces[*].trace_id`」，并对其中一个锚点实际展开出非空 `steps`。
- **A2**：`insufficient-data` 视角**在矩阵里成行**由 `DivergenceView.rows` 的构造保证（`_row` 对每条 `opinion` 都产一行，不按 `stance` 过滤）。**若错的影响**：若某处按 `stance` 过滤掉数据不足者，GWT-2 会失败，且把「数据缺失」误报成「没有该视角」。**验证方式**：用例造一个 `insufficient-data` 视角，断言矩阵行数与 `opinions` 数相等且该行 `stance == 'insufficient-data'`。
- **A3**：视角**定义**读面（`GET /api/deliberation/lens`）与**本次观点**（随 `analyze` 响应内联）是两条取数路径——因[取数模型](../决策日志.md)（[D-112](../决策日志.md) ②）无会话态，直接 URL 打开 `?lens=<id>` 时**只有定义**，观点与链需在本页先触发生过编排。**若错的影响**：若产品要求「打开链接即见上次观点」，则必须引入会话态 / 落盘——[D-112](../决策日志.md) ② 已否决。**验证方式**：Edge 走查**冷开** `?lens=<id>` 断言出定义 + 显式标注「本次未参与本次编排」；先触发再点入则三段齐。
- **A4**：`stance_labels` 与视角名均属**生成文案槽**（[D-064](../决策日志.md)），故 `/deliberation` 页渲染分歧图时**不经**页内任何自有词表——前端只透传描述。**若错的影响**：若前端自拼立场 / 视角名，那批文案会绕过回环边界的中性校验门（[01 §6](../../docs/技术架构-v2/01-平台共享契约.md)）。**验证方式**：`test_frontend_pure.py` 的静态扫描 + 用例断言页内 JS 不含立场词表字面量；描述里 `stance_labels` 非空。
