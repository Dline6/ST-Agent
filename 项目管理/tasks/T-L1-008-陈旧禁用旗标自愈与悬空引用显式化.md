# T-L1-008 · 陈旧禁用旗标自愈 + 复合契约悬空引用显式化（L1 遗留 B2/B3 收口）

## 目标
收口 [L1 遗留册](../遗留问题/L1-遗留问题.md) 的 `B2` / `B3`（原归属「人」，本次修正为归属本任务）：

① **B2**——`SkillRegistry.unregister` 只删 skill-registry 项，`config/sandbox-disabled/<skill_id>.json` 残留；又因 `skill_id` 由 `(server, tool)` 确定性派生，硬回收后重挂同一 Server 会**复用同一 id**，新注册的 Skill 一落地就被旧旗标误判禁用（实测 `is_disabled=True`）。第二半缺陷：`SkillSandbox._disabled` 是构造时的内存副本，删盘也清不掉同进程内的误伤。处置＝**注册侧自愈**（新注册实体不继承旧禁用状态）+ `is_disabled` 有 `Store` 时以盘为准。

② **B3**——`derive_io_contract`（公开 API，`__all__` + `workflow/__init__.py` 导出）对「DAG 引用已回收 Skill」**裸抛 `SkillNotFoundError`**，与同族 `missing_dependencies`（提示式）口径不一致。处置＝**改抛 `CompositeDependencyError`**（携逐条 `DependencyGap`），与 `save_as_composite_skill` 的依赖门口径统一。

> **册内描述修正**：`B3` 原文「`composite.py` / `trial.py` 的 `registry.get` 未 catch，会抛错」经实测**不成立**——`trial.py` 无 `registry.get`，其 `_runner.run` 与 `_resolve` 均已 catch → 产出 `validation_failed` 信封（实测 `status=validation_failed`）；`save_as_composite_skill` 亦有依赖门 → `CompositeDependencyError`。真实缺陷面仅为 `derive_io_contract` 一处，收工时同步修正册内措辞。

## 验收标准（Given-When-Then）
- GWT-1 旗标自愈：Given `config/sandbox-disabled/<skill_id>.json` 存在且该 `skill_id` 未注册（陈旧旗标），When `SkillRegistry.register` 注册同 base / version，Then 旗标文件被删除、`SkillSandbox.is_disabled(skill_id)` 为 `False`（同进程与新建 sandbox 实例两种口径均成立）。
- GWT-2 不误伤既存禁用态：Given 某已注册 Skill 被用户 `disable`，When 注册**另一个** base 的 Skill，Then 原禁用态与旗标文件均不受影响。
- GWT-3 悬空引用显式化：Given DAG 引用一个已回收（未注册）的 Skill，When `derive_io_contract(dag, registry)`，Then 抛 `CompositeDependencyError`，其 `gaps` 逐条含 `node_id` / `skill_id` / `reason`，且**不**冒泡 `SkillNotFoundError`。
- GWT-4 回归：既有用例全绿；`verify_docs.py --strict` PASS；账本 `render` 后 SYNC。

## 假设与前提
- **A1 · `is_disabled` 改为「有 `Store` 时读盘」不破坏既有语义**：无 `Store` 时仍走内存；代价是每次调用一次 `config` 分区列表查询（`SkillRunner.run` 每节点一次，量级同既有沙箱核对的 `list_files`）。若错（判定为不可接受的 IO 放大）：返工面＝改回内存缓存 + 由组合根（`T-L1-006`）接线在回收时清内存态。验证：GWT-1 的「新建 sandbox 实例」口径 + 既有 `test_sandbox.py` 全绿。
- **A2 · `derive_io_contract` 改抛类型无外部调用方依赖**：src 内仅 `save_as_composite_skill` 内部调用（且该路径先过依赖门），另经 `workflow/__init__.py` 导出（`__all__`）；已 grep 确认无其他调用方。若错（有调用方依赖 `SkillNotFoundError`）：返工面＝该调用方 catch 类型同步。
- **A3 · 「陈旧」无需额外判定**：`register` 已在同 `skill_id` 已注册时抛 `SkillExistsError`，故能走到删旗标一步时该 id **必然未注册**，旗标只能是上一个已消失实体所留。不做「按时间戳比对」等额外判据。验证：GWT-1 与 GWT-2 两条互为对照。
