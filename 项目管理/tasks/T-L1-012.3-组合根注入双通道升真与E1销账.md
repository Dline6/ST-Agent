# T-L1-012.3 · 组合根注入、双通道升真与 E1 销账

## 目标

把 `.1` / `.2` 交付的门面装配进运行时：组合根构造 `ConfigRegistryFacade`、注册各族（含 L2 注入的 `memory-policy` 适配器）、把描述体取数口（L1 `SkillRegistry`）接上，并**注入** L3 的 [`ConfigDraftHandling`](../../src/st_agent/l3/config/handling.py) 与 [`dual_channel_view`](../../src/st_agent/l3/config/registry.py)。使 [05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 的双通道同源从「**声明面回落**」升为「**真登记项**」，并销 [L1 册 `E1`](../遗留问题/L1-遗留问题.md)。

## 验收标准（Given-When-Then）

- **GWT-1 · 双通道升真**：Given 组合根装配出的运行时，When 对某官方 Skill 调 `dual_channel_view(skill_id, descriptors=…, registry=…)`，Then 每个参数的 `origin == "registry"`（真登记项，非声明面回落），且两通道（对话描述 / 面板字段）取自**同一条** `ConfigEntry`。
- **GWT-2 · 接受真落值**：Given 一份草稿，When `ConfigDraftHandling.accept(draft)`，Then 返回 `status=ok` 且携带**非空** `ChangeRecord`（`change_id` 可回滚），值可在重新装配后读回；**不再**是「未注入 → `unavailable`」。
- **GWT-3 · 未装 L2 的运行时仍可装配**：Given 只有 L0 / L1 的运行时（无 L2 记忆面），When 装配，Then **不抛错**——`memory-policy` 族缺席由「不在列」显式体现，其余族照常；LLM 未配置等既有 fail-closed 路径**不回退**。
- **GWT-4 · 注入面是可选参数、缺省行为逐字节不变**：`ConfigDraftHandling(descriptors=…)`（不传 `registry`）与 `dual_channel_view(…)`（不传 `registry`）的行为与 `.1` 之前完全一致（fail-closed / 声明面回落）；既有 [`tests/l3/test_config_draft.py`](../../tests/l3/test_config_draft.py) 全绿。
- **GWT-5 · 遗留销账**：[L1 册 `E1`](../遗留问题/L1-遗留问题.md) 从未闭区移入「已闭（备查）」，`verify_docs.py --strict` 检查 8 为 0；[执行日志](../执行日志.md) 有含「验证」行的关闭留痕。

## 接口面

- **输入（消费的前置接口）**
  - `.1` / `.2`（本批同出）`ConfigRegistryFacade`（`entry_for` / `list` / `apply`）+ 各族适配器
  - `T-L1-006`（done）[`build_l1_runtime` / `open_runtime`](../../src/st_agent/l1/runtime.py)（L1 组合根；门面的 L1 侧装配点）
  - `T-L3-003.2`（done）[`ConfigDraftHandling(descriptors=, registry=)`](../../src/st_agent/l3/config/handling.py) / [`dual_channel_view(target, descriptors=, registry=)`](../../src/st_agent/l3/config/registry.py)——**消费端已就位**，本叶只接线
  - `T-INT-002`（done）[`app.py`](../../src/st_agent/app.py) 的 `M1Runtime` 组合根（`ConfigDraftHandling` 现以 `descriptors=runtime.skills` 装配、**无 registry**）
- **输出（本任务交付的公共 API / 落盘位置）**
  - `src/st_agent/l1/runtime.py`：`L1Runtime` 增 `config_registry`（门面单例）；`build_l1_runtime(...)` 构造并注册 L1 / L0 侧各族
  - `src/st_agent/app.py`：`M1Runtime` 装配处注册 L2 的 `memory-policy` 适配器，并把门面注入 `ConfigDraftHandling(descriptors=runtime.skills, registry=…)`
  - 同批改 [05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md)：把「未登记时回落声明面」的落地口径补一句——**门面已交付**（归属 L1，[01 §7](../../docs/技术架构-v2/01-平台共享契约.md)），未接门面只发生在**未装配**或**目标未知**时
  - 遗留销账：[L1 册 `E1`](../遗留问题/L1-遗留问题.md) → 册尾「已闭（备查）」+ [执行日志](../执行日志.md) 关闭留痕
  - **无新增分区、不改 L3 侧代码**（消费端口零变更）

## 可关闭的遗留

- **L1 册 `E1`**（统一配置注册表门面本体无归属任务）→ **本批关闭**。处置＝门面本体落 L1（`.1`）、存量族与孤儿接上（`.2`）、组合根注入使双通道由「声明面回落」升为「真登记项」（本叶）；届时**同批复核**各子系统自落前缀是否收编——本轮结论：**不改名**（01 §7 原文「存储布局不构成契约」），收编与否留后续按需复核。

## 假设与前提

- **A1 · 门面装配进 L1 组合根、L2 适配器由 app 层注册**：`L1Runtime` 承载 L1 / L0 侧族；`memory-policy` 族因 L2 在 L1 之上，其适配器由 app 组合根注入（`.2` A3 的落地）。
  - 若错的影响：若把 L2 适配器也放进 `l1/runtime.py`，L1 将 import L2（违 [铁律 7](../工程宪法.md)），`tests/test_layering.py` 红；返工面＝注册点位置。
  - 验证方式：GWT-3（无 L2 运行时可装配）＋ `tests/test_layering.py` 全绿。
- **A2 · L3 侧的**消费端口**零改动**：`ConfigDraftHandling` / `dual_channel_view` 的签名与行为**不动**，只从组合根侧把 `registry=` 传进去——E1 的原文即「该注入端口可接真实门面」，端口形态由 `T-L3-003.2` 定死。（`.1` 已把 `panel_field_for` 的实现移居 L1、L3 再导出——那是**同一份映射的唯一化**，不属端口变更。）
  - 若错的影响：若发现端口语义不足以承接真门面（如需要 `config_id` 直取而非 `(target, param)`），返工面＝L3 端口签名 + `.1` 的 `entry_for` 实现。
  - 验证方式：GWT-4（缺省行为逐字节不变）＋ 既有 L3 用例全绿。
- **A3 · 集成验证面用 `tests/integration` 而非改 M1 关卡**：M1 关卡 `T-INT-002` 已 `done`，本批不重开它；门面接线的端到端验证以 `tests/integration` 的新用例承载（跨层套件恒随跑）。
  - 若错的影响：若判定须由 M1 关卡重跑覆盖，返工面＝`T-INT-002` 的关卡重开与其账本口径。
  - 验证方式：`tests/integration`（跨层套件）在范围套件内恒跑，且新增用例覆盖 GWT-1 / GWT-2；`.3` 的测试分层按 `src/st_agent/l1/**` + `src/st_agent/app.py`（组合根）判范围。
