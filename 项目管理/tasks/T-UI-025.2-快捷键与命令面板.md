# T-UI-025.2 · 快捷键表与命令面板（P0）

> M7 叶之三的第二半（[T-UI-025](T-UI-025-交互底座快捷键对话框与反馈层.md) 拆出）；依赖 [T-UI-025.1](T-UI-025.1-浮层底座与反馈四层.md) 的浮层栈与焦点陷阱。
> 口径见 [14 册](../../docs/PRD-v2-Agent/14-desktop-form.md) §6.1（`command-palette`）、§8.1（快捷键全表）、§9（可达性）。

## 目标

- **快捷键表**（14 册 §8.1）：`Ctrl+K` 命令面板、`Ctrl+1…8` 切分区、`Ctrl+B` / `Ctrl+J` 折叠左右栏、`Ctrl+,` 设置、`/` 聚焦输入、`Ctrl+Enter` 提交、`Esc` 关最上层浮层、`F5` / `Ctrl+R` 刷新当前面、`F1` 快捷键表、`Alt+←/→` 面内进退、`Ctrl+F` 面内查找。**`Ctrl+W` / `Ctrl+Q` 不接**（壳行为归 `T-UI-027`）
- **命令面板**：模糊搜索「页面 / 动作 / 记忆节点 / Skill」，纯键盘完成「搜索 → 选中 → 执行」；`Esc` 关闭并把焦点还给原控件
- **F1 快捷键表**：真对话框呈现全表，并显式标注 `Ctrl+W` / `Ctrl+Q` 归壳闭合叶
- **`Ctrl+F` 面内查找**：查找条 + 上一步 / 下一步，调用引擎原生 `window.find`；引擎不支持时**显式说明**，不假装有结果
- **焦点模型**：全局焦点环可见（`T-UI-023` 已立）、浮层内焦点被困、关闭后焦点归还

## 验收标准（Given-When-Then）

- GWT-1：Given 应用，When 按 `Ctrl+K`，Then 命令面板打开且可纯键盘完成「搜索 → 选中 → 执行」；`Esc` 关闭并把焦点还给原控件
- GWT-2：Given 任一页面，When 逐条按 14 册 §8.1 的快捷键（`Ctrl+W` / `Ctrl+Q` 除外），Then 各自动作按表执行；分区序取自页面登记表，不另抄词表
- GWT-3：Given 键盘用户，When 只按键盘走完「进分区 → 打开详情 → 提交动作 → 关闭浮层」，Then 全程无鼠标依赖、焦点环处处可见
- GWT-4：Given 命令面板，When 输入关键词，Then 结果覆盖页面 / 动作 / 记忆节点 / Skill 四类；某类数据面不可用时**显式标注原因**，不摆假清单
- GWT-5：Given `Ctrl+F`，When 输入关键词并回车 / 点下一步，Then 在当前面内定位到命中；引擎无原生查找能力时显式告知

## 假设与前提

- A1：目标引擎提供 `window.find`（Chromium / WebKit 均有）；无则显式告知「当前引擎不支持面内查找」，不降级为静默失败。验证方式＝浏览器走查与代码分支自审。
- A2：命令面板的「记忆节点 / Skill」只用既有读面（`/api/memory/browse` 与 `/api/skills/catalog`），不新增搜索端点、不改契约。若错：数据面未接入时面板显示点名原因，不伪造候选。验证方式＝走查与既有路由套件。
- A3：`Ctrl+1…8` 的分区序取自 `pages.js` 的 `root: true` 登记序（经 `nav.js` 的 `PARTITIONS`），不另立数组。若错：快捷键与左栏顺序漂移，守卫能发现。验证方式＝走查与静态守卫。
- A4：`F5` / `Ctrl+R` 拦截为**重渲染当前面**（保留页面与令牌），不整页 reload；`Ctrl+W` / `Ctrl+Q` 不拦截（归 `T-UI-027`）。若错：刷新会丢会话内状态或抢走壳行为。验证方式＝走查与静态守卫。
