# T-AGT-002 · 端点能力启动探测（工具调用支持，判据取真回调用）

## 目标

兑现 [02 §4](../../docs/技术架构-v2/02-L0-本地优先基座.md) 的**能力诚实性**：端点的工具调用能力**由探测所得，不由缺省假定**。本任务交付启动期的探测步骤与其结果落点。

1. **探测**：启动时对每个已登记端点发一次**必然要求调用工具**的探针请求（工具 + 提示均取最小形态）。
2. **判据**：**响应里确实含工具调用**才判为支持——**不看「没报 400」**（部分 OpenAI 兼容端点对未知字段静默忽略，只看请求成功会得**假阳性**）。
3. **落点**：结果补进该端点的能力档位（`supports_function_calling`），供 [`T-AGT-004.2`](T-AGT-004.2-循环驱动、协议端口与上界.md) 的循环侧门控消费。
4. **与播种解耦**：探测住在**播种之后**的独立补丁步骤——**不得**塞进 `_seed_llm_records`。
5. **不阻塞启动**：失败降级为**能力未知**，循环侧 fail-closed。
6. **出网留痕**：经 §6 统一网关执行（用同一 transport 即自然获得审计）。

## 验收标准（Given-When-Then）

- **GWT-1 · 探针真回调用才判支持**：Given 一个支持工具调用的端点替身，When 探测，Then 能力档置 `true`。
- **GWT-2 · 静默忽略不得判为支持**：Given 一个**静默忽略 `tools`**、正常回文本的端点替身，When 探测，Then 判为**不支持**（**假阳性是本条的存在理由**）。
- **GWT-3 · 探测可重入且不被播种吞掉**：Given 端点记录**已存在**（播种整组跳过），When 连续两次启动，Then **第二次仍写入**探测结果——**不静默不写**。
- **GWT-4 · 失败不阻塞启动**：Given 端点不可达 / 无凭据 / 超时，When 启动，Then 启动**照常完成**，该端点能力记为**未知**（非 `true`），其余端点不受影响。
- **GWT-5 · 探测是出网调用**：Given 审计开启，When 探测，Then 落一条 `NetworkEvent`（发起方与目的可读），**载荷内容不入审计**（既有网关口径）。
- **GWT-6 · 不臆测**：Given 探测未跑到（缺网等），When 循环侧取能力，Then 得**未知**并走 fail-closed，**不回落为 `true`**。

## 接口面

- **输入**：
  - [`T-AGT-001`](T-AGT-001-LLM工具调用通道.md) 交付的 `tools` 入参 + `supports_function_calling` 能力项。
  - [`l1/runtime.py`](../../src/st_agent/l1/runtime.py) 的引导装载段：`LlmBootstrap` / `_bootstrap_llm_transport` / `_seed_llm_records`（**注意：`_seed_llm_records` 是「已存在即整组跳过」，探测不得住其内**）。
  - [`LlmEndpointRegistry`](../../src/st_agent/l0/llm/registry.py) 的端点记录读面（取全体已登记端点、写回能力档）。
  - 网关 [`EgressGateway`](../../src/st_agent/l0/net/gateway.py)（出网唯一出口 + 审计口径，[02 §6](../../docs/技术架构-v2/02-L0-本地优先基座.md)）。
- **输出**：
  - 探测步骤（住 [`l1/runtime.py`](../../src/st_agent/l1/runtime.py) 启动装配段，**播种之后**）。
  - 写回后的端点能力档位——供循环侧门控取用。
  - 测试：`tests/l1` 的探测用例（含**静默忽略端点**这一反例，GWT-2 的机器钉法）。

## 假设与前提

- **A1 · 探针形态取「必然触发调用」而非「发得出就算」**——前提：[02 §4](../../docs/技术架构-v2/02-L0-本地优先基座.md) 明写判据取「真回了工具调用」；静默忽略端点的存在使弱判据必然产生假阳性。
  **若错的影响**：循环在「能力未知被当成支持」下运行——用户拿到的是**静默降级为纯文本**的结果，而系统自认在跑自主查证（**比不门控更糟**，[D-090](../决策日志.md) ⑤）。
  **验证方式**：GWT-2 以**静默忽略端点替身**这一反例钉死；探针需**真的把 `tools` 发出去并解析回包**，故也是「prompt 必须真的送达」一类的**读码可辨**面（同 [工作流](../工作流.md) §测试分层 的 live 子集动机）。
- **A2 · 结果不落 01 §7 登记条目，直接住端点记录**——前提：能力档位是端点记录（`config` 分区）的既有字段形态，不是「用户可配置项」；用户**不该**手填「我的端点支不支持工具调用」。
  **若错的影响**：若须经门面落值，则返工面 = 探测的写面与一条新 UI 面板。
  **验证方式**：GWT-1/3 以端点记录读写证实；[01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 未新增条目（**不新增登记项**是本任务的范围声明）。
- **A3 · 启动探测的成本可接受**——前提：一次极小探针 / 端点 / 启动；用量经 [`T-L0-*` 的用量报告](../../src/st_agent/l0/llm/client.py) 可见（本地统计）。
  **若错的影响**：频繁重启会累积可观的端点调用；须改为「按（端点 + base_url + model）缓存探测结果、配置变更才重探」。
  **验证方式**：GWT-3 已要求可重入；若 ④ 对齐判定成本不可接受，缓存即本条的返工面。

## 备注

**陷阱一（[调研报告](../../docs/Agent自主能力调研报告.md) §11.2）在实现期的具体形态**：`_seed_llm_records` 的注释明写「端点已存在即整组跳过——既不覆盖既有配置，也不留下半套记录」。探测若住进去，**第一次启动写成功、此后永远写不进去，且不报错**（因为跳过路径本身是合法行为）。故本任务把探测立为**独立的补丁步骤**，并由 GWT-3 用「连续两次启动」钉住。
