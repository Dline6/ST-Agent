# T-UI-014.3 · 记忆区导入导出面板与 Onboarding

> [`T-UI-014`](T-UI-014-记忆区三视图画像卡与节点详情.md) 三叶之一（[D-111](../决策日志.md) ①）。补 [11-sitemap §2 记忆](../../docs/PRD-v2-Agent/11-sitemap.md) 余下两条屏——**导入导出面板**（导出前「本次包含哪些信息」清单 + 确认门）与 **Onboarding 对话**（建初始画像：风险偏好 / 投资年限 / 关注板块）。两者在后端**都已就位**：[`MemoryShare`](../../src/st_agent/l2/memory/sharing.py) 的 `plan()`（三步同一次算齐：过滤 `private`/`sensitive` → 出中性清单 → 待确认）与 `export(confirmed_by=…)`；[`OnboardingProtocol`](../../src/st_agent/l2/memory/onboarding.py) 的 `questions()` / `empty_state()` / `build_initial_nodes()`——缺的只是**表现层的门与宿主**。

## 目标

- **导入导出面板**：触发导出 ⇒ 先出「本次导出包含的公开信息」清单 + 被过滤节点数 + **确认门**；未经确认**不导出**；确认后产出片段载荷并回报
- **Onboarding 对话**：常驻于 `/memory` 空态——取问题清单（≤10 条，官方 Pack 可覆盖），逐问作答（**可跳过**），提交后落初始画像节点；已有画像即不显示
- **与 Chat 主界面共用引导**：[11-sitemap §2.2](../../docs/PRD-v2-Agent/11-sitemap.md) 把「Onboarding 对话」列在 Chat 主界面屏内，本叶在 `/memory` 空态给**同一份问题的落地入口**，不另造对话协议

**本批的边界**（不越界）：

- **导出 / 清空的本体归 L2**（[04 §8](../../docs/技术架构-v2/04-L2-记忆图谱.md)）——本叶只做交互面与确认门，不重造过滤 / 载荷逻辑
- **`.stmem` 文件容器归 [09](../决策日志.md)**——本叶产出的片段载荷与 ECO 的 `/eco/*` 分享物**不同源**（后者是 Skill / 工作流）
- **可写端点仍走白名单**：本叶加两条 `POST`（记忆导出确认 / Onboarding 提交），逐条登记 [`_POST_ROUTES`](../../src/st_agent/ui/server.py)；[01 §12](../../docs/技术架构-v2/01-平台共享契约.md)「动作不进描述」由此不被触碰
- **三视图与画像卡归 [`.1`](T-UI-014.1-记忆区三视图与画像卡.md)、节点详情与修正历史归 [`.2`](T-UI-014.2-节点详情与修正历史.md)**

## 验收标准（Given-When-Then）

- GWT-1：Given 导出动作，When 触发，Then 先出「本次包含哪些信息」清单 + 过滤节点数 + 确认门；**未经确认不导出**
- GWT-2：Given 确认导出，When 提交，Then 经 `MemoryShare.export` 落片段载荷，回报产出结果；Given 未确认，When 直接调导出，Then 显式拒（**不静默成功**）
- GWT-3：Given 空记忆，When 打开 `/memory`，Then 出 Onboarding 引导（**不静默留空**）；Given 已有画像节点，When 打开，Then **不显示** Onboarding
- GWT-4：Given Onboarding 问题清单，When 逐问作答（留空可跳），Then 经 `build_initial_nodes` 落初始画像节点并如实回报落了几条；Given 全跳过，Then 显式报「未建立画像」（**不假装成功**）
- GWT-5：Given 文案，When 核对，Then 按[契约 9 中性表达](../../docs/PRD-v2-Agent/10-platform-capabilities.md)撰写，**无拟人化、无道歉式措辞**
- GWT-6：Given 真组合根 + 真回环服务，When 在 Edge 走查导出确认门与 Onboarding，Then 全程可用、控制台无新增报错

## 接口面

- 输入（消费的前置接口）：
  - `graph` 鸭子端口经 [`GraphFacade`](../../src/st_agent/app.py) 取 `sharing`（`plan` / `export`）与 `onboarding`（`questions` / `empty_state` / `build_initial_nodes`）——**本叶为其加两字段**（[`T-UI-011.1`](T-UI-011.1-多面端口注入与各面门面装配.md) 的薄门面只持句柄）
  - [`FragmentPlan`](../../src/st_agent/l2/memory/sharing.py) 的 `included_summary` / `excluded_nodes`
  - [`OnboardingQuestion`](../../src/st_agent/l2/memory/onboarding.py) 的 `id` / `prompt` / `field` / `skippable` / `choices`
- 输出（本任务交付的公共 API / 落盘位置）：
  - `GET /api/memory/export/plan` —— 只读；出清单 `report_card`（含确认门文案，动作不落描述）
  - `POST /api/memory/export` —— 写；体 `{confirmed_by}`，经 `MemoryShare.export` 落片段载荷
  - `GET /api/memory/onboarding` —— 只读；出 Onboarding 状态（问题清单 + 是否已有画像）
  - `POST /api/memory/onboarding` —— 写；体 `{answers: {question_id: value}}`，经 `build_initial_nodes` 落初始画像
  - [`src/st_agent/ui/web/js/pages/memory.js`](../../src/st_agent/ui/web/js/pages/memory.js) —— 导出面板 + Onboarding 段

## 可关闭的遗留

无（逐册读未闭区同 [`.1`](T-UI-014.1-记忆区三视图与画像卡.md)）。

## 假设与前提

- **A1**：清单里的「包含项」是 `included_summary`（**中性措辞、不含节点原文**）——回显用户原话属渲染面（[04 §8](../../docs/技术架构-v2/04-L2-记忆图谱.md)）。故清单纯 `generated` 槽。若错的影响：清单会泄露被过滤内容；验证方式：断言清单不含任何 `private` 节点文本
- **A2**：`export` 的确认门是「先 `plan()` 出清单、再 `export(confirmed_by)`」两跳——**不合并成一次**（[§8](../../docs/技术架构-v2/04-L2-记忆图谱.md) 的强制三步）。若错的影响：确认门形同虚设；验证方式：断言未经 plan 直接 export 时前端不发起请求、后端对空 `confirmed_by` 显式拒
- **A3**：Onboarding「已有画像」的判据是 `empty_state()` **为空**——即**当前问题清单的每条问项皆已有非空值**（缺省 6 条：风险偏好 / 投资年限 / 资金规模 / 认知偏差 / 关注板块 / 关注题材）。**落地订正**：本叶原写「三个维度皆有值即视为已建」，实测 `empty_state()` **按当前清单逐条点名**（问题条数可随官方 Pack 变），故**代码口径更严且更贴 [04 §7](../../docs/技术架构-v2/04-L2-记忆图谱.md)**——「已有画像」＝清单无剩余空维度。若错的影响：重复引导；验证方式：答齐 6 条后断言 `GET /api/memory/onboarding` 报 `has_profile=true`
- **A4**：问题清单取材 `OnboardingProtocol.questions()`（官方 Pack 注入者优先）——前端**不硬编码**问题。若错的影响：造出与官方 Pack 分叉的第二真相源；验证方式：注入自定义问题集，断言端点出注入者
