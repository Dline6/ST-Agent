# T-L2-002.2 · 冲突检测 · 提案队列与裁决落盘

## 目标

兑现 [04 §4](../../docs/技术架构-v2/04-L2-记忆图谱.md) 的后三条：**冲突检测**（新信息与既有节点冲突 → 产出 `MemoryConflictDetected` 事件，由 L3 发起裁决对话）、**裁决结果落盘**（确认变更 → 新版本 + `evolves_from` 边；确认不变 → 丢弃提案并记录）、以及 §4 末句的红线 **「不存在任何静默覆盖」**。本叶是 [Story 3 验收段](../../docs/PRD-v2-Agent/story-03-memory-graph.md)「副驾发现新信息与旧记忆冲突…主动询问用户，**不擅自覆盖**」的落点。

## 验收标准（Given-When-Then）

- **GWT-1 · 冲突被检出并落成提案**：Given 一条按 [`.1`](T-L2-002.1-自主写入白名单与写入策略.md) 判定为 `propose` 的新信息，或有既有节点与它冲突，When 检测，Then 产出一条提案（携冲突类型、目标节点、待写内容）落 `execution_log` 分区 `memory-conflict/<conflict_id>.json`；同一冲突重复检测幂等（不产生第二条）。
- **GWT-2 · 事件可被 L3 消费**：Given 一条新提案，When 组装上行通知，Then 得到 `PlatformEvent(event="MemoryConflictDetected", …)`，携带关联 `trace_id`（[01 §11](../../docs/技术架构-v2/01-平台共享契约.md) 对 `MemoryConflictDetected` 的必带项）与指向提案的 `conflict_id`。
- **GWT-3 · 确认变更 → 新版本 + `evolves_from`**：Given 一条待裁决提案，When 用户确认变更，Then **新增**一个新节点（新 `memory_node_id`，`source=inferred` 且带 `provenance.trace_id`）并加一条 `evolves_from` 边（新 → 旧）；**旧节点内容一字不改**（演化链保留）。
- **GWT-4 · 确认不变 → 丢弃并记录**：Given 一条待裁决提案，When 用户确认不变，Then 既有节点不变、**不产生新节点与新边**，提案落为「已裁决（保持原状）」并记录裁决时刻。
- **GWT-5 · 无静默覆盖**：Given 任一路径，When 写入完成，Then 既有节点的 `memory_node_id` 与其内容快照不变；副驾**不得**经本叶入口改写既有节点（改既有内容只经 [`MemoryWriter.edit_node`](../../src/st_agent/l2/memory/writer.py) 且须 `confirmed_by="user"`）。
- **GWT-6 · 越界与缺失显式化**：Given 裁决一个不存在或已裁决的 `conflict_id`，或裁决时缺 `confirmed_by="user"`，When 调用，Then 显式失败（不静默当作已处理）。

## 假设与前提

- **A1 · 冲突检测是结构化的（不含 LLM 语义判定）**：[04 §4](../../docs/技术架构-v2/04-L2-记忆图谱.md) 举例「thesis 方向相反、偏好标签变更」，但 §1 的 `thesis` 只有自由文本 `view`（无 stance 字段），L2 亦无 LLM 出口（`LlmClient` 归 L1）。故判据取**结构可比对**者：① 同 `subject` 的新 thesis；② `identity` / `evolution` 等单值维度的取值分歧。**语义方向判定与询问对话归 L3**（§4 原文即「L3 发起裁决对话」）。若错（须在 L2 内做语义判定）：返工面 = `detect` 的实现与判据表，提案 / 事件 / 裁决三面不变。
- **A2 · `MemoryConflictDetected` 的 payload 结构由 L2（发布层）定义，不改 01**：[01 §11](../../docs/技术架构-v2/01-平台共享契约.md) 该行只登记「事件名 + 发布方 + 订阅方」，并明写 payload「结构由发布层定义」；`T-L1-001.5` 的 `BehaviorViolation` 即按此办。若错（判定跨层结构须先登记 01）：走 ⑦ Sync——先改 01 §11 补字段表、再改本叶代码。
- **A3 · 「写入新版本」＝新节点 + `evolves_from`，不是原地改既有节点**：§4 明写「写入新版本 + `evolves_from` 边（保留演化链）」，而 `evolves_from` 的两端都是 `memory_node_id`——两端须是同存的两个节点，故「新版本」是新节点。这也与 §3.2 红线（副驾不得改既有节点内容）同向：接受路径因此**只经 `add_node`**。若错（须原地改 + 修正历史）：返工面 = `resolve` 的接受分支改走 `edit_node`，`evolves_from` 语义需另议。
- **A4 · 提案与裁决记录落 `execution_log` 分区**：[02 §2.1](../../docs/技术架构-v2/02-L0-本地优先基座.md) 的 `memory` 分区定义为「记忆图谱**全部节点与边**」——提案与裁决不是节点 / 边，而是**决策留痕**（§4 明写否决要「记录」）；`execution_log` 收「执行留痕」，且 §7 的 `ChangeRecord` 已先例落此分区。若错（须落 `memory` 或新分区）：返工面 = 落盘前缀一处。
- **A5 · 冲突检测的判据表为初版、不注册为可配置项**：§4 只要求**白名单**可配（已归 `.1`），未要求判据表可配。若错（用户须能开关某类冲突检测）：返工面 = 判据表提为 `.1` 的配置条目形态。
- **A6 · 用户自陈不进本门（收口时补记）**：[§3.2](../../docs/技术架构-v2/04-L2-记忆图谱.md) 定「用户显式…直接写入」，且 [Story 3 验收段](../../docs/PRD-v2-Agent/story-03-memory-graph.md) 明写用户自陈 thesis 是「**自动写入**一条 thesis 节点」——若对用户刚说的话再问一遍「是想法变了吗」，与产品行为相抵。故 `detect` 对 `source=user_stated` 直接返回 `None`。**代价**：用户前后自陈矛盾不会被本门拦下（不构成「静默覆盖」——两个节点并存，无改写）。若错（须拦用户自陈矛盾）：返工面 = `detect` 的入口条件，提案 / 事件 / 裁决三面不变。
