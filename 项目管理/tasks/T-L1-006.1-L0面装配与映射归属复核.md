# T-L1-006.1 · L0 面装配与 provider→host 归属复核

## 目标

交付组合根的 L0 半边：给定一个已解锁的 `Store`，装配 `EndpointRegistry` / `CredentialVault` / `EgressGateway` / `LlmClient` 四件并交给 L1 能力面（`.2`）；同时完成 [Q-001](../阻塞与未决.md) / [D-005](../决策日志.md) 留待的 `provider → host` 映射归属复核并落地。

## 验收标准（Given-When-Then）

- GWT-1 装配即用且不覆盖既有配置：Given 已解锁 `Store`（含既有端点 / 凭据 / 映射记录），When 装配 L0 面，Then 四件可用，且既有配置**逐条原样可读**（不重置、不静默覆盖）。
- GWT-2 出网唯一出口、缺省 fail-closed：Given 未注入发包实现，When 经装配面发起出网（`EgressGateway.execute` 或 `LlmClient.invoke`），Then 得 `unavailable`（不臆测、不直连）；Given 注入发包实现，Then 审计事件必记 `execution_log`（唯一出口与唯一审计点，[02 §6](../../docs/技术架构-v2/02-L0-本地优先基座.md)）。
- GWT-3 映射归属裁定落地：Given `D-005` 的过渡归属（`config/llm-provider-host/<provider>.json`，L1 沙箱持有），When 本任务复核，Then 结论落地（**维持 L1** —— 映射由组合根**注入**沙箱，沙箱的 `net_access` 核对行为不变）并留 `D-NNN`。
- GWT-4 会话级单次解锁：Given 同一会话内多次取用运行时，When 经装配面的会话入口进入，Then 口令派生（PBKDF2 600k）**每会话每存储只跑一次**，重复取用复用同一已解锁 `Store`；不引入进程内密钥缓存（口令 / 校验值不长驻内存）。

  - `T-L0-004`（done）· [`net/gateway.py`](../../src/st_agent/l0/net/gateway.py) 的 `EgressGateway(store, sender=None, *, online=True)`
  - `T-L0-001`（done）· [`storage/store.py`](../../src/st_agent/l0/storage/store.py) 的 `Store(root, keys)` 与 `Store.open(root, passphrase)`

  - 择型：[D-NNN](../决策日志.md)（`provider → host` 归属复核结论，**不改** [02 §4](../../docs/技术架构-v2/02-L0-本地优先基座.md) / [01 §7](../../docs/技术架构-v2/01-平台共享契约.md)）

## 可关闭的遗留

- L0 册 `B1`（`EndpointRegistry` / `CredentialVault` / `LlmClient` / `OutputRegistry` 无运行时装配）→ **本批关闭**；本叶兑现其中三件（`OutputRegistry` 属 L1 面、由 `.2` 兑现），销账在批末随父 `T-L1-006` 派生 `done` 执行。
- L0 册 `B2`（登录态会话密钥缓存未落地）→ **本批关闭**（以「会话级单次解锁」兑现，见 GWT-4），销账同上。

## 假设与前提

- A1 组合根落 `src/st_agent/l1/runtime.py`（不新建 app / 装配层）—— 铁律 7 允许 `l1` 向下依赖 `l0`，[`tests/test_layering.py`](../../tests/test_layering.py) 的层表无需改动 / 若错：须新建装配层并同改层表与 [00-架构总览 §3](../../docs/技术架构-v2/00-架构总览.md) / 验证：`pytest tests/test_layering.py` 全绿 + 装配模块 import 面复核。
- A2 「已解锁的 `Store`」＝调用方造好 `Store(root, keys)` 后传入；口令派生 / 解密 / 解锁本身**不属**组合根（属 L0 存储子系统，合并 GWT-4 的会话入口亦然——入口只负责**复用**，不负责派生）/ 若错：解锁职责漂到 L1、首启流程缺一环 / 验证：装配签名只收 `Store` 句柄；用例自建临时 `Store`。
- A3 幂等＝重复装配不重复注册、不重置既有配置；**不**引入「装配版本」概念 / 若错：二次装配抛 `SkillExistsError` 或覆盖用户配置 / 验证：GWT-1 的「既有配置逐条原样可读」。
- A4 会话级单次解锁的判据取「同一 `Store` 句柄的复用」，不引入跨进程 / 跨会话的密钥缓存；口令与派生密钥均不落盘（铁律 1）/ 若错：口令或快速校验值在进程内存长驻（须重新做安全权衡）/ 验证：GWT-4 的「每会话每存储只派生一次」。
- A5 发包实现 / `Transport` 一律**注入**，组合根不内置真实 sender（真实抓取由 L0 各子系统自持，见 [`T-L0-005`](T-L0-005-数据源缓存BaoStock首个源落地.md)）/ 若错：装配面偷偷具备出网能力、离线路径不可测 / 验证：GWT-2 的「缺省即 `unavailable`」两侧。
