# T-L0-010.3 · 龙虎榜域采集与管理

## 目标

交付**龙虎榜域**的完整链路，服务 [L4 情绪视角](../../docs/PRD-v2-Agent/story-04-multi-lens.md) 的「龙虎榜资金」维度。

- **表组按实体分两表**（**关键**：两源的差异是**实体粒度不同**，不是主备——[D-030](../../项目管理/决策日志.md) / `Q-003` 决议）：
  - `dragon_tiger`——**上榜记录**（`code` / `trade_date` / 上榜原因 / 买卖净额 / 换手率 / `source_id`）
  - `dragon_tiger_seat`——**席位明细**（`code` / `trade_date` / 席位 / 买入额 / 卖出额 / 排名 / `source_id`）
- **主备**：上榜记录以东财为主、交易所官方兜底；**席位明细以交易所官方为主**（一手营业部明细、排名可推导），东财 TOP5 与机构动向为补充源
- **新鲜度**：盘后 T+0 晚（当日盘后可得），逐日增量
- **范围**：全市场端点会带回 `security` 未收录代码（如北交所）→ 经 `.1` 的**预过滤 + `filtered_unmapped` 计数**处置（[D-032](../../项目管理/决策日志.md)），**不得**让批次失败

## 验收标准（Given-When-Then，从 Story 抄）

- 待 ④ 对齐时逐条定稿。草拟方向（④ 复核）：
  - GWT-1 两实体可分：Given 一次龙虎榜同步，When 查上榜记录与席位明细，Then 两表各自可查、粒度不同的事实**不混在一张表里**
  - GWT-2 席位的两个源可辨：Given 明细来自官方、排名来自东财，When 查询，Then 每条行带 `source_id`，**不冒充**单一来源
  - GWT-3 预过滤不炸批：Given 全市场批次含未收录代码，When 同步，Then 批次成功、计数如实登记
  - GWT-4 逐日增量：Given 已同步 T-1，When 同步 T，Then 仅追加 T 的记录，历史不动
