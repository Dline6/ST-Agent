# T-SC-001.1 · 标识体系 + ResultEnvelope 统一结果与错误模型

## 目标
实现 [01-平台共享契约](../../docs/技术架构-v2/01-平台共享契约.md) §1 的 12 类跨层标识（构造、唯一性、不可变）与 §5 的 ResultEnvelope 统一信封（六种 status 语义与失败分支），作为全平台标识与结果传递的单一真相源。这是同族子任务的地基，其余子任务依赖其类型。

## 验收标准（Given-When-Then）
- GWT-1：Given 任一上层模块，When 引用 `stock_id` / `trace_id` / `skill_id` 等标识，Then 均来自本契约定义、全局唯一、生成后不可变（§1）。
- GWT-2：Given 一次 Skill 执行产出，When 包装为 `ResultEnvelope`，Then 六种 `status`（ok / empty / unavailable / dependency_failed / validation_failed / failed）语义齐全——empty 必带 reason、非 ok 必填 reason、ok/empty 附 evidence_refs、含 as_of 时间锚位——失败不得裸返回（§5）。

## 接口面
> 追补于 2026-09-26：本任务完成早于接口面机制落地，据已合入代码与执行日志回溯填写（非 ④ 对齐时填写）。
- 输入（消费的前置接口）：无前置任务（M0 起点）；事实来源 01 §1·§5 契约文档；外部依赖 pydantic v2（frozen 模型 + 构造期校验）
- 输出（本任务交付的公共 API / 落盘位置）：
  - `st_agent.contracts.identifiers`：`PlatformId.generate()` / `.of(value)`、12 类 ID 类型与 `ID_REGISTRY` / `ID_KINDS` / `ID_ALIASES`
  - `st_agent.contracts.result_envelope`：`ResultEnvelope` 六状态构造器 `ok` / `empty` / `unavailable` / `dependency_failed` / `validation_failed` / `failed`、`EvidenceRef`、`new_evidence_id()`
  - `st_agent.contracts.errors`：`ContractViolation`
  - 出口口径：`from st_agent.contracts import ...`（L0–L6 唯一契约真相源，各层不得私造跨层格式）
