# T-L1-004.3 · 主动服务 Bundle 执行器

## 目标

为 03 §2.2 主动服务 Bundle 的 6 个 Skill 交付**可执行实现**：`stock-watch` / `data-aggregate` / `risk-alert` / `opportunity-mine` / `portfolio-stress-test` / `strategy-design`——各 bundle 的联动按已声明的 `dependencies` 生效（上游失败即 `dependency_failed`，不静默续跑），并兑现 §2.2 点名的 **`strategy-design` 特殊契约：未来函数检测**。本任务同时收口父任务 `T-L1-004`，故一并销 [L0 册 `A3`](../遗留问题/L0-遗留问题.md)。

## 验收标准（Given-When-Then）

- GWT-1 六个执行器逐个产出：Given 已装载的运行时 + 离线数据面 + 满足依赖的上游输出，When 逐个 `runner.run(skill_id, {…参数})`，Then 五条信封为 `ok` 且载荷过各自 `output_schema`；`data-aggregate` 在**无上游**时为 `empty`（无数据可聚合）、上游就绪（执行器级注入）时为 `ok`。
- GWT-2 依赖联动按声明生效：Given `risk-alert` / `opportunity-mine` / `strategy-design` 已声明上游依赖，When 上游执行失败（或返回非 `ok` / `empty`），Then 下游信封为 `dependency_failed` 且原因点名失败的上游（用错误数据继续即用例失败）；上游成功时下游 `ctx.upstream` 能取到对应载荷。
- GWT-3 未来函数检测：Given 用户设计的信号依赖了在其决策时点尚不可得的数据（如把财务字段对齐到报告期 `stat_date` 而非披露日 `pub_date`），When 校验，Then **报错并指出问题字段与原因**（`passed=False` + 逐条问题）；依赖合法的信号 → `passed=True`。
- GWT-4 无输入不编造：Given `data-aggregate` 无上游、`risk-alert` 与 `opportunity-mine` 上游为空/无产出，When 执行，Then 三者均为 `empty` 且带原因（不产出空壳 `ok`）；Given `portfolio-stress-test` 无用户组合，When 执行，Then 载荷**显式标注组合来源为本地全市场等权组合**（键 `portfolio_source`），不冒充用户持仓。
- GWT-5 参数生效：Given 同一 Skill 用不同参数（如 `lookahead_days` / `max_results` / `shock` / `format`），When 执行，Then 输出随参数变化且仍在 `output_schema` 内（参数口径经 `validate_call_params` 合并默认值）。

  - `T-L1-001.2` [`runner/runner.py`](../../src/st_agent/l1/runner/runner.py)：`SkillContext.upstream`（`{skill_id: ResultEnvelope}`，runner 递归执行 `descriptor.dependencies` 后注入）、`SkillContext.llm`（`strategy-design` 若需 LLM 生成须显式处理 None）

- 输出（本任务交付的公共 API / 落盘位置）：
  - `st_agent.l1.skills.official.ambient`：6 个执行器工厂（各为 `market_query -> SkillExecutor`），经 `OFFICIAL_EXECUTORS` 按 `base` 登记
  - 载荷形态（与 03 §2.2 职责一致；附加字段允许）：
    - `stock-watch` → `{"triggered": [{"code", "condition", "detail"}]}`
    - `data-aggregate` → `{"cards": [{"kind", "title", "payload"}]}`（`format` = `table` / `trend` / `brief` 决定卡片形态）
    - `risk-alert` → `{"alerts": [{"code", "dimension", "detail"}]}`
    - `opportunity-mine` → `{"candidates": [{"code", "style", "reasons"}]}`
    - `portfolio-stress-test` → `{"scenarios": [{"name", "shock", "impact"}]}`
    - `strategy-design` → `{"report": {"steps": [...], "signal_check": {"passed", "issues", "reason"}}}`
  - `st_agent.l1.skills.official.signal_check`（或 `ambient` 内等价公开面）：**未来函数检测的公开纯函数** + 结果模型（`passed` / `issues` / `reason`），独立于执行器可调用——`strategy-design` 是它的首个消费方，但不独占
  - 落盘：沿用既有布局，**不新增分区**
  - 消费方：`T-L1-005`（定时调度触发主动服务 Bundle）、`T-L5-002`（渠道投递消费预警载荷）、`T-L1-003.5` 官方模板（「策略回测流水线」的节点）、`T-INT-001`

## 假设与前提

- A1 **信号定义的输入形态由本任务定义**（03 §2.2 只写「用户设计的信号若依赖未来数据，校验即报错」，未给格式）：取「字段清单 + 逐字段对齐口径」的纯数据形态（如 `{"fields": [...], "align": {字段: "stat_date" | "pub_date" | "trade_date"}}`），检测件比对**该字段最早可得时点**与**信号决策时点**；执行期从 `ctx.upstream` 取信号定义，未提供时 `signal_check` 显式标注「未提供信号定义」（`passed=None`，不假装通过）/ 若错（须支持表达式级解析或 L3 传入的对话式信号）：返工面＝检测件 + `strategy-design` 执行器 + 可能的 [03 §2.2](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 补充说明 / 验证：GWT-3 双向（合法信号 `passed=True` / 未来函数 `passed=False` + 逐条问题）。
- A2 6 个 Skill 的运行期输入口径沿用父任务 A1（参数 + `ctx.upstream`），**不新增通道**；输入不足时走 GWT-4 的显式分支 / 若错：与父任务 A1 同返工面 / 验证：GWT-4 两条用例。
- A3 `portfolio-stress-test` 的组合来源取「**本地缓存最新交易日的在市标的等权组合**」，载荷以 `portfolio_source` 显式标注来源；风险放大系数 `beta = 1 + 组合内 ST 占比`（可解释、随数据变化）。**④ 后修正**：原设想的「上游组合载荷」通道在既有两条通道下不成立——该 Skill 的描述体 `dependencies` 为空，`ctx.upstream` 恒为空，故「未提供即 `validation_failed`」会让该 Skill 恒失败；改为「有默认口径 + 来源显式标注」，「用户组合 / 风格板块偏好 / 信号定义」等对象类输入的接入点按册规登记 [L1 册](../遗留问题/L1-遗留问题.md) 未闭区 / 若错（须支持用户配置组合）：返工面＝该执行器 + L2 记忆图谱的持仓接入 / 验证：GWT-4 的 `portfolio_source` 标注用例 + GWT-5 的 `shock` 参数生效用例。
- A4 `strategy-design` 与上游 `data-aggregate` 的**依赖**按种子声明（`dependencies=("sk_data_aggregate_v1.0",)`）由 runner 自动递归执行——本任务不绕开 runner 自行编排 / 若错（须自定义编排）：返工面＝执行器 + 可能触及 [03 §1.2](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) / 验证：GWT-2 断言 `ctx.upstream` 命中且失败时下游 `dependency_failed`。
- A5 `A3` 遗留的销账在**本任务**（最后一个叶子）而非父任务文件——父任务状态由 render 派生，销账以「父 `done`」为解封条件的判定依据 / 若错（须在父任务层销）：册内条目会被检查 8 提前判失败（归属 `T-L1-004` 已 `done` 却未销）/ 验证：`verify_docs.py --strict` 检查 8 为 0。
