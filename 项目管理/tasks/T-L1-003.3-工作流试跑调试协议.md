# T-L1-003.3 · 工作流试跑（调试协议）

## 目标

落地 03 §4 的**调试协议**：任何工作流可试跑——按拓扑序逐节点执行并留快照，支持**单步**、**输入注入**、**暂停 / 继续 / 中止**，每次试跑留存历史可对比（story-06「调试与测试」）。

## 验收标准（Given-When-Then）

- GWT-1 拓扑执行与失败短路：Given 一条校验通过的工作流，When 试跑，Then 节点按拓扑序执行，每节点产出「输入快照 + 输出信封 + 耗时」；某节点非 `ok`/`empty` 时其下游**不执行**并标 `dependency_failed`（禁止用错误数据继续）。
- GWT-2 单步：Given 一次试跑会话，When 逐步（`step`），Then 每步只推进一步，可在步间检视该节点的输入快照与输出快照。
- GWT-3 输入注入：Given 试跑开始前/进行中为某节点注入输入，When 该节点执行，Then 使用注入值（覆盖其参数绑定中的字面量），且快照标注该值来源为注入。
- GWT-4 暂停 / 继续 / 中止：Given 试跑进行中，When 暂停，Then 不推进；When 继续，Then 接着跑；When 中止，Then 后续节点一律不执行且试跑记录标 `aborted`。
- GWT-5 试跑历史对比：Given 同一工作流的两次试跑记录，When 取对照，Then 可按 `node_id` 对齐、逐节点列出输出差异（新增/消失/不同的节点）。

## 接口面

- 输入（消费的前置接口）：
  - `T-L1-003.1` 的 `st_agent.l1.workflow` 包：`WorkflowDAG`（`node()` 取节点 / 拓扑序 / 节点参数绑定与上游输出引用）、`validate_dag`（门禁判定）、`topological_order`、`dependency_graph`（失败短路的后代计算）
  - T-L1-001.2 `SkillRunner.run(skill_id, values, trace=, approved_permissions=, initiator=, purpose=) -> RunOutcome`——**逐节点调用**，不改其代码（工作流层是组合方）；**该 runner 必须不带 `OutputRegistry`**（构造期由 `TrialRunner` 显式拒绝违例）
  - T-SC-001.2 `Trace`：整条试跑共用一条链，逐节点追加 `skill_run` 步
  - T-L0-001 `Store`：`execution_log` 分区（试跑记录；与 `skill-run/` 同分区不同前缀）
- 输出（本任务交付的公共 API / 落盘位置，已经实现后按实测校正）：
  - `st_agent.l1.workflow.trial`：`TrialRunner(store, registry, runner, *, history=None, approved_permissions=(), initiator=, purpose=)`（`start(dag, values, trace=) -> WorkflowTrial`）；`WorkflowTrial`（`step` / `run_to_end` / `pause` / `resume` / `abort` / `inject` / `snapshots` / `snapshot_of` / `record` / `status` / `trace`）；`TrialStep`（`order` / `node_id` / `params` 输入快照 / `value_sources` 逐参数来源 / `envelope` / `duration_ms` / `skill_run_id` / `skipped`）；`TrialRecord`（整场记录：状态 / 注入 / 逐步快照 / 共用推理链）；`TrialDiff`
  - `st_agent.l1.workflow.trial_history`：`TRIAL_PREFIX = "workflow-trial/"`；`TrialHistory`（`save` / `get` / `list_all` / `list_for_flow` / `compare(trial_id_a, trial_id_b) -> TrialDiff`）
  - 错误面：`TrialError` 基类 · `TrialStateError`（非法状态转移）· `TrialNotFoundError`（记录不存在）
  - 落盘：`execution_log` 分区 `workflow-trial/<trial_id>.json`（试跑记录 + 逐节点快照；`trial_id` = 本任务升格进 [01 §1](../../docs/技术架构-v2/01-平台共享契约.md) 的契约 ID）
  - 消费方：`T-L1-003.4`（画布试跑入口）、`T-L3-004`（调试控制台渲染）、`T-L6-001`（反思可回溯工作流试跑）

## 假设与前提

- A1 试跑经**逐节点调 `SkillRunner.run`** 组合实现（拓扑排序由工作流层做），**不修改** `T-L1-001.2` 已合入的 `SkillRunner`——节点级依赖与 Skill 级 `dependencies` 是两个层次，可叠加 / 若错（须让 `SkillRunner` 感知工作流上下文，如同一 `trace_id` 下共享上游、或整图一次原子执行）：须改 `.2` 并回归其全部用例 / 验证：`git diff --name-only` 不含 `src/st_agent/l1/runner/`；GWT-1 + `.2` 全量用例绿。
- A2 参数绑定中的「上游输出引用」在试跑期**从上游 `ResultEnvelope.data` 按路径取值**；引用路径不存在时该节点 `validation_failed`（不静默置空）/ 若错（须支持转换/映射等更复杂绑定）：须扩 `ParamBinding` 形态（03 §3.1 补说明）/ 验证：GWT-1 / GWT-3。
- A3 暂停 / 继续 / 中止是**会话对象的状态机**（步进式驱动），非线程中断——同进程、确定性、可测；进程被杀不在覆盖范围（崩溃恢复不属试跑语义）/ 若错（要求跨进程可恢复的试跑）：须持久化会话游标并复算 / 验证：GWT-4 + 会话状态转移用例。
- A4 试跑记录落 `execution_log` 分区 `workflow-trial/`，与 `skill-run/`（`.2`）**同分区不同前缀**——试跑也是执行留痕，不另立分区（02 §2.1 的七分区不再扩） / 若错（试跑噪声污染审计面）：须加保留策略或另立前缀过滤 / 验证：`Store.list_files("execution_log")` 前缀可分辨。
- A5 试跑**不做**生产侧副作用隔离之外的事——执行器本身由 L1 沙箱（`.5`）约束；试跑与正式执行的差别仅在「可单步 / 可中止 / 留试跑历史」，不改权限口径（`approved_permissions` 照传）/ 若错（试跑须放宽权限以便调试）：须另立受限口径并与人确认 / 验证：GWT-1 传参断言 + 权限用例。
