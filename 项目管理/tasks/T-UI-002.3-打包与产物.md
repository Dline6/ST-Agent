# T-UI-002.3 · 打包与产物

## 目标
交付 `packaging/**` 与构建脚本：把[生产入口](T-UI-002.1-生产运行入口与壳后端握手协议.md)冻结为**后端二进制**、把[桌面壳](T-UI-002.2-桌面壳本体窗口托盘自启与通知接线.md)冻结为**壳产物**、静态资产随包；本机产出并冒烟 **Windows 产物**，另两平台只落构建口径（[D-076](../决策日志.md)：Windows 实测 + 三平台配置）。

## 验收标准（Given-When-Then）
- Given 打包配置，When 在 Windows 构建，Then 产出后端二进制与壳产物，且产物内**不含** `st_agent/ui/dev/**`（dev 面物理剔除在冻结产物上复核，不只是 wheel 层面）
- Given 冻结产物 + 清空 `PYTHON*` 环境 + 非仓库 `cwd`，When 运行后端二进制与壳，Then 界面可用（不依赖本机 site-packages 与仓库路径）
- Given 运行中的产物，When 写入用户数据，Then 数据只落**平台用户数据目录**（`data/`、仓库路径与 `cwd` 均不出现用户数据）——[数据主权红线](../Git协作规范.md)
- Given 三平台口径，When 查阅 `packaging/` 文档，Then 每平台的构建前置与命令齐备，**macOS / Linux 产物未产出**并显式标注（不写成「已支持」）
- Given 新增的打包路径，When 查 [工作流](../工作流.md)「测试分层」映射与 [`ci.yml`](../../.github/workflows/ci.yml)，Then 新路径已被纳入（机器可查，判据同 [`D-045`](../决策日志.md) 对 `tests/integration` 的同型教训）

- **输入**：

  - [`pyproject.toml`](../../pyproject.toml) 的 package-data（`st_agent.ui` 的静态资产）与 `packages.find` 的 dev 剔除口径
  - [00 §1.1](../../docs/技术架构-v2/00-架构总览.md)（壳是 UX / 打包项）· [02 §2.1](../../docs/技术架构-v2/02-L0-本地优先基座.md)（分区物理位置由实现决定）
- **输出**：
  - `packaging/st-agent-server.spec` / `packaging/st-agent-shell.spec`（PyInstaller）· `packaging/build.py`（逐平台构建）· `packaging/README.md`（三平台前置与命令口径）
  - Windows 实测产物（后端二进制 + 壳）与多层冒烟证据
  - [工作流](../工作流.md)「测试分层」映射与 [`ci.yml`](../../.github/workflows/ci.yml) 的范围判定补 `packaging/**` 一行
  - **不交付**：macOS / Linux 产物（待各自主机；本机无法构建）· 安装器 / 签名 / 公证（属发布流程，另案）

## 假设与前提
- **A1 · 用 PyInstaller 冻结**——前提：单栈（Python）交付、无 Node / Rust 工具链依赖，与 [D-076](../决策日志.md) 的壳选型同向。若错（需换 Nuitka / 安装器套件）：返工面＝`packaging/**` 与其冒烟。验证方式：产物在清空 `PYTHON*` 环境的条件下可运行。
- **A2 · 「无 Python 环境」以环境清空方式逼近**——前提：本机装有 Python，无法真造无 Python 机器。若错（存在隐性 site-packages 依赖）：产物在真机失败。验证方式：清空 `PYTHON*` / `PYTHONPATH` + 非仓库 `cwd` + 断言冻结产物不读仓库路径；**残余风险显式登记在遗留**（真机未验）。
- **A3 · 本批只产 Windows 产物**——同父任务 `A4`。若错（要求三平台产物齐备）：须引入跨平台构建 runner，本批不能收口。验证方式：`packaging/README.md` 的逐平台口径 + 产物缺位标注。
