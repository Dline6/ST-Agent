# T-L3-003.2 · 双通道登记面与处置三态

## 目标

兑现 [05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 的**双通道同源**与**流转三态**两个面：草稿生成与（面板通道的）编辑**共用** [01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 配置注册表——同一 `config_id` 的对话描述与面板表单取自**同一条**登记项；用户对草稿的三种处置（接受 / 微调 / 拒绝）各有确定的落点。

## 验收标准（Given-When-Then）

- **GWT-1 · 双通道同源**：Given 目标声明体中的一个参数，When 分别取**对话通道**与**面板通道**的视图，Then 两者由**同一处解析**得出——参数已登记时为**同一条** [`ConfigEntry`](../../src/st_agent/contracts/registry_types.py)（`description_for_chat` / `panel_form_spec` / 默认值 / `scope` 一致）；未登记时两个通道**同样**回落到该参数的声明面（[`ParameterSpec`](../../src/st_agent/contracts/capability_types.py) 的 `description` + 由 `type` 映射的表单字段）并**标注解析来源**；**不出现**「一个通道取登记项、另一个取声明面」。描述体取数口与登记面**都没注入** → `unavailable` + 点名，不各自降级出不同结果。
- **GWT-2 · 接受**：Given 一份草稿，When 用户**接受**，Then 配置落值生效并产生 `change_id`（[01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 变更留痕，形态为 [`ChangeRecord`](../../src/st_agent/contracts/registry_types.py)）；**未注入**登记面的写入端时 fail-closed（`unavailable` + 点名），**不假装生效**、不自行落盘到别的分区。
- **GWT-3 · 微调**：Given 一份草稿，When 用户**微调**，Then 返回**参数面板视图**（由同一条登记项的 `panel_form_spec` + 当前值构成），供面板通道继续编辑；草稿态**不落盘**（与 [03 §4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 工作流面「编辑期不落盘」同一条边界）。
- **GWT-4 · 拒绝**：Given 一份草稿，When 用户**拒绝**，Then 草稿丢弃、**不落盘**，可选 `reason` 随返回值透传（**反馈池归 [`T-L6-001`](T-L6-001-反馈采集FeedbackEvent每周反思报告.md)**，本叶不建反馈存储、未接入即点名不静默丢）。

## 接口面

- **输入（消费的前置接口）**
  - `T-L3-003.1`（本批同出）`ConfigDraft` 与 `generate`——本叶的处置对象
  - `T-SC-001.4` [01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 类型：[`ConfigEntry`（七字段）](../../src/st_agent/contracts/registry_types.py) / [`PanelField`](../../src/st_agent/contracts/registry_types.py) / [`ChangePolicy`](../../src/st_agent/contracts/registry_types.py) / [`ChangeRecord`](../../src/st_agent/contracts/registry_types.py)
  - **登记表门面（尚不存在）**：仓库现无统一读取面——现存登记项由各子系统自落 `config/<分区前缀>/*.json`（如 [`mcp-hub/reconnect-*.json`](../../src/st_agent/l1/mcp/lifecycle.py) / [`llm-provider-host/*.json`](../../src/st_agent/l1/sandbox/provider_hosts.py)）。本叶**只定义端口**，形态由 `## 假设与前提` A1 钉住；门面本体**待人立项**（见 `## 可关闭的遗留`）
- **输出（本任务交付的公共 API / 落盘位置）**
  - `src/st_agent/l3/config/registry.py`：**注入的鸭子类型端口**（缺省不注入 → 两个通道同样 fail-closed）——
    - 读取：`get(config_id) -> ConfigEntry` · `list(scope=None) -> tuple[ConfigEntry, ...]`
    - 落值：`apply(config_id, value, *, trace_id=None) -> ChangeRecord`（值 + 变更留痕**一次落**，`change_id` 即回滚单位）
  - `src/st_agent/l3/config/panel.py`：面板视图（`PanelView` = 登记项的 `panel_form_spec` + 当前值 + `config_id`）；对话视图即 `description_for_chat`——两个视图**同源**，是 GWT-1 的落点
  - `src/st_agent/l3/config/draft.py` 增收尾三入口：`accept(draft)`（经端口 `apply`）/ `tune(draft)`（返回 `PanelView`）/ `reject(draft, reason=None)`
  - 落盘：**本叶不新落任何分区**——值的落点与变更留痕**由登记面端口的实现承载**（[`.2`](T-L3-003.2-双通道登记面与处置三态.md) 不自行落盘，见 A1）
  - 同批改 [01 §7](../../docs/技术架构-v2/01-平台共享契约.md)：补「登记项的**消费面**（读取 / 落值）由谁提供、消费方按什么形态消费」；改 [05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md)：补三态各自的落点

## 可关闭的遗留

- **L1 册 `D2`（Skill 侧批准账本的写入入口无落点）→ 修正归属**：该条归属列原名点 [`T-L3-003`](T-L3-003-对话即配置ConfigDraft双通道.md) / [`T-L3-004`](T-L3-004-GenerativeUI推理链可视化.md) / [`T-ECO-002`](T-ECO-002-导入校验流水线官方Skill索引生态边界.md)。**本任务力不能及**——`D2` 的写入是**能力安装 / 导入审批**（挂载时 `declare`、用户批准时 `approve`），而本任务是对**既有能力做参数配置**（即「对话即配置」，不涉安装审批），两者不是同一面。故就地**去掉 `T-L3-003` 这一归属**，保留 `T-L3-004` 与 `T-ECO-002` 并写明理由（[册规](../遗留问题/README.md) 2）。
- L2 册 `B1` 归属 [`T-L3-005`](T-L3-005-冲突裁决与反馈采集点.md)（非本任务）；L3 册 `A1` 归属「待人立项」（非本任务）；L0 册 A / C / E / F 段无一条指向本任务。
- **新登记**：统一配置注册表**门面本体**无归属任务（现行各子系统自落、无按 scope 的读取面）→ 登记 [L1 册](../遗留问题/L1-遗留问题.md)「待人立项」。

## 假设与前提

- **A1 · 登记表门面以注入端口消费，本任务不在 L1 建门面**：[05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 要求「共用 [01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 配置注册表」，但仓库无统一门面（各子系统自落 `config/<前缀>/*.json`），且 [01 §7](../../docs/技术架构-v2/01-平台共享契约.md) 侧明说注册表的持久化不归 L3。故 L3 只定**端口形态**并按鸭子类型注入；门面本体**待人立项**（已登记 L1 册）。若错（须由本任务顺带在 L1 建门面）：返工面＝本叶实现跨层 + 门面形态缺少消费方验证。
- **A2 · 「配置生效」＝经端口 `apply` 落值 + 留痕，不是 L3 自行落盘**：[05 §5](../../docs/技术架构-v2/05-L3-对话主入口.md) 说接受后「配置生效并产生 `change_id`」。落点取注入的登记面写入端，`ChangeRecord` 即留痕；L3 不碰 `config` 分区（否则绕过登记表，双通道会分叉）。若错（L3 可直落）：返工面＝`accept` 的落点。
- **A3 · 面板通道的**渲染**不归本叶**：[05 §6](../../docs/技术架构-v2/05-L3-对话主入口.md) 已把前端骨架与组件注册表宿主归跨层 [`T-UI-001`](T-UI-001-表现层骨架与本地服务通信面.md)，L3 特有组件的渲染归 [`T-L3-004`](T-L3-004-GenerativeUI推理链可视化.md)。本叶只交付**视图数据**（`PanelView` / 对话描述），渲染与交互不在其列。若错（须本叶出渲染产物）：返工面＝本叶的交付面与 [D-060](../决策日志.md) 的归属划分。
- **A4 · 拒绝的原因只透传，不建反馈存储**：反馈池归 [`T-L6-001`](T-L6-001-反馈采集FeedbackEvent每周反思报告.md)（08 §1）。若错（须在本叶落反馈）：返工面＝`reject` 的落点与 L6 侧口径。
