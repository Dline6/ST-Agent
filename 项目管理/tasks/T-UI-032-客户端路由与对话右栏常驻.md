# T-UI-032 · 客户端路由与对话右栏常驻

## 目标

把页内导航改为客户端路由：点击页面链接不再整页重载，右栏对话、进行中的请求与页面内选择跨页保留；刷新或重启后按上次活动会话恢复右栏。

## 验收标准（Given-When-Then）

- GWT-1 页内切换：Given 在任一页面，When 点击左栏分区 / 二级项或页内页面链接，Then 地址与主区内容更新，右栏对话流与输入框保持原样（DOM 未重建），文档不发生整页加载。
- GWT-2 前进后退：Given 已经历多次页内切换，When 使用浏览器后退 / 前进，Then 主区切回对应页面，右栏对话不变。
- GWT-3 动作跳转：Given 由「打开详情 / 打开画布」等动作触发的跳转，When 执行，Then 同样走客户端路由，不退回 `location.assign`。
- GWT-4 冷启动恢复：Given 刷新或重启后打开应用且存在上次活动会话，When 右栏挂载，Then 从 `GET /api/chat/session` 取回消息并回放；会话不存在时清空并显式提示。
- GWT-5 应用内刷新：Given 使用应用内刷新（F5 / 命令面板），When 重绘当前主区，Then 右栏对话不被清空。

## 接口面

- 输入（消费的前置接口）：
  - `T-L3-008` 的 `GET /api/chat/session?id=` 与 `GET /api/chat/sessions`。
  - 既有 `pages.js` 登记表与 `nav.js` 的 `PARTITIONS` / `activeScreen`。
  - 既有 `main.js` 的 `boot` / `renderPage` / `mountChat` / `buildNav` / `paintCrumbs`。
- 输出（本任务交付的公共 API / 落盘位置）：
  - 新增 `src/st_agent/ui/web/js/router.js`：`navigate(path)`、`startRouter(onNavigate)`；只接管同一来源、且 `pageFor()` 能命中的页面链接。
  - `main.js`：`boot` 改为外壳只装载一次、主区可多次渲染；`go()` 走 `navigate`；`popstate` 重新渲染；`refreshCurrentPage` 不再重挂右栏。
  - 各页 `window.location.assign` 改走 `navigate`（`mcp.js` / `skills.js` / `studio.js` / `workspace.js` / `palette.js` / `deliberation.js` / `memory.js`）。
  - `chat.js`：挂载时读取 `localStorage` 的 `st.chat.active` 并恢复会话。
  - 无新增后端端点、无新增落盘（会话 id 存浏览器本地）。

## 可关闭的遗留

无（已扫各遗留册未闭区，无归属本任务的条目）。

## 假设与前提

- A1 各页面模块只依赖 `location.pathname` / `location.search` 取参，`pushState` 后读取行为一致；渲染不依赖文档级一次性初始化。若错：个别页面切页后不刷新内容，需在该页补一次重渲染。
- A2 客户端路由只接管 `pages.js` 已登记的路径；下载、外链、`target=_blank` 与登录类链接保持原生行为。若错：可能拦掉非页面导航。
- A3 切页不中止进行中的对话请求（SPA 不销毁模块，Promise 继续），回复到达后仍进入右栏。若错：需把请求挂到模块级 store。
- A4 右栏活动会话 id 存 `localStorage`（不含任何消息正文、不含令牌），刷新后可恢复；换设备不同步。若错：涉及数据主权口径，需改为仅 `sessionStorage`。
