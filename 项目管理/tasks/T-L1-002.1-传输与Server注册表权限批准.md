# T-L1-002.1 · MCP 传输与 Server 注册表 + 权限批准

## 目标
交付 MCP Hub 的**接入面**：两种传输（本地 stdio / 远程 HTTP-SSE）+ Server 注册表增删启停 + 添加时连接测试 + 01 §10 权限的「声明 → 逐项批准」闸门。默认只允许本地 stdio；远程 Server 须用户显式开启并确认「数据会离开本机」，且其出网一律经 L0 网关登记。

## 验收标准（Given-When-Then）
- GWT-1 添加即连接测试：Given 一份本地 stdio 配置（命令 + 参数 + 环境变量），When 调用 `add_server` 保存，Then 立即发起连接测试并在返回值里给出显式结论（成功＝Server 名 + 协议版本 + 该 Server 声明的权限项；失败＝人可读原因），且记录落 `config` 分区 `mcp-server/<server_id>.json`；连接测试失败时**不**留下「已连接」状态的记录（失败显式化）。
- GWT-2 默认只允许本地：Given `transport="stdio"` 的注册，When 未做任何远程开关，Then 放行；Given `transport="remote"`（HTTP-SSE）而 `remote_acknowledged=False`，When 注册，Then 拒（`McpValidationError`）并给出「这是远程 Server，数据会离开本机」说明，**不落盘**。
- GWT-3 远程显式开启 + 风险标注 + 网关登记：Given 远程 Server，When 用户置 `remote_acknowledged=True`，Then 注册成功且该记录带数据外发风险标注；此后该 Server 的每次出网经 `EgressGateway.execute("remote_mcp", <host>, initiator=<server_id>)` 登记，`gateway.query(kind="remote_mcp", initiator=<server_id>)` 可查得审计记录。
- GWT-4 注册表增删启停：Given 已注册的 Server，When `disable` / `enable` / `remove`，Then 记录状态随之变更或删除，`get_server` / `list_servers` 如实反映（幂等；操作不存在的 id → 显式 `McpServerNotFoundError`）。
- GWT-5 权限逐项批准：Given Server 声明了权限（多条），When 经 01 §10 `validate_permissions` 校验通过后落盘，Then 每条初态 `pending`；`approve_permission` / `reject_permission` 逐项落盘；`approved_permissions(server_id)` 只返回已批准的条目（未批准/被拒的不在其中）；Given 权限串不合 01 §10 语法，When 注册，Then 拒且不落盘。
- 回归：既有 591 用例全绿；`verify_docs.py --strict` PASS。

## 假设与前提
- **A1 · MCP 客户端取最小协议面**：只实现 JSON-RPC 2.0 的 `initialize` / `notifications/initialized` / `tools/list` / `tools/call`；stdio 用行分隔 JSON，HTTP 用 POST（响应体按 SSE 数据行取 JSON）。若错（目标 Server 要求 capability 协商、sampling、roots 等更全语义）：返工面＝`McpClient` + 两种传输 + `.2` 的映射装载。验证：测试内自建 stub Server（子进程 + 本地 HTTP stub）走通三种方法。
- **A2 · 远程响应体经 sender 闭包带回，不改 L0**：`EgressGateway.execute` 丢弃 sender 返回的 `chunks`（只记字节数），故 `HttpSseTransport` 在按次 `sender` 闭包内完成真实 POST 并把响应体写入调用方持有的容器，网关仍独占「在线判定 + 审计落盘 + 超时/取消」职责。沿用 T-L0-005 注入按操作抓取闭包的先例。若错（评审认为属绕过网关语义）：返工面＝`HttpSseTransport` + 需另立决策给 L0 `stream()` 加按次 `sender`（配 D-NNN）。验证：注入 fake post 的离线用例断言审计记录与响应体同时可得。
- **A3 · 连接测试的失败语义**：测试失败即注册失败（不落「已连接」记录），符合 Story「保存后自动连接测试」与失败显式化的既有口径。若错（产品要「先存后连」）：返工面＝`add_server` 分支 + GWT-1。验证：GWT-1 失败分支用例断言存储层无新增文件。
- **A4 · 本地 stdio 出的网不在本批审计范围**：子进程自开的 socket 无法在 Python 进程内拦截；02 §6「本地 stdio MCP Server 的网络行为仍受 L0 审计」在本批**只覆盖经网关的远程请求**。若错（要求覆盖子进程出网）：返工面＝需进程级网络隔离（沙箱/代理注入），远超本任务。验证：本批不承诺；收工时登记为已知边界（执行日志遗留 + 新建 L1 遗留册）。
- **A5 · Server 记录是 L1 内部类型，不进 01 契约**：`McpServerRecord` 只在 L1 与经 `provenance.origin_chain` 的生态追溯面出现，不是跨层数据格式。若错（09 生态需要跨层 Server 类型）：返工面＝先改 01 → 再改 03 → 后改代码（工作流第 ⑦ 步）。验证：`test_layering` 通过 + 无跨层 import。
