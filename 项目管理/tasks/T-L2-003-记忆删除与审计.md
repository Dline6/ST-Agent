# T-L2-003 · 记忆删除与审计

## 目标

兑现 [04 §6 删除与审计](../../docs/技术架构-v2/04-L2-记忆图谱.md)：用户删除任一节点时**级联删除其派生推理链**（`derived_from` 下游），且**执行日志中的原始记录保留**——审计与反思依据不因记忆删除而失真。Story 3 验收段对应条为「用户删除某条记忆 → 该节点及其派生推理链一起从图谱移除（不影响历史执行日志的原始记录）」。

## 验收标准（Given-When-Then）

- **GWT-1 · 级联删除派生链**：Given 一条 `history` 节点与派生自它的 `pattern` 节点（`derived_from` 边），When 用户确认删除该 `history`，Then 两节点**一并**从图谱移除，且它们相接的边同时消失（图谱中不得残留悬空边）。
- **GWT-2 · 不误伤无关节点**：Given 图谱中另有与本链无关的节点与边，When 删除该链根，Then 无关节点与边**逐条原样保留**（删除范围限于被删节点集合与它们的相接边）。
- **GWT-3 · 审计留痕且不动既有日志**：Given `execution_log` 分区中已有既有记录，When 删除节点，Then 既有记录**逐字节不变**，删除动作本身留一条可查记录（含被删节点快照、级联清单、时刻、缘由）。
- **GWT-4 · 失败显式、零变更**：Given 目标节点不存在、或调用方未声明用户确认，When 调用删除，Then 显式抛错且**图谱零变更**（fail-closed，不静默降级、不部分删除）。
- **GWT-5 · 递归与共享派生**：Given 一条多层派生链（`history` ← `pattern` ← `pattern`）或菱形（两个下游共享同一上游），When 删除链根，Then **整条下游递归移除**且每个节点只删一次，不重复删、不死循环。

## 假设与前提

- **A1 · `derived_from` 边的存储方向＝「派生方 → 依据方」**：[04 §2](../../docs/技术架构-v2/04-L2-记忆图谱.md) 示例写作「pattern 节点 ← 聚合的 history 节点」，且 [`conflict.resolve`](../../src/st_agent/l2/memory/conflict.py) 的 `evolves_from` 先例为「新 → 旧」（新＝派生方）。故级联判据＝「`edge_type == 'derived_from'` 且 `target_id == 当前节点`」的边的 `source_id` 为下游。**若错**（方向相反）：级联会朝上游（依据方）删，把「依据」删掉而留下派生——返工面 = 级联判据一行 + GWT-1/5 的期望；同时须复核 `T-L2-002.2` 是否有写入侧的反向约定。**验证方式**：开工先读 `conflict.py` 与既有 `evolves_from` 用例确认方向，再写 GWT-1。
- **A2 · 删除须一并清掉相接的边，且先边后节点**：[`MemoryGraph.add_edge`](../../src/st_agent/l2/memory/graph.py) 以「无悬空边」为不变量；只删节点会留下指向空气中的边。删除次序取**先删边、后删节点**——中断只可能留下「节点在而边少」（合法），不会留下悬空边（非法）。**若错**（应保留边作历史痕迹）：返工面 = 删除集合的构成，但须先解「悬空边」不变量（人决）。
- **A3 · 删除入口只接受 `confirmed_by="user"`**：Story 原文为「When **确认**删除」，且 [`edit_node`](../../src/st_agent/l2/memory/writer.py) / [`resolve`](../../src/st_agent/l2/memory/conflict.py) 已用同款形状强制「副驾不得自主改既有节点内容」。[04 §3.2 红线](../../docs/技术架构-v2/04-L2-记忆图谱.md) 的用词是「修改」，删除是更强形态，取同款门。**若错**（副驾可自主删推断类节点）：返工面 = 入口签名的门 + 一条自主删除白名单条目（属 01 §7 面）。
- **A4 · 删除留痕落 `execution_log` 分区**（待 ④ 确认）：[§6](../../docs/技术架构-v2/04-L2-记忆图谱.md) 只说「执行日志中的原始记录保留」；本条按标题的「审计」二字再进一步——**新增**一条删除记录（被删节点快照 + 级联清单 + 时刻 + 缘由），使「某条记忆何时被删、连带删了什么」可复核（呼应铁律 5「可解释」与 L6 反思面）。**若错**（「审计」仅指既有日志不被级联删，不新增记录）：返工面 = 去掉 `deletion.py` 的落盘半边与 GWT-3 后半，交付缩小为「级联删除 + 既有日志不受影响」。
- **A5 · 删除不存在的节点＝显式失败**：与 [`get_node`](../../src/st_agent/l2/memory/graph.py) 同款（`MemoryNotFoundError`），不取「幂等成功」。**若错**（须幂等）：返工面 = 入口的一处判断 + GWT-4 的一条分支。
- **A6 · 「完全清空」不在本任务**：[04 §6 第二条](../../docs/技术架构-v2/04-L2-记忆图谱.md) 明写「走 [02 §8.3](../../docs/技术架构-v2/02-L0-本地优先基座.md)」，而 `T-L0-006` 已 `done` 并交付 [`wipe_all`](../../src/st_agent/l0/backup/backup.py)（删存储根整目录，`memory` 分区随之消失）。L2 侧**无可配合项**，不另立入口（否则成为无人调用的第二清空路径）。**若错**（须在 L2 侧包一层带确认的入口）：返工面 = 新增薄门面 + 其 GWT，且在 L0 已有入口之上形成重复。
- **A7 · 不新增契约事件名**：[01 §11](../../docs/技术架构-v2/01-平台共享契约.md) 现无 `MemoryNodeDeleted` 之类事件，新增事件名属契约变更（铁律 8：先改 01 再改代码）。本任务**不**发事件；若上层（L3/L6）需要感知删除，另立任务并走 01 → 架构 → 代码三步。**若错**（须发事件）：返工面 = 01 §11 增事件名 + 本任务增 `event_for`。
- **A8 · 删除不写 `revision_history`**：修正历史是「同一条记忆被改」的留痕（ID 不变）；删除是**实体消失**，其痕迹的载体是 A4 的删除记录而非挂在某个节点上。**若错**：返工面 = 留痕改挂节点 + GWT-3 期望调整。
