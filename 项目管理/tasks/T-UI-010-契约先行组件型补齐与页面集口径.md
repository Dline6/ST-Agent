# T-UI-010 · 契约先行：组件型补齐与页面集口径

> **M6 的契约先行叶**（[D-103](../决策日志.md)）。按[铁律 8](../工程宪法.md) 的序——**先改契约、再改各层、最后改代码**——把 M6 各分区叶所需的表现面**先对齐**，使后续七叶的「涉及契约」有处可指、不再边做边改 `01 §12`。

## 目标

两件交付，都落在**契约面**（本叶**不建任何页面**）：

1. **组件型补齐**——逐条盘点 [11-sitemap §2 页面清单](../../docs/PRD-v2-Agent/11-sitemap.md) 所需的呈现形态，对 [01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 的枚举面表态：**已在 14 型内可复用的不新增**；**确需新形态的先登记**（`ComponentType` 的 `Literal` + `IMPLEMENTED_COMPONENT_TYPES` + [`ui_description.py`](../../src/st_agent/contracts/ui_description.py) + [`ui/registry.py`](../../src/st_agent/ui/registry.py) 的 `REQUIRED_SLOTS` + 渲染件 + [13-visual-design §5](../../docs/PRD-v2-Agent/13-visual-design.md) 视觉基线 + 两侧类型集合一致性断言）。
   - **已知候选**（④ 对齐时逐条判定，不足则不加）：记忆区**图谱视图**的节点-边图——现枚举里**无对应型**（`divergence_map` 的 `network` 槽是同形态但对位「分歧」语义，能否复用属本叶判定）；触达区的趋势 / 热力读面（预留型 `trend_chart` / `heatmap`）；工作区钉住看板（预留型 `pinned_board`）；偏好画像的风险徽标（预留型 `risk_badge`）。**预留型升为已实现属「实现」而非「改契约」**（[01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 早登记其名）。
2. **页面集口径**——把 [11-sitemap §2](../../docs/PRD-v2-Agent/11-sitemap.md) 声明的每条屏归并到**页面路径**（IA 是「有哪些屏」，本叶定「屏落到哪个路径」），并与 [`ui/app.py` 的 `PAGE_PATHS`](../../src/st_agent/ui/app.py) / [`web/js/pages.js`](../../src/st_agent/ui/web/js/pages.js) 同源；同批定**导航模型**——[11-sitemap §1](../../docs/PRD-v2-Agent/11-sitemap.md) 声明「无传统菜单式入口层级」，而现壳有常驻 `nav` 列表，两者的调和口径落文档（[11-sitemap](../../docs/PRD-v2-Agent/11-sitemap.md) 或 [05 §6–§7](../../docs/技术架构-v2/05-L3-对话主入口.md)）。

**本批的边界**（不越界）：

- **不改既有 14 型的槽语义**——新形态**只增不改**；若某既有型的槽词汇确需变更，按[铁律 8](../工程宪法.md) 另立条目、不在本叶夹带。
- **不建页面、不注入端口**——页面登记与端口注入归底座叶 [`T-UI-011`](T-UI-011-底座与骨架多面端口注入与全IA页面登记.md)。
- **不重排 IA 既有分区**——11-sitemap 的分区编排由 [`T-UI-006`](T-UI-006-IA补章受控自主分区与页面Flow.md) 补齐，本叶只在其上定路径。
- **不引构建链**——[D-063](../决策日志.md) 的零构建原生 ES 模块口径不动。

**拆分**（命中[拆分触发](../工作流.md)：两件交付各自跨多个契约小节——①涉 [01 §12](../../docs/技术架构-v2/01-平台共享契约.md) / [13 §5](../../docs/PRD-v2-Agent/13-visual-design.md) / [11-sitemap](../../docs/PRD-v2-Agent/11-sitemap.md) 与代码镜像；②涉 [11-sitemap §1–§2](../../docs/PRD-v2-Agent/11-sitemap.md) / [05 §6](../../docs/技术架构-v2/05-L3-对话主入口.md) / `PAGE_PATHS`；单次预计 Agent 会话轮次 > 20）——父转分组节点，交付由两叶承接（[D-108](../决策日志.md)）：

- [`T-UI-010.1`](T-UI-010.1-组件型补齐屏形态对位与四型落地.md)——**组件型补齐**：屏 → 形态对位表 + 四型落地（`graph_view` / `timeline_view` 新登记并实现；`heatmap` / `trend_chart` 预留升实现）
- [`T-UI-010.2`](T-UI-010.2-页面集与导航模型.md)——**页面集与导航模型**：屏 → 页面路径对位 + 导航模型口径 + 防漂移守卫

不合并成一叶：两叶失败面不同（「对位漏项 / 契约与镜像漂移 / 渲染件缺失」vs「路径漏项 / 文档与路由漂移 / 导航口径冲突」），且 `.1` 冻结的是**型**、`.2` 冻结的是**路径**——`.2` 的路径判定依赖 `.1` 的「哪些屏是页面」结论（故 `.2` `depends_on` `.1`）。

## 验收标准（Given-When-Then）

逐条落到两叶（父级只汇总，不重复）：

- GWT-1：Given [11-sitemap §2](../../docs/PRD-v2-Agent/11-sitemap.md) 的全部屏与 [01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 的枚举面，When 逐条对位，Then **每条屏所需形态都有归属**——「复用某既有型」或「登记某新 / 预留型升实现」或「非组件型面（页面 / 壳面 / 对话流内面）」，无未表态者 → [`.1`](T-UI-010.1-组件型补齐屏形态对位与四型落地.md) GWT-1
- GWT-2：Given 新登记 / 新实现的组件型，When 查看契约与镜像，Then `ComponentType` / `IMPLEMENTED_COMPONENT_TYPES` / [`ui/registry.py`](../../src/st_agent/ui/registry.py) 的 `REQUIRED_SLOTS` 与前端 [`web/js/registry.js`](../../src/st_agent/ui/web/js/registry.js) **两侧类型集合一致**（既有一致性用例不红），且每型有槽词汇与**中性边界**标注 → [`.1`](T-UI-010.1-组件型补齐屏形态对位与四型落地.md) GWT-2
- GWT-3：Given 每个新实现型，When 查 [13-visual-design §5](../../docs/PRD-v2-Agent/13-visual-design.md)，Then 有对应视觉基线行（结构 + 视觉），页面叶据此落地 → [`.1`](T-UI-010.1-组件型补齐屏形态对位与四型落地.md) GWT-3
- GWT-4：Given 页面集口径，When 对位 [11-sitemap §2](../../docs/PRD-v2-Agent/11-sitemap.md) 与 [`PAGE_PATHS`](../../src/st_agent/ui/app.py) / [`pages.js`](../../src/st_agent/ui/web/js/pages.js)，Then 每条屏落到某路径、每个路径有出处；导航模型口径落文档，与「无传统菜单」声明不冲突 → [`.2`](T-UI-010.2-页面集与导航模型.md) GWT-1 / GWT-2 / GWT-3
- GWT-5：Given 全项目相对链接，When 在 `项目管理/` 下跑 `python tools/verify_docs.py --strict`，Then 检查 1–9 全过、0 断链 → 两叶共有
