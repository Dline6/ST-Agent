# T-UI-015.3 · 能力区：Studio 附加面

> [`T-UI-015`](T-UI-015-能力区Skill库MCPHub与Studio附加面.md) 三叶之一（[D-117](../决策日志.md) ①）——补 `/studio` 上**除主画布外**的五条屏：Skill 参数面板 / 工作流属性面板 / **调试控制台**（真试跑）/ 版本历史页 / 模板库。主画布已由 [`T-UI-005`](done/M5/T-UI-005-Studio画布页.md) 交付；Skill 库与 MCP Hub 归 [`.1`](T-UI-015.1-Skill库浏览详情参数与执行日志.md) / [`.2`](T-UI-015.2-MCPHub服务器与权限确认.md)。

## 目标

story-06 的屏清单里，主画布（[`T-UI-005`](done/M5/T-UI-005-Studio画布页.md) 两叶）与导入导出对话框（[11-sitemap §2.2](../../docs/PRD-v2-Agent/11-sitemap.md) 归 `/eco`，[`T-UI-004.4`](done/M4/T-UI-004.4-生态面表现层入口.md) 已交付）**已在**；本叶补余下五条：

- **Skill 参数面板**（[§2.1](../../docs/PRD-v2-Agent/11-sitemap.md)：复用 `setting_panel` / `config_draft_card`）——**复用 [`.1`](T-UI-015.1-Skill库浏览详情参数与执行日志.md) 的 `skill-params` 面键与 `POST /api/skills/params`**（同一屏语义的两处宿主，不造第二套参数真相源）
- **工作流属性面板**（复用 `report_card`）——`WorkflowDAG` 的属性逐段并列（名称 / 说明 / 注册名 / 版本 / 调度 / 节点数 / 依赖清单 / 悬空引用）+ **版本动作**（`activate` / `rollback`，真落值 + `ChangeRecord` 留痕）
- **调试控制台**（复用 `trace_timeline` + `table`，[§2.1](../../docs/PRD-v2-Agent/11-sitemap.md)）——**真试跑**：起跑 / 单步 / 跑到结束 / 暂停 / 继续 / 中止，逐节点输入输出快照 + 值来源标注，两次试跑按 `node_id` 对比（[03 §4 调试协议落地口径](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)）
- **版本历史页**（复用 `timeline_view`）——`WorkflowStore.list_versions(base)` 逐条时序 + 两版 `diff` + 一键回滚
- **模板库**（复用 `table` / `report_card`，[§3.4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)）——逐条出名称 / 说明 / 节点数 / 引用 Skill / **缺失 Skill 清单**；`load` 出**只读预览**；`fork` 产用户自有副本并**交画布会话**编辑（「接受」才是落盘点）

**本批的边界**（不越界）：

- **不重造渲染件**——`setting_panel` / `config_draft_card` / `report_card` / `timeline_view` / `trace_timeline` / `studio_canvas` / `table` 均已实现，本叶只做**宿主页与取数**。
- **不重造主画布与编辑面**——画布会话、增删节点 / 连线 / 分组、接受 / 微调 / 拒绝归 [`T-UI-005`](done/M5/T-UI-005-Studio画布页.md) 与 L1 `CanvasEditor` / `DraftIntake`；本叶只**取数与转交**。
- **不重造导入导出对话框**——归 `/eco`（[D-117](../决策日志.md) ④）；Studio 侧只给一条通往 `/eco` 的入口。
- **试跑不登记输出复用**（[03 §4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)：彩排产物不进生产复用面）——`TrialRunner` 自带该守卫，表现层不绕过。
- **属性编辑（改 name / description / schedule）走草稿—接受流程**，不属本叶——属性面板**只读呈现 + 版本动作**，避免造出「页内改属性直接落盘」的第二条写入路径。

## 验收标准（Given-When-Then）

- GWT-1：Given [11-sitemap §2 能力](../../docs/PRD-v2-Agent/11-sitemap.md) 的 story-06 屏清单，When 对位现状，Then 除主画布与导入导出（已交付）外，参数面板 / 属性面板 / 调试控制台 / 版本历史 / 模板库**各有可见载体**
- GWT-2：Given 一个工作流，When 打开调试控制台试跑，Then 逐节点出输入输出快照（**逐参数标注来源**：注入 / 上游引用 / 字面量 / Skill 默认值），可单步、暂停后仍可单步、继续、中止；节点信封非 `ok` ⇒ 其**下游一律不执行**并标 `dependency_failed`（写明上游节点），试跑状态 `failed`
- GWT-3：Given 两次试跑记录，When 对比，Then 按 `node_id` 对齐逐节点列出输出差异（新增 / 消失 / 不同）；试跑记录**不进入**输出复用面（正式执行取不到彩排产物）
- GWT-4：Given 版本历史，When 查看两版 `diff` 并回滚，Then 差异逐项如实（增删节点 / 变化节点），回滚经 `WorkflowStore.rollback` 真落值并产生 `ChangeRecord`；**自建工作流为空** ⇒ 模板库**恒返回**且出「用一句话描述你想要的工作流」引导入口（[03 §4 空状态](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)），**不靠计数 0 反推**
- GWT-5：Given 数据面非 `ok`，When 呈现，Then 按 [01 §5](../../docs/技术架构-v2/01-平台共享契约.md) 六态如实——工作流标识不认识 / 不存在互不冒充、模板依赖缺失 ⇒ 浏览面**显式列缺失 Skill**（不静默滤除）、试跑被门禁拦 ⇒ 如实回拒因（成环 / 自环 / 重复标识 / 悬空引用）
- GWT-6：Given 文案，When 核对，Then 按[契约 9 中性表达](../../docs/PRD-v2-Agent/10-platform-capabilities.md)撰写，**无拟人化**；工作流名 / 说明（用户原话）作 `data` 槽原样呈现
- GWT-7：Given 真组合根 + 真回环服务，When 在 Edge 走查「模板 → fork → 属性 → 试跑 → 版本历史」，Then 全程可用、控制台无新增报错

## 假设与前提

- **A1**：**试跑会话须由组合根在进程内持有**（`trial_id → WorkflowTrial`）——`WorkflowTrial` 是步进式**活对象**，`TrialHistory` 只落每次状态变更后的**快照**（`TrialRecord`），暂停 / 继续 / 中止都作用在活对象的节点边界上，无法只靠落盘还原。**若错的影响**：若不持会话，则「单步 → 暂停 → 继续」跨 HTTP 请求无法实现（每次都新建会话 ⇒ 状态丢失），story-06 GWT-5 不成立。**验证方式**：读 [`trial.py`](../../src/st_agent/l1/workflow/trial.py) 的 `WorkflowTrial.__init__`（持 `_steps` / `_status` 于内存）与 `TrialRunner.start` 的返回；集成用例断言「start → step → pause → step → resume → run_to_end」在**同一 `trial_id`** 上推进且步数与拓扑序相符。
- **A2**：`templates.fork()` 的产物是 `WorkflowDAG`，而既有画布会话的入口 `DraftIntake.receive` 收的是 L3 形状的 `WorkflowDraft`（四字段 + `workflow_draft` 子对象）——两者之间需一条**小适配**（`WorkflowDAG` 的 `name` / `description` / `nodes` / `edges` / `groups` / `schedule` 正是 `workflow_draft` 的子集，身份字段 `flow_id` / `version` 按 §4 口径**剔除**后交接收方派生）。适配住**组合根**（UI→L1 的交接线），**不改 L1 语义**。**若错的影响**：若适配需要 L3 契约变更（如 `understanding_summary` 无来源），则 fork 只能退化为「只出只读预览 + 引导入口」，须登记未决并把该屏如实标注为部分交付。**验证方式**：读 [`draft.py`](../../src/st_agent/l1/studio/draft.py) 的 `receive` 的字段白名单 `_DAG_FIELDS` / `_FLOW_NAME_KEY` 与 [`templates.py`](../../src/st_agent/l1/studio/templates.py) 的 `fork` 返回；集成用例断言 fork 后经既有画布面 `GET /api/studio/canvas?proposal_id=…` 能取回同一份结构。
- **A3**：`WorkflowStore.diff(a, b)` 与 `TrialHistory.compare(a, b)` 的输出**足以支撑**「版本差异」与「试跑对比」两屏，无需新增比较逻辑。**若错的影响**：若需按节点级更细粒度（如逐参数差异），则要扩 L1 的比较件——那是 L1 的语义扩张，不在表现层任务范围。**验证方式**：读 [`store.py`](../../src/st_agent/l1/workflow/store.py) 的 `WorkflowDiff` 与 [`trial.py`](../../src/st_agent/l1/workflow/trial.py) 的 `TrialDiff` 字段表；用例断言两屏各含「新增 / 消失 / 不同」三类。
- **A4**：`/studio` 页现由 [`T-UI-005`](done/M5/T-UI-005-Studio画布页.md) 交付，本叶**只加段、不改其既有行为**——新段走 `?flow=` / `?view=` 查询串（不引动态段，[`PAGE_PATHS`](../../src/st_agent/ui/app.py) 保持精确匹配集合，[11-sitemap §2.2](../../docs/PRD-v2-Agent/11-sitemap.md)）。**若错的影响**：改既有画布段会波及 `T-UI-005` 的验收（会话一览 + 画布）与其用例，属越过本叶边界。**验证方式**：读 [`studio.js`](../../src/st_agent/ui/web/js/pages/studio.js) 现有的 `renderStudioPage` 与 `test_ui_studio.py`；走查确认无 `?flow=` 时旧行为逐字不变。
- **A5**：官方模板**恒返回**清单（[03 §4](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)：非空时亦然），空状态判据是 `WorkflowStore.list_all()` 为空——故「模板库」段**不因**已建工作流而消失。**若错的影响**：若按「有无模板」或「有无工作流」二选一呈现，会丢掉「已建工作流时仍可从模板新建」这条路径。**验证方式**：读 [`empty_state.py`](../../src/st_agent/l1/studio/empty_state.py) 的 `StudioHome.templates` 注释（「恒返回」）；集成用例断言建了工作流之后模板清单仍非空。
