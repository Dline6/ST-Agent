# T-UI-008 · 前端资产打包模式补全（wheel 漏 10 个文件）

> 缺陷修正，**来源**：`T-UI-007` 落地时核对静态资产投递面顺带发现（[执行日志](../执行日志.md) `[T-UI-007]` 的「遗留」行末段）。

## 目标

`pyproject.toml` 的 `package-data["st_agent.ui"]` 只列了五条**非递归**模式，未覆盖 `web/js/pages/**` 与 `web/js/plugins/{reflection,eco,studio}/**`，导致 **wheel 少 10 个前端文件**——`/reflection` `/evolution` `/eco` `/studio` 四个页面与 `studio_canvas` / `violation_alert` / `proposal_card` / `change_timeline` / `setting_panel` / `feedback_capture` 等组件型在非 editable 安装下**静默失效**（页面 404 或组件显式降级）。

**已核实的事实**（2026-10-09，真 wheel 实测，非推断）：

- 源码 `src/st_agent/ui/web/` 共 **27** 个文件，`pip wheel` 产物的 `st_agent/ui/web/` 下只有 **18** 个。
- 缺的 10 个：`web/js/pages/{eco,evolution,reflection,studio}.js` · `web/js/plugins/eco/violation_alert.js` · `web/js/plugins/reflection/{change_timeline,feedback_capture,proposal_card,setting_panel}.js` · `web/js/plugins/studio/studio_canvas.js`。
- **冻结产物不受影响**——[`packaging/st-agent-server.spec`](../../packaging/st-agent-server.spec) 用 `datas=[(…/"ui"/"web", "st_agent/ui/web")]` **整目录收集**，故 PyInstaller 路径已含全部资产；本缺陷只在 `pip wheel` / 非 editable 安装这条路上咬人。
- 旁证：仓内 `build/lib/`（2026-10-05 那次构建的落地树）同样只落了 15 个 web 文件。

**交付**：

1. [`pyproject.toml`](../../pyproject.toml) 的 `package-data["st_agent.ui"]` 改为**递归**模式（对 `web/` 全覆盖，新增目录不必再改配置）。
2. [`tests/ui/test_ui_dev_excluded.py`](../../tests/ui/test_ui_dev_excluded.py) 的 `test_web_assets_travel_with_the_package` **加强**——现行断言只要求「存在任一以 `web/` 开头的模式」，**任何**模式集都能过，等于没守；换成「`web/**` 下每个文件都被某个模式匹配」+「无模式匹配 `dev/**`」。

**本批的边界**（不越界）：

- **不改 PyInstaller / 打包脚本**——`packaging/**` 已正确，本批零改动。
- **不改** `[tool.setuptools.packages.find]` 的 `exclude = ["st_agent.ui.dev"]`——dev 剔除是另一条既有机制，本批只加一条「模式不得匹配 dev」的守卫。
- **不引入 wheel 内容核对步骤到 CI**——本批的验证用一次性真构建（见 GWT-5），不把构建机依赖塞进 `check` job。

## 验收标准（Given-When-Then）

- GWT-1：Given 源码 `src/st_agent/ui/web/**` 的全部资产，When 构建 wheel 并列出 `st_agent/ui/web/` 下的文件，Then 与源码**逐文件一致**（修正前缺 10 个，修正后 0 个缺口）
- GWT-2：Given 改后的 `package-data` 模式，When 往 `web/` 下**新目录**放入一个资产，Then 无需改 `pyproject.toml` 即被打包（模式对 `web/` 递归覆盖）
- GWT-3：Given 发布构建须物理剔除 dev 面（[D-060](../../项目管理/决策日志.md) ④I），When 逐个模式求值，Then **无**任何模式匹配 `st_agent/ui/dev/**`
- GWT-4：Given 既有弱断言（`assert any(pattern.startswith("web/"))`），When 换成覆盖断言，Then **删掉任一条模式即变红**（红-绿可验）
- GWT-5：Given 本批改 `pyproject.toml`（[测试分层](../工作流.md)把契约与打包列为**跨层共享面**），When 收工，Then 跑**全量** `python -m pytest` 且 `python tools/verify_docs.py --strict` 检查 1–9 全 0

## 接口面

- **输入**（消费的前置接口）：

  - `setuptools` 的 `build_py.find_data_files`（本机 setuptools **83.0.0**，已读源码）——它把模式交给 `glob(..., recursive=True)`，故 `**` 真递归；模式写法的依据在此，不在文档印象里。
  - [`packaging/st-agent-server.spec`](../../packaging/st-agent-server.spec) 的 `datas=[(…/"ui"/"web", "st_agent/ui/web")]`（**整目录收集**）——证明冻结路径已正确，本批对其零改动。
  - `[tool.setuptools.packages.find].exclude = ["st_agent.ui.dev"]`（[D-060](../../项目管理/决策日志.md) ④I）——GWT-3 守的是这条**既有**机制不被新模式破坏。
- **输出**（本任务交付的公共 API / 落盘位置）：
  - [`pyproject.toml`](../../pyproject.toml) `package-data["st_agent.ui"]`：五条非递归模式 → **三条递归模式**（`web/*.html` / `web/**/*.css` / `web/**/*.js`）。**这是对外面的形状**——新增 `web/` 下任意深度的资产从此自动入包。
  - [`tests/ui/test_ui_dev_excluded.py`](../../tests/ui/test_ui_dev_excluded.py)：`test_web_assets_travel_with_the_package` 由弱断言改为**覆盖断言**；新增 `test_package_data_patterns_never_reach_the_dev_surface`。
- **降级路径**：模式失配**不报错**——构建照常成功、wheel 静默少文件，只在运行时表现为「页面 404」或「组件显式降级」（[01 §12](../../docs/技术架构-v2/01-平台共享契约.md)）。正因如此，本条守卫是**唯一**的自动化防线；本批的验证必须落在**真 wheel 内容**上，不能只看模式表。

## 假设与前提

- **A1 · 取向取「收敛为递归模式」而非「枚举缺失的两个目录」**（2026-10-09 开工自定，④ 复述时无人异议即按此）：前提是数据文件模式经 `glob(recursive=True)` 展开，故 `**` 真递归（**已读 setuptools 83 源码核实**）。若错（某版本不递归）→ 返工面＝改回逐目录枚举并补两行。**验证方式**：clean 构建的真 wheel 实测 27/27（本批已跑）。
- **A2 · 缺陷只在 wheel 路径上咬人，冻结产物不受影响**：前提是 spec 用**整目录** `datas` 收集 `ui/web`。若错（spec 也逐文件）→ 返工面＝`packaging/**` 同批修 + 产物重构建。**验证方式**：读 spec 的 `datas` 行（本批已核，为整目录）。
- **A3 · 守卫按 setuptools 的同一套 glob 语义求值即可代表构建行为**：前提是 `find_data_files` 除 glob 外还有 `manifest_files` 与 `exclude_data_files` 两步，而本仓**无** `MANIFEST.in`、无 exclude 规则，两步均为空操作。若错（将来引入 MANIFEST 或 exclude）→ 守卫会与构建分叉，须同批补上那两步的模拟。**验证方式**：clean 构建实测与守卫结论**两处一致**（本批均为 27/27）。
- **A4 · 改 `pyproject.toml` ⇒ 收工跑全量**（[测试分层](../工作流.md)既定，非选型）：前提是「契约与打包是跨层共享面」这条映射成立。若错（应只跑范围）→ 无返工面，只是多跑一轮。**验证方式**：全量 `pytest` 结果进执行日志「验证」行。

## 备注

改法取向（④ 对齐时若无人异议即按此）：把五条非递归模式收敛为三条**递归**模式 `web/*.html` / `web/**/*.css` / `web/**/*.js`——已核 `setuptools 83` 的 `build_py.find_data_files` 用 `glob(..., recursive=True)`，故 `**` 真递归；递归模式**抗漂移**（新增插件目录不必再改配置），这正是本缺陷的成因。守卫用例按**同一套 glob 语义**求值（与 setuptools 同源），不用 `fnmatch`——后者 `*` 会跨 `/`，会把缺口算成通过。

**另一处旁证性发现**（不在本叶范围，仅记）：真 wheel 里出现了源码中**已删除**的 `web/js/plugins/l3/slots.js`——`build/lib/` 的陈旧文件被重打包，说明构建目录未清理时会带出死文件。本批不做处置，验证时以 **clean 构建**（先删 `build/`）取证据。
