# T-L1-006.3 · MCP 面装配与移除回收接线

## 目标

装配 MCP Hub 三件（`McpServerRegistry` / `McpSkillMapper` / `McpHubStateMachine`）并接上 [03 §5.2](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md) 的「删除即回收」——把 `remove_server` 的 `on_server_removed` 回调接到映射回收；同批补上**生命周期当前态记录**的回收路径，销 [L1 册 `B1`](../遗留问题/L1-遗留问题.md)。

## 验收标准（Given-When-Then）

- GWT-1 回收接线生效：Given 已装配运行时 + 一台已挂载的 MCP Server，When 经运行时移除该 Server，Then 其映射记录与派生 Skill（base 的**全部版本**，含 `skill-update/<base>.json` 待检查标记）被硬回收（[03 §5.2](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)）。
- GWT-2 生命周期记录不留孤儿（销 L1 册 `B1`）：Given 同上，When 移除完成，Then `config/mcp-lifecycle/<server_id>.json` 的**当前态记录**被清理；重挂同名 Server 不继承旧态，且不再出现「注册记录已删、当前态记录仍在」的孤儿。
- GWT-3 移除序列与缺省行为：Given 该 Server 有进行中调用，When 经运行时移除，Then 顺序为「先转 `disabled` 并发出取消信号 → 再删注册记录与回收」（顺序可验）；Given 未装配回调（裸 `McpServerRegistry`），Then `remove_server` 行为与既有**逐字节不变**（缺省 `None`）。
- GWT-4 审计留痕不受波及：Given 移除完成，When 读取，Then `execution_log` 的状态转移与通知留痕（append-only）原样可查（只清当前态，不动审计）。

  - `T-L1-002.2`（done）· [`mcp/mapping.py`](../../src/st_agent/l1/mcp/mapping.py) 的 `McpSkillMapper(store, *, servers, skills)` / `recycle_server(server_id)`

## 可关闭的遗留

- L1 册 `B1`（`config/mcp-lifecycle/<server_id>.json` 在 Server 移除后成孤儿）→ **本批关闭**，销账在批末随父 `T-L1-006` 派生 `done` 执行；**同批修正其描述**——原文两半：①「当前态记录没有回收路径」＝真缺陷（本叶修）；②「`state_of` 在注册记录删后重读会抛 `McpServerNotFoundError`」经复核＝**正确行为**（对不存在的 Server 显式失败），非缺陷，不改。

## 假设与前提

- A1 `B1` 的销账口径＝只清**当前态记录**，`execution_log` 的转移 / 通知留痕（append-only）不动（合 [D-024](../决策日志.md) 的范围边界）/ 若错：越权删审计 / 验证：GWT-4。
- A2 `state_of` 对未注册 Server 仍抛 `McpServerNotFoundError`——这是显式失败语义，**不改**；[L1 册 `B1`](../遗留问题/L1-遗留问题.md) 描述的后半属正确行为 / 若错：为「不抛」而让 `state_of` 为不存在的 Server 编一个状态 / 验证：GWT-2 + 既有 [`tests/l1/test_mcp_lifecycle.py`](../../tests/l1/test_mcp_lifecycle.py) 用例不改。
- A3 清理动作由**组合根的移除序列**承担（新增公共 API + `on_server_removed` 闭包），`McpSkillMapper.recycle_server` 的行为与范围**不变** / 若错：与 [03 §5.2](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)「范围边界」的表述冲突 / 验证：GWT-1 / GWT-3 + 既有 `tests/l1/test_mcp_mapping.py` 全绿。
- A4 需在 [03 §5.2](../../docs/技术架构-v2/03-L1-能力底座-Skills与MCP.md)「范围边界」补一句澄清（当前态记录的清理属组合根移除序列、不在 `recycle_server` 范围内），**不改** mapper 行为与 [01](../../docs/技术架构-v2/01-平台共享契约.md) 契约 / 若错：文档与实现看似冲突、日后被当矛盾重翻 / 验证：收工时该小节与代码一致性复核。
- A5 `McpServerRegistry` 只支持**一个** `on_server_removed` 回调，故组合根传一个闭包内顺序调两个回收（映射 + 生命周期）/ 若错：两者只有一个生效 / 验证：GWT-1 与 GWT-2 同时成立。
