# T-L1-001.2 · 执行流水线 + 依赖 DAG + 权限 + SkillRun 留痕

## 目标
实现 03 §1.2 执行流水线：解析 → 参数确认 → 依赖 DAG 解析（含循环拒绝与上游失败转 `dependency_failed`）→ 权限检查 → 执行与留痕（ResultEnvelope + SkillRun 挂 `trace_id`）。执行器为同步 callable 注册，LLM 经 `LlmClient.invoke`，出网经 `EgressGateway`。

## 验收标准（Given-When-Then）
- GWT-2（匹配+确认卡）：Given Chat 说「帮我做摘帽可能性分析」，When 调度匹配，Then 命中 `unhat-eligibility-check` 并返回参数确认卡数据（参数名/默认值/可调范围）。
- GWT-3（参数即时生效）：Given 在 Studio 改 `stock-watch` 推送频率，When 下次 Chat 触发，Then 执行使用新参数值。
- GWT-4（依赖失败显式）：Given Skill 依赖上游输出，When 上游失败，Then 下游明确报 `dependency_failed` 并标注，不静默返回错误结果。
- GWT-6（推理链可查）：Given 一次 Skill 执行，When 点开推理链，Then 可见输入快照、输出、耗时、依赖链（SkillRun + TraceStep）。

## 假设与前提
- A4 执行器为同步 callable 注册（`register_executor(skill_id, fn)`，签名 `(params, ctx) -> ResultEnvelope`），LLM 调用经 `LlmClient.invoke`，出网经 `EgressGateway.execute/stream` / 若错：调用方面返工 / 验证：流水线测试（含 LLM/网关注入）
- A5 SkillRun 记录放 `execution_log` 分区 `skill-run/<skill_run_id>.json`（输入快照、输出、耗时、错误、依赖链），Trace 追加 `skill_run` 步 / 若错：留痕布局返工 / 验证：GWT-6 推理链测试（对齐已确认）
- A6 权限检查按 01 §10 本次执行所需逐项核对，未批准即 `validation_failed` 拦截 / 若错：权限面返工 / 验证：未授权执行拒绝测试
