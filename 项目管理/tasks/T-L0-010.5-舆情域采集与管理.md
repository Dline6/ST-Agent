# T-L0-010.5 · 舆情域采集与管理

## 目标

交付**舆情域**的完整链路，服务 [L4 情绪视角](../../docs/PRD-v2-Agent/story-04-multi-lens.md) 的「舆情热度」维度。**本域是四域中风险最高者**，三项特殊性必须正面处置。

- **表组按实体分两表**：
  - `sentiment_qa`——**投资者问答**（`code` / `market` / `question` / `answer` / `answerer` / `ask_time` / `file_path` / `source_id`）；正文（问答文本）经 `.1` 的文本承载基件**落文件**
  - `sentiment_hot`——**热榜 / 人气榜**（`code` / `rank` / `snapshot_at` / `source_id`）；**独立实体，与问答非同源同义**
- **双市并行互补（非主备）**：深市走**互动易**、沪市走**上证e互动**——两源**同语义、按市场分片**，故**同表**分片（[D-030](../决策日志.md) 的业务键级单一事实源在此应读作「每个 `(code, question, ask_time)` 只由一条源产生」；`Q-003` 决议）。**必须核实互动易是否确实只覆盖深市**（外部信源自述沪市返回 0 条），若不成立则调整分片口径
- **易腐数据**：热榜是「此刻」排名、**历史有限**，**不进档案型新鲜度契约**——其陈旧判据与公告类**档案型文本**（[D-031](../决策日志.md) / [05 不可逆缺口](../../docs/数据库设计-BaoStock数据层/05-同步策略与新鲜度契约.md)）不同，须各自登记
- **风险**：本域**无官方备胎**（四域中唯一「主备皆抓」），且舆情是「易腐」的——覆盖缺口会被误读为「无舆情」

## 验收标准（Given-When-Then，从 Story 抄）

（④ 对齐定稿；实现与机器可查证据见 `tests/l0/`）
  - GWT-1 双市可查：Given 一次同步，When 按代码查问答，Then 深市与沪市记录均可读、带 `market` 分片标注
  - GWT-2 两实体不混：Given 同步后，When 查问答与热榜，Then 两表各自可查（热榜**不进**问答表）
  - GWT-3 易腐数据正确降级：Given 热榜快照过期，When 消费，Then 走**易腐**判据（而非档案型的新鲜度判据），且不冒充历史
  - GWT-4 正文两段同源同现：Given 一条问答，When 查正文，Then 文件与表行一致；缺一则分别为损坏 / 孤儿（不静默）
  - GWT-5 覆盖缺口显式：Given 某市场源不可用，When 查询，Then 能区分「该市场无记录」与「该市场数据缺失」

## 假设与前提

- A1 互动易**只覆盖深市**（其自述沪市返回 0 条）——故深市走互动易、沪市走上证e互动，二者**并行互补而非主备** / 若错（互动易实为全市）：沪市数据会重复写入（`market` 列可辨，去重靠 `qa_id` 业务键）/ 验证：GWT-1 两市分片标注正确。
- A2 未回复（`answer=NULL`）是**合法态**，不是缺失——不因此丢弃该行 / 若错（只留有回复的）：会系统性漏掉「公司尚未回应」这一**风险信号** / 验证：GWT-1「未回复也成行」。
- A3 热度榜为**易腐**数据：`snapshot` 模式、**无水位**、**不判「陈旧」**（过期即不可用）；且**不**进档案型判据 / 若错（按档案型处理）：会把「此刻排名过期」误报为「历史缺口」/ 验证：GWT-3（mode/watermark/archival 三向断言）。
- A4 快照时刻取**微秒**精度——`snapshot` 模式语义是「每次追加新快照、历史不动」，秒级会让同秒两次扫描坍缩 / 若错：监控频率高于 1Hz 时丢快照 / 验证：GWT-3「两次运行 → 两行」。
- A5 某市源不可用与该市「无记录」**必须可区分** / 若错：覆盖缺口被误读为「无舆情」（最危险的失败模式）/ 验证：GWT-5 双任务状态 + `freshness_verdict` 点名失败任务。
