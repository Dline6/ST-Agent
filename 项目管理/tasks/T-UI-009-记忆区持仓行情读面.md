# T-UI-009 · 记忆区持仓行情读面

> **分组节点**（命中[拆分触发](../工作流.md)「涉及 2 个及以上架构层」「单次预计会话轮次 > 20」）。交付由两叶承接，本节与下列各节只记**批次口径**，逐叶验收见各叶文件。
>
> **来源**：[13-visual-design.md §10](../../docs/PRD-v2-Agent/13-visual-design.md) 的两条「待补的视觉基线」——`--up` / `--down` / `--flat` 与 `--font-num` 在两处**无真实消费方**（`--up`/`--down`/`--flat` 在 `app.css` 里零引用；`--font-num` 只被 `.payload` 这个 JSON 转储框用上，不是行情读面）。负责人 2026-10-09 拍定：先把这两条基线补成**有真消费方**的形态，再推 [`T-UI-006`](T-UI-006-IA补章受控自主分区与页面Flow.md)（[D-105](../决策日志.md)）。

## 目标

让那两枚令牌**真的有消费方**：在记忆区落一条持仓 / 关注行情读面，涨跌恒由三路冗余编码表达（颜色 + ▲▼ + 数值符号），数字列右对齐等宽。

批次口径三条：

1. **原语先于页面**——表格的**列级词汇**（`text` / `number` / `direction`）与涨跌编码由**渲染件**统一产出，产出方只给数值。这样「颜色与符号恒同时出现」是**结构**上不可分离的，而不是一条要靠各页自觉的纪律（规范 §2.2 的判据）。
2. **顺带修一处实测缺陷**——`table` 的生产产出方（6 处）与渲染件**形状不一致**：产出方给位置形状（`columns: [字符串]` / `rows: [[…]]`），渲染件读的是键控形状（`column.label` / `row[column.key]`）。**实机实测（Edge · WebView2 同引擎）：生产的表表头与单元格全为空**，只有 dev 走查样本（键控形状）正常。缺陷由 [`.1`](T-UI-009.1-表格槽词汇与数字涨跌渲染原语.md) 承接。
3. **真消费方是记忆区**——持仓 / 关注取自 L2 记忆的 `attention` 节点，行情取自 L0 的最新日线视图；**不改** [11-sitemap](../../docs/PRD-v2-Agent/11-sitemap.md) 的页面集（记忆区本就有「列表视图」），**不动** L5 日报模型。由 [`.2`](T-UI-009.2-记忆区持仓行情读面页与鸭子端口.md) 承接。

## 本批的边界（不越界）

- **不改 [01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 的字段表与组件类型枚举**——`table` 早已登记且早已实现，本批只是把它的**槽形状**在产出方与渲染方之间对齐，并给列加一个 `kind` 键。槽词汇表按 [D-064](../决策日志.md) 本就由两侧共同约定（机器可读副本在 `ui/registry.py` 的 `REQUIRED_SLOTS`），不改契约节。
- **不新增 L1 Skill**——行情取数由组合根经既有鸭子类型 `market_query`（`MarketDb.query`）读 `v_k_line_latest`；「取数只有一条通道」约束的是 **L1 执行器**（[`common.py`](../../src/st_agent/l1/skills/official/common.py) 的模块文档），组合根装配面不在此列。此假设在 [`.2`](T-UI-009.2-记忆区持仓行情读面页与鸭子端口.md) 的 `## 假设与前提` 里逐条表态。
- **不做图谱视图 / 时间线视图 / 偏好画像卡**——记忆区整区的其余读面归 M6 后续功能面叶；本批只落**首个读面**（持仓 / 关注行情）。
- **不引 npm / 打包器 / 框架**——[D-063](../决策日志.md) ① 零构建不动。

## 假设与前提

- **A1 · 「行情读面」是记忆区的首个读面，不改 IA**（2026-10-09 ④ 对齐前经负责人选定，见 [D-105](../决策日志.md) ③）：前提是 [11-sitemap](../../docs/PRD-v2-Agent/11-sitemap.md) §2 记忆区本就含「列表视图」，持仓 / 关注读面可挂在其下（持仓摘要原落 Chat 首页的上下文卡片六段之一，本批为其另给一个**可独立寻址**的读面）。若错（[`T-UI-006`](T-UI-006-IA补章受控自主分区与页面Flow.md) 的 IA 补章要改记忆区页集）→ 返工面＝页面归属与路径调整（读面与端点本身不返工）。**验证方式**：[`T-UI-006`](T-UI-006-IA补章受控自主分区与页面Flow.md) 收工时复核 `/memory` 与补章后的页集不冲突。
- **A2 · 两叶的切分沿「原语 / 消费方」而非「后端 / 前端」**：前提是原语（表格词汇 + 涨跌编码 + 视觉基线 + 守卫）**与页面结构无关**，怎么建都不返工；会返工的只有端口与页。若错（原语需随页面形态调整）→ 返工面＝`.1` 的词汇重定，则 `.2` 同批跟改。**验证方式**：`.1` 的 GWT 全部可在**不建任何页面**的前提下验完（走查面 + 守卫）。
- **A3 · 修形状缺陷属「实现」而非「改契约」**：前提是 [01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 只登记**通用槽形状**（`slots` 是「槽名 → 已解析的 JSON 值」），`table` 的列 / 行内部形状按 [D-064](../决策日志.md) 属两侧共同约定，不属契约节。若错（被判定为契约变更）→ 返工面＝按[铁律 8](../工程宪法.md) 先改 [01 §12](../../docs/技术架构-v2/01-平台共享契约.md) 再改码，多一轮文档先行。**验证方式**：`tests/contracts` 不动即绿。
