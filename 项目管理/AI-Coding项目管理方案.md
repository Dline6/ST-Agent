# ST Agent · AI Coding 项目管理方案（单人 + AI Agent）

> 定位：把已有的「PRD Story（需求真相源）+ 技术架构（设计真相源）+ 数据库设计」推进到代码的**执行与追踪层**。
> 本层不复制、不改写规格，只做增量：一页宪法 + 一份派生账本 + 三本日志 + 一套工作流 + 一份入库规范 + 一个账本生成器 + 一目录任务文件。
> 本文为**方案设计说明（理由）**；日常操作的权威文件是同目录的 [工程宪法.md](工程宪法.md) / [工作流.md](工作流.md) / [README.md](README.md)。

## 0. 三条设计红线

1. **真相源唯一，绝不双写**。Story = What，架构 = How（都在 `docs/`），任务状态 = `tasks/*.md`；账本、就绪集、完成度全部由 `tools/render_ledger.py` **生成**，不手改。
2. **纯本地 Markdown、可 git、无 SaaS 锁定**。与产品自身「本地优先 / 数据主权」主张自洽（dogfooding）。
3. **无留痕不算完成**。任务 `status→done` 之前，[执行日志.md](执行日志.md) 必须有对应条目；涉及决策同步 [决策日志.md](决策日志.md)。追踪性优先于交付速度。

## 2. 工程宪法（constitution）

[工程宪法.md](工程宪法.md) 把架构 README 的 6 条全局硬约束升级为 Agent 编码时必须遵守、且不得违背的铁律，并补 **5 条工程铁律（合计 11 条）**：

**产品铁律（1–6，不可妥协，违背即任务失败）**：本地优先 / 中性视角（禁拟人化）/ 可配置性优先（双通道 + 可导出版本化）/ 多视角分歧并列（不合并、不给统一建议）/ 可解释（结论可追溯推理链）/ 共同演化透明（自动变更显式告知 + 可回滚）。

**工程铁律（7–11，架构与流程红线）**：

7. 层间只允许向下依赖，禁止反向调用与循环依赖。
8. 跨层接口变更：先改 `docs/技术架构-v2/01-平台共享契约.md` → 同步各层架构文档 → 最后改代码。
9. **文档一致性**——PRD 需求变更时受影响架构文档同批修订；任务状态只改 `tasks/T-*.md`，再跑 `render` 刷新派生账本（勿手改账本）；全项目相对链接断链校验通过。
10. **无留痕不关闭**——任务 `status→done` 前必须完成执行日志登记（含「验证」行）；涉及选型登记决策日志；遇未决登记并转 `blocked`。
11. **开工先对齐**——动手实现前（工作流 ④）Agent 必须向人复述「要交付什么 / 验收怎么算过 / 打算怎么做 / 有哪些假设或未决」并获确认，对齐结论记入执行日志；未对齐不得实现。

## 3. 任务体系（可递归拆分）

### 3.1 三级模型
- **Epic**（Story 级，不建独立文件）：账本按层分组，对应 `story-NN`。
- **Task**（`T-L0-001`）：可执行单元，也是拆分入口。
- **Sub-task**（叶子 `T-L0-001.1`）：**唯一喂给 Agent 开工的单位**。

ID 命名：`T-<层>-<三位序号>[.<子序号>]*-<中文slug>.md`，层 ∈ {SC, L0–L6, ECO, INT}；子序号嵌套建议 ≤ 2 层。INT 为**里程碑集成关卡**（2026-09-26 起落地，见 §4.1）。

### 3.2 什么时候必须拆分（任一命中即拆）
GWT > 5 · 涉及 ≥ 2 契约小节/架构层 · 跨 spec+plan 的一次性改动 · 预计会话轮次 > 20 · 中途新增需独立记录的决策。拆分在**开工 ③ 阶段**做，不预先铺满账本。

### 3.3 父任务状态派生（禁止手写）
父 `status` 由 children 聚合：全 done→done / 任一 blocked→blocked / 任一 doing→doing / 其余→todo。父 `depends_on` = children 并集去掉指向自身子树的边。**由 `tools/render_ledger.py render`（或 `status`）自动重算**，人不手填。

### 3.4 任务文件 frontmatter（真相源在 `tasks/T-*.md`，账本据此渲染）

| 字段 | 含义 | 示例 |
|---|---|---|
| `id` / `parent` | 层级号 / 上级（顶层留空） | `T-L0-001` / 空 |
| `title` | 一句话任务 | 存储分区落盘加密 |
| `story` | 回指 PRD（文件相对 → `../../docs/`） | `../../docs/PRD-v2-Agent/story-05-local-first.md` |
| `arch_link` | 账本渲染用的契约链接（文件相对；render 改写为 `../docs` 显示） | `[02 §2](../../docs/技术架构-v2/02-L0-本地优先基座.md)` |
| `priority` / `milestone` | P0/P1/P2 · M0–M4 | P0 · M0 |
| `depends_on` / `status` | 前置 id 列表 · todo/doing/blocked/done | `[T-SC-001]` · todo |
| `decisions` / `verify` | 引用 D-NNN · done 时填证据+日志锚点 | `[D-007]` · `日志 …· pytest 22/22` |

正文五块：**目标 / 验收标准（GWT，④ 对齐时从 Story 补） / 接口面（跨任务输入输出交接点） / 假设与前提 / 涉及契约**。实现细节不进文档，留给代码、commit 与执行日志。

### 3.5 账本降级为派生视图 + 里程碑归档（防膨胀）

[任务账本.md](任务账本.md) **不手工维护**——由 `tools/render_ledger.py` 从 `tasks/*.md` frontmatter 生成的只读视图（表格 / 完成度 / 就绪集全自动）。任务信息只在 `tasks/T-*.md` 一处写，改状态后跑 `render` 刷新。防膨胀三条曲线与对策：

| 膨胀来源 | 对策 |
|---|---|
| 拆叶子使任务变多 | 账本只渲染**活跃**（status≠done）任务；叶子在开工 ③ 才拆 |
| done 永久堆在表里 | 里程碑**全部 done** 时 `archive` 把整批文件移入 `tasks/done/<Mn>/`，账本塌缩成「✅ Mn done/N」 |
| 单文件持续增多 | `tasks/` 顶层只放进行中的工作，已完成沉到 `tasks/done/` |

命令：`render`（刷新账本 + 派生父状态）· `status`（打印就绪集）· `archive` / `--dry`（归档满员里程碑）。

## 4. 任务执行流程（每个叶子任务跑一遍）

```
① Spec    ← 读 Story 验收标准（What，只读）
② Plan    ← 读对应架构层契约（How，只读）
③ Task    ← 建/更新 tasks/T-*.md（真相源）；按 §3.2 判定拆分；填 depends_on；账本行由 render 生成
④ Align   ← 开工闸门：向人复述意图并获确认后才动手（不可跳过）
⑤ Implement ← 只喂「宪法 + 该任务文件（含其「接口面」交接点）+ 它链接到的契约小节 + 未决 open 段」给 Agent
⑥ Verify & Log ← 跑测试 + 断链校验 → 写执行日志（有决策则同步决策日志）→ 任务文件 status=done → 跑 render（派生父状态 + 刷新账本）
⑦ Sync    ← 若触发契约/架构变更：先改 01 平台契约 → 同步架构文档 → 更新受影响任务 + 记决策日志
```

**④ 意图对齐**：Agent 读完 Spec/Plan、建好任务后、写代码前，向人复述「交付什么 / 验收怎么算过 / 接口面（输入从哪来、输出去哪）/ 打算怎么做 / 有哪些假设或未决」，人回「对」才进 ⑤；有 open 未决先登记 [阻塞与未决.md](阻塞与未决.md) 并转 `blocked`。对齐结论写进任务文件两节（`## 接口面`、`## 假设与前提`）+ 执行日志一行。

**接口面（2026-09-26 落地）**：任务正文第五块，逐条点名「输入＝上游任务 id + 具体 API/落盘位置」「输出＝本任务交付的公共 API 与落盘位置」。第 ⑤ 步是受限上下文（不喂兄弟任务代码），接口面即该上下文里唯一的跨任务交接点；`doing` 起留占位即由 `verify_docs.py` 检查 6 判失败。

### 4.1 集成关卡（跨任务装配验证）

单任务 GWT 全是注入 Fake 的单测——装配关系与跨层数据流是它们集体覆盖不到的部分。故每个有任务的里程碑配**一个** `T-INT-NNN` 关卡任务（P0、`parent: null`、`milestone` 同所辖里程碑）：装配该里程碑全部交付物跑一次端到端，验收取自 [00-架构总览 §5 端到端数据流](../docs/技术架构-v2/00-架构总览.md)。`depends_on` 覆盖本里程碑全部叶子任务并与上一关卡串联（`verify_docs.py` 检查 7 把关）；里程碑 `archive` 与打 tag 前它必须 `done`。真实网络/长跑路径标 `@pytest.mark.live` 放 `tests/live/`，默认排除。

**⑥ 是硬闸门**：没有执行日志记录 = 不允许 done。冷启动实现顺序 = `01 契约 → L0 → L1 → L2 → L3 → L4 → L5 → L6 → ECO`。

## 5. 调度规则（AI 如何选下一个任务）

1. 就绪集 = `status=todo` 且 `depends_on` 全 `done` 且父链无 `blocked` 的**叶子任务**（`render`/`status` 自动算）。
2. 排序：`priority`（P0>P1>P2）→ 层号升序 → id 字典序，取队首。
3. 单人串行即按此推进；将来提速，就绪集内任务天然可并行（开 git worktree），无需改结构。
4. 收工顺序：任务文件置 `doing` → 读 Spec/Plan → ④ 对齐 → 干活 → 写日志 → 任务文件置 `done` → 跑 `render`。

## 6. 追踪机制（三本日志，各管一件事）

### 6.1 执行日志 [执行日志.md](执行日志.md) — 每次做了什么
append-only。标题 `## [T-<id>] <ISO时间> — <短标题> · <status>`；每条必含 **验证** 行；有 commit 写 hash；「遗留」若产生新任务，同步建 `tasks/` 文件（账本下次 render 出现）。超 500 条按年归档至 `执行日志/`。

### 6.2 决策日志 [决策日志.md](决策日志.md) — 为什么这么做
精简 ADR。ID 全局递增 `D-NNN`，任务用 `decisions:[D-NNN]` 引用。决策变更**不覆盖旧条目**：追加 `D-NNN` + `supersedes: D-MMM`，旧条目标 `[已废弃，见 D-NNN]`。登记后触发 ⑦ 同步架构文档。

### 6.3 阻塞与未决 [阻塞与未决.md](阻塞与未决.md) — 别猜
状态 `open` / `decided (D-NNN)` / `wontfix`。Agent 遇 open 未决立即停手、任务转 `blocked` 并登记，等人回填（呼应架构 L4 `blind_spots` 理念）。`decided` 时产生一条决策日志引用回来。

## 7. 里程碑与进度快照（人可感知视角）

账本顶部的「里程碑视图」由 `render` 自动聚合（完成度实时统计，满员即归档）：

| 里程碑 | 目标 | 覆盖层 |
|---|---|---|
| M0 · 骨架打通 | 平台契约 + L0 基座 + L1 能力池最小闭环 | SC / L0 / L1 |
| M1 · 首次可对话 | Chat 主入口打通到 L2 记忆读写 | L2 / L3 |
| M2 · 决策可用（MVP） | L4 多视角中性推理闭环 | L4 |
| M3 · 主动服务（P1） | L5 Ambient Delivery 投递闭环 | L5 |
| M4 · 自演进与生态（P2） | L6 反思演进 + 生态分享 | L6 / ECO |

里程碑是每个任务的 `milestone:` 视图字段（非新对象）。MVP = 走到 M2 完成；M3/M4 为增强。每个里程碑另配一个集成关卡任务（`T-INT-*`，见 §4.1）：**里程碑完成 = 该里程碑全部任务 done 且其关卡任务 done**。

## 8. Agent 冷启动指令（`CLAUDE.md` + `项目管理/README.md`）

新会话不预设记忆，靠固定六段开场（根 `CLAUDE.md` 与 `项目管理/README.md` 各放一份、口径一致）：

```
1. CLAUDE.md（根）                  — 项目地图 + 硬规则
2. 项目管理/工程宪法.md            — 11 条不可违背铁律
3. 项目管理/任务账本.md            — 派生的当前进度 + 就绪集
4. 项目管理/执行日志.md 末尾 5 条   — 最近上下文
5. 项目管理/决策日志.md 末尾 3 条   — 近期决策
6. 项目管理/阻塞与未决.md open 段   — 别猜的问题
```

然后从就绪叶子任务挑最高优先级者，按 §4 流程推进；开工前必过 ④ 对齐，遇 §3.2 触发即拆，遇 open 未决即停手。这一步让**任何失忆的新 AI 会话都在 5 分钟内接上主线**。
