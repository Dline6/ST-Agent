# 产品概要与问题域

> 本文档定义产品是什么、解决什么问题、市场空白在哪、以及本 PRD 故意不解决什么。
> 设计原则见 [03-goals.md](03-goals.md)；用户画像见 [02-personas.md](02-personas.md)；功能范围见 [README.md](README.md) 索引的 Story 列表。

## 产品概要

本项目构建一个**本地优先、对话式、可自演进的 ST 股票投资决策副驾**。产品内核不是"预置多个 Agent"，而是一个 **Agent Runtime**：

- 底层由**本地 Skills + MCP Hub** 组成能力池（[story-02](story-02-skills-runtime.md)、[story-08](story-08-mcp-hub.md)）
- 中层由**个人投资记忆图谱（Memory Graph）** 承载关于用户的一切认知（[story-03](story-03-memory-graph.md)）
- 交互层由 **Chat-as-OS** 作为主入口——配置即对话、看板按需生成（[story-01](story-01-chat-as-os.md)）
- 复杂决策场景走**多视角推理（Multi-Lens Deliberation）**，严格中性、无拟人化，输出分歧图而非统一结论（[story-04](story-04-multi-lens.md)）
- 触达层由 **Ambient Delivery** 按用户的注意力节奏主动服务（[story-07](story-07-ambient-delivery.md)）
- 最上层由 **Reflection Loop** 让整个系统随时间自我演进（[story-09](story-09-reflection-loop.md)）
- 一切建立在**本地优先基座**上：数据、记忆、配置全部归用户所有（[story-05](story-05-local-first.md)）

它服务的是**缺乏专业分析工具、又需要处理高消息面敏感度标的、且明确拒绝把持仓与决策数据托管到云端的个人投资者**。

**产品的成功形态**：用户第一次打开产品，用一段话表达完自己的偏好，就能立刻得到贴合自己的分析；三个月后，产品比任何通用工具都更懂他，且这份"懂"完全归他所有、可导出、可删除、可离线运行。

## 问题（用户视角）

ST 股票对消息面极度敏感——价格波动与公告信息、政策导向、市场情绪强关联。一个持有或关注 ST 股的个人投资者，每天要面对分散在各交易所公告、财报、龙虎榜、舆情中的海量信息，靠人工既读不过来、也读不懂"这条公告意味着什么风险/机会"，更难持续盯盘。

**六个核心痛点**：

1. **风险识别困难**：退市、流动性枯竭等风险信号隐藏在公告细节中，散户读不懂也来不及读。
2. **消息分散滞后**：信息散落在交易所、财报、龙虎榜、社群中，人工聚合成本高、必然滞后。
3. **个性化分析不足**：现有工具千人一面，无法按个人风格、板块偏好、风险阈值定制。
4. **工具不"懂我"**：即使提供"个性化配置"，也只是让用户填表单参数；用户的投资 thesis、风险偏好演化、犯过的错、认知偏差，工具从来不知道，也无法沉淀。
5. **数据主权焦虑**：把持仓、决策、心理弱点托管到云端 SaaS，用户始终不放心；一旦平台倒闭或涨价，多年积累归零。
6. **黑盒结论疲劳**：用户不满足于"系统告诉我买/卖"，想看到"系统是怎么想的"、"有哪些不同视角"、"分歧在哪里"，但现有工具只给结论不给推理过程。

## 当前 workaround（用户今天怎么解决）

- 用信息终端看数据和指标——只做展示、不做研判、更不懂"我"；
- 用量化平台做策略回测——门槛高、无法结合非结构化消息、数据要上传；
- 靠人工盯公告 + 加社群——滞后、易漏、噪音大；
- 部分进阶用户开始用通用 AI（ChatGPT / Claude）辅助研判，但每次都要重新解释自己的偏好、无法沉淀、没有主动服务、无法接入实时数据源。

## 为什么是现在

1. **AI Native 产品理念成熟**：Agent 产品已从"AI 功能叠加"演进到"Agent Runtime 为内核"，Chat-as-OS / Skills+MCP / Memory-as-Cognition / Proactive Ambient / Self-Evolving 五大范式确立。
2. **Skills + MCP 生态标准化**：能力原子化、跨平台可组合，用户可挂载自己的私有数据源；产品能力可以随生态自然增长。
3. **本地推理可行性**：中小模型在桌面端可得，敏感数据可完全留在本地；即使调用云端 LLM，也可由用户自带 API Key，产品方不接触用户数据。
4. **决策辅助的合规压力提升**：监管对"荐股""统一结论"越来越严，多视角分歧呈现反而是合规友好形态。

## 竞品格局与空白

| 维度 | 通用资管终端 | 国内信息终端 | 通用 AI 助手 | 量化平台 | **本产品** |
|---|---|---|---|---|---|
| 数据主权 | 云端 | 云端 | 云端 | 云端 | **本地优先，用户完全掌控** |
| 主入口 | 看板 | 看板 | Chat | 代码 | **Chat + 按需生成看板** |
| 个性化 | 弱（表单） | 弱（表单） | 弱（无持久记忆） | 中（策略参数） | **强（Memory Graph 沉淀）** |
| 推理透明度 | 无 | 无 | 中（有解释但不结构化） | 低（代码即真相） | **高（多视角分歧图 + 完整推理链）** |
| 主动服务 | 无 | 弱（预设告警） | 无 | 无 | **强（Ambient + 注意力预算）** |
| 自演进 | 无 | 无 | 无 | 无 | **有（Reflection Loop）** |
| 能力扩展 | 封闭 | 封闭 | 半开放（插件） | 半开放（SDK） | **开放（Skills + MCP）** |
| ST 专项 | 无 | 弱 | 无 | 中 | **强** |

**本产品填的空白**：**本地优先 + 对话式主入口 + 个人记忆图谱 + 多视角中性推理 + 主动服务 + 自演进 + ST 专项**的完整交叉空白——不是又一个数据终端，也不是套壳通用 AI，而是"真正属于用户自己、越用越懂他、可离线可携带"的投资副驾。

## 本 PRD 不解决什么（out of scope）

- 不做券商级实盘自动下单/交易执行（仅决策辅助与预警，不接管账户资金）；
- 不做 ST 之外的全市场行情软件（ST 是首个验证场景，范式可迁移但本版不铺开）；
- 不做通用资产管理组合（面向个人投资者的 ST 决策支持，非机构资管系统）；
- 不做云端多用户协同（本地优先原则下，协同只通过用户主动导出的 Skill/Memory 片段实现，见 [story-10](story-10-skill-sharing.md)）；
- 不做集中式 Skill 商店服务端（Skill 分享通过本地文件导入导出，不做中央注册中心）；
- 不做拟人化 Agent 角色（严格中性视角，不给 Agent 起名字/性格/情感表达，见 [story-04](story-04-multi-lens.md)）；
- 产品成效的量化度量（KPI、埋点、回测目标值）不在本 PRD 内，另立《指标与度量方案》。
