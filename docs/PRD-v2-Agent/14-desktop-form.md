# 桌面形态规范（表现层）

> **状态：已定稿 · §1–§12 为生效口径，工程实现随 P0–P4 分批落地。** 本文件**不由测试断言**
> （它的落地件是 `tokens.css` / `app.css` / 各页面 JS，以及 [13 册](13-visual-design.md) 与
> [11 册](11-sitemap.md) 各自的那两个 UI 守卫）；它取代 13 册的 §2.1 令牌值、§3 字号、
> §4 间距口径、§9 对比度细则，并修订 11 册的 §1 全局形态与 §2.2 导航模型。
>
> **起因**：现行表现层实质是「在浏览器里打开的 736px 单栏文档站」——1440×900 窗口下主区只占
> **16.4%** 面积，无侧栏、无快捷键、无真对话框、无窗口状态记忆、无右键菜单，且导航与页面标题
> 会随页面滚走（实测 `/memory` 滚到底后 `.nav` 的 `top = -66px`）。产品最终产物是**桌面应用**，
> 故按桌面形态重估。
>
> **本文的授权口径**：用户明示「不必遵守以前的 UI 设计约定」。因此
> [D-104](../../项目管理/决策日志.md) 的视觉方向、13 册 §2.1 的令牌总表、§4 的间距口径、
> §9 的对比度细则**在本文范围内视为可被取代**。
> **但以下不被取代**——它们不是 UI 约定，是产品铁律：
> [铁律 2 严格中性](../../项目管理/工程宪法.md)（不拟人化）、
> [铁律 4 分歧并列不合并](../../项目管理/工程宪法.md)、
> [契约 9 中性表达](10-platform-capabilities.md)、
> [D-063](../../项目管理/决策日志.md) 的**零构建前端**（本地优先取向，见 §12.1）。
>
> **待决项**见 §16。

## 1 形态：窗口是一等公民

| 项 | 目标 |
|---|---|
| 交付面 | **桌面应用**（pywebview + 系统 WebView）为产品面；浏览器面降级为**开发 / CI 面**，不再是默认启动路径 |
| 默认窗口 | 1440×900；**最小 1024×640**（低于此宽度进折叠态：左栏收成 48px 图标条，右栏自动收起） |
| 窗口状态 | 记忆尺寸 / 位置 / 最大化态，跨会话恢复（`window.py:48` 现为 `create_window(title, url)`，无任何窗口参数） |
| 标题栏 | 用**原生标题栏**，不自绘。标题 = `<分区> · <对象> — ST Agent`（现为常量 `ST Agent`，且全库无 `document.title` 赋值） |
| 命令入径 | 不自绘菜单栏（命令面窄）。改为 **命令栏 + 完整快捷键表 + 命令面板（`Ctrl+K`）** 三件套 |
| 关闭语义 | 关窗 = 收进托盘（保留现行 `closing → False`），但**首次关闭必须有一次显式说明**（现行无任何提示，用户会以为已退出） |
| 托盘 | 图标提供 16 / 32 / 256 三档资源并适配深浅主题；菜单：显示主窗口 / 新建窗口 / **主动触达设置…**（打开 `/delivery?view=config`）/ 开机自启 / 退出 |
| 多窗口 | 至少支持「主窗口 + 单个附属窗口」，用于把看板 / 图表 / 对比栏拖出去并排看 |
| 安装包 | 需安装包 + 代码签名（`T-UI-019` / `T-UI-020`，未做）；否则 SmartScreen 直接拦 |

## 2 骨架：三栏 + 常驻外壳

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 命令栏  持仓与关注 › 图谱          [命令面板 Ctrl+K]      ⟳  离线/同步态   │  ← 高 40px，常驻
├──────────┬────────────────────────────────────────────┬──────────────────┤
│ 分区导航  │  摘要锚点（sticky）                          │  Chat 伴随栏      │
│          │  总值 · 当日 · 累计 · 最后更新                │  （可折叠/可拖宽） │
│ 总览      ├────────────────────────────────────────────┤                  │
│ 工作区    │                                            │  对话流           │
│ 持仓与关注 │  主区（页面）                               │  独立滚动         │
│ 能力 ▾    │  可再分栏（左/右两栏）                       │                  │
│   Skill库 │  独立滚动                                   │  ┌────────────┐  │
│   Studio  │                                            │  │ 输入面      │  │
│   MCP Hub │                                            │  └────────────┘  │
│  导入导出  │                                            │                  │
│ 推理      │                                            │                  │
│ 触达      │                                            │                  │
│ 反思      │                                            │                  │
│ 设置      │                                            │                  │
├──────────┴────────────────────────────────────────────┴──────────────────┤
│ 状态栏  本机回环 · 数据源 baoStock · 最后同步 18:42 · 网络活动 · 任务队列   │  ← 高 24px，常驻
└──────────────────────────────────────────────────────────────────────────┘
     200–240px                自适应（≥480px）                  320–420px
```

**三条硬规则**：

1. **外壳永不滚动。** 滚动的只有主区、左栏、右栏三个**各自独立**的滚动区。
   （现状：全站唯一滚动容器是文档本身，`sticky`/`fixed` 元素各 **0** 个，`app.css` 里
   `position:` 出现 **0** 次——不是"没用 sticky"，是这个样式表没有定位能力。）
2. **任何栏位都可折叠 / 可拖宽**，宽度记忆。
3. **主区可分栏**，且分栏是**一等能力**：铁律 4 的「分歧并列」天然就是两栏/多栏，
   不必再靠"卡片并排挤在一栏里"模拟。

**摘要锚点**（主区顶部 sticky 条）是新增的必备件：投资类界面的第一原则是最重要的数字
一屏可见、不滚动、不心算。现状把这些数字放在会滚走的普通块里。

## 3 令牌体系

### 3.1 间距：从"组件局部调参"改为**受控 8 档**

现状诊断：`tokens.css` 里**没有任何间距令牌**，`app.css` 实际用了 **18 个**不同的边距/内距值，
其中 **11 个不在 4px 网格上**（2.4 / 3.2 / 4.8 / 5.6 / 6.4 / 7.2 / 8.8 / 9.6 / 11.2 / 12.8 / 14.4px）。
规范自称 4px 基线，实际未落——因为"不设令牌、只锁同层级同间距"这条口径无法机器校验。

```css
--space-1:  4px;   --space-5: 20px;
--space-2:  8px;   --space-6: 24px;
--space-3: 12px;   --space-7: 32px;
--space-4: 16px;   --space-8: 48px;   /* 另 --space-9: 64px 仅用于空态留白 */
```

**规则**：`app.css` 及页面内**不得出现裸间距值**；一律消费令牌。由测试断言（见 §15）。

### 3.2 密度双档

```css
[data-density="comfortable"] { --row-h: 32px; --cell-y: 8px;  --cell-x: 12px; }
[data-density="compact"]     { --row-h: 24px; --cell-y: 4px;  --cell-x: 8px;  }
```

- **comfortable** 是默认（表单、报告、设置、空态）。
- **compact** 用于行数多的读面（持仓表、执行日志、推送历史、网络活动）。
- 双档是**同一套组件**换变量，不是两套组件；用户可在设置里选默认，也可在具体表上临时切。

### 3.3 字号：从自造 5 档改为**对齐平台 ramp 的 9 档**

现状诊断：12.8 / 14.08 / 16 / 17.6 / 22.4px，比例 1.10 / 1.136 / 1.10 / 1.27 无规律，
且全部脱离平台 ramp（Windows 是 12·14·18·20·28·40·68，最小 14px semibold / 12px regular）。
正文 12.8px 对中文偏小。

| 令牌 | 字号/行高 | 用途 |
|---|---|---|
| `--text-caption` | 12 / 16，600 | 角标、密表表头、徽标 |
| `--text-body-sm` | 13 / 18 | 密表单元格、元信息 |
| `--text-body` | **14 / 20** | **界面默认正文** |
| `--text-body-lg` | 16 / 24 | 长文阅读面（反思报告、日报正文） |
| `--text-subtitle` | 18 / 24，600 | 卡标题、段标题 |
| `--text-title` | 20 / 28，600 | **页面标题** |
| `--text-title-lg` | 28 / 36，600 | 总览与空态的大标题 |
| `--text-metric` | 28 / 32，600 + `--font-num` | 指标块数字 |
| `--text-metric-lg` | 40 / 48，600 + `--font-num` | 摘要锚点的主指标 |

- **行高不再全局 1.7**：界面 chrome 用 1.33–1.43（随档给定），长文阅读面才用 1.5–1.6。
  （现状 `--leading: 1.7` 全局套用，16px → 实测 27.2px，连导航项和表格行一起虚胖。）
- **字重只用 400 / 600 两档**（13 册 §3 这条是对的，保留）。标题一律 600。
  现状 `.masthead h1` 等落到浏览器默认 **700**，与自身规范冲突。
- 数字：`--font-num` + `tabular-nums` + 右对齐 + 固定小数位——这条现状做对了，保留。

### 3.4 圆角

```css
--radius-control: 4px;   /* 按钮、输入、下拉、标签页 */
--radius-surface: 8px;   /* 并列卡、段、面板 */
--radius-overlay: 12px;  /* 对话框、浮层、菜单 */
--radius-pill:  999px;   /* 仅徽标/标签，不用于动作控件 */
```

现状 6/8/10 三档与层级绑定但混用（导航 6、主区 10、卡片 8、徽标 999），且 6/10 不属于桌面惯例档位。

## 4 色彩：修正后的令牌表

**改动边界**：只动**不达标**与**互相冲突**的值，其余保留（现有调色方向本身可用）。

### 4.1 结构与墨（含实测对比度）

| 令牌 | 浅色 | 暗色 | 对 `--card` 实测 | 说明 |
|---|---|---|---|---|
| `--bg` | `#fafbfc` | `#131519` | — | 纸底 |
| `--card` | `#ffffff` | `#1c1f25` | — | 面板 |
| `--line` | `#d8dbdf` | `#33383f` | 1.39 / 1.40 | **仅装饰**分隔线（段间、行间） |
| **`--line-strong`（新增）** | `#8a929d` | `#666f7c` | **3.14 / 3.25** | **控件边界**：输入框、按钮、可聚焦控件、分栏拖拽线 |
| `--fg` | `#1b1b1d` | `#e8eaed` | 17.20 / 13.87 | 正文墨 |
| `--fg-muted` | `#5a5f66` | `#a3aab3` | 6.43 / 7.13 | 次要墨（保留） |
| **`--fg-faint`（修正）** | `#6b7280` | `#868d96` | **4.83 / 4.92** | 原 `#8a9099`/`#7c838c` 只有 3.22 / 4.31，**不达 4.5**，却用于 `.num--none`、`.workspace__item-meta`、`.chat__command-source` 等正文级文字 |
| `--accent` | `#24457f` | `#8fb0e8` | 9.41 / 7.59 | 陈述性链接 / 当前项 / 焦点环 |
| `--accent-weak` | `#d3deee` | `#26313f` | — | 见 §4.3 |

**关键判断：`--line-strong` 不要全局替换 `--line`。** 3:1 的灰线相当重，铺满全屏会变成网格噪音。
规则是：**装饰线用 `--line`（可见性是"有"就行），凡是"这个边界不发出来用户就不知道那里能点/能拖/是个控件"的地方，必须用 `--line-strong`。**

这条直接修掉最严重的一处：现行设计的层级**全部**靠 1.39:1 的 1px 线（D-104 明确"不靠阴影"），
等于主要结构装置对低视力用户不可见。

### 4.2 六态（保留语义，只对齐新墨阶）

`--ok` / `--empty` / `--delayed` / `--error` / `--input-error` / `--notice` 语义与"色 + 文字双写"的
口径**全部保留**（这套设计是好的）。仅需保证每档文字在 `--card` 上 ≥ 4.5:1——现有值均已达标
（最低 `--delayed` 浅色 5.93）。

### 4.3 选中 / 悬停底

现状 `--accent-weak` 对 `--card` 只有 **1.17:1**，用作 `.chat__command-button:hover` 背景时
几乎不可见。改为 `#d3deee`（1.36:1）仍偏弱，故**不靠它单独承担"选中"语义**：

- **悬停**：`--accent-weak` 底（弱提示即可）
- **选中 / 当前行**：`--accent-weak` 底 **+ 1px `--accent` 描边**（或左侧 2px `--accent` 竖条）
- 理由：底色差在浅暗两套主题下都做不稳 3:1，而描边可以。

### 4.4 涨跌：保留 A 股惯例，修掉"同值冲突"

保留红涨绿跌（中文用户零学习成本，且与本产品市场语汇同源）与**三路冗余**
（颜色 + ▲▼ + 带符号数值）——这条做得对。

要修的是一处硬冲突（实测）：

| 暗色下 | 对比 |
|---|---|
| `--down #6fcf97` vs `--ok #6fcf97` | **1.00:1（完全同值）** |
| `--up #e08a80` vs `--error #f08a8a` | **1.07:1（几乎不可分）** |

提案：

| 令牌 | 浅色 | 暗色 | 对 `--card` |
|---|---|---|---|
| `--up` | `#b23a30` | `#e08a80` | 5.93 / 6.38 |
| `--down` | **`#0f6b6b`（青绿）** | **`#5fbfb2`（青绿）** | 6.30 / 7.53 |
| `--flat` | `#5a5f66` | `#a3aab3` | 保留 |

**诚实说明一个边界**：换色**不能**解决"涨跌色与状态色在色觉上接近"的问题——实测换完之后
`down-teal` 与 `ok` 之间仍只有 1.02 / 1.15:1，`up` 与 `error` 仍只有 1.25 / 1.07:1。
真正承担区分的是**冗余编码**（方向带 ▲▼、状态带文字）。所以本节的交付只有两条：
① 去掉**完全同值**这一处硬伤；② 补一条明文规则——**方向与状态不得只靠颜色区分，且两者不得落在同一单元格内只以颜色呈现**。

## 5 层级与浮层（现行完全缺失）

现状：`box-shadow` **0** 处、`transition` **0** 处、`z-index` 令牌 **0** 个、`position:` **0** 处。
后果不是"朴素"，而是**没有 elevation 模型**——对话框、下拉、菜单、toast 这些浮层**做不出来**，
所以现在所有"对话框"都被实现成页内块（`role="dialog"` / `aria-modal` 各 **0** 处）。

```css
--z-content: 0;    --z-sticky: 10;   --z-rail: 20;
--z-popover: 30;   --z-modal: 40;    --z-toast: 50;   --z-tooltip: 60;

--shadow-1: 0 1px 2px rgba(0,0,0,.06), 0 1px 3px rgba(0,0,0,.08);   /* 悬浮卡、下拉 */
--shadow-2: 0 4px 12px rgba(0,0,0,.10);                              /* 弹出面板、命令面板 */
--shadow-3: 0 12px 32px rgba(0,0,0,.18);                             /* 对话框 */

--dur-fast: 120ms;  --dur-base: 160ms;  --dur-slow: 240ms;
--ease-out: cubic-bezier(.2,.8,.2,1);
```

动效口径保留 13 册 §7 的克制取向（只做"回答动作"的动效、尊重 `prefers-reduced-motion`），
但现在**必须补上** `prefers-reduced-motion` 规则（实测 **0** 处）与 `forced-colors` 支持（实测 **0** 处）。

## 7 数据密集面（本产品主战场）

现状 736px 单栏 + 1.7 行高，一屏能承载的数据量远低于同类金融界面；且表格无 sticky 表头、
无排序、无列宽调整、无行选中、无键盘行导航。目标：

| 能力 | 要点 |
|---|---|
| sticky 表头 | 表头在主区滚动期内常驻 |
| 列排序 | 点击表头，三角指示，三态（升 / 降 / 无） |
| 列宽 | 可拖拽，持久化；双击自适应内容 |
| 行选中 | 整行可选中（`--accent-weak` + 1px `--accent` 描边）；`Ctrl+点击` 多选 |
| 键盘 | `↑↓` 行间、`Home/End` 首末、`PageUp/Down` 翻屏、`Enter` 打开、`Space` 选中 |
| 复制 | `Ctrl+C` 复制选中行为 TSV，可直接落进表格软件 |
| 密度 | 双档（§3.2），读面默认 compact |
| 分页 / 虚拟滚动 | 行数超阈值时二选一；不做"无限长表" |
| 数字 | 右对齐 + `--font-num` + `tabular-nums` + 固定小数位（**保留**现行为） |
| 涨跌 | 三路冗余（**保留**现行为，见 §4.4） |

选型说明：同类金融界面的取向是"有用的密度"，而其**时间密度**（响应与加载）比视觉密度更值钱。
故本节的 sticky / 键盘 / 复制 / 排序这些"少滚动、少点击"的能力，优先级高于把像素压得更密。

### 8.1 快捷键（现状：`keydown` / `keyup` 处理器各 **0** 个，`Escape` 引用 **0** 处）

**要求**：全部功能**可纯键盘完成**；焦点顺序符合视觉顺序；浮层内焦点被困住。

### 8.2 对话框 vs 页内块（现行把一切都做成了页内块）

| 形态 | 何时用 |
|---|---|
| **真对话框**（遮罩 + 焦点陷阱） | 阻断性、必须显式处置、**破坏性**（清空、回滚、删除、导出隐私数据）、需要密码 |
| **右侧滑出面板 `sheet`** | 查看详情（节点详情、Skill 详情、视角详情）——不打断主区上下文 |
| **页内块** | 常规内容与状态呈现 |
| **命令面板** | 动作选择 |

同时把「连点 3 次 + 进度计数」（`settings.js:240-285`）**换掉**：破坏性确认改为
**真对话框 + 明确列出影响对象与范围 + 要求输入确认词**（如输入"清空"），
而不是数点击数——后者既不说明范围，也不适用于键盘与读屏用户。

### 8.3 反馈四层

| 层 | 用途 | 时长 |
|---|---|---|
| inline field | 字段级校验错误 | 随输入清除 |
| inline block | 面内状态（六态 chrome，**保留**现行服务端下发模型） | 持续 |
| `toast` | 动作结果（成功 / 失败 / 可撤销） | 4–8s |
| `banner` | 全局环境态（离线） | 持续至恢复 |
| `dialog` | 阻断性处置 | 手动关闭 |

现状只有 inline 一层，无 toast、无全局非阻塞反馈。

### 8.4 忙碌分级（现状只有 `opacity:.5` + `cursor: progress`）

| 时长 | 表现 |
|---|---|
| < 100ms | 不给指示（避免闪烁） |
| 100ms – 1s | 不确定态进度指示（不是文字） |
| 1s – 10s | 确定态进度 或 允许离开 |
| > 10s | 转后台 + 完成时通知 |
| > 1min | **必须**可离开，禁止阻塞 |

同时修正语义混用：`.disabled`（不可用，`cursor: default`）与 `.is-busy`（正在忙，可显示进度）
是两个态，现状都用 `opacity:.5` + `cursor: progress`（4 处）。

## 10 保留的铁律与文案口径

- **空态与失败态**：陈述事实与出路，不拟人、不寒暄（契约 9，保留）。
- **"结构只在有含义时出现"**（13 册原则 5，保留）。
- **改动**：`.masthead` 的常驻产品名 + 营销语（"本机回环界面 · 数据不出本机 · 只经本机服务取数"）
  移入 **关于页 / 状态栏**。它每页占掉首屏 66px，是网页营销头，不是桌面 chrome。
- **改动**：13 册 §3 的"句首大写"是 Windows 拉丁口径，中文无大小写——改为"**语气统一**"。

## 14 已决形态选择（四条，2026-10-16 定案）

四条待决项按**效果优先**排序判定，同效时取本册推荐：

| 1 | Chat 与分区的关系 | **Chat 升为常驻右栏伴随面**——分区同时在左栏可达 | 四条里唯一直接影响「全部能力原则上都可从对话触达」这一核心承诺的。左栏让辅助区可达、右栏让对话随处在场，**两者同时成立**才既保住 Chat-as-OS 又拿到桌面形态。备选 A（Chat 占满屏）把桌面收益砍掉大半；备选 B（Chat 只在 `/`）等于放弃伴随、维持现状语义 |
| 2 | 默认密度 | **全局默认 comfortable；数据读面（持仓表 / 执行日志 / 推送历史 / 网络活动）默认 compact** | 双档成本几乎为零（同一套组件换变量），而「读面优先」正是本产品主战场。全局 compact 牺牲表单与报告的舒适度，全局 comfortable 又让持仓表一屏放不下几行——故按**面类型**给默认，而非全局一刀切 |
| 3 | 浏览器面去留 | **保留为开发 / CI 面**（`--dev` 已有），**不作产品交付路径** | 保留成本为零。收益有二：现有 `tests/ui` 全套（走回环 HTTP 面）继续可用；三栏布局在浏览器视口里更便于做尺寸与折行验证。彻底砍掉会让现有测试基建失去宿主 |
| 4 | 是否现在就动路由 | **不动**。左栏二级直接复用现路径（分区 → 页内查询串视图）；路由重排另立任务 | 收益（URL 更规范）远低于成本：要改写 `PAGE_PATHS`、`pages.js` 与 `test_ui_shell_routing.py`，而 11 册 §2.2 的表是那个守卫的**解析源**。且桌面应用的用户几乎不接触 URL |

**待决项残余：无**——四条全部定案。§15 的验收口径据此成立。第 1 条的一条后果已在 §2 覆盖：
右栏常驻会挤压主区（1440 − 240 − 380 ≈ 820px），故主区最小宽度取 480px，
窗口窄于 1240px 时右栏自动收起。

## 15 验收口径（每期怎么算过）

- **P0**：`tests/ui/test_ui_design_tokens.py` 扩展为"令牌名 + 令牌值"双断言；新增对比度断言脚本，
  对 `--fg*` / `--line-strong` / 六态色逐对校验阈值；`app.css` 出现裸间距值即失败。
- **P1**：`tests/ui/test_ui_shell_routing.py` 扩展为断言"外壳三区存在 + 每区可独立滚动 + 无整页滚动"；
  浏览器走查脚本断言 `.nav` 在滚动到底后仍在视口内。
- **P2**：快捷键表逐条可走；每个阻断性动作都有一个 `role="dialog"`；`Esc` 可关最上层浮层。
- **P3**：表格支持排序 / 列宽 / 键盘行导航 / TSV 复制，各有断言。
- **P4**：连续两次启动恢复窗口尺寸与位置；安装包在干净机器上可装可跑。

## 16 一句话总结

**把"736px 单栏长卷网页"换成"常驻外壳 + 三栏各自滚动 + 双密度 + 完整键鼠与浮层能力的桌面应用"**，
同时保留四件做对的事：数字为主角的三路冗余编码、服务端下发的六态、零硬编码的令牌纪律、以及"不合并分歧"的铁律。
