## 1 设计原则

五条，从产品铁律派生。**它们优先于本文件其余任何条文**——冲突时以本节为准。

1. **界面是工具与仪表，不是人。** 铁律 2 的视觉落点：不出现头像、气泡尾巴、欢迎语气、
   第一人称文案；视觉语汇不借「助手 / 伙伴 / 陪伴」隐喻。读作**仪表盘与工作底稿**。
2. **并列是默认，合并是禁止。** 铁律 4 的视觉落点：多视角、多来源、多分歧一律**同名并列**
   （对照栏 / 并列卡 / 逐条列表）；版式中**不出现**「合并后」的呈现形态（如单一的「综合结论」块）。
3. **层级靠线与留白，不靠阴影与卡片堆叠。** 结构线（`--line`）与间距表达从属关系；
   卡片是**并列单元**的容器，不是装饰。同一页面内圆角只按层级取（见 §4）。
4. **数字是主角。** 财务数字**右对齐成列**、等宽、带表格数字特性；涨跌**恒**由
   「颜色 + ▲▼ + 数值符号」三路同时表达（§2.2）。对齐是功能，不是风格。
5. **结构只在有含义时出现。** 分隔线、编号、标签是**信息**而非装饰：编号只在内容确实是
   序列时使用（如 trace 的步骤序号）；不为对称而加线、为留白而加标签。

### 2.2 涨跌：三路冗余编码

[D-104](../../项目管理/决策日志.md) ② 定 **A 股惯例红涨绿跌**（中文用户的零学习成本惯例，
且与本产品的市场语汇同源），并**强制冗余编码**以覆盖红绿色觉异常：

| 路 | 表达 | 说明 |
|---|---|---|
| 颜色 | `--up` / `--down` / `--flat` | 色值**避开纯饱和**（绛红 / 松绿），在两种色觉下仍可区分深浅 |
| 方向符 | `▲` / `▼` / `—` | **恒与颜色同时出现**，不可只上其一 |
| 数值符号 | `+1.24%` / `-0.86%` | 带符号数值；零值不带符号 |

**判据**：把界面转成灰度后，涨跌信息仍**必须**可判（靠 ▲▼ 与符号，不靠颜色）。
任一处只上颜色不出符号，视为不合规范。

### 2.3 语义色的边界

- 语义色**只**用于状态与方向，不用于装饰。`--accent` 用于「可点、当前、已选」，不用于强调正文。
- 「不可用」与「空」必须可区分（[契约 5](10-platform-capabilities.md)）：`unavailable` → `--delayed` 档，
  `empty` → `--empty` 档；两者**都**须带中性原因文案，不静默留白。

## 3 字体

**中文走系统栈，不嵌字体。** 嵌入中文字体动辄 5–10 MB 且涉商用许可，与本地优先的体积取向相抵
（[D-104](../../项目管理/决策日志.md) ④）；系统栈在三平台的字面差异**可接受**。

- 界面：`--font-ui` = `-apple-system, "Segoe UI", "PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif`
- 数字：`--font-num` = 等宽栈。**凡成列比较的数字**（表格、指标、时间戳、ID）用 `--font-num`
  并带 `font-variant-numeric: tabular-nums`——比例数字会让列对不齐，那是缺陷不是风格。
- 字重只用两档：**常规**与**600（半粗）**。不用 700 以上——粗体在同一页里超过一个层级就失去层级。
- 正文行长 < 80 字（中文按字计）；中文行高取 `--leading`（`1.7`），比拉丁正文宽一档。

## 4 版式与密度

- **基线网格 4px**。常用间距三档：`.5rem`（同组元素）/ `.75rem`（组内块间）/ `1.25rem`（块与块）。
  间距是**组件局部**的调参，不设令牌——规范只锁「同层级同间距」。
- **对齐**：正文与标签**左对齐**；数字**右对齐**；表头与其列对齐一致。
- **密度**：单档常规密度；表格另有一个 `紧凑` 变体（行高与内边距各减一档），用于行数多的读面。
- **圆角**：按层级取用（控件 `sm` / 块 `md` / 面 `lg`），**不按元素类型取**——同类元素在不同层级
  用不同圆角是允许的，同层级用不同圆角是缺陷。

## 5 组件视觉基线

覆盖 [01 §12](../技术架构-v2/01-平台共享契约.md) 的 **14 个已实现组件型**。**共性**：
标题用 `--text-lg`、元信息 `--text-sm` + `--fg-muted`；并列单元用 `--card` 底 + 1px `--line` +
`--radius-md`；**任何并列结构都不产出「合并后」的块**（原则 2）。动作按钮一律 `--radius-sm`。

| 组件型 | 结构 | 视觉基线 |
|---|---|---|
| `table` | 表头 + 行 | 行间 1px `--line`；`tabular-nums` 已生效；**数字列右对齐 + `--font-num` 随行情读面落地**（§10） |
| `report_card` | 多段式（段标题 + 内容） | 段间以留白 + 段名（`--fg-muted`）分层，**不用**分隔线 |
| `trace_timeline` | 步骤序列（**真序列** → 用序号） | 序号 `--fg-muted` 等宽；每步可展开；末步结论用半粗 |
| `context_card` | 六段固定卡（段序与段名固定） | 每段一单元；非 ok 段以 `--delayed` 呈现 + 中性原因，**不静默留空** |
| `config_draft_card` | 草稿（值 / 默认 / 摘要 + 面板）+ 面板视图 | 面板逐行「参数名（半粗）/ 取值」；**只读**（改值走 `setting_panel`） |
| `conflict_adjudication_card` | 两方**并列** | 两栏同宽（flex `1 1 14rem`）；**无**「合并后」字段 |
| `permission_approval_card` | 逐条权限并列 + 批准态 | 态用色 + 文案双写：待批 `--delayed` / 已准 `--ok` / 已拒 `--error` |
| `feedback_capture` | 五类动作按钮组 + 原因输入 | 按钮等权（不设主次），原因入口独立一行、整宽 |
| `proposal_card` | 逐条提案（配置项 / 现值 / 建议值 / 理由 / trace 依据） | 逐条并列，动作行附在**每条之下**；对照「现值 → 建议值」用两列 |
| `change_timeline` | 逐条变更 + 回滚状态 | 逐条并列；回滚按钮附在每条之下；已回滚条目标 `--fg-faint` |
| `setting_panel` | 逐条设置（标识 / 当前值 / 候选值 + 应用动作） | **带动作**（只读呈现走 `config_draft_card`）；候选值控件整宽 |
| `violation_alert` | 警示 + 越界事实 + 禁用动作 | 边框与文字取 `--error`；禁用按钮悬停反色 |
| `divergence_map` | **两视图均实现**：矩阵视图 + 证据网络视图 | 矩阵为**逐格并列**（视角 × 结论），网络用节点-边；一致 / 分歧 / 盲点**三段并列**，不合并 |
| `studio_canvas` | 会话 + 节点 / 连线 / 分组 + 校验违规 | 画布区与检查区并列；违规条目用 `--error`，节点 / 连线用 `--line` 与 `--accent` |

**降级占位**（未登记 / 未实现型，[01 §12](../技术架构-v2/01-平台共享契约.md)）：虚线边框 +
中性说明 + 可折叠原始描述；**不用**错误红——那会让「未实现」读作「出错」。

## 6 六态

六态是 [01 §5](../技术架构-v2/01-平台共享契约.md) 的呈现档，其 `presentation` 键由服务端下发，
渲染面**不自行推断**。视觉与文案成对：

| 呈现档 | 色 | 文案要求 |
|---|---|---|
| `normal`（ok） | `--ok` | 直接给内容，不加状态词以外的修饰 |
| `empty_state` | `--empty` | 说**空的原因**并给出下一步（空是邀请，不是结束） |
| `delayed`（含 unavailable） | `--delayed` | 说**不可用的原因**与最后更新时间，不静默留白 |
| `error`（failed） | `--error` | 说发生了什么 + 可查的 `log_ref`；**不道歉、不模糊** |
| `input_error` | `--input-error` | 说**哪一项**不合契约、怎么改 |
| `loading` | `--fg-muted` | 仅连接期，不得用于已就绪面的占位 |

**失败与空态的语气**：按[契约 9](10-platform-capabilities.md)——陈述事实与出路，不拟人、不寒暄。

## 7 动效

- **只做「回答动作」的动效**：展开 / 折叠、确认生效、降级切换、焦点移动。时长 `120–180ms`，
  缓动 `ease-out`。
- **不做**：入场动画、逐段 fade-and-slide、悬停位移 / 缩放、装饰性脉冲。整页加载只有一个静默完成态。
- 尊重 `prefers-reduced-motion: reduce`——该偏好下所有时长归零。

## 8 暗色

**同一套令牌换值，不另立规则**（[`tokens.css`](../../src/st_agent/ui/web/css/tokens.css) 的
`prefers-color-scheme: dark` 块）。三种面（纸底 / 面板 / 结构线）与全部语义色同步换值；
涨跌色在暗底上**仍需维持**「避开纯饱和」与三路冗余。不提供手动的浅暗切换——跟随系统。

## 9 可达性与文案细则

- **对比度**：正文对底 ≥ 4.5:1，大字（`--text-lg` 以上）≥ 3:1；结构线不作文字底。
- **焦点可见**：键盘焦点环用 `--accent`、2px、`outline-offset: 2px`；不得 `outline: none`。
- **不依赖单一颜色**：状态与方向一律「颜色 + 文字 / 符号」双写（§2.2、§2.3、§6）。
- **文案**：按[契约 9 中性表达](10-platform-capabilities.md)——无人名 / 性格 / 第一人称 / 情感 / 对话体；
  动作名与结果一致（按钮写「接受」，反馈即写「已接受」）；空态与失败态给方向不给情绪。

## 10 与既有实现的落差（本规范落地时一并处置）

- `app.css` 现为骨架样式（其首行自述「不做视觉定稿」）：本规范落地时它改为**消费令牌**，
  **结构类名与六态 chrome 不变**。
- **待补的视觉基线**：`--up` / `--down` / `--flat` 与 `--font-num` 目前**无消费方**——它们随
  行情 / 持仓类页面（记忆区与触达区）落地时才真正用上；本规范先把口径与令牌定死，
  避免各页各自造色。表格的 `tabular-nums` 已生效（§5 `table` 行）。
- **落地时的实测落差**（[执行日志](../../项目管理/执行日志.md) `[T-UI-007]` 验证行）：正文由 `15px/1.6`
  改为 `--text-md`/`--leading`（`1rem`/`1.7`），其余字号按**就近取阶梯**合入（如 `.9rem → --text-sm`、
  `.85rem → --text-xs`）；这是采用统一阶梯的正常代价，最大偏移 `.05rem`。
