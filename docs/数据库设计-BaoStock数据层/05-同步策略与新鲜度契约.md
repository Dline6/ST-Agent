# 05 同步策略与新鲜度契约

## 元数据表

### data_source — 数据源注册

```sql
CREATE TABLE data_source (
  source_id  TEXT PRIMARY KEY,   -- 'baostock'
  name       TEXT NOT NULL,
  manual_ref TEXT                -- 源文档位置
);
```

### sync_state — 同步任务状态与水位

```sql
CREATE TABLE sync_state (
  task_key        TEXT PRIMARY KEY,
  table_name      TEXT NOT NULL,
  source_id       TEXT NOT NULL REFERENCES data_source(source_id),
  mode            TEXT NOT NULL CHECK (mode IN ('full','incremental','snapshot','upsert_window')),
  schedule_desc   TEXT NOT NULL,
  watermark       TEXT,
  last_success_at TEXT,
  last_row_count  INTEGER,
  last_status     TEXT CHECK (last_status IN ('ok','partial','failed')),
  last_error      TEXT
);
```

- `watermark` 为表级水位，语义逐任务定义（见下表「水位语义」列）。
- `last_status='partial'` 表示任务完成但校验未全部通过（见「完整性校验」）；Agent 读取数据前应先检查本表。
- 四种同步模式：`full`（全量重拉覆盖）、`incremental`（按水位追加）、`snapshot`（追加新快照、历史不动）、`upsert_window`（滚动窗口重拉 + UPSERT，用于会被源端修正的数据）。

### indicator_dictionary — 指标字典

```sql
CREATE TABLE indicator_dictionary (
  indicator_key   TEXT PRIMARY KEY,
  domain          TEXT NOT NULL,
  source_api      TEXT NOT NULL,
  api_field       TEXT NOT NULL,
  name_cn         TEXT NOT NULL,
  unit            TEXT,
  precision_note  TEXT,
  algorithm_desc  TEXT
);
```

**种子数据以 [06-API映射契约.md](06-API映射契约.md) 为单一事实源生成**：该文档的映射表即字典内容（indicator_key=目标列，domain=所属域，source_api/api_field=来源，name_cn/unit/precision_note/algorithm_desc=字段说明）。两者不一致时以 06 文档为准并重新生成种子。

**时序前置**：所有行情/财务任务的触发前提是 `bs_calendar` 与 `bs_all_stock` 当日已成功；行业/成分快照以周一为锚（非交易日顺延至下一交易日，以 `trade_calendar` 判定）。

## 首次初始化顺序

依赖关系决定顺序，不可并行越级：

1. **元数据**：`data_source` 注册 baostock；`sync_state` 建任务行；`indicator_dictionary` 由 06 文档种子生成。
2. **trade_calendar**：1990 年至今全量。
3. **security**：`query_stock_basic()` 全量（股票+指数+可转债+ETF 全类型）。
4. **板块基线**：`stock_industry` + 三个指数成分首张快照。
5. **行情基线**：`k_line_daily` 1990-12-19 起全量；`adjust_factor`、`dividend` 全量。
6. **财务基线**：`financial_quarter`（2007 起）、`performance_express`（2006 起）、`profit_forecast`（2003 起）全量。
7. **宏观基线**：五张 `macro_*` 全量。
8. **（可选）分钟线**：仅当关注池非空时按池拉取。

全量拉取遵守源限流，登录/登出生命周期由管道统一管理（`login()` → 批量查询 → `logout()`），中断可从各任务水位续跑。

## 数据新鲜度契约

对齐产品约束「数据以公开市场数据可得的更新频率为准，本产品非实时行情系统」。BaoStock 的数据在其日终批处理后更新（非逐笔），因此：

| 数据 | 预期新鲜度 | 陈旧判据（Agent 自检 SQL） |
| --- | --- | --- |
| 日线行情 | T 日数据在 T 日 BaoStock 更新后可得；同步任务于当日数据窗口后执行 | 最新交易日 `> (SELECT max(trade_date) FROM k_line_daily)` 且 `last_success_at` 早于当日窗口 |
| 周/月线 | 周期最后交易日收盘后 | 同上按 frequency 分别判断 |
| 季频财务 | 财报披露后（pubDate 驱动），修正件在下一重拉窗口覆盖 | `max(stat_date)` 落后当前披露季超一个重拉周期 |
| 行业/成分 | 每周一 | 最新 `update_date` 落后最近周一超一周 |
| 宏观利率/准备金 | 公告事件驱动，周级对账 | 最新 `pub_date` 检查即可（无固定节奏，不判陈旧） |
| 货币供应 | 月度数据按月可得 | 最新 `(stat_year, stat_month)` 落后上一自然月 |

统一自检入口（Agent 每次分析前应执行）：

```sql
SELECT task_key, table_name, last_status, last_success_at, watermark, last_error
FROM sync_state
WHERE last_status IS NOT 'ok' OR last_success_at IS NULL;
```

返回非空即数据面不完整，Agent 应降级并明确告知用户数据的实际截止时间，而不是静默使用陈旧数据。

**与平台共享契约的衔接**（[01 §5 / §8](../技术架构-v2/01-平台共享契约.md)）：本表即全平台「freshness 查询」与「最后更新时间」的唯一数据来源——`sync_state` 非空 → 上层 ResultEnvelope 走 `unavailable` 分支；`as_of` 按数据域取该域实际截止时间（行情域 = `max(trade_date)`，板块域 = 最新 `update_date` 等）；`dataset_snapshot_id` 锚定于一次分析读取各域时的水位组合，不另行维护快照登记表。

## 完整性校验

每次同步完成后执行，结果写入 `sync_state.last_status`：

```sql
-- 1. 行情覆盖对账：某交易日入库证券数 vs 当日源全量证券数（源行数在同步时记录）
SELECT count(DISTINCT code) FROM k_line_daily WHERE trade_date = :d;

-- 2. 交易日历一致性：每个有行情的日期必须是交易日
SELECT DISTINCT k.trade_date FROM k_line_daily k
LEFT JOIN trade_calendar c ON c.calendar_date = k.trade_date
WHERE c.is_trading_day IS NULL OR c.is_trading_day = 0;

-- 3. 外键完整性（孤儿行必须为 0）
PRAGMA foreign_key_check;

-- 4. 财务键域合法性：stat_date 只能是季度末日
SELECT DISTINCT stat_date FROM financial_quarter
WHERE substr(stat_date, 9) NOT IN ('03-31','06-30','09-30','12-31');

-- 5. 停牌行形态校验：trade_status=0 的行 volume 应为 0
SELECT count(*) FROM k_line_daily WHERE trade_status = 0 AND volume > 0;
```

**校验失败处理**：`last_status='partial'`，`last_error` 记录失败的校验项；不回滚已写入数据（幂等 UPSERT 使下次同步自愈），但下游 Agent 按新鲜度契约降级。
