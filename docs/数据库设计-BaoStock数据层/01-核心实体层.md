# 01 核心实体层

核心实体层是全库的父层：`security` 是所有证券数据的挂载点，`trade_calendar` 是所有「按交易日推进」逻辑的基准。两张表均为源无关语义——BaoStock 落数只是其首个写入来源。

## security — 证券主档

全库统一以 `code`（交易所.六位代码）为主键。所有域表通过 `code` 外键关联。

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| code | TEXT | PK | `'sh.600000'` / `'sz.000001'`，含指数代码（如 `sh.000001` 上证综指） |
| code_name | TEXT | | 证券名称 |
| ipo_date | TEXT | | 上市日期 |
| out_date | TEXT | | 退市日期，未退市为 NULL |
| type | INTEGER | CHECK IN (1,2,3,4,5) | 1股票 2指数 3其它 4可转债 5ETF |
| status | INTEGER | CHECK IN (0,1) | 1上市 0退市 |

```sql
CREATE TABLE security (
  code      TEXT PRIMARY KEY,
  code_name TEXT,
  ipo_date  TEXT,
  out_date  TEXT,
  type      INTEGER CHECK (type IN (1,2,3,4,5)),
  status    INTEGER CHECK (status IN (0,1))
);
CREATE INDEX idx_security_status ON security(status);
```

**写入来源**：`query_stock_basic()`（全量基线）+ `query_all_stock()`（每交易日增量，见 [05-同步策略与新鲜度契约.md](05-同步策略与新鲜度契约.md)）。名称变更通过 UPSERT 自然覆盖；`type`/`status` 以最新拉取为准。

**注意**：`security` 与 `k_line_daily.is_st` 是两个正交维度——`status` 是上市状态（行政），`is_st` 是风险警示状态（每日变化），ST 池筛选必须联合两者（见 [07-典型查询模式.md](07-典型查询模式.md)）。

## trade_calendar — 交易日历

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| calendar_date | TEXT | PK | 自然日，含非交易日 |
| is_trading_day | INTEGER | NOT NULL, CHECK IN (0,1) | 0非交易日 1交易日 |

```sql
CREATE TABLE trade_calendar (
  calendar_date  TEXT PRIMARY KEY,
  is_trading_day INTEGER NOT NULL CHECK (is_trading_day IN (0,1))
);
```

**写入来源**：`query_trade_dates()`（上交所口径，1990 年至今）。

**消费语义**：

- 同步调度基准：`k_line_daily` 的增量拉取以「最近一个 `is_trading_day=1` 的日期」为水位目标。
- 完整性校验基准：任一交易日 `k_line_daily` 的证券行数应与 `query_all_stock(day)` 一致（校验 SQL 见 [05-同步策略与新鲜度契约.md](05-同步策略与新鲜度契约.md)）。
- Agent 时间推理基准：判断「今天是交易日吗」「上一交易日是哪天」一律查本表，不自行推算周末与节假日。
