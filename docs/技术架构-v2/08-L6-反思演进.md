# 08 · L6 反思演进（Reflection Loop）

承载 [Story 9](../PRD-v2-Agent/story-09-reflection-loop.md)。L6 让系统随使用而演进：反馈闭环 → 每周反思 → 主动提案 → 受控演进。**架构立场：一切演进走统一变更流，显式告知、可回滚；副驾永不自主修改 Memory**（红线见 [04-L2 §3.2](04-L2-记忆图谱.md)）。

## 1. 反馈采集（FeedbackEvent）

| 字段 | 说明 |
| --- | --- |
| `feedback_id` | 01 §1 标识 |
| `target` | 反馈对象（某条推送 delivery_id / 结论 trace_id / 建议 change_id） |
| `action` | `adopted` / `ignored` / `rejected` / `queried` / `liked` |
| `reason` | 用户说明的原因（否定类建议必填入口，可选填） |
| `timestamp` / `context` | 时间与情境（供模式识别） |

采集点：交互层的所有推送/结论/建议反馈入口（[05-L3 §9](05-L3-对话主入口.md)）、[07-L5 疲劳监控](07-L5-主动触达.md)。反馈全部进**本地反思数据池**（L0 `reflection` 分区），不外发。

**落盘与消费**（L3 产生、L6 归属）：

- **落盘**：`reflection` 分区内 `feedback/<feedback_id>.json`，**键＝`feedback_id`**（一条用户反馈的唯一标识，由交互层铸造，[01 §1](01-平台共享契约.md)）——同一 ID 重复到达是同一事实的重放，**幂等覆盖**、不追加流水。
- **消费面**：L6 经 [01 §11](01-平台共享契约.md) 的 `FeedbackRecorded` 订阅面接入（[`EventBus`](../../src/st_agent/l1/events.py) 一事件多订阅者；L5 疲劳面订阅同一事件消费答复，两者并列、互不干扰）。L6 **只消费、不自铸 `feedback_id`**。
- **落盘形态复用** L3 的 `FeedbackEvent`（六字段即契约本体），L6 不另造平行模型。

## 2. 每周反思报告

- 每周用户配置时间本地生成（配置＝**周几 + 时刻**两项标量条目；窗口取 **ISO 周**，落盘键 `<ISO 年>-W<ISO 周>`），四段式结构；**生成与生效分离**——本步只**产出**下列内容，任何配置生效一律走 §5 变更流：
  1. 本周为你做了什么（触达/命中采纳/过滤噪音的统计陈述；取材＝L5 的投递留痕与频控 / 疲劳计数）
  2. 观察到的偏好漂移（来自 Memory `evolution` 节点的分析，经 [04 §3.1](04-L2-记忆图谱.md) 的记忆读取面按 `reflection` 切片取材）
  3. 错误与理解（哪些推送被否定；**中性呈现**用户给出的 `reason` 原文——概念性理解是 §3 训练对话的事）
  4. 建议调整的配置（每条 = §5 的 **Change Proposal**；报告只**产出提案**，生效 / 回滚一律经 §5 变更流，**不存在静默生效路径**）
- 通过 [07-L5](07-L5-主动触达.md) 渠道分发（投出面复用 §3 渠道适配器，不另造投递路径）；**两处空态分开判定、皆不硬凑**：无任何触达 → 「本周无触达，无反馈可分析」；有触达但本周反馈数低于**数据不足阈值**（可配，缺省 3）→ 「数据还不够，下周见」
- 报告生成走完整 Trace，留档于 `reflection` 分区（`weekly/<ISO 年>-W<ISO 周>.json`）
- **文案过 [01 §6](01-平台共享契约.md) 中性化校验**——story-09 的第一人称叙述是产品描述，**不是**输出模板
- **表现层读面**（2026-10-07 由 [`T-UI-004.2`](../../项目管理/tasks/done/M4/T-UI-004.2-反思中心表现层入口.md) 触发登记，[铁律 8](../../项目管理/工程宪法.md)）：周报的读面按**周键**取（`stored(week)`），并**只增**一个「已落盘周键的列举面」（`stored_weeks()`，升序）供表现层列历史与取最近一期——**只增**、既有 `stored` / `build` / `publish` / `due` 行为逐字节不变。存储布局仍**不构成契约**（[01 §7](01-平台共享契约.md)）：表现层不自行拼 `reflection/weekly/*.json` 路径，也不自行算 ISO 周键（那会把落盘形态与周历口径复制到第二处）

## 3. 训练对话协议

用户发起「我想训练你」或对结论说「这条不对，因为…」时（前者经 [05 §3.1](05-L3-对话主入口.md) 的 `train` 意图，后者经 [05 §9](05-L3-对话主入口.md) 的否定反馈入口）：

1. 副驾做**概念性理解**（结构化复述用户的修正逻辑，请用户确认理解正确）——不是简单加权调整
2. 确认后：更新 Memory `pattern` 节点（`source: user_stated`）+ 生成对应 Skill 参数调整的 Change Proposal（走 §5 变更流，不直接生效）
3. 下次对话主动回访：「上次你说 XX 不对，我理解了 YY，是这样吗？」

## 4. 主动提案与 A/B 实验

- **主动提案**：模式识别规则（如「同类问题重复出现 > 5 次」→ 提议创建专门 Skill，附草稿；频率上限可配，防骚扰）。提案 = Change Proposal 的一种
- **A/B 实验**：Experiment 结构 = `{hypothesis, scope, sample, result, decision}`；仅适用于推送策略/视角组合等低风险参数；实验全程留日志可查；本地单用户小样本下不做统计显著性强断言，效果判断保守（用户反馈优先）
- 实验的启用受 §5 授权档位约束

## 5. 演进授权与变更流（Change Flow）

三档授权（配置注册表项，切换留痕）：

| 档位 | 语义 |
| --- | --- |
| `manual` | 副驾只能建议，任何配置永不自动变 |
| `collaborative` | 提案 → 用户批准 → 生效（默认档） |
| `autonomous` | **低风险参数**小步自主优化 + 每次变更经 L5 显式告知 + 可回滚 |

变更流（所有演进动作的唯一通道，复用 01 §7 配置注册表的 change 机制）：

```
Change Proposal（含理由、影响范围、trace 依据）
  → 审批门（按授权档位决定：用户批准 / 自动放行）
  → 生效（产生 change_id，记入变更历史）
  → 告知（L5 通道）
  → 可回滚（任意时点，一键恢复前一版本）
```

「小步优化」的边界（哪些参数可自主改、哪些必须协作）：以**风险分级清单**形式注册——默认仅推送文案风格、报告结构等表现层参数可自主；Skill 参数、注意力预算、视角阵容必须协作；Memory 内容永不可自主（红线）。

**落地口径**（2026-10-07 由 [`T-L6-003`](../../项目管理/tasks/done/M4/T-L6-003-演进授权与变更流回滚与出厂重置.md) 触发登记，[铁律 8](../../项目管理/工程宪法.md)）：

| 面 | 口径 |
| --- | --- |
| 档位承载 | 三档是 [01 §7](01-平台共享契约.md) 的**登记条目** `evolution.authorization`（`scope: global`，标量枚举，**缺省 `collaborative`**）；切换走统一标量落值面、**留痕**（产生 `change_id`，同 §2 的时段条目） |
| 风险分级清单 | 同为 [01 §7](01-平台共享契约.md) 条目 `evolution.risk-grading`；取值是**对象**（三类：可自主 / 必须协作 / 永不可自主）⇒ 不在统一标量落值面内，**写面归自有 API**（先例＝`weekly-report.template`）。**未分类条目按保守处理**（视为必须协作，**不静默放行**）——清单是白名单而非黑名单 |
| 档位判定面 | 三档的**判据**以鸭子面 `permits(scope) -> bool` 对外（§4 的 A/B 启用门即消费它）：`autonomous` 且范围在低风险清单内 ⇒ 放行；`manual` / `collaborative` ⇒ 不放行（走协作路径）。**档位读不到即 fail-closed**（不臆测为 `autonomous`） |
| 变更流归属 | 变更流**住 L6**（本节的唯一通道，`src/st_agent/l6/change.py`）；**复用 [01 §7](01-平台共享契约.md) 门面落值**（`apply` / `set` 一次调用同时完成「值生效」与「产生 `change_id`」），**不另造第二套变更机制** |
| 审批门语义 | 门只回答「是否**自动**放行」：`manual` ⇒ **不立案**（提案止步于建议面，不进待批准队列——「副驾只能建议」）；`collaborative` ⇒ **立案待批准**；`autonomous` 且风险类为「可自主」⇒ **自动放行**；`autonomous` 但风险类为「必须协作」/「永不可自主」⇒ 仍立案待批准（**永不可自主类恒不自动**）。逐条结论与原因**可查** |
| 提案处置 | 报告第四段与训练对话给出的建议可比照本节入口逐条处置：**接受**（经门面落值生效）· **否决**（留痕、值逐字节不变）· **延后**（**排队而非丢弃**，同 §4 频率上限口径）。三条来源（§2 第四段 / §3 第 2 步 / §4 提案）共用同一提案形态（`config_id` + 现值 + 建议值 + 理由 + trace 依据） |
| 生效与告知 | 生效后**发布 `ChangeApplied`**、回滚后**发布 `ChangeRolledBack`**（[01 §11](01-平台共享契约.md)，**必带 `change_id`**；该两事件的**发布方＝本节变更流**）。未接总线即按 [01 §11](01-平台共享契约.md) 的「未接通」条**不假装送达**；「经 L5 通道显式告知」的**订阅**归里程碑集成关卡装配 |
| 变更历史 | 演进变更留痕落 `reflection/changes/<change_id>.json`（**不新造分区**），在 `ChangeRecord` 之上补提案来源 / 授权档 / 理由 / trace 依据 / 回滚状态；**跨族**的 `ChangeRecord` 读面经 [01 §7](01-平台共享契约.md) 门面（「读取与落值的公共面只此一处」，存储布局不构成契约） |

**风险分级清单与运行期授权的共享口径（2026-10-07 定案，[D-090](../../项目管理/决策日志.md)）**：自主查证循环（[05 §10](05-L3-对话主入口.md)）的**运行期授权闸门**复用本节的三档与三风险类，但**档位彼此独立**——`evolution.authorization`（本节，演进授权）与运行期授权条目（新立）是**两条条目**，**共用同一张** `evolution.risk-grading` 清单（[01 §7](01-平台共享契约.md)）。三条口径：

- **清单是单一事实源**——三风险类与那张白名单**只此一份**，运行期授权**不另登记第二张**。故「Memory 内容与策略恒不可自主」这条红线**单点生效**，不会因两处各标一遍而在后续增删中漂移。
- **键空间含运行期动作标识**——除既有的 `config_id` 前缀外，清单键空间纳入动作标识（形如 `skill.<base>` / `memory.write` / `net.egress`），使「某工具能否**自主调用**」与「某配置能否**自主改**」共用同一套判据与同一份清单；**未命中任何规则一律保守**（视为必须协作）的既有白名单口径**不变**。
- **本节变更流与审批门不因共享而改变**——变更流仍**只管演进动作**（`change_id` / 回滚 / 告知链）。运行期工具调用**不进**本节变更流：每次调用都立 `ChangeRecord` 会把变更历史淹掉，且运行期授权的落点与「交还用户」语义归 [05 §10](05-L3-对话主入口.md)，与「演进动作的唯一通道」是两件事。

## 6. 回滚与出厂重置

- 单项回滚：变更历史时间线 → 任一 `change_id` 一键回滚
- 「回滚到出厂设置」（三次确认）：演进状态清空——Skill 参数恢复默认、A/B 实验停止、授权档复位；**Memory 原始数据保留**；变更历史归档可查

**落地口径**（2026-10-07 由 [`T-L6-003`](../../项目管理/tasks/done/M4/T-L6-003-演进授权与变更流回滚与出厂重置.md) 触发登记，[铁律 8](../../项目管理/工程宪法.md)）：

| 面 | 口径 |
| --- | --- |
| 单项回滚的依据 | 以**变更前的生效取值**为准**回放**（门面铸的 `ChangeRecord.old_value`；条目前**从未落过值**时该槽为空——全仓既定语义「此前无留痕」——此时取该条目的**声明面默认**作为生效取值）。回放**经门面落值**、因此**本身也是一次变更**（产生**新** `change_id`、新留痕），**不直改落盘**——否则等于造出一条绕过 §5 的静默路径（§7 红线）。原记录**保留**并标注已回滚。**边界**：连声明面默认也读不出时**不回放**并如实说明（**不写假值冒充恢复**） |
| 回滚被覆盖的早期变更 | 同样以该条自己的 `old_value` 为准（**不猜**「当前状态」应当是什么），历史里新旧两条**都在** |
| 出厂重置的确认 | **三次确认**：不足三次**即拒**——不留痕、不执行任何动作、不留「做了一半」的状态 |
| 「Skill 参数恢复默认」的范围 | 以**演进变更历史所记录的条目**为准，**逆序逐条回放** `old_value`（每条各自留痕）。**不波及**与演进无关的条目（`retention.*` / `mcp-hub/` 等）；条目的 `default` 槽存的是**当前取值**（01 §7 落值语义），故「出厂默认」不能由门面泛化给出——以变更历史为据是本条的**唯一**可行口径 |
| 「A/B 实验停止」 | 在跑实验转**已停止**态（**只增**一个停止面）；**留痕保留、不删**（同 §4「留痕即事实」）；`running()` 不再含已停止者 |
| 「授权档复位」 | `evolution.authorization` 回到**缺省 `collaborative`**（走同一落值面，故同样留痕） |
| Memory 保留 | 重置**不触碰** `memory` 分区、**不调用**任何删除面（L2 的删除面是**用户显式删除**的通道，本流程**不得借道**）——§7 红线的延伸 |
| 变更历史归档 | 重置**抹除**变更历史为**归档**：重置前的全部演进变更**仍可查**，可看出哪些已被回放、哪些是重置本身产生；重置本身落一条痕 `reflection/reset/<reset_id>.json`（**不新造分区**）。无历史可回放时**照常成功**并如实说明（不报错、不假装回放） |

**表现层入口（2026-10-07 由 [`T-UI-004.3`](../../项目管理/tasks/done/M4/T-UI-004.3-演进面表现层入口.md) 触发登记，[铁律 8](../../项目管理/工程宪法.md)）**：

| 面 | 口径 |
| --- | --- |
| 变更历史与回滚 | 时间线按 `(seq, applied_at, change_id)` **确定定序**（不靠时钟，同 §6 的回放口径），逐条含来源 / 授权档 / 理由 / trace 依据与回滚状态；回滚按钮对任一 `change_id` 可用，**回滚本身也是一次变更**（新 `change_id`、原记录保留并标注） |
| 出厂重置 | 「三次确认」在表现层是**硬门**：确认次数不足即**就地拒**、一步都不做（`memory` 分区逐字节不变由 §7 的机器断言兜底）；前端不把确认次数当成可选项 |
| 授权设置页 | 档位是 [01 §7](01-平台共享契约.md) 的标量登记条目，呈现走 `config_draft_card` 的面板分支（只读），**改值**走带动作的 `setting_panel`——**两者不合并**，理由与契约登记见 [01 §12](01-平台共享契约.md)；风险分级清单是**对象类**条目，表现层本批只**呈现**（替换仍经自有 API，[01 §7](01-平台共享契约.md) 的「对象类取值不在统一标量落值面内」） |
| 读面取数 | 变更时间线与「待批准项」各取 `change_flow` 的读面（`history()` / `pending()`），表现层不自行拼 `reflection/changes/*.json` 路径（存储布局不构成契约） |

## 7. 禁止事项（架构红线）

- 副驾不得自主修改 Memory 节点内容（只能新增 inferred 节点或提案）
- 不做跨用户的模式学习（无联邦、无数据外发）
- 任何演进变更不得绕过变更流（不存在「静默调参」路径）

**落地钉法**（2026-10-07 由 [`T-L6-003`](../../项目管理/tasks/done/M4/T-L6-003-演进授权与变更流回滚与出厂重置.md) 触发登记）：三条红线各以**机器断言**钉住——① 本层**不 import** L2 的删除面、全层无 `edit_node(` / `delete_node(` 调用，且出厂重置前后 `memory` 分区的清单与逐文件 `digest` 逐一致；② 本层**不 import** 任何出网面（`l0.llm` / `l0.net`），无跨用户数据面；③ 本层的条目录值**只经 [01 §7](01-平台共享契约.md) 门面**（`change_id` 的产生只此一处），`grep` 断言无第二条写值路径。
