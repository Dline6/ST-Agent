# 08 · L6 反思演进（Reflection Loop）

承载 [Story 9](../PRD-v2-Agent/story-09-reflection-loop.md)。L6 让系统随使用而演进：反馈闭环 → 每周反思 → 主动提案 → 受控演进。**架构立场：一切演进走统一变更流，显式告知、可回滚；副驾永不自主修改 Memory**（红线见 [04-L2 §3.2](04-L2-记忆图谱.md)）。

## 1. 反馈采集（FeedbackEvent）

| 字段 | 说明 |
| --- | --- |
| `feedback_id` | 01 §1 标识 |
| `target` | 反馈对象（某条推送 delivery_id / 结论 trace_id / 建议 change_id） |
| `action` | `adopted` / `ignored` / `rejected` / `queried` / `liked` |
| `reason` | 用户说明的原因（否定类建议必填入口，可选填） |
| `timestamp` / `context` | 时间与情境（供模式识别） |

采集点：交互层的所有推送/结论/建议反馈入口（[05-L3 §9](05-L3-对话主入口.md)）、[07-L5 疲劳监控](07-L5-主动触达.md)。反馈全部进**本地反思数据池**（L0 `reflection` 分区），不外发。

**落盘与消费**（L3 产生、L6 归属）：

- **落盘**：`reflection` 分区内 `feedback/<feedback_id>.json`，**键＝`feedback_id`**（一条用户反馈的唯一标识，由交互层铸造，[01 §1](01-平台共享契约.md)）——同一 ID 重复到达是同一事实的重放，**幂等覆盖**、不追加流水。
- **消费面**：L6 经 [01 §11](01-平台共享契约.md) 的 `FeedbackRecorded` 订阅面接入（[`EventBus`](../../src/st_agent/l1/events.py) 一事件多订阅者；L5 疲劳面订阅同一事件消费答复，两者并列、互不干扰）。L6 **只消费、不自铸 `feedback_id`**。
- **落盘形态复用** L3 的 `FeedbackEvent`（六字段即契约本体），L6 不另造平行模型。

## 2. 每周反思报告

- 每周用户配置时间本地生成（配置＝**周几 + 时刻**两项标量条目；窗口取 **ISO 周**，落盘键 `<ISO 年>-W<ISO 周>`），四段式结构；**生成与生效分离**——本步只**产出**下列内容，任何配置生效一律走 §5 变更流：
  1. 本周为你做了什么（触达/命中采纳/过滤噪音的统计陈述；取材＝L5 的投递留痕与频控 / 疲劳计数）
  2. 观察到的偏好漂移（来自 Memory `evolution` 节点的分析，经 [04 §3.1](04-L2-记忆图谱.md) 的记忆读取面按 `reflection` 切片取材）
  3. 错误与理解（哪些推送被否定；**中性呈现**用户给出的 `reason` 原文——概念性理解是 §3 训练对话的事）
  4. 建议调整的配置（每条 = §5 的 **Change Proposal**；报告只**产出提案**，生效 / 回滚一律经 §5 变更流，**不存在静默生效路径**）
- 通过 [07-L5](07-L5-主动触达.md) 渠道分发（投出面复用 §3 渠道适配器，不另造投递路径）；**两处空态分开判定、皆不硬凑**：无任何触达 → 「本周无触达，无反馈可分析」；有触达但本周反馈数低于**数据不足阈值**（可配，缺省 3）→ 「数据还不够，下周见」
- 报告生成走完整 Trace，留档于 `reflection` 分区（`weekly/<ISO 年>-W<ISO 周>.json`）
- **文案过 [01 §6](01-平台共享契约.md) 中性化校验**——story-09 的第一人称叙述是产品描述，**不是**输出模板

## 3. 训练对话协议

用户发起「我想训练你」或对结论说「这条不对，因为…」时（前者经 [05 §3.1](05-L3-对话主入口.md) 的 `train` 意图，后者经 [05 §9](05-L3-对话主入口.md) 的否定反馈入口）：

1. 副驾做**概念性理解**（结构化复述用户的修正逻辑，请用户确认理解正确）——不是简单加权调整
2. 确认后：更新 Memory `pattern` 节点（`source: user_stated`）+ 生成对应 Skill 参数调整的 Change Proposal（走 §5 变更流，不直接生效）
3. 下次对话主动回访：「上次你说 XX 不对，我理解了 YY，是这样吗？」

**落地口径**（2026-10-06 由 [`T-L6-002`](../../项目管理/tasks/T-L6-002-训练对话协议主动提案与AB实验.md) 触发登记，[铁律 8](../../项目管理/工程宪法.md)）：

| 面 | 口径 |
| --- | --- |
| 发起与承接 | 派发总线（[05 §4](05-L3-对话主入口.md)）交出**文本 + 反馈对象**，L6 按本节协议承接；L3 不解析训练语义、L6 不解析意图——两端只认这两样，不互猜 |
| 概念性理解 | **经注入的理解端口**承担（鸭子类型 ``understand(...) -> ResultEnvelope``，先例＝[05 §3.2](05-L3-对话主入口.md) 的意图理解端口）；**缺省不注入即 fail-closed**（`unavailable` + 原因），**不硬猜**。复述文案是**生成性文案**、过 [01 §6](01-平台共享契约.md) 执行点 2——story-09 的「我理解了 YY」是第一人称**产品叙述**，不是输出模板（同 [§2](08-L6-反思演进.md) 末条的口径） |
| 记忆写入 | **仅在用户确认理解之后**，经 [04 §3.2](04-L2-记忆图谱.md) 的写入面**新增** `pattern` 节点（`source: user_stated`、`triggered_by` 可为空）——**只增不改**（[04 §3.2](04-L2-记忆图谱.md) 红线：副驾永不自主修改既有节点内容）；未接写入面即**显式标注未写入**并点名，不假装写了 |
| 提案候选 | 确认后同批产出**Skill 参数调整的 Change Proposal 候选**（`config_id` + 现值 + 建议值 + 理由 + trace 依据）——**不产 `change_id`、不落变更历史、不生效**；生效 / 回滚一律经 §5（[§7](08-L6-反思演进.md) 红线：不存在静默调参路径） |
| 回访留痕 | 会话与待回访项落 `reflection/training/<training_id>.json`，读面供「下次对话主动提及」取材；**在对话中真正提及**的渲染是表现层的事——L6 只交留痕与读面，跨层接线归里程碑集成关卡 |

## 4. 主动提案与 A/B 实验

- **主动提案**：模式识别规则（如「同类问题重复出现 > 5 次」→ 提议创建专门 Skill，附草稿；频率上限可配，防骚扰）。提案 = Change Proposal 的一种
- **A/B 实验**：Experiment 结构 = `{hypothesis, scope, sample, result, decision}`；仅适用于推送策略/视角组合等低风险参数；实验全程留日志可查；本地单用户小样本下不做统计显著性强断言，效果判断保守（用户反馈优先）
- 实验的启用受 §5 授权档位约束

| 面 | 口径 |
| --- | --- |
| 模式识别取材 | 经**注入的模式观察面**（鸭子端口，逐条给出同类键 / 计数 / 样本原话 / 来源锚点 / Skill 草稿）——数据源是 L3 的对话史与 L2 的记忆节点，**L6 不自行扫描对话记录**；观察面缺省 ⇒ **不产提案**（fail-closed）并显式说明原因——不由计数为 0 反推「没有问题模式」 |
| 触发阈值 | 「同类问题重复出现 > N」的 N **登记为 [01 §7](01-平台共享契约.md) 条目**（`proposal.repeat-threshold`，缺省 5），**不硬编进代码** |
| 频率上限 | 每条提案的投出受**频率上限**约束（`proposal.rate-limit`，每 ISO 周最多 N 条、缺省 1），防骚扰；被上限压下的提案**排队而非丢弃**（窗口口径与 [§2](08-L6-反思演进.md) 的 ISO 周**同源**，不另造第二套时间口径） |
| 提案承载 | `SkillProposal` ＝ Change Proposal 候选（同 §3 的形态）+ Skill 草稿（`workflow_draft` 子对象，形态见 [05 §5](05-L3-对话主入口.md)）；落 `reflection/proposals/<proposal_id>.json`（键＝同类键的确定性摘要 ⇒ 重复检出幂等覆盖）；**只产提案、不产 `change_id`、不生效**（生效 / 回滚经 §5） |
| 与周报第四段同源 | [§2](08-L6-反思演进.md) 第 4 段「建议调整」的候选生成规则**即本节的规则表**——两处共用同一提案面（`advisor` 注入面），**不另造第二套规则**，否则同一份观察会给出两份不同的建议 |
| A/B 实验落点 | `reflection/experiments/<experiment_id>.json`（假设 / 范围 / 样本 / 结果 / 决策五字段 + 起止时刻），全程可查；启停与判定是**显式时刻的纯函数**（不起线程、不自行定时） |
| 保守判定 | 本地单用户小样本 ⇒ **不做统计显著性强断言**，效果判断保守、**用户反馈优先**；判据与样本口径随实验记录留存 |
| 启用门 | 受 §5 授权档位约束——授权判定经**注入的授权面**，**缺省不注入即不启用**（fail-closed）；不存在「未接授权面却自行开跑」的路径（[§7](08-L6-反思演进.md) 红线的延伸） |

## 5. 演进授权与变更流（Change Flow）

三档授权（配置注册表项，切换留痕）：

| 档位 | 语义 |
| --- | --- |
| `manual` | 副驾只能建议，任何配置永不自动变 |
| `collaborative` | 提案 → 用户批准 → 生效（默认档） |
| `autonomous` | **低风险参数**小步自主优化 + 每次变更经 L5 显式告知 + 可回滚 |

变更流（所有演进动作的唯一通道，复用 01 §7 配置注册表的 change 机制）：

```
Change Proposal（含理由、影响范围、trace 依据）
  → 审批门（按授权档位决定：用户批准 / 自动放行）
  → 生效（产生 change_id，记入变更历史）
  → 告知（L5 通道）
  → 可回滚（任意时点，一键恢复前一版本）
```

「小步优化」的边界（哪些参数可自主改、哪些必须协作）：以**风险分级清单**形式注册——默认仅推送文案风格、报告结构等表现层参数可自主；Skill 参数、注意力预算、视角阵容必须协作；Memory 内容永不可自主（红线）。

## 6. 回滚与出厂重置

- 单项回滚：变更历史时间线 → 任一 `change_id` 一键回滚
- 「回滚到出厂设置」（三次确认）：演进状态清空——Skill 参数恢复默认、A/B 实验停止、授权档复位；**Memory 原始数据保留**；变更历史归档可查

## 7. 禁止事项（架构红线）

- 副驾不得自主修改 Memory 节点内容（只能新增 inferred 节点或提案）
- 不做跨用户的模式学习（无联邦、无数据外发）
- 任何演进变更不得绕过变更流（不存在「静默调参」路径）
