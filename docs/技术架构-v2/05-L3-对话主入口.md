# 05 · L3 对话主入口（Chat-as-OS）

承载 [Story 1](../PRD-v2-Agent/story-01-chat-as-os.md)。产品主入口 = Chat 输入面 + 上下文卡片；v1 全部功能都在对话中被触发。L3 是**唯一的用户交互主入口**（Studio、设置等为辅助界面），核心职责：会话管理、意图理解与澄清、任务派发、Generative UI、推理链可视化、对话即配置。

**形态（2026-10-16 修订，[D-120](../../项目管理/决策日志.md)）**：原文「无传统菜单」的口径**已取代**。对话面由「一整页」改为**常驻右栏伴随面**（在任一分区页都在场），辅助区经左栏**分区导航**进入。**本层的契约面不因形态改变**——§2 的上下文卡片、§3 的意图与澄清协议、§4 的派发总线、§6 的 UI 描述契约、§10 的自主查证循环均不变；变的只是承载它的壳（见 [14-desktop-form.md](../PRD-v2-Agent/14-desktop-form.md) §2–§3）。

## 1. 会话模型

- 多轮、有状态、可回溯、可分支：会话为树状结构（任意消息可发起分支延续新话题）
- 对话历史存 L0 `chat_history` 分区：完全离线可查、可搜索、可导出 Markdown
- **消息落盘**（2026-10-27 补）：用户轮与助手轮**都**写入会话。助手轮除中性文本摘要（`text`，供搜索与 Markdown 导出）外，另附**出站载荷**（`payload`，可选）——它是该轮经 [01 §6](01-平台共享契约.md) 输出校验后的最终形态，供历史回放用**同一条**渲染路径重现；旧记录无该字段时按纯文本回放，不伪装成有卡片。
- **历史读面**（2026-10-27 补）：`GET /api/chat/sessions`（按更新时间倒序的会话列表：标识 / 标题 / 时刻 / 消息数 / 末条摘要）与 `GET /api/chat/session?id=`（默认链路的用户与助手消息）。两条都是本机回环的**只读**面，要启动令牌；未注入对话门面时 `unavailable` + 点名，不伪造空列表。
- 会话上下文 = 当前会话消息 + [04-L2](04-L2-记忆图谱.md) 的 MemoryReader 切片（受 Token 预算约束）

## 2. 上下文卡片（首页常驻）

> 标题的「首页」指**对话面**；2026-10-16 起该面为**常驻右栏伴随栏**（不再是「一整页」），卡片仍常驻其顶部。见 [D-120](../../项目管理/决策日志.md) 与 [14-desktop-form.md](../PRD-v2-Agent/14-desktop-form.md) §2–§3。

- 内容 = Memory 关键切片：持仓摘要、关注池、未读告警数、近期热点摘要、当前 thesis / 风险偏好（「副驾眼中的我」不超过 5 条关键标签，即偏好画像卡）
- 六项各占**一段**（段序与段名固定）：数据来源未就绪的段以「不可用 + 原因」呈现，**不静默留空、不用其他数据顶替**
- 点击进入 [04-L2](04-L2-记忆图谱.md) 完整图谱
- 空状态（新用户无 Memory）：显示「你还没告诉我任何偏好，我们先聊两句？」**（示例措辞；含第一人称，实现按铁律 2 中性改述）**引导 Onboarding
- **中性措辞**：卡片名、引导语、空状态提示等**本层自有**固定文案一律按铁律 2 中性改述（渲染前过 01 §6 执行点 2）；**记忆本体内容**（用户原话与推断记录）属数据展示，**不过**输出校验、原样呈现——见 [D-053](../../项目管理/决策日志.md)

## 3. 意图理解与澄清协议

### 3.1 意图分类

| 意图类型 | 派发目标 |
| --- | --- |
| `query`（查询/看数据） | L1 Skill 调用 → 结果渲染 |
| `configure`（配置/盯盘/建流程） | 对话即配置（§5） |
| `analyze`（复杂决策分析） | 触发 [06-L4 Deliberation](06-L4-多视角推理.md)（经确认） |
| `memory_op`（表达偏好/修正记忆） | L2 写入或冲突裁决对话 |
| `train`（训练副驾） | [08-L6 训练对话协议](08-L6-反思演进.md) |
| `explain`（追问推理） | Trace 展开渲染 |
| `investigate`（多步自主查证） | 自主查证循环（[§10](#10-自主查证循环agent-运行时)）→ 证据包渲染 |

**第七类 `investigate`（2026-10-07 增补，[D-090](../../项目管理/决策日志.md)）**：前三类「看数据 / 配置 / 决策」都假定**一次调用即可回答**——`query` 的派发目标是**单个** Skill，`analyze` 的派发目标是**固定编排**的多视角流程。凡「先查 A，看结果再定要不要查 B」这类**需临场编排**的诉求，此前只能预写成 Skill 依赖或工作流，模型无从参与。`investigate` 即该缺口的承载者：派发目标是一条**运行时循环**（§10），由模型在**授权闸门**内逐步选择调用哪个能力。它与 `query` **并存不替代**——`query` 的**确定性是可审计性的一部分**，简单查询不该付循环的成本与不确定性。

### 3.2 澄清协议

- 意图模糊（关键参数缺失）→ 副驾主动追问；**澄清预算 ≤ 3 个问题**，且每个问题可跳过（跳过用默认值继续）
- **澄清问项的来源**（2026-09-28 定案）：一条问项 ＝ 目标 Skill 的 [`SkillDescriptor.parameters`](01-平台共享契约.md) 中**未给出值**的一项（一问一参、问句与取值域取自该 `ParameterSpec`）；「跳过」即取该参数的 `default`。超出澄清预算的未澄清项**以默认值填充**，并在确认卡上标注其来源为默认值——不静默替用户决定
- **无 target Skill 的意图**（2026-10-04 补 · 2026-10-07 扩至 `investigate`）：`analyze` / `investigate` 等意图**没有**被调用的**单个** Skill（[§3.1](#31-意图分类) 的派发目标是整条 [06-L4](06-L4-多视角推理.md) 流程 / 整条自主查证循环（[§10](#10-自主查证循环agent-运行时)），非某个 Skill），其问项取自**意图级参数声明**——形态与问项来源规则同上一行（一问一参、取值域取自该 `ParameterSpec`、跳过取 `default`、超预算落默认值并标注），只是承载者不是 `SkillDescriptor` 而是该意图自身的参数声明（实现表见代码）。这是 [06 §2.1](06-L4-多视角推理.md)「询问模式（快速 / 深度）」的落点：未给出 `mode` 时按同一规则生成问项，而非由实现自行挑一个模式。**`investigate` 本期无意图级参数声明**——其循环上界（步数 / 调用次数）是**可配置项**（[01 §7](01-平台共享契约.md) 登记，见 [§10](#10-自主查证循环agent-运行时)）而非意图参数，故该意图的确认卡只有「意图」一条目（[§3.2](#32-澄清协议) 的 N ≥ 1 由此满足），不臆造问项。
- 意图过于模糊（无法收敛）→ 提供「3 个可能的方向」而非强行猜测；方向候选**取自意图理解产物**（本层只裁剪到 ≤3 条并按铁律 2 中性改述），理解不可用时走 `unavailable` + 原因，**不拿无关来源充数**
- 收敛后必须输出**意图确认卡**：「我理解到 3 件事：①…②…③…，对吗？」（**示例措辞；含第一人称，实现按铁律 2 中性改述**）——用户确认后才执行；卡的条目列表即 [§5](#5-对话即配置config-draft) `ConfigDraft.understanding_summary` 的**同一份**内容源，不另造第二份摘要
- **意图识别的实现口径**（2026-09-28 定案）：文本 → 七类意图的**理解**由**注入的理解端口**承担（缺省不注入即 fail-closed，走 `unavailable` + 原因）；快捷指令（[§8](#8-快捷指令)）命中时**短路**——直接取该指令的意图模板与参数预填，已预填参数不再追问。**理解端口看到的仍是「意图 + 抽取的参数」**——它**不**在理解阶段选择要调用哪个工具（那是 [§10](#10-自主查证循环agent-运行时) 循环内的事），故理解提示词**不含能力清单**，该口径不因新增 `investigate` 而变。
- **目标 Skill 的解析**（2026-10-25 补，[`T-L3-007`](../../项目管理/tasks/done/M7/T-L3-007-意图目标解析与可派发性守门.md)）：上一条的「提示词不含能力清单」约束的是**提示词**，不豁免理解之后的**目标解析**。`query` / `configure` 的派发目标是**单个** Skill（[§3.1](#31-意图分类) 表），故本层在理解产物之上再走一条**确定性**解析链：理解端口给出的目标先核**是否已注册**（形态非法 / 未注册一律视为未给出）→ 仍为空时对**用户原话**做一次 best-1 匹配（口径同快捷指令路径的 `SkillRunner.match`：名称 + 描述的字符 bigram 重叠，并列按标识字典序），重叠达到阈值才采信。补出来的目标**必须**在确认卡上以来源「匹配」标注——它是本层的推导、不是用户给出的。解析不出目标时**不得产出确认卡**（见下条「可派发性守门」）。
- **可派发性守门**（2026-10-25 补，[`T-L3-007`](../../项目管理/tasks/done/M7/T-L3-007-意图目标解析与可派发性守门.md)）：确认卡是「用户确认后才执行」的凭据，故**一张可确认的卡不得处于「派发必然失败」的状态**。需要目标 Skill 的去向（`query` / `configure`）在目标未解析出时**不出确认卡**，改为带原因的澄清轮 / 空态（已有方向候选则一并给出）——把失败暴露在确认**之前**，而不是让用户点一次「确认并执行」再收到 `validation_failed`。目标已确定时，理解端口抽出的参数若**未在目标描述体与意图级声明中登记**，该参数**不进** `values`（不送派发），并在卡上以来源「未采用」显式呈现——不静默丢弃，也不静默送进去被下游拒。

## 4. 任务派发总线

意图确认后派发执行；所有派发产生 `trace_id`（[01 §4](01-平台共享契约.md)）。

**会话身份进派发载荷（2026-10-28 定案，[D-142](../../项目管理/决策日志.md)）**：派发签名携带可选的 `session_id`（[§1](#1-会话模型) 的本地会话标识），使 `investigate` 等去向能回读本会话历史。**未提供 `session_id` 时不得臆造会话**——按「无历史的单次查证」照常执行，并在产出中**显式标注**该模式；存量调用方不传该参数时行为不变。会话标识不是 [01 §1](01-平台共享契约.md) 的契约 ID 类，只在本地进程内传递。

**去向与接入态**（2026-09-28 定案）：总线的路由表 ＝ [§3.1](#31-意图分类) 的七类去向。**尚未接入的去向不得伪造执行、也不得静默丢弃**——按 ResultEnvelope 的 `unavailable` 分支呈现，其 `reason` 必须点名**归属任务**（同 [§2](#2-上下文卡片首页常驻) 的「生产方未接入即 `unavailable` + 点名」口径）。

**接入进度**（2026-10-04）：逐去向的接入态由总线实现的路由表登记（每项含 `wired` 与未接入时的归属任务 id）。`query` / `configure` / `memory_op` / `explain` 于 M1 关卡接入；`analyze` 于 **M2 关卡（`T-INT-003`）**接入——经**组合根注入的编排端口**触发 [06-L4](06-L4-多视角推理.md) 的 Deliberation，**L3 不 import L4**（[铁律 7](../../项目管理/工程宪法.md)；`LAYER_ORDER` 为 `l3 < l4`），载荷按鸭子面透出（总线只认其中的 `ResultEnvelope`）；`train` 于 **L6（[`T-L6-002`](../../项目管理/tasks/done/M4/T-L6-002-训练对话协议主动提案与AB实验.md)）**接入——经**注入的训练对话端口**触发 [08 §3](08-L6-反思演进.md) 的协议（同向：**L3 不 import L6**，载荷按鸭子面透出），端口的**组合根注入**归 M4 关卡 [`T-INT-005`](../../项目管理/tasks/done/M4/T-INT-005-M4集成关卡反思演进与生态闭环.md)。

**`investigate` 的接入态（2026-10-07 增补，[D-090](../../项目管理/决策日志.md)；2026-10-09 接入完成）**：属 **M5 里程碑（`T-AGT-*`）**——经**组合根注入的循环端口**触发 [§10](#10-自主查证循环agent-运行时) 的运行时循环。落点与其余去向**同型**：循环本体住 **L3 自身**（`src/st_agent/l3/runtime/`，[D-090](../../项目管理/决策日志.md) 的落点 A），但总线仍**只见鸭子面**（只认返回载荷里的 `ResultEnvelope`）——**注入**而非就地构造，与 `runner` / `deliberations` / `trainings` 同一取向，以使总线可在**不接 LLM** 的前提下单测。

**接入完成（2026-10-09，[`T-INT-006`](../../项目管理/tasks/done/M5/T-INT-006-M5集成关卡受控自主闭环.md)）**：循环端口（`run_agent_loop` + `ActionGate` + `NativeToolCallProtocol`，各自交付件见 [§10](#10-自主查证循环agent-运行时)）的**装配**已落地——生产组合根 `build_m5_runtime`（[`__main__.py`](../../src/st_agent/__main__.py) 的默认组合根）注入它，故 `investigate` 在**生产入口**上从「未接入」转为**真链路**（[GWT-7](../../项目管理/tasks/done/M5/T-INT-006-M5集成关卡受控自主闭环.md)）。**未注入的根**（M1–M4 的历史组合根）仍按本节「未接入去向」口径 fail-closed（`unavailable` + 点名），**不伪造执行**。

**交还回执（2026-10-29 补，[`T-AGT-011`](../../项目管理/tasks/done/M8/T-AGT-011-计划与提问.md)）**：该去向的产出载荷在终止为**待确认**（`needs_confirmation`）或**待用户输入**（`needs_user_input`）时，除信封外还携**可续跑标识**——前者带被拦下的那一步（工具名 + 参数），后者带结构化问项（含被截断项的显式说明）；表现层据此出「确认并继续 / 提交答案 / 重跑」入口，续跑经同一去向端口的 `resume` 接回（[§10](#10-自主查证循环agent-运行时)）。

**派发面的异常面**（2026-10-25 补，[`T-L3-007`](../../项目管理/tasks/done/M7/T-L3-007-意图目标解析与可派发性守门.md)）：去向下游**抛出的异常不得穿透总线**——调用方传参非法（`ValueError` 系，如目标标识形态错误）按 `validation_failed` 呈现，其余执行面异常按 `dependency_failed` 呈现，两者都带原因。「不穿透」与「未接入选 `unavailable`」同一取向：既不伪造执行，也不把一次**可解释的拒绝**变成调用方侧的一次崩溃。

**结果渲染语义**（六态穷尽，机器可读映射见 §4 所述实现；`validation_failed` 一行为 2026-09-28 补入——原枚举遗漏该态）：

| status | UI 语义 | 必展示 |
| --- | --- | --- |
| `ok` | 正常 UI | —— |
| `empty` | 空状态文案 | 原因 |
| `unavailable` | 数据延迟提示 | **最后更新时间**、原因 |
| `dependency_failed` | 错误态（依赖失败） | 原因 |
| `failed` | 错误态（执行失败） | 原因、**日志入口** |
| `validation_failed` | 参数/输入校验失败态（**不允许保存**） | 理由 |

> **`dependency_failed` 不强制日志入口**（2026-10-27 订正，[D-138](../../项目管理/决策日志.md)）：此前的表格把它与 `failed` 并列要求「日志入口」，与 [01 §5](01-平台共享契约.md)「`failed`：须含可查日志入口」的强制面不一致——依赖失败（如 LLM 凭据缺失、上游返回非 ok）根本没有可指的运行记录，按旧口径渲染会在对话里露出内部契约提示。现按 01 §5 取齐：`dependency_failed` 必展示**原因**，`log_ref` 存在时照常显示、缺省不判违规。

**LLM 端点不可用**：显式降级告知，不静默失败（降级文案按铁律 2 中性改述）；**不依赖 LLM 的去向不受牵连**，照常执行。

## 5. 对话即配置（Config Draft）

「一句话 → Skill/工作流 配置草稿」的契约：

| 字段 | 说明 |
| --- | --- |
| `target` | 目标 Skill / 工作流（新配置或修改既有配置） |
| `parameter_draft` | 从对话提取的参数值（对齐 SkillDescriptor.parameters） |
| `understanding_summary` | 结构化理解摘要（「我理解到 N 件事」的内容源） |
| `open_questions` | 未澄清参数（供追问或标注默认值来源） |

流转：草稿 → 用户接受（配置生效并产生 `change_id`）/ 微调（进入参数面板）/ 拒绝（丢弃并可选记录原因进反馈池）。工作流草稿对象传递给 [03-L1 Skill Studio](03-L1-能力底座-Skills与MCP.md) 落画布可视化微调。配置草稿生成与编辑共用 01 §7 配置注册表，保证对话通道与面板通道效果一致。

`target` 为工作流时，草稿在上表四字段之外**另携** `workflow_draft` 子对象（`name` / `description` / `nodes` / `edges` / `groups` / `schedule`，可含 ASCII `flow_name`）承载结构与暂定名——身份字段 `flow_id` / `version` **不在草稿中**，由 Studio 侧「接受」派生。落画布与接受的完整口径见 [03-L1 §4](03-L1-能力底座-Skills与MCP.md)。

**落地口径**（2026-09-28 定案）：

- **四字段的来源只有一处**——**已确认的意图确认卡**（[§3.2](#32-澄清协议)）：`target` 与 `parameter_draft` 取卡上的目标与已收敛取值；`understanding_summary` 取卡的**条目列表**（§3.2 定案：**同一份内容源**，不另造第二份摘要）；`open_questions` 取卡上**未澄清**的参数。**未经确认的卡不得生成草稿**（`validation_failed`）。
- **`open_questions` 逐条结构化**（参数名 / 问句 / 默认值 / 来源）：「来源」区分**已按默认值填充**（跳过或超澄清预算者）与**待追问**两类——前者同批进 `parameter_draft`，两类不混同、不静默替用户决定。
- **三态的落点**（面板与草稿卡的**渲染**归 [§6](#6-generative-ui) 的骨架任务与 [`T-L3-004`](../../项目管理/tasks/done/M1/T-L3-004-GenerativeUI推理链可视化.md)）：

| 处置 | 落点 |
| --- | --- |
| 接受 | 经 [01 §7](01-平台共享契约.md) **登记面的写入端**落值并产生 `change_id`；L3 **不自行落** `config` 分区（否则绕过登记表，双通道会分叉） |
| 微调 | 返回**面板视图**（同一条 `ConfigEntry` 的 `panel_form_spec` + 当前值）；草稿态**不落盘** |
| 拒绝 | 丢弃、**不落盘**，`reason` 仅随返回值透传（反馈池归 [08-L6](08-L6-反思演进.md)） |

- **双通道同源**：同一个参数的对话描述与面板表单由**同一处解析**得出——该参数已登记到 [01 §7](01-平台共享契约.md) 时取同一条 `ConfigEntry`（`description_for_chat` / `panel_form_spec` / 默认值 / 生效范围）；**未登记**时两个通道**同样**回落到该参数的声明面（[01 §2](01-平台共享契约.md) 的 `ParameterSpec`：`description` + 由 `type` 映射的表单字段 / 默认值），并在视图上**标注解析来源**。**不出现**「一个通道取登记项、另一个取声明面」。描述体取数口与登记面**都没注入**时走 `unavailable` + 点名（「生产方未接入即 `unavailable` + 点名」的口径同 [§2](#2-上下文卡片首页常驻)）。**统一配置注册表门面已交付**（归属 L1，见 [01 §7](01-平台共享契约.md)；决策 [D-067](../../项目管理/决策日志.md)）——故「未接登记面」现只发生在**未装配**或**目标未知**时，而非门面缺席。
- **工作流分支的判定**：由**调用方随派发提供的结构载荷**判定（新草稿尚无 `flow_id`，无从按 id 形态识别），判据**只有一处**；判定为工作流时草稿交 [03-L1 §4](03-L1-能力底座-Skills与MCP.md) 的接收面，其接受 / 微调 / 拒绝由 Studio 的**草稿会话**承载，L3 **不另造**一套工作流落盘或变更留痕。

## 9. 冲突裁决与反馈采集点

- L3 承接 `MemoryConflictDetected` 事件（01 §11），在对话中发起裁决（[04-L2 §4](04-L2-记忆图谱.md)）
- 所有推送/结论/建议的反馈入口（采纳/忽略/否定/追问/点赞）在交互层采集，产生 FeedbackEvent 交 [08-L6](08-L6-反思演进.md)

**落地口径**（2026-09-28 定案）：

- **裁决的承载形态是专用裁决卡**：含冲突两方内容（既有节点 / 新提案）、中性问句、可选方向候选与 `accept` / `reject` 两个动作——动作与 [04-L2 §4](04-L2-记忆图谱.md) 的裁决结果**一一对应**。**不复用** [§3.2](#32-澄清协议) 的意图确认卡：后者服务于**派发**（其条目另有同源面），裁决没有派发目标 Skill。
- **方向判定归 L3**：[04-L2 §1](04-L2-记忆图谱.md) 的 `thesis` 只有自由文本 `view`（无方向字段），「方向相反」在结构上不可判——故判定由 L3 经**注入的判定端口**承担，**缺省不注入即不判定**（卡上不给方向候选并显式标注「方向未判定」）。**L2 节点模型不增字段**（该口径解 [L2 册 `B1`](../../项目管理/遗留问题/L2-遗留问题.md) 的归属问题）。
- **裁决只经 L2 的裁决面落地**：接受 → 新节点 + `evolves_from` 边、拒绝 → 丢弃并记录，一律经 [04-L2 §4](04-L2-记忆图谱.md) 的裁决面且 `confirmed_by` 恒为 `user`；L3 **不自行改写图谱、不绕过该面、不另存一份裁决记录**（落盘归 L2 的 `execution_log` 分区）。**非 `pending` 的提案不得重复裁决**，显式失败而非吞错。
- **`memory_op` 去向**即接上文两条：由 [§4](#4-任务派发总线) 的「去向尚未接入」口径转为实际执行；**未注入裁决面时仍 fail-closed**（`unavailable` + 点名），不伪造。
- **反馈由交互层采集并产生 `FeedbackEvent`**（[08-L6 §1](08-L6-反思演进.md) 六字段），经 `FeedbackRecorded` 事件（01 §11）交 L6；**`feedback_id` 的产生方据此为交互层（L3）**（[01 §1](01-平台共享契约.md) 同批订正）。**L3 不建反馈存储**——反馈全部进 L6 的反思数据池（`reflection` 分区），L3 **只产事件**；未注入事件接收面时**显式标注未送达 + 点名归属任务**，不假装送达、也不静默丢弃。否定类（`rejected`）的 `reason` **必填**（08 §1「否定类建议必填入口」），其余四类可选填；`target` 可取推送 `delivery_id` / 结论 `trace_id` / 建议 `change_id` 三类，按 [01 §1](01-平台共享契约.md) 的形态校验。

## 10. 自主查证循环（Agent 运行时）

`investigate`（[§3.1](#31-意图分类)）的派发目标是一条**运行时循环**——由模型在**授权闸门**内逐步选择调用哪个能力，而非执行预先声明的固定清单。本节登记该循环的**契约面**；机制取舍见 [D-090](../../项目管理/决策日志.md)，背景调研见 [Agent 自主能力调研报告](../Agent自主能力调研报告.md)。

**落点**（[D-090](../../项目管理/决策日志.md) ②）：循环本体住 **L3 自身**（`src/st_agent/l3/runtime/`）——**不新开层、不动 [铁律 7](../../项目管理/工程宪法.md)**。三条依据：L3 向下可直接取用 L1（执行面）与 L2（记忆）；向上一层（L4 / L6）经**既有鸭子端口**（[§4](#4-任务派发总线) 的 `deliberations` / `trainings` 同型）；「新开运行时层」已判为下策——横切面进层表＝把「不是第七层」反向编码（同 [D-060](../../项目管理/决策日志.md) 对表现层的裁法）。

**四段循环**（一轮）：

| 段 | 内容 |
| --- | --- |
| ① 出动作 | 模型据**工具目录**（[01 §2](01-平台共享契约.md) 描述体的投影，**唯一来源**）与已有证据，选定「调用某工具」或「结束」 |
| ② 过闸门 | 每个待执行动作先经**授权闸门**（[01 §7](01-平台共享契约.md) 的运行期授权条目）；仅 `autonomous-ok` 才自主执行 |
| ③ 执行 | 经 **L1 执行面**（`SkillRunner`）执行——参数 / 输入 / 输出 schema 核验、依赖 DAG、权限逐项核对、沙箱、留痕**全部沿用既有流水线**，循环**不绕过**其中任何一环。实参按描述体分**两条通道**填入：`parameters` 的标量走 `values`，`input_schema` 声明的对象走 `inputs`（[01 §2](01-平台共享契约.md)）；两处都未声明的键交 L1 显式拒绝，**不静默丢弃** |
| ④ 回填 | 结果（超阈值者**截断 + `log_ref` 指针**，见 [01 §5](01-平台共享契约.md) 的日志入口）回到循环**工作上下文**，进入下一轮 |

**循环工作上下文**：任务 + 工具目录 + 已执行动作与结果 + **近端会话历史** + **记忆切片**（后两者 2026-10-28 增补，[D-142](../../项目管理/决策日志.md)）。历史与记忆取自 [§1](#1-会话模型) 会话上下文装配的**两个产出**，作为**独立字段**并入——**不把会话上下文本身当工作上下文**：两者内容与消费者不同，可共用预算口径，但装配逻辑不同，**不得互指为同一件**。两段**空态显式**成行（「无更早消息」/「无可用记忆」），不静默省略——否则模型分不清「没有」与「没注入」。

**规模预算与超限取舍**：工作上下文受 [01 §7](01-平台共享契约.md) 的 `investigate.context_budget` 约束。超限时按**声明顺序**取舍并**如实标注被舍项**：先舍**记忆切片**，再舍**历史消息（自旧向新）**；**任务与工具目录恒保留**，**已执行动作与结果不丢弃**（[D-090](../../项目管理/决策日志.md) 冻结范围：本期不压缩）。取舍后仍超限则如实标 `over_budget`，不静默截断、不假装装得下；被舍项进运行报告与留痕（[铁律 5](../../项目管理/工程宪法.md)：可解释）。

**上界与终止**（[D-090](../../项目管理/决策日志.md) ⑥）：**步数与 LLM 调用次数双上界**，到界即终止并**如实标注「达到上界」**，不假装完成；模型自行给出「结束」亦终止。上界是**可配置项**（[01 §7](01-平台共享契约.md) 登记：`investigate.max_steps` 与 `investigate.max_llm_calls`，缺省 8 / 12）——可经对话或面板通道调整、变更留痕、可回滚；但它**不是意图级参数**（[§3.2](#32-澄清协议)），故 `investigate` 的确认卡仍只有「意图」一条目。

**计划原语（`sk_plan_update`）**：模型可显式维护本次查证的步骤计划（每步 `title` + 状态 `pending` / `active` / `done`），计划进工作上下文并在工作上下文里单独成段渲染；**空计划即显式清空**，不与「尚未给出计划」混同（两态在渲染上有不同文案）。计划更新是**决策**：[01 §4](01-平台共享契约.md) 的 Trace 步骤口径**不为它新造步骤**，也不产 `skill_run` 记录；其状态落 `agent_run` 留痕（步数与内容可审计）与描述槽（可渲染）。计划形态非法（非数组 / 步缺 `title` / 状态不在枚举）时，循环**不终止**，把原因写入工作上下文供模型下一轮纠正——到上界仍未纠正即按上界终止。该原语仍**逐步过授权闸门**（与其余工具同一形态），出厂清单标 `autonomous-ok`（无副作用，[01 §7](01-平台共享契约.md)）。

**提问原语（`sk_ask_user`）**：循环发现缺少关键参数、或无法在给定信息下收敛时，模型调用该原语**终止并交还结构化问项**——一问一参（`parameter` + `prompt`），可带取值域（`choices`）与默认值（`default`），并可选带方向候选（`directions`）。问项口径沿用 [§3.2](#32-澄清协议)：**≤ 3 问**；模型多给时保留前 3 条、其余**显式记入**交还说明（不静默丢）；问项形态非法（缺参名 / 缺问句，或零问项且无方向候选）时按同一原因显式终止，不猜、不臆造问项。该终止的终止原因为**「待用户输入」**（`needs_user_input`，与 `needs_confirmation` 并列的不同原因），产出为**结构化描述**（`ok` 载荷携带问项；[01 §5](01-平台共享契约.md) 的六态无「待输入」态，`empty` 已用于「无载荷」的交还）。该原语同样过闸门，出厂清单标 `autonomous-ok`。

**取数与同步原语（2026-10-29 增补，[D-145](../../项目管理/决策日志.md)）**：M8 的能力面只能「如实告知数据现状」，缺数据时无路可走；本节补三条原语，把 [02 §5](02-L0-本地优先基座.md) 的同步 / 取数面接进循环——**不新增取数通道**，落库、水位、防封与出网审计全部沿用既有引擎。

- **`sk_data_sync`（后台触发）**：按**数据集 id** 发起同步批次，返回 `job_id` / `state` / `order` / `auto_added` / `estimate`；已有批次运行时**显式拒绝**（不并发）。缺省不等待，可给 `wait_seconds` 等待；超时仍如实回运行态。它是**写类动作**，出厂清单判必须协作——循环碰到它即按本节「授权闸门与交还」交还，续跑时用户确认后再执行。
- **`sk_data_fetch`（同步取数）**：按数据集 id **同步**取一批（与后台批次共用单飞锁），落缓存并以 `sync_state` 的最后成功时间作 `as_of`；未登记数据集走 `unavailable` 并点名。它写缓存、出网，同属**写类动作**，需确认。逐码数据集缺省取关注池，显式给定才发现全市场 / 自定义代码集。
- **`sk_docs`（文档三面 + 一致性核对）**：`operation` ∈ `list` / `read` / `search` / `audit`；前三个对应 [`LocalDocSource`](../../src/st_agent/l0/info/docs.py) 的既有面，`audit` 报「表在而文件缺」（损坏，`unavailable`）与「文件在而表缺」（孤儿，标可回收）。只读本地缓存，出厂清单标 `autonomous-ok`；**回收删除不在工具面**。

三条原语的工具描述即模型可见形态，**受本节工作上下文预算约束**；工具数增加后按同一预算口径实测，必要时调整 `investigate.context_budget` 缺省（[01 §7](01-平台共享契约.md)）。产出仍走 `ResultEnvelope` 与既有渲染路径，不另造第二条。

**文件原语（2026-10-29 增补，[D-146](../../项目管理/决策日志.md)）**：让循环能读用户给的文件、也能把产出落成文件交付。范围由 [01 §10](01-平台共享契约.md) 的权限声明界定，原语不另造路径判据：

- **`sk_file_read` / `sk_file_glob` / `sk_file_grep`（只读）**：读工作区分区与导入收件目录内的文本；声明 `local_read:<workspace/**>` 与 `local_read:<inbox/**>`。`read` 支持 `offset` / `max_chars`，超出部分回 `truncated` + `next_offset`（截断不静默丢）；`glob` 只列路径；`grep` 逐行检索并跳过二进制 / 超大文件且计数。出厂清单标 `autonomous-ok`。
- **`sk_file_write`（写）**：落 [02 §2.1](02-L0-本地优先基座.md) 的 `workspace` 分区，声明 `local_write:<workspace/**>`；覆盖同名文件、经 `Store` 分区锁串行化（02 §2.4）。**不写导入收件目录、不写任意路径**。它是写类动作，出厂清单标必须协作——循环碰到它即按本节「授权闸门与交还」交还，续跑时用户确认后再执行。

文件原语的越界 / 未批准由 L1 沙箱拦截且**不执行原操作**（01 §10）；`ctx.sandbox` 未接线时原语显式 `unavailable` 并点名，不假装已访问。

**开放网络原语（2026-10-29 增补，T-AGT-015 批）**：让循环能搜、能抓，且每次出网可审、可关。两条原语都**只经** `ctx.gateway`（[02 §6](02-L0-本地优先基座.md) 的唯一出网口）发出，并先过 [01 §7](01-平台共享契约.md) 的 `web-egress/enabled` 开关：

- **`sk_web_search`**：按查询词调用已配置的第三方搜索（`search.provider` ∈ `brave` / `tavily`），返回带 `title` / `url` / `snippet` / `source` / `published_hint` 的结果与 `retrieved_at`。提供方或密钥未配置、开关关闭时走 `unavailable` 并给配置指引；**不静默降级**到其他通道。审计只记主机、目的与字节数，**查询词不进留痕**。
- **`sk_web_fetch`**：只允许 `web-egress/allowed-hosts` 名单内主机的 GET，把 HTML 抽成纯文本返回（附来源 URL 与 `fetched_at`）；名单外主机在发包前拦截。非文本 / 二进制 / 解码失败走 `unavailable`，**不返回乱码**；不自动跟随重定向。正文是**不可信数据**，只作证据引用，不得被当作指令执行。
- **风险分级**：两条原语出网，出厂清单**显式登记**为 `collaborative-required`（与 `skill.` 通则同判；写死口径，不靠「未被单独列出」兜底）。出网开关关闭时两条原语不可用且**不发起任何请求**——它与审计开关（管留痕）不是同一件。

**本地命令原语（2026-10-30 增补，T-AGT-016 批）**：让循环在本机执行一次性命令——「系统没预设也能干」的终极手段。它比写文件与出网**风险更高**，故设两道独立的门：

- **`sk_run_command`**：参数 `command` / `timeout_s` / `max_output_chars`，返回 `exit_code` / `stdout` / `stderr` / `truncated` / `timed_out` / `duration_ms`。执行路径唯一：`ctx.sandbox.run_command`——先由 L1 沙箱核对本 Skill 的 `exec_command` **已声明且已批准**（[01 §10](01-平台共享契约.md)），越界 / 未批准一律拦截且**不执行**。
- **开关**：[01 §7](01-平台共享契约.md) 的 `local-exec/enabled` **缺省关**；关闭时在触碰执行器之前 `unavailable` 且**零执行**、零留痕。
- **执行口径**：一次性 shell（无交互 stdin），每次在一次性临时工作目录中执行并清理；超时终止进程并显式标 `timed_out`（走 `failed`）；stdout / stderr 各自按上限截断。cwd 是**起始目录而非文件系统 jail**——命令进程仍可访问当前用户可访问的路径（进程级隔离未实现，与 [02 §6](02-L0-本地优先基座.md) 的 stdio MCP 子进程同一已知边界）。
- **留痕**：每次执行落 `execution_log/exec-command/` 一条（命令文本截断 2000 字符、cwd、退出码、耗时、超时 / 截断标志、发起方与 trace；不记 stdout / stderr 正文）。
- **风险分级**：出厂清单**显式登记**为 `collaborative-required`（最高风险，逐次确认后再执行；写死口径，不靠「未被单独列出」兜底）。

**工具检索与延迟加载（2026-10-31 增补，[`T-AGT-017.1`](../../项目管理/tasks/T-AGT-017.1-工具检索与延迟加载.md)）**：工具目录的**模型可见形态**超过阈值时，不再整份下发，只给「摘要索引 + 检索入口」，模型按需展开：

- **阈值**：目录模型可见形态的字符数**超过本次工作上下文预算**（[01 §7](01-平台共享契约.md) 的 `investigate.context_budget`）即进入惰性态；取值属实现口径（`run_agent_loop` 可注入覆盖）。未超阈值时装配输出**逐字节同前**，不多出任何条目。
- **摘要索引**：每条工具只给 `name` 与一行摘要（描述头部），完整描述与参数不占窗口；`tools` 通道只下发检索入口与**已展开**的条目。
- **检索入口 `sk_tool_search`**：参数 `query` / `limit`（1–10，缺省 5），按词法在 `name` + `description` 中匹配（全部词元命中、`name` 命中优先），把匹配条目**展开**进后续轮次；未命中 / 参数非法给显式说明，不终止循环。
- **它不是能力登记**：检索入口是循环的**上下文控制**，只在惰性态进入可见面，不注册进 L1 能力目录（否则「未超阈值逐字节不变」不成立）；因此不产 `skill_run` / Trace 步，但检索记录**进 `agent_run` 留痕**（可审计）。
- **能力安全**：展开的条目仍是 [01 §2](01-平台共享契约.md) 的同一份注册面投影，权限 / 沙箱 / 留痕**无特例**；模型直接调用未展开的条目也照常过闸门与 L1 校验（摘要索引里已给出名字）。

**大结果外部化与回读（2026-10-31 增补，[`T-AGT-017.2`](../../项目管理/tasks/T-AGT-017.2-大结果外部化.md)）**：超阈值的单条结果不再只给「截断 + 指针」，而是给**可操作的回读指针**：

- **落盘与唯一真相源**：完整结果仍由 `SkillRunner` 落 `execution_log/skill-run/<skill_run_id>.json`（[03 §1](03-L1-能力底座-Skills与MCP.md)），**不复制字节、不新增分区**（[D-090](../../项目管理/决策日志.md) ⑧）。
- **指针形态**：工作上下文里的截断件带 `skill_run_id` / `next_offset` / `read_tool`，并附回读提示；预览仍是原载荷头部，**不伪装成完整结果**。
- **回读原语 `sk_result_read`**：参数 `skill_run_id` / `offset` / `max_chars`（缺省 2000、上限 8000），返回与预览同一确定性序列化的分片与 `next_offset`；`offset` 越界（负值或大于总长）→ `validation_failed`；记录缺失 → `unavailable`；非成功态无载荷 → `empty` 并说明。`skill_run_id` 按 [01 §1](01-平台共享契约.md) 的形态校验，**不接受任意路径**。
- **风险分级**：只读既有记录、无副作用，出厂清单显式登记为 `autonomous-ok`（[08 §5](08-L6-反思演进.md)）。

**并行工具调用（2026-10-31 增补，[`T-AGT-018.1`](../../项目管理/tasks/T-AGT-018.1-并行工具调用.md)）**：一轮模型可给出多个工具调用；循环按**调用顺序逐个过闸门**（在任何执行之前），全部为 `autonomous-ok` 才进入执行：

- **同轮执行**：单调用、或底层未声明并发安全时**串行**；底层声明并发安全（`parallel_safe`）时**并行**执行。工作上下文里的已执行动作与结果、以及 Trace 步均按**原调用顺序**回填，不随完成先后乱序。
- **并发安全的声明**：`parallel_safe` 由装配方显式给出，**缺省 `false`**——未声明即**显式退回串行**并在运行报告标注（`parallel_note`），不静默并发。组合根仅在核验底层后注入 `true`（`Store` 的分区级互斥见 [02 §2.4](02-L0-本地优先基座.md)、L1 执行面无可变共享状态、Trace 为追加式）。并行批只会包含 `autonomous-ok` 动作——写类 / 出网 / 命令遇到即交还，故不会并发写入。
- **任一被拒**：该步被拒，**整批不执行**并终止交还（`needs_confirmation` / `denied`），被拒步进 `pending`，交还说明点名「同轮其余 N 个调用未执行」，不静默丢。
- **步数预算**：一轮多调用按**多个动作**计步；`已执行步数 + 本轮可执行调用数 > 上界` 即按上界终止，整批不执行（单调用时与既有的「到界即停」等价）。

**子 Agent 与上下文隔离（2026-10-31 增补，[`T-AGT-018.2`](../../项目管理/tasks/T-AGT-018.2-子Agent上下文隔离.md)）**：探索型子任务可派生**一层**子 Agent，在隔离子上下文里跑：

- **原语 `sk_spawn_agent`**：参数 `task`（自洽的子任务描述）；模型经它派生子循环。派生是**无副作用**的循环控制动作，出厂清单显式登记为 `autonomous-ok`；子循环内的每一步仍**逐步过同一闸门**、经 L1 同一流水线执行与留痕。
- **子上下文**：只含子任务、同一工具目录（**剔除** `sk_spawn_agent`，故只允许一层）与同一记忆切片；**不含**主循环的历史、已执行步骤与计划。子循环另起一条 Trace，步骤不并入主链（[01 §4](01-平台共享契约.md)）。
- **只回传结论与引用**：子 Agent 的产出以「子 Agent 结果」段进入主工作上下文（结论 + 成功步的 `skill_run_id` 引用），**不**作为主链的 `skill_run` 步；引用并入主产出的 `evidence_refs`。子循环另落一条 `agent_run` 留痕并以 `parent_trace_id` 指回主链，供 `explain` 逐层展开。
- **预算归属**：子循环的双上界取父循环的**剩余预算**；子 Agent 消耗的步数（含派生本身一步）与 LLM 调用次数**计入父循环**的同一组上界，`agent_run` 以 `executed_steps` 记实际消耗。
- **失败**：子循环非 `finished`（含需确认、触界、端点不可用）时，主循环收到**显式失败说明**（终止原因 + 已收集引用），主循环**不终止**，可据说明改选其他能力。
- **留痕端口**：子循环的落痕由组合根注入的记录端口完成（L3 不持存储）；未注入端口时派生**显式不可用**，不假跑。

**授权闸门与交还**（[D-090](../../项目管理/决策日志.md) ⑦）：闸门与 [08 §5](08-L6-反思演进.md) 的演进授权**共用同一张风险清单**、**档位彼此独立**（[01 §7](01-平台共享契约.md)）。运行期档位**出厂缺省 `autonomous`**（2026-10-28，[D-143](../../项目管理/决策日志.md)），但只放开清单中**显式登记为只读**的动作（`skill.sk_local_sql` / `skill.sk_data_status` / `skill.sk_docs`）、**无副作用的循环控制原语**（`skill.sk_plan_update` / `skill.sk_ask_user` / `skill.sk_spawn_agent`，见本节上文）；写类 / 出网动作、未登记动作与 `memory.*` 红线照旧不放行。碰到**非** `autonomous-ok` 的动作时，循环**终止并把「下一步需确认」交还用户**——本期**不做**循环挂起与恢复（那要异步 + 状态持久化，与 [00 §1.1](00-架构总览.md) 后端常驻形态是可分离的两件事）。交还必须**显式**：如实告知已收集的证据与那一步未执行的原因，**不静默跳过、不把半程结果呈现为已完成**。

**一键续跑（轻形态）**：两种交还（`needs_confirmation` / `needs_user_input`）都可**续跑**——用户确认那一步、或回答问项后，以**新一轮循环承接前序证据**继续：前序各步由 `execution_log` 的 `skill_run` 记录重建（**不复制载荷**、不造第二真相源），前序不计入新循环的步数 / LLM 调用上界，计划沿上下文承接；`needs_confirmation` 的确认步**先执行**再继续，`needs_user_input` 的答案作为「用户补充」进工作上下文；**子 Agent 的结论与引用**同样从旧 `agent_run` 的 `sub_agents` 摘要重建（不重跑子步骤、不复制子步骤）。续跑产**新** `agent_run_id` 并以 `resumed_from` 指回旧留痕（`trace_id` 也是新链，旧链仍按旧 `trace_id` 展开）。**依据过期**（留痕写入时刻起 30 分钟，实现口径）时显式提示并允许**重跑**（原任务从头跑、不带前序）——不把旧证据当新证据。续跑**不引入挂起 / 恢复状态机**（同 [D-090](../../项目管理/决策日志.md) ⑦ / [D-137](../../项目管理/决策日志.md) D-4）。

**产出形态与中性边界**（[D-090](../../项目管理/决策日志.md) ⑩）：循环产出**结构化证据包**（`ResultEnvelope` 载荷：各步 `skill_run_id` 与输出、引用清单），**不是**自由文本结论——交**既有**渲染路径（[§6](#6-generative-ui) 的 UI 描述与组件注册表）呈现，**不另造第二条渲染路径**，故 [01 §6](01-平台共享契约.md) 执行点 2 自然生效。**模型的中间推理（为何选下一步）一律不外显**；**不得给出统一建议或方向研判**（[铁律 4](../../项目管理/工程宪法.md)）。

**留痕**：每一步经 L1 执行面**各产一条 `skill_run` 步**，故多步循环**天然得到一条完整 Trace**（[01 §4](01-平台共享契约.md)），[§7](#7-推理链可视化) 与 `explain` 去向可直接逐步展开；循环自身的 `agent_run_id`（[01 §1](01-平台共享契约.md)）记**步数 / 终止原因 / 上界**。**模型的选步决策不产生 Trace 步骤**（[01 §4](01-平台共享契约.md) 的步骤口径）——中间决策不外显，动作全可追溯。

**失败与降级**（[D-090](../../项目管理/决策日志.md) ⑨）：端点**不支持工具调用或不可用** → **fail-closed + 显式降级告知**（沿用 [§4](#4-任务派发总线) 的 `unavailable` 口径与中性降级文案），**不静默退回** `query` 的确定性路径——那会让用户把「没跑成自主查证」误读为「这就是自主查证的结果」；端点能力的**探测与声明**归 [02 §4](02-L0-本地优先基座.md)。单个工具失败**不终止**循环：该步**如实记为失败信封并回填**（模型可据此改选其他能力），**不静默略过该步**；最终产出里失败步**照实呈现、不得呈现为成功**。
