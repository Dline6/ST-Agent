# 05 · L3 对话主入口（Chat-as-OS）

承载 [Story 1](../PRD-v2-Agent/story-01-chat-as-os.md)。产品首页 = Chat 输入框 + 上下文卡片，无传统菜单；v1 全部功能都在对话中被触发。L3 是**唯一的用户交互主入口**（Studio、设置等为辅助界面），核心职责：会话管理、意图理解与澄清、任务派发、Generative UI、推理链可视化、对话即配置。

## 1. 会话模型

- 多轮、有状态、可回溯、可分支：会话为树状结构（任意消息可发起分支延续新话题）
- 对话历史存 L0 `chat_history` 分区：完全离线可查、可搜索、可导出 Markdown
- 会话上下文 = 当前会话消息 + [04-L2](04-L2-记忆图谱.md) 的 MemoryReader 切片（受 Token 预算约束）

## 2. 上下文卡片（首页常驻）

- 内容 = Memory 关键切片：持仓摘要、关注池、未读告警数、近期热点摘要、当前 thesis / 风险偏好（「副驾眼中的我」不超过 5 条关键标签，即偏好画像卡）
- 点击进入 [04-L2](04-L2-记忆图谱.md) 完整图谱
- 空状态（新用户无 Memory）：显示「你还没告诉我任何偏好，我们先聊两句？」引导 Onboarding

## 3. 意图理解与澄清协议

### 3.1 意图分类

| 意图类型 | 派发目标 |
| --- | --- |
| `query`（查询/看数据） | L1 Skill 调用 → 结果渲染 |
| `configure`（配置/盯盘/建流程） | 对话即配置（§5） |
| `analyze`（复杂决策分析） | 触发 [06-L4 Deliberation](06-L4-多视角推理.md)（经确认） |
| `memory_op`（表达偏好/修正记忆） | L2 写入或冲突裁决对话 |
| `train`（训练副驾） | [08-L6 训练对话协议](08-L6-反思演进.md) |
| `explain`（追问推理） | Trace 展开渲染 |

### 3.2 澄清协议

- 意图模糊（关键参数缺失）→ 副驾主动追问；**澄清预算 ≤ 3 个问题**，且每个问题可跳过（跳过用默认值继续）
- 意图过于模糊（无法收敛）→ 提供「3 个可能的方向」而非强行猜测
- 收敛后必须输出**意图确认卡**：「我理解到 3 件事：①…②…③…，对吗？」——用户确认后才执行

## 4. 任务派发总线

意图确认后派发执行；所有派发产生 `trace_id`（01 §4），执行结果以 ResultEnvelope 语义渲染（`ok` → 正常 UI；`empty` → 空状态文案 + 原因；`unavailable` → 数据延迟提示 + 最后更新时间；`failed`/`dependency_failed` → 错误态 + 日志入口）。LLM 端点不可用时显式降级告知，不静默失败。

## 5. 对话即配置（Config Draft）

「一句话 → Skill/工作流 配置草稿」的契约：

| 字段 | 说明 |
| --- | --- |
| `target` | 目标 Skill / 工作流（新配置或修改既有配置） |
| `parameter_draft` | 从对话提取的参数值（对齐 SkillDescriptor.parameters） |
| `understanding_summary` | 结构化理解摘要（「我理解到 N 件事」的内容源） |
| `open_questions` | 未澄清参数（供追问或标注默认值来源） |

流转：草稿 → 用户接受（配置生效并产生 `change_id`）/ 微调（进入参数面板）/ 拒绝（丢弃并可选记录原因进反馈池）。工作流草稿对象传递给 [03-L1 Skill Studio](03-L1-能力底座-Skills与MCP.md) 落画布可视化微调。配置草稿生成与编辑共用 01 §7 配置注册表，保证对话通道与面板通道效果一致。

`target` 为工作流时，草稿在上表四字段之外**另携** `workflow_draft` 子对象（`name` / `description` / `nodes` / `edges` / `groups` / `schedule`，可含 ASCII `flow_name`）承载结构与暂定名——身份字段 `flow_id` / `version` **不在草稿中**，由 Studio 侧「接受」派生。落画布与接受的完整口径见 [03-L1 §4](03-L1-能力底座-Skills与MCP.md)。

## 6. Generative UI

- 对话中按需生成看板/图表/卡片/回测报告；**结构约定**：LLM 产出「结构化 UI 描述」（组件类型 + 数据绑定 + 布局提示），前端渲染器解析描述并渲染——渲染器维护**组件类型注册表**（表格、趋势图、热力图、分歧图、风险徽章、报告卡等），不解析任意代码
- 生成物可「钉」到工作区 → 变为持久组件（记录数据绑定与 `as_of`，数据更新时可刷新）
- 交互能力：钉住物支持刷新、下钻（跳转 Trace 或 Skill 详情）、取消钉住
- Studio 首页的**模板库卡片**与**空状态**（无自建工作流时：模板库 + 一句话入口）由 L1 提供、L3 只渲染——数据源为 `TemplateSummary`（名称 / 说明 / 节点数 / 引用 Skill 清单 / 缺失 Skill 清单）与 `StudioHome`（`templates` + `one_line_entry` + `is_empty`），口径见 [03-L1 §4](03-L1-能力底座-Skills与MCP.md)

## 7. 推理链可视化

- 每条回答附「推理链」入口，展开 Trace（01 §4）：调用了哪些 Skill → 读了 Memory 哪些片段 → 汇总了哪些视角 → 结论；每一环可点开细看（输入快照、输出、耗时、依赖）
- Trace 视图与 [06-L4 视角追问](06-L4-多视角推理.md)、[08-L6 反思报告](08-L6-反思演进.md) 复用同一渲染组件

## 8. 快捷指令

- `/` 触发的命令注册表：`/盯盘` `/回测` `/压测` `/今日看板` `/反思` 等；每个指令 = 预置意图模板（跳过部分澄清步骤）
- 注册表 schema：指令名、描述、意图模板、参数预填——可随官方 Pack 更新，命名过中性化校验（01 §6）

## 9. 冲突裁决与反馈采集点

- L3 承接 `MemoryConflictDetected` 事件（01 §11），在对话中发起裁决（[04-L2 §4](04-L2-记忆图谱.md)）
- 所有推送/结论/建议的反馈入口（采纳/忽略/否定/追问/点赞）在交互层采集，产生 FeedbackEvent 交 [08-L6](08-L6-反思演进.md)
