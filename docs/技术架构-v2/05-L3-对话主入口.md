# 05 · L3 对话主入口（Chat-as-OS）

承载 [Story 1](../PRD-v2-Agent/story-01-chat-as-os.md)。产品首页 = Chat 输入框 + 上下文卡片，无传统菜单；v1 全部功能都在对话中被触发。L3 是**唯一的用户交互主入口**（Studio、设置等为辅助界面），核心职责：会话管理、意图理解与澄清、任务派发、Generative UI、推理链可视化、对话即配置。

## 1. 会话模型

- 多轮、有状态、可回溯、可分支：会话为树状结构（任意消息可发起分支延续新话题）
- 对话历史存 L0 `chat_history` 分区：完全离线可查、可搜索、可导出 Markdown
- 会话上下文 = 当前会话消息 + [04-L2](04-L2-记忆图谱.md) 的 MemoryReader 切片（受 Token 预算约束）

## 2. 上下文卡片（首页常驻）

- 内容 = Memory 关键切片：持仓摘要、关注池、未读告警数、近期热点摘要、当前 thesis / 风险偏好（「副驾眼中的我」不超过 5 条关键标签，即偏好画像卡）
- 六项各占**一段**（段序与段名固定）：数据来源未就绪的段以「不可用 + 原因」呈现，**不静默留空、不用其他数据顶替**
- 点击进入 [04-L2](04-L2-记忆图谱.md) 完整图谱
- 空状态（新用户无 Memory）：显示「你还没告诉我任何偏好，我们先聊两句？」**（示例措辞；含第一人称，实现按铁律 2 中性改述）**引导 Onboarding
- **中性措辞**：卡片名、引导语、空状态提示等**本层自有**固定文案一律按铁律 2 中性改述（渲染前过 01 §6 执行点 2）；**记忆本体内容**（用户原话与推断记录）属数据展示，**不过**输出校验、原样呈现——见 [D-053](../../项目管理/决策日志.md)

## 3. 意图理解与澄清协议

### 3.1 意图分类

| 意图类型 | 派发目标 |
| --- | --- |
| `query`（查询/看数据） | L1 Skill 调用 → 结果渲染 |
| `configure`（配置/盯盘/建流程） | 对话即配置（§5） |
| `analyze`（复杂决策分析） | 触发 [06-L4 Deliberation](06-L4-多视角推理.md)（经确认） |
| `memory_op`（表达偏好/修正记忆） | L2 写入或冲突裁决对话 |
| `train`（训练副驾） | [08-L6 训练对话协议](08-L6-反思演进.md) |
| `explain`（追问推理） | Trace 展开渲染 |

### 3.2 澄清协议

- 意图模糊（关键参数缺失）→ 副驾主动追问；**澄清预算 ≤ 3 个问题**，且每个问题可跳过（跳过用默认值继续）
- **澄清问项的来源**（2026-09-28 定案）：一条问项 ＝ 目标 Skill 的 [`SkillDescriptor.parameters`](01-平台共享契约.md) 中**未给出值**的一项（一问一参、问句与取值域取自该 `ParameterSpec`）；「跳过」即取该参数的 `default`。超出澄清预算的未澄清项**以默认值填充**，并在确认卡上标注其来源为默认值——不静默替用户决定
- **无 target Skill 的意图**（2026-10-04 补）：`analyze` 等意图**没有**被调用的 Skill（[§3.1](#31-意图分类) 的派发目标是整条 [06-L4](06-L4-多视角推理.md) 流程，非某个 Skill），其问项取自**意图级参数声明**——形态与问项来源规则同上一行（一问一参、取值域取自该 `ParameterSpec`、跳过取 `default`、超预算落默认值并标注），只是承载者不是 `SkillDescriptor` 而是该意图自身的参数声明（实现表见代码）。这是 [06 §2.1](06-L4-多视角推理.md)「询问模式（快速 / 深度）」的落点：未给出 `mode` 时按同一规则生成问项，而非由实现自行挑一个模式
- 意图过于模糊（无法收敛）→ 提供「3 个可能的方向」而非强行猜测；方向候选**取自意图理解产物**（本层只裁剪到 ≤3 条并按铁律 2 中性改述），理解不可用时走 `unavailable` + 原因，**不拿无关来源充数**
- 收敛后必须输出**意图确认卡**：「我理解到 3 件事：①…②…③…，对吗？」（**示例措辞；含第一人称，实现按铁律 2 中性改述**）——用户确认后才执行；卡的条目列表即 [§5](#5-对话即配置config-draft) `ConfigDraft.understanding_summary` 的**同一份**内容源，不另造第二份摘要
- **意图识别的实现口径**（2026-09-28 定案）：文本 → 六类意图的**理解**由**注入的理解端口**承担（缺省不注入即 fail-closed，走 `unavailable` + 原因）；快捷指令（[§8](#8-快捷指令)）命中时**短路**——直接取该指令的意图模板与参数预填，已预填参数不再追问

## 4. 任务派发总线

意图确认后派发执行；所有派发产生 `trace_id`（[01 §4](01-平台共享契约.md)）。

**去向与接入态**（2026-09-28 定案）：总线的路由表 ＝ [§3.1](#31-意图分类) 的六类去向。**尚未接入的去向不得伪造执行、也不得静默丢弃**——按 ResultEnvelope 的 `unavailable` 分支呈现，其 `reason` 必须点名**归属任务**（同 [§2](#2-上下文卡片首页常驻) 的「生产方未接入即 `unavailable` + 点名」口径）。

**接入进度**（2026-10-04）：逐去向的接入态由总线实现的路由表登记（每项含 `wired` 与未接入时的归属任务 id）。`query` / `configure` / `memory_op` / `explain` 于 M1 关卡接入；`analyze` 于 **M2 关卡（`T-INT-003`）**接入——经**组合根注入的编排端口**触发 [06-L4](06-L4-多视角推理.md) 的 Deliberation，**L3 不 import L4**（[铁律 7](../../项目管理/工程宪法.md)；`LAYER_ORDER` 为 `l3 < l4`），载荷按鸭子面透出（总线只认其中的 `ResultEnvelope`）；`train` 待 [08-L6](08-L6-反思演进.md)。

**结果渲染语义**（六态穷尽，机器可读映射见 §4 所述实现；`validation_failed` 一行为 2026-09-28 补入——原枚举遗漏该态）：

| status | UI 语义 | 必展示 |
| --- | --- | --- |
| `ok` | 正常 UI | —— |
| `empty` | 空状态文案 | 原因 |
| `unavailable` | 数据延迟提示 | **最后更新时间**、原因 |
| `dependency_failed` / `failed` | 错误态 | 原因、**日志入口** |
| `validation_failed` | 参数/输入校验失败态（**不允许保存**） | 理由 |

**LLM 端点不可用**：显式降级告知，不静默失败（降级文案按铁律 2 中性改述）；**不依赖 LLM 的去向不受牵连**，照常执行。

## 5. 对话即配置（Config Draft）

「一句话 → Skill/工作流 配置草稿」的契约：

| 字段 | 说明 |
| --- | --- |
| `target` | 目标 Skill / 工作流（新配置或修改既有配置） |
| `parameter_draft` | 从对话提取的参数值（对齐 SkillDescriptor.parameters） |
| `understanding_summary` | 结构化理解摘要（「我理解到 N 件事」的内容源） |
| `open_questions` | 未澄清参数（供追问或标注默认值来源） |

流转：草稿 → 用户接受（配置生效并产生 `change_id`）/ 微调（进入参数面板）/ 拒绝（丢弃并可选记录原因进反馈池）。工作流草稿对象传递给 [03-L1 Skill Studio](03-L1-能力底座-Skills与MCP.md) 落画布可视化微调。配置草稿生成与编辑共用 01 §7 配置注册表，保证对话通道与面板通道效果一致。

`target` 为工作流时，草稿在上表四字段之外**另携** `workflow_draft` 子对象（`name` / `description` / `nodes` / `edges` / `groups` / `schedule`，可含 ASCII `flow_name`）承载结构与暂定名——身份字段 `flow_id` / `version` **不在草稿中**，由 Studio 侧「接受」派生。落画布与接受的完整口径见 [03-L1 §4](03-L1-能力底座-Skills与MCP.md)。

**落地口径**（2026-09-28 定案）：

- **四字段的来源只有一处**——**已确认的意图确认卡**（[§3.2](#32-澄清协议)）：`target` 与 `parameter_draft` 取卡上的目标与已收敛取值；`understanding_summary` 取卡的**条目列表**（§3.2 定案：**同一份内容源**，不另造第二份摘要）；`open_questions` 取卡上**未澄清**的参数。**未经确认的卡不得生成草稿**（`validation_failed`）。
- **`open_questions` 逐条结构化**（参数名 / 问句 / 默认值 / 来源）：「来源」区分**已按默认值填充**（跳过或超澄清预算者）与**待追问**两类——前者同批进 `parameter_draft`，两类不混同、不静默替用户决定。
- **三态的落点**（面板与草稿卡的**渲染**归 [§6](#6-generative-ui) 的骨架任务与 [`T-L3-004`](../../项目管理/tasks/T-L3-004-GenerativeUI推理链可视化.md)）：

| 处置 | 落点 |
| --- | --- |
| 接受 | 经 [01 §7](01-平台共享契约.md) **登记面的写入端**落值并产生 `change_id`；L3 **不自行落** `config` 分区（否则绕过登记表，双通道会分叉） |
| 微调 | 返回**面板视图**（同一条 `ConfigEntry` 的 `panel_form_spec` + 当前值）；草稿态**不落盘** |
| 拒绝 | 丢弃、**不落盘**，`reason` 仅随返回值透传（反馈池归 [08-L6](08-L6-反思演进.md)） |

- **双通道同源**：同一个参数的对话描述与面板表单由**同一处解析**得出——该参数已登记到 [01 §7](01-平台共享契约.md) 时取同一条 `ConfigEntry`（`description_for_chat` / `panel_form_spec` / 默认值 / 生效范围）；**未登记**时两个通道**同样**回落到该参数的声明面（[01 §2](01-平台共享契约.md) 的 `ParameterSpec`：`description` + 由 `type` 映射的表单字段 / 默认值），并在视图上**标注解析来源**。**不出现**「一个通道取登记项、另一个取声明面」。描述体取数口与登记面**都没注入**时走 `unavailable` + 点名（「生产方未接入即 `unavailable` + 点名」的口径同 [§2](#2-上下文卡片首页常驻)）。**统一配置注册表门面已交付**（归属 L1，见 [01 §7](01-平台共享契约.md)；决策 [D-067](../../项目管理/决策日志.md)）——故「未接登记面」现只发生在**未装配**或**目标未知**时，而非门面缺席。
- **工作流分支的判定**：由**调用方随派发提供的结构载荷**判定（新草稿尚无 `flow_id`，无从按 id 形态识别），判据**只有一处**；判定为工作流时草稿交 [03-L1 §4](03-L1-能力底座-Skills与MCP.md) 的接收面，其接受 / 微调 / 拒绝由 Studio 的**草稿会话**承载，L3 **不另造**一套工作流落盘或变更留痕。

## 6. Generative UI

- 对话中按需生成看板/图表/卡片/回测报告；**结构约定**：LLM 产出「结构化 UI 描述」（组件类型 + 数据绑定 + 布局提示），前端渲染器解析描述并渲染——渲染器维护**组件类型注册表**（表格、趋势图、热力图、分歧图、风险徽章、报告卡等），不解析任意代码。描述的**结构契约**（字段与组件类型登记表）见 [01 §12](01-平台共享契约.md)
- **骨架归属**（[D-060](../../项目管理/决策日志.md)）：**前端工程骨架、组件类型注册表宿主与本地服务通信面**由跨层工程任务 [`T-UI-001`](../../项目管理/tasks/T-UI-001-表现层骨架与本地服务通信面.md) 承载（进程形态见 [00 §1.1](00-架构总览.md)）；本层负责**产出**符合该描述契约的 UI 描述（生成流程见 [§3.1](#31-意图分类)），并声明 L3 特有组件（分歧图 / 推理链 / 上下文卡片等）的行为口径——[`T-L3-004`](../../项目管理/tasks/T-L3-004-GenerativeUI推理链可视化.md) `depends_on` 该骨架任务
- 生成物可「钉」到工作区 → 变为持久组件（记录数据绑定与 `as_of`，数据更新时可刷新）
- 交互能力：钉住物支持刷新、下钻（跳转 Trace 或 Skill 详情）、取消钉住
- Studio 首页的**模板库卡片**与**空状态**（无自建工作流时：模板库 + 一句话入口）由 L1 提供、L3 只渲染——数据源为 `TemplateSummary`（名称 / 说明 / 节点数 / 引用 Skill 清单 / 缺失 Skill 清单）与 `StudioHome`（`templates` + `one_line_entry` + `is_empty`），口径见 [03-L1 §4](03-L1-能力底座-Skills与MCP.md)

## 7. 推理链可视化

- 每条回答附「推理链」入口，展开 Trace（01 §4）：调用了哪些 Skill → 读了 Memory 哪些片段 → 汇总了哪些视角 → 结论；每一环可点开细看（输入快照、输出、耗时、依赖）
- Trace 视图与 [06-L4 视角追问](06-L4-多视角推理.md)、[08-L6 反思报告](08-L6-反思演进.md) 复用同一渲染组件

## 8. 快捷指令

- `/` 触发的命令注册表：`/盯盘` `/回测` `/压测` `/今日看板` `/反思` 等；每个指令 = 预置意图模板（跳过部分澄清步骤）
- 注册表 schema：指令名、描述、意图模板、参数预填——可随官方 Pack 更新，命名过中性化校验（01 §6）
- **意图模板**取 §3.1 的六类意图（`query` / `configure` / `analyze` / `memory_op` / `train` / `explain`）；该枚举的机器可读副本由 L3 维持，§3.1 是唯一出处
- **条目按来源分组**（官方 / 用户），**按来源整组替换**即「随官方 Pack 更新」的 L3 侧；官方命令种子的那一端＝[01 §13 官方资源包](01-平台共享契约.md) 的 `command` kind（[03 §1](03-L1-能力底座-Skills与MCP.md) 的包结构，铁律 8）——官方 Pack 已泛化为**类型化官方资源容器**（[`T-L1-013`](../../项目管理/tasks/done/M2/T-L1-013-官方Pack泛化为类型化官方资源容器.md)），种子经注入 `register_source` 消费
- **参数预填**的键对齐 [01 §2](01-平台共享契约.md) `SkillDescriptor.parameters` 的声明名，值只做默认值覆盖——不新增参数类型

## 9. 冲突裁决与反馈采集点

- L3 承接 `MemoryConflictDetected` 事件（01 §11），在对话中发起裁决（[04-L2 §4](04-L2-记忆图谱.md)）
- 所有推送/结论/建议的反馈入口（采纳/忽略/否定/追问/点赞）在交互层采集，产生 FeedbackEvent 交 [08-L6](08-L6-反思演进.md)

**落地口径**（2026-09-28 定案）：

- **裁决的承载形态是专用裁决卡**：含冲突两方内容（既有节点 / 新提案）、中性问句、可选方向候选与 `accept` / `reject` 两个动作——动作与 [04-L2 §4](04-L2-记忆图谱.md) 的裁决结果**一一对应**。**不复用** [§3.2](#32-澄清协议) 的意图确认卡：后者服务于**派发**（其条目另有同源面），裁决没有派发目标 Skill。
- **方向判定归 L3**：[04-L2 §1](04-L2-记忆图谱.md) 的 `thesis` 只有自由文本 `view`（无方向字段），「方向相反」在结构上不可判——故判定由 L3 经**注入的判定端口**承担，**缺省不注入即不判定**（卡上不给方向候选并显式标注「方向未判定」）。**L2 节点模型不增字段**（该口径解 [L2 册 `B1`](../../项目管理/遗留问题/L2-遗留问题.md) 的归属问题）。
- **裁决只经 L2 的裁决面落地**：接受 → 新节点 + `evolves_from` 边、拒绝 → 丢弃并记录，一律经 [04-L2 §4](04-L2-记忆图谱.md) 的裁决面且 `confirmed_by` 恒为 `user`；L3 **不自行改写图谱、不绕过该面、不另存一份裁决记录**（落盘归 L2 的 `execution_log` 分区）。**非 `pending` 的提案不得重复裁决**，显式失败而非吞错。
- **`memory_op` 去向**即接上文两条：由 [§4](#4-任务派发总线) 的「去向尚未接入」口径转为实际执行；**未注入裁决面时仍 fail-closed**（`unavailable` + 点名），不伪造。
- **反馈由交互层采集并产生 `FeedbackEvent`**（[08-L6 §1](08-L6-反思演进.md) 六字段），经 `FeedbackRecorded` 事件（01 §11）交 L6；**`feedback_id` 的产生方据此为交互层（L3）**（[01 §1](01-平台共享契约.md) 同批订正）。**L3 不建反馈存储**——反馈全部进 L6 的反思数据池（`reflection` 分区），L3 **只产事件**；未注入事件接收面时**显式标注未送达 + 点名归属任务**，不假装送达、也不静默丢弃。否定类（`rejected`）的 `reason` **必填**（08 §1「否定类建议必填入口」），其余四类可选填；`target` 可取推送 `delivery_id` / 结论 `trace_id` / 建议 `change_id` 三类，按 [01 §1](01-平台共享契约.md) 的形态校验。
