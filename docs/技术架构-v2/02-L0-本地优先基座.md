# 02 · L0 本地优先基座

承载 [Story 5](../PRD-v2-Agent/story-05-local-first.md)。L0 是所有层的公共底座，提供五个子系统：**本地存储**、**密钥与凭据**、**LLM 调用抽象**、**数据源缓存**、**出网审计**，外加**备份/恢复/清空**生命周期能力。跨层公共类型见 [01-平台共享契约](01-平台共享契约.md)。

## 1. 职责边界

- L0 负责：一切本地持久化、加密、数据抓取与快照、LLM 端点抽象、全部出网请求的执行与审计、备份归档与彻底清空
- L0 不负责：任何业务语义（Skill 逻辑、记忆语义、触达策略均在上层）
- 依赖规则：上层**必须**经 L0 存储与出网，禁止层内直连文件系统或网络。**已知边界**：本地 stdio MCP Server 由 L1 拉起为独立子进程，其**自身**出网（子进程自开的 socket）**不在 L0 审计范围内**——进程内无法拦截；经网关的请求仍全部登记（§6）。缓解项：本地 stdio 是默认且唯一默认放行的传输、Server 由用户自选本地二进制、`network` 权限须逐项批准、Server 禁用即摘其全部 Skill（见 [03-L1 §5](03-L1-能力底座-Skills与MCP.md)）

## 2. 存储子系统

### 2.1 存储分区

本地数据按来源与生命周期划分为七个逻辑分区，物理组织由实现决定，但分区边界必须可独立导出、独立清空：

| 分区 | 内容 | 消费方 |
| --- | --- | --- |
| `memory` | 记忆图谱全部节点与边 | L2 |
| `config` | 配置注册表数据、Skill 参数、版本锁 | L1 / 各层 |
| `chat_history` | 对话历史（可搜索、可导出 Markdown） | L3 |
| `execution_log` | SkillRun、Trace、投递记录等执行留痕 | L1 / L5 / L6 |
| `reflection` | 反思报告、反馈事件、A/B 实验日志 | L6 |
| `data_cache` | 市场数据快照（公告/行情/龙虎榜/股东/舆情） | 全部 Skill |

`data_cache` 分区的首个落地形态是以 BaoStock 为首个数据源的本地市场数据库，库表结构、同步任务与新鲜度契约见 [数据库设计-BaoStock数据层](../数据库设计-BaoStock数据层/README.md)；后续数据源按该文档族的「多源扩展规约」接入。
| `secrets` | 密钥派生材料、API Key（加密） | L0 内部 |

### 2.2 加密要求

- **存储加密为可选项、默认关**（[D-073](../../项目管理/决策日志.md)）：新建存储不设口令即**明文落盘**、免口令读写；用户可显式开启加密，此时加密密钥由**用户主密码派生**（口令派生方案须采用业界验证的标准构造，具体算法由实现阶段安全评审确定，不在此锁定）
- **格式自辨**：存储根落一枚**明文**格式标记（格式名 + 版本 / 模式），**不含任何密钥材料**、人可读；打开存储先读它，再决定要不要口令、走哪条解密路径。调用方**不指定格式**。标记缺失的既有根按「加密」口径读（历史兼容；既有加密存储行为逐字节不变）
- **凭据恒加密**：`secrets` 分区**无论存储整体是否加密，一律加密落盘**，密钥材料不出现在其他分区；明文模式下其余分区免口令，**访问 `secrets` 时才要求口令**（惰性解锁）——故「存储整体免口令」不覆盖凭据。这是「默认不加密」最敏感的一处边界：凭据明文落盘按安全事件对待
- **明密双向转换**：任一根目录可按格式转换（**源不动、写新根**），兑现「要不要加密」这一选择的可逆性；转换**原样搬运** `secrets` 的密钥材料与密文，故**不改凭据口令**
- 产品方零接触：不设任何由产品方持有的恢复通道；**启用加密后**主密码丢失 = 数据不可恢复（须在 Onboarding 显式告知）

### 2.3 损坏恢复

- 任一分区校验失败 → 从最近备份恢复 + 明确告知用户损坏范围
- 无备份 → 明确告知丢失范围，进入冷启动流程（对应各层空状态设计）
- **「不加密」不等于「不校验」**：明文模式**照旧保留**逐文件校验和（SHA-256）、分区清单与原子替换——降的是机密性，不是完整性 / 一致性；文件被篡改或丢失仍按上两条报损坏

### 2.4 并发访问口径

- **同一进程内**：存储句柄对**同一分区**的并发读写必须安全——写入之间串行化（不得因并发写而丢失清单条目），读取不得观察到「清单登记与文件内容配对不一致」的中间态（否则会误报损坏）。
- **分区间隔离**：一个分区的写入不得阻塞其余分区的读写——隔离粒度与 §2.3 的单分区损坏隔离一致。
- **不保证范围**：多个进程同时打开同一根目录（如应用与长跑脚本并存）不在保证范围内；需要并存时由上层约定单一写者，或各自使用独立根目录。**本项目的单一写者已定案**（[D-060](../../项目管理/决策日志.md)）：**常驻后端进程**是全部存储的唯一写者；UI（浏览器或桌面壳）**只经 IPC 取数、不直开存储**——二者不同时打开同一根目录，故不落入本「不保证范围」。
- **落盘原子性**：清单与文件内容的更新须原子替换——进程中断只能留下「完整旧版本 + 无害残留」，不得留下被当作有效状态读取的半截文件。中间产物的崩溃残留须在**下次打开存储时回收**（不得无限累积），且中间产物不得落在分区目录内、以致污染分区边界。

## 3. 密钥与凭据子系统

- LLM API Key、SMTP 凭据、Webhook URL 等敏感凭据全部存 `secrets` 分区（加密 + 界面掩码显示）
- `secrets` **恒加密**、**惰性解锁**：明文模式下口令由**首次解锁时设定**（此后错口令拒开）；加密根在打开时若给出的主密码同时满足凭据校验锚，则据其**一并解锁**，否则凭据保持锁定——故**凭据口令可与主密码不同**（明密转换的产物即此形态；转换原样搬运凭据材料与密文，**不改凭据口令**）。未解锁时对该分区的读写失败须**显式**（不静默当作空）
- 提供**凭据使用记录**：任何凭据被使用的时刻、目的、数据量可查——支撑「Key 泄露自查 + 随时吊销重设」
- 凭据绝不出现在 Trace、日志明文、导出物中

## 4. LLM 调用抽象（LLM Endpoint）

对上层提供统一端点接口，屏蔽「云端多家 / 本地推理」差异：

| 接口能力 | 说明 |
| --- | --- |
| 能力协商 | 端点声明自身能力档位（上下文规模、结构化输出支持等），上层按档位降级 |
| 流式返回 | 统一流式协议；中断/超时显式上报 |
| 失败语义 | 返回 ResultEnvelope（01 §5）；端点不可用时上层按 §7 离线分级降级 |
| 用量报告 | 每次调用的 token 用量对用户可见（本地统计，不外发） |
| 零中转 | 云端端点由用户自带 Key **直连** LLM 提供方；产品方不中转、不留存任何 prompt/response |
| 多端点并存 | 用户可配置多个端点并指定优先级/用途（如「日常用云端、敏感数据仅用本地」） |

## 5. 数据源缓存子系统

- **首次运行联网全量抓取**建立本地缓存；此后增量更新（各数据源频率以其公开可得为准，产品非实时行情系统）
- 每次抓取产生 `dataset_snapshot_id`（01 §8）；历史数据离线可查
- 数据源逐个可开关（如禁用舆情抓取）；某源不可用时该维度结果走 `unavailable` 分支并标注最后更新时间
- 抓取请求全部经 §6 出网网关

首个数据源为 BaoStock（行情/财务/公司报告/板块/宏观五域），其落地形态已细化至可执行 schema 与同步任务清单：[数据库设计-BaoStock数据层](../数据库设计-BaoStock数据层/README.md)。两处文档的分工：本文定义缓存子系统的**职责与边界**（快照、开关、降级、审计），数据库设计文档定义**库表结构、字段映射、同步水位与逐表新鲜度契约**。落地要点：

- `dataset_snapshot_id` 锚定于数据库的同步任务状态表（`sync_state` 的各任务水位与成功时间组合），取其**确定性摘要**（形态 `snap_` ＋ 20 位十六进制，**长度有界**——`MarketDb.snapshot_id()`；可读水位原文经 `MarketDb.snapshot_components()` 取，供复核，见 [D-033](../../项目管理/决策日志.md)）；`as_of` 按数据域取该域数据的实际截止时间；**一域多源时取各源水位的保守下界（`min`）**——该域数据只完整到最慢那条源，取 `max` 会让新源的水位掩盖旧源的陈旧（见 [数据库设计 §多源扩展规约](../数据库设计-BaoStock数据层/00-设计总览.md) 与 [D-030](../../项目管理/决策日志.md)）
- 「数据源逐个可开关」的开关状态属于配置注册表（01 §7）职责，不落数据库；数据库仅登记数据源（`data_source`）与任务状态
- **文本类信息以「表行＋文件」两段承载**（公告正文 / 舆情问答 / 新闻等）：正文落 `data_cache` 分区的文本目录、经 `Store` 加密落盘（逐文件 digest + 分区级校验），表行存可查询的元数据，两段**同源同现**。Skill **不直读文件**，一律经 L0 的**文档取数面**消费（与 `MarketDb.query` 同构）——缓存数据的读取属数据访问，不在 `local_read:<path-scope>` 权限范围内（该权限针对缓存外文件）。**检索类派生数据（含 RAG 索引）不是事实源**，可由文件重建，不参与 `as_of` / 快照口径（见 [数据库设计 §多源扩展规约](../数据库设计-BaoStock数据层/00-设计总览.md) §2 与 [D-031](../../项目管理/决策日志.md)）
- 「标注最后更新时间」直接消费 `sync_state` 的水位与最近成功时间，不另行维护第二套口径
- **长跑与增量的执行面口径**（[T-L0-017](../../项目管理/tasks/done/M1/T-L0-017-BaoStock长跑能力分批写入断点续跑与重试退避.md)）：逐码任务（日线 / 周月线 / 复权因子 / 分红 / 财务 / 快报预告）以**只**为抓取单位，故三点须显式——① **写入批大小可配**：一次事务可覆盖多只码，因为 `MarketDb.transact()` 的固定开销是「整分区文件的一次加解密往返」，逐码提交会让全量长跑呈平方级（缺省＝逐码一次，行为不变）；② **窗口起点可显式给定**：这是「按码分片、可中断续跑」成立的前提（分片 2 不会被分片 1 推高的全库水位跳成空窗口），缺省仍按水位推导、水位语义不变；③ **可重试错误的退避重试**（网络 / 会话类）与**结果集截断复核**（行数恰为源端整页时复核一次，两次不一致即判失败——半截结果集与正常收尾同形，不复核就会静默入库）。**重试与复核每次都是一条独立的出网审计**（见 §6），不合并、不隐藏。
- **互补信息面（公告 / 龙虎榜 / 股东变化 / 舆情）的端点与语义口径以 [数据库设计 §05](../数据库设计-BaoStock数据层/05-同步策略与新鲜度契约.md) 为单一事实源**，本层不另立一套。三处易被误读、须显式声明：① **舆情问答双市并行互补（非主备）**——沪市上证e互动**有**全市场流（`feeds.do`）、可按窗口式节奏重拉；深市互动易**无**全市场流，改按**用户关注面**（`coverage=watch`：只采关注池 / 持仓内的标的，须由调用方注入关注池、默认禁用）——**池外标的恒为空 ≠ 该标的无舆情**，消费方不得据此下全市场结论（[D-037](../../项目管理/决策日志.md)）；② **`announcement.ann_type` 逐源语义不同、并非「公告内容类型」**——内容类型须走巨潮**请求侧 `category`**（[D-038](../../项目管理/决策日志.md)）；③ **股东户数是主备两源、且主源只给最新一期**——「重拉最近 8 个季度」的**逐季语义由备胎（巨潮按报告期）承担**，东财 `RPT_HOLDERNUMLATEST` 是 latest-only、每周实际重拉的只有最新一期；同键两源值不同时**主源胜出**（[D-041](../../项目管理/决策日志.md)）。

## 6. 出网审计（网络活动透明化）

**平台发起的一切对外网络请求必须经统一网关执行**，包括：数据源抓取、LLM 调用、触达渠道（SMTP/Webhook）、远程 MCP Server、官方 Skill 索引浏览。**「经网关执行」是硬的；逐次留痕（审计）为可选项、默认关**（[D-073](../../项目管理/决策日志.md)）：缺省构造的网关照常完成发起前校验 / 计时 / 结果映射 / 离线拦截 / 能力分级，只是**不落审计记录**。**已知边界**：由 L1 拉起的本地 stdio MCP Server 与 L1 之间走 stdin/stdout 管道（非网络），其子进程**自身**的出网不经网关、不在审计范围内（进程级网络隔离未实现，见 §1 依赖规则）；远程 Server 的请求不在此列。

- **开关**：审计开关是配置注册表（[01 §7](01-平台共享契约.md)）条目，缺省 `false`；变更即对后续请求生效（不需重启进程），并可导出 / 导入 / 版本化。
- **发包实现（sender）由调用方注入**：网关只负责**发起前校验 → 计时 → 落审计（开启时）→ 映射结果**，不含任何协议实现（HTTP / SSE / 各家差异均在 sender 内）。一次性形态（`execute`）与流式形态（`stream`）**同款支持按次注入**——「一次请求的载荷只能在这一跳组装」的调用方（如 LLM 的 prompt 与凭据）把内容放进**按次 sender 闭包**，网关全程**只见字节数**：内容不进审计、不落盘、不出现在导出物中。故「先校验、后发包」的次序与「零明文」的纪律**不因按次注入而改变**，也**不因批量落盘而改变**。
- **落盘形态（分段日志）**：审计记录按**段**落盘（一段装多条），使落盘写入次数与请求数**解耦**——逐次一文件会让每次写入重写整分区清单而呈 O(n²)（实测 ≈16 ms/次、n=3.7 万；见 [T-L0-018.2](../../项目管理/tasks/done/M1/T-L0-018.2-出网审计可选与落盘形态批量化.md)）。段的组织**不改记录内容、不改读接口**：查询仍按条件过滤、按时戳升序返回；带时间下界的查询可借段的时间有序性**跳段**，不必读全量历史。
- **关闭时的口径（显式化，不静默）**：审计关闭**只**去掉「以后记不记」这一条，**不影响**网关的其余职责——离线拦截仍生效（那是**功能**不是留痕）；**已记下的旧记录仍可读**（关的是以后，不是清除）；「待补发」一类查询在关闭时走**显式不可用**并写明原因，**不得**静默返回空集被读成「没有待补发」。失败信封的 `log_ref`（01 §5 要求非空）在关闭时取一枚显式哨兵 `net-audit:disabled`——既不空着、也不指向不存在的记录。

NetworkEvent 记录结构：

| 字段 | 说明 |
| --- | --- |
| `timestamp` / `initiator` | 时间与发起方（系统组件 / skill_id / mcp_server_id） |
| `target_host` / `purpose` | 目标主机与目的（人可读） |
| `bytes` / `status` | 数据量与结果 |

要求：**审计开启时**，设置-网络活动面板展示过去任意时段全部请求、可导出；断网时该面板仍可查历史（读本地分区）。**审计关闭时**面板显示「审计未开启，无记录可查」——三种态（开启且有记录 / 开启但无记录 / 未开启）必须可区分，不得合并成同一种空态。

## 7. 离线能力分级

每项平台能力声明 `offline_level`，产品在离线模式下按声明渲染「可用/受限/不可用」清单：

| 级别 | 语义 | 示例 |
| --- | --- | --- |
| `full` | 断网完全可用 | Memory 读写、已缓存数据查询、本地通知、对话历史检索 |
| `degraded` | 可用但受限（明确标注） | 云端 LLM 依赖的功能降级到本地推理端点（若已配置）；数据停留在最后快照并标注过期 |
| `none` | 必须联网 | 新数据抓取、远程 MCP、云端渠道投递 |

离线模式横幅须列出三类清单；网络恢复后云端渠道补发（用户可关闭补发）。

## 8. 备份 / 恢复 / 完全清空

### 8.1 备份归档

- 「一键备份」产出**单个加密归档文件**，包含 memory / config / chat_history / reflection 四个分区（data_cache 可选包含）+ 归档清单（manifest：各分区版本、校验和、创建时间）
- **归档恒为加密容器**（[story-05](../PRD-v2-Agent/story-05-local-first.md)「单个加密文件」这条硬指标**不随存储整体默认不加密而放宽**）：归档有独立 salt 与密码校验锚，密码即用户重输的主密码；源存储是明文根时，归档仍以该密码加密——故「备份文件落到存储根之外」也不泄明文。**恢复**产出的新根沿用归档口径（**加密**根）；恢复到既有根时按其格式标记分派（明文 / 加密），不擅自改格式——既有明文根若从未设过凭据口令，本次给出的口令即成为其凭据口令（该分区为空，不存在顶替；02 §3 的惰性解锁口径）
- **风险提示（须现于备份 UI）**：`data_cache` 未纳入归档时，其中的**档案型文本**（公告正文等）在**源端失效后不可重取**（抓取源随时可能下线）——即「不备份即不可恢复」。备份粒度**维持按分区**（`data_cache` 整体可选），**不**引入子路径粒度；若机制立项后证明文本体量可接受，再考虑改为默认纳入（见 [D-031](../../项目管理/决策日志.md)）。
- 归档格式与 [09-生态](09-生态与分享.md) 的分享文件格式同族（加密容器），但备份含私有敏感数据，分享文件强制过滤——两者不可混用

### 8.2 恢复

- 在任意设备导入归档 + 主密码 → 完整还原（含图谱结构、参数、历史对话）；恢复前校验完整性与版本兼容性

### 8.3 完全清空

- 「完全清空」须三次确认；删除范围 = 全部分区 + 派生数据 + 缓存 + 日志
- 清空后提示「备份文件位置由用户自行处理」；产品不保留任何残留

## 9. 数据留存策略

- 对话历史、执行日志的自动清理周期**可配**（配置项注册进 01 §7 注册表），默认值实现阶段定但须显式告知用户
- 反思报告与 Memory 不自动清理（演进依据）；备份归档永不自动删除
