# 07 · L5 主动触达（Ambient Delivery）

承载 [Story 7](../PRD-v2-Agent/story-07-ambient-delivery.md)。L5 把副驾产出主动送到用户面前，核心是**注意力预算管理**：默认策略「少而准」，每日报告为主叙事，实时告警为插入项。

## 1. 信号模型（Signal）

上游（L1 Skill 定时监控、L4 Deliberation、L6 反思建议）通过 `SignalEmitted` 事件投递信号：

| 字段 | 说明 |
| --- | --- |
| `signal_id` | 01 §1 标识；**不在事件负载内**——由 L5 采纳时按「投递内容的确定性摘要」铸造（同一信号重复投递得同一 ID），故发布方不分配 ID |
| `level` | `emergency` / `important` / `routine` |
| `content_ref` | 内容载体：`conclusion`（中性陈述式结论，**非单一视角的措辞**）+ `lens_stances[]`（逐视角摘要：`lens_id` / `stance` / `summary`）——**多视角并列保留、不合并分歧**（铁律 4） |
| `evidence_refs` | 证据引用（可解释性落点） |
| `dedup_key` | 去重合并键（见 §6） |
| `source_trace_id` | 溯源 |

负载结构（除 `signal_id` 外的五字段）**登记在 [01 §11](01-平台共享契约.md)**（2026-10-06）——发布方按它填、L5 按它采纳；缺字段 / 非法 `level` / 空结论 / 空逐视角摘要一律显式拒绝，不臆补。

**产生规则与产生点（2026-10-06 定案，[T-INT-004](../../项目管理/tasks/T-INT-004-M3集成关卡主动触达投递闭环.md)）**：

- 上游产出的**形态**（L1 的 `ScheduledRun`（`envelope` / `trace_id` / `skill_run_id`）、L4 的 `AnalyzeOutcome`）与本节的 `Signal` 负载之间**没有既定映射**——01 §11 登记的只是负载结构。故由 **L5 持一张声明式「产生规则」面**（[`st_agent.l5.sources`](../../src/st_agent/l5/sources.py)）：规则＝「哪个 Skill 的哪一类产出 → 哪一级信号 ＋ 逐项去重键取哪几个字段 ＋ 哪几个字段承载逐视角摘要」，求值是**纯函数**（同输入恒同事件序列，可离线复算）。
- **规则住 L5、不住产出层**：01 §11 的 `SignalEmitted` 负载结构本就由**订阅方（L5）**先行登记并由 `adopt_signal` 校验（同节），规则放同处才保「一种形态一份真相」；L1 / L4 因此**零改动**（只交出既有的运行结果与 `AnalyzeOutcome`）。
- **无 L4 阵容参与的产生点**（如 L1 定时监控）以**观察视角**承载摘要——`lens_id` 由本层铸造，本节只校验形态、不解析阵容（同 [§7](#7-推送疲劳监控) 疲劳询问的既有做法）。
- **产生点接线**（谁把规则接到 [01 §11](01-平台共享契约.md) 的投递面上）归里程碑关卡 [`T-INT-004`](../../项目管理/tasks/T-INT-004-M3集成关卡主动触达投递闭环.md) 的组合根；**未接线时不假装有信号**（同 01 §11「未接通不假装送达」）。

## 2. 注意力预算

- 配置结构：**情境 × 时段 × 内容类型** 三维矩阵，每格定义允许的触达级别与节奏（如「工作日盘中：仅 emergency」「早通勤：可看长内容」「周末：长周期回顾」）
- 情境模式：工作日 / 周末 / 出差 / 休假 / 紧急——手动切换或按日历自动
- 预算配置注册进 01 §7 注册表（对话可改 + 矩阵可视化面板可改）；配置完成展示「注意力预算地图」

**两轴口径（2026-10-06 定案）**：**时段＝时钟区间** `HH:MM–HH:MM`（支持跨零点，如 `23:00–07:00`）——故「每天早晨 8 点」这类用户配置与格位边界**同一口径**，不另立一套；**内容类型＝受控枚举** `long_form` / `brief` / `interactive` / `retrospective`（长内容 / 短提示 / 交互式 / 周期回顾），取值集合随官方 Pack 可扩，**不接受自由字符串**（错字会静默造出永不命中的空格位，与 [00 §6 失败显式化](00-架构总览.md) 相悖）。

**格位取值与落值面**：每格取值是一个**对象**（允许级别集合 + 节奏），按 [01 §7](01-平台共享契约.md)「取值为对象 / 列表的条目**不在统一标量落值面内**」的裁定——注册族为**只读声明面**（供对话与面板读出整张矩阵），**写面归 L5 的 `AttentionBudget` 自有 API**；配置落 `config/` 既有布局（路径由 `config_id` 点分派生），**不新造分区**。

**「按日历自动」的边界**：用户日历面尚未交付（本仓只有 L0 的市场交易日历，与用户日程无关），故本层只交付**手动模式切换**；按日历自动切换待该面就位后接入，期间**不假装有日历**（缺面即显式不可用）。

## 3. 渠道适配器（ChannelAdapter）

所有渠道实现统一适配器接口：`deliver(signal)`、`health()`、`degrade()`。渠道清单（全部本地适配器，凭据存 [02-L0 secrets 分区](02-L0-本地优先基座.md)）：

| 渠道 | 类型 | 离线行为 |
| --- | --- | --- |
| 桌面通知 / 系统托盘 | 本地 | 断网可用 |
| TTS 语音朗读 | 本地 | 断网可用（本地合成） |
| 邮件 | 云端（用户自带 SMTP） | 标注「离线，暂无法发送」，恢复后补发（可关） |
| IM Webhook（主流 IM 若干，用户自配） | 云端 | 同上 |

- 渠道偏好可配：每种信号级别对应哪些渠道
- 渠道失效（如 Webhook 不可达）→ 明确提示 + 自动降级到下一渠道
- 所有云端渠道请求经 L0 出网网关登记审计

**适配器形态与接入口径（2026-10-06 定案，[T-L5-002](../../项目管理/tasks/T-L5-002-渠道适配器投递编排与升级链.md)）**：

- **统一协议** `deliver(signal)` / `health()` / `degrade()`——三类返回一律**显式**（成功 / 不可达 / 未接线各成一支），不静默降级（[00 §6](00-架构总览.md)）。
- **本地渠道经注入的原生能力端口**——桌面通知与 TTS 各收一个鸭子类型端口（`send(title, body)` / `synthesize(text)`），由**组合根注入**：L5 是层，**不得** import 表现层（[`tests/test_layering.py` 的机器断言](../../tests/test_layering.py)）；原生通知的平台命令构造保持**单一份实现**（现住表现层，[T-UI-002.2](../../项目管理/tasks/T-UI-002.2-桌面壳本体窗口托盘自启与通知接线.md)）。真实实现取自表现层的 `ui.shell.notify`，由**生产入口**（唯一可同时 import `app` 与 `ui` 的模块，[T-UI-002.1](../../项目管理/tasks/T-UI-002.1-生产运行入口与壳后端握手协议.md)）注入——组合根自己不持平台分支实现（否则与表现层那份必然漂移）。**本仓无 TTS 面** ⇒ 该渠道在接线前走**显式不可用**，不假装能本地合成。
- **云端渠道经 [02 §6](02-L0-本地优先基座.md) 网关**以 `kind=channel_delivery` 发出（该出网类目早已在网关白名单），凭据取 [02 §3](02-L0-本地优先基座.md) `secrets` 分区、**只经 `CredentialVault.use()` 取明文**（明文不进网关、不进审计）。
- **渠道偏好的落值面**：「级别 → 有序渠道链」取值是**列表** ⇒ 按 [01 §7](01-平台共享契约.md)「取值为对象 / 列表的条目不在统一标量落值面内」，注册族为**只读声明面**（供对话与面板读出），**写面归 L5 的 `ChannelPolicies` 自有 API**（裁法同 [§2](#2-注意力预算) 的格位）。
- **离线与补发的依据（[L0 册 `A5`](../../项目管理/遗留问题/L0-遗留问题.md) 的收口口径）**：本地渠道断网照常（[02 §7](02-L0-本地优先基座.md) 的 `full` 档）；云端渠道**显式标注「离线，暂无法发送」**并记入**本层自持的待发清单**（`delivery_id` 留痕的 `pending_reconnect` 态）——**不以 L0 出网审计为补发依据**（审计是可选、默认关，[02 §6](02-L0-本地优先基座.md)；默认关时 `pending_reconnect` 按设计走显式不可用，故补发不能建在它上面）。网络恢复后按**用户开关**补发（可关）。

## 4. 投递编排与升级链

- 升级链状态机（按信号级别与用户配置）：如 emergency → 桌面通知 → 5 分钟未读 → 邮件 → 15 分钟未读 → IM（每级产生 `delivery_id` 留痕；升级参数可配）
- routine 信号默认**汇总进每日报告**，不单独推送（除非用户显式配置）
- 文案个性化：经 MemoryReader 读取用户风格偏好切片，同样信号对不同措辞（过 01 §6 中性化校验——个性化 ≠ 拟人化）

**升级链与编排口径（2026-10-06 定案，[T-L5-002](../../项目管理/tasks/T-L5-002-渠道适配器投递编排与升级链.md)）**：

- **链的构成**＝该级别 [§3](#3-渠道适配器channeladapter) 渠道偏好里的**有序渠道序列** + 每级**未读等待时长**（可配）。级次从 1 起、逐级推进；**每级产生一枚 `delivery_id`**（形态见 [01 §1](01-平台共享契约.md) 的确定性摘要 ⇒ 同一级重放 / 补发得同一 ID，升级链可安全重入），留痕落 `execution_log` 分区。
- **判定与推进都是显式时刻的纯函数**——`dispatch(signal, now)` 与 `advance(now)` 同输入恒同结论、不读系统时钟（时钟由调用方按次传入，取向同 [L1 调度器](03-L1-能力底座-Skills与MCP.md)），故升级链可离线重复验证。
- **未读超时即升级**并产生 `DeliverySettled`（含未读超时语义，[01 §11](01-平台共享契约.md)）；链尽仍未读 → 结算为「未确认」并按缺省**转入日报汇总**（见下条与 [§5](#5-每日报告主叙事形态)），**不丢弃**。「已读」由交互面的显式事件给出（反馈对象的 `delivery_id`，[05 §9](05-L3-对话主入口.md)）。
- **routine 路由**：带 [§2](#2-注意力预算) 的 `BudgetVerdict.dispatch="daily_report"` 的信号**不单独触达**——本层只记一条 `route="daily_report"` 的**待汇总项**（可被 §5 读出），**日报本体、去重合并与频控归 [T-L5-003](../../项目管理/tasks/T-L5-003-每日报告去重频控推送疲劳监控.md)**（§5–§6）。不单独推 ≠ 丢弃，也 ≠ 静默消失。
- **文案个性化**：经 [04-L2](04-L2-记忆图谱.md) 的 `MemoryReader` 读用户**风格偏好切片**，同一信号对不同用户取**不同措辞档**（不是不同人格——个性化 ≠ 拟人化，[铁律 2](../../项目管理/工程宪法.md)）；生成文案**过 [01 §6](01-平台共享契约.md) 执行点 2**，命中即阻断并记录，**不**把用户原话当生成文案复检（[D-053](../../项目管理/决策日志.md) 的切分）。

## 5. 每日报告（主叙事形态）

- 每天用户配置时间本地生成：「给你的信」= 昨日回顾 + 今日关注 + 多视角摘要 + Memory 更新摘要（无内容硬凑时明确写「今天没有需要打扰你的事」）
- 结构模板注册为配置（可订阅到任一渠道）；生成过程走完整 Trace
- 模板完整结构属 PRD 待澄清项，实现以配置注册表形式落地便于迭代

**生成与落盘口径（2026-10-06 定案，[T-L5-003](../../项目管理/tasks/T-L5-003-每日报告去重频控推送疲劳监控.md)）**：

- **只凭本层留痕 + 注入的记忆面组装**——待汇总项（[§4](#4-投递编排与升级链)）**连文案一起落盘**（[`delivery_store.py`](../../src/st_agent/l5/delivery_store.py) 的「留痕自足」），故日报面**不需要上游重发信号、也不另存一份上下文**；「Memory 更新摘要」经 [04 §3.1](04-L2-记忆图谱.md) 的 `MemoryReader` **注入**取材（不 import 具体实现）。
- **生成是「显式时刻的纯函数」**（同 [§4](#4-投递编排与升级链) 的裁法）——同一 `(day, 留痕状态)` 恒得同一结论、**写同一路径** `execution_log/daily_report/<YYYY-MM-DD>.json`（**既有分区，不新造**）；到点重跑不产生重复报告。**实际到点触发**（常驻循环 / 调度器目标）不在本层——本层交 `build` 与到点判定，接线归里程碑关卡（[T-INT-004](../../项目管理/tasks/T-INT-004-M3集成关卡主动触达投递闭环.md) 已落为**组合根 `tick(now)` 纯函数 + 生产入口常驻循环**：判定仍在 `tick` 内、循环只决定「何时 tick」，故可离线复算；**不**把它造成 L1 调度目标——日报不是 Skill / 工作流，塞进 `ScheduleTarget` 会让模型别扭）。
- **四段取材**：昨日回顾＝昨日留痕的中性陈述统计；今日关注＝当日待汇总项与在途投递；多视角摘要＝**逐待汇总项的逐视角摘要并列保留、不合并分歧**（[铁律 4](../../项目管理/工程宪法.md)）；Memory 更新摘要＝记忆切片。**段级空态显式**；**四段皆空** ⇒ 正文写「今天没有需要打扰你的事」，**不硬凑**。
- **整段文案过 [01 §6](01-平台共享契约.md) 执行点 2**（命中即显式抛错）；**Trace 锚点**＝参与组装的 `signal_id` / `delivery_id` / `memory_node_id` / `evidence_refs`（[01 §4](01-平台共享契约.md)）。
- **「可订阅到任一渠道」＝经 [§3](#3-渠道适配器channeladapter) 的渠道面投出**，**不另造投递路径**；模板（生成时刻 / 四段开关 / 订阅渠道）注册进 [01 §7](01-平台共享契约.md)（取值是对象 ⇒ 写面归 L5 的日报自有 API，裁法同 [§2](#2-注意力预算)）。

## 6. 去重与频控

- 同 `dedup_key`（如同一标的同一事件类型）短时间多次触发 → 合并为一条（附触发次数），避免刷屏——呼应产品 anti-metric「不追求推送量」
- 全局频控：超出注意力预算格位节奏的信号排队进下一次日报，不丢弃

**计数归属与合并键（2026-10-06 定案，[T-L5-003](../../项目管理/tasks/T-L5-003-每日报告去重频控推送疲劳监控.md)）**：

- **[§2](#2-注意力预算) 的 `max_per_slot` 是上限、不是记账**（[T-L5-001.2](../../项目管理/tasks/T-L5-001.2-注意力预算与情境模式.md) 明写「本层只给上限、不做计数」）——**计数状态、合并与排队归 L5 的频控面**（避免两套记账）。
- **「类」＝ `dedup_key`**（[§1](#1-信号模型signal) 的「同一标的同一事件类型」合并键，是信号面上唯一现成的分类标识）。
- **合并发生在「触达与日报呈现」上、不发生在信号上**——信号已由 [§1](#1-信号模型signal) 采纳（`signal_id` 幂等），合并是把同一 `dedup_key` 的多次触发收敛为**一条呈现 + 触发次数**（`trigger_count`）。
- **超格位节奏 ⇒ 记一条 `route="daily_report"` 的待汇总项**（**排队进下一次日报、不丢弃、不静默**）——与 [§4](#4-投递编排与升级链) 的 `routine` 路由同一落点。
- **计数是「显式时刻的纯函数推进」**（同 [§4](#4-投递编排与升级链)）；计数条目**损坏即显式暴露**，不把「读不出」静默当成「没超限」（[00 §6](00-架构总览.md)）。投递留痕**只增**携带 `dedup_key`（日报面与疲劳面的共同归组键，[§5](#5-每日报告主叙事形态) / [§7](#7-推送疲劳监控) 都按它分组）；**触发次数由频控面自持的计数状态给出**（留痕不重复记一份）。
- **频控面读 [§7](#7-推送疲劳监控) 的静音清单**——用户答复「关闭」的类（逐 `dedup_key`）在裁决时**改判为汇总进日报**（关闭单独触达 ≠ 丢弃）。静音粒度小于渠道偏好（级别）与预算（情境 × 时段 × 内容类型），故由 L5 自持（见 [§7](#7-推送疲劳监控)）。

## 7. 推送疲劳监控

- 每类信号维护「连续忽略计数」；超过阈值（可配，默认 5）→ 产生询问信号：「这类推送对你有用吗？要不要减少？」用户可减少/关闭/保持
- 计数与用户答复作为 FeedbackEvent 交 [08-L6](08-L6-反思演进.md) 消费

**「类」与答复归属（2026-10-06 定案，[T-L5-003](../../项目管理/tasks/T-L5-003-每日报告去重频控推送疲劳监控.md)）**：

- **「类」＝ [§6](#6-去重与频控) 的 `dedup_key`**；**「连续」以「已读」打断**——「忽略」＝链尽 `unacknowledged` / 未读超时结算（[§4](#4-投递编排与升级链)），一次已读即把该类计数**归零**（是**连续**计数，不是累计）。
- **阈值可配（默认 5）**，注册进 [01 §7](01-平台共享契约.md)。
- **询问按原文「询问信号」复用 [§1](#1-信号模型signal) 的 `Signal` 承载**——`content_ref.conclusion` 为中性问句，逐视角摘要承载 **L5 的疲劳观察**（[`signal.py`](../../src/st_agent/l5/signal.py) 对 `lens_id` **只校验形态、不解析 L4 阵容**）；由此询问经 [§4](#4-投递编排与升级链) 正常投出、得一枚**可寻址的 `delivery_id`**（[08 §1](08-L6-反思演进.md) 的反馈对象三类之一）。**不重复发问**：同类已发问而用户**尚未答复**时不发；已答复过则要**再攒满一轮阈值**（`连续计数 ≥ 上次发问时的计数 + 阈值`）才复问——否则「保持」之后计数不变，下一轮就会**立刻再问**，那是骚扰不是「少而准」。
- **`feedback_id` 的产生方仍为交互层（[01 §1](01-平台共享契约.md)）——L5 不自铸**：L5 只产**询问信号**与**计数**；**答复由交互层采集**成 `FeedbackEvent`（`target` 取询问的 `delivery_id`，[05 §9](05-L3-对话主入口.md)），L5 经 [01 §11](01-平台共享契约.md) 的 `FeedbackRecorded` **订阅面**消费答复以落值。「减少 / 关闭 / 保持」的落点分两种：**「减少」**经 [§3](#3-渠道适配器channeladapter) 的**既有写面**收窄该级别的渠道链（留痕可回溯、可回滚）；**「关闭」**记入 L5 自持的**静音清单**（逐 `dedup_key`）——因为「类」的粒度小于渠道偏好（级别）与预算（情境 × 时段 × 内容类型）任一既有面，故只能由本层承载，[§6](#6-去重与频控) 的频控面读它把该类改判为**汇总进日报**（关闭单独触达 ≠ 丢弃）；**「保持」**不改任何配置。三种答复一律留痕。
- **计数只有一份、且它不被答复改写**（2026-10-06 收口口径，[T-L5-003.3](../../项目管理/tasks/T-L5-003.3-推送疲劳监控与答复回流.md) 交付面）——连续忽略计数由**留痕现算**（每次链尽未读即一次忽略，`read` 打断），故**不另存**一份可被答复改写的副本（两份必然漂移）。于是「保持」的作用是**释放问答等待**（该类的下一次发问回到「再攒满一轮阈值」的基线），而不是把计数抹掉；「关闭」只加静音、也不改计数——**用户越回应，复问越少**这一点由问答基线保证，不由计数保证。
- **计数与答复在本层可读面上齐备**（逐类的连续忽略计数 / 阈值 / 最近答复 + 时间锚），供 [08-L6](08-L6-反思演进.md) 在《每周反思报告》里消费——此即「交 L6 消费」的落点；询问文案过 [01 §6](01-平台共享契约.md) 执行点 2。
