# 01 · 平台共享契约

本文定义全平台跨层复用的数据结构与校验规则。**任何层的实现必须遵守本文；新增跨层类型必须先在本文登记**，再被各层文档引用。

约定：以下 schema 用字段表表达，不绑定任何序列化格式或 schema 方言；「必填」指逻辑上不可缺少，序列化方案由实现决定。

## 1. 标识（ID）体系

所有 ID 全局唯一、生成后不可变、可本地持久化。

| ID | 指代对象 | 产生方 | 说明 |
| --- | --- | --- | --- |
| `stock_id` | 证券标的 | L0 数据缓存 | 交易所代码规范映射，跨数据源统一；首个落地形态为本地市场数据库 `security` 主档的主键（BaoStock `sh./sz.` 格式，见 [数据库设计](../数据库设计-BaoStock数据层/01-核心实体层.md)）；**不由本机随机生成**（随机产出即与 `security` 主档脱节） |
| `announcement_id` | 单条公告/披露 | L0 数据缓存 | 含来源与发布日期，用于证据引用；**形态＝业务键（代码 + 标题 + 披露日期）的确定性摘要**——跨源的同一公告得**同一 ID**（故可合并去重），且**不沿用源方 ID**；长度须**有界**以合 `EvidenceRef.ref` 上限（见 §5）；**不由本机随机生成**（随机产出即失去幂等与可复核性） |
| `dataset_snapshot_id` | 一次数据快照 | L0 数据缓存 | 数据一致性锚点（见 §8）；**形态＝同步水位的确定性摘要**（`snap_` ＋ 20 位十六进制）——同一水位得**同一 ID**、换任一水位即换 ID，长度**有界**以合 `EvidenceRef.ref` 上限（见 §5）；**不由本机随机生成**；可读水位原文由 L0 另取，供复核（见 [02 §5](02-L0-本地优先基座.md)） |
| `skill_id` | 一个 Skill 的某个版本 | L1 | 含版本号语义（见 §9） |
| `skill_run_id` | 一次 Skill 执行 | L1 | 输出复用与审计的寻址单位 |
| `memory_node_id` | 一个记忆节点 | L2 | 见 [04-L2](04-L2-记忆图谱.md) |
| `trace_id` | 一次完整推理链 | L1 调度器创建 | 全链路贯穿（见 §4） |
| `signal_id` | 一条待触达信号 | L5 | 见 [07-L5](07-L5-主动触达.md) |
| `delivery_id` | 一次渠道投递 | L5 | 升级链追踪单位 |
| `feedback_id` | 一条用户反馈 | 交互层（L3） | 反馈**在交互层采集并产生**（[05-L3 §9](05-L3-对话主入口.md)），本机生成、**不外发**；落盘与消费归 [08-L6](08-L6-反思演进.md) 的反思数据池（`reflection` 分区）——**产生方与归属方不是同一方**（2026-09-28 由 [T-L3-005.2](../../项目管理/tasks/T-L3-005.2-反馈采集点.md) 订正） |
| `change_id` | 一次配置/演进变更 | 配置注册表 | 回滚单位（见 §7） |
| `lens_id` | 一个视角定义 | L4 | 见 [06-L4](06-L4-多视角推理.md) |
| `flow_id` | 一条工作流定义（含版本语义） | L1 | 形态为 `wf_<注册名>_v<主>.<次>`（与 `skill_id` 同构）；定义见 [03-L1 §3.1](03-L1-能力底座-Skills与MCP.md)；**不由本机随机生成**（随机产出即与「注册名 + 版本」脱节） |
| `trial_id` | 一次工作流试跑 | L1 | 调试协议（见 [03-L1 §4](03-L1-能力底座-Skills与MCP.md)）的留存与对比单位；试跑共用一条推理链（§4），但其标识独立于 `trace_id` |
| `description_id` | 一份 UI 描述 | L3 | 见 §12；形态为 `desc_` ＋ 20 位十六进制，**本机生成、不外发**；渲染面据其追溯，「钉」到工作区后的寻址单位 |

## 2. SkillDescriptor（Skill 元数据）

每个 Skill（无论官方、自建、MCP 映射、导入）必须具备完整描述，作为 L1 注册、L3 调度、[09-生态](09-生态与分享.md) 分享的共同基础。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `skill_id` | ✅ | 全局唯一，含版本语义 |
| `name` | ✅ | 中性功能化命名（过 §6 校验） |
| `description` | ✅ | 做什么的、何时该被调用（供意图匹配使用） |
| `input_schema` / `output_schema` | ✅ | 输入输出契约（类型化，见下方方言澄清） |
| `parameters` | ✅ | 可配参数列表：每项含名称、类型、默认值、取值范围、说明（供面板表单与对话配置共用） |
| `dependencies` | ✅ | 依赖的其他 skill_id 列表（可为空） |
| `source` | ✅ | 枚举：`official` / `user-built` / `mcp-mapped` / `imported` |
| `provenance` | ✅ | 来源追溯（导入类必填分享者、时间、校验和；见 [09 §5](09-生态与分享.md)） |
| `permissions` | ✅ | 权限声明列表（见 §10） |
| `offline_level` | ✅ | 枚举：`full` / `degraded` / `none` |
| `version_policy` | ✅ | 枚举：`follow-latest` / `locked`（官方 Pack 用） |

**方言澄清（2026-09-26 定案）**：`input_schema` / `output_schema` 取**最小 JSON Schema 子集**——关键字仅 `type` / `properties` / `required` / `items`；`type` 取值 `object` / `string` / `number` / `integer` / `boolean` / `array`。语义：`properties` 只约束**已声明且已出现**属性的类型，未列入 `required` 的属性缺省即合法（无 `required` 名单时，空 `{}` 亦合契约）；未出现在子集中的关键字（`oneOf` / `$ref` / `format` 等）不解析、不报错。全平台对这两个字段的判定**只有一个口径**——`st_agent.contracts.schema_check`（`check_payload` 核输出载荷、`check_link` 判连线匹配），各层与生态导入校验一律经它，不得各造一套匹配规则。

**`input_schema` 的运行期语义（2026-09-28 定案）**：它既是工作流连线判定面，也是**运行期输入判定面**。三条输入通道的分工是——① `parameters` 承载**用户可调的标量**（`ParameterSpec.type` 仅 string / number / integer / boolean / enum）；② **对象类输入**（用户组合 / 风格偏好 / 标的池这类 `ParameterSpec` 装不下的对象）由**调用方**经运行期 `inputs` 供给，按该描述体的 `input_schema` 核验（判定件同上，`check_payload`）——不合契约即拒绝执行（`validation_failed` + 违规点），且 `inputs` 只作用于**被请求的那个 Skill**、不沿依赖链下发；③ `dependencies` 承载**上游 Skill 输出**。调用方从何取得该对象（如读 L2 记忆图谱）**不属本契约的约定**——被注入方不向上取，层间依赖不因此反转。

## 3. LensOpinion（结构化观点）

Multi-Lens Deliberation 中每个视角的唯一合法输出形态（禁止「角色台词」）。定义与执行细节见 [06-L4](06-L4-多视角推理.md)，此处登记结构：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `lens_id` | ✅ | 产生该观点的视角 |
| `stance` | ✅ | 枚举：`positive` / `negative` / `neutral` / `insufficient-data` |
| `key_reasons` | ✅ | 理由列表（陈述式，无第一人称） |
| `evidence_refs` | ✅ | 证据引用列表：`announcement_id` / `dataset_snapshot_id` / `skill_run_id` / `memory_node_id` |
| `confidence` | ✅ | 枚举：`high` / `medium` / `low` |
| `skills_triggered` | ✅ | 触发的 skill_run_id 列表 |
| `trace_id` | ✅ | 该观点的推理链锚点 |

## 4. Trace（推理链）

每条面向用户的结论必须可展开为完整 Trace。结构为步骤列表，每步可下钻：

| 字段 | 说明 |
| --- | --- |
| `trace_id` | 推理链标识 |
| `steps[]` | 步骤序列，每步含：`step_type`（`data_fetch` / `skill_run` / `memory_read` / `lens_opinion` / `aggregation`）、`ref`（对应 ID）、`input_digest`、`output_digest`、`duration`、`timestamp` |
| `conclusion_ref` | 最终结论的载体（消息 / 分歧图 / 信号） |

要求：Trace 不可事后修改（追加可以）；断网、降级路径同样记入 Trace。

## 5. ResultEnvelope（统一结果与错误模型）

所有 Skill / 视角 / 数据源 / 渠道的返回值必须包装为统一信封，**禁止编造结果或静默失败**：

| 字段 | 说明 |
| --- | --- |
| `status` | 枚举：`ok` / `empty` / `unavailable` / `failed` / `dependency_failed` / `validation_failed` |
| `data` | status=ok 时的载荷；empty 时为空 |
| `reason` | 非 ok 时必填：人可读原因（中性措辞） |
| `evidence_refs` | ok/empty 时附证据引用 |
| `as_of` | 本结果基于的数据快照时间（见 §8） |

状态语义（全平台一致，UI 层按状态渲染，见各 Story 的状态设计触点）：

- `ok`：正常结果
- `empty`：合法的空结果，**必须**携带原因说明（如「今日全市场无退市高危信号」），不得返回裸空
- `unavailable`：数据源不可用；必须提示「数据不可用/延迟，最后更新时间 T」，可附上次快照（标注过期）
- `dependency_failed`：上游依赖失败；下游必须显式标注「依赖失败」，不得用错误数据继续
- `validation_failed`：输入/参数校验失败；必须说明理由，不允许保存
- `failed`：其他执行失败；须含可查日志入口

## 6. 中性化校验（Neutrality Guard）

产品硬约束「严格中性、非拟人化」的契约级实现。以下三个**强制执行点**，任何实现不得省略：

1. **命名校验**（保存自定义视角、自建 Skill、快捷指令命名时）：名称必须为功能化描述（如「机会视角」「流动性视角」）；拒绝人名、性格标签（如「激进派」）、拟人后缀；描述文本禁用第一人称与情感动词
2. **输出校验**（LensOpinion、Skill 文案、推送文案渲染前）：禁用第一人称代词、情感表达（「我担心/我认为/你说得对」）、对话体措辞；命中即阻断渲染并记录校验失败
3. **命名建议**（对话生成配置草稿、新建视角引导时）：生成器只产中性候选名

校验以规则库形式实现（否定词表 + 结构校验），规则库可随官方 Pack 更新，但**校验点本身不可配置关闭**。合规背景见 PRD §7（规避「AI 荐股」定性）。

## 7. 配置元模型（Configurability Registry）

「可配置性优先」的落点：**所有可配置项必须注册到统一配置注册表**，注册后自动获得三个能力：

| 注册字段 | 说明 |
| --- | --- |
| `config_id` / `display_name` | 唯一标识与展示名 |
| `value_schema` / `default` | 取值契约与默认值 |
| `description_for_chat` | 面向对话通道的自然语言描述（供 L3 意图理解与澄清） |
| `panel_form_spec` | 面板通道的表单渲染规格（供双通道之一） |
| `scope` | 生效范围：全局 / 单 Skill / 单工作流 / 单渠道 |
| `change_policy` | 变更是否需确认、是否记入变更历史、是否可回滚 |

由此保证：① 同一配置项对话可改、面板可改、效果一致；② 配置可整体导出/导入（备份与 [09-生态](09-生态与分享.md) 分享）；③ 每次变更产生 `change_id`，可回滚（L6 演进复用同一机制）。

**登记项的消费面（2026-09-28 定案）**：本节规定**注册条目的形态**（上表七字段）与「注册后自动获得双通道可改 / 变更留痕 / 可回滚」三项能力，**不规定**由谁提供统一的读取与落值门面。消费方（如 [05 §5](05-L3-对话主入口.md) 的对话即配置）只依赖以下**语义**、不依赖存储布局——**读取**：按 `config_id` 取条目、按 `scope` 列举条目；**落值**：一次调用同时完成「值生效」与「产生 `change_id`」的变更留痕（留痕形态即 `ChangeRecord`）。各子系统自落 `config/<前缀>*.json` 属存储布局的一种，不构成契约；门面的实现归属由立项决定。

**门面归属与命名口径（2026-09-30 定案）**：[L1 册 `E1`](../../项目管理/遗留问题/L1-遗留问题.md) 的「门面本体无归属任务」由 [`T-L1-012`](../../项目管理/tasks/T-L1-012-统一配置注册表门面.md) 落定（决策 [D-067](../../项目管理/决策日志.md)），补足上段的三个待决口径：

- **门面归属 L1**——统一门面由 L1 承载（`st_agent.l1.registry`），[00 §1](00-架构总览.md) 的层表不因此新增层；L2 / L3 消费它属向下依赖（[铁律 7](../../项目管理/工程宪法.md)）。各层仍可自持条目落盘，但**读取与落值的公共面只此一处**。
- **`config_id` 取点分语义**——`<族>.<名>`，族即首段；作用域族为 `skill.<base>.<param>` / `workflow.<base>.<param>`。作用域族的键取 **base**（版本号剥离的能力身份，与 §9 的版本语义正交），故**同 base 的版本升级沿用同一份配置**。
- **落盘路径由 `config_id` 确定性派生**——` . → / ` 再缀 `.json`，故「`config_id` 主干即文件名」这一既有不变量对**全部**族成立，不另设路径规则。**段分隔符约束**：作用域族的 `base` / `param` 是**单段名**，不得含 `.` 或 `/`——§2 的 `ParameterSpec.name` 未禁 `.`，含点在点分形态下会歧义，故门面**反解失败即拒**（不静默误解析）。
- **落值语义是「逐条目一次落值」**——门面 `apply` 的每条取值是**该条目的取值域内的一次取值**；取值为对象 / 列表的条目（如 [04 §4–§5](04-L2-记忆图谱.md) 的置信度与写入白名单）**不在统一落值面内**，其写面归各自 owner 的 API（把复合取值塞进统一标量落值面只会造出一条与 owner 校验并行的第二写路径）。**取值不变的条目不留痕、不落盘**（与各 owner 既有取向一致）。
- **存量族不改名**——已自落的路径前缀式 `config_id`（`scheduler-policy/...` / `mcp-hub/...` / `llm-provider-host/...` / `memory-policy/...`）保留原名与其落盘布局（上段「存储布局不构成契约」），门面按各族适配器读取；是否收编为统一形态留后续按需复核。**「所有可配置项必须注册」这一条不留孤儿**：只产出条目形态、从未落盘的（如 [02 §9](02-L0-本地优先基座.md) 的留存两旋钮）同批纳入注册。

## 8. 数据快照与时间口径

- 所有分析性结论基于 `dataset_snapshot_id` 标识的数据快照，结论必须携带 `as_of` 时间
- 数据源延迟/缺失时走 ResultEnvelope 的 `unavailable` 分支，并标注「最后更新时间」；禁止用旧数据冒充新数据
- 时间统一使用用户本地时区存储与展示，内部传输带时区语义
- 数据域须声明**覆盖范围**（`coverage`，见 [05 同步策略与新鲜度契约](../数据库设计-BaoStock数据层/05-同步策略与新鲜度契约.md)）：其中 `watch` ＝按**用户关注面**（关注池 / 持仓）采集，**非**市场全域——此类域的**空结果不等于全市场无数据**，消费方不得据此下全市场结论（[D-037](../../项目管理/决策日志.md)）

`as_of` 的取值与「最后更新时间」的登记机制由 L0 数据缓存的同步状态承载：逐表水位、成功时间与陈旧判据见 [数据库设计-BaoStock数据层 §05 同步策略与新鲜度契约](../数据库设计-BaoStock数据层/05-同步策略与新鲜度契约.md)。

## 9. 版本化规范

所有可导出/可分享/可回滚的对象（官方 Skill、自建 Skill、工作流、视角、配置集、文件格式）遵循同一版本语义：

- 版本号遵循「主版本.次版本」语义：主版本变更 = 契约不兼容（消费方需人工确认）；次版本变更 = 兼容性增强
- 每个版本保留变更日志（做了什么、影响范围）；官方 Pack 更新必须展示变更日志 + 影响范围，用户可选更新/跳过/锁定
- Skill 版本升级导致契约变化时，引用它的下游对象（工作流、视角）自动标记「待检查」，用户确认后才升级——禁止自动破坏下游

## 10. 权限声明模型（Permission Model）

全平台统一的权限申请-审批模型（被 L1 执行沙箱、[L1 MCP Hub](03-L1-能力底座-Skills与MCP.md)、[09 导入校验](09-生态与分享.md) 共用）：

| 权限项 | 说明 |
| --- | --- |
| `local_read:<path-scope>` | 读取声明范围内的本地数据（超出声明范围的读取在运行时被拦截并警示） |
| `net_access:<host-pattern>` | 访问匹配的远程主机（所有实际请求纳入 L0 网络审计） |
| `exec_command` | 执行本地命令（最高风险，逐次或逐项审批） |

规则：能力（Skill / MCP Server / 导入物）在安装/挂载时声明权限，用户逐项批准；运行时行为超出声明即拦截 + 警示「行为异常」+ 提供禁用选项；权限申请展示必须说明「这个能力想做什么」。

**声明的语义范围**（2026-09-27 定案）：权限声明只覆盖**该能力自身发起**的文件 / 网络 / 命令行为——「运行时行为超出声明即拦截」拦的正是这三类出口。经**注入的取数面**（如 L0 鸭子类型的市场数据 / 文档取数接口）消费数据不经这些出口，故**不属** `local_read` 的范围（读 `data_cache` 内的缓存数据亦然，见 [D-031](../../项目管理/决策日志.md)）；一个只经注入句柄取数的能力**不声明任何权限**——官方 Skill Pack 即按此声明为空。批准态由 **Skill 侧**与 **MCP Server 侧**各持一条持久落点，两者的簿记语义是同一份实现。

## 12. UI 描述（Generative UI）

对话中按需生成的看板 / 图表 / 卡片 / 报告，其**结构**以「UI 描述」表达（见 [05 §6](05-L3-对话主入口.md)）。描述由**产出方**（L3）生成、由**渲染方**（表现层，见 [00 §1.1](00-架构总览.md)）解析渲染；本节登记的只是**结构**，不是渲染实现。

**不变量**：描述恒经（见 §5）包裹——**仅 `status=ok` 时 `data` 为描述**（或其序列），非 ok 态不带描述、由 `reason` 载中性原因。**渲染器只解析描述、不解析任意代码**（见 [05 §6](05-L3-对话主入口.md)）。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `description_id` | ✅ | 描述标识（形态见 §1）；M1 用于追溯，「钉」到工作区后的寻址单位 |
| `component_type` | ✅ | 组件类型键，取值见下表；**未登记即显式降级**，不猜测 |
| `title` | | 生成文案（过 §6 执行点 2） |
| `slots` | ✅ | 数据绑定：命名槽 → **已解析的 JSON 值**或 §1 的 ID 引用；**禁止**表达式 / 模板 / 可执行片段 |
| `layout` | | 声明式布局提示（如槽位所属的 `inline` / `pinned` / `panel`、跨度、是否折叠）；渲染器**可忽略** |
| `as_of` | | 数据快照时间（见 §8） |
| `text_kinds` | ✅ | 槽名 → `generated`（系统生成文案，过 §6）／`data`（用户原话、记忆本体等，**原样呈现、不过 §6**）；**必须逐槽显式标注**，不留白 |

**本期登记并实现的组件类型**：

| `component_type` | 说明 |
| --- | --- |
| `table` | 表格 |

**降级口径**：`component_type` 未登记、或渲染方未实现该型时，渲染器展示**显式降级占位**（类型名 + 原因 + 可折叠的原始描述），**不执行、不猜测、不静默丢弃**。

**中性口径的切分**（沿用 [D-053](../../项目管理/决策日志.md)）：只有 `text_kinds` 标为 `generated` 的文本过 §6 执行点 2（渲染前），命中即阻断渲染并记录校验失败；标为 `data` 的文本属**数据展示**，**不整串复检**——否则会把用户原话误判为违规。
