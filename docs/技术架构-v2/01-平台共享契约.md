# 01 · 平台共享契约

本文定义全平台跨层复用的数据结构与校验规则。**任何层的实现必须遵守本文；新增跨层类型必须先在本文登记**，再被各层文档引用。

约定：以下 schema 用字段表表达，不绑定任何序列化格式或 schema 方言；「必填」指逻辑上不可缺少，序列化方案由实现决定。

## 1. 标识（ID）体系

所有 ID 全局唯一、生成后不可变、可本地持久化。

| ID | 指代对象 | 产生方 | 说明 |
| --- | --- | --- | --- |
| `stock_id` | 证券标的 | L0 数据缓存 | 交易所代码规范映射，跨数据源统一；首个落地形态为本地市场数据库 `security` 主档的主键（BaoStock `sh./sz.` 格式，见 [数据库设计](../数据库设计-BaoStock数据层/01-核心实体层.md)）；**不由本机随机生成**（随机产出即与 `security` 主档脱节） |
| `announcement_id` | 单条公告/披露 | L0 数据缓存 | 含来源与发布日期，用于证据引用；**形态＝业务键（代码 + 标题 + 披露日期）的确定性摘要**——跨源的同一公告得**同一 ID**（故可合并去重），且**不沿用源方 ID**；长度须**有界**以合 `EvidenceRef.ref` 上限（见 §5）；**不由本机随机生成**（随机产出即失去幂等与可复核性） |
| `dataset_snapshot_id` | 一次数据快照 | L0 数据缓存 | 数据一致性锚点（见 §8）；**形态＝同步水位的确定性摘要**（`snap_` ＋ 20 位十六进制）——同一水位得**同一 ID**、换任一水位即换 ID，长度**有界**以合 `EvidenceRef.ref` 上限（见 §5）；**不由本机随机生成**；可读水位原文由 L0 另取，供复核（见 [02 §5](02-L0-本地优先基座.md)） |
| `skill_id` | 一个 Skill 的某个版本 | L1 | 含版本号语义（见 §9） |
| `skill_run_id` | 一次 Skill 执行 | L1 | 输出复用与审计的寻址单位 |
| `memory_node_id` | 一个记忆节点 | L2 | 见 [04-L2](04-L2-记忆图谱.md) |
| `trace_id` | 一次完整推理链 | L1 调度器创建 | 全链路贯穿（见 §4） |
| `signal_id` | 一条待触达信号 | L5 | 见 [07-L5](07-L5-主动触达.md)；**形态＝投递内容的确定性摘要**（`sig_` ＋ 20 位十六进制）——L5 **采纳** `SignalEmitted`（§11 负载结构）时铸造，同一信号重复投递得**同一 ID**（幂等与去重的共同锚点）；**不由本机随机生成**（随机产出即失去幂等） |
| `delivery_id` | 一次渠道投递 | L5 | 升级链追踪单位；**形态＝（信号 + 渠道 + 升级级次）的确定性摘要**（`dlv_` ＋ 20 位十六进制）——同一信号的同一级**重放 / 补发得同一 ID**，故升级链可安全重入、补发不产生重复投递记录；**不由本机随机生成**（随机产出即失去幂等，见 [07 §4](07-L5-主动触达.md)） |
| `feedback_id` | 一条用户反馈 | 交互层（L3） | 反馈**在交互层采集并产生**（[05-L3 §9](05-L3-对话主入口.md)），本机生成、**不外发**；落盘与消费归 [08-L6](08-L6-反思演进.md) 的反思数据池（`reflection` 分区）——**产生方与归属方不是同一方**（2026-09-28 由 [T-L3-005.2](../../项目管理/tasks/done/M1/T-L3-005.2-反馈采集点.md) 订正） |
| `change_id` | 一次配置/演进变更 | 配置注册表 | 回滚单位（见 §7） |
| `lens_id` | 一个视角定义 | L4 | 见 [06-L4](06-L4-多视角推理.md) |
| `flow_id` | 一条工作流定义（含版本语义） | L1 | 形态为 `wf_<注册名>_v<主>.<次>`（与 `skill_id` 同构）；定义见 [03-L1 §3.1](03-L1-能力底座-Skills与MCP.md)；**不由本机随机生成**（随机产出即与「注册名 + 版本」脱节） |
| `trial_id` | 一次工作流试跑 | L1 | 调试协议（见 [03-L1 §4](03-L1-能力底座-Skills与MCP.md)）的留存与对比单位；试跑共用一条推理链（§4），但其标识独立于 `trace_id` |
| `description_id` | 一份 UI 描述 | L3 | 见 §12；形态为 `desc_` ＋ 20 位十六进制，**本机生成、不外发**；渲染面据其追溯，「钉」到工作区后的寻址单位 |
| `agent_run_id` | 一次自主查证循环的执行 | L3 | 见 [05 §10](05-L3-对话主入口.md)；循环的**留痕与审计单位**（步数 / 终止原因 / 上界），一次派发一条，与本次派发**共用 `trace_id`** |

## 2. SkillDescriptor（Skill 元数据）

每个 Skill（无论官方、自建、MCP 映射、导入）必须具备完整描述，作为 L1 注册、L3 调度、[09-生态](09-生态与分享.md) 分享的共同基础。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `skill_id` | ✅ | 全局唯一，含版本语义 |
| `name` | ✅ | 中性功能化命名（过 §6 校验） |
| `description` | ✅ | 做什么的、何时该被调用（供意图匹配使用） |
| `input_schema` / `output_schema` | ✅ | 输入输出契约（类型化，见下方方言澄清） |
| `parameters` | ✅ | 可配参数列表：每项含名称、类型、默认值、取值范围、说明（供面板表单与对话配置共用） |
| `dependencies` | ✅ | 依赖的其他 skill_id 列表（可为空） |
| `source` | ✅ | 枚举：`official` / `user-built` / `mcp-mapped` / `imported` |
| `provenance` | ✅ | 来源追溯（导入类必填分享者、时间、校验和；见 [09 §5](09-生态与分享.md)） |
| `permissions` | ✅ | 权限声明列表（见 §10） |
| `offline_level` | ✅ | 枚举：`full` / `degraded` / `none` |
| `version_policy` | ✅ | 枚举：`follow-latest` / `locked`（官方 Pack 用） |

**方言澄清（2026-09-26 定案）**：`input_schema` / `output_schema` 取**最小 JSON Schema 子集**——关键字仅 `type` / `properties` / `required` / `items`；`type` 取值 `object` / `string` / `number` / `integer` / `boolean` / `array`。语义：`properties` 只约束**已声明且已出现**属性的类型，未列入 `required` 的属性缺省即合法（无 `required` 名单时，空 `{}` 亦合契约）；未出现在子集中的关键字（`oneOf` / `$ref` / `format` 等）不解析、不报错。全平台对这两个字段的判定**只有一个口径**——`st_agent.contracts.schema_check`（`check_payload` 核输出载荷、`check_link` 判连线匹配），各层与生态导入校验一律经它，不得各造一套匹配规则。

**`input_schema` 的运行期语义（2026-09-28 定案）**：它既是工作流连线判定面，也是**运行期输入判定面**。三条输入通道的分工是——① `parameters` 承载**用户可调的标量**（`ParameterSpec.type` 仅 string / number / integer / boolean / enum）；② **对象类输入**（用户组合 / 风格偏好 / 标的池这类 `ParameterSpec` 装不下的对象）由**调用方**经运行期 `inputs` 供给，按该描述体的 `input_schema` 核验（判定件同上，`check_payload`）——不合契约即拒绝执行（`validation_failed` + 违规点），且 `inputs` 只作用于**被请求的那个 Skill**、不沿依赖链下发；③ `dependencies` 承载**上游 Skill 输出**。调用方从何取得该对象（如读 L2 记忆图谱）**不属本契约的约定**——被注入方不向上取，层间依赖不因此反转。

**工具暴露面的唯一来源（2026-10-07 定案）**：自主查证循环（[05 §10](05-L3-对话主入口.md)）须把**可调用能力**以「工具条目」的形态交给模型。该条目的**唯一来源是本节的 `SkillDescriptor`**——工具名取 `skill_id` 的 **base**（版本剥离的能力身份，取点同 [§7](#7-配置元模型configurability-registry) 的作用域族）、描述取 `description`、参数面由 `parameters` 与 `input_schema` 派生。**禁止另设第二份能力登记**（为模型单列的「工具清单」文件 / 表 / 注册表）：那会让「L1 注册了什么」与「模型看得见什么」成为两套可分别漂移的事实。`source` 为 `mcp-mapped` 的映射能力与官方 / 自建 / 导入**在此无差别**——一律经本节描述体，故模型的可见面**恒等于** L1 的注册面。暴露哪些**字段**（schema 方言、是否带默认值）属实现口径，不构成契约；**必须是本节描述体的投影**这一条构成契约。

**版本折叠口径（2026-10-07 定案）**：同一 base 的多个已注册版本在工具面上**折叠为一条**——工具名既是版本剥离的能力身份，条目内的执行目标取该 base 的**最高版本**。故版本升级**只换执行目标，不新增条目、不改工具名**，模型的可见面基数＝**能力数（base 数）**而非描述体条数。这与 [§9](#9-版本化规范)「升级不得自动破坏下游」同向：循环的调用面是**能力**，不随版本漂移。

## 3. LensOpinion（结构化观点）

Multi-Lens Deliberation 中每个视角的唯一合法输出形态（禁止「角色台词」）。定义与执行细节见 [06-L4](06-L4-多视角推理.md)，此处登记结构：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `lens_id` | ✅ | 产生该观点的视角 |
| `stance` | ✅ | 枚举：`positive` / `negative` / `neutral` / `insufficient-data` |
| `key_reasons` | ✅ | 理由列表（陈述式，无第一人称） |
| `evidence_refs` | ✅ | 证据引用列表：`announcement_id` / `dataset_snapshot_id` / `skill_run_id` / `memory_node_id` |
| `confidence` | ✅ | 枚举：`high` / `medium` / `low` |
| `skills_triggered` | ✅ | 触发的 skill_run_id 列表 |
| `trace_id` | ✅ | 该观点的推理链锚点 |

## 4. Trace（推理链）

每条面向用户的结论必须可展开为完整 Trace。结构为步骤列表，每步可下钻：

| 字段 | 说明 |
| --- | --- |
| `trace_id` | 推理链标识 |
| `steps[]` | 步骤序列，每步含：`step_type`（`data_fetch` / `skill_run` / `memory_read` / `lens_opinion` / `aggregation`）、`ref`（对应 ID）、`input_digest`、`output_digest`、`duration`、`timestamp` |
| `conclusion_ref` | 最终结论的载体（消息 / 分歧图 / 信号） |

要求：Trace 不可事后修改（追加可以）；断网、降级路径同样记入 Trace。

**自主查证循环的步骤口径（2026-10-07 定案）**：循环（[05 §10](05-L3-对话主入口.md)）中模型「选下一个工具」这一动作**不产生步骤**——它是**决策**而非**动作**，上方五类 `step_type` 无对应项，**不为其新造一类、也不借任何一类充数**（同 [05 §4](05-L3-对话主入口.md)「未接入去向不伪造步骤」的一贯口径；亦同 L4 各端口内的 LLM 调用不单独成步的既有事实）。循环跑过的每个 Skill **各产一条 `skill_run` 步**（由 L1 执行器追加），故多步循环**天然得到一条完整的链**，[05 §7](05-L3-对话主入口.md) 的推理链可视化与 `explain` 去向可逐步展开——中间决策不外显，动作全可追溯。

## 5. ResultEnvelope（统一结果与错误模型）

所有 Skill / 视角 / 数据源 / 渠道的返回值必须包装为统一信封，**禁止编造结果或静默失败**：

| 字段 | 说明 |
| --- | --- |
| `status` | 枚举：`ok` / `empty` / `unavailable` / `failed` / `dependency_failed` / `validation_failed` |
| `data` | status=ok 时的载荷；empty 时为空 |
| `reason` | 非 ok 时必填：人可读原因（中性措辞） |
| `evidence_refs` | ok/empty 时附证据引用 |
| `as_of` | 本结果基于的数据快照时间（见 §8） |

状态语义（全平台一致，UI 层按状态渲染，见各 Story 的状态设计触点）：

- `ok`：正常结果
- `empty`：合法的空结果，**必须**携带原因说明（如「今日全市场无退市高危信号」），不得返回裸空
- `unavailable`：数据源不可用；必须提示「数据不可用/延迟，最后更新时间 T」，可附上次快照（标注过期）
- `dependency_failed`：上游依赖失败；下游必须显式标注「依赖失败」，不得用错误数据继续
- `validation_failed`：输入/参数校验失败；必须说明理由，不允许保存
- `failed`：其他执行失败；须含可查日志入口

## 6. 中性化校验（Neutrality Guard）

产品硬约束「严格中性、非拟人化」的契约级实现。以下三个**强制执行点**，任何实现不得省略：

1. **命名校验**（保存自定义视角、自建 Skill、快捷指令命名时）：名称必须为功能化描述（如「机会视角」「流动性视角」）；拒绝人名、性格标签（如「激进派」）、拟人后缀；描述文本禁用第一人称与情感动词
2. **输出校验**（LensOpinion、Skill 文案、推送文案渲染前）：禁用第一人称代词、情感表达（「我担心/我认为/你说得对」）、对话体措辞；命中即阻断渲染并记录校验失败
3. **命名建议**（对话生成配置草稿、新建视角引导时）：生成器只产中性候选名

校验以规则库形式实现（否定词表 + 结构校验），规则库可随官方 Pack 更新（其官方缺省由 [§13 官方资源包](#13-官方资源包official-resource-pack) 的 `rulepack` kind 承载、经注入取），但**校验点本身不可配置关闭**。合规背景见 PRD §7（规避「AI 荐股」定性）。

## 7. 配置元模型（Configurability Registry）

「可配置性优先」的落点：**所有可配置项必须注册到统一配置注册表**，注册后自动获得三个能力：

| 注册字段 | 说明 |
| --- | --- |
| `config_id` / `display_name` | 唯一标识与展示名 |
| `value_schema` / `default` | 取值契约与默认值 |
| `description_for_chat` | 面向对话通道的自然语言描述（供 L3 意图理解与澄清） |
| `panel_form_spec` | 面板通道的表单渲染规格（供双通道之一） |
| `scope` | 生效范围：全局 / 单 Skill / 单工作流 / 单渠道 |
| `change_policy` | 变更是否需确认、是否记入变更历史、是否可回滚 |

由此保证：① 同一配置项对话可改、面板可改、效果一致；② 配置可整体导出/导入（备份与 [09-生态](09-生态与分享.md) 分享）；③ 每次变更产生 `change_id`，可回滚（L6 演进复用同一机制）。

**登记项的消费面（2026-09-28 定案）**：本节规定**注册条目的形态**（上表七字段）与「注册后自动获得双通道可改 / 变更留痕 / 可回滚」三项能力，**不规定**由谁提供统一的读取与落值门面。消费方（如 [05 §5](05-L3-对话主入口.md) 的对话即配置）只依赖以下**语义**、不依赖存储布局——**读取**：按 `config_id` 取条目、按 `scope` 列举条目；**落值**：一次调用同时完成「值生效」与「产生 `change_id`」的变更留痕（留痕形态即 `ChangeRecord`）。各子系统自落 `config/<前缀>*.json` 属存储布局的一种，不构成契约；门面的实现归属由立项决定。

**门面归属与命名口径（2026-09-30 定案）**：[L1 册 `E1`](../../项目管理/遗留问题/L1-遗留问题.md) 的「门面本体无归属任务」由 [`T-L1-012`](../../项目管理/tasks/done/M2/T-L1-012-统一配置注册表门面.md) 落定（决策 [D-067](../../项目管理/决策日志.md)），补足上段的三个待决口径：

- **门面归属 L1**——统一门面由 L1 承载（`st_agent.l1.registry`），[00 §1](00-架构总览.md) 的层表不因此新增层；L2 / L3 消费它属向下依赖（[铁律 7](../../项目管理/工程宪法.md)）。各层仍可自持条目落盘，但**读取与落值的公共面只此一处**。
- **`config_id` 取点分语义**——`<族>.<名>`，族即首段；作用域族为 `skill.<base>.<param>` / `workflow.<base>.<param>`。作用域族的键取 **base**（版本号剥离的能力身份，与 §9 的版本语义正交），故**同 base 的版本升级沿用同一份配置**。
- **落盘路径由 `config_id` 确定性派生**——` . → / ` 再缀 `.json`，故「`config_id` 主干即文件名」这一既有不变量对**全部**族成立，不另设路径规则。**段分隔符约束**：作用域族的 `base` / `param` 是**单段名**，不得含 `.` 或 `/`——§2 的 `ParameterSpec.name` 未禁 `.`，含点在点分形态下会歧义，故门面**反解失败即拒**（不静默误解析）。
- **落值语义是「逐条目一次落值」**——门面 `apply` 的每条取值是**该条目的取值域内的一次取值**；取值为对象 / 列表的条目（如 [04 §4–§5](04-L2-记忆图谱.md) 的置信度与写入白名单）**不在统一落值面内**，其写面归各自 owner 的 API（把复合取值塞进统一标量落值面只会造出一条与 owner 校验并行的第二写路径）。**取值不变的条目不留痕、不落盘**（与各 owner 既有取向一致）。
- **存量族不改名**——已自落的路径前缀式 `config_id`（`scheduler-policy/...` / `mcp-hub/...` / `llm-provider-host/...` / `memory-policy/...`）保留原名与其落盘布局（上段「存储布局不构成契约」），门面按各族适配器读取；是否收编为统一形态留后续按需复核。**「所有可配置项必须注册」这一条不留孤儿**：只产出条目形态、从未落盘的（如 [02 §9](02-L0-本地优先基座.md) 的留存两旋钮）同批纳入注册；**新增条目同此**——出网审计开关（`net-audit/enabled`，取值布尔、**缺省 `false`**，owner ＝ L0 网关，见 [02 §6](02-L0-本地优先基座.md)）随其实现任务一并接入门面，不走「先落盘、后补注册」。

**运行期动作的授权档位与风险分级（2026-10-07 定案，[D-090](../../项目管理/决策日志.md)）**：自主查证循环（[05 §10](05-L3-对话主入口.md)）在每一步调用工具前须过一次**授权闸门**。该闸门**复用 [08 §5](08-L6-反思演进.md) 已有的三档 + 三风险类**，不另造一套；三条口径：

- **分级清单一处、档位两处**——`RiskClass` 三态（`autonomous-ok` / `collaborative-required` / `never-autonomous`）与那张**白名单清单**为**共享的单一事实源**（清单本体归 [08 §5](08-L6-反思演进.md)）；**档位是两条彼此独立的登记条目**——`evolution.authorization`（演进授权，已有）与**运行期授权条目**（新）。故「记忆内容与策略恒不可自主」这类红线**只登记一次**，不在两处各标一遍（红线单点＝不给漂移留口子）。
- **分级键空间含「动作标识」**——除既有的 `config_id` 前缀外，清单键空间纳入**运行期动作标识**（形如 `skill.<base>` / `memory.write` / `net.egress`），使「某个工具能否**自主调用**」与「某个配置能否**自主改**」共用同一套判据与同一张清单。**未命中任何规则一律保守**（按必须协作），与既有口径同——**不静默放行**。
- **缺省与损坏都不放行**——运行期授权条目未落值即取 `collaborative`（不自动）；条目**损坏一律不放行**并给出原因（fail-closed），**不臆测为自主**（同 [08 §5](08-L6-反思演进.md) 的既有取向）。

**自主查证循环的上界（2026-10-08 定案，[D-099](../../项目管理/决策日志.md)）**：[05 §10](05-L3-对话主入口.md) 的自主查证循环有两道**上界**——**步数**与 **LLM 调用次数**。两条**登记为本节配置项** `investigate.max_steps` / `investigate.max_llm_calls`（族 `investigate.`、`scope` 全局、`change_policy` 需确认），缺省 8 / 12（＝循环入口的缺省，**单一事实源**），取值域为**整数且 ≥1 并带防跑飞上限**（上限取值属实现口径）。两条目**不是** [05 §3.2](05-L3-对话主入口.md) 的**意图级参数**——那是单次请求的问项，而上界是**长期偏好**，故 `investigate` 的确认卡仍只有「意图」一条目。**owner 住 L3**（`st_agent.l3.runtime`），族适配器由**组合根注入**本节门面（[铁律 7](../../项目管理/工程宪法.md)「层间只向下依赖」；先例为 L2 / L5 / L6 各族适配器，门面本体仍归 L1）。

## 8. 数据快照与时间口径

- 所有分析性结论基于 `dataset_snapshot_id` 标识的数据快照，结论必须携带 `as_of` 时间
- 数据源延迟/缺失时走 ResultEnvelope 的 `unavailable` 分支，并标注「最后更新时间」；禁止用旧数据冒充新数据
- 时间统一使用用户本地时区存储与展示，内部传输带时区语义
- 数据域须声明**覆盖范围**（`coverage`，见 [05 同步策略与新鲜度契约](../数据库设计-BaoStock数据层/05-同步策略与新鲜度契约.md)）：其中 `watch` ＝按**用户关注面**（关注池 / 持仓）采集，**非**市场全域——此类域的**空结果不等于全市场无数据**，消费方不得据此下全市场结论（[D-037](../../项目管理/决策日志.md)）

`as_of` 的取值与「最后更新时间」的登记机制由 L0 数据缓存的同步状态承载：逐表水位、成功时间与陈旧判据见 [数据库设计-BaoStock数据层 §05 同步策略与新鲜度契约](../数据库设计-BaoStock数据层/05-同步策略与新鲜度契约.md)。

## 9. 版本化规范

所有可导出/可分享/可回滚的对象（官方 Skill、自建 Skill、工作流、视角、配置集、文件格式）遵循同一版本语义：

- 版本号遵循「主版本.次版本」语义：主版本变更 = 契约不兼容（消费方需人工确认）；次版本变更 = 兼容性增强
- 每个版本保留变更日志（做了什么、影响范围）；官方 Pack 更新必须展示变更日志 + 影响范围，用户可选更新/跳过/锁定
- Skill 版本升级导致契约变化时，引用它的下游对象（工作流、视角）自动标记「待检查」，用户确认后才升级——禁止自动破坏下游

## 10. 权限声明模型（Permission Model）

全平台统一的权限申请-审批模型（被 L1 执行沙箱、[L1 MCP Hub](03-L1-能力底座-Skills与MCP.md)、[09 导入校验](09-生态与分享.md) 共用）：

| 权限项 | 说明 |
| --- | --- |
| `local_read:<path-scope>` | 读取声明范围内的本地数据（超出声明范围的读取在运行时被拦截并警示） |
| `net_access:<host-pattern>` | 访问匹配的远程主机（所有实际请求**经 L0 网关执行**；逐次留痕为审计、**默认可关**，见 [02 §6](02-L0-本地优先基座.md)） |
| `exec_command` | 执行本地命令（最高风险，逐次或逐项审批） |

规则：能力（Skill / MCP Server / 导入物）在安装/挂载时声明权限，用户逐项批准；运行时行为超出声明即拦截 + 警示「行为异常」+ 提供禁用选项；权限申请展示必须说明「这个能力想做什么」。

**声明的语义范围**（2026-09-27 定案）：权限声明只覆盖**该能力自身发起**的文件 / 网络 / 命令行为——「运行时行为超出声明即拦截」拦的正是这三类出口。经**注入的取数面**（如 L0 鸭子类型的市场数据 / 文档取数接口）消费数据不经这些出口，故**不属** `local_read` 的范围（读 `data_cache` 内的缓存数据亦然，见 [D-031](../../项目管理/决策日志.md)）；一个只经注入句柄取数的能力**不声明任何权限**——官方 Skill Pack 即按此声明为空。批准态由 **Skill 侧**与 **MCP Server 侧**各持一条持久落点，两者的簿记语义是同一份实现。

**`SignalEmitted` 负载结构（2026-10-06 定案，[T-L5-001.1](../../项目管理/tasks/done/M3/T-L5-001.1-信号模型与采纳.md)）**：§11 原记「负载结构由发布层定义」，而该信号模型的**订阅方**是 L5、发布方 L1/L4 无既定结构，故在此**先行登记**（[铁律 8](../../项目管理/工程宪法.md)）——发布方按此填、L5 按此采纳：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `level` | ✅ | `emergency` / `important` / `routine`（[07 §1](07-L5-主动触达.md)） |
| `content_ref` | ✅ | 内容载体：`conclusion`（中性陈述式结论，**非单一视角的措辞**）+ `lens_stances[]`（逐视角摘要，每项含 `lens_id` / `stance` / `summary`）——**多视角并列保留、不合并分歧**（[铁律 4](../../项目管理/工程宪法.md)） |

| `source_trace_id` | ✅ | 溯源推理链（§4；与该事件的 `trace_id` 同源） |

**`signal_id` 不在负载内**——由 L5 采纳时按 §1 的确定性摘要铸造，故发布方无需（也无从）分配；重复投递同一信号得同一 `signal_id`。缺字段 / 非法 `level` / 空 `conclusion` / 空的逐视角摘要一律**显式拒绝**（[00 §6 失败显式化](00-架构总览.md)），不臆补。

**事件投递口径（2026-10-06 定案，[T-L5-002](../../项目管理/tasks/done/M3/T-L5-002-渠道适配器投递编排与升级链.md)）**：本节此前只登记了事件的**形态、发布方 / 订阅方与 `trace_id` 关联要求**——「下层向上层只通过事件通信」的**投递（发布 / 订阅）面**没有承载，导致 `MemoryConflictDetected` 的两端（L2 的产生与 L3 的消费）齐备却无人接线（[L3 册 `A2`](../../项目管理/遗留问题/L3-遗留问题.md)）。今在此补登记**机制口径**（[铁律 8](../../项目管理/工程宪法.md)）；**不登记任何具体事件名与负载结构**（那些仍归各自小节与本表）：

| 口径 | 内容 |
| --- | --- |
| **总线归属** | **L1**（`st_agent.l1.events`）——归属理由与 [§7 配置门面](#7-配置元模型configurability-registry)同：装配只向下依赖 L0，且免各层各自实现一套（[D-067](../../项目管理/决策日志.md) 的同一裁法）。L0 侧不发布事件（`NetworkRequestLogged` 由查询侧按需组装，见 [02 §6](02-L0-本地优先基座.md)），故 L0 不因总线住 L1 而反向依赖 |
| **接入形态** | 发布方持 `publish(event) -> bool`、订阅方持 `subscribe(event_name, handler) -> 注销句柄`，两侧均为**鸭子类型端口**、由组合根注入——**层与层之间不互相 import**（同 `DispatchBus` 的 `analyze` 去向、L3 `FeedbackCollector` 的 `sink`） |
| **派发语义** | **同步、按订阅登记顺序**——同一事件序列恒得同一派发序列（决定论，可离线重复验证）；发布方在**发布这一跳**得知受理结果 |
| **失败显式化** | 订阅者抛错**不吞、不阻断其余订阅者**：该次派发的返回里逐订阅者记结果（受理 / 异常 + 原因），异常**不得**被静默降级成「已送达」 |
| **未接通** | 未接入总线时**不假装送达**——发布端受理恒为「未受理」并**点名归属任务**（形如 `UndeliveredPublisher`，同 L3 `FeedbackCollector` 的既有取向）；事件仍留在发布端可自行保留与重试，**不静默丢弃** |
| **不落盘** | 总线是**进程内通知**、自身零落盘；需要留痕的事件由发布方自行落（如 `SkillRunCompleted` 落 `execution_log`）或由消费侧按需组装（`NetworkRequestLogged`）。**跨进程**（常驻后端 → 可分离 UI 客户端）的推送是表现层消费面的事，不在本口径内 |

**本表 2026-10-07 补五型**（[`T-UI-004.2`](../../项目管理/tasks/done/M4/T-UI-004.2-反思中心表现层入口.md) / [`.3`](../../项目管理/tasks/done/M4/T-UI-004.3-演进面表现层入口.md) / [`.4`](../../项目管理/tasks/done/M4/T-UI-004.4-生态面表现层入口.md)，[铁律 8](../../项目管理/工程宪法.md)）：`feedback_capture` 与 `proposal_card` 是 story-09「设计触点」明列的**反馈按钮组**与**提案接受 / 否决按钮**，`change_timeline` 是**变更历史时间线 + 回滚按钮**，`setting_panel` 是**演进授权设置页**，`violation_alert` 是 story-10 的**异常行为警示对话框**——此前均无载体；登记后其渲染件与槽词汇表随对应任务落地。

**`setting_panel` 与 `config_draft_card` 的分工（2026-10-07 定案）**：`config_draft_card` 的面板分支（[05 §5](05-L3-对话主入口.md) 的「面板通道」）按既有口径是**只读视图**（渲染件只呈现、不落值）；`setting_panel` 才带**应用动作**。故「双通道同源」到表现层时：同一 `config_id` 的**呈现**可走 `config_draft_card`，**改值**必须走带动作的面——两者不合并，因为「只渲染」与「会写」是两条不同的安全边界。

**动作不进描述（2026-10-07 定案）**：页面上「点一下会写点什么」的控件（反馈按钮 / 接受·否决·延后 / 一键回滚 / 导出确认 / 安装批准）**不由描述承载动作**——`slots` 只放**数据**（反馈对象、`pending_id`、`change_id`、提案内容等），发起写请求的路由是**渲染件已知的固定回环路由**（`/api/reflection/**` · `/api/evolution/**` · `/api/eco/**`），**不接受**描述携带 URL / 方法 / 脚本。理由与本节开篇的不变量同源：描述一旦能表达「调哪个端点」，它就从**数据结构**退化为**控制通道**，而渲染器只解析描述、不执行任意代码这条随之失守。

**已登记、本期不实现（留给后续里程碑）**：`divergence_map` / `heatmap` / `trend_chart` / `risk_badge` / `pinned_board`。提前登记的理由是让后续补这些形态属于**实现**而不是**改契约**——[06-L4](06-L4-多视角推理.md) 的分歧图与 [08-L6](08-L6-反思演进.md) 的报告卡都在其列。

**降级口径**：`component_type` 未登记、或渲染方未实现该型时，渲染器展示**显式降级占位**（类型名 + 原因 + 可折叠的原始描述），**不执行、不猜测、不静默丢弃**。

**中性口径的切分**（沿用 [D-053](../../项目管理/决策日志.md)）：只有 `text_kinds` 标为 `generated` 的文本过 §6 执行点 2（渲染前），命中即阻断渲染并记录校验失败；标为 `data` 的文本属**数据展示**，**不整串复检**——否则会把用户原话误判为违规。

## 13. 官方资源包（Official Resource Pack）

「可随官方 Pack 更新」在三节的原文里出现（[§6 中性化规则库](#6-中性化校验neutrality-guard) / [04 §7 Onboarding 问题清单](04-L2-记忆图谱.md) / [05 §8 快捷指令](05-L3-对话主入口.md)），但此前只有 [03 §2](03-L1-能力底座-Skills与MCP.md) 的 Skill 描述体真正装在一个「Pack」里。本节把该措辞落成**契约**：**官方 Pack＝官方资源的类型化容器**，各类官方资源以**类型化条目**承载，「随 Pack 更新」即容器内该类条目的整组替换。

**容器条目**：

| 字段 | 说明 |
| --- | --- |
| `kind` | 资源类别的**字符串键**（见下「kinds」）；**开放注册**——本契约不固定 closed 枚举，新增类别属**扩充**而非改契约 |
| `version` | 该类资源的版本（语义见 [§9](#9-版本化规范)） |
| `payload` | 资源本体；容器**不解读**其形态——形态归该 kind 的既有出处（见下表） |

**kinds 与各节的关系**（容器只定「装载 / 分发」面，**不重复定义**各资源的形态）：

| `kind` | 资源 | 形态出处 | 消费方 |
| --- | --- | --- | --- |
| `skill` | Skill 描述体 | [§2](#2-skilldescriptorskill-元数据) | L1 `SkillRegistry` |
| `rulepack` | 中立性规则库 | [§6](#6-中性化校验neutrality-guard) | `NeutralityGuard`（**全部**消费点） |
| `onboarding_questions` | Onboarding 问题清单 | [§7](#7-配置元模型configurability-registry) 条目形态 | L2 `OnboardingProtocol` |
| `command` | 快捷指令种子 | [05 §8](05-L3-对话主入口.md) | L3 `CommandRegistry.register_source` |

**装载与分发语义**：

- **「kind → loader」分派**：每条目按其 `kind` 交由该 kind 的 **loader** 消费；loader 由消费方（层）提供并注册，**未注册 loader 的 kind 被显式拒**（不静默忽略、不猜测）。容器归属 L1（[03 §2](03-L1-能力底座-Skills与MCP.md)）；消费方（L2/L3）向容器注册 loader 属**向下依赖**（[铁律 7](../../项目管理/工程宪法.md)）。
- **幂等**：同 kind 同 `version` 重复装载**不重复、不静默覆盖**（沿用官方 Pack 的既有幂等口径）。
- **更新**：换一版即 [§9](#9-版本化规范) 的版本语义——主版本不兼容需人工确认、次版本兼容增强，并展示变更日志 + 影响范围（用户可选更新 / 跳过 / 锁定）。
- **回退**：各消费方**保留自有的内置缺省**——Pack 缺席或某 kind 未装载时，消费方行为与其内置缺省一致（不留「必须注 Pack 才能跑」的隐含前提）。

**与 [§7 配置注册表](#7-配置元模型configurability-registry) 的关系**：`onboarding_questions` 这类条目**同时**是 §7 的登记项——Pack 提供其**官方缺省**，登记项的三能力（双通道可改 / 变更留痕 / 可回滚）不因缺省来源改变而降级。
